Reżyser Audio GPT — Complete Guide (Version 18.10.0 – Release Edition)

Welcome to the Hybrid Recording Studio! This toolkit allows for the automatic writing, planning, formatting, and translation of radio play and audiobook scripts. It has been optimized to work with professional speech synthesizers and local screen reader engines (NVDA).

The set consists of the main studio (Direction), a translation and accent tool (Polyglot), a file structure building tool (Audiobook Architect), a Rule Manager (from version 13.0 — without Python, you can add a new accent, cipher, or creative mode, see STEP 7b below), and — from version 15.0 — the Story Module (interactive second-person fiction generated by AI, read by TTS or screen reader, described in a separate manual tales.en.html). All five tools are available in a single program window, switchable with buttons on the toolbar or keyboard shortcuts Ctrl+1..Ctrl+5.

STEP 1: First Launch (Cross-Platform)

Download the latest installer from the Releases tab on GitHub (file Rezyser_Audio_v<version>_Installer.exe) and run it by double-clicking. The installer will suggest a default installation location — the Programs folder in your local account directory — and does not require administrator privileges. You can choose your own path with the "Browse" button; in that case, REMEMBER it (it will be useful for updates — see "Automatic Updates" below). After installation, launch the program using the desktop icon or from the Start Menu. After a moment, the main program window will appear — Audio Director GPT. From version 17.0, the application is frozen as a native executable in windowed mode, so no terminal window flickers, and it starts faster than before. No browser, no background server. When you're done working, simply close the program window.

The entire application, including the Python engine, projects, and API key, resides in one folder under the installation path — the entire folder can be moved to a USB drive, the cloud, or another computer (detailed instructions in the "Transferring Projects and API Key" section below).

Important: The runtime/ folder inside the installation folder is a PyInstaller bundle (from version 17.0) — it contains an isolated Python interpreter and libraries, ready to use without a separate system installation; it also serves as a container for hidden project metadata. If you clone the repository (developer path), this folder is absent and should not be there — you then use the virtual environment venv described in the developer section below.

STEP 3: Main Directing Studio

This is your command center for inventing stories and writing scripts. Navigate to it by clicking the "🎬 Director" button on the button bar or by selecting Tools → Director from the menu (shortcut: Ctrl+1).

Important: Project file format — back to .txt

In version 7, project files were saved in Markdown format (.md), e.g. skrypty/znieczulica.md. This was a deliberate experiment — the .md format was meant to serve as a psychological barrier for non-technical users, discouraging them from opening and manually editing the file in Notepad (and thus accidentally corrupting the structure headers).

The experiment did not work out. AI frequently and flagrantly breaks one of the fundamental prohibitions (more on that in a moment). For this reason, version 8 returned to simple .txt files — more intuitive and readable for everyone. For example, a project named "znieczulica" will now be saved as skrypty/znieczulica.txt, and its summary as skrypty/znieczulica_streszczenie.txt. This will allow everyone to more easily make ongoing directorial corrections or cuts to the text.

⚠️ Critical Editor's Rule (read before you start!)

All your generated scripts and books are saved in plain text files (.txt), which you can easily open in Notepad.

As the Director, you have FULL RIGHT (and indeed an obligation) to edit this file! If the AI gets carried away and, for example, resolves the characters' problem on its own at the end of a generated passage, open the file, delete the last few lines and leave the text cut off at the most tense moment, then click "Reload project from disk" to synchronize the model's memory with the corrected file, and "Send to AI" to continue.

🔴 However — what you must not touch

Never modify, delete, or alter lines containing structure (e.g. Act 1, Scene 2, Chapter 1, Prologue). If you break these headers:
1. Your story will fall apart in screen readers (NVDA).
2. The Audiobook Architect, and consequently ElevenLabs Studio, will not be able to correctly divide your book into passages for reading.
3. The application's internal Converter will not generate a correct table of contents in the Word file or on the ElevenLabs timeline.

Edit the dialogue, cut the action, but leave the structure alone!

How to use the Directing Studio?

  • World Book (left sidebar): This is where you enter the rules of your universe. Each project now has its own World Book linked to the filename — if your story file is e.g. emilia_heist_audiobook.txt, the World Book will be saved as skrypty/emilia_heist_audiobook.md. That is why the order matters: first enter the project filename in the "Project filename" field, and only then can you save the World Book. The "💾 Save the Book Permanently" button remains grayed out until you provide a name. Loading an existing project with the "Load History" button will automatically load the corresponding .md file as well — you don't need to do anything manually. Note: Without a filled-in World Book, the application will block sending queries to the AI — this is a deliberate safeguard that protects you from generating text without any rules.
  • Long-Term Memory (left sidebar): The second field in the sidebar. This is where the AI automatically saves a plot summary when memory starts to fill up. You can also enter your own notes here manually — the model will treat them as "what I already know" before reading the current scene. HISTORICAL BUG (fixed in v15.5): previously, if you entered a very short note here and clicked "Save Summary" before there was anything significant in the narrative file, on the next load the application would PRIORITIZE loading the summary and SKIP the full story — the model would then receive only the World Book and a one-sentence note, with no context of tone or recent scenes. From v15.5 onward, loading is intelligent: if the entire story fits within the context window, it is loaded in full (and any redundant old summary is deleted), so the model does not lose context. And after manually editing the narrative file in the editor, use the new "Reload project from disk" button (from v15.5), which synchronizes internal memory with the disk in a single click; to simply open the file in the editor, use "Open narration file…" as before.
  • Brainstorming Mode: Enter a loose idea and the AI will give you 3 plot development options. For each option it will immediately generate a ready-made "--- PROMPT DRAFT ---" block. Once you choose one, paste that prompt into Script Mode or Audiobook Mode and add any comments or information for the model. Story memory does not change during Brainstorming — you can experiment without risk!
  • Raw Script Mode (from v16.0 — staged reading): Paste the "Prompt Draft" generated in Brainstorming here. The AI will write a long narrator-dialogue passage: narration (setting, time, action) in [Narrator: ...] tags and character lines in [Name: emotion] tags. No sound effects — context is carried by the narrator's words. The text is automatically appended to your file (e.g. nowa_scena.txt) in the skrypty/ folder. This finished script can then be turned into a multi-voice audiobook (bridge to ElevenLabs Studio — separate chapter below).
  • Traditional Audiobook Mode: A mode for writers. The AI generates clean literary prose — no tags, no phonetics, classic dialogue woven into narration. Text is appended to the file in the same way as in Script Mode.
  • Automatic character creation: The script is programmed to automatically create new [Speaker] tags if the plot requires a new character. Tip: If the AI creates a great character, copy their tag and paste it into the World Book so the model remembers them permanently!

Project management — three action buttons:
- Load History: Loads an existing project into memory. Available when current memory is empty. From version 15.2.3 it supports two paths: if the project name field is empty, a selection dialog opens with a list of all projects found in the skrypty/ folder (skipping summary files) — NVDA reads the list naturally, and the user does not need to remember and retype the name from the keyboard. If the name field is filled in, the application immediately attempts to load the project with that name (expert path: Enter in the name field or click after typing from memory).
- Close Project (Hard Reset): Completely clears the project. Deletes the history, summary, World Book and resets all counters. Use when switching projects or starting a new story.
- Open narration file… (from v15.2.3): Emergency editing of the narrative file in the system text editor. Requires a project name to be entered. The application opens skrypty/<nazwa>.txt in Notepad (Windows), TextEdit (macOS), or the default GUI editor (Linux). Typical scenarios: (a) the AI does not close a scene and you want to add the ending manually; (b) you loaded a project with a summary and want to copy the last scenes into Long-Term Memory so the model has full tonal context (architectural gap described above); (c) you want to make a cut in the middle of a chapter that the application's engine does not natively support.

  • Reload project from disk (from v15.5, rebuilt in v17.6): Reloads the ENTIRE project from disk after manually editing the narrative file — this is a true reload, not just a refresh of current memory. It recalculates Chapter/Act/Scene counters, picks up the World Book, Brainstorming mode and options, and synchronizes working memory. If the entire story fits within the context window, it loads it in full (and deletes any redundant old summary so the engine works on the complete text). If the story is long and has a saved summary, it keeps that summary intact and asks you which header the AI's working memory should start from: in Audiobook mode you choose a Chapter, in Script mode you first choose an Act and then a Scene within that act (or the entire Act) — the rest is represented by the summary. Canceling the selection = emergency cut to the last fragment of text (which is why it pays to maintain the header structure). Before overwriting the fields with the version from disk, it warns you if you have unsaved content in them. Typical scenario: the AI incorrectly closed a scene (broke anti-closure), you cut the bad ending in the editor and click Reload — no more fixing things in two places.

Historical note — why modes are now protected against accidental changes:
In earlier versions of the application, nobody enforced consistency of the creative mode within a single project. The result was a certain subtle creative possibility that could be described like this: you start a story in Script Mode, insert "Act 1" and "Scene 1" (the application is delighted by your consistency), generate several screens of tension with [SFX: Door slam] and [Speaker 1: Marek - resigned] tags... and then — because inspiration has just struck — you click "Insert cut Chapter 1". The application, without batting an eye, appends the header "Chapter 1" to the file, right after "Scene 3". You now have in your file a hybrid of a 1950s radio play and a literary novel. ElevenLabs looks at this structure, sees a chapter header in the middle of an act, and decides it's probably a glitch in the matrix. The table of contents looks like the work of an avant-garde artist. The Audiobook Architect, for its part, assumes you're an adult and simply processes it without a word — but also without any guarantees of the result. From version 12.0 the interface tried to block changing the recording mode — at least in theory. Practice turned out to be more creative: Brainstorming (always active as a planning mode) was a back door through which you could navigate between Script and Audiobook using the up and down arrow keys (Audiobook → Brainstorm → Script and analogously in the other direction). The first click of "Insert Act 1" or "Insert Chapter 1" in the newly selected mode smoothly overwrote the .mode file, mixing acts with chapters in a single narrative file. Only from version 15.2.3 do we have true protection: once the mode decision has been committed (first structure or first successful production send), the second recording position in the mode selector is actually locked. Brainstorming remains always active as an emergency mechanism — it generates a summary when the context window overflows and provides plot options — but you can no longer use it to jump sideways into a different recording mode.

Showrunner Prompts — AI as a TV series writer (from version 7, retained)

This is the biggest change introduced in version 7, retained unchanged. It is not visible in the interface, but it radically changes the quality of the generated plot.

A showrunner in the television industry is the person responsible for the overall vision of a series — they ensure that the plot never moves toward an easy resolution, but constantly thickens, piles up conflicts, and keeps the viewer in suspense across many seasons. In version 7, this philosophy was built directly into the AI's system instructions.

The Anti-Closure Directive — and what the Anthropic engine (Claude) changed

The Showrunner philosophy is enforced by the Anti-Closure directive built into every mode: a prohibition on closing scenes with summaries, morals, and false happy endings. In the old era (GPT model), things were exactly the opposite of today — the engine notoriously broke this prohibition and "closed" the story at every opportunity: it wove in plot-summarizing sentences, created false happy endings, or wrapped up storylines in the middle of a chapter as if every passage were the last. From version 18, the entire AI engine runs on Anthropic (Claude) by default — and from version 18.4 you can optionally specify your own provider (STEP 2B) — and Claude adheres to Anti-Closure far more rigorously.

A different, purely technical side effect has emerged as a result: since the model consistently does not close a scene, its output can reach the single-response length limit and cut off mid-sentence (and sometimes even mid-word). The application handles this on its own — when it detects that a passage was cut off by the limit, it uses one short additional query to close the last sentence so that it sounds natural in the language of your story, and only then saves the text. If for some reason this cannot be resolved, you will see a gentle warning, and the text will be saved in its current state regardless — we never block saving, and you can always polish a truncated ending by hand.

The editor's rule described above remains in force: if the model nevertheless closes a scene too neatly, it is your right (and indeed your duty) as the Director to open the .txt file, delete those last sentences, leave the text cut off at a tense moment, and click "Reload project from disk" to synchronize memory with the corrected file.

Every mode has a built-in Anti-Closure directive:

  • Brainstorming: The AI acts as a writer on a multi-season series. Each of the 3 proposed options MUST pile up obstacles, introduce new dilemmas, open storylines, and cliffhangers. An absolute ban on proposing options in which the characters reconcile permanently, overcome the main obstacle without powerful consequences, or the story moves toward a hasty ending. A ban on inventing cheap, magical locations that break the world's architecture.
  • Raw Script Mode: An absolute ban on ending text with summaries, morals, or bookend closures. The AI must cut the action naturally at a tense moment (cliffhanger), avoiding conclusions so that the next passage can smoothly take over the narrative.
  • Traditional Audiobook Mode: An absolute ban on ending text with pompous summaries, wrapping up storylines, or suggesting the end of the story (e.g. "She was ready for new challenges", "She understood it was time to move on"). The text must cut off in the middle of ongoing action, tension, or an open thought.

Exception to the rule: If you explicitly ask for an ending, finale, or epilogue, the AI will generate a satisfying conclusion to the story — the ban does not apply when you ask for it yourself.

Managing Acts and Scenes (Script Mode, from version 7, retained)

Raw Script Mode has a dedicated "✂️ Structure Management" panel with buttons for building the structure of a radio play in real time.

  • Insert Act X: Inserts an act header (e.g. "Act 2") AND automatically appends "Scene 1" beneath it — because every new act begins with the first scene. The act counter jumps to the next number, and the scene counter resets to 2 (ready for the next scene in that act).
  • Insert Scene X: Inserts only a scene header (e.g. "Scene 3") within the current act. The scene counter increments automatically.

Intelligent file loading: When you load an existing script file, the application automatically scans it and sets the act and scene counters to the correct numbers. The scene counter is always calculated within the last act in the file.

Prologue and Epilogue: The "📜 Insert Prologue" and "🏁 Insert Epilogue" buttons are shared by both modes and available in the same panel.

The Audiobook Architect will automatically convert Acts into main navigation points (Heading 1) for ElevenLabs and NVDA — Scenes will become bold text visible in the document, but not visible in the table of contents.

Intelligent Chapter Management (Audiobook Mode, from version 5, retained)

The LLM generates a maximum of approximately 5,000 characters per single query — that is not enough for a full chapter. This is why you work iteratively: you generate successive passages using the "Send to AI" button until you decide that a given chapter is ready. You then click "Insert chapter cut" — the application appends the header to the file and memory, and the chapter counter automatically jumps to the next number.

Buttons in the panel:

  • Insert cut (Chapter X): Inserts a header (e.g. "Chapter 3") into the file and memory. The chapter counter updates automatically.
  • Insert Prologue: Works only at the beginning, when memory is empty. A safeguard against accidentally inserting a Prologue in the middle of the story.
  • Insert Epilogue: Closes the story. Once the Epilogue has been inserted with content, the application will block the generation of new passages — this is intentional, because once the story is finished there is nothing left to add.

Intelligent file loading: When you load an existing file, the application automatically scans it and sets the chapter counter to the correct number. If the file has a Prologue and three chapters, the counter will show "Chapter 4" — no manual counting required.

Story Accumulator — how AI memory works

Only the clean text of the story flows into the model's memory — what the AI actually wrote. Instructions, options, and plans disappear after use and do not clutter the context. The result? The model maintains focus for longer, remembers character accents better, and less frequently "drifts" away from the World Book rules.

The "Model Memory" indicator on screen shows how full the model's context window is. From version 15.1 this is NO longer a simple count of story characters — the application counts real TOKENS (using the same method the model itself uses) and sums up the ENTIRE payload sent to the AI: the current story, Long-Term Memory (the summary) AND the World Book. This is why the indicator also rises when you expand the World Book or have a long summary — not only from the narrative itself. The value is displayed as a percentage of the window's capacity:
- Green (up to approx. 70%): The model is fully focused; you have a safe buffer.
- Yellow (approx. 70–90%): You are approaching the limit. The AI may start shortening its responses and ignoring rules; in planning mode (Brainstorming) the engine begins forcing a summary. Start slowly wrapping up the current thread.
- Red (above approx. 90%): Critical overload!

Diagnosing the summary threshold (when the AI hallucinates earlier than the threshold assumes): the thresholds (warning ~70%, alarm ~90%) are empirically estimated. If you notice a recurring tendency for the model to "drift" from the rules or start hallucinating BEFORE the indicator enters the yellow/red zone — that is, earlier than the threshold assumes — please open an issue in the application's repository and describe at roughly what fill level (percentage) it actually starts to break down, ideally with an example. If this tendency is confirmed more broadly (by other users, across different projects), the automatic summary threshold will be lowered in the next patch. This is a deliberately iterative mechanism — it is better to tune it on real data than to guess in advance.

Infinite Memory (from version 6, retained)

When the red alarm lights up, you no longer need to copy the summary manually. Type a command containing the word "summary" or "recap" into Brainstorming — the AI will generate a concise knowledge capsule covering the entire plot so far. Then click the "Save Summary (permanently)" button — the application automatically creates a _streszczenie.txt file in the skrypty/ folder and protects it against accidental overwriting. After saving, clear the memory and you can continue creating in the current file. Load the summary into the Long-Term Memory field before your next session — and you can continue the story indefinitely, with no length restrictions whatsoever.

When to summarize (updated in v15.5): You no longer need to watch a rigid character threshold "before finishing work." It is best to summarize after a natural closure of a larger structural unit — after finishing a scene, act, or chapter. The reason: when you later manually correct the ending in the narrative file and click "Reload project from disk", the application will ask you from which header to restore the fresh passage — and the summary of the earlier part will remain untouched (no more correcting things in two places). This is all the more reason to maintain structure: regularly insert Chapter/Act/Scene headers from the structure panel (long-form works with no acts or chapters at all — e.g. a "modernist drama" written as one continuous stream — are discouraged). EXCEPTION: if you are writing a very long story ENTIRELY without headers, generating and saving a Summary before a break remains necessary — without markers the application can only restore the last passage counted in characters, and the engine without context could "panic."

Automatic summarization: When memory enters an alarm state, Brainstorming automatically switches to emergency mode — instead of immediately generating options, it first creates a detailed summary of the entire plot so far and saves it within <STRESZCZENIE> tags. The application detects these tags and automatically transfers the summary to the Long-Term Memory field. Zero manual effort!

Intelligent loading and reloading from disk (updated in v17.6): Both when loading a project and after clicking "Reload project from disk" (following manual editing of the narrative file in the editor), the application reconciles memory with disk in a single pass — it recalculates structure counters and picks up the World Book and mode. If the ENTIRE story fits within the context window — it loads it in full and deletes any redundant old summary, so the engine works on the complete text (this closes the former gap in which the model received only the summary without the context of the most recent scenes). If the story is LONG and has a saved summary file — it keeps the summary intact and asks you from which structural header (Chapter/Act/Scene) the AI's working memory should start; the rest of the plot is represented by the summary. This way you do not waste tokens reloading the entire story, while at the same time the next summary is not built on outdated data.

STEP 3b: Two Outputs of the Script — Multi-Voice Audiobook (ElevenLabs) and Screen Reader Version

A finished read-aloud theatre script (Script mode) has two independent outputs: a multi-voice ElevenLabs Studio project (audio) and an HTML version for screen readers. These are two ways to "hear" the same play — you can use one, the other, or both. Both are optional and do not change the classic converter workflow.

Bridge to ElevenLabs Studio (audio, optional)

The bridge turns the script into a multi-voice Studio project — the narrator and each character get their own voice. Without an ElevenLabs key nothing changes: the bridge simply remains hidden.

ElevenLabs Key (optional)

Paste your ElevenLabs key into the golden_key.env file on a separate line: ELEVENLABS_API_KEY=sk_... Note: the ElevenLabs key starts with sk_ (with an UNDERSCORE), unlike the Anthropic key (sk-ant-). If you are using a restricted key, grant it the scopes projects_write and voices_read. The key status is visible on the main screen (System Check) — a missing key is not an error; the bridge simply remains hidden.

The bridge appears in the Director panel in Script mode (when the key is valid). It works on a finished play saved to disk — first generate or load a project, then proceed to the bridge.

Step 1 — Voice Cast

Click "Voice Cast…". The application will read the characters that have lines from your script and will always add a Narrator slot (the narrator is the default voice — it reads chapter titles and all narration). For each speaker, paste a voice ID. IMPORTANT: every voice used in the play must first be in your "My Voices" — voices you create yourself (e.g. in "Voice Design") go there automatically, while voices from the public library are browsed in the "Explore" tab and added with the "Add to My Voices" button. How to get a voice ID in ElevenLabs (in the browser): find the voice, play the sample to make sure it is the right one, and copy its identifier with the "Copy Voice ID" button; once the voice is in "My Voices", this button is available immediately — without expanding "More actions". Choosing voices: to minimise potential regenerations, the easiest approach is to pick from the "Best for Eleven v3" collection (voices verified for the v3 model on which the project is built); alternatively, design your own voice in "Voice Design", and for the adventurous there is IVC (Instant Voice Cloning) or PVC (Professional Voice Cloning). You can leave fields empty and come back later — the save is a draft.

Step 2 — Build the Project

Click "Create ElevenLabs Studio Project…". The application will check that the script has at least one chapter (Prologue/Act/Chapter) and that every speaker and the narrator have a voice assigned, and will then create a multi-voice Studio project divided into chapters in your account. Creating the project itself does NOT consume credits. The application immediately sets the project language (correct pronunciation of header lines) and volume normalisation to the audiobook standard — it does this via the API so you do not have to go into the project settings in the browser.

Format Guardian (extension of the Editor's Rule): the bridge requires that in the script EVERY line is either a line of dialogue with a speaker tag ([Narrator: …] or [Name: …]) or a structural header (Prologue, Act, Scene, Chapter). Plain, untagged prose written "loose" — for example an author's note or a narration fragment without a tag — is not assigned to any voice and is silently skipped during the build, so the finished project could diverge from your file. Therefore, if the application detects such orphan lines, it will show a list of them with line numbers and ask whether to build anyway: you can then cancel and fix the script (open it with the "Open narration file…" button, add the missing speaker tags or remove those lines) or knowingly build anyway, accepting that they will be omitted. This is a natural extension of the Editor's Rule: just as structural headers must not be broken, every line in a script intended for the bridge should have its own speaker or be a header.

Step 3 — Render in the Browser

After the project is created, the application will show its identifier and a button that opens ElevenLabs Studio. In the browser, find the project, render the speech (this is what actually consumes credits — roughly 1 credit per character), and then export the audio file or publish the project to Eleven Reader. Rendering and publishing happen on your side, deliberately — the application only builds the project.

Expression and Accents (Eleven v3 model)

The project is built on the Eleven v3 model (over 70 languages). Emotions are NOT expressed with capital letters, ellipses, or dashes — the engine ignores these. Instead, the Director weaves English v3 audio tags into the lines, for example [whispers], [sighs], [angry], [laughs] — these control expression and work regardless of the spoken language. A character's ACCENT, on the other hand, comes from the VOICE SAMPLE: if you want someone to speak, for example, in Polish with a foreign accent, select or design a voice in Voice Design whose sample has that accent. In practice, experiment with the voice prompt until you hear, for example, a Polish sample with a Finnish accent — the v3 model will preserve that accent in the finished recording. Tip: very long sentences weaken the accent, which is why the Director is already prompted to use short sentences.

Awareness of the v3 Model (alpha phase)

Eleven v3 is the most expressive, but is still in alpha. Occasionally a single line will render as crackling noise instead of speech — simply regenerate it in Studio (each block has several free regenerations). In the ElevenLabs project settings, the engine may also display recommendations to switch the model (to Eleven Flash v2.5 or Multilingual v2) — this is NOT an error, just a suggestion from the engine. If you do not want to see these messages, simply do not open the project settings: the application has already set everything needed via the API (model, language, volume normalisation).

Why read-aloud theatre and not sound effects? In earlier versions, Script mode produced raw [SFX: ...] effects without a narrator. The bridge to a finished, multi-voice recording requires, however, that context (place, time, action) be carried by the narrator in words: sound effects in Studio are not accessible to screen readers, and the model reliably handles either a narrator or effects — never both stably at the same time. That is why Script mode is read-aloud theatre: narrator plus dialogue, without SFX.

Screen Reader Version (HTML, without ElevenLabs)

In Script mode, regardless of the ElevenLabs key, you have a "Generate screen reader version" button. It creates a file skrypty/<nazwa>_screen_reader.html — a separate output for people using screen readers (e.g. NVDA). It works as follows: lines of characters who have an accent defined in the World Book (e.g. the entry "[Joana] Finnish accent") receive phonetic spelling (deliberately "broken" orthography) and a language marker (lang attribute), so that the screen reader reads them with the correct foreign accent. V3 audio tags (e.g. [whispers]) are removed in this version — the screen reader should not read them aloud. Prologue/Act/Scene headers become HTML headings, making the document easy to navigate.

This is a deliberate complement to the audio bridge: for the v3 model, the accent is carried by the voice sample, while for the screen reader it is carried by the orthography plus the language marker. That is why the orthography in the audio version remains clean (v3 selects the language itself), while the "broken" orthography goes exclusively into the separate HTML file, where it is desirable.

Assigning Chapter Titles (Audiobook Mode)

STEP 5: AI Polyglot

An application for translations and enforcing strong accents on screen reader synthesizers. Access it by clicking the "🌍 Polyglot" button on the toolbar or selecting Tools → Polyglot from the menu (shortcut: Ctrl+2).

Mode 1: Regular Translator (Uses AI - Paid)

Ideal for listening to stories in beautiful, correct foreign language.

  • Load a file using the "Load file into memory" button or by using the "Browse..." button to select a file in the system window.
  • Select the "AI Translator" mode, enter the target language (e.g., "Finnish").
  • The script will translate the content. If you load an .html file, it will only translate the text visible to the reader and update the language code in the html tag.
  • If you load a plain .txt or .md file (e.g., a script generated by the Director), the script will automatically save the result as an .html file with an embedded language tag after translation — ready for reading by NVDA without any additional work.
  • Also supports .docx files.

Intelligent block division: Long texts are automatically divided into blocks measured in model tokens (not characters) and translated sequentially with a progress bar. This way even densely written languages such as Chinese or Japanese fit within the model's response limit, and a truncated response is detected and automatically retried on smaller fragments.

Crash-resistant progress saving (NEW in version 9): Each translated block is immediately saved to a hidden temporary file in the application's system folder. If the translation is interrupted due to API limit exhaustion, upon the next launch, the application will automatically detect this file, restore the already paid progress, and calmly complete the work from where it left off — without any manual copying. Upon successful completion, the temporary file is automatically deleted.

Why is this important? In version 8, the approach to resuming translation had a critical, silent bug: if you didn't rename the file with the partial translation and cut out the translated fragment according to the instructions, and then immediately resumed translating the rest — the application would open the output file in overwrite mode. The paid progress would be irretrievably and unknowingly erased before you noticed anything. Version 9 completely eliminates this trap: the save is permanent after each block, regardless of what you do afterward.

Mode 3: Cipher (NEW in 13.0 — text play, free, local)

The third RadioButton in Polyglot, next to AI Translator and Director Mode: "Cipher Mode (text play, random stuttering)". It activates six local text-distorting algorithms — for fun, puzzles, and language games. After selecting the mode, a dropdown list of algorithms appears, and for one of them (Caesar Cipher), an additional numeric field for the shift.

Available algorithms (select in the menu "Choose a distorting algorithm"):

  • Text Reverser (Reading backwards with a capital letter) — each sentence is reversed character by character, keeping the period/exclamation/question mark at the end and a capital letter at the beginning. Before reversing, the script expands popular abbreviations (e.g., i.e., etc., U.S., U.K.), so the result still makes sense after reversing — without this, "e.g." would reverse into the nonsensical ".g.e".

Inspiration: a mission from the program "The Traitors". When the host unexpectedly showed participants a popular Polish song from a cartoon — just played backwards — reactions were like "what language is this?", "it must be Armenian", "Hungarian or Finnish". The actual mission was that one team received the song's lyrics written backwards in the forest, had to sing it in this reversed form, the other team recorded it, played it from the end — and theoretically recovered the original song to guess. Our Reverser generates exactly the same funny phonetic misunderstanding when you run the processed file through a TTS synthesizer.

  • Typoglycemia (Scrambled word middles) — a classic psycholinguistic effect: "Aoccdrnig to a rscheearch at Cmabrigde Uinervtisy, it deosn't mttaer in waht oredr the ltteers in a wrod are, the olny iprmoatnt tihng is taht the frist and lsat ltteer be at the rghit pclae." The script randomly scrambles the middle of each word longer than 4 characters, leaving the first and last letter untouched. Great for testing "how much do I really see, and how much does my brain guess."

  • Broken Telephone / Snake Dialect — each "s", "z", or digraph "sz" is randomly elongated into a hiss of 4-8 characters ("ssssss", "zzzzzz", "ssssssz"). Inspiration: Snecko from the game "Slay the Spire". Effect: the text sounds as if read by a snake with a speech impediment.

  • Vowelizer (Everything booms on "O") — every vowel in the text is replaced with "o", preserving Polish softening. "Dzień dobry" → "Dźoń doboro". The longer the text, the funnier the effect (and a screen reader reads it with full conviction).

  • Strong Stuttering / Broken Robot — attaches stuttering at the beginning of words: "c-c-c-computer", "sh-sh-shower". For short words (less than 3 characters), the algorithm skips them. If the second letter of the word is a consonant, it repeats the first two letters (more natural effect); if a vowel — it repeats only the first.

  • Caesar Cipher (EN alphabet shift) — a classic substitution cipher: each letter is shifted by N positions in the English alphabet (ABCD…XYZ, 26 characters). You enter the shift value in the numeric field "Caesar Cipher Shift (0 = random, range -25…25)". If you enter 0 — the application will randomly select a shift in the range 1-25 and display it in a message after completion (so you can decrypt it later). Characters outside the alphabet (numbers, punctuation, spaces) remain unchanged.

Practical application: ciphers save the result in the same format as Director Mode (.html with a lang tag or .docx with XML tags), so NVDA reads them with the appropriate language voice. Especially the Reverser and Vowelizer sound much more interesting in a synthesizer than when you read them with your eyes — because the brain automatically tries to "decode" the text when reading visually, while TTS reads it exactly as written.

All six ciphers are also described in broader, accessible language in the file docs/dictionaries.pl.html in the application package — along with tips on how to add your own cipher type "letter substitution" without programming knowledge (e.g., school slang, gibberish).

Language Detection

Before the script "distorts" the text, it checks which language it is written in. If it detects that it is not Polish, it will display a warning. The phonetic rules are tailored for Polish — applying them to a foreign language text would yield unpredictable results.

Accents optimized for local synthesizers (NVDA)

The accents have been 100% designed for local, free, and paid screen reader synthesizers — Vocalizer and eSpeak in NVDA. This ensures stability and predictability of the effect on every computer.

Why not ElevenLabs? Tests on longer documents have shown that phonetic text distortion in engines like ElevenLabs does not enforce the intended accent — the engine simply "guesses" the language and tends to create a Western/Southern Slavic accent. Local NVDA synthesizers are much more compliant in this regard.

Different TTS engines behave differently. Below are key differences that directly affect the functioning of accents:

A lightweight, free engine with a vast database of languages — supports, for example, Icelandic. Very strict about character encoding, which makes it predictable. After installation, a dedicated "Tiflotecnia Voices" submenu will appear in the NVDA menu, along with its own category in NVDA settings. The add-on's GUI guides you step-by-step through purchasing a license (or activating a 7-day trial period), selecting and installing the first voices (e.g., Polish Ewa for smooth reading of system controls, Finnish Satu for accents in Polyglot). The built-in help of the add-on is clear, so we won't duplicate the procedure here — just follow the add-on's guidance.

Tip for those migrating from Vocalizer and Eloquence: an upgrade is available at a lower price. Procedure: after successful payment, immediately send an email to the address linked on the payment success screen and request validation of the old activation code — Tiflotecnia will confirm the right to a discount and adjust the price. Voice availability: Tiflotecnia Voices supports most of the languages that Vocalizer had (including Polish, English, German, French, Spanish, Finnish, Italian, Russian). The list of voices per language is visible in the add-on settings category before purchasing a license.

Free voices built into the Windows system (Mobile Voices). A good compromise between quality and language availability. Offers high quality and supports Icelandic (Gudrun), Finnish (Heidi), and Italian (Elsa). Killer Feature for the Blind: Files with Language Tags

This is a true revolution. Processed files are now saved as:

  • .html with a lang attribute (e.g., lang="fi" for Finnish) — NVDA reads this tag and automatically switches the voice to the appropriate language synthesizer. Zero manual configuration!
  • .docx with formatting preserved — each text run has a language tag injected into the document's XML, so Word and NVDA know which voice to use for each segment.

Processed files are always saved as NEW documents (e.g., accent_Finski.html).

Automatic Language Switching in NVDA — What You Need to Know

For NVDA to actually switch voices based on the lang tag, the setting "Automatically switch language when supported" must be enabled. You can find it in NVDA Preferences → Speech. By default, it is enabled upon the first launch of the reader — but it's worth checking if someone has turned it off.

Important limitation of OneCore voices: Microsoft OneCore voices do not natively support this mechanism with NVDA, only with the built-in Windows narrator. There is an unofficial NVDA add-on called "One Core Autolang" that attempts to fix this — but its development was quickly halted. The reason is simple: every year, with the first NVDA version of the year, there are changes that break API compatibility (so-called API Breaking Changes). Sometimes it's enough to update the "last tested version" field in the add-on's manifest, but sometimes real changes in the code are required — and the author can't keep up with updates. If you care about automatic language switching, safer choices are Tiflotecnia Voices (paid, section above) or eSpeak (free, lower quality), which support this mechanism natively — but note: currently in Tiflotecnia Voices, it works with a priority bug (see "Critical Catch" below). After applying the patch, automatic switching works flawlessly, as in the old Vocalizer.

Critical Tiflotecnia Voices Catch: Broken Language Detection

First, the good news — the NVDA 2026.1 alarm from previous manual versions ended on a happy note: Cerrence provided 64-bit libraries, Tiflotecnia released them in a .nvda-addon package available in the Add-on Store (section above), and Vocalizer for those who kept it until the end returned under a new name — with better quality and without 32-bit limitations.

However, with the release of Tiflotecnia Voices, a new critical catch emerged — in language detection. In the add-on settings, you can configure which voice should be used for specific letters (e.g., Latin, Cyrillic) depending on the installed voices. The problem lies in the priority order: currently, it first applies an override per letter, then falls back to the ISO language code (practically unreachable for the SAME alphabet to which the override has already matched), and finally the selected voice. The effect appears within the same alphabet: you have Finnish text with the correct lang="fi" tag, Satu installed as the Finnish Tiflotecnia voice, BUT in the settings, a Polish voice is set for Latin letters — Satu WILL NOT read this text, despite the correct ISO tag. The per-letter "Polish voice for Latin" override wins at the first level, and ISO fi is never checked. For different alphabet pairs, the mechanism works correctly (Russian text + Milena for Cyrillic + Polish voice for Latin — all Cyrillic goes to Milena, any Latin proper names with the Polish voice; each alphabet stays in its override). After migrating from Vocalizer, where language switching based on ISO worked flawlessly, users will notice this regression immediately — especially those who use several European accents (Satu, Alice, Markus) in Polyglot on the same Latin letter pool.

Diagnosis and patch: I diagnosed the issue at the Python level in the add-on code and prepared a patch changing the priority order to: ISO → selected voice → letter override. The patch retains useful switching to Latin for Latin names in Russian text when "language detection based on Unicode characters" is enabled in the settings. I sent the patch to the Tiflotecnia developers — no response so far, so they most likely stand by their own solution. If the add-on gets an update, I will update the patch if needed.

What to do in the meantime: if you care about correct language detection (it's worth it — it was one of the killer features of the old Vocalizer, see "Killer Feature for the Blind" above), open an issue in the application's GitHub repository with the label tiflotecnia-patch and your email address in the content. It's a good idea to add a short description of your problem in your own language (2–3 sentences are enough) — the bot will detect the language (supported: Polish, English, German, Spanish, Finnish, French, Icelandic, Italian, Russian) and reply in the same one; without a description or in another language, the reply will come in English. An automatic bot will immediately close the issue with a confirmation of submission (without a trace in the public thread), and you will usually receive the patch privately via email within a few days. The patch itself is NOT published in the application repository or as a Gist — Tiflotecnia Voices for NVDA is commercial software, and the add-on license does not allow redistribution of its files, even modified. After receiving the patch, its contents must be copied to %appdata%\Roaming\nvda\addons\TiflotecniaVoices, replacing the files. Be careful when copying: if Windows did not ask for a replacement, you most likely copied the entire TiflotecniaVoices_edits folder with its contents INSTEAD of just the contents — in such a case, go into the created subfolder, cut everything, paste it one level up, and overwrite. After successfully applying the patch, restart NVDA — enjoy better quality Cerrence 64-bit voices and correct language detection, a combo not available from any single manufacturer on the market. We assume, of course, that you have a valid Tiflotecnia Voices license — we do not verify this, but you won't be able to apply the patch to someone else's folder without a license.

STEP 6: Audiobook Architect

A tool for preparing a professional file structure for screen readers and ElevenLabs. Access it by clicking the "📄 Converter" button on the button bar or by selecting Tools → Converter from the menu (shortcut: Ctrl+3).

How does it work?

  1. Enter the path to the source file in the text field or click the "Browse..." button to select a file in the system dialog. The script accepts both .txt and .docx files, as well as .html and .htm files.
  2. Click "Build Architecture for ElevenLabs".
  3. The script will scan each line of text and convert keywords (Act, Chapter, Prologue, Epilogue, Foreword) into "Heading 1" headings in the Word document.
  4. Scenes (lines beginning with the word "Scena") are converted to bold text — visible in the document, but not visible in the ElevenLabs table of contents.
  5. All remaining text (dialogue, descriptions) passes through unchanged.
  6. You will receive a file named architecture_[nazwa_oryginału].docx — a professional Word file ready for further work. For example, if your input file was named znieczulica.txt, the output file will be named architecture_znieczulica.docx and will appear in the same folder as the original.

Cleanup on the fly: The script automatically removes HTML tags (if the text comes from a browser or from a local .html file, e.g. generated by Polyglot) and Markdown heading markers (e.g. ### or ####) before processing. You do not need to clean the file manually.

Story Mode: automatic grouping of turns into scenes (since v15.1)

If you load an opowiesci/<gra>.txt file generated by the Interactive Stories module into the Architect, the converter will recognize turn markers (e.g. "--- Tura 7 ---" — also in the other supported languages, if you played in a different one) and every five turns will insert a new first-level heading "Scena N" (the number starts at 1, in your game's language). The remaining turn markers are stripped — they do not appear in the audiobook narration, because "Tura 7" spoken by TTS breaks the listener's immersion. The result is a Word file with a natural division into scenes of a few minutes of audio each, ready for import into ElevenLabs. The mechanism is auto-detecting — regular audiobook files without turn markers (classic narration from Director) are processed exactly as before.

A powerful advantage for NVDA and ElevenLabs users

"Heading 1" formatting for chapters is not just about aesthetics. In NVDA you can navigate through headings instantly by pressing the H key (or 1 for first-level headings). Instead of scrolling through hundreds of pages, you jump from chapter to chapter in a fraction of a second. This changes the way you work with long documents. In ElevenLabs you can be confident that the engine will automatically insert cuts and will not freeze while directing audio clips.

STEP 7: How to Write the World Book (The Architect Prompt and Mini Markdown Course)

The artificial intelligence powering the Main Studio understands commands best when they are formatted in the Markdown markup language. If you give the AI in the Director only a loose idea (e.g. "two sisters in the afterlife"), the machine will panic from lack of detail and produce a banal, predictable story, ignoring all logic.

To prevent this, use an external chatbot (e.g. the free ChatGPT or Claude) as your personal Architect. In version 13.0 you no longer need to retype the prompt from the instructions — in the Director panel, just below the "💾 Save the Book Permanently" button, you will find a "📖 Architect's Prompt for AI…" button. Click it and a dialog window will open with the ready-made prompt text in a read-only field and a "Copy to clipboard" button. NVDA announces the entire contents immediately upon opening the window — simply click "Copy", paste (Ctrl+V) into ChatGPT/Claude, and replace the "[TUTAJ WPISZ SWÓJ POMYSŁ]" fragment with your own story seed.

Why this way rather than copying from the instructions? The GUI dialog has a key accessibility advantage: it is native and read without interference by a screen reader, requires no switching to a text editor (where Polish diacritics and quotation marks can be copied incorrectly), and works identically on every operating system. The same pattern — a dialog with a prompt to copy — is also used in the Rules Manager (see STEP 7b below).

How the AI responds: In response you will receive text in two parts. The first is the World Book enclosed in a Markdown code block (markers markdown …). Copy ONLY the contents of the code block (without the ``` markers themselves) and paste it into the "World Book" field in the Director, then click "💾 Save the Book Permanently". The second part is a recommendation for which of the creative modes (Script or Audiobook) best suits your idea — treat it as a hint when selecting the mode in the mode selection field.

STEP 7b (supplement): The order of replacement: rules matters

Files in dictionaries/<code>/accents/*.yaml contain a list of replacement: rules — pattern → replacement pairs that the engine applies SEQUENTIALLY. Each subsequent rule operates on the output of the previous one. This allows building pipelines like "break down the digraph szcz into shch, then replace ch with h", but it also opens up a classic trap for the language pack author.

The "sequential loop" trap. Let's assume that for the Spanish accent trying to make the Polish "ñ" sound like Diego (Loquendo), the author adds two rules:
1. ñ → nj (so that the Polish "ñ" sounds like a soft "nj")
2. j → x (so that the Polish "j" sounds like the Spanish "j" — phonetically /x/)

Upon execution, it turns out that words with "ñ" are pronounced as "nx", not "nj". Why? Because when the first rule changes "ñ" to "nj", the new "j" is immediately caught by the second rule and changed to "x". Result: instead of the intended "ñ → nj", we get "ñ → nx".

Order rule (universal). When one rule introduces a character that another rule uses as a pattern, ORDER MATTERS. A safe heuristic: FIRST replace the TARGET (character later used as pattern in another rule) with something safe, THEN introduce the SOURCE (character that should break down into the TARGET). For the Spanish example correctly: first j → x, then ñ → nj. Result: "ñ" gives "nj" (the second "j" will not be eaten, because the j → x rule was applied earlier, when "nj" did not yet exist).

How to test. After changing the order of rules in the accent file, pass a sentence containing BOTH letters through the Director Mode. For example ES: "Niño de paja juega" → the result must have both the ñ accent ("ñ → nj") and the j accent ("j → x"), something like "Ninjo de paxa xuega". If you see "ninxo" instead of "ninjo" — the order is reversed.

Engine validation (opt-in for pack authors). The application has a built-in heuristic for detecting potential loops, but it is disabled by default — because many pipelines look like a loop, though they are intentional (classic "szcz → shch" + "ch → h"). To enable it: set the environment variable REZYSER_VALIDATE_ZAMIANY=1 and run the application from the console — from source via python main.py, because the frozen .exe in windowed mode (from version 17.0) does not have a console window. The engine will print one aggregated WARN line for each accent file with the first three potential loops and the number of remaining ones. Check the resulting phonetics on the test sentence — if the effect is intended, ignore the WARN.

Rule movement buttons in the GUI Rule Manager (drag-and-drop, "Up / Down") are a separate feature planned for a later version cycle — it requires redesigning the Manager (currently delegates file editing to an external system Notepad and does not have its own rule view). Until its implementation: edit the YAML file manually, move lines in the replacement: section, use the validator ENV-var, and test on control sentences.

STEP 2B (advanced, optional): Custom AI provider compatible with OpenAI

Most users should stick with the recommended Anthropic (STEP 2) — it delivers the highest quality. The entire AI engine then follows a single path to that endpoint, with no separate per-provider integration.

This is an option for advanced users: you configure it manually in the golden_key.env file, adding alongside (or instead of) the Anthropic key three lines plus the key for your chosen provider:

LLM_PROVIDER=openai_compat
LLM_BASE_URL=endpoint_address (e.g. https://openrouter.ai/api/v1)
LLM_MODEL=model_name_at_provider (e.g. openai/gpt-4o-mini)
OPENAI_API_KEY=your_key_for_that_provider

How it works:
• When LLM_PROVIDER=openai_compat, the ENTIRE AI engine (Director, Stories, Polyglot, titles, language detection) uses the specified endpoint, and LLM_MODEL overrides the model name from the configuration files.
• When the LLM_PROVIDER line is absent (or set to anthropic), the application behaves as in STEP 2 — using the Anthropic key exclusively. You don't need to change anything.

Important (quality): the application's system prompts are written and tuned for Claude. A different model may deliver lower quality — it may follow world rules less strictly, lose JSON structure in choice-based modes, or return text in the wrong language. This is a conscious cost↔quality trade-off on your part. If the best result matters to you, stick with Anthropic.
