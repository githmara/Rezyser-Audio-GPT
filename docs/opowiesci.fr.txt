Reżyser Audio GPT — Module Histoires Interactives (14.0 – Version de Publication)

Le deuxième mode principal de l'application à côté du Réalisateur — cette fois, vous devenez le joueur d'une histoire générée dynamiquement au lieu de son auteur. L'intelligence artificielle mène la narration à la deuxième personne du singulier (« Vous marchez à travers la forêt brumeuse, vous sentez l'odeur des feuilles mouillées... »), et vous décidez du prochain mouvement — en écrivant n'importe quelle action en texte libre ou en choisissant l'une des options numérotées.

Le module a été conçu dès le départ pour les joueurs aveugles — la narration est lue linéairement par un lecteur d'écran (NVDA) ou un moteur TTS, les choix dynamiques sous forme de boutons avec descriptions vocales, chaque tour terminée est signalée par un son de cloche et un transfert automatique du focus sur le texte nouvellement généré.

Vous ouvrez le panneau avec le bouton "📖  Histoires" sur la barre d'outils ou le raccourci clavier Ctrl+5.



ÉTAPE 1 : Trois modes de jeu — choisissez le style de jeu

Juste en dessous de la barre de titre du jeu, vous trouverez une case de sélection de mode (RadioBox). Le mode détermine comment le moteur narratif dialogue avec vous :

MODE LIBRE — vous entrez n'importe quelle action en texte libre (« j'essaie d'ouvrir la porte », « je demande au garde le chemin », « je fuis par l'escalier arrière »). Le moteur narratif peut proposer 1 à 3 suggestions, mais ce ne sont que des indices — pas un chemin obligatoire. Le mode le plus libre, recommandé pour les joueurs expérimentés improvisant leur propre histoire.

MODE CHOIX — chaque tour se termine par 3 à 5 options numérotées A-E sous forme de boutons cliquables. Chaque choix est une action spécifique que vous pouvez entreprendre. Vous pouvez également entrer votre propre action en texte libre — le moteur l'adaptera au choix sémantiquement le plus proche. Le mode le plus intuitif pour les joueurs aveugles : NVDA vous lira toutes les options, vous cliquez sur Tab entre elles, Enter valide.

MODE MOINDRE MAL — comme le mode Choix, mais chacune des 3 à 5 options est défavorable moralement, physiquement ou stratégiquement. Pas d'option « neutre », pas de fin heureuse dans ce tour. Mode pour les amateurs de fiction sombre dans l'esprit des « Tales of Consequence » ou des drames moraux.

Le mode peut être changé en cours de jeu — au tour suivant, le moteur narratif s'adaptera au nouveau style (du mode Libre au mode Choix, cela peut se faire en un clic).



ÉTAPE 2 : Démarrage rapide — scénarios d'ouverture prêts à l'emploi

Sous le champ du titre du jeu, vous trouverez une deuxième ligne avec l'étiquette « Démarrage rapide : » et une sélection déroulante (wx.Choice). La position par défaut est "(jeu personnalisé)" — le moteur inventera lui-même le monde à partir de votre première action.

Vous pouvez cependant choisir l'un des cinq préréglages prêts à l'emploi pour vous plonger immédiatement dans un monde spécifique :

SF POST-APOCALYPTIQUE — un siècle après une catastrophe écologique. Les restes de l'humanité dans des abris sous les Montagnes Sainte-Croix. Vous êtes un jeune coursier du Clan Sztolnia avec votre première mission sérieuse. Mode par défaut : Choix.

FANTASY SOMBRE — frontière du Royaume des Trois Ruisseaux, neuvième année de guerre religieuse. Vous êtes une jeune Inquisitrice sur la piste d'un village où quelqu'un protège un enfant possédé. Mode par défaut : Moindre mal.

URBAN FANTASY DÉTECTIVE — Varsovie 2008, soirée d'octobre. Vous êtes un détective privé qui voit les fantômes. Une cliente veut retrouver son mari disparu sous le Château Royal. Mode par défaut : Choix.

HORREUR COSMIQUE — année 2247, station de recherche en orbite autour d'une étoile à neutrons. Vous vous réveillez de l'hibernation sans capitaine — et sans traces que le capitaine ait jamais existé. Mode par défaut : Libre (l'atmosphère lovecraftienne favorise l'improvisation).

COMÉDIE ROMANTIQUE SOCIALE — Saska Kępa avril 2024, un petit café est sur le point de fermer. Vous êtes barista-serveuse, dont le propriétaire demande d'être « gentille » avec un rédacteur timide que vous vouliez aborder depuis longtemps. Mode par défaut : Libre.

Après avoir choisi un préréglage, cliquez sur "Nouveau jeu" — le moteur injectera une brève description du monde et du personnage, définira le mode de jeu par défaut (vous pouvez le remplacer par le RadioBox avant de cliquer sur « Nouveau jeu »). Le premier tour du LLM jouera la scène d'ouverture.



ÉTAPE 3 : Premier jeu à partir de zéro — sans préréglage

Si vous préférez une totale liberté, laissez "(jeu personnalisé)" dans le champ Démarrage rapide et préparez-vous à entrer la première action manuellement.

1. Entrez le nom du jeu dans la barre « Nom du jeu » (par exemple, « mon_aventure_1 ») — sous ce nom seront enregistrés les fichiers de narration, d'état et de log.
2. Choisissez le mode (Libre/Choix/Moindre mal).
3. Cliquez sur "Nouveau jeu". L'application créera 3 fichiers : état du jeu (.game.json), Livre du Monde vide (.md) et métadonnées du mode (.mode). Le fichier de narration (.txt) sera créé après le premier tour.
4. Dans le champ « Votre action ou commande » en bas du panneau, entrez la première action, par exemple, « je me réveille dans une pièce inconnue ». Cliquez sur "Envoyer". Le moteur narratif ouvrira le monde basé sur votre action — description de la pièce, sons, personnages, premières décisions.
5. Chaque tour sera automatiquement enregistré — vous pouvez fermer l'application à tout moment et charger le jeu plus tard avec le bouton "Charger".



ÉTAPE 4 : Commandes Slash — actions rapides sans API

Dans le champ d'action, vous pouvez à tout moment entrer une commande commençant par une barre oblique `/`. Les commandes sont locales (ne coûtent pas d'appels à OpenAI) et fonctionnent indépendamment du mode de jeu. Les variantes françaises et anglaises sont acceptées :

/zapisz, /save — forcer l'enregistrement manuel de l'état du jeu. L'enregistrement automatique se fait après chaque tour, donc cette commande est principalement pour s'assurer avant de fermer l'application.

/wczytaj, /load — ouvre une boîte de dialogue de sélection de fichier depuis le dossier runtime/opowiesci/. Après le chargement, le nom du jeu, le mode et la narration complète sont restaurés — vous pouvez continuer à partir du tour où vous vous êtes arrêté.

/ustawienia, /settings — ouvre une boîte de dialogue de sélection du modèle AI. Par défaut, nous utilisons gpt-4o-mini (Standard) — plus rapide et moins cher. En passant à gpt-4o (Haute qualité), la narration devient plus riche, mais chaque tour coûte plus cher et prend plus de temps.

/wizualizuj <opis>, /visualize <description> — description multisensorielle de la scène actuelle. Ne change pas l'état du jeu, ne propose pas de choix — le moteur narratif utilise les cinq sens (vue, ouïe, odorat, toucher, goût) pour montrer la scène avec plus de profondeur. Le résultat apparaît dans une boîte de dialogue séparée, il n'est PAS ajouté à la narration ni enregistré dans le fichier audiobook. Exemple : « /wizualizuj à quoi ressemble le garde » ou « /wizualizuj l'odeur du café ».

/koniec, /quit — ferme l'application (après l'enregistrement automatique du tour en cours).



ÉTAPE 5 : Fichiers de jeu — où trouver vos données

Chaque jeu produit cinq fichiers, chacun dans un dossier différent, avec des rôles différents :

skrypty/<nom>.txt — narration complète prête à être écoutée comme un livre audio. Peut être ouvert dans le Bloc-notes ou chargé dans l'Architecte de Livres Audio (Convertisseur) pour générer un fichier Word avec des chapitres ou un timing pour ElevenLabs.

skrypty/<nom>.md — Livre du Monde des personnages au format [Nom : caractéristiques], régénéré après chaque tour. Format compatible avec le parseur du Réalisateur ! Vous pouvez charger ce fichier dans le panneau du Réalisateur (Fichier → Charger) et obtenir des accents de personnages natifs dans la narration classique TTS — un pont entre les deux modules principaux de l'application.

runtime/opowiesci/<nom>.game.json — état complet du jeu : nom, mode, personnages actifs, localisation, équipement, fils ouverts, les 6 derniers tours sous forme abrégée. C'est la source de vérité pour charger le jeu — sans ce fichier, il est impossible de continuer.

runtime/opowiesci/<nom>.story.jsonl — journal brut de chaque tour (demande du joueur + réponse du modèle en JSON). Le fichier n'est pas nécessaire pour jouer — il sert au débogage ou à l'analyse ultérieure (par exemple, statistiques sur la durée de l'aventure, quels fils le LLM a introduits).

runtime/skrypty/<nom>.mode — métadonnées du numéro de mode (3=Libre, 4=Choix, 5=Moindre mal). Fichier partagé avec le Réalisateur, mais la numérotation ne se chevauche pas (le Réalisateur utilise 0-2).



ÉTAPE 6 : Indicateur de mémoire du modèle — pourquoi les tours dans les anciens jeux ne nécessitent pas votre intervention manuelle

Sous le RadioBox du mode, vous trouverez un indicateur de mémoire du modèle — une barre de progression (wx.Gauge) avec une description de l'état à côté. L'indicateur montre le pourcentage de remplissage de la fenêtre contextuelle du moteur narratif (gpt-4o-mini a un tampon de 128 000 tokens).

Quatre niveaux de remplissage :

🟢 propre (0%) — le jeu vient de commencer, pas de tours enregistrés.
🟢 OK (1-69%) — tout est normal, vous pouvez continuer sans restrictions.
⚠️ avertissement (70-89%) — le moteur génère automatiquement un résumé des tours précédents dans le fil de fond. Un message « Résumé automatique du contexte en cours... » apparaîtra — n'envoyez pas le tour suivant tant que le résumé n'est pas terminé. Après succès, les tours précédents seront condensés en un seul condensé, le tampon sera libéré, et vous recevrez une confirmation « Mémoire du modèle récupérée » avec le nombre de tours condensés.
🚨 ALARME (90%+) — le résumé automatique n'a pas libéré le tampon (cas rare après une panne de l'API). L'envoi du tour suivant est bloqué. Forcez la fin du jeu avec /koniec, puis rechargez-le — le moteur chargera l'état à partir de game.json sans l'historique des derniers tours, le tampon sera frais.

En pratique, le mécanisme de réduction automatique est invisible — le joueur ne sent pas que quelque chose se passe, car le fil de fond résout le problème avant qu'il ne soit remarqué. Il est seulement important de ne pas envoyer le tour suivant pendant le résumé automatique (le bouton "Envoyer" est alors grisé).



ÉTAPE 7 : Avertissement Méta Cinématique — intermède dramatique après le 150e tour

Après 150 tours d'un même jeu, le moteur narratif insérera UNE FOIS un « Avertissement Méta Cinématique » — un intermède dramatique méta-narratif. Il apparaîtra dans une boîte de dialogue séparée avec un son de cloche, avec une adresse directe à vous à la deuxième personne, un résumé des réalisations et un avertissement sur l'importance des décisions prises.

⚠️🚨⚠️ L'Avertissement Cinématique n'est PAS une partie de la narration de l'audiobook — le moteur de filtrage .txt coupe automatiquement son contenu (marqué par des balises ⚠️🚨⚠️), afin que vous n'entendiez pas de méta-commentaire sur votre propre jeu lors de l'écoute de l'audiobook. Le contenu est uniquement enregistré dans le journal .story.jsonl (pour réflexion ou comme souvenir) et dans le dialogue de l'interface graphique, où vous pouvez le lire une fois et continuer.



ÉTAPE 8 : Pont vers le Réalisateur — utilisez le Livre du Monde créé dans les Histoires

Le fichier skrypty/<nom>.md généré pendant le jeu contient le Livre du Monde avec les personnages qui sont apparus dans la narration, avec leurs caractéristiques, accents et personnalités. Le format est exactement celui requis par le parseur du Réalisateur — [Nom : caractéristiques avec description de l'accent].

Ce que vous pouvez en faire :

1. Après avoir terminé le jeu, ouvrez le panneau "🎬  Réalisateur" (Ctrl+1).
2. Chargez le projet du même nom — le Réalisateur chargera le fichier .txt comme histoire et .md comme Livre du Monde.
3. Vous obtiendrez maintenant une narration classique du Réalisateur (longues scènes structurées avec actes et chapitres) avec les accents natifs des personnages que vous avez aimés dans les Histoires. Le garde Karmel du refuge parlant en phrases courtes, l'inquisitrice Rosanna avec un accent chantant de l'Est — toutes les caractéristiques sont conservées.

C'est un pont à sens unique : les Histoires produisent du matériel, le Réalisateur le formate. L'inverse n'est pas possible — le Réalisateur ne charge pas les jeux des Histoires comme état interactif.



ÉTAPE 9 : Accessibilité (NVDA et lecteurs d'écran) — conçu dès le départ

Tout le module Histoires a été optimisé pour les joueurs aveugles. Ce que nous avons fait spécifiquement :

CHAMP DE NARRATION — c'est un wx.TextCtrl en lecture seule multiligne. NVDA lit linéairement toute la narration, vous pouvez naviguer avec les flèches dans le texte, copier des fragments avec Ctrl+C. Le champ n'est jamais éditable — vous modifiez l'histoire UNIQUEMENT par un nouveau tour ou en éditant le fichier .txt en dehors de l'application.

BOUTONS DE CHOIX DYNAMIQUES — dans les modes Choix et Moindre mal, chaque tour crée de nouveaux wx.Buttons dans la zone de choix. Chacun a une infobulle lue par NVDA (« Choisissez : continuez dans la forêt »). Tab entre eux fonctionne naturellement. Enter sur le bouton sélectionné envoie automatiquement ce choix au moteur narratif.

MASQUAGE DES ZONES VIDES — en mode Libre, la zone de choix est COMPLÈTEMENT masquée (wx.Hide), pas seulement grisée — Tab la contourne, NVDA ne l'inclut pas dans la liste des éléments. Cela évite de désorienter le joueur qui tomberait sur un espace réservé vide. Dans les modes 4 et 5, la zone apparaît uniquement après la validation réussie de la réponse du modèle (tableau de choix non vide) ; une hallucination du modèle (choix vides) entraîne un retour au texte libre sans encombrer l'interface.

SIGNAL SONORE — chaque tour terminé est signalé par wx.Bell (cloche système), suivi d'un transfert automatique du focus sur le champ de narration. NVDA lira alors la nouvelle narration sans nécessiter de navigation manuelle.

STATUTS MÉMOIRE COLORÉS — l'indicateur de mémoire du modèle change la couleur de la police (vert/orange/rouge) selon le niveau de remplissage. Pour les utilisateurs voyants, c'est un signal visuel supplémentaire ; NVDA lit quand même le texte du statut, donc les aveugles ne perdent pas d'information.

ACCÉLÉRATEURS CLAVIER — tous les boutons ont un signe `&` devant l'une des lettres de l'étiquette, ce qui active l'accélérateur Alt+lettre. Fonctionne de manière identique aux autres modules de l'application.



Problèmes fréquents

Problème : Après avoir cliqué sur "Nouveau jeu", un message « Clé API manquante » apparaît.
Cause et solution : Le fichier golden_key.env dans le dossier principal de l'application n'a pas de clé OpenAI valide. Revenez à l'écran de démarrage (bouton Accueil), cliquez sur "Générer le fichier golden_key.env et ouvrir l'éditeur de texte" et suivez les instructions (ÉTAPE 2 du manuel principal).

Problème : J'essaie d'envoyer un autre tour, mais le bouton "Envoyer" est grisé.
Cause et solution : Un auto-résumé du contexte ou la génération d'un Avertissement Cinématique est en cours dans le fil de fond. Le statut mémoire affichera « Auto-résumé du contexte en cours… ». Attendez quelques secondes — le bouton se déverrouillera automatiquement après le succès.

Problème : Le message « Mémoire du modèle surchargée » bloque le jeu.
Cause et solution : L'auto-résumé n'a pas libéré le tampon (par exemple, limite de taux OpenAI). Terminez le jeu avec la commande /koniec ou fermez l'application, puis rechargez-la — le moteur chargera uniquement l'état à partir de game.json sans l'historique des derniers tours.

Problème : En mode Choix, le moteur n'a pas généré de boutons, bien que je m'y attendais.
Cause et solution : Hallucination du modèle — malgré le mode 4, le LLM a renvoyé un tableau de choix vide. L'application masque alors consciemment la zone de choix (au lieu d'afficher un espace réservé vide) et permet de continuer avec du texte libre. Le tour suivant générera probablement correctement les choix.

Problème : Les fichiers .game.json et .story.jsonl ne sont pas visibles sur le bureau.
Cause et solution : C'est intentionnel — runtime/ est un dossier système pour les utilisateurs ordinaires, invisible depuis l'explorateur de fichiers. Les fichiers de narration (.txt, .md) vont dans skrypty/ — vous les trouverez là.
