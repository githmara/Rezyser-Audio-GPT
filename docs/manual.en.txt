Audio AI Director Manual - Complete Guide (Version 15.6 – Release Edition)

Welcome to the Hybrid Recording Studio! This toolkit allows for the automatic writing, planning, formatting, and translation of radio play and audiobook scripts. It has been optimized to work with professional speech synthesizers and local screen reader engines (NVDA).

The set consists of the main studio (Direction), a translation and accent tool (Polyglot), a file structure building tool (Audiobook Architect), a Rule Manager (from version 13.0 — without Python, you can add a new accent, cipher, or creative mode, see STEP 7b below), and — from version 15.0 — the Story Module (interactive second-person fiction generated by AI, read by TTS or screen reader, described in a separate manual opowiesci.pl.txt). All five tools are available in a single program window, switchable with buttons on the toolbar or keyboard shortcuts Ctrl+1..Ctrl+5.


STEP 1: First Launch (Cross-Platform)

Download the latest installer from the Releases tab on GitHub (the file Rezyser_Audio_v<number>_Installer.exe) and run it by double-clicking. The installer suggests a default installation location — the Programs folder inside your local user directory — and does not require administrator privileges. You can choose your own path with the "Browse" button; in that case REMEMBER it (you will need it during updates — see "Automatic Updates" below). After installation, launch the program from the desktop icon or the Start Menu. A brief terminal window will open (disappears automatically), and after a moment, the main program window will appear — Audio Director GPT. No browser, no background server. When you're done working, just close the program window.

The entire application — the Python engine, your projects, and the API key — lives inside a single folder under the installation path, so the whole folder can be moved to a USB stick, to the cloud, or to another computer (detailed instructions in the "Moving Projects and API Key" section below).


Important: The runtime/ folder inside the installation folder contains an isolated Python environment ready to use without a separate system-level installation. If you clone the repository (developer path), this folder is not present and should not be — you will then use the virtual environment venv described in the developer section below.

--- For Developers (Windows — Git Repository) ---

1. Clone the repository to your disk.
2. Run the setup_dev.bat file. The script will automatically create a Python virtual environment (venv) and install all required dependencies from the requirements.txt file.
3. Launch the application with the command python main.py or via the run_dev.bat file — the script will automatically detect the venv folder and start the program.

--- For Developers and Regular Users (macOS / Linux) ---

1. Clone the repository to your disk.
2. Open a terminal in the project folder and grant execution permissions to the scripts: chmod +x *.sh
3. Run the setup script: ./setup_dev.sh — the script will create a venv environment and install the dependencies.
4. Launch the application: python main.py or ./run.sh

What you'll see upon launch: After starting the program, a window with the start screen opens. You will find a brief description of the available tools and the "System Check" section. If the API key is not yet configured, you will see a red message indicating that AI-based modules (Director, Translator) will not work — free local features (accents, Architect) are active immediately. The API key configuration is described in the next step.

Automatic Updates

The application checks at startup if a newer version is available on GitHub — the check is performed in the background and does not block the interface.

If you installed the program via the ready-made installer (.exe): upon detecting a newer version, a window will appear asking if you want to download it. After confirmation, a progress bar will start, and when the download is complete, the application will close automatically, and the new installer will launch by itself. IMPORTANT: in the new installer window, make sure the proposed installation path is THE SAME as during the first installation (usually visible in the "Destination Folder" field). If you accept the default proposal but originally chose a different location with the "Browse" button, you will end up with a SECOND empty installation without your projects and API key — the first one still sits in the old place, but the desktop shortcut and the one in the Start Menu will be replaced to point at the new install. If you accept the same path as before, the installer overwrites the application engine files and the whole rule pack (folder dictionaries/) — your projects (folders skrypty/, opowiesci/) and API key (golden_key.env) remain intact. WARNING: if you edited via the Rule Manager any files that exist in the package (e.g. accent tweaks in `dictionaries/pl/akcenty/wloski.yaml`), those edits WILL BE OVERWRITTEN by the update — before confirming the update, back up the `dictionaries/` folder using the procedure in "Moving Projects and API Key" below (just copy the `dictionaries/` folder to a USB stick), and after the update paste it back over the new files. Completely new rules you created from scratch that are not in the package (e.g. an additional base language or a brand-new cipher) are kept automatically — the installer never deletes files that are not in the package. As of version 15.2.8 the update prompt itself displays this warning inline and includes an „Open dictionaries folder" button that opens Explorer at the right location with a single click — just press it before confirming the update to make a backup conveniently, then return to the dialog and click „Download and install".

If you do not remember your installation path, there are two quick ways to recover it. Windows 11: in the context menu of the desktop shortcut choose "Open file location" (if the option isn't visible in the new reduced context menu, pick "Show more options" first, or press Shift+F10 twice to go straight to the full menu), go one level up with Backspace, select the application folder and press Ctrl+Shift+C (or choose "Copy as path" from the context menu) — the full path lands in the clipboard wrapped in quotation marks (when pasting it into the installer, remember to strip those quotation marks). Older Windows versions (7/8/10): right-click the shortcut and choose "Properties"; in the "Shortcut" tab, the "Target" field shows the full path to the program's launcher file (`.exe` in v15.2.5+ or `run.bat` in older versions) — copy it and delete the trailing filename, leaving the bare installation folder path.

Note when upgrading from older versions (v15.2.4 or earlier, when the app launched via `run.bat` from the Portable ZIP package): your existing desktop shortcut may point at `run.bat` in the old location, which no longer exists after upgrading to v15.2.5+ — versions 15.2.5+ use a standalone `.exe` created by the installer. If your shortcut stops working after the upgrade, delete it manually and let the installer create a fresh one during the next install.

If you are using the Git repository (developers and macOS/Linux users): instead of a download proposal, you will see information about the new version with a direct link to the release page on GitHub. Download the "Source code" archive from there or update the repository with the command git pull.

Moving Projects and API Key (migration)

If you want to move your projects, API key, and local settings to another computer (or restore everything after reinstalling Windows), there is no need to copy individual files manually — the whole application folder is self-contained.

1. Make sure the application is COMPLETELY closed. If you see the program icon in the system tray (next to the clock, on the right side of the taskbar), right-click on it and choose "Close". Open files block copying.
2. Locate the Audio Director GPT shortcut on the desktop. Right-click on it (or press the Application key, or Shift+F10 when navigating with NVDA) and choose "Open file location". NOTE on Windows 11: in the new reduced context menu this option may be hidden — pick "Show more options" first (or press Shift+F10 twice to open the full menu with the option straight away).
3. A Windows Explorer window opens in the program's installation folder. Press Backspace (simplest, always works) or click the "Up" arrow on the toolbar, to go one level up — you will see the full application folder. Note: the Alt+Up shortcut only works when focus is on the file list — if Explorer opens with focus on the address bar (the typical case), Alt+Up does nothing; use Backspace instead.
4. Copy the whole folder to a USB stick, a cloud drive (OneDrive, Google Drive, Dropbox), or an external disk. The folder contains everything needed to restore your working state:
   - Your projects (folder skrypty/ — narrative .txt files, World Book .md files, _streszczenie.txt summaries; folder opowiesci/ — interactive games).
   - Your API key (the file golden_key.env in the main application folder).
   - Your custom phonetic rules, accents, ciphers, if you edited anything in the Rule Manager (folder dictionaries/<language_code>/, e.g. dictionaries/pl/akcenty/wloski.yaml).
   - Application preferences and creative mode selections (folder runtime/skrypty/, .mode files).
   - The isolated Python environment (folder runtime/), so you do not need to install anything extra on the new computer.
5. On the new computer: download the latest installer from the Releases tab on GitHub and install the application normally. Launch it once so that it creates the empty configuration file structure. Close the application. Then either copy the previously saved folder over the new installation overwriting files — or selectively pick only the folders you care about (skrypty/, opowiesci/, golden_key.env) and paste them into the corresponding locations of the new installation.

Tip for NVDA users: the context menu "Open file location" reached with the Application key is fully accessible — NVDA reads each item natively. After Explorer opens in the target folder, use Backspace to go one level up (always works regardless of whether focus is on the file list or the address bar), then Ctrl+A to select everything and Ctrl+C to copy.

Tip: "Open file location" is the native option name on an English Windows installation. On a Polish system it reads "Otwórz lokalizację pliku", on other locales — the analogous wording in the operating system's local language.

STEP 3: Main Directing Studio

This is your command center for creating stories and writing scripts. Access it by clicking the "🎬  Director" button on the toolbar or selecting Tools → Director from the menu (shortcut: Ctrl+1).



IMPORTANT: Project File Format — Return to .txt

In version 7, project files were saved in Markdown format (.md), e.g., skrypty/anesthesia.md. This was a deliberate experiment — the .md format was intended as a psychological barrier for non-technical users, discouraging them from opening and manually editing the file in Notepad (thus preventing accidental damage to the structure headers).

The experiment did not work. AI often inadvertently breaks one of the fundamental prohibitions (more on that shortly). For this reason, version 8 reverted to simple .txt files — more intuitive and readable for everyone. For example, a project named "anesthesia" will now be saved as skrypty/anesthesia.txt, and its summary as skrypty/anesthesia_streszczenie.txt. This will allow everyone to easily make directorial corrections or text cuts on the fly.


⚠️ CRITICAL EDITOR RULE (READ BEFORE YOU START!) ⚠️

All your generated scripts and books are saved in plain text files (.txt), which you can easily open in Notepad.

As a Director, you have FULL RIGHT (and indeed an obligation) to edit this file! If the artificial intelligence gets ahead of itself and, for example, resolves the characters' problems at the end of a generated fragment, open the file, delete the last lines, and leave the text cut off at the most tense moment before clearing the memory, reloading the file to refresh the context window, and clicking "Send to AI" to continue.

🔴 HOWEVER - WHAT YOU MUST NOT TOUCH:

Never modify, delete, or change lines containing the structure (e.g., Act 1, Scene 2, Chapter 1, Prologue). If you mess up these headers:
1. Your story will fall apart in screen readers (NVDA).
2. The audiobook architect, and consequently Studio Eleven Labs, will not be able to correctly divide your book into reading fragments.
3. The application's internal Converter will not generate a correct table of contents in the Word file or on the timeline in ElevenLabs.

Edit dialogues, cut action, but leave the structure alone!


How to Use Directing?

- World Book (sidebar on the left): Here you enter the rules of the universe. Each project now has its own Book linked to the file name — if your story file is, for example, emilia_heist_audiobook.txt, the World Book will be saved as skrypty/emilia_heist_audiobook.md. Therefore, the order is important: first enter the project file name in the "Project File Name" field, and only then can you save the Book. The "💾 Save the Book Permanently" button remains grayed out until you provide a name. Loading an existing project with the "Load History" button will automatically load the corresponding .md file — you don't have to do anything manually. Note: Without a filled World Book, the application will block sending queries to AI — this is a deliberate safeguard to protect you from generating text without any rules.
- Long-Term Memory (sidebar on the left): The second field in the sidebar. Here, AI automatically saves a summary of the plot when memory starts to overflow. You can also manually enter your own notes here — the model will treat them as "what I already know" before reading the current scene. HISTORICAL GAP (fixed in v15.5): previously, if you typed a very short note here and clicked "Save Summary (permanently)" before there was anything meaningful in the narration file, the next time you loaded the project the application would PRIORITIZE the summary and SKIP the full history — the model then received only the World Book and a one-sentence note, with no context for the tone or the latest scenes. Since v15.5, loading is intelligent: if the entire history fits within the context window, it is loaded in full (and the redundant old summary is deleted), so the model never loses context. And after manually editing the narration file in an editor, use the new "Refresh from disk" button (since v15.5), which synchronizes the internal memory with the disk in a single click; to simply open the file in the editor, "Open narration file…" is still the button to use.
- Brainstorming Mode: Enter a loose idea, and AI will give you 3 options for plot development. For each option, it will immediately generate a ready block "--- PROMPT SKETCH ---". After choosing one, paste this prompt into Script or Audiobook Mode and make any comments or information for the model. The plot memory does not change during Brainstorming — you can experiment without risk!
- Raw Script Mode: You paste the "Prompt Sketch" generated in Brainstorming here. AI will write a long fragment with full tags [Speaker X: Name - emotion] for dialogues and effects [SFX: ...] for sounds. The text is automatically appended to your file (e.g., new_scene.txt) in the skrypty/ folder.
- Traditional Audiobook Mode: A mode for writers. AI generates pure literary prose — zero tags, zero phonetics, classic dialogues woven into the narrative. The text is appended to the file just as in Script Mode.
- Automatic Character Creation: The script is programmed to automatically create new [Speaker] tags if the plot requires a new character. Tip: If AI creates a cool character, copy its tag and paste it into the World Book so the model remembers it permanently!

Project Management — three action buttons:
- Load History: Loads an existing project into memory. Available when the current memory is empty. From version 15.2.3 it supports two paths: if the project name field is empty, a selection dialog opens with a list of all projects found in the skrypty/ folder (summary files are filtered out) — NVDA reads the list naturally, the player doesn't have to remember and retype the name from the keyboard. If the name field is filled, the application tries to load a project with that name directly (expert path: Enter in the name field or click after typing from memory).
- Clear Current (Keep Summary): Clears only the current story. The Summary in Long-Term Memory and the World Book are preserved — ideal for continuing a long book after generating a summary.
- Close Project (Hard Reset): Completely clears the project. Deletes the story, summary, World Book, and resets all counters. Use when changing the project or starting a new story.
- Open narration file… (since v15.2.3): Emergency editing of the narration file in the system text editor. Requires a project name in the field. The application opens skrypty/<name>.txt in Notepad (Windows), TextEdit (macOS), or the default GUI editor (Linux). Typical scenarios: (a) AI doesn't close a scene and you want to write the ending manually; (b) you loaded a project with a summary and want to copy the last scenes into Long-Term Memory so the model has the full tone context (architectural gap described above); (c) you want to make a textual cut in the middle of a chapter that the application engine doesn't support natively.
- Refresh from disk (since v15.5): Synchronizes the application's internal memory with the narration file after you have edited it by hand — without a hard reset and a full reload of the project. It decides for itself: if the entire history fits within the context window, it loads it in full (and deletes the redundant old summary, so the engine works on the complete text); if the history is long and has a saved summary, it keeps the summary untouched and restores only the fresh ending, counted from the last structure header (Act/Scene/Chapter) — which is why it pays to keep the structure. It does not change the World Book or any counters. Typical scenario: the AI mistakenly closed a scene (broke anti-closure), you cut off the bad ending in the editor and click Refresh — no more fixing the same thing in two places.

Historical Note — why modes are now protected from accidental change:
In earlier versions of the application, no one monitored the consistency of the creative mode within a single project. The result was a certain subtle creative possibility that could be described as follows: you start a story in Script Mode, insert "Act 1" and "Scene 1" (the application is delighted with your consistency), generate a few screens of tension with tags [SFX: Door slam] and [Speaker 1: Mark - resigned]... and then — because inspiration just struck — click "Insert Chapter 1 cut." The application, without batting an eye, appends the "Chapter 1" header to the file, right after "Scene 3." You now have a hybrid of a 1950s radio play and a social novel in the file. ElevenLabs looks at this structure, sees a chapter header in the middle of an act, and decides it's probably a glitch in the matrix. The table of contents looks like the work of an avant-garde artist. The Audiobook Architect, on the other hand, assumes you're an adult and just processes it without a word — but also without any guarantees of the result. From version 12.0, the interface tried to block changing the recording mode — at least in theory. Practice turned out to be more creative: Brainstorming (always active as a planning mode) was a back door through which, using the up and down arrow keys, you could move between Script and Audiobook (Audiobook → Brainstorming → Script and analogously in the opposite direction). The first click on "Insert Act 1" or "Insert Chapter 1" in the newly selected mode smoothly overwrote the .mode file, mixing acts with chapters in a single narrative file. Only from version 15.2.3 do we have real protection: once the mode decision has been locked in (first structure marker or first successful production send), the second recording position in the RadioBox is genuinely disabled. Brainstorming remains always active as an emergency mechanism — it generates a summary when the context window fills up and produces plot options — but you can no longer use it as a sideways jump to a different recording mode.


Showrunner Prompts — AI as a TV Series Scriptwriter (from version 7, retained)

This is the biggest change introduced in version 7, retained without changes. It is not visible in the interface but radically changes the quality of the generated plot.

A showrunner in the television industry is responsible for the overall series — ensuring that the plot never leads to an easy resolution but constantly thickens, builds conflicts, and keeps the viewer in suspense for many seasons. In version 7, this philosophy was directly embedded in the AI's system instructions.

Anti-Closure Directive — state in version 8

Despite testing various approaches, the Anti-Closure ban is often notoriously broken by the model, especially in Traditional Audiobook Mode. AI has a strong tendency to "close" stories at every opportunity — it weaves summary sentences into the plot, creates false happy endings, or closes threads in the middle of a chapter, as if each fragment were the last. The effect is that the next fragment starts from scratch, without natural continuity.

That's why the editor's rule described above is so important: if AI breaks the ban and closes the scene itself, your task as a Director is to open the .txt file, remove those last sentences, and leave the text cut off at a tense moment before reloading it back into the application.

Each mode has a built-in Anti-Closure directive:

- Brainstorming: AI acts as a multi-season TV series scriptwriter. Each of the 3 proposed options MUST build obstacles, introduce new dilemmas, open threads, and cliffhangers. An absolute ban on proposing options where characters permanently reconcile, overcome the main obstacle without significant consequences, or the story leads to a hasty end. A ban on inventing cheap, magical locations that break the world's architecture.
- Raw Script Mode: An absolute ban on ending the text with summaries, morals, or closures. AI must naturally cut off the action at a tense moment (cliffhanger), avoiding conclusions so that the next fragment can smoothly take over the narrative.
- Traditional Audiobook Mode: An absolute ban on ending the text with pathetic summaries, closing threads, or suggesting the end of the story (e.g., "She was ready for new challenges," "She realized it was time to move on"). The text must cut off in the middle of ongoing action, tension, or an open thought.

Exception to the rule: If you explicitly ask for an ending, finale, or epilogue, AI will generate a satisfying closure to the story — the ban does not apply when you ask for it.


Managing Acts and Scenes (Script Mode, from version 7, retained)

Raw Script Mode has a dedicated "✂️ Structure Management" panel with buttons for building the radio play structure in real-time.

- Insert Act X: Inserts an act header (e.g., "Act 2") AND automatically appends "Scene 1" under it — because every new act starts with the first scene. The act counter jumps to the next number, and the scene counter resets to 2 (ready for the next scene in this act).
- Insert Scene X: Inserts only the scene header (e.g., "Scene 3") within the current act. The scene counter increases automatically.

Intelligent File Loading: When you load an existing script file, the application will automatically scan it and set the act and scene counters to the correct numbers. The scene counter is always calculated within the last act in the file.

Prologue and Epilogue: The "📜 Insert Prologue" and "🏁 Insert Epilogue" buttons are common to both modes and available in the same panel.

The Audiobook Architect will automatically convert Acts into main navigation points (Heading 1) for ElevenLabs and NVDA — Scenes will become bold text visible in the document but invisible in the table of contents.


Intelligent Chapter Management (Audiobook Mode, from version 5, retained)

The LLM generates a maximum of about 5000 characters per query — not enough for a full chapter. Therefore, you work iteratively: generate successive fragments with the "Send to AI" button until you decide that a given chapter is ready. Then click "Insert Chapter Cut" — the application appends a header to the file and memory, and the chapter counter automatically jumps to the next number.

Buttons in the panel:

- Insert Cut (Chapter X): Inserts a header (e.g., "Chapter 3") into the file and memory. The chapter counter updates automatically.
- Insert Prologue: Works only at the beginning when the memory is empty. A safeguard against accidentally inserting a Prologue in the middle of the story.
- Insert Epilogue: Closes the story. After inserting the Epilogue with content, the application will block generating new fragments — this is intentional because after the story ends, there's nothing more to add.

Intelligent File Loading: When you load an existing file, the application will automatically scan it and set the chapter counter to the correct number. If the file has a Prologue and three chapters, the counter will show "Chapter 4" — no manual counting required.


Plot Accumulator — How AI Memory Works

Only the pure text of the story enters the model's memory — what the AI actually wrote. Instructions, options, and plans disappear after use and do not clutter the context. The effect? The model maintains focus longer, remembers character accents better, and less frequently "escapes" from the rules of the World Book.

The "Model Memory" indicator on the screen shows how much space your story already occupies:
- Green (up to 150,000 characters): The model is fully focused, you have a safe buffer.
- Yellow (150,000 – 175,000 characters): You're approaching the limit. AI may start shortening statements and ignoring rules. Begin slowly closing the thread.
- Red (over 175,000 characters): Critical overload!

Infinite Memory (from version 6, retained)

When the red alert lights up, you no longer have to manually copy the summary. Enter a command in Brainstorming containing the word "summary" — AI will generate a concise capsule of knowledge about the entire plot so far. Then click the "Save Summary (permanently)" button — the application automatically creates a _streszczenie.txt file in the skrypty/ folder and protects it from accidental overwriting. After saving, clear the memory and you can continue creating in the current file. Load the summary into the Long-Term Memory field before the next session — and you can continue the story indefinitely, without any length restrictions.

When to summarize (updated in v15.5): You no longer have to watch a rigid character threshold "before pausing work". It is best to summarize after the natural close of a larger structural part — after finishing a scene, an act, or a chapter. The reason: when you later manually fix the ending in the narration file and click "Refresh from disk", the application precisely restores the fresh fragment counted from the last header — while the summary of the earlier part stays untouched. This is all the more reason to keep the structure: regularly insert Act/Scene/Chapter headers from the structure panel (long forms with no acts or chapters at all, e.g. a single-stretch "modernist drama", are discouraged). EXCEPTION: if you are running a very long story COMPLETELY without headers, generating and saving the Story Summary before a break remains necessary — without markers the application can only restore the last fragment counted in characters.

Automatic Summarization: When memory enters an alarm state, Brainstorming automatically switches to emergency mode — instead of generating options immediately, it first creates a detailed summary of the entire plot so far and saves it in <SUMMARY> tags. The application detects these tags and automatically transfers the summary to the Long-Term Memory field. Zero manual work!

Intelligent loading and refreshing from disk (updated in v15.5): Both when loading a project and after clicking the new "Refresh from disk" button (after manually editing the narration file in an editor), the application decides for itself how to reconcile the memory with the disk. If the ENTIRE history fits within the context window — it loads it in full and deletes the redundant old summary, so the engine works on the complete text (this closes the old gap in which the model received only the summary without the context of the latest scenes). If the history is LONG and has a saved summary file — it keeps the summary untouched and inserts into the Current Memory only the fresh ending, counted from the last structure header (Act/Scene/Chapter). This way you don't waste tokens reloading the whole story, and at the same time the next summary is not built on stale data.


STEP 4: Postproduction in Directing

After writing the story, you have a postproduction tool available at the bottom of the Directing panel (it appears only in Audiobook Mode).

Assigning Chapter Titles (Audiobook Mode)

The AI will analyze the entire story and suggest descriptive, literary titles for each chapter (as well as any Prologue and Epilogue). The module iterates through the chapters from the saved file and assigns them a short title by analyzing only the beginnings of each chapter (up to 6000 characters). It returns only a numbered list of titles — without rewriting the book's content.

Note: The module requires the file to already be saved on disk (generated or loaded). If the file does not exist, the application will display an appropriate message.


STEP 5: AI Polyglot

An application for translations and enforcing strong accents on screen reader synthesizers. Access it by clicking the "🌍  Polyglot" button on the toolbar or selecting Tools → Polyglot from the menu (shortcut: Ctrl+2).

Mode 1: Regular Translator (Uses AI - Paid)

Ideal for listening to stories in beautiful, correct foreign language.

- Load a file using the "Load file into memory" button or by using the "Browse..." button to select a file in the system window.
- Select the "AI Translator" mode, enter the target language (e.g., "Finnish").
- The script will translate the content. If you load an .html file, it will only translate the text visible to the reader and update the language code in the html tag.
- If you load a plain .txt or .md file (e.g., a script generated by the Director), the script will automatically save the result as an .html file with an embedded language tag after translation — ready for reading by NVDA without any additional work.
- Also supports .docx files.

Intelligent block division: Long texts are automatically divided into blocks of up to 10,000 characters and translated sequentially with a progress bar.

Crash-resistant progress saving (NEW in version 9): Each translated block is immediately saved to a hidden temporary file in the application's system folder. If the translation is interrupted due to API limit exhaustion, upon the next launch, the application will automatically detect this file, restore the already paid progress, and calmly complete the work from where it left off — without any manual copying. Upon successful completion, the temporary file is automatically deleted.

Why is this important? In version 8, the approach to resuming translation had a critical, silent bug: if you didn't rename the file with the partial translation and cut out the translated fragment according to the instructions, and then immediately resumed translating the rest — the application would open the output file in overwrite mode. The paid progress would be irretrievably and unknowingly erased before you noticed anything. Version 9 completely eliminates this trap: the save is permanent after each block, regardless of what you do afterward.

Mode 2: Director Mode / Accents (Free - Works Locally)

A tool for "spoiling" text. Forces broken Polish on synthesizers.

The integrated Director Mode dropdown menu allows you to select an accent directly from one list. Available options include:
Polish (Ewa in Vocalizer, Paulina in OneCore)
Russian (Milena — Vocalizer/Apple, Irina / Pavel / Yuri — OneCore, eSpeak)
French (Thomas / Amelie — Vocalizer/Apple, Julie — OneCore)
German (Markus / Stefan — Vocalizer/Apple, Hedda / Katja — OneCore)
Spanish (Jorge / Monica — Vocalizer/Apple, Helena — OneCore)
Icelandic (Gudrun — OneCore, eSpeak; note: Vocalizer does not have this language!)
Italian (Alice / Luca — Vocalizer/Apple, Elsa — OneCore)
Finnish (Satu / Mikko — Vocalizer/Apple, Heidi — OneCore)
And two cleaning options without accent:
"None (Cleaning WITHOUT number normalization)"
"None (Cleaning WITH number normalization)"
The option with number normalization automatically converts digits to their word form (e.g., 15 becomes "fifteen") before processing — this way NVDA reads numbers smoothly, and if the text has a forced accent, the number will also have it, without any exceptions.
You might ask if the synthesizer will be able to inflect such normalized numbers depending on the context? The answer is: no. And this is an intentional feature. As is widely known: "Polish language is difficult" — and a foreigner mangling our grammar only adds authenticity to the broken accent!

Tag Fixer (NEW in version 9): At the end of the list, you'll find an additional option — Tag Fixer. It does not apply any phonetic rules or cleaning. It does one thing: injects the two-letter ISO language code you provide (e.g., "fi" for Finnish, "en" for English) into the file. It is useful when you already have a ready file — e.g., previously translated by the AI Translator — but for some reason, it came out with an incorrect or missing language tag. Instead of translating it anew, simply run the Fixer with the correct ISO code, and in a moment, you have a correct file.

The script cleans parenthetical director's notes — removes entire text fragments enclosed in round brackets (e.g., "(with interspersed breaths)", "(whispering)", "(ironically)"). ElevenLabs should read only dialogues and narration, not director's instructions interwoven in the text.

The script also cleans Markdown tags — removes header hashtags (e.g., #, ##, ###), equal signs used as header underlines, and orphaned commas that could disrupt the reading rhythm by the synthesizer.

- Protective shield: The script protects all HTML tags. It only spoils dialogues and narration.
- Works locally and costs nothing!

Cipher: Text Reverser

The Reverser cipher expands English abbreviations before reversing the sentence — without expansion, dotted abbreviations would reverse into phonetic nonsense (English example: ".g.e" becomes "e.g.").

Mode 3: Cipher (NEW in 13.0 — text play, free, local)

The third RadioButton in Polyglot, next to AI Translator and Director Mode: "Cipher Mode (text play, random stuttering)". It activates six local text-distorting algorithms — for fun, puzzles, and language games. After selecting the mode, a dropdown list of algorithms appears, and for one of them (Caesar Cipher), an additional numeric field for the shift.

Available algorithms (select in the menu "Choose a distorting algorithm"):

- Text Reverser (Reading backwards with a capital letter) — each sentence is reversed character by character, keeping the period/exclamation/question mark at the end and a capital letter at the beginning. Before reversing, the script expands popular abbreviations (e.g., i.e., etc., U.S., U.K.), so the result still makes sense after reversing — without this, "e.g." would reverse into the nonsensical ".g.e".

  Inspiration: a mission from the program "The Traitors". When the host unexpectedly showed participants a popular Polish song from a cartoon — just played backwards — reactions were like "what language is this?", "it must be Armenian", "Hungarian or Finnish". The actual mission was that one team received the song's lyrics written backwards in the forest, had to sing it in this reversed form, the other team recorded it, played it from the end — and theoretically recovered the original song to guess. Our Reverser generates exactly the same funny phonetic misunderstanding when you run the processed file through a TTS synthesizer.

- Typoglycemia (Scrambled word middles) — a classic psycholinguistic effect: "Aoccdrnig to a rscheearch at Cmabrigde Uinervtisy, it deosn't mttaer in waht oredr the ltteers in a wrod are, the olny iprmoatnt tihng is taht the frist and lsat ltteer be at the rghit pclae." The script randomly scrambles the middle of each word longer than 4 characters, leaving the first and last letter untouched. Great for testing "how much do I really see, and how much does my brain guess."

- Broken Telephone / Snake Dialect — each "s", "z", or digraph "sz" is randomly elongated into a hiss of 4-8 characters ("ssssss", "zzzzzz", "ssssssz"). Inspiration: Snecko from the game "Slay the Spire". Effect: the text sounds as if read by a snake with a speech impediment.

- Vowelizer (Everything booms on "O") — every vowel in the text is replaced with "o", preserving Polish softening. "Dzień dobry" → "Dźoń doboro". The longer the text, the funnier the effect (and a screen reader reads it with full conviction).

- Strong Stuttering / Broken Robot — attaches stuttering at the beginning of words: "co-co-co-computer", "sh-sh-shower". For short words (less than 3 characters), the algorithm skips them. If the second letter of the word is a consonant, it repeats the first two letters (more natural effect); if a vowel — it repeats only the first.

- Caesar Cipher (EN alphabet shift) — a classic substitution cipher: each letter is shifted by N positions in the English alphabet (ABCD…XYZ, 26 characters). You enter the shift value in the numeric field "Caesar Cipher Shift (0 = random, range -25…25)". If you enter 0 — the application will randomly select a shift in the range 1-24 and display it in a message after completion (so you can decrypt it later). Characters outside the alphabet (numbers, punctuation, spaces) remain unchanged.

Practical application: ciphers save the result in the same format as Director Mode (.html with a lang tag or .docx with XML tags), so NVDA reads them with the appropriate language voice. Especially the Reverser and Vowelizer sound much more interesting in a synthesizer than when you read them with your eyes — because the brain automatically tries to "decode" the text when reading visually, while TTS reads it exactly as written.

All six ciphers are also described in broader, accessible language in the file docs/dictionaries.pl.txt in the application package — along with tips on how to add your own cipher type "letter substitution" without programming knowledge (e.g., school slang, gibberish).


Language Detection

Before the script "distorts" the text, it checks which language it is written in. If it detects that it is not Polish, it will display a warning. The phonetic rules are tailored for Polish — applying them to a foreign language text would yield unpredictable results.

Automatic Language Switching in NVDA — What You Need to Know

For NVDA to actually switch voices based on the lang tag, the setting "Automatically switch language when supported" must be enabled. You can find it in NVDA Preferences → Speech. By default, it is enabled upon the first launch of the reader — but it's worth checking if someone has turned it off.

Important limitation of OneCore voices: Microsoft OneCore voices do not natively support this mechanism with NVDA, only with the built-in Windows narrator. There is an unofficial NVDA add-on called "One Core Autolang" that attempts to fix this — but its development was quickly halted. The reason is simple: every year, with the first NVDA version of the year, there are changes that break API compatibility (so-called API Breaking Changes). Sometimes it's enough to update the "last tested version" field in the add-on's manifest, but sometimes real changes in the code are required — and the author can't keep up with updates. If you care about automatic language switching, safer choices are Tiflotecnia Voices (paid, section above) or eSpeak (free, lower quality), which support this mechanism natively — but note: currently in Tiflotecnia Voices, it works with a priority bug (see "Critical Catch" below). After applying the patch, automatic switching works flawlessly, as in the old Vocalizer.


Critical Tiflotecnia Voices Catch: Broken Language Detection

First, the good news — the NVDA 2026.1 alarm from previous manual versions ended on a happy note: Cerrence provided 64-bit libraries, Tiflotecnia released them in a .nvda-addon package available in the Add-on Store (section above), and Vocalizer for those who kept it until the end returned under a new name — with better quality and without 32-bit limitations.

However, with the release of Tiflotecnia Voices, a new critical catch emerged — in language detection. In the add-on settings, you can configure which voice should be used for specific letters (e.g., Latin, Cyrillic) depending on the installed voices. The problem lies in the priority order: currently, it first applies an override per letter, then falls back to the ISO language code (practically unreachable for the SAME alphabet to which the override has already matched), and finally the selected voice. The effect appears within the same alphabet: you have Finnish text with the correct `lang="fi"` tag, Satu installed as the Finnish Tiflotecnia voice, BUT in the settings, a Polish voice is set for Latin letters — Satu WILL NOT read this text, despite the correct ISO tag. The per-letter "Polish voice for Latin" override wins at the first level, and ISO `fi` is never checked. For different alphabet pairs, the mechanism works correctly (Russian text + Milena for Cyrillic + Polish voice for Latin — all Cyrillic goes to Milena, any Latin proper names with the Polish voice; each alphabet stays in its override). After migrating from Vocalizer, where language switching based on ISO worked flawlessly, users will notice this regression immediately — especially those who use several European accents (Satu, Alice, Markus) in Polyglot on the same Latin letter pool.

Diagnosis and patch: I diagnosed the issue at the Python level in the add-on code and prepared a patch changing the priority order to: ISO → selected voice → letter override. The patch retains useful switching to Latin for Latin names in Russian text when "language detection based on Unicode characters" is enabled in the settings. I sent the patch to Tiflotecnia developers 5 days ago — no response yet.

What to do in the meantime: if you care about correct language detection (it's worth it — it was one of the killer features of the old Vocalizer, see "Killer Feature for the Blind" above), open an issue in the application's GitHub repository with the label `tiflotecnia-patch` and your email address in the content. It's a good idea to add a short description of your problem in your own language (2–3 sentences are enough) — the bot will detect the language (supported: Polish, English, German, Spanish, Finnish, French, Icelandic, Italian, Russian) and reply in the same one; without a description or in another language, the reply will come in English. An automatic bot will immediately close the issue with a confirmation of submission (without a trace in the public thread), and you will usually receive the patch privately via email within a few days. The patch itself is NOT published in the application repository or as a Gist — Tiflotecnia Voices for NVDA is commercial software, and the add-on license does not allow redistribution of its files, even modified. After receiving the patch, its contents must be copied to `%appdata%\Roaming\nvda\addons\TiflotecniaVoices`, replacing the files. Be careful when copying: if Windows did not ask for a replacement, you most likely copied the entire `TiflotecniaVoices_edits` folder with its contents INSTEAD of just the contents — in such a case, go into the created subfolder, cut everything, paste it one level up, and overwrite. After successfully applying the patch, restart NVDA — enjoy better quality Cerrence 64-bit voices and correct language detection, a combo not available from any single manufacturer on the market. We assume, of course, that you have a valid Tiflotecnia Voices license — we do not verify this, but you won't be able to apply the patch to someone else's folder without a license.


STEP 6: Audiobook Architect

A tool for preparing a professional file structure for screen readers and ElevenLabs. Access it by clicking the "📄  Converter" button on the toolbar or selecting Tools → Converter from the menu (shortcut: Ctrl+3).

How does it work?

1. Enter the path to the source file in the text field or click the "Browse..." button to select a file in the system dialog. The script accepts .txt, .docx, as well as .html and .htm files.
2. Click "Build Architecture for ElevenLabs".
3. The script will scan each line of text and convert keywords (Act, Chapter, Prologue, Epilogue, Foreword) into "Heading 1" headers in the Word document.
4. Scenes (lines starting with the word "Scene") are converted into bold text — visible in the document but invisible in the ElevenLabs table of contents.
5. All remaining text (dialogues, descriptions) passes unchanged.
6. You will receive a file named architektura_[original_name].docx — a professional Word document ready for further work. For example, if your input file was named anesthesia.txt, the resulting file will be named architektura_anesthesia.docx and will appear in the same folder as the original.

Incidental Cleaning: The script automatically removes HTML tags (if the text comes from a browser or a local .html file, e.g., generated by Polyglot) and Markdown header markers (e.g., ### or ####) before processing. You don't need to clean the file manually.

Story Mode: Automatic grouping of turns into scenes (from v15.1)

If you load into the Architect a file opowiesci/<game>.txt generated by the Interactive Stories module, the converter will recognize turn markers (e.g., "--- Turn 7 ---") in 9 languages (Tura, Turn, Runde, Turno, Vuoro, Tour, Umferð, Turno, Ход) and every five turns will insert a new first-level header in the form "Scene N" (the number starts from 1, local for the given language — in English "Scene N", in German "Szene N", etc.). The remaining turn markers are stripped — they do not appear in the audiobook narration because "Turn 7" spoken by TTS breaks listener immersion. The result is a Word file with a natural division into scenes of a few minutes of audio each, ready for import into ElevenLabs. The mechanism is auto-detecting — ordinary audiobook files without turn markers (classic narration from the Director) are processed exactly as before.

A powerful advantage for NVDA and ElevenLabs users

"Heading 1" formatting for chapters is not just about aesthetics. In NVDA, you can navigate through headers instantly by pressing the H key (or 1 for first-level headers). Instead of scrolling through hundreds of pages, you jump from chapter to chapter in a fraction of a second. This changes the way you work with long documents. In ElevenLabs, you are assured that the engine will automatically insert cuts and will not hang during the directing of audio clips.


STEP 7: How to Write the Book of the World (Architect Prompt and Markdown Mini-Course)

The artificial intelligence powering the Main Studio best understands commands when formatted in Markdown markup language. If you provide the AI in the Director with just a loose idea (e.g., "two sisters in the afterlife"), the machine will panic due to lack of details and create a banal, predictable story, ignoring logic.

STEP 7b (addendum): The order of `zamiany:` rules matters

Files in `dictionaries/<code>/akcenty/*.yaml` contain a list of `zamiany:` rules — `wzor → zamiana` pairs (pattern → replacement) that the engine applies SEQUENTIALLY. Each rule operates on the output of the previous one. This lets you build pipelines like "break the digraph `szcz` into `shch`, then turn the resulting `ch` into `h`", but it also opens a classic trap for the language pack author.

The "sequential loop" trap. Say the author of a Spanish accent (meant to make Polish "ñ" sound right for Diego/Loquendo) adds two rules:
1. `ñ → nj` (so Polish "ñ" sounds like a soft "nj")
2. `j → x` (so Polish "j" sounds like Spanish "j" — phonetically /x/)

After running the app, words containing "ñ" come out as "nx", not "nj". Why? Because when the first rule turns "ñ" into "nj", the new "j" is immediately caught by the second rule and turned into "x". Result: instead of the intended "ñ → nj", you get "ñ → nx".

Ordering rule (general). When one rule introduces a character that another rule uses as a pattern, ORDER MATTERS. Safe heuristic: FIRST replace the TARGET (the character later used as a `wzor` in another rule) with something safe, ONLY THEN introduce the SOURCE (the character that decomposes into the TARGET). For the Spanish example, the correct order is: first `j → x`, then `ñ → nj`. Result: "ñ" produces "nj" (the second "j" is no longer eaten, because rule `j → x` had already been applied earlier, before "nj" existed).

How to test. After changing the order of rules in an accent file, run a sentence containing BOTH letters through Director mode. For the Spanish example: "Niño de paja juega" → the output must contain both the ñ effect ("ñ → nj") and the j effect ("j → x"), i.e. something like "Ninjo de paxa xuega". If you see "ninxo" instead of "ninjo" — the order is wrong.

Engine-side validation (opt-in for pack authors). The application has a built-in heuristic for detecting potential loops, but it's disabled by default — because many pipelines look like loops while being entirely intentional (the classic "szcz → shch" + "ch → h" decomposition). To enable it: set the environment variable `REZYSER_VALIDATE_ZAMIANY=1` and launch the app from a console. The engine will print one aggregated WARN line per accent file listing the first three potential loops and the count of remaining ones. Check the resulting phonetics on a test sentence — if the effect is intended, ignore the WARN.

Rule-reordering buttons in the Rule Manager GUI (drag-and-drop, "Move up / Move down") are a separate feature planned for a later version cycle — they require redesigning the Manager (which currently delegates file editing to the system Notepad rather than offering its own rule view). Until that lands: edit the YAML file by hand, move rows within the `zamiany:` section, run the ENV-var validator, and verify on control sentences.


Important tips for screen reader users (NVDA)

1. Success and error messages

When the application completes an action (e.g., saves a file or encounters an error), a dialog box will appear with a title such as "Success," "Warning," or "Error." NVDA will immediately announce this window and read its content. You don't need to do anything — dialogs are fully accessible via the keyboard, and the focus automatically lands on the "OK" button. After clicking buttons like "Send to AI" or "Run Processing", the program immediately starts processing in the background. Navigating between tools (Director, Polyglot, Converter, Rule Manager) is done in a single program window using four buttons on the toolbar or through the Tools menu (Alt, then N). Available keyboard shortcuts: Ctrl+0 (Home), Ctrl+1 (Director), Ctrl+2 (Polyglot), Ctrl+3 (Converter), Ctrl+4 (Rule Manager — new in 13.0). After switching tools, the focus automatically lands on the description of the new module — NVDA immediately starts reading the new view.

4. Tab order and widget names

Every interface element has a clear Polish name — NVDA will read it when focused. The tab order is logical: from the tool description, through configuration fields, to action buttons. There are no surprises here — keyboard navigation works just like in any other native Windows program. All menus and buttons are in Polish, and NVDA will read them with a Polish voice without any additional settings.

The Audiobook Architect no longer saves the resulting file under the same name architektura_ready.docx. Now, the name is derived from the input file — for example, for znieczulica.txt, the resulting file is architektura_znieczulica.docx. The file appears in the same folder as the original.

Features Retained Without Changes from Version 8

Return to .txt Format for Project Files (CHANGE)
Project files and summaries are now saved in .txt format instead of .md (Markdown). The experiment with the .md format as a psychological barrier against editing proved ineffective — AI often notoriously breaks the anti-closure rule, and it is often better to edit the file on the fly and then reload memory so that AI, as much as possible, does not receive hidden permission to break the prohibition. The .txt format is more intuitive and readable for everyone.

Editor’s Rule — New Warning
A clear warning has been added to the instructions (and in future versions of the interface) explaining what can and cannot be edited in project files. The user has full rights to edit dialogues and content but absolutely cannot modify the structure lines (Act, Scene, Chapter, Prologue, Epilogue) — damaging them spoils NVDA navigation, division in ElevenLabs, and the table of contents in Word.

Updated Architect Prompt (CHANGE)
The prompt for the external chatbot (ChatGPT/Claude) has been redesigned. Instead of returning raw Markdown code, the AI now returns the response in two clearly separated parts: Part 1 is the World Book enclosed in a Markdown code block (easy to copy without markers), and Part 2 is the Mode Recommendation as plain text outside the block — advising whether to use Raw Script Mode or Traditional Audiobook Mode. The description of character tags has also been changed: instead of "sound," it now refers to accent and voice tone in the tag, e.g., [Speaker 1: Name] - lisps and French accent.

Explanation of the Anti-Closure Directive Status (DOCUMENTATION)
The instructions now include a candid explanation that despite built-in Anti-Closure prohibitions, the model still notoriously breaks this rule, especially in Audiobook Mode. Instead of hiding this problem, version 8 makes it clear and returns the responsibility for "manual closure" back to the Director — hence the Editor’s Rule as an official working tool and the return to the regular text format.

- Refactor to YAML — accents, ciphers, and Director modes in text files (ARCHITECTURAL CHANGE, the largest since the migration to wxPython). Until version 12.0, all phonetic rules (accents) and Director's creative modes (Storm, Script, Audiobook, title post-production) were "hardcoded" in Python as constants, functions, and rigid prompt strings, and the entire category of ciphers/text games simply didn't exist — they are introduced along with the 13.0 refactor. Full description in the updated STEP 7.

- Russian accent in Polyglot (NEW — eighth European language in the Director Mode menu). The dropdown list "Director Mode / Accents" now includes the option "Russian (e.g. Milena / Irina / Yuri / Pavel)". Unlike other accents, which only "distort" Polish text at the Latin letter level (e.g. "sz" → "sh", "w" → "v"), the Russian accent performs a full transliteration of Polish text into Cyrillic — allowing Russian-speaking TTS voices (Vocalizer Milena, OneCore Irina / Pavel / Yuri, eSpeak "ru") to "pronounce" words. Mapping has been enriched with iotated vowels ("ja" → "я", "je" → "е", "jo" → "ё", "ju" → "ю"), Polish softening si/ci/ni/zi + vowel (e.g. "ciocia" → "цёця"), as well as Russian special digraphs: "ść" / "szcz" → "щ", "sz" → "ш", "cz" → "ч", "rz" → "ж", "ch" → "х".

  Phonetic note: The accent is not an academic Russian transliteration (ISO 9, GOST, BGN/PCGN). The goal is solely to phonetically resemble Polish text to Russian — for speech synthesis purposes, not for serious transliteration of proper names. For the latter task, use dedicated linguistic tools.

  Language code for the output file: "ru" (ISO 639-1). NVDA with the "Automatically switch language when supported" option enabled will immediately switch to a Russian voice.

- Note on "ź": There is no exact equivalent of the Polish "ź" in Russian, so this character is normalized to "ж" — similar to "ż". Some northern Russian dialects and Belarusian pronounce "ź" closer to "зь", but from the perspective of a speech synthesizer, the difference is negligible. If a linguist prefers "зь", they can independently replace this one rule in the `dictionaries/pl/akcenty/rosyjski.yaml` file — the engine loads YAMLs dynamically, so no recompilation of the application is required.

- Expanded navigation bar and Tools menu (CHANGE). The bar now has a fourth button — Rule Manager — and the "Tools" menu supports the new shortcut Ctrl+4. Existing shortcuts (Ctrl+0 Home, Ctrl+1 Director, Ctrl+2 Polyglot, Ctrl+3 Converter) remain unchanged.

- "Refresh Director Accents from YAML" button on the Home Page (NEW). After adding a new accent via the Rule Manager (or manually editing the YAML file), clicking this button will reload the accent_* wrappers in the Polyglot and Director engines, so the new accent is visible in the menu and in automatic accent detection based on character tags in the World Book. Polyglot detects YAMLs automatically (without refreshing), but the Director requires wrapper regeneration — usually, after refreshing, you need to restart the application.
