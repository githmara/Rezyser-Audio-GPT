Reżyser Audio GPT — Guide complet (Version 18.17.0 – Version de Lancement)

Bienvenue dans le Studio d'Enregistrement Hybride ! Cet ensemble d'outils permet l'écriture, la planification, le formatage et la traduction automatiques de scripts pour pièces radiophoniques et livres audio. Il est optimisé pour fonctionner avec des synthétiseurs vocaux professionnels ainsi que des moteurs de lecteurs d'écran locaux (NVDA).

L'ensemble se compose du studio principal (Réalisation), de l'outil de traduction et d'accents (Polyglotte), de l'outil de construction de structure de fichier (Architecte de Livres Audio), du Gestionnaire de Règles (à partir de la version 13.0 — sans Python, vous pouvez ajouter un nouvel accent, un chiffre ou un mode créatif, voir ÉTAPE 7b ci-dessous) et — à partir de la version 15.0 — du module Histoires (fiction interactive à la deuxième personne générée par IA, lue par TTS ou lecteur d'écran, décrite dans le manuel séparé tales.fr.html). Les cinq outils sont disponibles dans une seule fenêtre de programme, commutable par des boutons sur la barre ou par des raccourcis clavier Ctrl+1..Ctrl+5.

ÉTAPE 1 : Première exécution (Cross-Platform)

Téléchargez le dernier installateur depuis l'onglet Releases sur GitHub (fichier Rezyser_Audio_v<numéro>_Installer.exe) et lancez-le par un double-clic. L'installateur proposera un emplacement d'installation par défaut — le dossier Programs dans le répertoire local de votre compte — et ne nécessite pas de droits administrateur. Vous pouvez aussi choisir votre propre chemin en cliquant sur "Parcourir" — l'installateur le retient et le réutilise de lui-même lors des mises à jour suivantes, sans rien demander. Après l'installation, lancez le programme via l'icône sur le bureau ou depuis le Menu Démarrer. Après un moment, la fenêtre principale du programme apparaîtra — Réalisateur Audio GPT. Depuis la version 17.0, l'application est figée en tant que fichier exécutable natif en mode fenêtré, donc aucune fenêtre de terminal ne clignote plus, et elle se lance plus rapidement qu'auparavant. Pas de navigateur, pas de serveur en arrière-plan. Lorsque vous avez terminé votre travail, fermez simplement la fenêtre du programme.

L'application entière, y compris le moteur Python, les projets et la clé API, vit dans un seul dossier sous le chemin d'installation — tout le dossier peut être déplacé sur une clé USB, dans le cloud ou sur un autre ordinateur (instructions détaillées dans la section "Transfert de projets et de clé API" ci-dessous).

Important: Le dossier runtime/ à l'intérieur du dossier d'installation est le bundle PyInstaller (depuis la version 17.0) — il contient un interpréteur Python isolé et des bibliothèques, prêtes à l'emploi sans installation système séparée ; il sert également de conteneur pour les métadonnées cachées des projets. Si vous clonez le dépôt (chemin développeur), ce dossier n'existe pas et ne devrait pas exister — vous utilisez alors un environnement virtuel venv décrit dans la section pour développeurs ci-dessous.

Pour les développeurs (Windows — dépôt Git)

  1. Clonez le dépôt sur votre disque.
  2. Exécutez le fichier setup_dev.bat. Le script créera automatiquement un environnement virtuel Python (venv) et installera toutes les dépendances requises depuis le fichier requirements.txt.
  3. Lancez l'application avec la commande python main.py ou via le fichier run_dev.bat — le script détectera automatiquement le dossier venv et lancera le programme.

Pour les développeurs et utilisateurs ordinaires (macOS / Linux)

  1. Clonez le dépôt sur votre disque.
  2. Ouvrez un terminal dans le dossier du projet et accordez aux scripts les droits d'exécution : chmod +x *.sh
  3. Exécutez le script de configuration : ./setup_dev.sh — le script créera un environnement venv et installera les dépendances.
  4. Lancez l'application : python main.py ou ./run.sh

Ce que vous verrez au démarrage : Après le lancement du programme, une fenêtre avec l'écran de démarrage s'ouvre. Vous y trouverez une brève description des outils disponibles ainsi qu'une section "Vérification du Système". Si la clé API n'est pas encore configurée, un message rouge vous informera que les modules basés sur l'IA (Réalisation, Traducteur) ne fonctionneront pas — les fonctionnalités locales gratuites (accents, Architecte) sont cependant actives immédiatement. La configuration de la clé est décrite dans l'étape suivante.

Mises à jour automatiques

L'application vérifie au démarrage si une nouvelle version est disponible sur GitHub — la vérification se fait en arrière-plan et ne bloque pas l'interface.

Si vous avez installé le programme via le fichier installateur (.exe) : lorsqu'une nouvelle version est détectée, une fenêtre s'affiche pour vous demander si vous souhaitez la télécharger. Après confirmation, une barre de progression s'affiche, et lorsque le téléchargement est terminé, l'application se ferme automatiquement et le nouvel installateur se lance automatiquement. Vous n'avez pas à vous soucier du chemin d'installation : l'installateur reconnaît l'installation précédente et installe dans le même dossier qu'auparavant — l'assistant n'affiche alors même pas la page du dossier de destination (cela vaut aussi pour un emplacement choisi à la main avec "Parcourir"). La mise à jour écrase les fichiers du moteur de l'application et tout le package de règles (dossier dictionaries/) — vos projets (dossiers skrypty/, opowiesci/) et la clé API (golden_key.env) restent intacts. IMPORTANT : si vous avez édité des fichiers existants dans le package via le Gestionnaire de Règles (par exemple, des modifications d'accent dans dictionaries/pl/akcenty/wloski.yaml), ces éditions SERONT ÉCRASÉES lors de la mise à jour — avant de confirmer la mise à jour, faites une sauvegarde du dossier dictionaries/ selon la procédure de la section "Transfert de projets et de clé API" ci-dessous (il suffit de copier le dossier dictionaries/ sur une clé USB), puis après la mise à jour, remettez-le en écrasant les fichiers plus récents. Les nouvelles règles que vous avez créées à partir de zéro et qui ne sont pas dans le package (par exemple, une langue de base supplémentaire ou un chiffre personnel) restent intactes automatiquement — l'installateur ne supprime pas les fichiers en dehors du package. Depuis la version 15.2.8, le dialogue proposant la mise à jour affiche cet avertissement directement dans le texte et contient un bouton "Ouvrir le dossier dictionaries", qui ouvre l'Explorateur d'un simple clic au bon endroit — il suffit de le presser avant de confirmer la mise à jour pour faire facilement une sauvegarde, puis de revenir au dialogue et de cliquer sur "Télécharger et installer".

Le chemin d'installation sert en revanche à copier des fichiers à la main (sauvegarde, transfert vers un autre ordinateur — voir la section ci-dessous). Si vous ne vous en souvenez pas, il existe deux moyens rapides de le récupérer. Windows 11 : dans le menu contextuel du raccourci sur le bureau, sélectionnez "Ouvrir l'emplacement du fichier" (si l'option n'est pas visible dans le nouveau menu contextuel simplifié, sélectionnez d'abord "Afficher plus d'options" ou appuyez deux fois sur Shift+F10 pour ouvrir directement le menu complet), remontez d'un niveau avec la touche Backspace, sélectionnez le dossier de l'application et appuyez sur Ctrl+Shift+C (ou choisissez "Copier en tant que chemin" dans le menu contextuel) — le chemin complet ira dans le presse-papiers entre guillemets (en collant dans l'installateur, n'oubliez pas de supprimer les guillemets eux-mêmes). Versions antérieures de Windows (7/8/10) : cliquez avec le bouton droit de la souris sur le raccourci et sélectionnez "Propriétés" ; dans l'onglet "Raccourci", dans le champ "Cible", vous verrez le chemin complet vers le fichier exécutable (.exe dans la version 15.2.5+ ou run.bat dans les versions antérieures) — copiez-le et supprimez le nom du fichier final, il ne restera que le chemin du dossier d'installation.

Attention lors de la mise à jour à partir de versions plus anciennes (v15.2.4 ou antérieure, lorsque l'application était lancée via run.bat à partir du package Portable ZIP) : le raccourci existant sur le bureau peut pointer vers run.bat dans l'ancien emplacement, qui n'existe plus après la mise à jour vers v15.2.5+ — les versions 15.2.5+ utilisent un fichier .exe autonome créé par l'installateur. Si le raccourci cesse de fonctionner après la mise à jour, supprimez-le manuellement et laissez l'installateur en créer un nouveau lors de la réinstallation.

Si vous utilisez le dépôt Git (développeurs et utilisateurs macOS/Linux) : au lieu de la proposition de téléchargement, vous verrez une information sur la nouvelle version avec un lien direct vers la page de publication sur GitHub. Téléchargez le code source à partir de là ou mettez à jour le dépôt avec la commande git pull.

Transfert de projets et de clé API (migration)

Si vous souhaitez transférer vos projets, votre clé API et vos paramètres locaux sur un autre ordinateur (ou restaurer le tout après avoir réinstallé Windows), il n'est pas nécessaire de copier manuellement des fichiers individuels — tout le dossier de l'application est autonome.

  1. Assurez-vous que l'application est COMPLÈTEMENT fermée. Si vous voyez l'icône du programme dans la barre système (à côté de l'horloge, sur le côté droit de la barre des tâches), cliquez dessus avec le bouton droit de la souris et sélectionnez "Fermer". Les fichiers ouverts bloquent la copie.
  2. Trouvez le raccourci Réalisateur Audio GPT sur le bureau. Cliquez dessus avec le bouton droit de la souris (ou avec la touche Application ou Shift+F10 lors de la navigation NVDA) et sélectionnez l'option "Ouvrir l'emplacement du fichier". ATTENTION sous Windows 11 : dans le nouveau menu contextuel simplifié, cette option peut être cachée — sélectionnez d'abord "Afficher plus d'options" (ou appuyez deux fois sur Shift+F10 pour ouvrir directement le menu complet avec l'option).
  3. Une fenêtre de l'Explorateur Windows s'ouvrira dans le dossier d'installation du programme. Appuyez sur la touche Backspace (le moyen le plus simple, fonctionne toujours) ou cliquez sur la flèche "Vers le haut" dans la barre d'outils pour monter d'un niveau — vous y verrez le dossier complet de l'application. Attention : le raccourci Alt+Flèche vers le haut ne fonctionne que lorsque le focus est sur la liste des fichiers — si l'Explorateur s'est ouvert avec le focus sur la barre d'adresse (typique), Alt+Flèche vers le haut ne fera rien, utilisez alors Backspace.
  4. Copiez tout ce dossier sur une clé USB, un disque cloud (OneDrive, Google Drive, Dropbox) ou un disque externe. Le dossier contient tout ce qui est nécessaire pour restaurer l'état de travail :
    - Vos projets (dossier skrypty/ — fichiers .txt de narration, .md Livre du Monde et les fichiers de résultats des outils de postproduction : mémoire, titres, fiche de publication ; dossier opowiesci/ — jeux interactifs).
    - La clé API (fichier golden_key.env dans le dossier principal de l'application).
    - Vos propres règles phonétiques, accents, chiffres, si vous avez édité quelque chose dans le Gestionnaire de Règles (dossier dictionaries/<kod>/, par exemple dictionaries/pl/akcenty/wloski.yaml).
    - Les préférences de l'application et le choix des modes créatifs (dossier runtime/skrypty/, fichiers .mode).
    - Un environnement Python isolé (dossier runtime/), vous n'avez donc rien à installer sur le nouvel ordinateur.
  5. Sur le nouvel ordinateur : téléchargez le dernier installateur depuis l'onglet Releases sur GitHub et installez l'application normalement. Lancez le programme une fois pour créer une structure de fichiers de configuration vide. Fermez l'application. Ensuite, copiez le dossier précédemment enregistré à l'emplacement d'installation en écrasant les fichiers — ou sélectionnez uniquement les dossiers qui vous intéressent (skrypty/, opowiesci/, golden_key.env) et collez-les aux endroits appropriés de la nouvelle installation.

Astuce pour les utilisateurs de NVDA: le menu contextuel "Ouvrir l'emplacement du fichier" appelé avec la touche Application est entièrement accessible — NVDA lit chaque élément en français. Après avoir ouvert l'Explorateur dans le dossier cible, utilisez la touche Backspace pour monter d'un niveau (fonctionne toujours, que le focus soit sur la liste des fichiers ou sur la barre d'adresse), puis Ctrl+A pour tout sélectionner et Ctrl+C pour copier.

Astuce: l'option "Ouvrir l'emplacement du fichier" est le nom natif pour la version polonaise de Windows. Dans le système anglais, elle est "Open file location", dans les autres versions linguistiques — de manière analogue dans la langue locale du système d'exploitation.

ÉTAPE 2 : Alimentation de l'API (clé Anthropic / Claude recommandée)

Le fournisseur d'IA recommandé et par défaut est Anthropic (Claude) — tous les prompts de l'application sont optimisés pour lui, ce qui garantit la meilleure qualité de narration et le respect le plus fidèle des règles de l'univers. Dans cette configuration (recommandée), une seule clé API dans le fichier golden_key.env suffit :

• Clé Anthropic (Claude) — alimente L'INTÉGRALITÉ du moteur IA : la narration du Réalisateur (livre audio, théâtre radiophonique, brainstorming), le mode Histoires, le Polyglotte (traducteur) ainsi que l'attribution de titres aux chapitres et la détection de la langue du contenu. Elle commence par sk-ant-.

Si vous effectuez une mise à jour depuis une version antérieure : l'ancienne clé OpenAI n'est plus nécessaire pour la configuration par défaut — vous pouvez conserver ou supprimer sa ligne dans golden_key.env, l'application l'ignore (sauf si vous configurez délibérément un autre fournisseur — voir ÉTAPE 2B ci-dessous).

Comment obtenir une clé Anthropic :
1. Créez un compte sur console.anthropic.com et approvisionnez-le (onglet Billing / Plans).
2. Générez une clé dans la section API Keys (elle commence par sk-ant-). Copiez-la immédiatement — elle n'est parfois affichée qu'une seule fois.

Comment saisir la clé dans le programme :
3. Sur l'écran de démarrage du programme, cliquez sur le bouton "Générer le fichier golden_key.env et ouvrir l'éditeur de texte". Le système créera automatiquement un fichier de configuration vierge au bon emplacement et ouvrira le Bloc-notes avec un modèle prêt à être édité.
4. Dans le fichier ouvert, vous verrez la ligne : ANTHROPIC_API_KEY=PASTE_YOUR_KEY_HERE. Supprimez le texte de remplacement et collez votre clé directement après le signe égal (sans espace ni guillemets). Enregistrez le fichier et relancez l'application.

Conseil: Après le redémarrage, l'application vérifiera le fichier et affichera le statut de la clé dans la section "Vérification du Système". Il doit être vert pour que tous les modules IA soient prêts à fonctionner. Si la clé est absente ou incorrecte, le programme l'indiquera clairement et vous permettra d'ouvrir l'éditeur de texte pour corriger rapidement l'erreur.

ÉTAPE 3 : Le Studio de Mise en Scène Principal

C'est votre centre de commandement pour inventer des histoires et écrire des scénarios. Accédez-y en cliquant sur le bouton "🎬 Réalisateur" dans la barre de boutons ou en sélectionnant Outils → Réalisateur dans le menu (raccourci : Ctrl+1).

Important : Format des fichiers de projet — retour au .txt

Dans la version 7, les fichiers de projet étaient enregistrés au format Markdown (.md), par exemple skrypty/znieczulica.md. Il s'agissait d'une expérience délibérée — le format .md devait constituer une barrière psychologique pour les personnes non techniques, les décourageant d'ouvrir et de modifier manuellement le fichier dans le Bloc-notes (et donc d'endommager accidentellement les en-têtes de structure).

L'expérience n'a pas fonctionné. L'IA enfreint fréquemment l'une des interdictions fondamentales (nous y reviendrons dans un moment). C'est pourquoi, dans la version 8, on est revenu aux simples fichiers .txt — plus intuitifs et lisibles pour tout le monde. Par exemple, un projet nommé "znieczulica" sera désormais enregistré sous skrypty/znieczulica.txt, et son résumé sous skrypty/znieczulica_streszczenie.txt. Cela permettra à chacun d'apporter plus facilement des corrections de mise en scène ou des coupes de texte au fil du travail.

⚠️ Règle critique du Monteur (lisez avant de commencer !)

Tous vos scripts et livres générés sont enregistrés dans de simples fichiers texte (.txt), que vous pouvez facilement ouvrir dans le Bloc-notes.

En tant que Metteur en scène, vous avez le PLEIN DROIT (et même le devoir) de modifier ce fichier ! Si l'intelligence artificielle s'emballe et, par exemple, résout elle-même le problème des personnages à la fin du fragment généré, ouvrez le fichier, supprimez les dernières lignes et laissez le texte interrompu au moment le plus tendu, puis cliquez sur "Recharger le projet depuis le disque" pour synchroniser la mémoire du modèle avec le fichier corrigé, et "Envoyer à l'IA" pour continuer.

🔴 Cependant — ce que vous n'avez pas le droit de toucher

Ne modifiez jamais, ne supprimez jamais et ne changez jamais les lignes contenant la structure (par ex. Acte 1, Scène 2, Chapitre 1, Prologue). Si vous abîmez ces en-têtes :
1. Votre histoire s'effondrera dans les lecteurs d'écran (NVDA).
2. L'Architecte d'audiobook, et par conséquent aussi ElevenLabs Studio, ne sera pas en mesure de diviser correctement votre livre en fragments à lire.
3. Le Convertisseur interne de l'application ne générera pas correctement la table des matières dans le fichier Word ni sur la timeline dans ElevenLabs.

Modifiez les dialogues, coupez l'action, mais laissez la structure tranquille !

Comment utiliser la Mise en Scène ?

  • Livre du Monde (barre latérale gauche) : C'est ici que vous saisissez les règles de l'univers. Chaque projet possède désormais son propre Livre associé au nom du fichier — si votre fichier d'histoire est par exemple emilia_heist_audiobook.txt, le Livre du Monde sera enregistré sous skrypty/emilia_heist_audiobook.md. C'est pourquoi l'ordre est important : saisissez d'abord le nom du fichier de projet dans le champ "Nom du fichier de projet", et seulement ensuite vous pourrez enregistrer le Livre. Le bouton "💾 Sauvegarder la Bible de manière permanente" reste grisé tant que vous n'avez pas fourni de nom. Le chargement d'un projet existant via le bouton "Charger l'histoire" chargera automatiquement le fichier .md correspondant — vous n'avez rien à faire manuellement. Attention : Sans Livre du Monde rempli, l'application bloquera l'envoi de requêtes à l'IA — c'est une protection intentionnelle qui vous empêche de générer du texte sans aucune règle.
  • Mémoire à Long Terme (barre latérale gauche) : Deuxième champ dans la barre latérale. C'est ici qu'arrive le résumé de l'intrigue — produit par l'outil du panneau de postproduction (ÉTAPE 4) ou, au niveau d'alarme de la mémoire, automatiquement. Vous pouvez également y saisir vos propres notes manuellement — le modèle les traitera comme "ce que je sais déjà" avant de lire la scène en cours. LACUNE HISTORIQUE (corrigée en v15.5) : auparavant, si vous saisissiez une note très courte ici et cliquiez sur « Enregistrer le Résumé » avant qu'il y ait quelque chose de significatif dans le fichier de narration, au prochain chargement l'application chargeait le résumé EN PRIORITÉ et IGNORAIT l'histoire complète — le modèle ne recevait alors que le Livre du Monde et une note d'une phrase, sans le contexte du ton et des dernières scènes. Depuis la v15.5, le chargement est intelligent : si toute l'histoire tient dans la fenêtre de contexte, elle est chargée en intégralité (et l'ancien résumé superflu est supprimé), de sorte que le modèle ne perd pas le contexte. Et après avoir modifié manuellement le fichier de narration dans l'éditeur, utilisez le nouveau bouton « Recharger le projet depuis le disque » (depuis la v15.5), qui synchronise en un clic la mémoire interne avec le disque ; pour ouvrir simplement le fichier dans l'éditeur, on utilise toujours « Ouvrir le fichier de narration… ».
  • Mode Brainstorming : Saisissez une idée libre et l'IA vous donnera 3 options de développement de l'intrigue. Pour chaque option, elle générera immédiatement un bloc "--- ÉBAUCHE DE PROMPT ---" prêt à l'emploi. Après en avoir choisi une, collez ce prompt dans le Mode Scénario ou Audiobook et ajoutez vos éventuelles remarques ou informations pour le modèle. La mémoire de l'intrigue ne change pas pendant le Brainstorming — vous pouvez expérimenter sans risque !
  • Mode Scénario Brut (depuis la v16.0 — théâtre radiophonique) : Vous collez ici l'"Ébauche de Prompt" générée dans le Brainstorming. L'IA écrira un long fragment narrativo-dialogué : la narration (décor, temps, action) dans des balises [Narrator: ...] et les répliques des personnages dans des balises [Nom: émotion]. Sans effets sonores — le contexte est porté par le narrateur en mots. Le texte est automatiquement ajouté à votre fichier (par ex. nouvelle_scene.txt) dans le dossier skrypty/. Un tel scénario prêt à l'emploi peut ensuite être transformé en audiobook multi-voix (passerelle vers ElevenLabs Studio — chapitre séparé ci-dessous).
  • Mode Audiobook Traditionnel : Mode pour les écrivains. L'IA génère de la prose littéraire pure — zéro balise, zéro phonétique, des dialogues classiques intégrés dans la narration. Le texte est ajouté au fichier de la même façon qu'en Mode Scénario.
  • Création automatique de personnages : Le script est programmé pour créer automatiquement de nouvelles balises [Speaker] si l'intrigue nécessite un nouveau personnage. Conseil : Si l'IA crée un personnage intéressant, copiez sa balise et collez-la dans le Livre du Monde pour que le modèle s'en souvienne de façon permanente !

Gestion de projet — trois boutons d'action :
- Charger l'histoire : Charge un projet existant en mémoire. Disponible lorsque la mémoire actuelle est vide. Depuis la version 15.2.3, il gère deux chemins : si le champ du nom de projet est vide, une boîte de dialogue de sélection s'ouvre avec la liste de tous les projets trouvés dans le dossier skrypty/ (en omettant les fichiers de résumés) — NVDA lit la liste naturellement, l'utilisateur n'a pas besoin de se souvenir du nom et de le retaper au clavier. Si le champ du nom est rempli, l'application tente immédiatement de charger le projet portant ce nom (chemin expert : Entrée dans le champ du nom ou clic après avoir saisi de mémoire).
- Fermer le Projet (Réinitialisation Complète) : Efface complètement le projet. Supprime l'histoire, le résumé, le Livre du Monde et remet tous les compteurs à zéro. À utiliser lors du changement de projet ou d'une nouvelle histoire.
- Ouvrir le fichier de narration… (depuis la v15.2.3) : Édition d'urgence du fichier de narration dans l'éditeur de texte système. Nécessite un nom de projet saisi. L'application ouvre skrypty/<nazwa>.txt dans le Bloc-notes (Windows), TextEdit (macOS) ou l'éditeur GUI par défaut (Linux). Scénarios typiques : (a) l'IA ne clôture pas la scène et vous souhaitez ajouter la fin manuellement ; (b) vous avez chargé un projet avec un résumé et vous souhaitez copier les dernières scènes dans la Mémoire à Long Terme pour que le modèle dispose du contexte complet du ton (lacune architecturale décrite ci-dessus) ; (c) vous souhaitez effectuer une coupe de texte au milieu d'un chapitre que le moteur de l'application ne prend pas en charge nativement.

  • Recharger le projet depuis le disque (depuis la v15.5, remanié en v17.6) : Recharge le projet ENTIER depuis le disque après une édition manuelle du fichier de narration — il s'agit d'un véritable rechargement, pas seulement d'une actualisation de la mémoire courante. Il recalcule les compteurs de Chapitres/Actes/Scènes, recharge le Livre du Monde, le mode et les options de Brainstorming, et synchronise la mémoire de travail. Si toute l'histoire tient dans la fenêtre de contexte, elle est chargée en intégralité (et l'ancien résumé superflu est supprimé, afin que le moteur travaille sur le texte complet). Si l'histoire est longue et qu'un résumé a été enregistré, celui-ci est conservé intact et l'application vous demande à partir de quel en-tête la mémoire de travail de l'IA doit démarrer : en mode Audiobook, vous choisissez le Chapitre ; en mode Scénario, vous choisissez d'abord l'Acte, puis la Scène de cet acte (ou l'Acte entier) — le reste est représenté par le résumé. Annuler la sélection = coupure d'urgence vers le dernier fragment de texte (c'est pourquoi il est conseillé de maintenir la structure des en-têtes). Avant d'écraser les champs avec la version du disque, l'application vous avertit si vous y avez du contenu non enregistré. Scénario typique : l'IA a incorrectement clôturé une scène (violation de l'anti-closure), vous supprimez la mauvaise fin dans l'éditeur et cliquez sur Recharger — fini de corriger au même endroit deux fois.

Note historique — pourquoi les modes sont désormais protégés contre les changements accidentels :
Dans les versions antérieures de l'application, personne ne veillait à la cohérence du mode créatif au sein d'un même projet. Il en résultait une certaine possibilité créative subtile, que l'on pourrait décrire ainsi : vous commencez une histoire en Mode Scénario, vous insérez "Acte 1" et "Scène 1" (l'application est ravie de votre cohérence), vous générez plusieurs écrans de tension avec des balises [SFX: Claquement de porte] et [Speaker 1: Marek - résigné]... puis — parce que l'inspiration vient de frapper — vous cliquez sur "Insérer coupure Chapitre 1". L'application ajoute sans sourciller l'en-tête "Chapitre 1" au fichier, juste après "Scène 3". Vous avez désormais dans votre fichier un hybride entre une pièce radiophonique des années 50 et un roman de mœurs. ElevenLabs regarde cette structure, voit un en-tête de chapitre au milieu d'un acte et décide que c'est probablement une erreur dans la matrice. La table des matières ressemble à l'œuvre d'un artiste d'avant-garde. L'Architecte d'Audiobooks, quant à lui, part du principe que vous êtes un adulte et traite simplement le tout sans un mot — mais aussi sans aucune garantie de résultat. Depuis la version 12.0, l'interface tentait de bloquer le changement de mode d'enregistrement — du moins en théorie. La pratique s'est avérée plus créative : le Brainstorming (toujours actif en tant que mode de planification) était une porte dérobée par laquelle on pouvait passer entre Scénario et Audiobook à l'aide des flèches haut et bas (Audiobook → Brainstorming → Scénario et inversement). Le premier clic sur "Insérer Acte 1" ou "Insérer Chapitre 1" dans le mode nouvellement sélectionné écrasait tranquillement le fichier .mode, mélangeant actes et chapitres dans un seul fichier de narration. Ce n'est que depuis la version 15.2.3 que nous disposons d'une véritable protection : une fois la décision de mode confirmée (première structure ou premier envoi de production réussi), le second élément d'enregistrement dans le champ de sélection du mode est effectivement verrouillé. Le Brainstorming reste toujours actif en tant que mode de planification — il propose des options narratives — mais il n'est plus possible de l'utiliser pour basculer vers un autre mode d'enregistrement. (Depuis la version 18.13, le Brainstorming ne résume plus rien ; cette tâche revient à l'outil de Mémoire à Long Terme du panneau de postproduction.)

Prompts Showrunner — l'IA en tant que scénariste de série (depuis la v7, conservés)

Il s'agit du changement le plus important introduit dans la version 7, conservé sans modification. Il n'est pas visible dans l'interface, mais il modifie radicalement la qualité de la fiction générée.

Le showrunner est, dans l'industrie télévisuelle, la personne responsable de l'ensemble d'une série — il veille à ce que l'intrigue ne tende jamais vers une résolution facile, mais s'épaississe constamment, accumule les conflits et maintienne le spectateur en haleine pendant de nombreuses saisons. Dans la version 7, cette philosophie a été intégrée directement dans les instructions système de l'IA.

La Directive Anti-Closure — et ce qu'a changé le moteur Anthropic (Claude)

La philosophie du Showrunner est appliquée par la directive Anti-Closure intégrée dans chaque mode : interdiction de clôturer les scènes par des résumés, des morales et de faux happy ends. À l'ancienne époque (modèle GPT), c'était exactement l'inverse de ce que l'on observe aujourd'hui — le moteur enfreignait notoirement cette interdiction et "fermait" lui-même l'histoire à chaque occasion : il intercalait des phrases récapitulant l'intrigue, créait de faux happy ends ou clôturait des fils narratifs au milieu d'un chapitre, comme si chaque fragment était le dernier. Depuis la version 18, l'ensemble du moteur IA fonctionne par défaut sur Anthropic (Claude) — et depuis la version 18.4, vous pouvez optionnellement désigner votre propre fournisseur (ÉTAPE 2B) — et Claude respecte l'Anti-Closure de façon bien plus rigoureuse.

Un autre effet secondaire, purement technique, est apparu : puisque le modèle ne clôture pas systématiquement la scène, sa réponse peut atteindre la limite de longueur d'une réponse individuelle et s'interrompre en pleine phrase (voire en plein mot). L'application gère cela automatiquement — lorsqu'elle détecte qu'un fragment s'est interrompu à la limite, elle envoie une courte requête supplémentaire pour clôturer la dernière phrase de façon naturelle dans la langue de votre histoire, et ce n'est qu'ensuite que le texte est enregistré. Si pour une raison quelconque cela ne peut pas être finalisé, vous verrez un avertissement discret, mais le texte sera enregistré dans son état actuel — nous ne bloquons jamais l'enregistrement, vous pouvez toujours peaufiner manuellement une fin interrompue.

La règle du monteur décrite ci-dessus reste inchangée : si malgré tout le modèle clôture une scène trop proprement, c'est votre droit (et même votre devoir) en tant que Metteur en scène d'ouvrir le fichier .txt, de supprimer ces dernières phrases, de laisser le texte interrompu à un moment de tension et de cliquer sur "Recharger le projet depuis le disque" pour synchroniser la mémoire avec le fichier corrigé.

Chaque mode possède une directive Anti-Closure intégrée :

  • Brainstorming : L'IA agit comme le scénariste d'une série multi-saisons. Chacune des 3 options proposées DOIT accumuler les obstacles, introduire de nouveaux dilemmes, des fils narratifs ouverts et des cliffhangers. Interdiction absolue de proposer des options dans lesquelles les personnages se réconcilient définitivement, surmontent l'obstacle principal sans conséquences majeures, ou dans lesquelles l'histoire tend vers une fin précipitée. Interdiction d'inventer des lieux bon marché et magiques qui brisent l'architecture du monde.
  • Mode Scénario Brut : Interdiction absolue de terminer le texte par des résumés, des morales ou des boucles narratives. L'IA doit interrompre l'action naturellement à un moment de tension (cliffhanger), en évitant toute conclusion, afin que le fragment suivant puisse reprendre la narration de façon fluide.
  • Mode Audiobook Traditionnel : Interdiction absolue de terminer le texte par des résumés grandiloquents, de clôturer des fils narratifs ou de suggérer la fin de l'histoire (par ex. "Elle était prête pour de nouveaux défis", "Elle comprit qu'il était temps d'avancer"). Le texte doit s'interrompre au milieu d'une action en cours, d'une tension ou d'une pensée ouverte.

Exception à la règle : Si vous demandez explicitement une conclusion, un final ou un épilogue, l'IA générera une clôture satisfaisante de l'histoire — l'interdiction ne s'applique pas lorsque vous en faites vous-même la demande.

Gestion des Actes et des Scènes (Mode Scénario, depuis la v7, conservé)

Le Mode Scénario Brut dispose d'un panneau dédié "✂️ Gestion de la Structure" avec des boutons pour construire la structure de la pièce radiophonique en temps réel.

  • Insérer Acte X : Insère un en-tête d'acte (par ex. "Acte 2") ET ajoute automatiquement "Scène 1" en dessous — car chaque nouvel acte commence par la première scène. Le compteur d'actes passe au numéro suivant, et le compteur de scènes se réinitialise à 2 (prêt pour la scène suivante dans cet acte).
  • Insérer Scène X : Insère uniquement un en-tête de scène (par ex. "Scène 3") au sein de l'acte en cours. Le compteur de scènes s'incrémente automatiquement.

Chargement intelligent du fichier : Lorsque vous chargez un fichier de scénario existant, l'application le scanne automatiquement et règle les compteurs d'actes et de scènes sur les bons numéros. Le compteur de scènes est toujours calculé au sein du dernier acte du fichier.

Prologue et Épilogue : Les boutons "📜 Insérer le Prologue" et "🏁 Insérer l'Épilogue" sont communs aux deux modes et disponibles dans le même panneau.

L'Architecte d'Audiobooks convertira automatiquement les Actes en points de navigation principaux (Heading 1) pour ElevenLabs et NVDA — les Scènes deviendront du texte en gras visible dans le document, mais invisible dans la table des matières.

Gestion Intelligente des Chapitres (Mode Audiobook, depuis la v5, conservé)

Le LLM génère au maximum environ 5 000 caractères par requête — c'est insuffisant pour un chapitre complet. C'est pourquoi vous travaillez de façon itérative : vous générez des fragments successifs en cliquant sur "Envoyer à l'IA", jusqu'à estimer que le chapitre en cours est terminé. Vous cliquez alors sur "Insérer coupure de chapitre" — l'application ajoute l'en-tête au fichier et à la mémoire, et le compteur de chapitres passe automatiquement au numéro suivant.

Boutons du panneau :

  • Insérer coupure (Chapitre X) : Insère un en-tête (par ex. "Chapitre 3") dans le fichier et la mémoire. Le compteur de chapitres se met à jour automatiquement.
  • Insérer Prologue : Ne fonctionne qu'au début, lorsque la mémoire est vide. Protection contre l'insertion accidentelle d'un Prologue au milieu de l'histoire.
  • Insérer Épilogue : Clôture l'histoire. Une fois l'Épilogue inséré avec son contenu, l'application bloquera la génération de nouveaux fragments — c'est intentionnel, car une fois l'histoire terminée, il n'y a plus rien à ajouter.

Chargement intelligent du fichier : Lorsque vous chargez un fichier existant, l'application le scanne automatiquement et règle le compteur de chapitres sur le bon numéro. Si le fichier comporte un Prologue et trois chapitres, le compteur affichera "Chapitre 4" — sans comptage manuel.

Accumulateur de Trame — comment fonctionne la mémoire de l'IA

Seul le texte pur de l'histoire est transmis à la mémoire du modèle — ce que l'IA a effectivement écrit. Les instructions, options et plans disparaissent après utilisation et ne polluent pas le contexte. Résultat ? Le modèle maintient sa concentration plus longtemps, mémorise mieux les accents des personnages et "dévie" moins souvent des règles du Livre du Monde.

L'indicateur "Mémoire du Modèle" à l'écran indique dans quelle mesure la fenêtre de contexte du modèle est remplie. Depuis la version 15.1, il ne s'agit PLUS d'un simple comptage des caractères de l'histoire — l'application compte les TOKENS réels (selon la même méthode qu'utilise le modèle) et additionne l'INTÉGRALITÉ de la charge envoyée à l'IA : l'histoire en cours, la Mémoire à Long Terme (résumé) ET le Livre du Monde. C'est pourquoi l'indicateur augmente également lorsque vous enrichissez le Livre du Monde ou que vous avez un résumé long — pas seulement en raison de la narration elle-même. La valeur est affichée en pourcentage de remplissage de la fenêtre :
- Vert (jusqu'à environ 70 %) : Le modèle est pleinement concentré, vous disposez d'une marge de sécurité confortable.
- Jaune (environ 70–90 %) : Vous approchez de la limite. L'IA peut commencer à raccourcir ses réponses et à ignorer les règles. C'est le moment d'enregistrer vous-même la Mémoire à Long Terme — et de clore progressivement le fil narratif.
- Rouge (au-dessus d'environ 90 %) : Surcharge critique ! Depuis la version 18.13, à ce niveau l'application lance elle-même, après chaque envoi réussi, l'outil de Mémoire à Long Terme du panneau de postproduction et enregistre le résumé — vous en recevez un message et le panneau reste bloqué le temps de la génération.

Diagnostic du seuil de résumé (lorsque l'IA hallucine avant le seuil prévu) : les seuils (avertissement ~70 %, alarme ~90 %) sont estimés empiriquement. Si vous constatez une tendance répétée du modèle à "dévier" des règles ou à commencer à halluciner AVANT que l'indicateur n'entre dans le jaune/rouge — c'est-à-dire plus tôt que ne le prévoit le seuil — ouvrez un ticket dans le dépôt de l'application et décrivez à quel niveau de remplissage approximatif (pourcentage) les problèmes commencent réellement, de préférence avec un exemple. Si cette tendance se confirme plus largement (chez d'autres utilisateurs, sur différents projets), le seuil de résumé automatique sera abaissé dans le prochain correctif. Il s'agit d'un mécanisme délibérément itératif — mieux vaut l'affiner sur des données réelles que de l'estimer à l'avance.

Mémoire Infinie (depuis la v6, conservée)

Lorsque l'alarme rouge se déclenche, vous n'avez plus besoin de copier manuellement un résumé. Depuis la version 18.13, un outil distinct du panneau de postproduction (ÉTAPE 4) s'en charge : un clic génère une synthèse concise de toute la trame développée jusqu'ici, l'enregistre comme fichier de mémoire dans le dossier skrypty/ (dans le pack français <nom>_resume.txt) et la place aussitôt dans le champ de Mémoire à Long Terme. Une fois enregistrée, vous pouvez vider la mémoire et continuer à écrire dans le même fichier — l'histoire peut se poursuivre à l'infini, sans aucune limite de longueur.

Ce qui a changé par rapport aux versions précédentes : jusqu'à la v18.12, on commandait un résumé dans le Brainstorming en écrivant le mot « résumé » ou « récapitulatif » dans l'instruction. Cette voie avait un défaut inscrit dans sa conception : le prompt du Brainstorming interdit au modèle d'écrire autre chose que trois options d'intrigue ; demander un simple résumé le plaçait donc devant deux instructions contradictoires à la fois — et pouvait se terminer par une erreur au lieu d'un résultat. C'est pourquoi le résumé est désormais un outil autonome doté de sa propre instruction, sans contradiction, et le Brainstorming est revenu à une seule tâche : planifier l'intrigue.

Quand résumer (mis à jour en v15.5) : Vous n'avez plus besoin de surveiller un seuil de caractères rigide "avant de terminer votre travail". Il est préférable de résumer après la clôture naturelle d'une partie structurelle importante — après la fin d'une scène, d'un acte ou d'un chapitre. La raison : lorsque vous corrigerez manuellement la fin dans le fichier de narration et cliquerez sur "Recharger le projet depuis le disque", l'application vous demandera à partir de quel en-tête reconstituer le fragment récent — et le résumé de la partie antérieure restera intact (fini de corriger au même endroit deux fois). C'est pourquoi il est d'autant plus utile de maintenir la structure : insérez régulièrement des en-têtes Chapitre/Acte/Scène depuis le panneau de structure (les formes longues sans aucun acte/chapitre sont déconseillées, par ex. un "drame moderniste" d'un seul tenant). EXCEPTION : si vous menez une très longue histoire ENTIÈREMENT sans en-têtes, générer et enregistrer un Résumé avant une pause reste indispensable — sans marqueurs, l'application ne peut reconstituer que le dernier fragment compté en caractères, et le moteur sans contexte pourrait "paniquer".

Résumé automatique (reconstruit en v18.13) : lorsque l'indicateur de mémoire entre en état d'alarme (au-dessus d'environ 90 %), l'application lance elle-même l'outil de Mémoire à Long Terme dès la fin de l'envoi — sans poser de question, car à ce niveau chaque appel suivant est déjà menacé. Le résultat va directement dans le fichier de résumé et dans le champ de Mémoire à Long Terme, et vous recevez un message vous en informant. Zéro travail manuel. Vous pouvez bien sûr corriger le résumé dans le champ et l'enregistrer de nouveau avec le bouton d'enregistrement de la Mémoire.

Le résumé est INCRÉMENTAL : l'outil ne relit pas tout le projet depuis le début à chaque fois. Il reçoit la Mémoire à Long Terme existante ainsi que la partie du récit écrite après le dernier résumé (l'application retient à quel en-tête elle s'est arrêtée) et fusionne les deux. Ainsi, le coût des résumés successifs ne croît pas avec la longueur du roman, et les événements plus anciens ne se perdent pas à chaque rafraîchissement.

Chargement intelligent et rechargement depuis le disque (mis à jour en v17.6) : Aussi bien lors du chargement d'un projet que après avoir cliqué sur "Recharger le projet depuis le disque" (après une édition manuelle du fichier de narration dans l'éditeur), l'application réconcilie en un seul passage la mémoire avec le disque — elle recalcule les compteurs de structure et recharge le Livre du Monde ainsi que le mode. Si l'INTÉGRALITÉ de l'histoire tient dans la fenêtre de contexte — elle est chargée en intégralité, et l'ancien résumé superflu est supprimé, afin que le moteur travaille sur le texte complet (ce qui comble l'ancienne lacune où le modèle ne recevait que le résumé sans le contexte des dernières scènes). Si l'histoire est LONGUE et qu'un fichier de résumé a été enregistré — le résumé est conservé intact et l'application vous demande à partir de quel en-tête de structure (Chapitre/Acte/Scène) la mémoire de travail de l'IA doit démarrer ; le reste de la trame est représenté par le résumé. Vous ne gaspillez ainsi pas de tokens à recharger toute l'histoire, tout en évitant qu'un nouveau résumé soit généré à partir de données obsolètes.

ÉTAPE 3b : Deux sorties du Scénario — livre audio multivoix (ElevenLabs) et version pour lecteurs d'écran

Le scénario de théâtre radiophonique finalisé (mode Scénario) dispose de deux sorties indépendantes : un projet ElevenLabs Studio multivoix (audio) et une version HTML pour lecteurs d'écran. Ce sont deux façons d'« entendre » la même pièce — vous pouvez utiliser l'une, l'autre ou les deux. Toutes deux sont optionnelles et ne modifient pas le flux classique avec le convertisseur.

Passerelle vers ElevenLabs Studio (audio, optionnel)

La passerelle transforme le scénario en projet Studio multivoix — le narrateur et chaque personnage reçoivent une voix distincte. Sans clé ElevenLabs, rien ne change : la passerelle reste simplement masquée.

Clé ElevenLabs (optionnelle)

Collez votre clé ElevenLabs dans le fichier golden_key.env, sur une ligne séparée : ELEVENLABS_API_KEY=sk_... Attention : la clé ElevenLabs commence par sk_ (avec UNDERSCORE), contrairement à la clé Anthropic (sk-ant-). Si vous utilisez une clé avec restrictions (restricted key), accordez-lui les permissions (scopes) projects_write et voices_read. Le statut de la clé est visible sur l'écran principal (System Check) — l'absence de clé n'est pas une erreur, la passerelle reste simplement masquée.

La passerelle apparaît dans le panneau du Réalisateur en mode Scénario (lorsque la clé est valide). Elle fonctionne sur une pièce finalisée enregistrée sur le disque — générez ou chargez d'abord le projet, puis accédez à la passerelle.

Étape 1 — Distribution des voix

Cliquez sur « Distribution des voix… ». L'application lira les personnages ayant des répliques dans votre scénario et ajoutera toujours un emplacement Narrateur (le narrateur est la voix par défaut — il lit les titres de chapitres et toute la narration). Pour chaque locuteur, collez un voice ID. IMPORTANT : chaque voix utilisée dans la pièce doit d'abord figurer dans vos « My Voices » — les voix que vous créez vous-même (par exemple via « Voice Design ») y arrivent automatiquement, tandis que les voix de la bibliothèque publique se parcourent dans l'onglet « Explore » et s'ajoutent via le bouton « Add to My Voices ». Comment obtenir un voice ID dans ElevenLabs (dans le navigateur) : trouvez la voix, écoutez l'échantillon pour vous assurer qu'il s'agit du bon, et copiez son identifiant via le bouton « Copy Voice ID » ; lorsque la voix est déjà dans « My Voices », ce bouton est disponible immédiatement — sans développer « More actions ». Choix des voix : pour limiter les éventuelles régénérations, le plus simple est de choisir dans la collection « Best for Eleven v3 » (voix validées pour le modèle v3 sur lequel le projet est créé) ; vous pouvez aussi concevoir votre propre voix dans « Voice Design », et pour les plus aventureux, il reste le clonage IVC (Instant Voice Cloning) ou PVC (Professional Voice Cloning). Vous pouvez laisser les champs vides et revenir plus tard — la sauvegarde est un brouillon.

Étape 2 — Construire le projet

Cliquez sur « Créer un projet ElevenLabs Studio… ». L'application vérifiera que le scénario comporte au moins un chapitre (Prologue/Acte/Chapitre) et que chaque locuteur ainsi que le narrateur ont une voix assignée, puis créera dans votre compte un projet Studio multivoix divisé en chapitres. La simple création du projet NE consomme PAS de crédits. L'application configure immédiatement la langue du projet (prononciation correcte des lignes d'en-tête) ainsi que la normalisation du volume selon le standard du livre audio — tout cela via l'API, afin que vous n'ayez pas à accéder aux paramètres du projet dans le navigateur.

Gardien du format (extension de la Règle du Monteur) : la passerelle exige que dans le scénario CHAQUE ligne soit soit une réplique avec indicateur de locuteur ([Narrator: …] ou [Nom: …]), soit un en-tête de structure (Prologue, Acte, Scène, Chapitre). La prose ordinaire non balisée saisie « librement » — par exemple une note d'auteur ou un fragment de narration sans balise — n'est attribuée à aucune voix et est silencieusement ignorée lors de la construction, de sorte que le projet final pourrait diverger de votre fichier. C'est pourquoi, si l'application détecte de telles lignes orphelines, elle en affiche la liste avec les numéros et demande si la construction doit quand même avoir lieu : vous pouvez alors annuler et corriger le scénario (ouvrez-le via le bouton « Ouvrir le fichier de narration… », ajoutez les indicateurs de locuteur manquants ou supprimez ces lignes) ou choisir délibérément de construire malgré tout, en acceptant leur omission. C'est une extension naturelle de la Règle du Monteur : tout comme il est interdit d'altérer les en-têtes de structure, dans un scénario destiné à la passerelle, chaque ligne doit avoir son locuteur ou être un en-tête.

Étape 3 — Rendu dans le navigateur

Après la création du projet, l'application affichera son identifiant ainsi qu'un bouton ouvrant ElevenLabs Studio. Dans le navigateur, trouvez le projet, effectuez le rendu de la parole (c'est seulement à ce moment que les crédits sont consommés — environ 1 crédit par caractère), puis exportez le fichier audio ou publiez le projet dans Eleven Reader. Le rendu et la publication se font de votre côté, en toute connaissance de cause — l'application se contente de construire le projet.

Expression et accents (modèle Eleven v3)

Le projet est créé sur le modèle Eleven v3 (plus de 70 langues). Les émotions NE s'expriment PAS par des majuscules, des points de suspension ou des tirets — le moteur les ignore. À la place, le Réalisateur intègre dans les répliques des balises audio v3 en anglais, par exemple [whispers], [sighs], [angry], [laughs] — ce sont elles qui contrôlent l'expression et fonctionnent indépendamment de la langue parlée. L'ACCENT d'un personnage provient en revanche de l'ÉCHANTILLON DE VOIX : si vous souhaitez qu'un personnage parle par exemple en polonais avec un accent étranger, choisissez ou concevez dans Voice Design une voix dont l'échantillon possède cet accent. En pratique, expérimentez avec le prompt de la voix jusqu'à entendre par exemple un échantillon polonais avec un accent finnois — le modèle v3 conservera cet accent dans l'enregistrement final. Conseil : les phrases très longues affaiblissent l'accent, c'est pourquoi le Réalisateur est déjà invité dans le prompt à utiliser des phrases courtes.

Conscience du modèle v3 (phase alpha)

Eleven v3 est le plus expressif, mais toujours en phase alpha. Il arrive qu'une réplique isolée soit rendue sous forme de grésillements plutôt que de parole — il suffit de la régénérer dans Studio (chaque bloc dispose de quelques régénérations gratuites). Dans les paramètres du projet ElevenLabs, des recommandations de changement de modèle peuvent également s'afficher (vers Eleven Flash v2.5 ou Multilingual v2) — ce n'est PAS une erreur, seulement une suggestion du moteur. Si vous ne souhaitez pas voir ces messages, n'ouvrez simplement pas les paramètres du projet : l'application a déjà tout configuré via l'API (modèle, langue, normalisation du volume).

Pourquoi le théâtre radiophonique et non les effets sonores ? Dans les versions précédentes, le mode Scénario produisait des effets bruts [SFX: ...] sans narrateur. La passerelle vers un enregistrement multivoix finalisé exige cependant que le contexte (lieu, temps, action) soit porté par le narrateur en mots : les effets sonores dans Studio ne sont pas accessibles aux lecteurs d'écran, et le modèle réalise de toute façon soit le narrateur, soit les effets — jamais les deux de manière stable simultanément. C'est pourquoi le mode Scénario est un théâtre radiophonique : narrateur plus dialogue, sans SFX.

Version pour lecteurs d'écran (HTML, sans ElevenLabs)

En mode Scénario, indépendamment de la clé ElevenLabs, vous disposez du bouton « Générer la version pour lecteurs d'écran ». Il crée le fichier skrypty/<nazwa>_screen_reader.html — une sortie distincte pour les personnes utilisant des lecteurs d'écran (par exemple NVDA). Son fonctionnement : les répliques des personnages qui ont un accent défini dans le Livre du Monde (par exemple l'entrée « [Joana] accent finnois ») reçoivent une transcription phonétique (orthographe délibérément « altérée ») ainsi qu'un marqueur de langue (attribut lang), grâce auquel le lecteur d'écran les lit avec l'accent étranger approprié. Les balises audio v3 (par exemple [whispers]) sont supprimées dans cette version — le lecteur ne doit pas les lire à voix haute. Les en-têtes Prologue/Acte/Scène deviennent des en-têtes HTML, ce qui permet une navigation aisée dans le document.

C'est un complément délibéré à la passerelle audio : l'accent pour le modèle v3 est porté par l'échantillon de voix, et pour le lecteur d'écran — par l'orthographe et le marqueur de langue. C'est pourquoi l'orthographe dans la version audio reste propre (v3 choisit lui-même la langue), tandis que l'« altération » de l'orthographe se retrouve exclusivement dans le fichier HTML séparé, où elle est souhaitée.

ÉTAPE 4 : Postproduction dans la Réalisation

Après avoir écrit l'histoire, vous disposez d'un panneau d'outils de postproduction en bas du panneau Réalisation. Ce panneau est dynamique : chaque outil est un fichier YAML distinct dans le dossier rezyser/ (kategoria: postprodukcja), et son champ dla_trybow détermine dans quels modes créatifs l'outil apparaît. L'ensemble des boutons change donc selon le mode sélectionné — et lorsqu'aucun outil ne correspond au mode en cours, le panneau reste masqué. Vous pouvez créer votre propre outil dans le Gestionnaire de Règles (modèle de type postproduction — voir ÉTAPE 7b).

Un outil fonctionne selon l'un des trois périmètres (champ zakres dans le YAML) :

  • per_rozdzial — itère sur les chapitres du fichier enregistré et traite chacun séparément (c'est ainsi que fonctionne l'Attribution de Titres ci-dessous),
  • calosc — envoie à l'IA l'intégralité du fichier de projet en un seul appel (par exemple un rapport ou un audit de l'histoire entière) ; si le projet possède un Livre du Monde, l'outil peut l'inclure comme contexte supplémentaire,
  • rekoncyliacja (depuis la v18.13) — au lieu du fichier complet, envoie la Mémoire à Long Terme existante ainsi que la partie de la narration écrite depuis le dernier résumé. C'est ainsi que fonctionne l'outil de Mémoire à Long Terme décrit plus bas ; grâce à cela, le coût des appels suivants n'augmente pas avec la longueur du roman.

Le résultat apparaît toujours dans une boîte de dialogue (à copier), et un outil dont le suffixe de fichier de résultat est configuré l'enregistre en outre à côté de la narration, dans le dossier skrypty/ (par exemple nazwa_audyt.txt). Avant d'écraser un fichier de résultat existant, l'application demande confirmation — avant même de dépenser le moindre centime en appel IA. Si le contenu destiné à l'outil dépasse la fenêtre contextuelle sur laquelle l'application se base pour mesurer la mémoire (128 000 jetons), un avertissement s'affichera d'abord, demandant si vous souhaitez malgré tout lancer l'outil. Il ne s'agit que d'un avertissement : les modèles Claude disposent d'une fenêtre bien plus large que ce compteur, mais votre propre fournisseur d'IA, avec une fenêtre plus petite, rejettera une telle requête — et vous paierez quand même pour la tentative.

Attribution de Titres aux Chapitres (Mode Livre Audio)

L'IA analysera l'histoire entière et proposera des titres descriptifs et littéraires pour chaque chapitre (ainsi que pour un éventuel Prologue et Épilogue). Le module itère sur les chapitres du fichier enregistré et leur attribue un titre court, en n'analysant que le début de chaque chapitre (jusqu'à 6000 caractères). Il ne renvoie qu'une liste numérotée de titres — sans réécrire le contenu du livre.

Mémoire à Long Terme — résumé du projet (depuis la v18.13)

Cet outil est disponible dans les deux modes d'enregistrement (Scénario et Livre Audio). Il génère un enregistrement concis des faits : déroulement des événements, décisions des personnages et leurs conséquences, personnages, lieux, intrigues en suspens, et enfin une note d'une phrase sur le style et le ton de la narration. Le destinataire de ce texte est le moteur narratif, pas le lecteur — c'est pourquoi le résumé est sec et factuel, sans fioritures.

Il possède une caractéristique que les autres outils n'ont pas : son résultat n'atterrit pas « à côté » du projet comme un rapport, mais DEVIENT la Mémoire à Long Terme — il aboutit simultanément dans le fichier de mémoire du dossier skrypty/ (son nom est déclaré par la recette de l'outil ; dans le pack français, c'est <nom>_resume.txt), dans le champ « Mémoire à Long Terme » du panneau, et dans un marqueur interne grâce auquel l'application sait jusqu'où s'étend le résumé (c'est ce marqueur qui permet de résumer de manière incrémentale et qui vous interroge sur le point de référence lors du rechargement du projet depuis le disque). L'outil se lance également tout seul lorsque l'indicateur de mémoire du modèle entre en état d'alerte — voir ÉTAPE 3.

Le nom du fichier de mémoire est localisé (depuis la v18.14). Chaque pack linguistique déclare son propre mot natif dans le champ sufiks_pliku_wyniku du fichier rezyser/postprod_streszczenie.yaml : français _resume, anglais _overview, allemand _zusammenfassung, finnois _yhteenveto, etc. Vous pouvez changer cette valeur dans le Gestionnaire de Règles pour n'importe quelle autre (par exemple _memoire) — l'application gérera la transition, car elle recherche le fichier de mémoire à l'aide d'une LISTE DE CANDIDATS :

  • elle vérifie, dans l'ordre, les suffixes des outils de mémoire du pack de la langue du CONTENU du projet (et non de la langue de l'interface — le fichier appartient à l'histoire, pas au menu), puis le neutre _overview, et enfin l'historique _streszczenie ;
  • lorsqu'elle trouve EXACTEMENT UN fichier portant un nom différent de l'actuel, elle le renomme avec son marqueur interne — vous n'avez rien à faire à la main ;
  • lorsqu'elle en trouve PLUSIEURS (parce que vous avez un outil de mémoire distinct « pour vous » et « pour l'IA », ou des fichiers datant d'une autre langue d'interface), elle vous demande lequel doit être la Mémoire à Long Terme et ne touche pas aux autres. Annuler cette question signifie une session sans mémoire : le champ reste vide, aucun fichier n'est modifié ni supprimé, et avec une narration longue l'application vous demandera d'indiquer le point de référence de la mémoire de travail.

Fiche de publication ElevenReader (depuis la v18.14)

L'outil lit tout le texte du projet et compose un jeu de métadonnées prêt pour le formulaire de publication du livre audio sur ElevenReader, en enregistrant le résultat dans le dossier skrypty/ (dans le pack français sous le nom <nom>_publication.txt). La fiche contient : un titre et un sous-titre optionnel, une description de 1000 caractères maximum (limite de la plateforme), un ou deux genres provenant EXCLUSIVEMENT de la liste canonique des 22 catégories d'ElevenReader, le public visé, l'indication du contenu pour adultes avec une phrase de justification, deux à trois extraits choisis comme aperçu gratuit, un prompt prêt à l'emploi pour un générateur d'image de couverture (vertical 1200×1800 px, avec de la place pour un titre et un nom d'auteur lisibles) ainsi qu'un rappel des champs que vous laissez par défaut dans le formulaire.

Les noms des champs de la fiche sont en ANGLAIS (Title:, Description, Genres:, Target audience:, Mature content:, Sample chapters:, ISBN:) — le formulaire de la plateforme n'existe qu'en anglais, vous les recopiez donc 1:1. Le contenu des champs est dans la langue de votre projet, mais les VALEURS des champs fermés (genres, public, le Yes/No du contenu pour adultes) restent également en anglais, car la plateforme ne les accepte que depuis sa propre liste.

Ce que la fiche ne fera pas à votre place : elle n'invente ni l'éditeur ni le numéro ISBN — elle les laisse comme champs à remplir à la main (l'ISBN est un numéro enregistré, et une hallucination serait ici une fausse déclaration éditoriale). Un profil d'auteur est obligatoire sur ElevenReader, car les publications anonymes ne sont pas autorisées et cela va de pair avec la déclaration de droits d'auteur — l'outil recopiera donc le nom ou le pseudonyme depuis le Livre du Monde, et s'il n'en trouve aucun, insérera un champ à remplir. Il choisit TOUJOURS les extraits d'aperçu, car le formulaire en exige au moins un, quel que soit le modèle de rémunération que vous choisirez plus tard.

Après la génération, l'application vérifie la fiche de son côté : si la description tient dans la limite, si les genres et le public proviennent de la liste de la plateforme, si les champs obligatoires sont remplis et si des chiffres sont apparus dans le champ ISBN. Elle affiche les écarts comme des remarques souples — vous recevez le résultat en entier et décidez vous-même quoi corriger. C'est une protection contre le cas où le modèle inventerait une catégorie inexistante que le formulaire ne rejetterait qu'à la fin de l'assistant.

Remarque : Les outils de postproduction exigent que le fichier de projet soit déjà enregistré sur le disque (généré ou chargé). Si le fichier n'existe pas, l'application affichera un message approprié.

ÉTAPE 5 : Polyglotte AI

Application pour la traduction et l'imposition d'accents forts sur les synthétiseurs de lecteurs d'écran. Accédez-y en cliquant sur le bouton "🌍 Polyglotte" dans la barre de boutons ou en sélectionnant Outils → Polyglotte dans le menu (raccourci : Ctrl+2).

Mode 1 : Traducteur Ordinaire (Utilise l'IA - Payant)

Idéal pour écouter des histoires dans une belle langue étrangère correcte.

  • Chargez un fichier avec le bouton "Charger le fichier en mémoire" ou utilisez le bouton "Parcourir..." pour sélectionner un fichier dans la fenêtre système.
  • Choisissez le mode "Traducteur IA", entrez la langue cible (par exemple, "Finnois").
  • Le script traduira le contenu. Si vous chargez un fichier .html, il traduira uniquement le texte visible pour le lecteur et mettra à jour le code de langue dans la balise html.
  • Si vous chargez un fichier .txt ou .md ordinaire (par exemple, un script généré par le Réalisateur), le script enregistrera automatiquement le résultat comme un fichier .html avec une balise de langue intégrée — prêt à être lu par NVDA sans aucun travail supplémentaire.
  • Prend également en charge les fichiers .docx.

Division intelligente en blocs : Les longs textes sont automatiquement divisés en blocs mesurés en tokens du modèle (et non en caractères) et traduits séquentiellement avec une barre de progression. Ainsi, même les langues à écriture dense, comme le chinois ou le japonais, tiennent dans la limite de réponse du modèle, et une réponse tronquée est détectée et automatiquement retentée sur des fragments plus petits.

Enregistrement de progression résistant aux pannes (NOUVEAUTÉ dans la version 9) : Chaque bloc traduit est immédiatement enregistré dans un fichier temporaire caché dans le dossier système de l'application. Si la traduction est interrompue en raison de l'épuisement de la limite API, lors du prochain lancement, l'application détectera automatiquement ce fichier, restaurera la progression déjà payée et terminera tranquillement le travail à partir du point d'interruption — sans aucun copier-coller manuel. Après une fin réussie, le fichier temporaire est automatiquement supprimé.

Pourquoi est-ce important ? Dans la version 8, l'approche de reprise de traduction avait un bug critique et silencieux : si vous ne renommiez pas le fichier avec une traduction partielle et coupiez le fragment traduit selon les instructions, puis repreniez immédiatement la traduction du reste — l'application ouvrait le fichier de sortie en mode écrasement. La progression payée était effacée de manière irréversible et inconsciente avant que vous ne puissiez vous en rendre compte. La version 9 élimine complètement ce piège : l'enregistrement est permanent après chaque bloc, peu importe ce que vous faites ensuite.

Mode 2 : Mode Réalisateur / Accents (Gratuit - Fonctionne localement)

Outil pour "détériorer" le texte. Imposant un accent polonais cassé sur les synthétiseurs.

Le menu déroulant intégré du Mode Réalisateur permet de choisir l'accent directement à partir d'une seule liste. Les options disponibles sont :
Anglais (Samantha / Mark — Vocalizer/Apple, Zira / Hazel — OneCore)
Russe (Milena — Vocalizer/Apple, Irina / Pavel / Yuri — OneCore, eSpeak)
Polonais (Ewa — Vocalizer, Paulina — OneCore)
Allemand (Markus / Stefan — Vocalizer/Apple, Hedda / Katja — OneCore)
Espagnol (Jorge / Monica — Vocalizer/Apple, Helena — OneCore)
Islandais (Gudrun — OneCore, eSpeak ; note : Vocalizer ne prend pas en charge cette langue !)
Italien (Alice / Luca — Vocalizer/Apple, Elsa — OneCore)
Finnois (Satu / Mikko — Vocalizer/Apple, Heidi — OneCore)
Et aussi deux options de nettoyage sans accent :
"Aucun (Nettoyage SANS normalisation des nombres)"
"Aucun (Nettoyage AVEC normalisation des nombres)"
L'option avec normalisation des nombres convertit automatiquement les chiffres en leur forme écrite (par exemple, 15 devient "quinze") avant le traitement — ainsi NVDA lit les nombres de manière fluide, et si le texte a un accent imposé, le nombre l'aura aussi, sans aucune exception.
Vous vous demandez probablement si le synthétiseur saura décliner ces nombres normalisés en fonction du contexte ? La réponse est : non. Et c'est une fonctionnalité délibérée. Comme on le sait bien : "la langue polonaise être difficile" — et un étranger écorchant notre grammaire ne fait qu'ajouter à l'authenticité de l'accent cassé !

Réparateur de Balises (NOUVEAUTÉ dans la version 9) : À la fin de la liste, vous trouverez une option supplémentaire — le Réparateur de Balises. Il n'applique aucune règle phonétique ni de nettoyage. Il fait une chose : injecte dans le fichier le code de langue ISO que vous fournissez — à deux lettres (par exemple, "fi" pour le finnois, "en" pour l'anglais) ou avec un sous-tag de région ou d'écriture (par exemple, "pt-BR" pour le portugais brésilien, "zh-Hans" pour le chinois simplifié). Utile lorsque vous avez déjà un fichier prêt — par exemple, précédemment traduit par le Traducteur IA — mais qui est sorti avec une balise de langue incorrecte ou manquante. Au lieu de le traduire à nouveau, vous lancez simplement le Réparateur avec le bon code ISO et en un rien de temps, vous avez un fichier corrigé.

Le script nettoie les didascalies entre parenthèses — il supprime tous les fragments de texte entre parenthèses (par exemple, "(avec des respirations intégrées)", "(en chuchotant)", "(ironiquement)"). ElevenLabs doit lire uniquement les dialogues et la narration, et non les instructions de mise en scène intégrées dans le texte.

Le script nettoie également les balises Markdown — il supprime les hashtags des en-têtes (par exemple, #, ##, ###), les signes égaux utilisés comme soulignements d'en-têtes, ainsi que les virgules orphelines qui pourraient perturber le rythme de lecture par le synthétiseur.

  • Bouclier de protection : Le script protège toutes les balises HTML. Il ne détériore que les dialogues et la narration.
  • Fonctionne localement et ne coûte rien !

Mode 3 : Chiffreur (NOUVEAUTÉ dans la version 13.0 — jeux de texte, gratuit, local)

Le troisième RadioButton dans Polyglotte, à côté du Traducteur IA et du Mode Réalisateur : « Mode Chiffreur (jeux de texte, découpage aléatoire) ». Il active six algorithmes locaux de distorsion de texte — pour des jeux, des énigmes, des casse-têtes linguistiques. Après avoir sélectionné le mode, une liste déroulante d'algorithmes apparaît, et pour l'un d'eux (Chiffre de César), un champ numérique supplémentaire pour le décalage.

Algorithmes disponibles (sélectionnez dans le menu « Choisir l'algorithme de distorsion ») :

  • Inverseur de Texte (Lecture à l'envers avec une majuscule) — chaque phrase est inversée caractère par caractère, en conservant le point/exclamation/interrogation à la fin et la majuscule au début. Avant l'inversion, le script développe les abréviations populaires (p. ex., c.-à-d., etc., M., Dr, etc.), pour que le résultat après inversion ait encore du sens — sans cela, « p. ex. » après inversion devient un absurde « .xe ».

Inspiration : mission du programme « The Traitors. Traîtres ». Quand l'animatrice a montré sans préavis aux participants une chanson populaire polonaise de dessin animé — simplement jouée à l'envers — les réactions allaient dans le style « quelle est cette langue ? », « c'est peut-être de l'arménien », « hongrois ou finnois ». La mission proprement dite consistait en ce qu'une équipe recevait dans la forêt le texte de la chanson écrit à l'envers, devait la chanter sous cette forme inversée, l'autre équipe l'enregistrait, la jouait à l'envers — et en théorie récupérait la chanson originale à deviner. Exactement le même malentendu phonétique amusant est généré par notre Inverseur lorsque vous passez le fichier traité par un synthétiseur TTS.

  • Typoglycémie (Milieu des mots mélangé) — effet psycholinguistique classique : « Vous puoevz lirre un txete peu i'moprte l'odrre des ltteers, tnat que la piremère et la derinère ltteer sont à la bnnoe pclae ». Le script mélange aléatoirement le milieu de chaque mot de plus de 4 lettres, la première et la dernière lettre restent intactes. Idéal pour tester « combien je vois vraiment, et combien mon cerveau devine ».

  • Téléphone Cassé / Dialecte Serpent — chaque « s », « z » ou digramme « sz » est allongé aléatoirement en un sifflement de 4 à 8 caractères (« sssssss », « zzzzzzz », « sssssssz »). Inspiration : Snecko du jeu « Slay the Spire ». Effet : le texte semble lu par un serpent avec un défaut de prononciation.

  • Voyelliseur (Tout résonne en « O ») — chaque voyelle dans le texte est remplacée par « o », en conservant les adoucissements polonais. « Bonjour » → « Bonjoor ». Plus le texte est long, plus l'effet est amusant (et le lecteur d'écran le lit avec pleine conviction).

  • Bégaiement Fort / Robot Endommagé — ajoute des bégaiements au début des mots : « or-or-or-ordinateur », « st-st-stratégie ». Pour les mots courts (moins de 3 lettres), l'algorithme les ignore. Si la deuxième lettre du mot est une consonne, il répète les deux premières lettres (effet plus naturel) ; si c'est une voyelle — il ne répète que la première.

  • Chiffre de César (décalage de l'alphabet FR) — chiffre de substitution classique : chaque lettre est décalée de N positions dans l'alphabet français (ABCDEFGHIJKLMNOPQRSTUVWXYZ, 26 lettres). Vous entrez la valeur du décalage dans le champ numérique « Décalage du chiffre de César (0 = aléatoire, plage -25…25) ». Si vous entrez 0 — l'application choisira un décalage aléatoire dans la plage 1-25 et l'affichera dans un message après la fin (pour que vous puissiez ensuite déchiffrer). Les caractères hors alphabet (chiffres, ponctuation, espaces et lettres accentuées comme é, à, ç) restent inchangés.

Application pratique : les chiffres enregistrent le résultat dans le même format que le Mode Réalisateur (.html avec balise lang ou .docx avec balises XML), donc NVDA les lira avec la voix de la langue appropriée. En particulier, l'Inverseur et le Voyelliseur sonnent beaucoup plus intéressants dans le synthétiseur que lorsque vous les lisez avec vos yeux — car le cerveau lors de la lecture visuelle essaie automatiquement de « décoder » le texte, tandis que le TTS le lit exactement tel qu'il est écrit.

Les six chiffres sont également décrits dans un langage plus large et accessible dans le fichier docs/dictionaries.pl.html du package de l'application — avec des conseils sur la façon d'ajouter votre propre chiffre de type « substitution de lettres » sans connaissance en programmation (par exemple, langage argot scolaire, langue de bois).

Langue de traitement, forçage et mode qualité (NOUVEAU dans la 18.11)

La section de chargement de fichier dispose désormais d'une liste déroulante de langue de traitement. Elle permet de choisir selon les règles de quelle langue fonctionnent les modes Réalisateur et Chiffrant : les listes d'accents et de chiffres, ainsi que l'alphabet du Chiffre de César et sa plage de décalage.

  • La position par défaut « Détecter automatiquement » conserve le comportement antérieur : la langue est déterminée à partir du fichier chargé, et si elle diffère de la langue de l'application, vous recevrez une brève notification indiquant que les listes ont été commutées.
  • Le choix d'une langue précise dans la liste est contraignant — l'application ne le modifiera pas d'elle-même lors du chargement d'un fichier.

Sous la liste se trouve une case à cocher forçant la langue choisie pour l'ensemble du document. Par défaut, chaque paragraphe est traité selon la langue détectée pour ce paragraphe — c'est généralement le meilleur choix, car les insertions en langue étrangère reçoivent leurs propres règles correctes. Cochez le forçage lorsque vous souhaitez un traitement uniforme de l'ensemble. Exemple où cela est indispensable : le chiffrement réversible multicouche. L'alphabet du Chiffre de César a une longueur différente selon chaque langue, donc sans forçage, un texte mêlant plusieurs langues sera chiffré avec plusieurs alphabets différents — et le déchiffrement nécessitera alors de savoir où passaient les frontières linguistiques. Avec la langue forcée, tout le document est chiffré et déchiffré avec un seul et même alphabet. Réserve : dans les langues dont l'alphabet de César contient des lettres diacritiques normalisées au chargement (polonais, allemand), le déchiffrement n'est pas totalement fidèle — les lettres diacritiques du cryptogramme sont converties en leurs formes de base lors du rechargement, avant d'atteindre le déchiffrement. La réversibilité complète est garantie par les alphabets sans de tels caractères (par ex. l'anglais).

Le traducteur IA a quant à lui gagné une case à cocher pour le mode qualité. Une fois cochée, le modèle dispose d'un budget supplémentaire pour l'analyse interne du texte avant traduction (ce qu'on appelle l'extended thinking) — la traduction prend plus de temps et consomme davantage de jetons, mais les passages difficiles sont traités avec plus de soin. Cette option ne fonctionne qu'avec les modèles Anthropic Claude ; si vous utilisez un fournisseur alternatif via un point de terminaison compatible OpenAI, cocher la case n'a aucun effet.

Détail connexe : les caractères avec macron utilisés dans la romanisation japonaise (par ex. Tōkyō, rāmen, jūdō) sont depuis cette version normalisés comme les autres signes diacritiques étrangers — dans la plupart des langues, réduits à la lettre nue (Tokyo), et dans le pack finnois, par doublement de la voyelle (Tookyoo), conformément à la convention finnoise de notation des sons longs. Ainsi, ils ne disparaissent plus de l'alphabet du Chiffre de César en tant que caractères apparents dans le cryptogramme.

Détection de la langue

Avant que le script ne "détériore" le texte, il vérifie dans quelle langue il est écrit. S'il détecte que ce n'est pas du polonais, il affichera un avertissement. Les règles phonétiques sont conçues pour le polonais — les appliquer à un texte dans une autre langue donnerait des résultats imprévisibles.

Accents optimisés pour les synthétiseurs locaux (NVDA)

Les accents ont été conçus à 100 % pour les synthétiseurs-lecteurs d'écran locaux, gratuits et payants — Vocalizer et eSpeak dans NVDA. Cela garantit la stabilité et la prévisibilité du résultat sur chaque ordinateur.

Pourquoi pas ElevenLabs ? Les tests sur des documents plus longs ont montré que la distorsion phonétique du texte dans des moteurs comme ElevenLabs n'impose pas l'accent souhaité — le moteur "devine" simplement la langue et en fait plutôt un accent slave occidental/sud. Les synthétiseurs locaux NVDA sont beaucoup plus obéissants à cet égard.

Spécificité des synthétiseurs vocaux locaux (TTS)

Différents moteurs TTS se comportent différemment. Voici les principales différences qui influencent directement le fonctionnement des accents :

eSpeak (Open Source)

Un moteur léger et gratuit avec une vaste base de langues — prend en charge notamment l'islandais. Très strict en matière de codage des caractères, ce qui le rend prévisible. Cependant, il présente des défauts phonétiques : il partage souvent des phonèmes entre les langues, ce qui fait que, par exemple, l'ukrainien sonne avec une teinte russe.

Tiflotecnia Voices pour NVDA (voix Cerrence — anciennement Vocalizer de Nuance)

Tiflotecnia Voices est le successeur direct de Vocalizer de Nuance — un moteur commercial avec des voix de nouvelle génération de la société Cerrence, distribué sous forme de paquet .nvda-addon dans le NVDA Add-on Store. L'ancien Vocalizer (bibliothèques .dll 32 bits de Nuance) a été abandonné avec NVDA 2026.1 ; Cerrence a recompilé les voix en 64 bits et Tiflotecnia les a publiées sous un nouveau nom. La qualité de la prononciation est sensiblement meilleure que dans la génération précédente.

Killer Feature pour les malvoyants : Fichiers avec balises linguistiques

C'est une véritable révolution. Les fichiers traités sont maintenant enregistrés comme suit :

  • .html avec un attribut lang (par exemple, lang="fi" pour le finnois) — NVDA lit cette balise et bascule automatiquement sur le synthétiseur vocal approprié. Zéro configuration manuelle !
  • .docx en conservant le formatage — chaque segment de texte a une balise linguistique injectée dans le XML du document, donc Word et NVDA savent quelle voix utiliser pour chaque partie.

Les fichiers traités sont toujours enregistrés comme de NOUVEAUX documents (par exemple, accent_Finski.html).

Automatisation du changement de langue dans NVDA — ce que vous devez savoir

Pour que NVDA change effectivement de voix en fonction de la balise lang, le paramètre "Changer automatiquement de langue si pris en charge" doit être activé. Vous le trouverez dans Préférences NVDA → Voix. Par défaut, il est activé lors du premier lancement du lecteur d'écran — mais il est bon de vérifier si quelqu'un ne l'a pas désactivé.

Limitation importante des voix OneCore : Les voix Microsoft OneCore ne prennent pas en charge ce mécanisme avec NVDA de manière native, mais uniquement avec le narrateur intégré de Windows. Il existe un module complémentaire non officiel pour NVDA appelé "One Core Autolang" qui tente de résoudre ce problème — mais son développement a été rapidement interrompu. La raison est simple : chaque année, avec la première version de NVDA de l'année, des changements rompent la compatibilité API (appelés API Breaking Changes). Parfois, il suffit de mettre à jour le champ "last tested version" dans le manifeste du module, mais parfois de véritables modifications du code sont nécessaires — et l'auteur ne parvient pas à suivre les mises à jour. Si vous tenez à l'automatisation du changement de langue, un choix plus sûr est Tiflotecnia Voices (payant, section ci-dessus) ou eSpeak (gratuit, de moindre qualité), qui prennent en charge ce mécanisme de manière native — mais attention : actuellement, dans Tiflotecnia Voices, cela fonctionne avec un bug de priorités (voir "Astuce critique" ci-dessous). Après avoir appliqué le patch, le changement automatique fonctionne parfaitement, comme dans l'ancien Vocalizer.

Problème critique avec Tiflotecnia Voices : détection de langue défectueuse

D'abord, la bonne nouvelle — l'alerte concernant NVDA 2026.1 des versions précédentes du manuel s'est terminée par une fin heureuse : Cerrence a fourni des bibliothèques 64 bits, Tiflotecnia les a publiées dans un paquet .nvda-addon disponible dans l'Add-on Store (section ci-dessus), et Vocalizer, pour ceux qui l'ont conservé jusqu'à la fin, est revenu sous un nouveau nom — avec une meilleure qualité et sans les limitations 32 bits.

Cependant, avec le lancement de Tiflotecnia Voices, un nouveau problème critique est apparu — dans la détection de langue. Dans les paramètres de l'extension, on peut configurer quelle voix doit être utilisée pour certaines lettres (par exemple, latines, cyrilliques) en fonction des voix installées. Le problème réside dans l'ordre des priorités : actuellement, on applique d'abord le remplacement par lettre, puis le retour au code ISO de la langue (en pratique inatteignable pour le MÊME alphabet auquel le remplacement s'est déjà adapté), et enfin la voix choisie. Le résultat apparaît au sein du même alphabet : vous avez un texte en finnois avec la balise correcte lang="fi", Satu installée comme voix finnoise de Tiflotecnia, MAIS dans les paramètres, une voix polonaise est définie pour les lettres latines — Satu NE lira PAS ce texte, malgré la balise ISO correcte. Le remplacement par lettre « voix polonaise pour le latin » l'emporte au premier niveau, l'ISO fi n'est jamais vérifié. Pour les paires d'alphabets différents, le mécanisme fonctionne correctement (texte russe + Milena pour le cyrillique + voix polonaise pour le latin — tout le cyrillique est lu par Milena, les éventuels noms propres latins par la voix polonaise ; chaque alphabet reste dans son remplacement). Après la migration de Vocalizer, où le changement de langue basé sur l'ISO fonctionnait parfaitement, les utilisateurs remarqueront cette régression immédiatement — en particulier ceux qui utilisent plusieurs accents européens dans Polyglotte (Satu, Alice, Markus) sur le même ensemble de lettres latines.

Diagnostic et correctif : j'ai diagnostiqué le problème au niveau de Python dans le code de l'extension et préparé un correctif modifiant l'ordre des priorités en : ISO → voix choisie → remplacement par lettre. Le correctif conserve le changement utile vers le latin pour les noms latins dans un texte russe, lorsque l'option « détection de langue basée sur les caractères Unicode » est activée dans les paramètres. J'ai envoyé le correctif aux développeurs de Tiflotecnia — pour l'instant sans réponse, ils s'en tiennent donc très probablement à leur propre solution. Si l'extension reçoit une mise à jour, je mettrai le correctif à jour si nécessaire.

Que faire en attendant : si vous tenez à une détection correcte de la langue (cela vaut la peine — c'était l'une des fonctionnalités phares de l'ancien Vocalizer, voir « Fonctionnalité phare pour les aveugles » ci-dessus), ouvrez un problème dans le dépôt de l'application sur GitHub avec l'étiquette tiflotecnia-patch et votre adresse email dans le contenu. Il vaut la peine d'ajouter une courte description du problème dans votre propre langue (2–3 phrases suffisent) — le bot détectera la langue (prises en charge : polonais, anglais, allemand, espagnol, finnois, français, islandais, italien, russe) et répondra dans la même ; sans description ou dans une autre langue, la réponse arrivera en anglais. Un bot automatique fermera immédiatement le problème avec une confirmation de soumission (sans trace dans le fil public), et vous recevrez le correctif par email généralement dans quelques jours. Le correctif lui-même N'EST PAS publié dans le dépôt de l'application ni comme Gist — Tiflotecnia Voices for NVDA est un logiciel commercial, et la licence de l'extension n'autorise pas la redistribution de ses fichiers, même modifiés. Après avoir reçu le correctif, son contenu doit être copié dans %appdata%\Roaming\nvda\addons\TiflotecniaVoices, en remplaçant les fichiers. Attention lors de la copie : si Windows n'a pas demandé de remplacement, vous avez probablement copié tout le dossier TiflotecniaVoices_edits avec son contenu AU LIEU du contenu lui-même — dans ce cas, entrez dans le sous-dossier créé, coupez tout, collez un niveau plus haut et écrasez. Après avoir appliqué correctement le correctif, redémarrez NVDA — vous profitez de la meilleure qualité des voix Cerrence 64 bits et de la détection correcte de la langue, soit une combinaison introuvable chez un seul fabricant sur le marché. Nous supposons bien sûr que vous avez une licence valide pour Tiflotecnia Voices — nous ne vérifions pas cela, mais vous ne pourrez pas appliquer le correctif sur un dossier étranger sans licence.

ÉTAPE 6 : L'Architecte d'Audilivres

Outil de préparation d'une structure de fichier professionnelle pour les lecteurs d'écran et ElevenLabs. Accédez-y en cliquant sur le bouton "📄 Convertisseur" dans la barre de boutons ou en sélectionnant Outils → Convertisseur dans le menu (raccourci : Ctrl+3).

Comment ça fonctionne ?

  1. Saisissez le chemin vers le fichier source dans le champ de texte ou cliquez sur le bouton "Parcourir..." pour sélectionner un fichier dans la boîte de dialogue système. Le script accepte aussi bien les fichiers .txt que .docx, ainsi que les fichiers .html et .htm.
  2. Cliquez sur "Construire l'Architecture pour ElevenLabs".
  3. Le script analysera chaque ligne de texte et remplacera les mots-clés (Acte, Chapitre, Prologue, Épilogue, Introduction) par des titres "Heading 1" dans le document Word.
  4. Les scènes (lignes commençant par le mot "Scena") se transforment en texte en gras — visibles dans le document, mais invisibles dans la table des matières d'ElevenLabs.
  5. Tout le texte restant (dialogues, descriptions) passe sans modification.
  6. Vous obtiendrez un fichier architecture_[nazwa_oryginału].docx — un document Word professionnel prêt pour la suite du travail. Par exemple, si votre fichier d'entrée s'appelait znieczulica.txt, le fichier résultant s'appellera architecture_znieczulica.docx et apparaîtra dans le même dossier que l'original.

Nettoyage au passage : Le script supprime automatiquement les balises HTML (si le texte provient d'un navigateur ou d'un fichier .html local, par exemple généré par le Polyglotte) ainsi que les marqueurs de titres Markdown (par ex. ### ou ####) avant le traitement. Vous n'avez pas besoin de nettoyer le fichier manuellement.

Mode Histoires : regroupement automatique des tours en scènes (depuis la v15.1)

Si vous chargez dans l'Architecte un fichier opowiesci/<gra>.txt généré par le module des Histoires Interactives, le convertisseur reconnaîtra les marqueurs de tour (par ex. « --- Tura 7 --- » — également dans les autres langues prises en charge, si vous avez joué dans une autre langue) et insérera un nouveau titre de premier niveau « Scena N » tous les cinq tours (la numérotation commence à 1, dans la langue de votre partie). Les autres marqueurs de tour sont supprimés — ils n'apparaissent pas dans la narration de l'audiolire, car « Tura 7 » prononcé par un TTS brise l'immersion de l'auditeur. Le résultat est un fichier Word avec une division naturelle en scènes de quelques minutes d'audio chacune, prêt à être importé dans ElevenLabs. Le mécanisme est auto-détecté — les fichiers d'audiolires ordinaires sans marqueurs de tour (narration classique depuis le Réalisateur) sont traités exactement comme avant.

Un avantage puissant pour les utilisateurs de NVDA et d'ElevenLabs

Le formatage "Heading 1" pour les chapitres n'est pas seulement une question d'esthétique. Dans NVDA, vous pouvez naviguer entre les titres instantanément en appuyant sur la touche H (ou 1 pour les titres de premier niveau). Au lieu de faire défiler des centaines de pages, vous sautez de chapitre en chapitre en une fraction de seconde. Cela change la façon de travailler avec les longs documents. Dans ElevenLabs, vous avez la certitude que le moteur insérera automatiquement les coupures et ne se bloquera pas lors de la réalisation des clips audio.

ÉTAPE 7 : Comment écrire le Livre du Monde (Prompt de l'Architecte et Mini-cours Markdown)

L'intelligence artificielle qui alimente le Studio Principal comprend mieux les commandes lorsqu'elles sont formatées dans le langage de balisage Markdown. Si vous ne donnez à l'IA dans le Réalisateur qu'une idée vague (par ex. « deux sœurs dans l'au-delà »), la machine paniquera faute de détails et créera une histoire banale et prévisible, en ignorant toute logique.

Pour éviter cela, utilisez un chatbot externe (par ex. ChatGPT gratuit ou Claude) comme votre Architecte personnel. À partir de la version 13.0, vous n'avez plus besoin de recopier le prompt depuis les instructions — dans le panneau du Réalisateur, juste sous le bouton « 💾 Sauvegarder la Bible de manière permanente », vous trouverez le bouton « 📖 Prompt de l'Architecte pour l'IA… ». Cliquez dessus et une fenêtre de dialogue s'ouvrira avec le texte du prompt prêt à l'emploi dans un champ « lecture seule » ainsi qu'un bouton « Copier dans le presse-papiers ». NVDA annonce tout le contenu dès l'ouverture de la fenêtre — il suffit de cliquer sur « Copier », de coller (Ctrl+V) dans ChatGPT/Claude et de remplacer le fragment « [INSÈRE ICI TON IDÉE] » par votre propre germe d'intrigue.

Pourquoi procéder ainsi plutôt que par copie depuis les instructions ? La boîte de dialogue dans l'interface graphique présente un avantage d'accessibilité essentiel : elle est native et lue sans interférence par le lecteur d'écran, ne nécessite pas de basculer vers un éditeur de texte (où les caractères spéciaux et les guillemets peuvent être mal copiés) et fonctionne de manière identique sur chaque système d'exploitation. Ce même modèle — une boîte de dialogue avec un prompt à copier — est également utilisé dans le Gestionnaire de Règles (voir ÉTAPE 7b ci-dessous).

Comment l'IA répond : Vous recevrez une réponse en deux parties. La première est le Livre du Monde encadré dans un bloc de code Markdown (balises markdown …). Copiez UNIQUEMENT le contenu du bloc de code (sans les balises ``` elles-mêmes) et collez-le dans le champ « Livre du Monde » du Réalisateur, puis cliquez sur « 💾 Sauvegarder la Bible de manière permanente ». La seconde partie est une recommandation indiquant lequel des modes créatifs (Script ou Audiobook) convient le mieux à votre idée — considérez-la comme un conseil lors de la sélection du mode dans le champ de choix du mode.

Mini-cours Markdown dans le Livre : un seul dièse (#) désigne la section principale (par ex. « # Personnages »), un double dièse (##) désigne une sous-section, les tirets (-) créent des listes, et les doubles astérisques (texte) mettent en gras les règles absolues et inviolables (par ex. « Le Héros NE MENT JAMAIS »). Pour un personnage de langue étrangère, ajoutez un tag avec l'accent, par ex. « [Speaker 1: Marek] - a un accent français ». Le mot-clé « akcent » est OBLIGATOIRE — le moteur de l'application le détecte automatiquement et applique les règles phonétiques correctes aux dialogues de ce personnage.

Conseil: Pensez à mettre à jour votre Livre du Monde de temps en temps (au fur et à mesure que l'intrigue s'enrichit de nouveaux lieux ou de personnages importants). Vous pouvez le faire manuellement ou avec l'aide d'un chatbot externe. Plus la base est riche, meilleurs seront les résultats dans la Réalisation !

ÉTAPE 7b : Gestionnaire de Règles (Ctrl+4) — dictionnaires pour les linguistes sans Python

La version 13.0 introduit un quatrième outil dans la barre : le Gestionnaire de Règles. Vous l'ouvrez avec la touche Ctrl+4 ou depuis le menu Outils. C'est un explorateur visuel du dossier dictionaries/, où l'application stocke toutes les règles phonétiques (accents), les chiffres et les modes du Réalisateur dans des fichiers YAML (format lisible par l'homme, plus simple que JSON).

Pourquoi utiliser YAML ? Jusqu'à la version 12.0, tous les accents, modes créatifs et filtres étaient « intégrés » dans le code Python. Ajouter un nouvel accent nécessitait un programmeur. Dans la version 13.0, tout a été déplacé vers des fichiers .yaml dans le dossier dictionaries/ — toute personne capable d'ouvrir le Bloc-notes peut ajuster un accent existant (« remplacer sz par sh par sch ») ou en ajouter un complètement nouveau (suédois, danois, dialecte russe).

Ce que vous trouverez dans le Gestionnaire de Règles :
- Arborescence des fichiers — liste complète de tous les fichiers YAML dans dictionaries/ avec une répartition par langues sources (actuellement complètement implémentées : Polski, Deutsch, English, Español, Suomi, Français, Íslenska, Italiano, Русский) et catégories (akcenty/, szyfry/, rezyser/, opowiesci/, gui/). Navigation avec les flèches comme dans l'Explorateur de fichiers Windows, support complet de NVDA.
- Bouton « 📝 Ouvrir dans l'éditeur de texte » — ouvre le fichier sélectionné dans le Bloc-notes par défaut du système. Vous éditez, enregistrez, cliquez sur « 🔄 Actualiser l'arborescence » et c'est prêt.
- Bouton « 📋 Dupliquer le fichier sélectionné » — le moyen le plus rapide pour un nouvel accent : vous prenez un fichier existant (par exemple finski.yaml), donnez un nouveau nom (par exemple suédois), le Gestionnaire crée une copie avec le commentaire « changez les champs étiquette et description » et l'ouvre dans l'éditeur.
- Bouton « ➕ Nouveau fichier de règles… » — assistant avec choix du type (accent, chiffre, mode Réalisateur, nouvelle langue source, chiffre algorithmique). Pour les cas simples (accent, chiffre de type « remplacement de lettres »), l'assistant crée un modèle YAML prêt à éditer. Pour les cas nécessitant un programmeur (nouvelle langue source, algorithme de type « mélange du milieu des mots »), l'assistant génère une invite pour le chatbot AI — vous collez dans ChatGPT, obtenez un fichier YAML prêt, enregistrez dans dictionaries/ et c'est prêt.

Application pratique : Vous voulez ajouter un accent suédois ? Ouvrez le Gestionnaire de Règles, choisissez dictionaries/pl/accents/finski.yaml, cliquez sur « Dupliquer », nommez le fichier suédois, changez dans celui-ci le champ étiquette en "Suédois (Alva / Oskar)", le code iso en sv, modifiez quelques règles de remplacement et enregistrez. Retournez à la Page d'accueil et relancez l'application. Le nouvel accent apparaîtra dans le menu Polyglotte (en Mode Réalisateur) et — si vous l'ajoutez au Livre du Monde des personnages (« [Marek] - a un accent suédois ») — également dans la détection automatique des accents du Réalisateur.

Où chercher plus de documentation sur le dossier dictionaries/ :
- Fichier docs/dictionaries.pl.html (disponible dans le package pour les utilisateurs finaux depuis l'onglet Releases) — description courte, en langage simple, de chaque sous-dossier, 6 chiffres prêts, 8 accents prêts et des idées de ce que vous pouvez faire vous-même, sans connaissance de Python.
- Fichier dictionaries/README.md (disponible uniquement lors du clonage du dépôt depuis GitHub — les packages de distribution filtrent les fichiers .md) — documentation technique détaillée du format YAML avec des exemples, des listes de champs, des règles de pipeline, des regex. Ce document est destiné aux linguistes connaissant les bases de la programmation ainsi qu'aux développeurs.

Conseils importants pour les utilisateurs de lecteurs d'écran (NVDA)

1. Messages de succès et d'erreur

Lorsque l'application termine une action (par exemple, enregistre un fichier ou rencontre une erreur), une boîte de dialogue apparaît avec un titre tel que "Succès", "Avertissement" ou "Erreur". NVDA annoncera immédiatement cette fenêtre et lira son contenu. Vous n'avez rien à faire — les dialogues sont entièrement accessibles au clavier, et le focus se place automatiquement sur le bouton "OK". Il n'y a plus de ruses avec le préfixe "Alerte" — les boîtes de dialogue natives wxPython sont directement prises en charge par le lecteur d'écran.

2. Avertissement important : traitement silencieux en arrière-plan

Après avoir cliqué sur des boutons tels que "Envoyer à l'IA" ou "Lancer le Traitement", le programme commence immédiatement le traitement en arrière-plan. Une barre de progression (Gauge) apparaît à l'écran, mais NVDA NE lit PAS sa valeur en temps réel — le lecteur d'écran reste silencieux pendant le travail. Ne cliquez pas à nouveau sur le bouton. Attendez qu'une boîte de dialogue avec le résultat ou un message d'erreur apparaisse — NVDA l'annoncera automatiquement.

3. Navigation entre les outils

La navigation entre les outils (Réalisateur, Polyglotte, Convertisseur, Gestionnaire de Règles) se fait dans une seule fenêtre de programme à l'aide de quatre boutons sur la barre d'outils ou via le menu Outils (Alt, puis N). Raccourcis clavier disponibles : Ctrl+0 (Page d'accueil), Ctrl+1 (Réalisateur), Ctrl+2 (Polyglotte), Ctrl+3 (Convertisseur), Ctrl+4 (Gestionnaire de Règles — nouveauté en 13.0). Après avoir changé d'outil, le focus se place automatiquement sur la description du nouveau module — NVDA commence immédiatement à lire la nouvelle vue.

4. Ordre de tabulation et noms des widgets

Chaque élément de l'interface a un nom français lisible — NVDA le lira lorsqu'il sera focalisé. L'ordre de tabulation est logique : de la description de l'outil, en passant par les champs de configuration, jusqu'aux boutons d'action. Il n'y a pas de surprises ici — la navigation au clavier fonctionne comme dans n'importe quel autre programme natif Windows. Tous les menus et boutons sont en français et NVDA les lira avec une voix française sans aucun réglage supplémentaire.

Notes importantes pour la version 9.0 / Changelog

Nouvelles fonctionnalités et changements dans la version 9

Sauvegarde de la progression de traduction résistante aux plantages (CHANGEMENT — correction d'un bug critique)
Dans la version 8, la reprise d'une traduction interrompue cachait un piège silencieux et destructeur : si l'utilisateur suivait les instructions (en découpant manuellement le fragment déjà traduit) puis reprenait immédiatement la traduction du reste, l'application ouvrait le fichier de sortie en mode écrasement — effaçant irrémédiablement et inconsciemment toute la progression payée. Dans la version 9, l'ensemble du mécanisme a été repensé. Chaque bloc traduit est désormais immédiatement enregistré dans un fichier temporaire (.jsonl) avec un index attribué. La reprise est entièrement automatique — l'application détecte elle-même le fichier et restaure la progression sans aucune intervention de l'utilisateur. Une fois l'opération terminée avec succès, le fichier temporaire est automatiquement supprimé.

Réparateur de Balises dans le Mode Réalisateur (NOUVEAUTÉ)
Une nouvelle option a été ajoutée au menu du Mode Réalisateur — le Réparateur de Balises. Il injecte dans le fichier uniquement le code de langue ISO à deux lettres indiqué par l'utilisateur, sans appliquer aucune règle phonétique ni nettoyage. ÉTAPE 7b (complément) : L'ordre des règles zamiany: est important

Les fichiers dans dictionaries/<kod>/akcenty/*.yaml contiennent une liste de règles zamiany: — des paires modèle → remplacement que le moteur applique SÉQUENTIELLEMENT. Chaque règle suivante opère sur la sortie de la précédente. Cela permet de construire des pipelines du type « décomposer le digramme szcz en shch, puis remplacer ch par h », mais cela ouvre également le piège classique pour l'auteur du pack linguistique.

Le piège de la « boucle séquentielle ». Supposons que pour un accent espagnol visant à faire ressembler le « ñ » polonais à la prononciation de Diego (Loquendo), l'auteur ajoute deux règles :
1. ñ → nj (pour que le « ñ » polonais sonne comme un « nj » doux)
2. j → x (pour que le « j » polonais sonne comme le « j » espagnol — phonétiquement /x/)

Après exécution, il s'avère que les mots avec « ñ » sont prononcés comme « nx », pas « nj ». Pourquoi ? Parce que lorsque la première règle remplace « ñ » par « nj », le nouveau « j » est immédiatement capturé par la deuxième règle et remplacé par « x ». Résultat : au lieu de l'intention « ñ → nj », nous obtenons « ñ → nx ».

Règle de l'ordre (universelle). Lorsque qu'une règle introduit un caractère qu'une autre règle a comme modèle, L'ORDRE COMPTE. Une heuristique sûre : D'ABORD remplacez la CIBLE (le caractère utilisé plus tard comme modèle dans une autre règle) par quelque chose de sûr, ENSUITE introduisez la SOURCE (le caractère qui doit se décomposer en CIBLE). Pour l'exemple espagnol, correctement : d'abord j → x, puis ñ → nj. Résultat : « ñ » donne « nj » (le deuxième « j » ne sera plus consommé, car la règle j → x a été appliquée plus tôt, lorsque « nj » n'existait pas encore).

Comment tester. Après avoir modifié l'ordre des règles dans le fichier d'accent, passez une phrase contenant LES DEUX lettres par le Mode Réalisateur. Pour l'exemple ES : « Niño de paja juega » → le résultat doit avoir l'accent ñ (« ñ → nj ») et l'accent j (« j → x »), c'est-à-dire quelque chose comme « Ninjo de paxa xuega ». Si vous voyez « ninxo » au lieu de « ninjo » — l'ordre est inversé.

Validation dans le moteur (opt-in pour les auteurs de packs). L'application a une heuristique intégrée pour détecter les boucles potentielles, mais elle est désactivée par défaut — car de nombreux pipelines ressemblent à une boucle, bien qu'ils soient intentionnels (le classique « szcz → shch » + « ch → h »). Pour l'activer : réglez la variable d'environnement REZYSER_VALIDATE_ZAMIANY=1 et lancez l'application depuis la console — depuis la source via python main.py, car l'exécutable .exe figé en mode fenêtre (à partir de la version 17.0) n'a pas de fenêtre de console. Le moteur affichera pour chaque fichier d'accents une ligne WARN agrégée avec les trois premières boucles potentielles et le nombre restant. Vérifiez la phonétique résultante sur une phrase test — si l'effet est intentionnel, ignorez le WARN.

Les boutons de déplacement des règles dans le GUI du Gestionnaire de Règles (glisser-déposer, « Vers le haut / Vers le bas ») sont une fonction distincte prévue pour un cycle de version ultérieur — cela nécessite une refonte du Gestionnaire (actuellement, il délègue l'édition de fichiers à un Bloc-notes système externe et n'a pas sa propre vue des règles). Jusqu'à sa mise en œuvre : éditez le fichier YAML manuellement, déplacez les lignes dans la section zamiany:, utilisez le validateur avec la variable ENV et testez sur des phrases de contrôle.

ÉTAPE 2B (avancé, optionnel) : Fournisseur d'IA personnalisé compatible OpenAI

La plupart des utilisateurs devraient rester avec Anthropic recommandé (ÉTAPE 2) — c'est lui qui offre la meilleure qualité. Cependant, si vous avez une raison particulière (coût, accès, confidentialité, modèle local personnel), à partir de la version 18.4 vous pouvez indiquer N'IMPORTE QUEL endpoint compatible avec l'API OpenAI — par exemple OpenRouter, Groq, Fireworks, DeepSeek, Ollama local ou un endpoint Gemini compatible OpenAI. Tout le moteur IA emprunte alors un seul chemin vers cet endpoint, sans intégration séparée par fournisseur.

Il s'agit d'une option pour utilisateurs avancés : vous la configurez manuellement dans le fichier golden_key.env, en ajoutant à côté (ou à la place) de la clé Anthropic trois lignes ainsi que la clé du fournisseur choisi :

LLM_PROVIDER=openai_compat
LLM_BASE_URL=adresse_de_l'endpoint (ex. https://openrouter.ai/api/v1)
LLM_MODEL=nom_du_modèle_chez_le_fournisseur (ex. openai/gpt-4o-mini)
OPENAI_API_KEY=votre_clé_chez_ce_fournisseur

Comment ça fonctionne :
• Lorsque LLM_PROVIDER=openai_compat, TOUT le moteur IA (Réalisateur, Histoires, Polyglotte, titres, détection de langue) utilise l'endpoint indiqué, et le nom du modèle issu des fichiers de configuration est remplacé par LLM_MODEL.
• Lorsque la ligne LLM_PROVIDER est absente (ou a la valeur anthropic), l'application fonctionne comme à l'ÉTAPE 2 — exclusivement avec la clé Anthropic. Vous n'avez rien à modifier.

Important (qualité): les prompts système de l'application sont écrits et ajustés pour Claude. Un autre modèle peut produire une qualité inférieure — respecter moins bien les règles du monde, perdre la structure JSON dans les modes avec choix ou renvoyer du texte dans une mauvaise langue. Il s'agit d'un compromis délibéré coût↔qualité de votre côté. Si vous tenez au meilleur résultat, restez avec Anthropic.
