Reżyser Audio GPT — Heildarleiðarvísir (Útgáfa 18.21.0 – Fullbúin útgáfa)

Velkomin í Hybrid Recording Studio! Þessi verkfærakista gerir þér kleift að skrifa, skipuleggja, stilla og þýða handrit fyrir hljóðleiki og hljóðbækur sjálfvirkt. Hún hefur verið fínstillt til að vinna með faglegum talgervlum og staðbundnum skjálestrum (NVDA).

Verkfærakistan samanstendur af aðalstúdíóinu (Leikstjórn), þýðinga- og hreimaverkfærinu (Tungumálamaður), skráarbyggingarverkfærinu (Hljóðbókararkitekt), Reglustjóra (frá útgáfu 13.0 — án Python geturðu bætt við nýjum hreim, dulmáli eða sköpunarham, sjá SKREF 7b hér að neðan) og — frá útgáfu 15.0 — Sögueiningunni (gervigreindarframleiddur gagnvirkur skáldskapur í annarri persónu, lesin af TTS eða skjálesara, lýst í sérstöku handriti tales.is.html). Öll fimm verkfærin eru aðgengileg í einum forritsglugga, skipt á milli með hnöppum á stikunni eða með lyklaborðssamsetningum Ctrl+1..Ctrl+5.

SKREF 1: Fyrsta gangsetning (Cross-Platform)

Sæktu nýjustu uppsetningarskrána frá Releases flipanum á GitHub (skrá Rezyser_Audio_v<numer>_Installer.exe) og keyrðu hana með því að tvísmella. Uppsetningarforritið mun bjóða upp á sjálfgefna staðsetningu fyrir uppsetningu — Programs möppuna í staðbundnu skráasafni á reikningnum þínum — og krefst ekki stjórnandaaðgangs. Þú getur einnig valið þína eigin slóð með „Browse" hnappnum — uppsetningarforritið man hana og notar hana sjálft við síðari uppfærslur, án þess að spyrja. Eftir uppsetningu skaltu ræsa forritið með tákninu á skjáborðinu eða úr Start valmyndinni. Eftir smá stund birtist aðalgluggi forritsins — Hljóðstjóri GPT. Frá útgáfu 17.0 er forritið fryst sem innfædd keyrsluskrá í gluggaham, svo enginn flöktandi terminalgluggi birtist lengur og það ræsir hraðar en áður. Engin vafri, enginn bakgrunnsþjónn. Þegar þú ert búinn að vinna, lokaðu bara glugganum.

Allt forritið, þar á meðal Python vél, verkefni og API lykill, er í einni möppu undir uppsetningarslóðinni — alla möppuna má flytja á USB, í skýið eða á aðra tölvu (ítarleg leiðbeining í kaflanum „Flytja verkefni og API lykil" hér að neðan).

Mikilvægt: Möppan runtime/ inni í uppsetningarmöppunni er PyInstaller pakki (frá útgáfu 17.0) — inniheldur einangraðan Python túlka og bókasöfn, tilbúin til notkunar án sérstakrar kerfisuppsetningar; hún gegnir einnig hlutverki íláts fyrir falin verkefnametadata. Ef þú klónar geymslu (þróunarslóð), er þessi mappa ekki til staðar og ætti ekki að vera — þú notar þá sýndarumhverfi venv eins og lýst er í kaflanum fyrir forritara hér að neðan.

Fyrir Forritara (Windows — Git geymsla)

  1. Klónaðu geymsluna á diskinn þinn.
  2. Keyrðu skrána setup_dev.bat. Skjalið mun sjálfkrafa búa til sýndar Python umhverfi (venv) og setja upp allar nauðsynlegar háðar frá skránni requirements.txt.
  3. Keyrðu forritið með skipuninni python main.py eða með skránni run_dev.bat — skjalið mun sjálfkrafa greina venv möppuna og ræsa forritið.

Fyrir Forritara og venjulega notendur (macOS / Linux)

  1. Klónaðu geymsluna á diskinn þinn.
  2. Opnaðu skel í verkefnamöppunni og gefðu skrám heimild til að keyra: chmod +x *.sh
  3. Keyrðu uppsetningarskrána: ./setup_dev.sh — skjalið mun búa til venv umhverfi og setja upp háðar.
  4. Keyrðu forritið: python main.py eða ./run.sh

Hvað þú sérð eftir gangsetningu: Eftir að forritið hefur verið ræst opnast gluggi með upphafsskjá. Þar finnur þú stutta lýsingu á tiltækum verkfærum og kafla „Kerfisathugun". Ef API lykillinn er ekki enn stilltur, sérðu rauða tilkynningu sem segir að AI-byggðar einingar (Leikstjórn, Þýðandi) muni ekki virka — ókeypis staðbundnar aðgerðir (hreim, Arkitekt) eru þó virkar strax. Stillingu API-lykilsins er lýst í næsta skrefi.

Flytja verkefni og API lykil (migrering)

Ef þú vilt flytja verkefnin þín, API lykil og staðbundnar stillingar á aðra tölvu (eða endurheimta allt eftir að Windows hefur verið endursett), er ekki nauðsynlegt að afrita einstaka skrár handvirkt — öll forritsmappan er sjálfbær.

  1. Gakktu úr skugga um að forritið sé ALVEG lokað. Ef þú sérð forritstáknið í kerfisbakkanum (við hliðina á klukkunni, hægra megin á verkefnastikunni), hægri-smelltu á það og veldu „Loka". Opnar skrár hindra afritun.
  2. Finndu Hljóðstjóri GPT skjáborðstáknið. Hægri-smelltu á það (eða notaðu Umsóknarhnappinn eða Shift+F10 við NVDA leiðsögn) og veldu valkostinn „Opna skráarstaðsetningu". ATH á Windows 11: í nýju einfaldaðri samhengisvalmyndinni gæti þessi valkostur verið falinn — veldu fyrst „Sýna fleiri valkosti" (eða ýttu á Shift+F10 tvisvar til að opna strax fulla valmyndina með valkostinum).
  3. Windows Explorer gluggi opnast í uppsetningarmöppunni. Ýttu á Backspace takkann (einfaldasta leiðin, virkar alltaf) eða smelltu á „Upp" örina á tækjastikunni til að fara upp um eitt stig — þar sérðu fulla möppuna með forritinu. Athugið: Alt+Upp ör virkar aðeins þegar fókusinn er á skráarlistanum — ef Explorer opnast með fókus á slóðastikunni (algengt), þá gerir Alt+Upp ör ekkert, notaðu þá Backspace.
  4. Afritaðu alla þessa möppu á USB, skýjadrif (OneDrive, Google Drive, Dropbox) eða ytri disk. Möppan inniheldur allt sem þarf til að endurheimta vinnustöðu:
    - Verkefnin þín (möppan skrypty/ — .txt skrár af frásögnum, .md Heimsbók og útkomuskrár eftirvinnslutækjanna: minni, kaflatitlar, útgáfukort; möppan opowiesci/ — gagnvirkir leikir).
    - API lykill (skráin golden_key.env í aðalmöppunni).
    - Þínar eigin hljóðreglur, hreim, dulmál, ef þú breyttir einhverju í Reglustjóra (möppan dictionaries/<tungumálakóði>/, t.d. dictionaries/pl/akcenty/wloski.yaml).
    - Forritsstillingar og val á skapandi ham (möppan runtime/skrypty/, .mode skrár).
    - Einangrað Python umhverfi (möppan runtime/), svo þú þarft ekki að setja neitt upp á nýju tölvunni.
  5. Á nýju tölvunni: sæktu nýjustu uppsetningarskrána frá Releases flipanum á GitHub og settu upp forritið á hefðbundinn hátt. Keyrðu forritið einu sinni til að búa til tóma skráarskipan. Lokaðu forritinu. Afritaðu síðan áður vistaða möppuna á uppsetningarstaðinn og skrifaðu yfir skrárnar — eða veldu sértækt aðeins þær möppur sem þú hefur áhuga á (skrypty/, opowiesci/, golden_key.env) og límdu þær á réttan stað í nýju uppsetningunni.

Ábending fyrir NVDA notendur: samhengisvalmyndin „Opna skráarstaðsetningu" sem er kölluð fram með Umsóknarhnappinum er fullkomlega aðgengileg — NVDA les hvert atriði á íslensku. Eftir að Explorer hefur verið opnað í markmöppunni, notaðu Backspace takkann til að fara upp um eitt stig (virkar alltaf, óháð því hvort fókusinn er á skráarlistanum eða slóðastikunni), og síðan Ctrl+A til að velja allt og Ctrl+C til að afrita.

Ábending: valkosturinn „Opna skráarstaðsetningu" er innfætt nafn fyrir íslenska útgáfu Windows. Í ensku kerfi heitir hann „Open file location", í öðrum tungumálaútgáfum — á sama hátt á staðbundnu tungumáli stýrikerfisins.

Hamur 3: Dulritari (NÝTT í 13.0 — skemmtun með texta, frítt, staðbundið)

Þriðji RadioButton í Tungumálamanninum, við hliðina á AI Þýðanda og Leikstjórnarham: „Dulritarahamur (skemmtun með texta, tilviljanakennd truflun)". Virkjar sex staðbundnar reiknirit sem afmynda texta — til skemmtunar, gátna, tungumálalegra þrauta. Eftir að hamurinn er valinn birtist fellilisti með reikniritum, og fyrir eitt þeirra (Cæsar dulritið) er viðbótar reitur fyrir færslu.

Aðgengileg reiknirit (veldu í valmyndinni „Veldu afmyndar reiknirit"):

  • Texta Afturköllun (Lesið afturábak með stórum staf) — hver setning er snúin við staf fyrir staf, með punktum/upphrópunarmerki/spurningarmerki á enda og stórum staf í upphafi. Áður en snúið er við, stækkar skriftin vinsælar skammstafanir (t.d., þ.e., m.a., u.þ.b., o.s.frv.), svo útkoman eftir viðsnúning hafi enn merkingu — án þess myndi „t.d." snúast við í fáránlegt „.d.t".

Innblástur: verkefni úr þættinum „The Traitors. Zdrajcy". Þegar stjórnandinn sýndi þátttakendum vinsælt pólskt lag úr teiknimynd — einfaldlega spilað afturábak — voru viðbrögðin á borð við „hvaða tungumál er þetta?", „þetta er líklega armenska", „ungverska eða finnska". Verkefnið var að eitt lið fékk texta lagsins í skóginum, skrifað afturábak, og átti að syngja það í þessari snúnu mynd, hitt liðið tók það upp, spilaði það afturábak — og í kenningu endurheimti upprunalega lagið til að giska á. Nákvæmlega sama fyndna hljóðvilla myndar okkar Afturköllun þegar þú spilar breytta skrá í gegnum TTS.

  • Typoglycemia (Blandaður miðhluti orða) — klassískur sálfræðilegur áhrif: „Þú gtiær lseið txeta í hvðaa röð sem er, svo fralarmega sem ftysri og sðsíiasti sftaur hvres oðrs er á rttéum saðt". Skriftin blandar tilviljanakennt miðhluta hvers orðs lengra en 4 stafir, fyrsti og síðasti stafur eru óbreyttir. Frábært til að prófa „hversu mikið sé ég í raun, og hversu mikið ályktar heilinn minn".

  • Skemmdur Sími / Ormadíalekt — hvert „s", „z" eða tvíhljóð „sz" er tilviljanakennt lengt í hvæs af lengd 4-8 stafa („ssssss", „zzzzzz", „ssssssz"). Innblástur: Snecko úr leiknum „Slay the Spire". Áhrif: textinn hljómar eins og hann hafi verið lesinn af ormi með talgalla.

  • Sérhljóðari (Allt hljómar á „O") — hverjum sérhljóða í textanum er breytt í „o", líka broddstöfunum (á, é, í, ó, ú, ý). „Góðan daginn" → „Goðon dogonn". Mýkingarþrepið úr pólsku (dzi/ci/ni/si/zi) er viljandi tómt í íslenska pakkanum: þessi skrif eru ekki til hér, svo reglan verður einfaldlega sérhljóðaskipti. Því lengri texti, því skemmtilegri áhrif (og skjálesari les þetta með fullri sannfæringu).

  • Sterkt Stam / Skemmdur Vélmenni — bætir við stami í upphafi orða: „st-st-stelpa", „þr-þr-þrjótur". Fyrir stutt orð (minna en 3 stafir) sleppir reikniritið þeim. Ef annar stafur orðsins er samhljóði, endurtekur það fyrstu tvo stafina (náttúrulegri áhrif); ef sérhljóði — endurtekur aðeins fyrsta.

  • Cæsar Dulrit (færslu íslenska stafrófsins) — klassískt staðgengils dulrit: hver stafur er færður um N stöður í íslenska stafrófinu (AÁBDÐEÉFGHIÍJKLMNOÓPRSTUÚVXYÝÞÆÖ, 32 stafir). Færslugildið slærðu inn í reitinn „Færsla Cæsar dulrits (0 = tilviljun, bil -31…31)". Ef þú slærð inn 0 — forritið velur tilviljanakennda færslu á bilinu 1-31 og sýnir hana í skilaboðum eftir að ljúka (svo þú getir síðan afkóðað). Stafir utan stafrófsins (tölur, greinarmerki, bil) eru óbreyttir.

Hagnýt notkun: dulritin vista niðurstöðuna á sama formi og Leikstjórnarhamur (.html með lang tagi eða .docx með XML merkjum), þannig að NVDA les þau með rödd viðeigandi tungumáls. Sérstaklega Afturköllun og Sérhljóðari hljóma í talgervli mun áhugaverðari en þegar þú lest þau með augunum — því heilinn reynir sjálfkrafa að „afkóða" textann við sjónlestur, en TTS les hann nákvæmlega eins og hann er skráður.

Öll sex dulritin eru einnig lýst á breiðari, aðgengilegri hátt í skjalinu docs/dictionaries.pl.html í forritapakkanum — ásamt ráðum um hvernig á að bæta við eigin dulriti af gerðinni „skipta um stafi" án þess að kunna forritun (t.d. skólaslang, grasamál).

Vinnslutungumál, þvingun og gæðahamur (NÝTT í 18.11)

Skjalahlutinn hefur nú fellilista fyrir vinnslutungumál. Með honum velur þú samkvæmt reglum hvaða tungumáls Leikstjórnar- og Dulkóðunarhamur vinna: hreimlista og dulmálslista, ásamt stafrófi Sesarslykils og tilfærsluspönn þess.

  • Sjálfgefna stillingin „Greina sjálfkrafa" heldur fyrra hegðunarmynstri: tungumálið ákvarðast út frá innlesnu skjali, og ef það er annað en tungumál forritsins færðu stutta tilkynningu um að listunum hafi verið skipt yfir.
  • Val á tilteknu tungumáli úr listanum er bindandi — forritið breytir því ekki sjálfkrafa við innlestur skjals.

Undir listanum er valreitur sem þvingar valið tungumál fyrir allt skjalið. Sjálfgefið er hver efnisgrein unnin samkvæmt tungumáli sem greinist fyrir þá efnisgrein — það er yfirleitt besti kosturinn, því innskot á öðrum tungumálum fá sínar eigin, réttu reglur. Merktu við þvingun þegar þú vilt samræmda vinnslu á öllu skjalinu. Dæmi þar sem þetta er nauðsynlegt: afturkræf fjöllaga dulritun. Stafróf Sesarslykils er mislangt eftir tungumálum, svo án þvingunar verður texti með blönduðum tungumálum dulritaður með nokkrum ólíkum stafrófum — og þá krefst afkóðun þess að vita hvar tungumálamörkin lágu. Með þvinguðu tungumáli dulritar og afkóðar allt skjalið eitt og sama stafróf. Fyrirvari: í tungumálum þar sem Caesar-stafrófið inniheldur broddstafi sem eru samræmdir við innlestur (pólska, þýska) er afkóðunin ekki fullkomlega trú — broddstafir dulritextans eru umbreyttir í grunnform sín við endurinnlestur, áður en þeir ná afkóðuninni. Full afturkræfni fæst með stafrófum án slíkra tákna (t.d. ensku).

Gervigreindarþýðandinn hefur hins vegar fengið nýjan valreit fyrir gæðahaminn. Þegar merkt er við hann fær líkanið aukið svigrúm fyrir innri textagreiningu áður en þýtt er (svokölluð extended thinking) — þýðingin tekur lengri tíma og kostar fleiri tákneiningar (tokens), en erfiðir kaflar verða vandaðri. Valkosturinn virkar eingöngu með Anthropic Claude-líkönum; ef þú notar annan þjónustuveitanda gegnum OpenAI-samhæfðan endapunkt hefur merking við hann engin áhrif.

Skyld smáatriði: Stafir með makron sem notaðir eru við umritun japönsku (t.d. Tōkyō, rāmen, jūdō) eru frá og með þessari útgáfu samræmdir eins og aðrir erlendir broddstafir — í flestum tungumálum í hreinan staf (Tokyo), en í finnska pakkanum með tvöföldun sérhljóðans (Tookyoo), í samræmi við finnsku venjuna við ritun langra hljóða. Þannig detta þeir ekki lengur út úr stafrófi Sesarslykils sem opinská tákn í dulritextanum.

Málgreining

Áður en skriftin "spillar" textanum, athugar hún hvaða tungumál textinn er skrifaður á. Ef hún greinir að það sé ekki pólskur texti, birtir hún viðvörun. Hljóðfræðilegu reglurnar eru sniðnar fyrir pólsku — að beita þeim á texta á öðru tungumáli myndi leiða til ófyrirsjáanlegra áhrifa.

Hreimar hannaðir fyrir staðbundna talgervla (NVDA)

Hreimarnir hafa verið 100% hannaðir fyrir staðbundna, ókeypis og greidda talgervla fyrir skjálesara — Vocalizer og eSpeak í NVDA. Þetta tryggir stöðugleika og fyrirsjáanleika á hverri tölvu.

Af hverju ekki ElevenLabs? Prófanir á lengri skjölum sýndu að hljóðfræðileg afbökun texta í vélum eins og ElevenLabs þvingar ekki fram tilætlaðan hreim — vélin "giskar" einfaldlega á tungumálið og gerir frekar hreim vestur-/suður-slavneskan. Staðbundnir talgervlar NVDA eru mun hlýðnari í þessu efni.

Sérkenni staðbundinna talgervla (TTS)

Mismunandi TTS-vélar hegða sér á ólíkan hátt. Hér að neðan eru lykilmunir sem hafa bein áhrif á framburð:

eSpeak (Open Source)

Léttur, ókeypis vél með gríðarlega stórt tungumálasafn — styður m.a. íslensku. Mjög strangur varðandi kóðun tákna, sem gerir hann fyrirsjáanlegan. Hins vegar hefur hann hljóðfræðilegar takmarkanir: oft deilir hann hljóðönum milli tungumála, sem veldur því að til dæmis úkraínska hljómar með rússneskum blæ.

Tiflotecnia Voices fyrir NVDA (raddir Cerrence — áður Vocalizer frá Nuance)

Tiflotecnia Voices er beinn arftaki Vocalizer frá Nuance — viðskiptahugbúnaður með raddir af nýrri kynslóð frá fyrirtækinu Cerrence, dreift sem .nvda-addon pakki í NVDA Add-on Store. Gamli Vocalizer (32-bita .dll bókasöfn frá Nuance) var lagður af með NVDA 2026.1; Cerrence endursamdi raddirnar í 64-bita og Tiflotecnia gaf þær út undir nýju nafni. Gæði framburðar eru áberandi betri en í fyrri kynslóðinni.

Hvernig á að setja upp: NVDA → Verkfæri → Add-on Store → leita að „Tiflotecnia Voices for NVDA" → Setja upp. Eftir uppsetningu birtist sérstök undirvalmynd „Tiflotecnia Voices" í NVDA valmyndinni og eigin flokkur í stillingum NVDA. GUI viðbótarinnar leiðir þig skref fyrir skref í gegnum kaup á leyfi (eða virkjun 7 daga prufutímabils), val og uppsetningu fyrstu raddanna (t.d. pólsku Ewa fyrir fljótlegan lestur á kerfisstýringum, finnsku Satu fyrir hreim í Tungumálamanninum). Innbyggð hjálp viðbótarinnar er skýr, svo við endurtökum ekki ferlið hér — það er nóg að láta viðbótina leiða þig.

Ábending fyrir þá sem flytja frá Vocalizer og Eloquence: uppfærsla á lægra verði er í boði. Ferli: eftir að greiðsla hefur verið staðfest, sendu strax tölvupóst á netfangið sem er tengt á skjánum eftir greiðslu og biddu um staðfestingu á gamla virkjunarkóðanum — Tiflotecnia mun staðfesta rétt til afsláttar og laga verðið. Án þessa tölvupósts mun kerfið meðhöndla þig sem nýjan viðskiptavin.

Aðgengi að röddum: Tiflotecnia Voices styður flest tungumál sem Vocalizer hafði (m.a. pólsku, ensku, þýsku, frönsku, spænsku, finnsku, ítölsku, rússnesku). Listi yfir raddir fyrir hvert tungumál er sýnilegur í stillingaflokki viðbótarinnar áður en leyfi er keypt.

Microsoft OneCore

Ókeypis raddir sem eru innbyggðar í Windows kerfið (Mobile Voices). Gott jafnvægi milli gæða og aðgengis tungumála. Býður upp á hágæði og hefur stuðning fyrir íslensku (Gudrun), finnsku (Heidi) og ítölsku (Elsa). Athugið: OneCore styður EKKI sjálfvirka tungumálaskiptingu byggða á lang-tögum (nema þú notir innbyggðan skjálesara kerfisins, sögumann) — sjá kafla hér að neðan.

Hvernig á að sækja OneCore raddir á Windows? OneCore raddir eru ókeypis, en flest tungumál eru ekki uppsett sjálfgefið. Til að sækja tungumál sem vantar, farðu í Windows Stillingar → Tími og tungumál → Tal → Stjórna röddum (eða "Bæta við röddum"). Veldu tungumál af listanum (t.d. Íslenska, Finnska, Ítalska) og smelltu á Sækja. Eftir niðurhal birtist röddin sjálfkrafa í NVDA — án nokkurrar viðbótarstillingar.

Apple (iPhone / iPad / Mac) — VoiceOver með Vocalizer

Á Apple tækjum er Vocalizer vél innbyggð í stýrikerfið og styður öll tungumál án nokkurra viðbótarkaupa. Sjálfgefið er þó uppsett þétt útgáfa af röddum sem hljóma dálítið vélrænt. Til að fá mun betri og náttúrulegri hljóm er gott að hlaða niður útvíkkuðum eða úrvalsútgáfum:
- Á iPhone/iPad: Stillingar → Aðgengi → VoiceOver → Tal → Rödd → veldu tungumál (t.d. Finnska) → snertu nafn raddarinnar (t.d. Satu) → þú munt sjá valkostina "Útvíkkað" og "Úrvals". Sæktu valda útgáfu — hún tekur meira pláss á disknum, en munurinn á gæðum er áberandi.
- Á Mac: Kerfisvalkostir (eða Kerfisstillingar) → Aðgengi → VoiceOver → Opna VoiceOver verkfæri → Tal → Rödd → smelltu á "Sérsníða" við valda rödd og sæktu útvíkkaða eða úrvalsútgáfu.

Android — Vocalizer greitt fyrir hverja rödd

Á Android er Vocalizer fáanlegt sem forrit í Google Play Store (leitaðu að "Vocalizer TTS"). Athugið: hvert tungumál og rödd er keypt sérstaklega — það er ekki til eitt leyfi fyrir allt. Killer Feature fyrir blinda: Skrár með tungumálamerkjum

Þetta er sannkölluð bylting. Unnar skrár eru nú vistaðar sem:

  • .html með lang eiginleika (t.d. lang="fi" fyrir finnsku) — NVDA les þennan merkimiða og skiptir sjálfkrafa yfir á viðeigandi tungumálatalgervil. Engin handvirk stilling!
  • .docx með varðveittum sniði — hver textahluti hefur innsprautað tungumálamerki í XML skjalsins, þannig að Word og NVDA vita hvaða rödd á að nota fyrir hvern hluta.

Unnar skrár eru alltaf vistaðar sem NÝ skjöl (t.d. akcent_Finski.html).

Sjálfvirk tungumálaskipting í NVDA — það sem þú þarft að vita

Til að NVDA skipti raunverulega um rödd byggt á lang tag, þarf að vera virk stilling "Skiptu sjálfkrafa um tungumál þegar það er stutt". Þú finnur það í NVDA Valmynd → Tal. Sjálfgefið er það virkt við fyrstu ræsingu lesarans — en það er gott að athuga hvort einhver hafi slökkt á því.

Mikilvægt takmörkun á OneCore röddum: Microsoft OneCore raddir styðja ekki innfæddan þennan eiginleika með NVDA, aðeins með innbyggða Windows lesaranum. Það er til óopinber viðbót við NVDA sem heitir „One Core Autolang", sem reynir að laga þetta — en þróun þess hefur verið stöðvuð fljótt. Ástæðan er einföld: á hverju ári, með fyrstu útgáfu NVDA á því ári, koma breytingar sem brjóta samhæfni API (svokallaðar API Breaking Changes). Stundum er nóg að uppfæra reitinn „last tested version" í yfirlýsingu viðbótarinnar, en stundum þarf raunverulegar breytingar á kóðanum — og höfundurinn nær ekki að fylgja eftir með uppfærslum. Ef þú vilt sjálfvirka tungumálaskiptingu, eru öruggari valkostir Tiflotecnia Voices (greitt, kafli hér að ofan) eða eSpeak (ókeypis, lakari gæði), sem styðja þennan eiginleika innfæddan — en varúð: núna í Tiflotecnia Voices virkar það með forgangsvillu (sjá „Kritískur krókur" hér að neðan). Eftir að hafa afritað plásturinn gengur sjálfvirk skipting eins og í gamla Vocalizer.

Kritískur galli Tiflotecnia Voices: biluð tungumálagreining

Fyrst góðu fréttirnar — viðvörunin um NVDA 2026.1 úr fyrri útgáfum handbókarinnar endaði með góðum árangri: Cerrence afhenti 64-bita bókasöfn, Tiflotecnia gaf þau út í .nvda-addon pakka sem er aðgengilegur í Add-on Store (sjá kaflann hér að ofan), og Vocalizer hjá þeim sem héldu honum til loka kom aftur undir nýju nafni — með betri gæðum og án 32-bita takmarkana.

Með útgáfu Tiflotecnia Voices kom hins vegar nýr kritískur galli — í tungumálagreiningu. Í stillingum viðbótarinnar er hægt að stilla hvaða rödd á að nota fyrir ákveðna stafi (t.d. latneska, kyrillíska) eftir því hvaða raddir eru uppsettar. Vandamálið er í forgangsröðinni: núna er fyrst beitt yfirskrift á hvern staf, síðan fallbakki til ISO tungumálakóða (í reynd óaðgengilegt fyrir SAMA stafróf, sem yfirskriftin hefur nú þegar verið stillt á), og að lokum valin rödd. Afleiðingin birtist innan sama stafrófs: þú ert með texta á finnsku með réttum lang="fi" merkimiða, uppsett Satu sem finnska rödd Tiflotecnia, EN í stillingum er valin pólsk rödd fyrir latneska stafi — Satu LES ekki þennan texta, þrátt fyrir réttan ISO merkimiða. Yfirskrift á hvern staf „pólsk rödd fyrir latínu" vinnur á fyrsta stigi, ISO fi er aldrei athugað. Fyrir pör með mismunandi stafróf virkar kerfið rétt (rússneskur texti + Milena fyrir kyrillískt + pólsk rödd fyrir latínu — allt kyrillískt fer með Milenu, möguleg latnesk nöfn með pólskri rödd; hvert stafróf er í sinni yfirskrift). Eftir flutning frá Vocalizer, þar sem tungumálaskipting á grundvelli ISO virkaði fullkomlega, munu notendur taka eftir þessari afturför strax — sérstaklega þeir sem nota nokkra evrópska hreima í Tungumálamanninum (Satu, Alice, Markus) á sama latneska stafrófi.

Greining og plástur: Ég greindi vandamálið á Python stigi í kóða viðbótarinnar og útbjó plástur sem breytir forgangsröðinni í: ISO → valin rödd → stafayfirskrift. Plásturinn viðheldur gagnlegri skiptingu á latínu fyrir latnesk nöfn í rússneskum texta, þegar „tungumálagreining á grundvelli Unicode stafa" er virk í stillingum. Ég sendi plásturinn til þróunaraðila Tiflotecnia — enn án svars, svo þeir halda sig líklega við sína eigin lausn. Ef viðbótin fær uppfærslu mun ég uppfæra plásturinn ef þörf krefur.

Hvað á að gera á meðan: ef þú vilt hafa rétta tungumálagreiningu (það er þess virði — þetta var eitt af „killer features" gamla Vocalizer, sjá „Killer Feature fyrir blinda" hér að ofan), opnaðu mál í forritasafni á GitHub með merkimiðanum tiflotecnia-patch og netfangið þitt í textanum. Það er þess virði að bæta við stuttri lýsingu á vandamálinu á eigin tungumáli (2–3 setningar duga) — vélmennið greinir tungumálið (stuðningur: pólska, enska, þýska, spænska, finnska, franska, íslenska, ítalska, rússneska) og svarar á sama tungumáli; án lýsingar eða á öðru tungumáli kemur svarið á ensku. Sjálfvirka vélmennið mun strax loka málinu með staðfestingu á innsendingu (án ummerkja í opinberu þræðinum), og þú færð plásturinn í tölvupósti yfirleitt innan nokkurra daga. Plásturinn er EKKI birtur í forritasafninu né sem Gist — Tiflotecnia Voices fyrir NVDA er viðskiptahugbúnaður, og leyfi viðbótarinnar leyfir ekki endurdreifingu á skrám þess, jafnvel ekki breyttum. Eftir að þú hefur fengið plásturinn þarftu að afrita innihald hans í %appdata%\Roaming\nvda\addons\TiflotecniaVoices, skipta út skrám. Varúð við afritun: ef Windows spurði ekki um skipti, þá hefurðu líklega afritað alla TiflotecniaVoices_edits möppuna með innihaldi hennar Í STAÐINN FYRIR einungis innihaldið — í slíku tilviki farðu inn í nýju undirmöppuna, klipptu allt, límdu það upp um eitt stig og skrifaðu yfir. Eftir að plástrinum hefur verið beitt með góðum árangri, endurræstu NVDA — njóttu betri gæða Cerrence 64-bita radda og réttrar tungumálagreiningar, sem er sambland sem enginn einstakur framleiðandi á markaðnum býður upp á. Við gerum ráð fyrir að þú hafir gilt leyfi fyrir Tiflotecnia Voices — við staðfestum það ekki, en þú getur ekki beitt plástrinum á möppu annarra án leyfis.

SKREF 6: Arkitekt hljóðbóka

Tól til að undirbúa faglega skráarskipulag fyrir skjálesara og ElevenLabs. Farðu í það með því að smella á hnappinn „📄 Breytingartæki" á hnappaslánni eða velja Verkfæri → Breytingartæki úr valmyndinni (flýtilykill: Ctrl+3).

Hvernig virkar þetta?

  1. Sláðu inn slóð að upprunaskránni í textareitinn eða smelltu á hnappinn „Skoða..." til að velja skrá í kerfisglugga. Skriftin tekur við bæði .txt og .docx, sem og .html og .htm skrám.
  2. Smelltu á „Byggja arkitektúr fyrir ElevenLabs".
  3. Skriftin mun skanna hverja línu texta og breyta lykilorðum (Þáttur, Kafli, Formáli, Eftirskrift, Upphaf) í „Heading 1" fyrirsagnir í Word-skjalinu.
  4. Senur (línur sem byrja á orðinu „Atriði") breytast í feitletraðan texta — sýnilegar í skjalinu en ósýnilegar í efnisyfirliti ElevenLabs.
  5. Allur annar texti (samræður, lýsingar) fer óbreyttur í gegn.
  6. Þú færð skrána arkitektúr_[nazwa_oryginału].docx — faglegt Word-skjal tilbúið til frekari vinnslu. Til dæmis ef inntaksskráin þín hét znieczulica.txt, mun úttaksskráin heita arkitektúr_znieczulica.docx og birtast í sömu möppu og frumskráin.

Hreinsun samhliða: Skriftin fjarlægir sjálfkrafa HTML-merki (ef textinn kemur úr vafra eða úr staðbundinni .html skrá, t.d. þeirri sem Poliglótan bjó til) og Markdown-fyrirsagnarmerki (t.d. ### eða ####) áður en vinnsla hefst. Þú þarft ekki að hreinsa skrána handvirkt.

Söguhamur: sjálfvirk flokkun leiktíma í senur (frá v15.1)

Ef þú hleður inn í Arkitektinn skrána opowiesci/<gra>.txt sem Gagnvirka Söguhlutinn bjó til, mun umbreytirinn þekkja leiktímamerki (t.d. „--- Tura 7 ---" — einnig á öðrum studdum tungumálum ef þú lékst á öðru) og setja inn nýja fyrsta stigs fyrirsögn „Atriði N" á fimm leiktíma fresti (númerið byrjar á 1, á tungumáli leiksins þíns). Önnur leiktímamerki eru fjarlægð — þau birtast ekki í frásögn hljóðbókarinnar, því „Tura 7" lesið upp af TTS brýtur innlifun hlustandans. Útkoman er Word-skjal með náttúrulegu senuskipulagi, nokkrar mínútur af hljóði í hverri senu, tilbúið til innflutnings í ElevenLabs. Virkni þessi er sjálfvirk — venjulegar hljóðbókarskrár án leiktímamerkja (klassísk frásögn úr Leikstjóra) eru unnar nákvæmlega eins og áður.

Öflugur kostur fyrir NVDA og ElevenLabs notendur

„Heading 1" snið fyrir kafla er ekki bara fagurfræðilegt. Í NVDA geturðu flett yfir fyrirsagnir á ljóshraða með því að ýta á H-takkann (eða 1 fyrir fyrirsagnir á fyrsta stigi). Í stað þess að fletta í gegnum hundruð síður hoppar þú úr kafla í kafla á broti úr sekúndu. Þetta breytir vinnulaginu með löngum skjölum. Í ElevenLabs hefurðu vissu fyrir því að vélin setji sjálfkrafa inn skurði og hengist ekki upp við stjórnun hljóðklippa.

SKREF 7: Hvernig á að skrifa Heimsbókina (Kvaðning Arkitektsins og Markdown-smánámskeið)

Gervigreind sem knýr Aðalstúdíóið skilur skipanir best þegar þær eru sniðnar á Markdown-merkingarmálinu. Ef þú gefur gervigreind í Leikstjóranum aðeins lauslega hugmynd (t.d. „tvær systur í hinum heimi"), mun vélin fara í uppnám vegna skorts á upplýsingum og búa til banallega, fyrirsjáanlega sögu sem hunsar rökfræðina.

Til að koma í veg fyrir þetta skaltu nota ytri spjallbot (t.d. ókeypis ChatGPT eða Claude) sem persónulegan Arkitekt þinn. Í útgáfu 13.0 þarftu ekki lengur að afrita kvaðninguna úr leiðbeiningunum handvirkt — í stjórnborði Leikstjórans, rétt undir hnappinum „💾 Vista Heimsbók varanlega", finnur þú hnappinn „📖 Ábending Arkitekts fyrir AI…". Smelltu á hann og gluggi opnast með tilbúnum kvaðningstexta í „eingöngu lestur" reitnum ásamt hnappinum „Afrita á klippiborð". NVDA tilkynnir allt innihaldið strax þegar glugginn opnast — nóg er að smella á „Afrita", líma (Ctrl+V) í ChatGPT/Claude og skipta út hlutanum „[SETTU HUGMYND ÞÍNA HÉR]" fyrir eigin frumkeim sögunnar.

Af hverju svona en ekki með afritun úr leiðbeiningunum? Glugginn í GUI hefur lykilforskot hvað aðgengi varðar: hann er innbyggður og lesinn án truflana af skjálesara, krefst ekki þess að skipta yfir í textaritil (þar sem pólskir „ogonki"-stafir og gæsalappir geta afritast rangt) og virkar eins á öllum stýrikerfum. Sama mynstur — gluggi með kvaðningu til afritunar — er einnig notað í Reglustjóranum (sjá SKREF 7b hér að neðan).

Hvernig gervigreind svarar: Í svarinu færðu texta í tveimur hlutum. Fyrsti hlutinn er Heimsbókin lokuð í Markdown-kóðablokk (merki markdown …). Afritaðu EINGÖNGU innihald kóðablokkanna (án sjálfra merkjanna ```) og límdu í reitinn „Heimsbókin" í Leikstjóranum, og smelltu síðan á „💾 Vista Heimsbók varanlega". Annar hlutinn er ráðlegging um hvaða skapandi ham (Skript eða Hljóðbók) hentar hugmynd þinni best — líttu á hana sem vísbendingu þegar þú velur ham í hamsvalsreitnum.

Markdown-smánámskeið í Bókinni: eitt myllumerki (#) er aðalhluti (t.d. „# Persónur"), tvöfalt myllumerki (##) er undirhluti, bandstrik (-) búa til lista, og tvöföldar stjörnur (texti) feitletra algerar, óbrigðular reglur (t.d. „Hetjan LYGAR ALDREI"). Fyrir erlendmælandi persónu skaltu bæta við merki með hreim, t.d. „[Speaker 1: Marek] - hefur franskan hreim". Lykilorðið „akcent" er NAUÐSYNLEGT — vélin í forritinu greinir það sjálfkrafa og beitir réttum hljóðfræðireglum á samræður viðkomandi persónu.

Ráðlegging: Mundu að uppfæra Heimsbókina þína reglulega (þegar söguþráðurinn þróast með nýjum stöðum eða mikilvægum persónum). Þetta er hægt að gera handvirkt eða með hjálp ytri spjallbots. Því ríkulegri sem grunnurinn er, þeim mun betri verða niðurstöðurnar í Leikstjóranum!

SKREF 7b: Reglustjóri (Ctrl+4) — orðabækur fyrir málfræðinga án Python

Útgáfa 13.0 kynnir fjórða tólið á stikunni: Reglustjóra. Þú opnar það með Ctrl+4 eða úr Verkfæravalmyndinni. Þetta er sjónrænn skoðari fyrir möppuna dictionaries/, þar sem forritið geymir allar hljóðreglur (hreim), dulmál og hami Leikstjóra í YAML skrám (mannlesanlegt snið, einfaldara en JSON).

Af hverju YAML? Fram að útgáfu 12.0 voru allir hreimar, skapandi hamir og síur „innbyggðar" í Python kóðann. Að bæta við nýjum hreim þurfti forritara. Í útgáfu 13.0 var þetta allt flutt í .yaml skrár í möppunni dictionaries/ — hver sem er sem getur opnað Notepad getur stillt núverandi hreim („skipta sz fyrir sh fyrir sch") eða bætt við alveg nýjum (sænskur, danskur, rússneskur mállýska).

Hvað finnur þú í Stjórnanda Reglna:
- Skjalamappa — fullur listi yfir allar YAML skrár í dictionaries/ með skiptingu eftir grunnmálum (nú fullkomlega útfærð: Polski, Deutsch, English, Español, Suomi, Français, Íslenska, Italiano, Русский) og flokkum (akcenty/, szyfry/, rezyser/, opowiesci/, gui/). Leiðsögn með örvum eins og í Windows File Explorer, fullur NVDA-stuðningur.
- Hnappur „📝 Opna í textaritli" — opnar valda skrá í sjálfgefnum Notepad kerfisins. Þú breytir, vistar, smellir á „🔄 Endurnýja tré" og búið.
- Hnappur „📋 Afrita valda skrá" — fljótlegasta leiðin til nýs hreims: þú tekur núverandi skrá (t.d. finski.yaml), gefur nýtt nafn (t.d. sænska), Stjórnandi býr til afrit með athugasemd „breyta reitnum merki og lýsing" og opnar hana í ritli.
- Hnappur „➕ Ný regla skrá…" — skapalón með vali á tegund (hreim, dulmál, ham Leikstjóra, nýtt grunnmál, reiknirit dulmál). Fyrir venjuleg tilfelli (hreim, dulmál eins og „skipta um stafi") býr skapalónið til tilbúið YAML sniðmát til að breyta. Fyrir tilfelli sem krefjast forritara (nýtt grunnmál, reiknirit eins og „blanda miðju orða") býr skapalónið til skeyti fyrir AI spjallmenni — þú límir það í ChatGPT, færð tilbúna YAML skrá, vistar í dictionaries/ og búið.

Hagnýt notkun: Viltu bæta við sænskum hreim? Opnaðu Stjórnanda Reglna, veldu dictionaries/pl/akcenty/finski.yaml, smelltu á „Afrita", nefndu skrána sænska, breyttu reitnum merki í "Sænska (Alva / Oskar)", iso kóða í sv, breyttu nokkrum reglum um skipti og vistaðu. Farðu aftur á Heimaskjáinn og ræstu forritið aftur. Nýi hreimurinn birtist í valmynd Tungumálamanns (í Leikstjórnarham) og — ef þú bætir honum við Persónuheimsbókina („[Marek] - hefur sænskan hreim") — einnig í sjálfvirkri hreimsgreiningu Leikstjórans.

Hvar á að leita að frekari skjölum um möppuna dictionaries/:
- Skjal docs/dictionaries.pl.html (aðgengilegt í pakkanum fyrir endanotendur frá Releases flipanum) — stutt, einföld lýsing á hverri undirmöppu, 6 tilbúin dulmál, 8 tilbúnir hreimar og hugmyndir um hvað hægt er að gera sjálfstætt, án Python þekkingar.
- Skjal dictionaries/README.md (aðeins aðgengilegt við klónun úr GitHub geymslu — útgáfupakkar sía .md skrár) — ítarleg tæknileg skjölun á YAML sniðinu með dæmum, lista yfir reiti, reglur um leiðslur, regex. Þetta skjal er ætlað málvísindamönnum sem þekkja grunnatriði forritunar og þróunaraðilum.

Mikilvæg atriði fyrir notendur skjálesara (NVDA)

1. Tilkynningar um árangur og villur

Þegar forritið lýkur aðgerð (t.d. vista skrá eða lendir í villu), birtist valmyndargluggi með titli eins og "Árangur", "Viðvörun" eða "Villa". NVDA mun strax tilkynna þennan glugga og lesa innihald hans. Þú þarft ekki að gera neitt — valmyndirnar eru fullkomlega aðgengilegar með lyklaborðinu og fókus lendir sjálfkrafa á "OK" hnappinum. Það eru engar brellur með forskeytið "Viðvörun" — innbyggðir valmyndargluggar wxPython eru studdir beint af lesaranum.

2. Mikilvæg viðvörun: hljóðlaus bakgrunnsvinnsla

Eftir að smellt er á hnappa eins og "Senda til AI" eða "Keyra vinnslu", byrjar forritið strax að vinna í bakgrunni. Framvindustika (Gauge) birtist á skjánum, en NVDA LES ekki gildi hennar í rauntíma — skjálesarinn er hljóður á meðan unnið er. Ekki smella á hnappinn aftur. Bíddu þar til valmyndargluggi með niðurstöðu eða villuskilaboðum birtist — NVDA mun tilkynna það sjálfkrafa.

3. Leiðsögn milli verkfæra

Færsla milli verkfæra (Leikstjóri, Tungumálamaður, Umbreyting, Reglustjóri) fer fram í einum forritsglugga með fjórum hnöppum á verkfæraslánni eða í gegnum Verkfæri valmyndina (Alt, síðan N). Aðgengilegir lyklaborðsskammtar: Ctrl+0 (Heimasíða), Ctrl+1 (Leikstjóri), Ctrl+2 (Tungumálamaður), Ctrl+3 (Umbreyting), Ctrl+4 (Reglustjóri — nýjung í 13.0). Eftir að verkfæri er skipt, lendir fókus sjálfkrafa á lýsingu nýja einingarsins — NVDA byrjar strax að lesa nýja útsýnið.

4. Röð flipa og nöfn búnaðar

Hvert viðmótselement hefur skýrt íslenskt nafn — NVDA mun lesa það þegar það er í fókus. Röð flipa er rökrétt: frá lýsingu verkfæris, í gegnum stillingarsvæði, til aðgerðahnappa. Það eru engin óvænt atriði — lyklaborðsleiðsögn virkar eins og í hverju öðru innfæddu Windows forriti. Allar valmyndir og allir hnappar eru á íslensku og NVDA mun lesa þau með íslenskum hreim án nokkurra viðbótarstillinga.

Mikilvæg atriði fyrir útgáfu 9.0 / Breytingaskrá

Nýir eiginleikar og breytingar í útgáfu 9

Bilunarþolið skráning á framvindu þýðingar (BREYTING — viðgerð á alvarlegum galla)
Í útgáfu 8 var endurupptaka rofinna þýðinga með hljóðlausri, eyðileggjandi gildru: ef notandi fylgdi leiðbeiningum (handvirkt klipping á þýddum hluta) og hélt síðan áfram með þýðingu á restinni, opnaði forritið útgangsskrána í yfirskriftarham — eyðandi óafturkræft og óafvitandi alla greidda framvindu. Í útgáfu 9 hefur allt kerfið verið endurhannað. Hver þýdd blokk er nú þegar skráð í tímabundna skrá (.jsonl) með úthlutaðri vísitölu. Endurupptaka er fullkomlega sjálfvirk — forritið greinir sjálfkrafa skrána og endurheimtir framvindu án nokkurrar íhlutunar notanda. Eftir vel heppnaða lokun er tímabundna skráin sjálfkrafa fjarlægð.

Tagaviðgerð í Leikstjórnarhami (NÝTT)
Nýjum valkosti hefur verið bætt við Leikstjórnarhami — Tagaviðgerð. Það sprautar aðeins inn tveggja stafa ISO tungumálakóða sem notandi gefur upp, án þess að nota neinar hljóðreglur eða hreinsun. Neyðartæki ef tilbúin skrá kemur út með röngu tungumálamerki eða tungumálamerki sem vantar.

Sjálfvirk umbreyting .txt í .html í Þýðingaham (BREYTING)
Textaskrár (.txt og .md) sem þýddar eru af AI þýðanda eru nú sjálfkrafa vistaðar á .html formi með innbyggðu tungumálamerki. Þannig les NVDA strax skrána með réttri rödd — án nokkurra viðbótar skrefa af hálfu notanda.

Snjöll skráarheiti í Arkitektinum (BREYTING)
Arkitekt hljóðbóka vistar ekki lengur niðurstöðuskrána alltaf undir sama nafni arkitektura_gotowa.docx. Nú kemur nafnið frá inntaksskránni — til dæmis fyrir znieczulica.txt verður niðurstöðuskráin arkitektura_znieczulica.docx. Skráin birtist í sömu möppu og upprunalega skráin.

Eiginleikar haldnir óbreyttir frá útgáfu 8

Afturhvarf til .txt-sniðs fyrir verkefnaskrár (BREYTING)
Verkefnaskrár og samantektir eru nú vistaðar á .txt formi í stað .md (Markdown). Tilraun með .md form sem sálfræðileg hindrun gegn breytingum reyndist árangurslaus — AI brýtur oft regluna um anti-closure og oft er betra að breyta skrá á staðnum og síðan endurhlaða minni, svo AI, eftir því sem mögulegt er, fái ekki leynilegt leyfi til að brjóta bannið. .txt formið er meira innsæi og læsilegt fyrir alla.

Regla Klipparans — ný viðvörun
Í leiðbeiningunum (og í framtíðarútgáfum viðmótsins) hefur verið bætt við skýrri viðvörun sem útskýrir hvað má og hvað má ekki breyta í verkefnaskrám. SKREF 7b (viðbót): Röð reglna zamiany: skiptir máli

Skrár í dictionaries/<kod>/akcenty/*.yaml innihalda lista af reglum zamiany: — pör wzor → zamiana, sem vélin framkvæmir Í RÖÐ. Hver næsta regla vinnur á útkomu fyrri. Þetta gerir kleift að byggja pípulagnir eins og „brjóta tvíhljóðið szcz í shch, og svo breyta ch í h", en opnar einnig klassíska gildru fyrir höfund tungumálapakkans.

Gildra „röðunarhrings". Gerum ráð fyrir að fyrir spænska hreiminn sem á að líkja pólsku „ñ" við framburð Diego (Loquendo), bætir höfundur við tveimur reglum:
1. ñ → nj (til að pólsku „ñ" hljómi eins og mjúkt „nj")
2. j → x (til að pólsku „j" hljómi eins og spænska „j" — hljóðfræðilega /x/)

Eftir keyrslu kemur í ljós að orð með „ñ" eru borin fram sem „nx", ekki „nj". Af hverju? Vegna þess að þegar fyrsta reglan breytir „ñ" í „nj", er nýja „j" strax gripið af annarri reglunni og breytt í „x". Niðurstaða: í stað fyrirhugaðs „ñ → nj", fáum við „ñ → nx".

Regla um röðun (alhliða). Þegar ein regla kynnir tákn sem önnur regla hefur sem mynstur, SKIPTIR RÖÐIN MÁLI. Öruggur leiðarvísir: FYRST breyta TARGET (táknið sem er notað síðar sem wzor í annarri reglu) í eitthvað öruggt, SÍÐAN kynna SOURCE (táknið sem á að brotna í TARGET). Fyrir spænska dæmið rétt: fyrst j → x, síðan ñ → nj. Niðurstaða: „ñ" gefur „nj" (seinni „j" verður ekki étin, því reglan j → x var notuð áður, þegar „nj" var ekki enn til).

Hvernig á að prófa. Eftir að hafa breytt röð reglna í hreimskránni, keyrðu setningu sem inniheldur BÆÐI stafi í gegnum Stjórnunarhaminn. Fyrir ES dæmi: „Niño de paja juega" → niðurstaðan verður að hafa bæði ñ hreim („ñ → nj") og j hreim („j → x"), sem er eitthvað á borð við „Ninjo de paxa xuega". Ef þú sérð „ninxo" í stað „ninjo" — er röðin röng.

Staðfesting í vélinni (opt-in fyrir höfunda pakka). Forritið hefur innbyggða heuristík til að greina mögulegar lykkjur, en hún er sjálfgefið óvirk — því margar pípulagnir líta út eins og lykkja, þó þær séu viljandi (klassískt „szcz → shch" + „ch → h"). Til að virkja hana: stilltu umhverfisbreytuna REZYSER_VALIDATE_ZAMIANY=1 og keyrðu forritið úr skel — úr kóðanum með python main.py, því frosið .exe í gluggaham (frá útgáfu 17.0) hefur ekki skelglugga. Vélin mun prenta eina samantektarlínu WARN fyrir hverja hreimskrá með fyrstu þremur mögulegum lykkjum og fjölda hinna. Athugaðu niðurstöðuna á prófunarsetningu — ef áhrifin eru fyrirhuguð, hunsaðu WARN.

Hnappar til að færa reglur í Reglustjórnunarviðmótinu (drag-and-drop, „Upp / Niður") eru sérstök aðgerð sem er áætluð fyrir seinni útgáfutíma — krefst endurhönnunar á Stjórnandanum (núna sendir hann skráarbreytingar til utanaðkomandi Kerfisritils, en hefur ekki eigin reglusýn). Þar til hún er innleidd: breyttu YAML skránni handvirkt, færðu línur í zamiany: kaflanum, notaðu staðfestingarbreytuna ENV-var og prófaðu á prófunarsetningum.

SKREF 7b — Pólsk heiti á möppum og skrám (fyrir notendur utan Póllands)

SKREF 2B (ítarlegt, valfrjálst): Eigin AI-þjónustuaðili samhæfur OpenAI

Flestir notendur ættu að halda sig við ráðlagðan Anthropic (SKREF 2) — hann gefur hæstu gæðin. Ef þú hefur þó eigin ástæðu (kostnaður, aðgangur, friðhelgi, eigið staðbundið líkan), getur þú frá útgáfu 18.4 bent á HVAÐA endpoint sem er samhæfan OpenAI API — til dæmis OpenRouter, Groq, Fireworks, DeepSeek, staðbundið Ollama eða OpenAI-compatible Gemini endpoint. Öll AI-vélin fer þá eina leið að þessum endpoint, án sérstakrar samþættingar per þjónustuaðila.

Þetta er valkostur fyrir lengra komna: þú stillir hann handvirkt í skránni golden_key.env, með því að bæta við (eða í stað) Anthropic-lykils þremur línum og lykli valins þjónustuaðila:

LLM_PROVIDER=openai_compat
LLM_BASE_URL=heimilisfang_endpoint (t.d. https://openrouter.ai/api/v1)
LLM_MODEL=nafn_líkans_hjá_þjónustuaðila (t.d. openai/gpt-4o-mini)
OPENAI_API_KEY=þinn_lykill_hjá_þessum_þjónustuaðila

Hvernig þetta virkar:
• Þegar LLM_PROVIDER=openai_compat, notar ÖLL AI-vélin (Leikstjóri, Sögur, Tungumálamaður, titlar, tungumálagreining) tilgreindan endpoint, og LLM_MODEL skrifar yfir líkansnafnið úr stillingarskrám.
• Þegar línan LLM_PROVIDER vantar (eða hefur gildið anthropic), virkar forritið eins og í SKREF 2 — eingöngu með Anthropic-lykli. Þú þarft ekki að breyta neinu.
