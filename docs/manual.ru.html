Reżyser Audio GPT — Полное руководство (Версия 18.18.0 – Релизная версия)

Добро пожаловать в Гибридную Студию Записи! Этот набор инструментов позволяет автоматически писать, планировать, форматировать и переводить сценарии радиопостановок и аудиокниг. Он оптимизирован для работы с профессиональными синтезаторами речи и локальными движками экранных чтецов (NVDA).

Набор состоит из главной студии (Режиссура), инструмента для переводов и акцентов (Полиглот), инструмента для построения структуры файла (Архитектор Аудиокниг), Менеджера Правил (с версии 13.0 — без Python можно добавить новый акцент, шифр или творческий режим, см. ШАГ 7b ниже) и — с версии 15.0 — модуля Историй (интерактивная второличная фикция, генерируемая AI, читаемая TTS или экранным чтецом, описанная в отдельном руководстве tales.ru.html). Все пять инструментов доступны в одном окне программы, переключаемом кнопками на панели или клавишами Ctrl+1..Ctrl+5.

ШАГ 1: Первое запуск (Кроссплатформенность)

Скачайте последнюю версию установщика с вкладки Releases на GitHub (файл Rezyser_Audio_v<numer>_Installer.exe) и запустите его двойным щелчком. Установщик предложит стандартное место установки — папку Programs в локальном каталоге вашей учетной записи — и не требует прав администратора. Вы можете выбрать и собственный путь кнопкой «Обзор» — установщик его запомнит и при последующих обновлениях воспользуется им сам, не спрашивая. После установки запустите программу с помощью значка на рабочем столе или из меню Пуск. Через некоторое время появится главное окно программы — Режиссер Audio GPT. Начиная с версии 17.0 приложение заморожено как собственный исполняемый файл в оконном режиме, поэтому больше не мигает окно терминала, и оно запускается быстрее, чем раньше. Никакого браузера, никакого сервера в фоновом режиме. Когда закончите работу, просто закройте окно программы.

Все приложение, включая движок Python, проекты и ключ API, находится в одной папке по пути установки — всю папку можно перенести на флешку, в облако или на другой компьютер (подробная инструкция в разделе «Перенос проектов и ключа API» ниже).

Важно: Папка runtime/ внутри папки установки — это бандл PyInstaller (с версии 17.0) — содержит изолированный интерпретатор Python и библиотеки, готовые к использованию без отдельной системной установки; также служит контейнером для скрытых метаданных проектов. Если вы клонируете репозиторий (путь разработчика), этой папки нет и не должно быть — вы используете виртуальную среду venv, описанную в разделе для разработчиков ниже.

Для разработчиков (Windows — репозиторий Git)

  1. Клонируйте репозиторий на свой диск.
  2. Запустите файл setup_dev.bat. Скрипт автоматически создаст виртуальную среду Python (venv) и установит все необходимые зависимости из файла requirements.txt.
  3. Запустите приложение командой python main.py или через файл run_dev.bat — скрипт автоматически обнаружит папку venv и запустит программу.

Для разработчиков и обычных пользователей (macOS / Linux)

  1. Клонируйте репозиторий на свой диск.
  2. Откройте терминал в папке проекта и дайте скриптам права на выполнение: chmod +x *.sh
  3. Запустите конфигурационный скрипт: ./setup_dev.sh — скрипт создаст среду venv и установит зависимости.
  4. Запустите приложение: python main.py или ./run.sh

Что вы увидите после запуска: После запуска программы открывается окно с начальным экраном. На нем вы найдете краткое описание доступных инструментов и раздел "System Check". Если ключ API еще не настроен, вы увидите красное сообщение, информирующее о том, что модули на основе ИИ (Режиссура, Переводчик) не будут работать — бесплатные локальные функции (акценты, Архитектор) активны сразу. Настройка ключа описана в следующем шаге.

Автоматические обновления

Приложение проверяет при запуске, доступна ли на GitHub новая версия — проверка происходит в фоновом режиме и не блокирует интерфейс.

Если вы устанавливали программу через готовый файл установщика (.exe): при обнаружении новой версии появится окно с вопросом, скачать ли ее. После подтверждения запустится индикатор прогресса, а когда загрузка завершится, приложение автоматически закроется, и новый установщик запустится самостоятельно. О пути установки при этом можно не беспокоиться: установщик распознаёт прежнюю установку и ставит программу в ту же папку, что и раньше, — мастер тогда вообще не показывает страницу выбора целевой папки (это касается и расположения, выбранного когда-то вручную кнопкой «Обзор»). Обновление перезаписывает файлы движка приложения и весь пакет правил (папка dictionaries/) — ваши проекты (папки skrypty/, opowiesci/) и ключ API (golden_key.env) останутся нетронутыми. ВАЖНО: если вы редактировали через Менеджер Правил файлы, существующие в пакете (например, изменения акцента в dictionaries/pl/akcenty/wloski.yaml), эти изменения БУДУТ ПЕРЕЗАПИСАНЫ при обновлении — перед подтверждением обновления сделайте резервную копию папки dictionaries/ по процедуре из раздела «Перенос проектов и ключа API» ниже (достаточно скопировать саму папку dictionaries/ на флешку), а после обновления загрузите ее обратно, перезаписывая более новые файлы. Совершенно новые правила, которые вы создали с нуля и которых нет в пакете (например, собственный дополнительный базовый язык или собственный шифр), остаются нетронутыми автоматически — установщик не удаляет файлы, не входящие в пакет. Начиная с версии 15.2.8 сам диалог, предлагающий обновление, отображает это предупреждение непосредственно в содержании и содержит кнопку «Открыть папку dictionaries», которая одним щелчком открывает Проводник в нужном месте — достаточно нажать на нее перед подтверждением обновления, чтобы удобно сделать резервную копию, а затем вернуться к диалогу и нажать «Скачать и установить».

Путь установки пригодится, напротив, при ручном копировании файлов (резервная копия, перенос на другой компьютер — см. раздел ниже). Если вы его не помните, есть два быстрых способа его восстановления. Windows 11: в контекстном меню ярлыка на рабочем столе выберите «Открыть расположение файла» (если опция не видна в новом упрощенном контекстном меню, выберите сначала «Показать больше опций» или нажмите Shift+F10 дважды, чтобы сразу открыть полное меню), перейдите на уровень выше клавишей Backspace, выделите папку с приложением и нажмите Ctrl+Shift+C (или выберите «Копировать как путь» из контекстного меню) — полный путь попадет в буфер обмена в кавычках (вставляя в установщик, не забудьте удалить сами кавычки). Старые версии Windows (7/8/10): щелкните правой кнопкой мыши на ярлыке и выберите «Свойства»; на вкладке «Ярлык» в поле «Объект» вы увидите полный путь к исполняемому файлу (.exe в версии 15.2.5+ или run.bat в более старых версиях) — скопируйте его и удалите конечное имя файла, останется только путь к папке установки.

Примечание при обновлении со старых версий (v15.2.4 или более старой, когда приложение запускалось через run.bat из Portable ZIP): существующий ярлык на рабочем столе может указывать на run.bat в старом расположении, которого после обновления до v15.2.5+ больше нет — версии 15.2.5+ используют самостоятельный файл .exe, созданный установщиком. Если после обновления ярлык перестает работать, удалите его вручную и позвольте установщику создать новый при повторной установке.

Если вы используете репозиторий Git (разработчики и пользователи macOS/Linux): вместо предложения загрузки вы увидите информацию о новой версии с прямой ссылкой на страницу выпуска на GitHub. Скачайте оттуда архив «Source code» или обновите репозиторий командой git pull.

Перенос проектов и ключа API (миграция)

Если вы хотите перенести свои проекты, ключ API и локальные настройки на другой компьютер (или восстановить все после переустановки Windows), нет необходимости вручную копировать отдельные файлы — вся папка приложения самодостаточна.

  1. Убедитесь, что приложение ПОЛНОСТЬЮ закрыто. Если вы видите значок программы в системном трее (рядом с часами, справа на панели задач), щелкните по нему правой кнопкой мыши и выберите «Закрыть». Открытые файлы блокируют копирование.
  2. Найдите ярлык Режиссер Audio GPT на рабочем столе. Щелкните по нему правой кнопкой мыши (или клавишей Приложения или Shift+F10 при навигации NVDA) и выберите опцию «Открыть расположение файла». ВНИМАНИЕ на Windows 11: в новом, упрощенном контекстном меню эта опция может быть скрыта — выберите сначала «Показать больше опций» (или нажмите Shift+F10 дважды, чтобы сразу открыть полное меню с опцией).
  3. Откроется окно Проводника Windows в папке установки программы. Нажмите клавишу Backspace (самый простой способ, работает всегда) или щелкните стрелку «Вверх» на панели инструментов, чтобы перейти на один уровень выше — там вы увидите полную папку с приложением. Примечание: сочетание клавиш Alt+Стрелка вверх работает только когда фокус находится на списке файлов — если Проводник открылся с фокусом на адресной строке (типично), Alt+Стрелка вверх ничего не сделает, используйте тогда Backspace.
  4. Скопируйте всю эту папку на флешку, облачное хранилище (OneDrive, Google Drive, Dropbox) или внешний диск. Папка содержит все, что нужно для восстановления состояния работы:
    - Ваши проекты (папка skrypty/ — файлы .txt повествования, .md Книга Мира и файлы результатов инструментов постобработки: память, заголовки, карточка публикации; папка opowiesci/ — интерактивные игры).
    - Ключ API (файл golden_key.env в главной папке приложения).
    - Собственные фонетические правила, акценты, шифры, если вы что-то редактировали в Менеджере Правил (папка dictionaries/<kod>/, например, dictionaries/pl/akcenty/wloski.yaml).
    - Настройки приложения и выбор творческих режимов (папка runtime/skrypty/, файлы .mode).
    - Изолированная среда Python (папка runtime/), благодаря чему вам не нужно ничего доустанавливать на новом компьютере.
  5. На новом компьютере: скачайте последнюю версию установщика с вкладки Releases на GitHub и установите приложение стандартно. Запустите программу один раз, чтобы она создала пустую структуру конфигурационных файлов. Закройте приложение. Затем скопируйте ранее сохраненную папку в место установки, перезаписывая файлы — или выберите выборочно только интересующие вас папки (skrypty/, opowiesci/, golden_key.env) и вставьте их в соответствующие места новой установки.

Подсказка для пользователей NVDA: контекстное меню «Открыть расположение файла», вызываемое клавишей Приложения, полностью доступно — NVDA читает каждую позицию на русском. После открытия Проводника в целевой папке используйте клавишу Backspace, чтобы перейти на уровень выше (работает всегда, независимо от того, находится ли фокус на списке файлов или на адресной строке), а затем Ctrl+A, чтобы выделить все, и Ctrl+C, чтобы скопировать.

Подсказка: опция «Открыть расположение файла» — это нативное название для русской версии Windows. В английской системе она звучит как «Open file location», в остальных языковых версиях — аналогично на местном языке операционной системы.

ШАГ 2: Подключение API (рекомендуемый ключ Anthropic / Claude)

Рекомендуемым и используемым по умолчанию поставщиком AI является Anthropic (Claude) — все промпты приложения настроены именно под него, поэтому он обеспечивает наивысшее качество нарратива и наилучшее соблюдение правил мира. В этом (рекомендуемом) варианте достаточно ОДНОГО ключа API в файле golden_key.env:

• Ключ Anthropic (Claude) — питает ВЕСЬ движок AI: нарратив Режиссера (аудиокнига, читаемый театр, мозговой штурм), режим Историй, Полиглота (переводчик), а также присвоение названий главам и определение языка контента. Начинается с sk-ant-.

Если вы обновляетесь с более старой версии: прежний ключ OpenAI больше не нужен для варианта по умолчанию — вы можете оставить или удалить его строку в golden_key.env, приложение ее игнорирует (если только вы намеренно не настраиваете другого поставщика — см. ШАГ 2B ниже).

Как получить ключ Anthropic:
1. Создайте аккаунт на console.anthropic.com и пополните баланс (вкладка Billing / Plans).
2. Сгенерируйте ключ в разделе API Keys (начинается с sk-ant-). Скопируйте его сразу — он может быть показан только один раз.

Как ввести ключ в программу:
3. На стартовом экране программы нажмите кнопку "Сгенерировать файл golden_key.env и открыть текстовый редактор". Система автоматически создаст чистый файл конфигурации в нужном месте и откроет Блокнот с шаблоном, готовым к редактированию.
4. В открытом файле вы увидите строку: ANTHROPIC_API_KEY=PASTE_YOUR_KEY_HERE. Удалите замещающий текст и вставьте свой ключ непосредственно после знака равенства (без пробелов и без кавычек). Сохраните файл и перезапустите приложение.

Подсказка: После повторного запуска приложение проверит файл и в разделе "System Check" отобразит статус ключа. Он должен быть зеленым, чтобы все модули AI были готовы к работе. Если ключ отсутствует или введен неверно, программа четко на это укажет и позволит открыть текстовый редактор для быстрого исправления ошибки.

Важно: Формат файлов проектов — возврат к .txt

В версии 7 файлы проектов сохранялись в формате Markdown (.md), например skrypty/znieczulica.md. Это был намеренный эксперимент — формат .md должен был служить психологическим барьером для нетехнических пользователей, отпугивая их от открытия и ручного редактирования файла в Блокноте (и тем самым от случайного повреждения заголовков структуры).

Эксперимент не оправдал себя. ИИ нередко грубо нарушает один из фундаментальных запретов (подробнее об этом чуть ниже). По этой причине в версии 8 был осуществлен возврат к простым файлам .txt — более интуитивным и понятным для всех. Например, проект с названием "znieczulica" теперь сохранится как skrypty/znieczulica.txt, а его краткое содержание — как skrypty/znieczulica_streszczenie.txt. Это позволит каждому легче вносить режиссерские правки или сокращения текста по ходу работы.

⚠️ Критическое правило монтажера (прочитайте перед началом работы!)

Все ваши сгенерированные сценарии и книги сохраняются в обычных текстовых файлах (.txt), которые легко открыть в Блокноте.

Как Режиссер вы имеете ПОЛНОЕ ПРАВО (и даже обязанность) редактировать этот файл! Если искусственный интеллект увлечется и, например, самостоятельно разрешит проблему героев в конце сгенерированного фрагмента, откройте файл, удалите последние строки и оставьте текст оборванным в самый напряженный момент, затем нажмите "Перезагрузить проект с диска", чтобы синхронизировать память модели с исправленным файлом, и "Отправить в AI" для продолжения.

🔴 Однако — чего нельзя трогать

Никогда не изменяйте, не удаляйте и не переписывайте строки, содержащие структуру (например, Акт 1, Сцена 2, Глава 1, Пролог). Если вы испортите эти заголовки:
1. Ваша история рассыплется в экранных читалках (NVDA).
2. Архитектор аудиокниги, а следовательно и ElevenLabs Studio не смогут корректно разбить вашу книгу на фрагменты для чтения.
3. Внутренний конвертер приложения не сформирует правильное оглавление в файле Word и не создаст временну́ю шкалу в ElevenLabs.

Редактируйте диалоги, сокращайте действие, но не трогайте структуру!

Как пользоваться Режиссерской Студией?

  • Книга Мира (боковая панель слева): Здесь вы записываете правила вселенной. Каждый проект теперь имеет собственную Книгу, связанную с именем файла — если ваш файл истории называется, например, emilia_heist_audiobook.txt, Книга Мира сохранится как skrypty/emilia_heist_audiobook.md. Поэтому порядок важен: сначала введите имя файла проекта в поле «Имя файла проекта», и только после этого можно сохранить Книгу. Кнопка "💾 Сохранить Книгу навсегда" остается неактивной, пока вы не укажете имя. При загрузке существующего проекта кнопкой "Загрузить историю" соответствующий файл .md загрузится автоматически — вам не нужно делать ничего вручную. Внимание: без заполненной Книги Мира приложение заблокирует отправку запросов к ИИ — это намеренная защита, которая уберегает вас от генерации текста без каких-либо правил.
  • Долговременная Память (боковая панель слева): Второе поле на боковой панели. Сюда попадает краткое содержание сюжета — созданное инструментом на панели постобработки (ШАГ 4) или, при тревожном уровне памяти, автоматически. Вы также можете вводить здесь собственные заметки вручную — модель воспримет их как "то, что я уже знаю" перед прочтением текущей сцены. ИСТОРИЧЕСКАЯ ОШИБКА (исправлена в v15.5): раньше, если вы вводили здесь очень короткую заметку и нажимали «Сохранить Резюме» до того, как в файле нарратива было что-то значимое, при следующей загрузке приложение ПРИОРИТЕТНО загружало краткое содержание и ПРОПУСКАЛО полную историю — модель получала тогда только Книгу Мира и однострочную заметку, без контекста тона и последних сцен. Начиная с v15.5 загрузка стала интеллектуальной: если вся история умещается в окне контекста, она загружается целиком (а ненужное старое краткое содержание удаляется), поэтому модель не теряет контекст. А после ручного редактирования файла нарратива в редакторе используйте новую кнопку «Перезагрузить проект с диска» (начиная с v15.5), которая одним нажатием синхронизирует внутреннюю память с диском; для простого открытия файла в редакторе по-прежнему служит «Открыть файл повествования…».
  • Режим Мозгового Штурма: Введите свободную идею, и ИИ предложит вам 3 варианта развития сюжета. Для каждого варианта сразу же сгенерирует готовый блок "--- ЧЕРНОВИК ПРОМПТА ---". Выбрав один из них, вставьте этот промпт в Режим Сценария или Аудиокниги и добавьте при необходимости комментарии или информацию для модели. Память сюжета не изменяется во время Мозгового Штурма — вы можете экспериментировать без риска!
  • Режим Чернового Сценария (начиная с v16.0 — читаемый театр): Сюда вставляется "ЧЕРНОВИК ПРОМПТА", сгенерированный в Мозговом Штурме. ИИ напишет длинный нарративно-диалоговый фрагмент: нарратив (обстановка, время, действие) в тегах [Narrator: ...] и реплики персонажей в тегах [Имя: эмоция]. Без звуковых эффектов — контекст передается нарратором словами. Текст автоматически дописывается в ваш файл (например, nowa_scena.txt) в папке skrypty/. Готовый сценарий можно затем превратить в многоголосую аудиокнигу (мост к ElevenLabs Studio — отдельная глава ниже).
  • Режим Традиционной Аудиокниги: Режим для писателей. ИИ генерирует чистую художественную прозу — никаких тегов, никакой фонетики, классические диалоги, вплетенные в нарратив. Текст дописывается в файл так же, как в Режиме Сценария.
  • Автоматическое создание персонажей: Сценарий запрограммирован так, чтобы автоматически создавать новые теги [Speaker], если сюжет требует нового персонажа. Подсказка: если ИИ создаст интересного персонажа, скопируйте его тег и вставьте в Книгу Мира, чтобы модель запомнила его навсегда!

Управление проектом — три кнопки действий:
- Загрузить историю: Загружает существующий проект в память. Доступна, когда текущая память пуста. Начиная с версии 15.2.3 поддерживает два пути: если поле имени проекта пусто, открывается диалог выбора со списком всех проектов, найденных в папке skrypty/ (файлы кратких содержаний пропускаются) — NVDA читает список естественно, пользователю не нужно помнить и вводить имя с клавиатуры. Если поле имени заполнено, приложение сразу пытается загрузить проект с этим именем (путь эксперта: Enter в поле имени или клик после ввода по памяти).
- Закрыть Проект (Жесткий Сброс): Полностью очищает проект. Удаляет историю, краткое содержание, Книгу Мира и обнуляет все счетчики. Используйте при смене проекта или начале новой истории.
- Открыть файл повествования… (начиная с v15.2.3): Аварийное редактирование файла нарратива в системном текстовом редакторе. Требует указанного имени проекта. Приложение открывает skrypty/<nazwa>.txt в Блокноте (Windows), TextEdit (macOS) или стандартном GUI-редакторе (Linux). Типичные сценарии: (a) ИИ не завершает сцену, и вы хотите дописать концовку вручную; (b) вы загрузили проект с кратким содержанием и хотите скопировать последние сцены в Долговременную Память, чтобы модель имела полный контекст тона (архитектурная ошибка, описанная выше); (c) вы хотите сделать сокращение текста в середине главы, которое движок приложения не поддерживает нативно.

  • Перезагрузить проект с диска (начиная с v15.5, переработан в v17.6): Перезагружает ВЕСЬ проект с диска после ручного редактирования файла нарратива — это полноценная перезагрузка, а не просто обновление текущей памяти. Пересчитывает счетчики Глав/Актов/Сцен, подгружает Книгу Мира, режим и параметры Мозгового Штурма, синхронизирует рабочую память. Если вся история умещается в окне контекста, загружает ее целиком (и удаляет ненужное старое краткое содержание, чтобы движок работал на полном тексте). Если история длинная и для нее сохранено краткое содержание, оставляет его нетронутым и спрашивает, с какого заголовка должна стартовать рабочая память ИИ: в режиме Аудиокниги вы выбираете Главу, в режиме Сценария — сначала Акт, затем Сцену этого акта (или весь Акт) — остальное представлено кратким содержанием. Отмена выбора = аварийная обрезка до последнего фрагмента текста (поэтому важно поддерживать структуру заголовков). Перед тем как перезаписать поля версией с диска, предупреждает, если в них есть несохраненное содержимое. Типичный сценарий: ИИ ошибочно закрыло сцену (нарушило anti-closure), вы обрезаете неудачную концовку в редакторе и нажимаете «Перезагрузить» — больше не нужно исправлять в двух местах.

Историческая заметка — почему режимы теперь защищены от случайной смены:
В ранних версиях приложения никто не следил за согласованностью творческого режима в рамках одного проекта. Следствием была одна тонкая творческая возможность, которую можно описать так: вы начинаете историю в Режиме Сценария, вставляете «Акт 1» и «Сцена 1» (приложение в восторге от вашей последовательности), генерируете несколько экранов напряжения с тегами [SFX: Хлопок двери] и [Speaker 1: Марек - подавленный]... а затем — потому что именно в этот момент пришло вдохновение — нажимаете «Вставить разрыв Глава 1». Приложение без тени сомнения дописывает заголовок «Глава 1» в файл, прямо после «Сцена 3». Теперь в вашем файле — гибрид радиоспектакля 50-х и бытового романа. ElevenLabs смотрит на эту структуру, видит заголовок главы посреди акта и решает, что это, вероятно, сбой в матрице. Оглавление выглядит как творение художника-авангардиста. Архитектор Аудиокниг, в свою очередь, исходит из того, что вы взрослый человек, и просто обрабатывает это молча — но и без каких-либо гарантий результата. Начиная с версии 12.0 интерфейс пытался блокировать смену режима записи — по крайней мере в теории. На практике все оказалось куда изобретательнее: Мозговой Штурм (всегда активный как режим планирования) был черным ходом, через который стрелками вверх и вниз можно было переключаться между Сценарием и Аудиокнигой (Аудиокнига → Мозговой Штурм → Сценарий и аналогично в обратную сторону). Первый клик «Вставить Акт 1» или «Вставить Главу 1» в только что выбранном режиме без труда перезаписывал файл .mode, смешивая акты с главами в одном файле нарратива. Лишь начиная с версии 15.2.3 появилась настоящая защита: после фиксации решения о режиме (первая структура или первая успешная производственная отправка) второй пункт записи в поле выбора режима фактически заблокирован. Мозговой Штурм по-прежнему всегда активен как режим планирования — предлагает сюжетные варианты — но перепрыгнуть через него в другой режим записи уже невозможно. (С версии 18.13 Мозговой Штурм больше ничего не резюмирует; эту задачу взял на себя инструмент Долговременной Памяти на панели постобработки.)

Промпты Шоураннера — ИИ как сценарист сериала (из версии 7, сохранено)

Это самое значительное изменение, введенное в версии 7 и сохраненное без изменений. Оно не видно в интерфейсе, но кардинально меняет качество генерируемого сюжета.

Шоураннер — это в телевизионной индустрии человек, отвечающий за сериал в целом: он следит за тем, чтобы сюжет никогда не двигался к легкой развязке, а постоянно сгущался, нагромождал конфликты и удерживал зрителя в напряжении на протяжении многих сезонов. В версии 7 эта философия была встроена непосредственно в системные инструкции ИИ.

Директива Anti-Closure — и что изменил движок Anthropic (Claude)

Философия Шоураннера реализуется через встроенную в каждый режим директиву Anti-Closure: запрет на закрытие сцен резюме, моралями и фальшивыми хэппи-эндами. В прежнюю эпоху (модель GPT) все было ровно наоборот — движок систематически нарушал этот запрет и «закрывал» историю при каждом удобном случае: вплетал подводящие итог предложения, создавал фальшивые хэппи-энды или завершал сюжетные линии в середине главы, словно каждый фрагмент был последним. Начиная с версии 18 весь движок ИИ работает по умолчанию на Anthropic (Claude) — а с версии 18.4 вы можете опционально указать собственного провайдера (ШАГ 2B) — и Claude придерживается Anti-Closure значительно строже.

В результате возник другой, сугубо технический побочный эффект: поскольку модель последовательно не закрывает сцену, ее ответ может достигать лимита длины одного ответа и обрываться на полуслове (а бывает, и на полуслоге). Приложение обрабатывает это самостоятельно — когда обнаруживает, что фрагмент оборвался по лимиту, одним коротким дополнительным запросом завершает последнее предложение так, чтобы оно звучало естественно на языке вашей истории, и лишь затем сохраняет текст. Если по какой-то причине это не удается, вы увидите мягкое предупреждение, а текст все равно сохранится в текущем виде — запись никогда не блокируется, оборванную концовку вы всегда можете доработать вручную.

Правило монтажера, описанное выше, остается в силе: если модель все же закрывает сцену слишком гладко, ваше право (и прямая обязанность) как Режиссера — открыть файл .txt, удалить эти последние предложения, оставить текст оборванным в напряженный момент и нажать «Перезагрузить проект с диска», чтобы синхронизировать память с исправленным файлом.

Каждый режим имеет встроенную директиву Anti-Closure:

  • Мозговой Штурм: ИИ действует как сценарист многосезонного сериала. Каждый из 3 предлагаемых вариантов ОБЯЗАН нагромождать препятствия, вводить новые дилеммы, открытые сюжетные линии и клиффхэнгеры. Абсолютный запрет предлагать варианты, в которых герои окончательно мирятся, преодолевают главное препятствие без серьезных последствий или история движется к поспешному финалу. Запрет на придумывание дешевых, магических локаций, ломающих архитектуру мира.
  • Режим Чернового Сценария: Абсолютный запрет заканчивать текст резюме, моралями или обрамлением. ИИ должно обрывать действие естественно в напряженный момент (клиффхэнгер), избегая выводов, чтобы следующий фрагмент мог плавно подхватить нарратив.
  • Режим Традиционной Аудиокниги: Абсолютный запрет заканчивать текст пафосными резюме, закрытием сюжетных линий или намеком на конец истории (например, «Она была готова к новым вызовам», «Она поняла, что пора идти дальше»). Текст должен обрываться в середине продолжающегося действия, напряжения или незавершенной мысли.

Исключение из правила: Если вы прямо попросите о концовке, финале или эпилоге, ИИ сгенерирует удовлетворяющее завершение истории — запрет не действует, когда вы сами об этом просите.

Управление Актами и Сценами (Режим Сценария, из версии 7, сохранено)

Режим Чернового Сценария имеет выделенную панель «✂️ Управление Структурой» с кнопками для построения структуры радиоспектакля в реальном времени.

  • Вставить Акт X: Вставляет заголовок акта (например, «Акт 2»), а также автоматически дописывает под ним «Сцена 1» — потому что каждый новый акт начинается с первой сцены. Счетчик актов переходит на следующий номер, а счетчик сцен сбрасывается до 2 (готов к следующей сцене в этом акте).
  • Вставить Сцену X: Вставляет только заголовок сцены (например, «Сцена 3») в рамках текущего акта. Счетчик сцен увеличивается автоматически.

Интеллектуальная загрузка файла: При загрузке существующего файла сценария приложение автоматически сканирует его и устанавливает счетчики актов и сцен на правильные номера. Счетчик сцен всегда вычисляется в рамках последнего акта в файле.

Пролог и Эпилог: Кнопки «📜 Вставить Пролог» и «🏁 Вставить Эпилог» общие для обоих режимов и доступны на той же панели.

Архитектор Аудиокниг автоматически преобразует Акты в основные навигационные точки (Heading 1) для ElevenLabs и NVDA — Сцены станут жирным текстом, видимым в документе, но не отображаемым в оглавлении.

Интеллектуальное Управление Главами (Режим Аудиокниги, из версии 5, сохранено)

LLM генерирует максимум около 5000 символов за один запрос — этого недостаточно для полноценной главы. Поэтому вы работаете итеративно: генерируете последовательные фрагменты кнопкой «Отправить в AI», пока не решите, что данная глава готова. Затем нажимаете «Вставить разрыв главы» — приложение дописывает заголовок в файл и память, а счетчик глав автоматически переходит на следующий номер.

Кнопки на панели:

  • Вставить разрыв (Глава X): Вставляет заголовок (например, «Глава 3») в файл и память. Счетчик глав обновляется автоматически.
  • Вставить Пролог: Работает только в начале, когда память пуста. Защита от случайной вставки Пролога в середине истории.
  • Вставить Эпилог: Закрывает историю. После вставки Эпилога с содержимым приложение заблокирует генерацию новых фрагментов — это сделано намеренно, поскольку после завершения истории дописывать уже нечего.

Интеллектуальная загрузка файла: При загрузке существующего файла приложение автоматически сканирует его и устанавливает счетчик глав на правильный номер. Если файл содержит Пролог и три главы, счетчик покажет «Глава 4» — без ручного подсчета.

Аккумулятор Сюжета — как работает память ИИ

В память модели попадает исключительно чистый текст истории — то, что ИИ фактически написало. Инструкции, варианты и планы исчезают после использования и не засоряют контекст. Результат: модель дольше сохраняет сосредоточенность, лучше помнит акценты персонажей и реже «уходит» от правил Книги Мира.

Индикатор «Память Модели» на экране показывает, насколько заполнено контекстное окно модели. Начиная с версии 15.1 это уже НЕ просто подсчет символов истории — приложение считает реальные ТОКЕНЫ (тем же методом, которым пользуется модель) и суммирует ВСЮ нагрузку, отправляемую в ИИ: текущую историю, Долгосрочную Память (краткое содержание) И Книгу Мира. Поэтому индикатор растет и тогда, когда вы расширяете Книгу Мира или у вас длинное краткое содержание — не только от самого нарратива. Значение отображается как процент заполнения окна:
- Зеленый (до ~70%): Модель полностью сосредоточена, у вас есть безопасный буфер.
- Желтый (~70–90%): Вы приближаетесь к пределу. ИИ может начать сокращать ответы и игнорировать правила. Это момент, когда стоит сохранить Долговременную Память самому — и начать постепенно закрывать сюжетную линию.
- Красный (выше ~90%): Критическая перегрузка! С версии 18.13 на этом уровне приложение после каждой удачной отправки само запускает инструмент Долговременной Памяти с панели постобработки и сохраняет краткое содержание — вы получаете об этом сообщение, а панель на время генерации блокируется.

Диагностика порога краткого содержания (когда ИИ начинает галлюцинировать раньше, чем предполагает порог): пороги (предупреждение ~70%, тревога ~90%) определены эмпирически. Если вы заметите устойчивую тенденцию, что модель «уходит» от правил или начинает галлюцинировать ДО того, как индикатор войдет в желтую/красную зону — то есть раньше, чем предполагает порог — откройте issue в репозитории приложения и опишите, при каком примерно заполнении (в процентах) это фактически начинается, желательно с примером. Если эта тенденция подтвердится шире (у других пользователей, на разных проектах), порог автоматического создания краткого содержания будет снижен в следующем патче. Это осознанно итеративный механизм — лучше настраивать его на реальных данных, чем угадывать заранее.

Бесконечная Память (из версии 6, сохранено)

Когда загорается красная тревога, вам больше не нужно вручную копировать краткое содержание. С версии 18.13 этим занимается отдельный инструмент на панели постобработки (ШАГ 4): одно нажатие создаёт сжатую выжимку знаний обо всём сюжете на данный момент, сохраняет её файлом памяти в папке skrypty/ (в русском пакете <название>_пересказ.txt) и сразу помещает в поле Долговременной Памяти. После сохранения можно очистить память и продолжать писать в том же файле — историю можно вести бесконечно, без каких-либо ограничений по длине.

Что изменилось по сравнению с прежними версиями: до v18.12 краткое содержание заказывалось в Мозговом Штурме — достаточно было написать в инструкции слово «резюме» или «подытожь». У этого пути был встроенный в конструкцию изъян: промпт Мозгового Штурма запрещает модели писать что-либо, кроме трёх сюжетных вариантов, поэтому просьба об одном лишь резюме ставила её перед двумя противоречивыми инструкциями сразу — и могла закончиться ошибкой вместо результата. Поэтому резюмирование теперь самостоятельный инструмент с собственной, непротиворечивой инструкцией, а Мозговой Штурм вернулся к одной задаче: планированию сюжета.

Когда создавать краткое содержание (обновлено в v15.5): Вам больше не нужно строго следить за порогом символов «перед завершением работы». Лучше всего создавать краткое содержание после естественного закрытия крупной структурной части — после завершения сцены, акта или главы. Причина: когда вы позже вручную исправите концовку в файле нарратива и нажмете «Перезагрузить проект с диска», приложение спросит, с какого заголовка восстановить свежий фрагмент — а краткое содержание предыдущей части останется нетронутым (конец правки в двух местах). Поэтому тем более стоит поддерживать структуру: регулярно вставляйте заголовки Глава/Акт/Сцена с панели структуры (не рекомендуются длинные формы без каких-либо актов/глав, например «модернистская драма» одним потоком). ИСКЛЮЧЕНИЕ: если вы ведете очень длинную историю ПОЛНОСТЬЮ без заголовков, генерация и сохранение краткого содержания перед перерывом по-прежнему обязательны — без маркеров приложение может восстановить только последний фрагмент, отсчитанный в символах, а движок без контекста может «запаниковать».

Автоматическое создание краткого содержания (перестроено в v18.13): когда индикатор памяти входит в тревожное состояние (выше ~90%), приложение по завершении отправки само запускает инструмент Долговременной Памяти — не спрашивая, потому что на этом уровне каждый следующий вызов уже под угрозой. Результат идёт прямо в файл краткого содержания и в поле Долговременной Памяти, а вы получаете сообщение о том, что это произошло. Никакой ручной работы. Краткое содержание, разумеется, можно поправить в поле и сохранить заново кнопкой сохранения Памяти.

Краткое содержание ИНКРЕМЕНТАЛЬНО: инструмент не читает каждый раз весь проект заново. Он получает накопленную Долговременную Память и ту часть повествования, которая возникла после последнего резюме (приложение помнит, на каком заголовке остановилось), и сводит одно с другим. Благодаря этому стоимость последующих резюме не растёт вместе с длиной романа, а более старые события не теряются при каждом обновлении.

Интеллектуальная загрузка и перезагрузка с диска (обновлено в v17.6): Как при загрузке проекта, так и после нажатия «Перезагрузить проект с диска» (после ручного редактирования файла нарратива в редакторе) приложение единым потоком согласует память с диском — пересчитывает счетчики структуры и подгружает Книгу Мира и режим. Если ВСЯ история умещается в контекстном окне — загружает ее целиком, а ненужное старое краткое содержание удаляет, чтобы движок работал на полном тексте (это закрывает давнюю брешь, при которой модель получала только краткое содержание без контекста последних сцен). Если история ДЛИННАЯ и для нее сохранен файл краткого содержания — оставляет краткое содержание нетронутым и спрашивает, с какого структурного заголовка (Глава/Акт/Сцена) должна стартовать рабочая память ИИ; остальная часть сюжета представлена кратким содержанием. Благодаря этому вы не тратите токены на повторную загрузку всей истории, а следующее краткое содержание не создается на устаревших данных.

ШАГ 3b: Два выхода Скрипта — многоголосая аудиокнига (ElevenLabs) и версия для экранных дикторов

Готовый скрипт читаемого театра (режим Скрипт) имеет два независимых выхода: многоголосый проект ElevenLabs Studio (аудио) и HTML-версию для экранных дикторов. Это два способа «услышать» одну и ту же пьесу — можно использовать один, другой или оба. Оба являются необязательными и не изменяют классический рабочий процесс с конвертером.

Мост к ElevenLabs Studio (аудио, необязательно)

Мост превращает скрипт в многоголосый проект Studio — нарратор и каждый персонаж получают отдельный голос. Без ключа ElevenLabs ничего не меняется: мост просто остается скрытым.

Ключ ElevenLabs (необязательно)

Вставьте свой ключ ElevenLabs в файл golden_key.env, в отдельной строке: ELEVENLABS_API_KEY=sk_... Внимание: ключ ElevenLabs начинается с sk_ (с ПОДЧЕРКИВАНИЕМ), в отличие от ключа Anthropic (sk-ant-). Если вы используете ключ с ограничениями (restricted key), назначьте ему права (scope'ы) projects_write и voices_read. Статус ключа виден на главном экране (System Check) — отсутствие ключа не является ошибкой, мост просто остается скрытым.

Мост появляется в панели Режиссера в режиме Скрипт (когда ключ корректен). Он работает с готовой пьесой, сохраненной на диске — сначала сгенерируйте или загрузите проект, затем перейдите к мосту.

Шаг 1 — Голосовой состав

Нажмите «Obsada głosowa…». Приложение загрузит из вашего скрипта персонажей, у которых есть реплики, и всегда добавит слот Нарратора (нарратор — это голос по умолчанию, который читает заголовки глав и всю нарративную часть). Для каждого говорящего вставьте voice ID. ВАЖНО: каждый голос, используемый в пьесе, должен сначала оказаться в вашем разделе «My Voices» — голоса, которые вы создаете сами (например, в «Voice Design»), попадают туда автоматически, а голоса из публичной библиотеки просматриваются во вкладке «Explore» и добавляются кнопкой «Add to My Voices». Как получить voice ID в ElevenLabs (в браузере): найдите голос, воспроизведите образец, чтобы убедиться, что это нужный, и скопируйте его идентификатор кнопкой «Copy Voice ID»; когда голос уже находится в «My Voices», эта кнопка доступна сразу — без раскрытия «More actions». Подбор голосов: чтобы минимизировать возможные регенерации, проще всего выбирать из коллекции «Best for Eleven v3» (голоса, проверенные для модели v3, на которой создается проект); альтернативно — разработайте собственный голос в «Voice Design», а для смелых остается клонирование IVC (Instant Voice Cloning) или PVC (Professional Voice Cloning). Поля можно оставить пустыми и вернуться позже — сохранение является черновиком.

Шаг 2 — Сборка проекта

Нажмите «Stwórz projekt ElevenLabs Studio…». Приложение проверит, есть ли в скрипте хотя бы одна глава (Пролог/Акт/Глава) и назначен ли голос каждому говорящему и нарратору, а затем создаст в вашем аккаунте многоголосый проект Studio, разбитый на главы. Само создание проекта НЕ расходует кредиты. Приложение сразу устанавливает язык проекта (правильное произношение строк заголовков) и нормализацию громкости по стандарту аудиокниги — это делается через API, чтобы вам не нужно было заходить в настройки проекта в браузере.

Страж формата (расширение Правила Монтажера): мост требует, чтобы в скрипте КАЖДАЯ строка была либо репликой с маркером говорящего ([Narrator: …] или [Имя: …]), либо заголовком структуры (Пролог, Акт, Сцена, Глава). Обычная, непомеченная проза, вписанная «свободно» — например, авторская заметка или фрагмент нарратива без тега — не попадает ни к одному голосу и при сборке молча пропускается, поэтому готовый проект может разойтись с вашим файлом. Поэтому если приложение обнаружит такие строки-сироты, оно покажет их список с номерами и спросит, строить ли все равно: вы можете отменить и исправить скрипт (откройте его кнопкой «Открыть файл повествования…», добавьте недостающие маркеры говорящего или удалите эти строки) или сознательно выполнить сборку, смирившись с их пропуском. Это естественное расширение Правила Монтажера: так же, как нельзя портить заголовки структуры, в скрипте, предназначенном для моста, каждая строка должна иметь своего говорящего или быть заголовком.

Шаг 3 — Рендер в браузере

После создания проекта приложение покажет его идентификатор и кнопку, открывающую ElevenLabs Studio. В браузере найдите проект, выполните рендер речи (вот тогда расходуются кредиты — ориентировочно 1 кредит за символ), а затем экспортируйте аудиофайл или опубликуйте проект в Eleven Reader. Рендер и публикация происходят на вашей стороне, осознанно — приложение лишь собирает проект.

Экспрессия и акценты (модель Eleven v3)

Проект создается на модели Eleven v3 (более 70 языков). Эмоции НЕ выражаются заглавными буквами, многоточиями или тире — движок это игнорирует. Вместо этого Режиссер вплетает в реплики английские аудио-теги v3, например [whispers], [sighs], [angry], [laughs] — именно они управляют экспрессией и работают независимо от языка речи. АКЦЕНТ персонажа берется из ОБРАЗЦА ГОЛОСА: если вы хотите, чтобы кто-то говорил, например, по-русски с иностранным акцентом, подберите или разработайте в Voice Design голос, образец которого имеет этот акцент. На практике экспериментируйте с промптом голоса, пока не услышите, например, русский образец с финским акцентом — модель v3 сохранит этот акцент в готовой записи. Подсказка: очень длинные предложения ослабляют акцент, поэтому Режиссер уже просится в промпте использовать короткие предложения.

Осведомленность о модели v3 (фаза alpha)

Eleven v3 наиболее экспрессивна, но все еще находится в фазе alpha. Бывает, что отдельная реплика рендерится как треск вместо речи — достаточно ее регенерировать в Studio (каждый блок имеет несколько бесплатных регенераций). В настройках проекта ElevenLabs также может отображать рекомендации по смене модели (на Eleven Flash v2.5 или Multilingual v2) — это НЕ ошибка, а лишь подсказка движка. Если вы не хотите видеть эти сообщения, просто не открывайте настройки проекта: приложение уже установило через API все необходимое (модель, язык, нормализацию громкости).

Почему читаемый театр, а не звуковые эффекты? В более ранних версиях режим Скрипт производил сырые эффекты [SFX: ...] без нарратора. Однако мост к готовой, многоголосой записи требует, чтобы контекст (место, время, действие) нес нарратор словами: звуковые эффекты в Studio недоступны для экранных дикторов, а модель все равно реализует либо нарратора, либо эффекты — никогда стабильно оба сразу. Поэтому режим Скрипт — это читаемый театр: нарратор плюс диалог, без SFX.

Версия для экранных дикторов (HTML, без ElevenLabs)

В режиме Скрипт, независимо от ключа ElevenLabs, у вас есть кнопка «Generuj wersję dla czytników ekranu». Она создает файл skrypty/<nazwa>_screen_reader.html — отдельный выход для людей, использующих экранные дикторы (например, NVDA). Работает это так: реплики персонажей, у которых в Книге Мира определен акцент (например, запись «[Joana] akcent fiński»), получают фонетическую запись (намеренно «испорченная» орфография) и языковой маркер (атрибут lang), благодаря чему экранный диктор читает их с правильным, иностранным акцентом. Аудио-теги v3 (например, [whispers]) в этой версии удаляются — диктор не должен читать их вслух. Заголовки Пролог/Акт/Сцена становятся заголовками HTML, поэтому по документу удобно перемещаться.

Это осознанное дополнение аудиомоста: акцент для модели v3 несет образец голоса, а для экранного диктора — орфография плюс языковой маркер. Поэтому орфография в аудиоверсии остается чистой (v3 сам определяет язык), а «порча» орфографии попадает исключительно в отдельный HTML-файл, где она желательна.

ШАГ 4: Постобработка в Режиссуре

После написания истории в вашем распоряжении находится панель инструментов постобработки внизу панели Режиссуры. Панель динамична: каждый инструмент — это отдельный файл YAML в папке rezyser/ (kategoria: postprodukcja), а его поле dla_trybow определяет, в каких творческих режимах инструмент появляется. Набор кнопок меняется вместе с выбранным режимом — а когда ни один инструмент не подходит к текущему режиму, панель остаётся скрытой. Собственный инструмент вы создадите в Менеджере Правил (шаблон типа postprodukcja — см. ШАГ 7b).

Инструмент работает в одном из трёх диапазонов (поле zakres в YAML):

  • per_rozdzial — итерирует по главам сохранённого файла и обрабатывает каждую отдельно (так работает «Присвоение Заголовков» ниже),
  • calosc — отправляет в AI весь файл проекта за один вызов (например, отчёт или аудит всей истории); если у проекта есть Книга Мира, инструмент может подключить её как дополнительный контекст,
  • rekoncyliacja (с версии v18.13) — вместо всего файла отправляет накопленную Долговременную Память, а также ту часть повествования, которая возникла после последнего резюме. Так работает описанный ниже инструмент Долговременной Памяти; благодаря этому стоимость последующих вызовов не растёт вместе с длиной романа.

Результат всегда появляется в диалоговом окне (для копирования), а инструмент с заданным суффиксом файла результата дополнительно сохраняет его рядом с повествованием в папке skrypty/ (например, nazwa_audyt.txt). Перед перезаписью существующего файла результата приложение спрашивает согласия — прежде чем потратить хоть грош на вызов AI. Если материал для инструмента превышает контекстное окно, по которому приложение измеряет память (128 тысяч токенов), вы сначала увидите предупреждение с вопросом, стоит ли всё же запустить инструмент. Это лишь предупреждение: модели Claude имеют окно значительно большее, чем этот счётчик, но собственный провайдер AI с меньшим окном отклонит такой запрос — а за попытку вы всё равно заплатите.

Присвоение Заголовков Главам (Режим Аудиокниги)

AI проанализирует всю историю и предложит описательные, литературные названия для каждой главы (а также возможного Пролога и Эпилога). Модуль итерирует по главам из сохранённого файла и присваивает им короткое название, анализируя только начала каждой главы (до 6000 знаков). Возвращает исключительно пронумерованный список названий — без переписывания содержания книги.

Долговременная Память — резюме проекта (с версии v18.13)

Инструмент доступен в обоих режимах сохранения (Skrypt и Audiobook). Генерирует сжатую запись фактов: ход событий, решения персонажей и их последствия, персонажей, места, открытые сюжетные линии, а в конце — однострочную заметку о стиле и тоне повествования. Получателем этого текста является нарративный движок, а не читатель — поэтому резюме сухое и фактографическое, без украшений.

У него есть одна особенность, которой нет у остальных инструментов: его результат не оказывается «рядом» с проектом, как отчёт, а СТАНОВИТСЯ Долговременной Памятью — попадает одновременно в файл памяти в папке skrypty/ (его имя задаёт рецепт инструмента; в русском пакете это <название>_пересказ.txt), в поле «Долговременная Память» в панели и во внутренний маркер, по которому приложение узнаёт, докуда доходит резюме (именно он позволяет резюмировать инкрементально и спрашивает вас о точке отсчёта при перезагрузке проекта с диска). Инструмент запускается также автоматически, когда индикатор памяти модели входит в тревожное состояние — см. ШАГ 3.

Имя файла памяти локализуемо (с версии 18.14). Каждый языковой пакет указывает своё родное слово в поле sufiks_pliku_wyniku файла rezyser/postprod_streszczenie.yaml: русский _пересказ, английский _overview, немецкий _zusammenfassung, финский _yhteenveto и так далее. Значение можно изменить в Менеджере Правил на любое своё (например _память) — приложение справится с переходом, потому что ищет файл памяти по СПИСКУ КАНДИДАТОВ:

  • оно проверяет по очереди суффиксы инструментов памяти из пакета языка СОДЕРЖАНИЯ проекта (не языка интерфейса — файл принадлежит истории, а не меню), затем нейтральный _overview и, наконец, исторический _streszczenie;
  • если находит РОВНО ОДИН файл под именем, отличным от текущего, переименовывает его вместе с внутренним маркером — вручную делать ничего не нужно;
  • если находит НЕСКОЛЬКО (потому что у вас отдельный инструмент памяти «для себя» и «для ИИ» либо файлы времён другого языка интерфейса), спрашивает вас, какой должен стать Долговременной Памятью, и не трогает остальные. Отмена этого вопроса означает сессию без памяти: поле остаётся пустым, ни один файл не изменяется и не удаляется, а при длинном повествовании приложение попросит вас указать точку отсчёта рабочей памяти.

Карточка публикации ElevenReader (с версии 18.14)

Инструмент читает весь текст проекта и собирает готовый набор метаданных для формы публикации аудиокниги на ElevenReader, а результат сохраняет в папке skrypty/ (в русском пакете как <название>_публикация.txt). Карточка содержит: название и необязательный подзаголовок, описание до 1000 знаков (лимит платформы), один или два жанра ИСКЛЮЧИТЕЛЬНО из канонического списка 22 категорий ElevenReader, целевую аудиторию, отметку о контенте для взрослых с одним предложением обоснования, от двух до трёх фрагментов, выбранных для бесплатного превью, готовый промпт для генератора изображения обложки (вертикально 1200×1800 px, с местом для читаемого названия и имени автора), а также напоминание о полях, которые в форме вы оставляете по умолчанию.

Названия полей в карточке — АНГЛИЙСКИЕ (Title:, Description, Genres:, Target audience:, Mature content:, Sample chapters:, ISBN:): форма платформы существует только на английском, поэтому вы переписываете их 1:1. Содержание полей — на языке вашего проекта, но ЗНАЧЕНИЯ закрытых полей (жанры, аудитория, Yes/No для контента для взрослых) тоже остаются английскими, потому что платформа принимает их только из своего списка.

Чего карточка не сделает за вас: она не выдумывает ни издателя, ни номер ISBN — оставляет их полями для заполнения вручную (ISBN — регистрируемый номер, и галлюцинация здесь была бы ложным издательским заявлением). Профиль автора на ElevenReader обязателен, потому что анонимные публикации не допускаются и это связано с заявлением об авторских правах — поэтому инструмент перепишет имя или псевдоним из Книги Мира, а если не найдёт его там, вставит поле для заполнения. Фрагменты для превью он подбирает ВСЕГДА, потому что форма требует хотя бы одного, независимо от модели выплат, которую вы выберете позже.

После генерации приложение проверяет карточку со своей стороны: укладывается ли описание в лимит, взяты ли жанры и аудитория из списка платформы, заполнены ли обязательные поля и не появились ли цифры в поле ISBN. Расхождения показывает как мягкие замечания — результат вы получаете целиком и сами решаете, что править. Это защита от случая, когда модель выдумает несуществующую категорию, а форма отклонит её лишь в самом конце мастера.

Внимание: Инструменты постобработки требуют, чтобы файл проекта был уже сохранён на диске (сгенерирован или загружен). Если файл не существует, приложение выведет соответствующее сообщение.

ШАГ 5: Полиглот AI

Приложение для перевода и принудительного наложения акцентов на синтезаторы экранных чтецов. Перейдите к нему, нажав кнопку "🌍 Полиглот" на панели инструментов или выбрав Инструменты → Полиглот в меню (сочетание клавиш: Ctrl+2).

Режим 1: Обычный Переводчик (Использует AI - Платный)

Идеально подходит для прослушивания рассказов на красивом, правильном иностранном языке.

  • Загрузите файл кнопкой "Загрузить файл в память" или используйте кнопку "Обзор..." для выбора файла в системном окне.
  • Выберите режим "Переводчик ИИ", введите целевой язык (например, "Финский").
  • Скрипт переведет содержимое. Если вы загрузите файл .html, он переведет только текст, видимый для читателя, и обновит языковой код в теге html.
  • Если вы загрузите обычный файл .txt или .md (например, скрипт, сгенерированный Режиссером), скрипт после перевода автоматически сохранит результат как файл .html с встроенным языковым тегом — готовый к чтению NVDA без дополнительной работы.
  • Поддерживает также файлы .docx.

Интеллектуальное разделение на блоки: Длинные тексты автоматически разделяются на блоки, измеряемые в токенах модели (а не в символах), и переводятся последовательно с индикатором прогресса. Благодаря этому даже языки с плотной письменностью, такие как китайский или японский, укладываются в лимит ответа модели, а обрезанный ответ обнаруживается и автоматически повторяется на меньших фрагментах.

Устойчивое к сбоям сохранение прогресса (НОВИНКА в версии 9): Каждый переведенный блок немедленно сохраняется во временный файл в системной папке приложения. Если перевод прерывается из-за исчерпания лимита API, при следующем запуске приложение автоматически обнаружит этот файл, восстановит уже оплаченный прогресс и спокойно завершит работу с места прерывания — без ручного копирования. После успешного завершения временный файл автоматически удаляется.

Почему это важно? В версии 8 подход к возобновлению перевода имел критическую, тихую ошибку: если не переименовать файл с частичным переводом и вырезать переведенный фрагмент согласно инструкции, а затем сразу возобновить перевод остального — приложение открывало выходной файл в режиме перезаписи. Оплаченный прогресс безвозвратно и незаметно стирался, прежде чем вы успели что-либо заметить. Версия 9 полностью устраняет эту ловушку: сохранение происходит после каждого блока, независимо от того, что вы делаете потом.

Режим 2: Режим Режиссера / Акценты (Бесплатный - Работает локально)

Инструмент для "искажения" текста. Принуждает синтезаторы к ломаному польскому.

Интегрированное выпадающее меню Режима Режиссера позволяет выбрать акцент прямо из одного списка. Доступные опции:
Английский (Samantha / Mark — Vocalizer/Apple, Zira / Hazel — OneCore)
Польский (Ewa — Vocalizer, Paulina — OneCore)
Французский (Thomas / Amelie — Vocalizer/Apple, Julie — OneCore)
Немецкий (Markus / Stefan — Vocalizer/Apple, Hedda / Katja — OneCore)
Испанский (Jorge / Monica — Vocalizer/Apple, Helena — OneCore)
Исландский (Gudrun — OneCore, eSpeak; внимание: Vocalizer не поддерживает этот язык!)
Итальянский (Alice / Luca — Vocalizer/Apple, Elsa — OneCore)
Финский (Satu / Mikko — Vocalizer/Apple, Heidi — OneCore)
А также две опции очистки без акцента:
"Никакой (Очистка БЕЗ нормализации чисел)"
"Никакой (Очистка С нормализацией чисел)"
Опция с нормализацией чисел автоматически преобразует цифры в их словесное представление (например, 15 становится "пятнадцать") перед обработкой — благодаря этому NVDA читает числа плавно, а если текст имеет принудительный акцент, число также получит его, без исключений.
Вы, вероятно, спросите, сможет ли синтезатор склонять такие нормализованные числа в зависимости от контекста? Ответ: нет. И это целевая функция. Как известно: "польский язык трудный" — а иностранец, коверкающий нашу грамматику, только добавляет аутентичности ломаному акценту!

Исправитель Тегов (НОВИНКА в версии 9): В конце списка вы найдете дополнительную опцию — Исправитель Тегов. Он не применяет никаких фонетических правил или очистки. Делает одну вещь: встраивает в файл указанный вами код языка ISO — двухбуквенный (например, "fi" для финского, "en" для английского) или с субтегом региона либо письменности (например, "pt-BR" для бразильского португальского, "zh-Hans" для упрощенного китайского). Полезно, когда у вас уже есть готовый файл — например, ранее переведенный Переводчиком AI — но по какой-то причине он вышел с ошибочным или отсутствующим языковым тегом. Вместо того чтобы переводить его заново, просто запускаете Исправитель с правильным кодом ISO, и через мгновение у вас будет правильный файл.

Скрипт очищает режиссерские ремарки в скобках — удаляет все фрагменты текста, заключенные в круглые скобки (например, "(с вкраплениями вдохов)", "(шепотом)", "(иронично)"). ElevenLabs должен читать только диалоги и повествование, а не режиссерские инструкции, встроенные в текст.

Скрипт также очищает маркеры Markdown — удаляет хэштеги заголовков (например, #, ##, ###), знаки равенства, используемые как подчеркивания заголовков, а также одиночные запятые, которые могут нарушить ритм чтения синтезатором.

  • Защитный экран: Скрипт защищает все HTML-теги. Искажает только диалоги и повествование.
  • Работает локально и ничего не стоит!

Режим 3: Шифровальщик (НОВИНКА в 13.0 — игры с текстом, бесплатные, локальные)

Третий RadioButton в Полиглоте, рядом с Переводчиком ИИ и Режимом Режиссера: «Режим Шифровальщика (текстовые игры, случайные заикания)». Запускает шесть локальных алгоритмов искажения текста — для развлечений, загадок, языковых головоломок. После выбора режима появляется выпадающий список алгоритмов, а для одного из них (Шифра Цезаря) дополнительное числовое поле для смещения.

Доступные алгоритмы (отметьте в меню «Выберите искажающий алгоритм»):

  • Перевертыш Текста (Чтение задом наперед с заглавной буквой) — каждое предложение переворачивается знак за знаком, с сохранением точки/восклицательного/вопросительного знака в конце и заглавной буквы в начале. Перед переворачиванием скрипт разворачивает популярные сокращения (т.е., т.д., т.н., т.к., и.о. и т.п.), чтобы результат после переворота все еще имел смысл — без этого «т.е.» после переворота превращается в абсурдное «.е.т».

Вдохновение: миссия из программы «The Traitors. Предатели». Когда ведущая без предупреждения показала участникам популярную польскую песню из мультфильма — просто воспроизведенную задом наперед — реакции были в стиле «какой это язык?», «это, наверное, армянский», «венгерский или финский». Настоящая миссия заключалась в том, что одна команда получала в лесу текст песни, записанный задом наперед, должна была спеть его в этой перевернутой форме, другая команда это записывала, воспроизводила с конца — и теоретически восстанавливала оригинальную песню для угадывания. Точно такое же забавное фонетическое недоразумение генерирует наш Перевертыш, когда вы запускаете обработанный файл через синтезатор TTS.

  • Типогликемия (Перемешанный центр слов) — классический психолингвистический эффект: «Сгласно исслеводаним в Кембриджском Университете, не важо, в каком порякде буквы в слове, важо, чтобы первя и последня буква были на правельных местах». Скрипт случайным образом перемешивает середину каждого слова длиннее 4 знаков, первая и последняя буква остаются нетронутыми. Отлично подходит для теста «сколько я на самом деле вижу, а сколько догадывается мой мозг».

  • Сломанный Телефон / Змеиный диалект — каждое «с», «з» или двузнак «ш» случайно удлиняется в шипение длиной 4-8 знаков («сссссс», «зззззз», «сссссш»). Вдохновение: Snecko из игры «Slay the Spire». Эффект: текст звучит, как будто его прочитал змей с дефектом речи.

  • Гласновик (Все гудит на «О») — каждая гласная в тексте заменяется на «о», с сохранением польских смягчений. «Добрый день» → «Добро день». Чем длиннее текст, тем забавнее эффект (а экранный чтец читает это с полной уверенностью).

  • Сильное Заикание / Поврежденный Робот — добавляет заикания в начале слов: «к-к-к-компьютер», «пр-пр-привет». Для коротких слов (менее 3 знаков) алгоритм их пропускает. Если вторая буква слова согласная, повторяет первые две буквы (более естественный эффект); если гласная — повторяет только первую.

  • Шифр Цезаря (смещение алфавита RU) — классический шифр подстановки: каждая буква сдвигается на N позиций в русском алфавите с добавленной латиницей (АБВГ…ЮЯ + ABC…XYZ, 59 знаков). Значение смещения вводите в числовое поле «Смещение шифра Цезаря (0 = случайное, диапазон -58…58)». Если введете 0 — приложение выберет случайное смещение в диапазоне 1-58 и покажет его в сообщении после завершения (чтобы вы могли потом расшифровать). Знаки вне алфавита (цифры, пунктуация, пробелы) остаются без изменений.

Практическое применение: шифры записывают результат в том же формате, что и Режим Режиссера (.html с тегом lang или .docx с тегами XML), то есть NVDA прочитает их голосом соответствующего языка. Особенно Перевертыш и Гласновик звучат в синтезаторе гораздо интереснее, чем когда вы читаете их глазами — потому что мозг при чтении глазами автоматически пытается «раскодировать» текст, а TTS читает его точно так, как записано.

Все шесть шифров также описаны более широким, доступным языком в файле docs/dictionaries.pl.html в пакете приложения — вместе с советами, как добавить собственный шифр типа «замена букв» без знания программирования (например, школьный жаргон, тарабарщина).

Язык обработки, принудительный режим и режим качества (НОВОЕ в 18.11)

Раздел загрузки файла теперь оснащен раскрывающимся списком языка обработки. С его помощью вы выбираете, по правилам какого языка работают режимы Режиссера и Шифровальщика: списки акцентов и шифров, а также алфавит Шифра Цезаря вместе с диапазоном сдвига.

  • Позиция по умолчанию «Определить автоматически» сохраняет прежнее поведение: язык определяется на основе загруженного файла, а если он отличается от языка приложения, вы получите короткое уведомление о том, что списки были переключены.
  • Выбор конкретного языка из списка является обязывающим — приложение не изменит его самостоятельно при загрузке файла.

Под списком расположено поле выбора, принудительно задающее выбранный язык для всего документа. По умолчанию каждый абзац обрабатывается согласно языку, определенному для этого абзаца, — это обычно наилучший выбор, поскольку иноязычные вставки получают свои собственные, корректные правила. Отметьте принудительный режим, если вам важна единообразная обработка всего текста целиком. Пример, в котором это необходимо: обратимое многослойное шифрование. Алфавит Шифра Цезаря имеет в каждом языке разную длину, поэтому без принудительного режима текст, смешанный по языкам, будет зашифрован несколькими разными алфавитами — а расшифровка в таком случае требует знания, где проходили границы языков. С принудительно заданным языком весь документ шифруется и расшифровывается одним и тем же алфавитом. Оговорка: в языках, чей алфавит Цезаря содержит диакритические буквы, нормализуемые при загрузке (польский, немецкий), расшифровка не полностью точна — диакритические буквы шифрограммы при повторной загрузке преобразуются в базовые формы, прежде чем попасть в расшифровку. Полную обратимость гарантируют алфавиты без таких знаков (например, английский).

ИИ-переводчик в свою очередь получил поле выбора режима качества. При его включении модель получает дополнительный бюджет на внутренний анализ текста перед переводом (так называемое extended thinking) — перевод занимает больше времени и обходится большим количеством токенов, но сложные фрагменты обрабатываются более тщательно. Опция работает исключительно с моделями Anthropic Claude; если вы пользуетесь альтернативным поставщиком через endpoint, совместимый с OpenAI, включение этой опции не дает никакого эффекта.

Смежная деталь: знаки с макроном, используемые в японской романизации (например, Tōkyō, rāmen, jūdō), начиная с этой версии нормализуются так же, как и другие иностранные диакритические знаки — в большинстве языков до простой буквы (Tokyo), а в финском пакете через удвоение гласной (Tookyoo), в соответствии с финской конвенцией записи долгих звуков. Благодаря этому они больше не выпадают из алфавита Шифра Цезаря как явные символы в шифрограмме.

Определение языка

Перед тем как скрипт "испортит" текст, он проверяет, на каком языке он написан. Если будет обнаружено, что это не польский, появится предупреждение. Фонетические правила адаптированы под польский язык — их применение к тексту на другом языке может привести к непредсказуемым результатам.

Акценты, оптимизированные для локальных синтезаторов (NVDA)

Акценты были на 100% разработаны для локальных, бесплатных и платных синтезаторов экранных чтецов — Vocalizer и eSpeak в NVDA. Это гарантирует стабильность и предсказуемость результата на каждом компьютере.

Почему не ElevenLabs? Тесты на более длинных документах показали, что фонетическое искажение текста в движках, таких как ElevenLabs, не заставляет использовать заданный акцент — движок просто "угадывает" язык и из него скорее делает акцент западно/южно-славянский. Локальные синтезаторы NVDA в этом вопросе значительно более послушны.

Специфика локальных синтезаторов (TTS)

Различные движки TTS ведут себя по-разному. Ниже приведены ключевые различия, которые непосредственно влияют на работу акцентов:

eSpeak (Open Source)

Легкий, бесплатный движок с огромной базой языков — поддерживает, например, исландский. Очень строг к кодировке символов, что делает его предсказуемым. Однако у него есть фонетические недостатки: часто делит фонемы между языками, из-за чего, например, украинский звучит с русским акцентом.

Tiflotecnia Voices для NVDA (голоса Cerrence — ранее Vocalizer от Nuance)

Tiflotecnia Voices — это прямой преемник Vocalizer от Nuance, коммерческий движок с голосами нового поколения от компании Cerrence, распространяемый как пакет .nvda-addon в NVDA Add-on Store. Старый Vocalizer (32-битные библиотеки .dll от Nuance) ушел в прошлое вместе с NVDA 2026.1; Cerrence перекомпилировала голоса на 64-бита, и Tiflotecnia выпустила их под новым названием. Качество произношения заметно лучше, чем в предыдущем поколении.

Как установить: NVDA → Инструменты → Add-on Store → найдите «Tiflotecnia Voices for NVDA» → Установить. После установки в меню NVDA появится специальное подменю «Tiflotecnia Voices», а также собственная категория в настройках NVDA. Графический интерфейс дополнения пошагово проводит через покупку лицензии (или активацию 7-дневного пробного периода), выбор и установку первых голосов (например, польская Ewa для плавного чтения системных контролей, финская Satu для акцентов в Полиглоте). Встроенная помощь дополнения ясна, поэтому здесь не дублируем процедуру — достаточно следовать указаниям дополнения.

Совет для мигрирующих с Vocalizer и Eloquence: доступно обновление по сниженной цене. Процедура: после успешной оплаты сразу напишите письмо на адрес, указанный на экране успешной оплаты, и попросите валидацию старого активационного кода — Tiflotecnia подтвердит право на скидку и урегулирует цену. Без этого письма система будет считать вас новым клиентом.

Доступность голосов: Tiflotecnia Voices поддерживает большинство языков, которые имел Vocalizer (включая польский, английский, немецкий, французский, испанский, финский, итальянский, русский). Список голосов по языкам виден в категории настроек дополнения перед покупкой лицензии.

Microsoft OneCore

Бесплатные голоса, встроенные в систему Windows (Mobile Voices). Хороший компромисс между качеством и доступностью языков. Предлагает высокое качество и поддерживает исландский (Gudrun), финский (Heidi) и итальянский (Elsa) языки. Внимание: OneCore изначально НЕ поддерживает автоматическое переключение языка на основе тегов lang (если только вы не используете встроенный в систему экранный диктор) — см. раздел ниже.

Как скачать голоса OneCore на Windows? Голоса OneCore бесплатны, но большинство языков не установлено по умолчанию. Чтобы скачать недостающие языки, зайдите в Настройки Windows → Время и язык → Речь → Управление голосами (или "Добавить голоса"). Выберите язык из списка (например, Исландский, Финский, Итальянский) и нажмите Скачать. После загрузки голос появится автоматически в NVDA — без какой-либо дополнительной настройки.

Apple (iPhone / iPad / Mac) — VoiceOver с Vocalizer

На устройствах Apple движок Vocalizer встроен в операционную систему и поддерживает все языки без дополнительных покупок. Однако по умолчанию установлены компактные версии голосов, которые звучат несколько механически. Чтобы получить значительно лучшее, более естественное звучание, стоит загрузить расширенные или премиум-версии:
- На iPhone/iPad: Настройки → Универсальный доступ → VoiceOver → Речь → Голос → выберите язык (например, Финский) → коснитесь названия голоса (например, Satu) → вы увидите опции "Расширенный" и "Премиум". Загрузите выбранную версию — она занимает больше места на диске, но разница в качестве заметна.
- На Mac: Системные настройки (или Настройки системы) → Универсальный доступ → VoiceOver → Открыть утилиту VoiceOver → Речь → Голос → нажмите "Настроить" рядом с выбранным голосом и загрузите расширенную или премиум-версию.

Android — Vocalizer платный за каждый голос

На Android Vocalizer доступен как приложение в Google Play Store (ищите "Vocalizer TTS"). Внимание: каждый язык и голос приобретаются отдельно — нет единой лицензии на все. Перед покупкой вы можете протестировать голос в течение нескольких минут в демо-режиме. После покупки голос привязывается к аккаунту Google и может быть установлен на любом устройстве с тем же аккаунтом.

Killer Feature для незрячих: Файлы с языковыми тегами

Это настоящая революция. Обработанные файлы теперь сохраняются как:

  • .html с атрибутом lang (например, lang="fi" для финского) — NVDA считывает этот тег и автоматически переключает голос на соответствующий языковой синтезатор. Никакой ручной настройки!
  • .docx с сохранением форматирования — каждый фрагмент текста имеет встроенный языковой тег в XML документа, поэтому Word и NVDA знают, каким голосом читать каждый фрагмент.

Обработанные файлы всегда сохраняются как НОВЫЕ документы (например, акцент_Finski.html).

Автоматическое переключение языка в NVDA — что нужно знать

Чтобы NVDA действительно переключало голос на основе тега lang, должно быть включено настройка "Автоматически менять язык, если поддерживается". Вы найдете его в Настройках NVDA → Речь. По умолчанию оно включено при первом запуске программы — но стоит проверить, не было ли оно отключено.

Важное ограничение голосов OneCore: Голоса Microsoft OneCore изначально не поддерживают этот механизм с NVDA, а только с встроенным в Windows экранным диктором. Существует неофициальное дополнение к NVDA под названием «One Core Autolang», которое пытается это исправить — но его разработка была быстро прекращена. Причина проста: каждый год, с первой версией NVDA в данном году, появляются изменения, нарушающие совместимость API (так называемые API Breaking Changes). Иногда достаточно обновить поле «last tested version» в манифесте дополнения, но иногда требуются реальные изменения в коде — а автор не успевает с обновлениями. Если вам важно автоматическое переключение языка, более безопасным выбором будут Tiflotecnia Voices (платные, раздел выше) или eSpeak (бесплатные, более низкое качество), которые поддерживают этот механизм изначально — но внимание: в Tiflotecnia Voices это работает с ошибкой приоритетов (см. «Критический крючок» ниже). После применения патча автоматическое переключение работает образцово, как в старом Vocalizer.

Критическая проблема Tiflotecnia Voices: неисправная детекция языка

Сначала хорошие новости — тревога о NVDA 2026.1 из предыдущих версий руководства закончилась хэппи-эндом: Cerrence предоставил 64-битные библиотеки, Tiflotecnia выпустила их в пакете .nvda-addon, доступном в Add-on Store (см. раздел выше), и Vocalizer у тех, кто его сохранил до конца, вернулся под новым именем — с лучшим качеством и без 32-битных ограничений.

Однако с выпуском Tiflotecnia Voices появилась новая критическая проблема — в детекции языка. В настройках дополнения можно настроить, какой голос должен использоваться для определенных букв (например, латинских, кириллических) в зависимости от установленных голосов. Проблема заключается в порядке приоритетов: в настоящее время сначала применяется переопределение по букве, затем резервный вариант до ISO-кода языка (на практике недостижимый для ТОГО ЖЕ алфавита, к которому уже применилось переопределение), и в конце выбранный голос. Это приводит к проблемам в пределах одного и того же алфавита: у вас есть текст на финском с правильным тегом lang="fi", установлен Satu как финский голос Tiflotecnia, НО в настройках установлен польский голос для латинских букв — Satu НЕ прочитает этот текст, несмотря на правильный ISO-тег. Переопределение по букве «польский голос для латиницы» выигрывает на первом уровне, ISO fi никогда не проверяется. Для пар с разными алфавитами механизм работает правильно (русский текст + Milena для кириллицы + польский голос для латиницы — вся кириллица идет Milena, возможные латинские собственные имена польским голосом; каждый алфавит сидит в своем переопределении). После миграции с Vocalizer, в котором переключение языка на основе ISO работало безупречно, пользователи заметят это ухудшение сразу — особенно те, кто в Полиглоте использует несколько европейских акцентов (Satu, Alice, Markus) на той же латинской пуле букв.

Диагностика и патч: я диагностировал проблему на уровне Python в коде дополнения и подготовил патч, изменяющий порядок приоритетов на: ISO → выбранный голос → переопределение по букве. Патч сохраняет полезное переключение на латиницу для латинских имен в русском тексте, когда в настройках включено «обнаружение языка на основе символов Unicode». Я отправил патч разработчикам Tiflotecnia — пока без ответа, так что, скорее всего, они придерживаются своего решения. Если дополнение получит обновление, я обновлю патч при необходимости.

Что делать в это время: если вам важно правильное обнаружение языка (стоит — это была одна из ключевых особенностей старого Vocalizer, см. «Ключевая особенность для незрячих» выше), откройте issue в репозитории приложения на GitHub с меткой tiflotecnia-patch и адресом электронной почты в тексте. Стоит добавить краткое описание проблемы на своем языке (достаточно 2–3 предложений) — бот определит язык (поддерживаются: польский, английский, немецкий, испанский, финский, французский, исландский, итальянский, русский) и ответит на том же; без описания или на другом языке ответ придет на английском. Автоматический бот сразу закроет issue с подтверждением отправки (без следа в публичной ветке), а патч вы получите по электронной почте обычно в течение нескольких дней. Сам патч НЕ публикуется в репозитории приложения или как Gist — Tiflotecnia Voices for NVDA является коммерческим программным обеспечением, а лицензия дополнения не разрешает перераспределение его файлов, даже модифицированных. После получения патча его содержимое нужно скопировать в %appdata%\Roaming\nvda\addons\TiflotecniaVoices, заменяя файлы. Внимание при копировании: если Windows не спросил о замене, скорее всего, вы скопировали всю папку TiflotecniaVoices_edits с ее содержимым ВМЕСТО самого содержимого — в таком случае войдите в созданную подпапку, вырежьте все, вставьте уровнем выше и перезапишите. После успешного применения патча перезапустите NVDA — наслаждайтесь лучшим качеством голосов Cerrence 64-бит и правильным обнаружением языка, то есть комбо, недоступным ни от одного производителя на рынке. Предполагается, конечно, что у вас есть действующая лицензия Tiflotecnia Voices — мы это не проверяем, но патч без лицензии все равно не примените на чужую папку.

ШАГ 6: Архитектор Аудиокниг

Инструмент для подготовки профессиональной структуры файла для экранных читалок и ElevenLabs. Перейдите к нему, нажав кнопку "📄 Конвертер" на панели кнопок или выбрав Инструменты → Конвертер в меню (сочетание клавиш: Ctrl+3).

Как это работает?

  1. Введите путь к исходному файлу в текстовом поле или нажмите кнопку "Обзор...", чтобы выбрать файл в системном диалоговом окне. Скрипт принимает как .txt, так и .docx, а также файлы .html и .htm.
  2. Нажмите "Создать Архитектуру для ElevenLabs".
  3. Скрипт просканирует каждую строку текста и преобразует ключевые слова (Акт, Глава, Пролог, Эпилог, Вступление) в заголовки "Heading 1" в документе Word.
  4. Сцены (строки, начинающиеся со слова "Сцена") превращаются в жирный текст — видимый в документе, но не отображаемый в оглавлении ElevenLabs.
  5. Весь остальной текст (диалоги, описания) проходит без изменений.
  6. Вы получите файл архитектура_[nazwa_oryginału].docx — профессиональный документ Word, готовый к дальнейшей работе. Например, если ваш входной файл назывался znieczulica.txt, итоговый файл будет называться архитектура_znieczulica.docx и появится в той же папке, что и оригинал.

Очистка попутно: Скрипт автоматически удаляет HTML-теги (если текст получен из браузера или из локального файла .html, например сгенерированного Полиглотом) и маркеры заголовков Markdown (например, ### или ####) перед обработкой. Вам не нужно вручную очищать файл.

Режим Историй: автоматическая группировка ходов в сцены (начиная с v15.1)

Если вы загрузите в Архитектор файл opowiesci/<gra>.txt, сгенерированный модулем Интерактивных Историй, конвертер распознает маркеры хода (например, «--- Tura 7 ---» — а также аналогичные на других поддерживаемых языках, если вы играли на другом языке) и каждые пять ходов вставит новый заголовок первого уровня «Сцена N» (нумерация начинается с 1, на языке вашей игры). Остальные маркеры ходов удаляются — они не появляются в нарративе аудиокниги, поскольку «Tura 7», произнесенное TTS, разрушает погружение слушателя. Результатом является файл Word с естественным делением на сцены по несколько минут аудио каждая, готовый к импорту в ElevenLabs. Механизм работает автоматически — обычные файлы аудиокниг без маркеров ходов (классическая нарративная работа из Режиссера) обрабатываются точно так же, как прежде.

Весомое преимущество для пользователей NVDA и ElevenLabs

Форматирование "Heading 1" для глав — это не только эстетика. В NVDA можно молниеносно перемещаться по заголовкам, нажимая клавишу H (или 1 для заголовков первого уровня). Вместо того чтобы прокручивать сотни страниц, вы перепрыгиваете от главы к главе за долю секунды. Это меняет подход к работе с длинными документами. В ElevenLabs вы можете быть уверены, что движок автоматически вставит разрывы и не зависнет при режиссировании аудиоклипов.

ШАГ 7: Как писать Книгу Мира (Промпт Архитектора и Мини-курс Markdown)

Искусственный интеллект, питающий Главную Студию, лучше всего понимает команды, отформатированные на языке разметки Markdown. Если вы дадите ИИ в Режиссере лишь расплывчатую идею (например, «две сестры в загробном мире»), машина запаникует от недостатка деталей и создаст банальную, предсказуемую историю, игнорируя логику.

Чтобы этого избежать, используйте внешний чат-бот (например, бесплатный ChatGPT или Claude) в качестве своего личного Архитектора. В версии 13.0 вам больше не нужно переписывать промпт из инструкции — в панели Режиссера, прямо под кнопкой «💾 Сохранить Книгу навсегда», вы найдете кнопку «📖 Подсказка Архитектора для AI…». Нажмите ее, и откроется диалоговое окно с готовым текстом промпта в поле «только для чтения» и кнопкой «Скопировать в буфер обмена». NVDA зачитывает все содержимое сразу после открытия окна — достаточно нажать «Скопировать», вставить (Ctrl+V) в ChatGPT/Claude и заменить фрагмент «[ЗДЕСЬ ВВЕДИТЕ СВОЮ ИДЕЮ]» собственным зерном сюжета.

Почему именно так, а не через копирование из инструкции? Диалог в GUI обладает ключевым преимуществом доступности: он нативный и читается без помех программой экранного доступа, не требует переключения в текстовый редактор (где польские «хвостики» и кавычки порой копируются неверно) и работает одинаково на любой операционной системе. Тот же шаблон — диалог с промптом для копирования — используется и в Менеджере Правил (см. ШАГ 7b ниже).

Как отвечает ИИ: В ответе вы получите текст в двух частях. Первая — это Книга Мира, заключенная в блок кода Markdown (маркеры markdown …). Скопируйте ТОЛЬКО содержимое блока кода (без самих маркеров ```) и вставьте в поле «Книга Мира» в Режиссере, затем нажмите «💾 Сохранить Книгу навсегда». Вторая часть — рекомендация, какой из творческих режимов (Скрипт или Аудиокнига) лучше всего подходит к вашей идее — воспринимайте ее как подсказку при выборе режима в поле выбора режима.

Мини-курс Markdown в Книге: одиночный хэштег (#) — это главный раздел (например, «# Персонажи»), двойной хэштег (##) — подраздел, дефисы (-) создают списки, а двойные звездочки (текст) выделяют жирным абсолютные, незыблемые правила (например, «Герой НИКОГДА не лжет»). Для иноязычного персонажа добавляйте тег с акцентом, например: «[Speaker 1: Marek] - имеет французский акцент». Ключевое слово «akcent» ОБЯЗАТЕЛЬНО — движок приложения обнаруживает его автоматически и применяет правильные фонетические правила к диалогам данного персонажа.

Совет: Не забывайте время от времени (по мере расширения сюжета новыми локациями или важными персонажами) обновлять свою Книгу Мира. Это можно делать вручную или с помощью внешнего чат-бота. Чем богаче фундамент, тем лучше результаты в Режиссуре!

ШАГ 7b: Менеджер Правил (Ctrl+4) — словари для лингвистов без Python

Версия 13.0 вводит четвертый инструмент на панели: Менеджер Правил. Вы открываете его клавишей Ctrl+4 или из меню Инструменты. Это визуальный проводник по папке dictionaries/, в которой приложение хранит все фонетические правила (акценты), шифры и режимы Режиссера в файлах YAML (формат, читаемый человеком, проще чем JSON).

Зачем нужен YAML? До версии 12.0 все акценты, творческие режимы и фильтры были «зашиты» в коде Python. Добавление нового акцента требовало программиста. В версии 13.0 все это переместилось в файлы .yaml в папке dictionaries/ — каждый, кто умеет открыть Блокнот, может настроить существующий акцент («заменить sz на sh на sch») или добавить совершенно новый (шведский, датский, польский диалект).

Что вы найдете в Менеджере Правил:
- Дерево файлов — полный список всех файлов YAML в dictionaries/ с разделением на исходные языки (в настоящее время полностью внедрены: Polski, Deutsch, English, Español, Suomi, Français, Íslenska, Italiano, Русский) и пять категорий (akcenty/, szyfry/, rezyser/, opowiesci/, gui/). Навигация стрелками как в Проводнике Windows, полная поддержка NVDA.
- Кнопка «📝 Открыть в текстовом редакторе» — открывает выбранный файл в системном Блокноте по умолчанию. Редактируете, сохраняете, нажимаете «🔄 Обновить дерево» и готово.
- Кнопка «📋 Дублировать выбранный файл» — самый быстрый путь к новому акценту: берете существующий файл (например, finski.yaml), задаете новое имя (например, шведский), Менеджер создает копию с комментарием «измените поля метка и описание» и открывает ее в редакторе.
- Кнопка «➕ Новый файл правил…» — мастер с выбором типа (акцент, шифр, режим Режиссера, новый исходный язык, алгоритмический шифр). Для обычных случаев (акцент, шифр типа «замена букв») мастер создает готовый для редактирования шаблон YAML. Для случаев, требующих программиста (новый исходный язык, алгоритм типа «перемешивание середины слов») мастер генерирует запрос для чат-бота AI — вставляете в ChatGPT, получаете готовый файл YAML, сохраняете в dictionaries/ и готово.

Практическое применение: Хотите добавить шведский акцент? Откройте Менеджер Правил, выберите dictionaries/pl/akcenty/finski.yaml, нажмите «Дублировать», назовите файл шведский, измените в нем поле метка на "Шведский (Alva / Oskar)", код iso на sv, измените несколько правил замены и сохраните. Вернитесь на Главную страницу и перезапустите приложение. Новый акцент появится в меню Полиглоты (в Режиме Режиссера) и — если добавите его в Книгу Мира персонажей («[Марк] - имеет шведский акцент») — также в автоматическом обнаружении акцентов Режиссера.

Где искать дальнейшую документацию папки dictionaries/:
- Файл docs/dictionaries.pl.html (доступен в пакете для конечных пользователей с вкладки Releases) — краткое, простым языком описание каждой подпапки, 6 готовых шифров, 8 готовых акцентов и идеи, что можно сделать самостоятельно, без знания Python.
- Файл dictionaries/README.md (доступен только при клонировании репозитория с GitHub — выпускные пакеты фильтруют файлы .md) — подробная техническая документация формата YAML с примерами, списками полей, правилами pipeline, regex-ами. Этот документ адресован лингвистам, знающим основы программирования, а также разработчикам.

Важные указания для пользователей экранных чтецов (NVDA)

1. Сообщения об успехе и ошибках

Когда приложение завершает выполнение (например, сохраняет файл или сталкивается с ошибкой), появляется диалоговое окно с заголовком, таким как "Успех", "Предупреждение" или "Ошибка". NVDA сразу объявляет это окно и читает его содержимое. Вам не нужно ничего делать — диалоги полностью доступны с клавиатуры, а фокус автоматически устанавливается на кнопку "OK". Больше нет трюков с префиксом "Alert" — нативные диалоговые окна wxPython поддерживаются напрямую чтецом.

2. Важное предупреждение: тихая обработка в фоновом режиме

После нажатия кнопок, таких как "Отправить в AI" или "Запустить обработку", программа сразу начинает обработку в фоновом режиме. На экране появляется индикатор прогресса (Gauge), но NVDA НЕ читает его значение в реальном времени — экранный чтец молчит во время работы. Не нажимайте кнопку повторно. Подождите, пока не появится диалоговое окно с результатом или сообщением об ошибке — NVDA объявит их автоматически.

3. Навигация между инструментами

Перемещение между инструментами (Режиссер, Полиглот, Конвертер, Менеджер Правил) осуществляется в одном окне программы с помощью четырех кнопок на панели инструментов или через меню Инструменты (Alt, затем N). Доступные горячие клавиши: Ctrl+0 (Главная страница), Ctrl+1 (Режиссер), Ctrl+2 (Полиглот), Ctrl+3 (Конвертер), Ctrl+4 (Менеджер Правил — новинка в 13.0). После переключения инструмента фокус автоматически устанавливается на описание нового модуля — NVDA сразу начинает читать новый вид.

4. Порядок табуляции и названия виджетов

Каждый элемент интерфейса имеет понятное польское название — NVDA прочитает его при фокусировке. Порядок табуляции логичен: от описания инструмента, через конфигурационные поля, до кнопок действий. Здесь нет сюрпризов — навигация с клавиатуры работает так же, как и в любой другой нативной программе Windows. Все меню и кнопки на польском языке, и NVDA прочитает их польским голосом без каких-либо дополнительных настроек.

Важные замечания к версии 9.0 / Changelog

Новые функции и изменения в версии 9

Устойчивое к сбоям сохранение прогресса перевода (ИЗМЕНЕНИЕ — исправление критической ошибки)
В версии 8 возобновление прерванного перевода было связано с тихой, разрушительной ловушкой: если пользователь следовал инструкциям (вручную вырезал переведенный фрагмент), а затем сразу же возобновлял перевод остального, приложение открывало выходной файл в режиме перезаписи — безвозвратно и неосознанно удаляя весь оплаченный прогресс. В версии 9 весь механизм был перепроектирован. Каждый переведенный блок теперь немедленно сохраняется в временный файл (.jsonl) с присвоенным индексом. Возобновление полностью автоматическое — приложение само обнаруживает файл и восстанавливает прогресс без какого-либо вмешательства пользователя. После успешного завершения временный файл автоматически удаляется.

Исправитель Тегов в Режиме Режиссера (НОВИНКА)
В меню Режима Режиссера добавлена новая опция — Исправитель Тегов. Вставляет в файл только указанный пользователем двухбуквенный код языка ISO, без применения каких-либо фонетических правил или очистки. Спасательный инструмент на случай, если готовый файл вышел с неправильным или отсутствующим языковым тегом.

Автоматическая конвертация .txt в .html в Режиме Переводчика (ИЗМЕНЕНИЕ)
Текстовые файлы (.txt и .md), переводимые Переводчиком AI, теперь автоматически сохраняются в формате .html с встроенным языковым тегом. Благодаря этому NVDA сразу читает файл правильным голосом — без каких-либо дополнительных шагов со стороны пользователя.

Интеллектуальное именование файла в Архитекторе (ИЗМЕНЕНИЕ)
Архитектор Аудиокниг больше не сохраняет итоговый файл всегда под одним и тем же именем архитектура_gotowa.docx. Теперь имя зависит от входного файла — например, для znieczulica.txt итоговый файл будет архитектура_znieczulica.docx. Файл появляется в той же папке, что и оригинал.

Функции, сохраненные без изменений с версии 8

Возврат к формату .txt для файлов проектов (ИЗМЕНЕНИЕ)
Файлы проектов и резюме теперь сохраняются в формате .txt вместо .md (Markdown). Эксперимент с форматом .md как психологическим барьером против редактирования оказался неэффективным — AI часто нарушает принцип anti-closure и часто лучше редактировать файл на ходу и затем перезагружать память, чтобы AI, по возможности, не получало скрытого разрешения на нарушение запрета. Формат .txt более интуитивен и читаем для каждого.

Принцип Монтажера — новое предупреждение
В инструкции (и в будущих версиях интерфейса) добавлено явное предупреждение, объясняющее, что можно, а что нельзя редактировать в файлах проектов. Пользователь имеет полное право редактировать диалоги и содержание, но абсолютно не может изменять линии структуры (Акт, Сцена, Глава, Пролог, Эпилог) — их повреждение портит навигацию NVDA, разделение в ElevenLabs и оглавление в Word.

Обновленный Промпт Архитектора (ИЗМЕНЕНИЕ)
Промпт к внешнему чат-боту (ChatGPT/Claude) был перепроектирован. Вместо возврата сырого кода Markdown, AI теперь возвращает ответ в двух четко разделенных частях: Часть 1 — это Книга Мира, заключенная в блок кода Markdown (легко копируется без меток), а Часть 2 — это Рекомендация Режима как обычный текст вне блока — советует, лучше ли использовать Режим Сырого Сценария или Режим Традиционной Аудиокниги. Также изменено описание тегов персонажей: вместо "звуковых" теперь речь идет об акценте и тоне голоса в теге, например, [Speaker 1: Имя] — шепелявит и акцент французский.

Объяснение состояния директивы Anti-Closure (ДОКУМЕНТАЦИЯ)
Инструкция теперь содержит честное объяснение, что несмотря на встроенные запреты Anti-Closure, модель все еще часто нарушает этот принцип, особенно в Режиме Аудиокниги. Вместо того чтобы скрывать эту проблему, версия 8 ставит вопрос ребром и передает ответственность за "ручное закрытие" обратно Режиссеру — отсюда Принцип Монтажера как официальное рабочее средство и возврат к обычному текстовому формату.

Функции, сохраненные без изменений с версии 7

Промпты Шоураннера — Директива Anti-Closure (Режиссура — все режимы)
Все три режима Режиссуры сохраняют встроенные директивы шоураннера. Мозговой Штурм действует как сценарист многосезонного сериала. Режим Сырого Сценария и Режим Аудиокниги имеют запрет на завершение текста резюме, моралями и нарративными рамками — за исключением случаев, когда пользователь прямо просит о финале или эпилоге.

Управление Актами и Сценами в реальном времени (Режиссура — Режим Сценария)
Режим Сырого Сценария имеет панель с кнопками "Вставить Акт X" и "Вставить Сцену X". Счетчики обновляются автоматически. Загрузка существующего файла устанавливает оба счетчика на правильные номера.

Очистка скобочных ремарок режиссера (Полиглот — Режим Режиссера)
Скрипт удаляет все фрагменты текста, заключенные в круглые скобки (например, "(шепотом)", "(с вплетенными вдохами)"). ElevenLabs читает только диалоги и наррацию.

Бесконечная Память и Автоматическое Резюмирование (Режиссура — Аккумулятор Сюжета)
Когда индикатор памяти входит в состояние красной тревоги, Мозговой Штурм автоматически генерирует резюме сюжета и сохраняет его в поле Долговременной Памяти. Нажатие "Сохранить Резюме (на постоянной основе)" создает файл _streszczenie.txt. После очистки памяти и загрузки резюме можно продолжать историю без каких-либо ограничений по длине.

Архитектор Аудиокниг
Инструмент поддерживает ключевые слова Акт, Глава, Пролог, Эпилог и Вступление как заголовки первого уровня. Сцены превращаются в жирный текст. Скрипт автоматически очищает HTML-теги и метки Markdown перед обработкой.

Интеллектуальное Управление Главами (Режим Аудиокниги)
Специальная панель с кнопками для вставки Пролога, Эпилогов и разрезов глав непосредственно из интерфейса. Счетчик глав обновляется автоматически. Загрузка существующего файла устанавливает счетчик на правильный номер без ручного подсчета.

Присвоение Названий Главам (Постобработка — Режим Аудиокниги)
Модуль проходит по главам из сохраненного файла и присваивает им короткое, литературное название с использованием быстрого AI-модели, анализируя только начала каждой главы.

ШАГ 7b (дополнение): Порядок правил zamiany: имеет значение

Файлы в dictionaries/<kod>/akcenty/*.yaml содержат список правил zamiany: — пар шаблон → замена, которые движок применяет ПОСЛЕДОВАТЕЛЬНО. Каждое последующее правило работает на выходе предыдущего. Это позволяет строить конвейеры типа «разложить двузнак szcz на shch, а затем заменить ch на h», но также открывает классическую ловушку для автора языкового пакета.

Ловушка «циклической последовательности». Предположим, что для испанского акцента, чтобы польское «ñ» звучало как произношение Диего (Loquendo), автор добавляет два правила:
1. ñ → nj (чтобы польское «ñ» звучало как мягкое «nj»)
2. j → x (чтобы польское «j» звучало как испанское «j» — фонетически /x/)

После запуска оказывается, что слова с «ñ» произносятся как «nx», а не «nj». Почему? Потому что когда первое правило заменяет «ñ» на «nj», новая «j» сразу же захватывается вторым правилом и заменяется на «x». Результат: вместо задуманного «ñ → nj», получаем «ñ → nx».

Правило порядка (универсальное). Когда одно правило вводит символ, который другое правило использует как шаблон, ПОРЯДОК ИМЕЕТ ЗНАЧЕНИЕ. Безопасная эвристика: СНАЧАЛА замените ЦЕЛЬ (символ, используемый позже как шаблон в другом правиле) на что-то безопасное, ТОЛЬКО ПОТОМ вводите ИСТОЧНИК (символ, который должен разложиться на ЦЕЛЬ). Для испанского примера правильно: сначала j → x, потом ñ → nj. Результат: «ñ» дает «nj» (второе «j» больше не будет съедено, потому что правило j → x было применено раньше, когда «nj» еще не существовало).

Как тестировать. После изменения порядка правил в файле акцента пропустите предложение, содержащее ОБЕ буквы, через Режим Режиссера. Для примера ES: «Niño de paja juega» → результат должен иметь и акцент ñ («ñ → nj»), и акцент j («j → x»), то есть что-то вроде «Ninjo de paxa xuega». Если вы видите «ninxo» вместо «ninjo» — порядок обратный.

Валидация в движке (opt-in для авторов пакетов). Приложение имеет встроенную эвристику для обнаружения потенциальных циклов, но она по умолчанию отключена — потому что многие конвейеры выглядят как цикл, хотя они целенаправленные (классический «szcz → shch» + «ch → h»). Чтобы ее включить: установите переменную окружения REZYSER_VALIDATE_ZAMIANY=1 и запустите приложение из консоли — из исходника через python main.py, так как замороженный .exe в оконном режиме (с версии 17.0) не имеет консольного окна. Движок выведет для каждого файла акцентов одну агрегированную строку WARN с первыми тремя потенциальными циклами и числом оставшихся. Проверьте результирующую фонетику на тестовом предложении — если эффект задуман, игнорируйте WARN.

Кнопки перемещения правил в GUI Менеджера Правил (drag-and-drop, «Вверх / Вниз») — это отдельная функция, запланированная на более поздний цикл версии — требует перепроектирования Менеджера (в настоящее время делегирует редактирование файла внешнему системному Блокноту, а собственного вида правил не имеет). До ее внедрения: редактируйте файл YAML вручную, перемещайте строки в секции zamiany:, используйте валидатор с ENV-переменной и тестируйте на контрольных предложениях.

ШАГ 2B (расширенный, необязательный): Собственный провайдер AI, совместимый с OpenAI

Большинству пользователей рекомендуется остаться на Anthropic (ШАГ 2) — он обеспечивает наивысшее качество. Однако если у вас есть собственная причина (стоимость, доступ, конфиденциальность, собственная локальная модель), начиная с версии 18.4 вы можете указать ЛЮБОЙ endpoint, совместимый с API OpenAI — например OpenRouter, Groq, Fireworks, DeepSeek, локальный Ollama или OpenAI-compatible endpoint Gemini. Весь движок AI тогда идет по единому пути к этому endpoint, без отдельной интеграции на каждого провайдера.

Это опция для продвинутых пользователей: вы настраиваете ее вручную в файле golden_key.env, дописывая рядом (или вместо) ключа Anthropic три строки и ключ выбранного провайдера:

LLM_PROVIDER=openai_compat
LLM_BASE_URL=адрес_endpoint (например https://openrouter.ai/api/v1)
LLM_MODEL=название_модели_у_провайдера (например openai/gpt-4o-mini)
OPENAI_API_KEY=ваш_ключ_у_этого_провайдера

Как это работает:
• Когда LLM_PROVIDER=openai_compat, ВЕСЬ движок AI (Режиссер, Истории, Полиглот, заголовки, определение языка) использует указанный endpoint, а название модели из конфигурационных файлов переопределяется параметром LLM_MODEL.
• Когда строка LLM_PROVIDER отсутствует (или имеет значение anthropic), приложение работает как в ШАГ 2 — исключительно на ключе Anthropic. Ничего менять не нужно.

Важно (качество): системные промпты приложения написаны и настроены под Claude. Другая модель может давать более низкое качество — хуже соблюдать правила мира, терять структуру JSON в режимах с выборами или возвращать текст на неправильном языке. Это осознанный компромисс между стоимостью и качеством на вашей стороне. Если вам важен наилучший результат, оставайтесь на Anthropic.
