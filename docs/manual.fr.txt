Manuel du Réalisateur Audio IA - Guide Complet (Version 13.8.1 – Version de Publication)

Bienvenue dans le Studio d'Enregistrement Hybride ! Cet ensemble d'outils permet l'écriture, la planification, le formatage et la traduction automatiques de scripts pour des pièces radiophoniques et des livres audio. Il a été optimisé pour fonctionner avec des synthétiseurs vocaux professionnels et des moteurs de lecteurs d'écran locaux (NVDA).

L'ensemble se compose du studio principal (Réalisateur), de l'outil de traduction et d'accents (Polyglotte), de l'outil de construction de structure de fichier (Architecte de Livres Audio) et — depuis la version 13.0 — du Gestionnaire de Règles, où vous pouvez ajouter un nouvel accent, un chiffre ou un mode créatif sans Python (voir ÉTAPE 7b ci-dessous). Les quatre outils sont disponibles dans une seule fenêtre de programme, commutable par des boutons sur la barre ou des raccourcis clavier Ctrl+1..Ctrl+4.

ÉTAPE 1 : Première exécution (Cross-Platform)

L'application est entièrement portable et prête à fonctionner sur le système Windows. Il suffit d'entrer dans le dossier et de lancer le fichier run.bat (en double-cliquant dessus ou en créant un raccourci sur le bureau). Une fenêtre de terminal éphémère s'ouvrira (elle disparaît automatiquement), et après un moment, la fenêtre principale du programme apparaîtra — Réalisateur Audio GPT. Pas de navigateur, pas de serveur en arrière-plan. Lorsque vous avez terminé, il suffit de fermer la fenêtre du programme.

Important : Le dossier runtime/ fait partie uniquement des packages prêts pour Windows téléchargés depuis l'onglet Releases sur GitHub. Il contient un environnement Python isolé prêt à l'emploi sans installation. Si vous clonez le dépôt, ce dossier n'est pas présent et ne doit pas l'être — vous utilisez alors un environnement virtuel venv décrit dans la section pour développeurs ci-dessous.

--- Pour les Développeurs (Windows — dépôt Git) ---

1. Clonez le dépôt sur votre disque.
2. Exécutez le fichier setup_dev.bat. Le script créera automatiquement un environnement virtuel Python (venv) et installera toutes les dépendances requises à partir du fichier requirements.txt.
3. Exécutez l'application avec la commande python main.py ou via le fichier run_dev.bat — le script détectera automatiquement le dossier venv et lancera le programme.

--- Pour les Développeurs et les utilisateurs ordinaires (macOS / Linux) ---

1. Clonez le dépôt sur votre disque.
2. Ouvrez un terminal dans le dossier du projet et donnez aux scripts les permissions d'exécution : chmod +x *.sh
3. Exécutez le script de configuration : ./setup_dev.sh — le script créera l'environnement venv et installera les dépendances.
4. Exécutez l'application : python main.py ou ./run.sh

Ce que vous verrez après le lancement : Après avoir lancé le programme, une fenêtre avec un écran de démarrage s'ouvrira. Vous y trouverez une brève description des outils disponibles et une section "Vérification du Système". Si la clé API n'est pas encore configurée, vous verrez un message rouge indiquant que les modules basés sur l'IA (Réalisateur, Traducteur) ne fonctionneront pas — les fonctions locales gratuites (accents, Architecte) sont cependant actives immédiatement. La configuration de la clé est décrite dans l'étape suivante.

Mises à jour automatiques

L'application vérifie au démarrage si une nouvelle version est disponible sur GitHub — la vérification se fait en arrière-plan et ne bloque pas l'interface.

Si vous avez installé le programme via un fichier d'installation prêt (.exe) : en cas de détection d'une nouvelle version, une fenêtre apparaîtra pour vous demander si vous souhaitez la télécharger. Après confirmation, une barre de progression s'affichera, et une fois le téléchargement terminé, l'application se fermera automatiquement et le nouvel installateur se lancera de lui-même — vos projets et votre clé API resteront intacts.

Si vous utilisez le dépôt Git (développeurs et utilisateurs macOS/Linux) : au lieu d'une proposition de téléchargement, vous verrez une information sur la nouvelle version avec un lien direct vers la page de publication sur GitHub. Téléchargez l'archive "Source code" ou mettez à jour le dépôt avec la commande git pull.

ÉTAPE 2 : Alimentation de l'API (Clé OpenAI)

Pour que l'intelligence artificielle fonctionne, elle a besoin d'accéder aux serveurs OpenAI (créateurs de ChatGPT).

1. Créez un compte sur platform.openai.com et rechargez votre compte dans l'onglet Billing.
2. Générez une clé dans l'onglet API Keys (elle commence par sk-proj-). Attention : la clé n'est affichée qu'une seule fois — au moment de sa création. Si vous fermez la fenêtre sans la copier, elle est perdue à jamais et vous devrez la révoquer (option revoke secret key) et en générer une nouvelle. Copiez-la immédiatement, avant de cliquer sur quoi que ce soit.
3. Sur l'écran de démarrage du programme, cliquez sur le bouton "Générer le fichier golden_key.env et ouvrir l'éditeur de texte". Le système créera automatiquement un fichier de configuration vierge au bon endroit et ouvrira le Bloc-notes avec un modèle prêt à être édité.
4. Dans le fichier ouvert, vous verrez la ligne OPENAI_API_KEY=COLLEZ_VOTRE_CLÉ_ICI. Supprimez le texte de remplacement et collez votre clé copiée directement après le signe égal (sans espace). Enregistrez le fichier et relancez l'application.

Astuce : Après avoir relancé l'application, celle-ci vérifiera le fichier et affichera un message vert dans la section "Vérification du Système" — cela signifie que tous les modules IA sont prêts à fonctionner. Sinon, elle vous dira clairement ce qui ne va pas et vous permettra d'ouvrir l'éditeur de texte pour corriger rapidement l'erreur.

ÉTAPE 3 : Studio Principal de Réalisation

C'est votre centre de commande pour inventer des histoires et écrire des scénarios. Accédez-y en cliquant sur le bouton "🎬  Réalisateur" sur la barre de boutons ou en sélectionnant Outils → Réalisateur dans le menu (raccourci : Ctrl+1).

IMPORTANT : Format des fichiers de projet — retour au .txt

Dans la version 7, les fichiers de projet étaient enregistrés au format Markdown (.md), par exemple scripts/indifférence.md. C'était une expérience délibérée — le format .md devait constituer une barrière psychologique pour les personnes non techniques, les décourageant d'ouvrir et de modifier manuellement le fichier dans le Bloc-notes (et donc d'endommager accidentellement les en-têtes de structure).

L'expérience n'a pas fonctionné. L'IA enfreint souvent l'une des interdictions fondamentales (plus à ce sujet dans un instant). Pour cette raison, dans la version 8, nous sommes revenus à de simples fichiers .txt — plus intuitifs et lisibles pour tout le monde. Par exemple, un projet nommé "indifférence" sera désormais enregistré sous le nom scripts/indifférence.txt, et son résumé sous le nom scripts/indifférence_résumé.txt. Cela permettra à chacun d'apporter plus facilement des corrections ou des coupures de texte en temps réel.

⚠️ RÈGLE CRITIQUE DU MONTEUR (LISEZ AVANT DE COMMENCER !) ⚠️

Tous vos scripts et livres générés sont enregistrés dans des fichiers texte ordinaires (.txt), que vous pouvez facilement ouvrir dans le Bloc-notes.

En tant que Réalisateur, vous avez TOUT À FAIT LE DROIT (et même le devoir) de modifier ce fichier ! Si l'intelligence artificielle s'emballe et, par exemple, résout elle-même le problème des personnages à la fin d'un fragment généré, ouvrez le fichier, supprimez les dernières lignes et laissez le texte interrompu au moment le plus tendu, avant de vider la mémoire, de recharger le fichier pour recharger la fenêtre contextuelle et de cliquer sur "Envoyer à l'IA" pour continuer.

🔴 CEPENDANT - CE QUE VOUS NE DEVEZ PAS TOUCHER :

Ne modifiez jamais, ne supprimez jamais et ne changez jamais les lignes contenant la structure (par exemple, Acte 1, Scène 2, Chapitre 1, Prologue). Si vous endommagez ces en-têtes :
1. Votre histoire s'effondrera dans les lecteurs d'écran (NVDA).
2. L'Architecte de livres audio, et donc également le Studio Eleven Labs, ne pourra pas diviser correctement votre livre en fragments à lire.
3. Le Convertisseur interne de l'application ne générera pas un sommaire correct dans le fichier Word ni sur la chronologie dans ElevenLabs.

Éditez les dialogues, coupez l'action, mais laissez la structure tranquille !

Comment utiliser la Réalisation ?

- Livre du Monde (barre latérale à gauche) : Ici, vous entrez les règles de l'univers. Chaque projet a maintenant son propre Livre lié au nom du fichier — si votre fichier d'histoire est par exemple emilia_heist_audiobook.txt, le Livre du Monde sera enregistré sous le nom scripts/emilia_heist_audiobook.md. C'est pourquoi l'ordre est important : entrez d'abord le nom du fichier de projet dans le champ "Nom du fichier de projet", puis vous pouvez enregistrer le Livre. Le bouton "💾 Sauvegarder la Bible de manière permanente" reste grisé tant que vous n'avez pas fourni de nom. Charger un projet existant avec le bouton "Charger l'histoire" chargera automatiquement le fichier .md correspondant — vous n'avez rien à faire manuellement. Attention : Sans Livre du Monde rempli, l'application bloquera l'envoi de requêtes à l'IA — c'est une protection délibérée qui vous protège de la génération de texte sans règles.
- Mémoire à Long Terme (barre latérale à gauche) : Le deuxième champ de la barre latérale. Ici, l'IA enregistre automatiquement le résumé de l'intrigue lorsque la mémoire commence à se remplir. Vous pouvez également y entrer vos propres notes manuellement — le modèle les traitera comme "ce que je sais déjà" avant de lire la scène actuelle.
- Mode Brainstorming : Entrez une idée libre, et l'IA vous donnera 3 options de développement de l'intrigue. Pour chaque option, elle générera immédiatement un bloc "--- ÉBAUCHE DE PROMPT ---". Après avoir choisi l'une d'elles, collez ce prompt dans le Mode Script ou Audiobook et ajoutez des remarques ou des informations pour le modèle. La mémoire de l'intrigue ne change pas pendant le Brainstorming — vous pouvez expérimenter sans risque !
- Mode Script Brut : Collez ici "Ébauche de Prompt" générée dans le Brainstorming. L'IA écrira un long fragment avec des balises complètes [Speaker X: Nom - émotion] pour les dialogues et des effets [SFX: ...] pour les sons. Le texte est automatiquement ajouté à votre fichier (par exemple, nouvelle_scène.txt) dans le dossier scripts/.
- Mode Audiobook Traditionnel : Mode pour les écrivains. L'IA génère une prose littéraire pure — zéro balise, zéro phonétique, dialogues classiques intégrés dans la narration. Le texte est ajouté au fichier de la même manière que dans le Mode Script.
- Création automatique de personnages : Le script est programmé pour créer automatiquement de nouvelles balises [Speaker] si l'intrigue nécessite un nouveau personnage. Astuce : Si l'IA crée un personnage intéressant, copiez sa balise et collez-la dans le Livre du Monde pour que le modèle s'en souvienne de façon permanente !

Gestion du projet — trois boutons d'action :
- Charger l'histoire : Charge un fichier de projet existant en mémoire. Disponible uniquement lorsque la mémoire est vide et qu'un nom de fichier est saisi.

- Effacer l'actuel (garder le Résumé) : Efface uniquement l'histoire actuelle. Le Résumé dans la Mémoire à Long Terme et le Livre du Monde sont conservés — idéal pour continuer un long livre après avoir généré un résumé.
- Fermer le Projet (Réinitialisation Complète) : Efface complètement le projet. Supprime l'histoire, le résumé, le Livre du Monde et réinitialise tous les compteurs. À utiliser lors du changement de projet ou d'une nouvelle histoire.

Note historique — pourquoi les modes sont maintenant protégés contre les changements accidentels :
Dans les versions antérieures de l'application, personne ne surveillait la cohérence du mode créatif au sein d'un même projet. Le résultat était une certaine possibilité créative subtile, que l'on pourrait décrire ainsi : vous commencez une histoire en Mode Script, insérez "Acte 1" et "Scène 1" (l'application est ravie de votre cohérence), générez quelques scènes de tension avec des balises [SFX: Claquement de porte] et [Speaker 1: Marek - résigné]... puis — parce que l'inspiration vient de frapper — vous cliquez sur "Insérer une coupure Chapitre 1". L'application, sans sourciller, ajoute l'en-tête "Chapitre 1" au fichier, juste après "Scène 3". Vous avez maintenant dans le fichier un hybride de pièce radiophonique des années 50 et de roman contemporain. ElevenLabs regarde cette structure, voit un en-tête de chapitre au milieu d'un acte et décide que c'est probablement une erreur dans la matrice. Le sommaire ressemble à une œuvre d'art avant-gardiste. L'Architecte de Livres Audio, quant à lui, part du principe que vous êtes un adulte et traite simplement cela sans mot dire — mais aussi sans aucune garantie de résultat. Depuis la version 12.0, l'interface bloque simplement le changement de mode d'enregistrement lorsqu'une histoire est déjà en mémoire. Le Brainstorming est toujours disponible — vous pouvez y comploter sans restrictions.

Prompts de Showrunner — IA en tant que scénariste de série (depuis la version 7, conservé)

C'est le plus grand changement introduit dans la version 7, conservé tel quel. Il n'est pas visible dans l'interface, mais change radicalement la qualité de l'intrigue générée.

Le Showrunner est, dans l'industrie télévisuelle, la personne responsable de l'ensemble de la série — il veille à ce que l'intrigue ne se dirige jamais vers une solution facile, mais qu'elle s'épaississe constamment, accumule les conflits et maintienne le spectateur en haleine pendant de nombreuses saisons. Dans la version 7, cette philosophie a été intégrée directement dans les instructions système de l'IA.

Directive Anti-Closure — état dans la version 8

Malgré le test de différentes approches, l'interdiction Anti-Closure est souvent notoirement violée par le modèle, en particulier en Mode Audiobook Traditionnel. L'IA a une forte tendance à "fermer" l'histoire à chaque occasion — elle insère des phrases résumant l'intrigue, crée de faux happy ends ou clôt les intrigues au milieu d'un chapitre, comme si chaque fragment était le dernier. L'effet est que le fragment suivant commence à zéro, sans continuité naturelle.

C'est pourquoi la règle du monteur décrite ci-dessus est si importante : si l'IA enfreint l'interdiction et clôt elle-même la scène, votre tâche en tant que Réalisateur est d'ouvrir le fichier .txt, de supprimer ces dernières phrases et de laisser le texte interrompu à un moment tendu avant de le recharger dans l'application.

Chaque mode a une directive Anti-Closure intégrée :

- Brainstorming : L'IA agit comme un scénariste de série multi-saisons. Chacune des 3 options proposées DOIT accumuler des obstacles, introduire de nouveaux dilemmes, des intrigues ouvertes et des cliffhangers. Interdiction absolue de proposer des options où les personnages se réconcilient définitivement, surmontent le principal obstacle sans conséquences majeures ou où l'histoire se dirige vers une fin précipitée. Interdiction d'inventer des lieux magiques bon marché brisant l'architecture du monde.
- Mode Script Brut : Interdiction absolue de terminer le texte par des résumés, des morales ou des conclusions. L'IA doit interrompre l'action naturellement à un moment tendu (cliffhanger), évitant les conclusions, pour que le fragment suivant puisse reprendre la narration en douceur.
- Mode Audiobook Traditionnel : Interdiction absolue de terminer le texte par des résumés pompeux, de clore les intrigues ou de suggérer la fin de l'histoire (par exemple, "Elle était prête pour de nouveaux défis", "Elle comprit qu'il était temps d'aller de l'avant"). Le texte doit s'interrompre au milieu d'une action en cours, d'une tension ou d'une pensée ouverte.

Exception à la règle : Si vous demandez explicitement une conclusion, un final ou un épilogue, l'IA générera une clôture satisfaisante de l'histoire — l'interdiction ne s'applique pas lorsque vous le demandez vous-même.

Gestion des Actes et Scènes (Mode Script, depuis la version 7, conservé)

Le Mode Script Brut dispose d'un panneau dédié "✂️ Gestion de la Structure" avec des boutons pour construire la structure de la pièce radiophonique en temps réel.

- Insérer Acte X : Insère un en-tête d'acte (par exemple, "Acte 2") ET ajoute automatiquement "Scène 1" en dessous — car chaque nouvel acte commence par la première scène. Le compteur d'actes passe au numéro suivant, et le compteur de scènes se réinitialise à 2 (prêt pour la scène suivante dans cet acte).
- Insérer Scène X : Insère uniquement un en-tête de scène (par exemple, "Scène 3") dans l'acte en cours. Le compteur de scènes augmente automatiquement.

Chargement intelligent du fichier : Lorsque vous chargez un fichier de script existant, l'application le scanne automatiquement et règle les compteurs d'actes et de scènes sur les numéros appropriés. Le compteur de scènes est toujours calculé dans le dernier acte du fichier.

Prologue et Épilogue : Les boutons "📜 Insérer le Prologue" et "🏁 Insérer l'Épilogue" sont communs aux deux modes et disponibles dans le même panneau.

L'Architecte de Livres Audio convertira automatiquement les Actes en principaux points de navigation (Heading 1) pour ElevenLabs et NVDA — les Scènes deviendront du texte en gras visible dans le document, mais invisible dans le sommaire.

Gestion Intelligente des Chapitres (Mode Audiobook, depuis la version 5, conservé)

LLM génère un maximum d'environ 5000 caractères par requête — c'est trop peu pour un chapitre complet. C'est pourquoi vous travaillez de manière itérative : vous générez des fragments successifs avec le bouton "Envoyer à l'IA", jusqu'à ce que vous jugiez qu'un chapitre est prêt. Ensuite, vous cliquez sur "Insérer une coupure de chapitre" — l'application ajoute un en-tête au fichier et à la mémoire, et le compteur de chapitres passe automatiquement au numéro suivant.

Boutons dans le panneau :

- Insérer une coupure (Chapitre X) : Insère un en-tête (par exemple, "Chapitre 3") dans le fichier et la mémoire. Le compteur de chapitres se met à jour automatiquement.
- Insérer Prologue : Fonctionne uniquement au début, lorsque la mémoire est vide. Protection contre l'insertion accidentelle d'un Prologue au milieu de l'histoire.
- Insérer Épilogue : Clôt l'histoire. Après avoir inséré un Épilogue avec du contenu, l'application bloquera la génération de nouveaux fragments — c'est intentionnel, car après la fin de l'histoire, il n'y a plus rien à ajouter.

Chargement intelligent du fichier : Lorsque vous chargez un fichier existant, l'application le scanne automatiquement et règle le compteur de chapitres sur le bon numéro. Si le fichier a un Prologue et trois chapitres, le compteur affichera "Chapitre 4" — sans comptage manuel.

Accumulateur d'Intrigue — comment fonctionne la mémoire de l'IA

Seul le texte pur de l'histoire entre dans la mémoire du modèle — ce que l'IA a effectivement écrit. Les instructions, options et plans disparaissent après utilisation et ne polluent pas le contexte. Résultat ? Le modèle reste concentré plus longtemps, se souvient mieux des accents des personnages et s'éloigne moins souvent des règles du Livre du Monde.

L'indicateur "Mémoire du Modèle" à l'écran montre combien d'espace votre histoire occupe déjà :
- Vert (jusqu'à 150 000 caractères) : Le modèle est pleinement concentré, vous avez un tampon sûr.
- Jaune (150 000 – 175 000 caractères) : Vous vous approchez de la limite. L'IA peut commencer à raccourcir les discours et à ignorer les règles. Commencez à clore lentement l'intrigue.
- Rouge (au-dessus de 175 000 caractères) : Surcharge critique !

Mémoire Infinie (depuis la version 6, conservé)

Lorsque l'alarme rouge s'allume, vous n'avez plus besoin de copier manuellement le résumé. Entrez dans le Brainstorming une commande contenant le mot "résumé" ou "synthèse" — l'IA générera une capsule concise de connaissances sur toute l'intrigue jusqu'à présent. Ensuite, cliquez sur le bouton "Enregistrer le Résumé (de manière permanente)" — l'application crée automatiquement un fichier _résumé.txt dans le dossier scripts/ et le protège contre l'écrasement accidentel. Après avoir enregistré, effacez la mémoire et vous pouvez continuer à créer dans le fichier actuel. Vous chargerez le résumé dans le champ de Mémoire à Long Terme avant la prochaine session — et vous pouvez continuer l'histoire indéfiniment, sans aucune limite de longueur. Vous devez seulement vous rappeler que si tout le fichier de l'histoire dépasse 175000 caractères, pour pouvoir interrompre le travail en toute sécurité et y revenir plus tard, vous devez générer et enregistrer un Résumé de l'histoire. L'IA y ajoute maintenant aussi quelques derniers paragraphes de l'histoire au moment de l'écriture du résumé.

Résumé automatique : Lorsque la mémoire entre en état d'alerte, le Brainstorming passe automatiquement en mode de secours — au lieu de générer immédiatement des options, il crée d'abord un résumé détaillé de toute l'intrigue jusqu'à présent et l'enregistre dans des balises <RÉSUMÉ>. L'application détecte ces balises et transfère automatiquement le résumé dans le champ de Mémoire à Long Terme. Zéro travail manuel !

Chargement intelligent avec fichier de résumé : Lorsque vous chargez un projet qui a déjà un fichier de résumé enregistré (par exemple, indifférence_résumé.txt), l'application charge automatiquement le résumé dans la Mémoire à Long Terme et laisse la Mémoire Actuelle vide. Ainsi, vous ne gaspillez pas de jetons à recharger toute l'histoire — le modèle connaît le contexte à partir du résumé et est prêt pour une continuation infinie.

ÉTAPE 4 : Postproduction en Réalisation

Après avoir écrit l'histoire, vous disposez d'un outil de postproduction disponible en bas du panneau de Réalisation (n'apparaît qu'en Mode Audiobook).

Attribution de Titres aux Chapitres (Mode Audiobook)

L'IA analysera toute l'histoire et proposera des titres descriptifs et littéraires pour chaque chapitre (ainsi que pour le Prologue et l'Épilogue éventuels). Le module itère sur les chapitres du fichier enregistré et leur attribue un titre court, en analysant uniquement les débuts de chaque chapitre (jusqu'à 6000 caractères). Il ne retourne qu'une liste numérotée de titres — sans réécrire le contenu du livre.

Remarque : Le module nécessite que le fichier soit déjà enregistré sur le disque (généré ou chargé). Si le fichier n'existe pas, l'application affichera un message approprié.

ÉTAPE 5 : Polyglotte AI

Application pour traduire et imposer des accents forts sur les synthétiseurs des lecteurs d'écran. Accédez-y en cliquant sur le bouton "🌍  Polyglotte" sur la barre de boutons ou en sélectionnant Outils → Polyglotte dans le menu (raccourci : Ctrl+2).

Mode 1 : Traducteur Ordinaire (Utilise l'IA - Payant)

Idéal pour écouter des histoires dans une belle langue étrangère correcte.

- Chargez le fichier avec le bouton "Charger le fichier en mémoire" ou utilisez le bouton "Parcourir..." pour sélectionner un fichier dans la fenêtre système.
- Choisissez le mode "Traducteur AI", entrez la langue cible (par exemple, "Finnois").
- Le script traduira le contenu. Si vous chargez un fichier .html, il traduira uniquement le texte visible pour le lecteur et mettra à jour le code de langue dans la balise html.
- Si vous chargez un fichier .txt ou .md ordinaire (par exemple, un script généré par Réalisation), le script enregistrera automatiquement le résultat traduit en tant que fichier .html avec une balise de langue intégrée — prêt à être lu par NVDA sans travail supplémentaire.
- Prend également en charge les fichiers .docx.

Division intelligente en blocs : Les longs textes sont automatiquement divisés en blocs de 10 000 caractères et traduits séquentiellement avec une barre de progression.

Enregistrement résistant aux pannes (NOUVEAUTÉ dans la version 9) : Chaque bloc traduit est immédiatement enregistré dans un fichier temporaire caché dans le dossier système de l'application. Si la traduction est interrompue en raison de la limite API atteinte, lors du prochain démarrage, l'application détectera automatiquement ce fichier, restaurera le progrès déjà payé et terminera calmement le travail à partir de l'endroit où il a été interrompu — sans aucun copier-coller manuel. Après une fin réussie, le fichier temporaire est automatiquement supprimé.

Pourquoi est-ce important ? Dans la version 8, l'approche de reprise de la traduction avait un bug critique et silencieux : si vous ne renommiez pas le fichier avec la traduction partielle et que vous coupiez le fragment traduit selon les instructions, puis que vous repreniez immédiatement la traduction du reste — l'application ouvrait le fichier de sortie en mode écrasement. Le progrès payé était effacé de manière irréversible et inconsciente avant que vous ne puissiez remarquer quoi que ce soit. La version 9 élimine complètement ce piège : l'enregistrement est permanent après chaque bloc, peu importe ce que vous faites ensuite.

Mode 2 : Mode Réalisateur / Accents (Gratuit - Fonctionne localement)

Outil pour "altérer" le texte. Impose aux synthétiseurs des lecteurs d'écran un accent étranger cassé.

Le menu déroulant intégré du Mode Réalisateur vous permet de choisir un accent directement à partir d'une liste. Les options disponibles sont :
Anglais (Samantha / Mark — Vocalizer/Apple, Zira / Hazel — OneCore)
Russe (Milena — Vocalizer/Apple, Irina / Pavel / Yuri — OneCore, eSpeak)
Polonais (Ewa — Vocalizer/Apple, Paulina — OneCore)
Allemand (Markus / Stefan — Vocalizer/Apple, Hedda / Katja — OneCore)
Espagnol (Jorge / Monica — Vocalizer/Apple, Helena — OneCore)
Islandais (Gudrun — OneCore, eSpeak; note : Vocalizer ne supporte pas cette langue !)
Italien (Alice / Luca — Vocalizer/Apple, Elsa — OneCore)
Finnois (Satu / Mikko — Vocalizer/Apple, Heidi — OneCore)
Et deux options de nettoyage sans accent :
"Aucun (Nettoyage SANS normalisation des chiffres)"
"Aucun (Nettoyage AVEC normalisation des chiffres)"
L'option avec normalisation des chiffres convertit automatiquement les chiffres en leur forme écrite (par exemple, 15 devient "quinze") avant le traitement — ainsi, NVDA lit les chiffres de manière fluide, et si le texte a un accent forcé, le chiffre l'aura aussi, sans exception.
Vous vous demandez sûrement si le synthétiseur saura décliner ces chiffres normalisés en fonction du contexte ? La réponse est : non. Et c'est une fonctionnalité intentionnelle. Comme on le sait bien : "la langue polonaise est difficile" — et un étranger écorchant notre grammaire ajoute simplement de l'authenticité à l'accent cassé !

Réparateur de Balises (NOUVEAUTÉ dans la version 9) : À la fin de la liste, vous trouverez une option supplémentaire — le Réparateur de Balises. Il n'applique aucune règle phonétique ni de nettoyage. Il fait une seule chose : injecte dans le fichier le code de langue ISO à deux lettres que vous fournissez (par exemple, "fi" pour le finnois, "en" pour l'anglais). Utile lorsque vous avez déjà un fichier prêt — par exemple, traduit précédemment par le Traducteur AI — mais qui est sorti avec une balise de langue incorrecte ou manquante. Au lieu de le traduire à nouveau, vous lancez simplement le Réparateur avec le bon code ISO et en un instant, vous avez un fichier corrigé.

Le script nettoie les didascalies entre parenthèses — il supprime tous les fragments de texte entre parenthèses (par exemple, "(avec des respirations entrecoupées)", "(en chuchotant)", "(ironiquement)"). ElevenLabs doit lire uniquement les dialogues et la narration, pas les instructions de mise en scène intégrées dans le texte.

Le script nettoie également les balises Markdown — il supprime les hashtags des en-têtes (par exemple, #, ##, ###), les signes égaux utilisés comme soulignements d'en-têtes et les virgules orphelines qui pourraient perturber le rythme de lecture du synthétiseur.

- Bouclier de protection : Le script protège toutes les balises HTML. Il altère uniquement les dialogues et la narration.
- Fonctionne localement et ne coûte rien !

Mode 3 : Chiffreur (NOUVEAUTÉ dans la version 13.0 — jeux de texte, gratuit, local)

Troisième RadioButton dans Polyglotte, à côté du Traducteur AI et du Mode Réalisateur : "Mode Chiffreur (jeux de texte, altération aléatoire)". Lance six algorithmes locaux de distorsion de texte — pour des jeux, des énigmes, des casse-têtes linguistiques. Après avoir choisi le mode, une liste déroulante d'algorithmes apparaît, et pour l'un d'eux (Chiffre de César) un champ numérique supplémentaire pour le décalage.

Algorithmes disponibles (sélectionnez dans le menu "Choisissez un algorithme de distorsion") :

- Inverseur de Texte (Lecture à l'envers avec majuscule) — chaque phrase est inversée caractère par caractère, en conservant le point/exclamation/interrogation à la fin et la majuscule au début. Avant l'inversion, le script développe les abréviations populaires (p. ex., c.-à-d., etc., M., Dr) pour que le résultat après inversion ait toujours du sens — sans cela, "p. ex." après inversion devient un absurde ".xe p".

  Inspiration : une mission du programme "The Traitors. Traîtres". Lorsque l'animatrice a montré aux participants une chanson populaire polonaise de dessin animé — simplement jouée à l'envers — les réactions allaient dans le sens de "quelle langue est-ce ?", "c'est probablement de l'arménien", "hongrois ou finnois". La mission proprement dite consistait à ce qu'une équipe reçoive dans la forêt le texte de la chanson écrit à l'envers, qu'elle devait chanter dans cette forme inversée, l'autre équipe l'enregistrait, la jouait à l'envers — et en théorie récupérait la chanson originale à deviner. Exactement le même malentendu phonétique amusant est généré par notre Inverseur lorsque vous passez le fichier traité par un synthétiseur TTS.

- Typoglycémie (Milieu des mots mélangé) — effet psycholinguistique classique : "Vous pvoeuz lrie un txete dnas n'improtre qluel odrre de ltteers, tnat que la piremère et la drenèire ltteer sont à la bnoe palce". Le script mélange aléatoirement le milieu de chaque mot de plus de 4 caractères, la première et la dernière lettre restent intactes. Idéal pour tester "combien je vois vraiment, et combien mon cerveau devine".

- Téléphone Cassé / Dialecte Serpent — chaque "s", "z" ou digramme "sz" est aléatoirement allongé en un sifflement de 4-8 caractères ("ssssss", "zzzzzz", "ssssssz"). Inspiration : Snecko du jeu "Slay the Spire". Effet : le texte semble lu par un serpent avec un défaut de prononciation.

- Voyelliseur (Tout résonne en "O") — chaque voyelle dans le texte est remplacée par "o", y compris les voyelles accentuées (à, â, é, è, ê, î, ô, ù, û, ÿ). "Bonjour" → "Bonjoor", "café" → "cofo". Plus le texte est long, plus l'effet est amusant (et le lecteur d'écran le lit avec pleine conviction).

- Fort Bégaiement / Robot Endommagé — ajoute des bégaiements au début des mots : "co-co-co-computer", "do-do-douche". Pour les mots courts (moins de 3 caractères), l'algorithme les ignore. Si la deuxième lettre du mot est une consonne, il répète les deux premières lettres (effet plus naturel) ; si c'est une voyelle, il ne répète que la première.

- Chiffre de César (décalage de l'alphabet par langue source) — chiffre de substitution classique : chaque lettre est décalée de N positions dans l'alphabet de la langue source détectée (par exemple, alphabet français ABCDEFGHIJKLMNOPQRSTUVWXYZÀÂÇÉÈÊËÎÏÔÙÛÜŸ, 40 caractères ; alphabet polonais AĄBCĆ…ZŻŹ, 35 caractères). Vous entrez la valeur de décalage dans le champ numérique "Décalage du chiffre de César". La plage autorisée est ±(taille de l'alphabet−1). Si vous entrez 0 — l'application choisira un décalage aléatoire et l'affichera dans un message après la fin (pour que vous puissiez ensuite déchiffrer). Les caractères hors alphabet (chiffres, ponctuation, espaces) restent inchangés.

Application pratique : les chiffres enregistrent le résultat dans le même format que le Mode Réalisateur (.html avec balise lang ou .docx avec balises XML), donc NVDA les lira avec la voix de la langue appropriée. Surtout l'Inverseur et le Voyelliseur sonnent beaucoup plus intéressants dans le synthétiseur que lorsque vous les lisez avec vos yeux — car le cerveau essaie automatiquement de "décoder" le texte à la lecture visuelle, tandis que le TTS le lit exactement comme il est écrit.

Les six chiffres sont également décrits dans un langage plus large et accessible dans le fichier docs/dictionaries.pl.txt du package de l'application — avec des conseils sur la façon d'ajouter votre propre chiffre de type "remplacement de lettres" sans connaissance en programmation (par exemple, langage de l'argot scolaire, charabia).

Détection de la langue

Avant que le script "altère" le texte, il détecte la langue du texte (lingua-language-detector, paragraphe par paragraphe) et charge le pack de règles correspondant à partir de dictionaries/<code>/. Si la langue détectée n'a pas de pack installé, un avertissement s'affiche — les règles phonétiques sont strictement liées à la langue source et ne peuvent pas être empruntées d'un autre dossier.

Accents optimisés pour les synthétiseurs locaux (NVDA)

Les accents ont été conçus à 100 % pour les synthétiseurs locaux, gratuits et payants des lecteurs d'écran — Vocalizer et eSpeak dans NVDA. Cela garantit la stabilité et la prévisibilité de l'effet sur chaque ordinateur.

Pourquoi pas ElevenLabs ? Les tests sur des documents plus longs ont montré que la distorsion phonétique du texte dans des moteurs comme ElevenLabs n'impose pas l'accent souhaité — le moteur "devine" simplement la langue et en fait plutôt un accent slavo-occidental/sud. Les synthétiseurs locaux NVDA sont beaucoup plus obéissants à cet égard.

Spécificité des synthétiseurs locaux (TTS)

Les différents moteurs TTS se comportent différemment. Voici les principales différences qui ont un impact direct sur le fonctionnement des accents :

eSpeak (Open Source)
Moteur léger et gratuit avec une énorme base de langues — prend en charge, entre autres, l'islandais. Très rigoureux en matière de codage des caractères, ce qui le rend prévisible. Cependant, il a des défauts phonétiques : il partage souvent des phonèmes entre les langues, ce qui fait que, par exemple, l'ukrainien sonne avec un accent russe.

Nuance Vocalizer
Moteur commercial payant, intégré gratuitement dans les appareils Apple (VoiceOver). Offre une qualité de prononciation très naturelle. Limitation importante : NE POSSÈDE PAS de support pour toutes les langues — PAS de voix islandaise. Pour le finnois, Satu est disponible, pour l'italien Alice.

Comment télécharger Vocalizer sur Windows ?

Vocalizer n'est pas intégré dans Windows — ce sont des modules payants pour NVDA distribués par Tiflotecnia. L'installation se fait en deux étapes : téléchargement du pilote et des voix elles-mêmes.
- Achat et téléchargement du pilote : Rendez-vous sur le site tiflotecnia.com (le formulaire d'achat est en anglais), achetez une licence et allez dans la section "Downloads" pour télécharger le fichier du pilote. Remarque importante pour NVDA : La sous-page "Downloads" est un cauchemar architectural — les en-têtes sont en anglais, la navigation en portugais, et toute la page a une balise de langue portugaise injectée dans le code ! Même si vous activez le traducteur dans le navigateur, il traduira le contenu mais ne supprimera généralement pas la balise de langue du code. En conséquence, le lecteur d'écran peut essayer de lire une page en anglais-polonais avec un accent portugais très cassé. Ne vous laissez pas décourager par cela et désactivez temporairement le changement de langue automatique, puis traduisez simplement la page et téléchargez le pilote !
- Téléchargement des voix : Le pilote seul ne suffit pas — après son installation, NVDA affichera par défaut une erreur de chargement du synthétiseur. Pour y remédier, vous devez télécharger séparément les packs de voix que vous prévoyez d'utiliser (par exemple, la voix polonaise Ewa pour la lecture fluide des contrôles système et la voix finnoise Satu pour les accents dans Polyglotte).
Remarque : N'oubliez pas de réactiver le changement de langue automatique après avoir fermé la sous-page, pour ne pas être déçu par la suite !
- Installation rapide : Les fichiers téléchargés sont des paquets d'extension NVDA (ils ont l'extension .nvda-addon). Vous n'avez pas besoin de chercher leur installation via NVDA -> Outils -> Add-on Store. Si NVDA est activé, il suffit d'"ouvrir" ces fichiers de manière habituelle (en appuyant sur Entrée). Windows peut masquer leur extension, mais l'info-bulle les lira correctement comme "Fichier de paquet d'extension NVDA". Le lecteur vous demandera automatiquement si vous souhaitez installer l'extension.
Après avoir installé le pilote et les voix et redémarré le lecteur, Vocalizer apparaîtra dans la liste des synthétiseurs dans les paramètres NVDA et ne devrait pas afficher d'erreurs.

Microsoft OneCore
Voix gratuites intégrées dans Windows (Mobile Voices). Un bon compromis entre qualité et disponibilité des langues. Offre une haute qualité et prend en charge la langue islandaise (Gudrun), finnoise (Heidi) et italienne (Elsa). Remarque : OneCore ne prend pas en charge nativement le changement automatique de langue basé sur les balises lang (sauf si vous utilisez le lecteur d'écran intégré au système, Narrateur) — voir la section ci-dessous.

Comment télécharger les voix OneCore sur Windows ? Les voix OneCore sont gratuites, mais la plupart des langues ne sont pas installées par défaut. Pour télécharger les langues manquantes, allez dans Paramètres Windows → Heure et langue → Voix → Gérer les voix (ou "Ajouter des voix"). Sélectionnez la langue dans la liste (par exemple, Islandais, Finnois, Italien) et cliquez sur Télécharger. Après le téléchargement, la voix apparaîtra automatiquement dans NVDA — sans aucune configuration supplémentaire.

Apple (iPhone / iPad / Mac) — VoiceOver avec Vocalizer
Sur les appareils Apple, le moteur Vocalizer est intégré nativement dans le système d'exploitation et prend en charge toutes les langues sans achats supplémentaires. Cependant, les versions compactes des voix sont installées par défaut, ce qui leur donne un son quelque peu mécanique. Pour obtenir un son beaucoup meilleur et plus naturel, il est conseillé de télécharger les versions étendues ou premium :
- Sur iPhone/iPad : Réglages → Accessibilité → VoiceOver → Voix → sélectionnez la langue (par exemple, Finnois) → touchez le nom de la voix (par exemple, Satu) → vous verrez les options "Étendu" et "Premium". Téléchargez la version choisie — elle occupe plus d'espace disque, mais la différence de qualité est notable.
- Sur Mac : Préférences Système (ou Réglages Système) → Accessibilité → VoiceOver → Ouvrir l'utilitaire VoiceOver → Voix → cliquez sur "Personnaliser" à côté de la voix choisie et téléchargez la version étendue ou premium.

Android — Vocalizer payant pour chaque voix
Sur Android, Vocalizer est disponible en tant qu'application sur le Google Play Store (cherchez "Vocalizer TTS"). Remarque : chaque langue et voix est achetée séparément — il n'y a pas de licence unique pour tout. Avant l'achat, vous pouvez tester la voix pendant quelques minutes en mode démo. Après l'achat, la voix est liée à votre compte Google et peut être installée sur n'importe quel appareil avec le même compte.

Fonctionnalité révolutionnaire pour les aveugles : Fichiers avec balises de langue

C'est une véritable révolution. Les fichiers traités sont maintenant enregistrés comme :

- .html avec l'attribut lang (par exemple, lang="fi" pour le finnois) — NVDA lit cette balise et change automatiquement la voix pour le synthétiseur de langue approprié. Zéro configuration manuelle !
- .docx avec conservation du formatage — chaque segment de texte a une balise de langue injectée dans le XML du document, donc Word et NVDA savent quelle voix utiliser pour chaque partie.

Les fichiers traités sont toujours enregistrés comme de NOUVEAUX documents (par exemple, accent_Finois.html).

Changement automatique de langue dans NVDA — ce que vous devez savoir

Pour que NVDA change effectivement la voix en fonction de la balise lang, l'option "Changer automatiquement de langue lorsque pris en charge" doit être activée. Vous la trouverez dans Préférences NVDA → Voix. Par défaut, elle est activée au premier démarrage du lecteur — mais il vaut la peine de vérifier si quelqu'un ne l'a pas désactivée.

Limitation importante des voix OneCore : Les voix Microsoft OneCore ne prennent pas en charge ce mécanisme avec NVDA nativement, mais seulement avec le lecteur d'écran intégré à Windows, Narrateur. Il existe un add-on non officiel pour NVDA appelé "One Core Autolang" qui essaie de corriger cela — mais son développement a été rapidement interrompu. La raison est prosaïque : chaque année, avec la première version de NVDA de l'année, il y a des changements qui brisent la compatibilité API (appelés API Breaking Changes). Parfois, il suffit de mettre à jour le champ "last tested version" dans le manifeste de l'add-on, mais parfois des modifications réelles du code sont nécessaires — et l'auteur ne suit pas les mises à jour. Si vous tenez au changement automatique de langue, un choix plus sûr est Vocalizer ou eSpeak, qui prennent en charge ce mécanisme nativement, bien que dans le premier cas, vous devez également vous attendre à une indisponibilité temporaire du pilote Vocalizer mis à jour pour le dernier NVDA en raison de ce qui a été décrit quelques lignes plus haut. Vous aurez alors le choix :
- Ne pas mettre à jour NVDA - les voix fonctionneront sûrement, mais vous n'aurez pas accès aux nouvelles fonctionnalités potentielles, améliorations ou corrections de bugs.
- Mettre à jour NVDA et forcer l'activation de l'add-on en remplaçant la compatibilité (introduit assez récemment, cela fonctionnera si jusqu'à présent il suffisait de mettre à jour le manifeste). Sinon... eh bien, il y avait un avertissement que vous le faisiez à vos propres risques.

ALERTE pour les utilisateurs de Vocalizer : NVDA 2026.1 (mai 2026)

L'avertissement ci-dessus vient de devenir un fait. NVDA 2026.1 n'est pas une simple mise à jour annuelle avec un petit API Breaking Change — c'est un saut architectural qui BRISERA tous les add-ons Vocalizer existants. NVDA est passé à Python 3.13 et a abandonné le support de l'architecture 32 bits, donc les bibliothèques .dll des voix doivent être RECOMPILÉES — la simple mise à jour du manifeste et du code de l'add-on ne suffit pas. Tant que Tiflotecnia n'aura pas publié un paquet de pilotes et de voix mis à jour, Vocalizer dans NVDA 2026.1+ ne fonctionnera dans aucune configuration — aucun remplacement de compatibilité ne le contournera.

Conséquences pratiques :
- Si vous n'avez PAS encore mis à jour NVDA et que vous tenez à Vocalizer — RETARDEZ LA MISE À JOUR. Pour le moment, il n'existe pas de chemin de secours qui restaurera Vocalizer dans 2026.1. Attendez une annonce officielle de Tiflotecnia.
- Si vous avez déjà mis à jour et que Vocalizer a disparu — vous avez deux options :
  1. Réconciliez-vous avec Vocalizer : désinstallez NVDA 2026.1 et revenez à la version précédente qui fonctionnait (par exemple, 2025.x). C'est le moyen le plus rapide de retrouver des voix fonctionnelles.
  2. Achetez une licence pour un pack vocal commercial pour SAPI5 — par exemple, auprès de A T Guys (atguys.com). ATTENTION lors de la configuration : dans NVDA, lors du choix du synthétiseur, sélectionnez "Microsoft Speech API version 5 — 32 bits", et NON "Microsoft Speech API version 5" tout court. Le choix de la variante SAPI5 par défaut laissera la liste des voix vide — les voix SAPI5 sous licence sont distribuées sous forme de bibliothèques 32 bits et seule la variante API 32 bits les "voit".

ÉTAPE 6 : Architecte d'Audiobooks

Outil pour préparer une structure de fichier professionnelle pour les lecteurs d'écran et ElevenLabs. Accédez-y en cliquant sur le bouton "📄  Convertisseur" dans la barre de boutons ou en choisissant Outils → Convertisseur dans le menu (raccourci : Ctrl+3).

Comment ça fonctionne ?

1. Entrez le chemin du fichier source dans le champ texte ou cliquez sur le bouton "Parcourir..." pour sélectionner un fichier dans la boîte de dialogue système. Le script accepte les fichiers .txt, .docx, ainsi que les fichiers .html et .htm.
2. Cliquez sur "Construire l'Architecture pour ElevenLabs".
3. Le script scanne chaque ligne de texte et transforme les mots-clés (Acte, Chapitre, Prologue, Épilogue, Introduction) en en-têtes "Heading 1" dans le document Word.
4. Les scènes (lignes commençant par le mot "Scène") sont transformées en texte en gras — visibles dans le document, mais invisibles dans la table des matières d'ElevenLabs.
5. Tout le reste du texte (dialogues, descriptions) passe sans changement.
6. Vous obtiendrez un fichier architecture_[nom_original].docx — un Word professionnel prêt pour un travail ultérieur. Par exemple, si votre fichier d'entrée s'appelait anesthesie.txt, le fichier résultant sera nommé architecture_anesthesie.docx et apparaîtra dans le même dossier que l'original.

Nettoyage en passant : Le script supprime automatiquement les balises HTML (si le texte provient du navigateur ou d'un fichier .html local, par exemple généré par Polyglotte) et les balises d'en-tête Markdown (par exemple, ### ou ####) avant le traitement. Vous n'avez pas besoin de nettoyer le fichier manuellement.

Avantage puissant pour les utilisateurs de NVDA et ElevenLabs

Le formatage "Heading 1" pour les chapitres n'est pas seulement esthétique. Dans NVDA, vous pouvez naviguer rapidement entre les en-têtes en appuyant sur la touche H (ou 1 pour les en-têtes de premier niveau). Au lieu de faire défiler des centaines de pages, vous sautez de chapitre en chapitre en une fraction de seconde. Cela change la façon de travailler avec de longs documents. Dans ElevenLabs, vous avez l'assurance que le moteur insérera automatiquement des coupures et ne se bloquera pas lors de la réalisation de clips audio.

ÉTAPE 7 : Comment écrire le Livre du Monde (Prompt de l'Architecte et Mini-cours Markdown)

L'intelligence artificielle alimentant le Studio Principal comprend mieux les commandes lorsqu'elles sont formatées en langage de balisage Markdown. Si vous fournissez à l'IA du Réalisateur seulement une idée vague (par exemple, "deux sœurs dans l'au-delà"), la machine paniquera par manque de détails et créera une histoire banale et prévisible, ignorant la logique.

Pour éviter cela, utilisez un chatbot externe (par exemple, le ChatGPT ou Claude gratuit) comme votre Architecte personnel. Dans la version 13.0, vous n'avez plus besoin de réécrire le prompt à partir des instructions — dans le panneau du Réalisateur, juste en dessous du bouton «💾 Sauvegarder la Bible de manière permanente», vous trouverez le bouton «📖 Prompt de l'Architecte pour l'IA…». Cliquez dessus, et une fenêtre de dialogue s'ouvrira avec le texte du prompt prêt dans un champ "lecture seule" et un bouton "Copier dans le presse-papiers". NVDA annonce tout le contenu dès l'ouverture de la fenêtre — il suffit de cliquer sur "Copier", de coller (Ctrl+V) dans ChatGPT/Claude et de remplacer le fragment "[INSÉREZ VOTRE IDÉE ICI]" par votre propre ébauche d'intrigue.

Pourquoi de cette manière plutôt que par copie depuis les instructions ? Le dialogue dans l'interface graphique a un avantage clé en termes d'accessibilité : il est natif et lu sans perturbation par le lecteur d'écran, ne nécessite pas de basculer vers un éditeur de texte (où les accents français et les guillemets peuvent être mal copiés) et fonctionne de manière identique sur chaque système d'exploitation. Ce même modèle — un dialogue avec un prompt à copier — est également utilisé dans le Gestionnaire de Règles (voir ÉTAPE 7b ci-dessous).

Comment l'IA répond : En réponse, vous recevrez un texte en deux parties. La première est le Livre du Monde enfermé dans un bloc de code Markdown (balises ```markdown … ```). Copiez UNIQUEMENT le contenu du bloc de code (sans les balises ```) et collez-le dans le champ "Livre du Monde" dans le Réalisateur, puis cliquez sur «💾 Sauvegarder la Bible de manière permanente». La deuxième partie est une recommandation sur lequel des modes créatifs (Scénario ou Audiobook) convient le mieux à votre idée — considérez-la comme une suggestion lors de la sélection du mode dans le RadioBox.

Mini-cours Markdown dans le Livre : un seul hashtag (#) est une section principale (par exemple, «# Personnages»), un double hashtag (##) est une sous-section, les tirets (-) créent des listes, et les doubles astérisques (**texte**) mettent en gras des règles absolues et inaltérables (par exemple, «**Le héros NE ment JAMAIS**»). Pour un personnage parlant une langue étrangère, ajoutez une balise avec l'accent, par exemple, «[Speaker 1: Marek] - a un accent français». Le mot-clé "accent" est NÉCESSAIRE — le moteur de l'application le détecte automatiquement et applique les règles phonétiques correctes aux dialogues du personnage.

Astuce : N'oubliez pas de mettre à jour de temps en temps votre Livre du Monde à mesure que l'intrigue s'enrichit de nouveaux lieux ou personnages importants. Vous pouvez le faire manuellement ou avec l'aide d'un chatbot externe. Plus le fondement est riche, meilleurs sont les résultats en Réalisation !

ÉTAPE 7b : Gestionnaire de Règles (Ctrl+4) — dictionnaires pour linguistes sans Python

La version 13.0 introduit le quatrième outil sur la barre : le Gestionnaire de Règles. Vous l'ouvrez avec la touche Ctrl+4 ou depuis le menu Outils. C'est un explorateur visuel du dossier dictionaries/, où l'application stocke toutes les règles phonétiques (accents), chiffres et modes du Réalisateur dans des fichiers YAML (format lisible par l'homme, plus simple que JSON).

Pourquoi YAML ? Jusqu'à la version 12.0, tous les accents, modes créatifs et filtres étaient "intégrés" dans le code Python. Ajouter un nouvel accent nécessitait un programmeur. Dans la version 13.0, tout cela a été déplacé vers des fichiers .yaml dans le dossier dictionaries/ — toute personne capable d'ouvrir le Bloc-notes peut ajuster un accent existant ("remplacer sz par sh par sch") ou en ajouter un tout nouveau (suédois, danois, dialecte russe).

Ce que vous trouverez dans le Gestionnaire de Règles :
- Arborescence des fichiers — liste complète de tous les fichiers YAML dans dictionaries/ avec une division par langues sources (actuellement complètement déployées : Polski, Deutsch, English, Suomi, Français, Íslenska, Italiano, Русский) et catégories (accents/, chiffres/, réalisateur/). Navigation par flèches comme dans l'Explorateur de fichiers Windows, support complet NVDA.
- Bouton «📝  Ouvrir dans l'éditeur de texte» — ouvre le fichier sélectionné dans le Bloc-notes par défaut du système. Vous éditez, enregistrez, cliquez sur «🔄  Actualiser l'arborescence» et c'est prêt.
- Bouton «📋  Dupliquer le fichier sélectionné» — le moyen le plus rapide pour un nouvel accent : prenez un fichier existant (par exemple, finski.yaml), donnez-lui un nouveau nom (par exemple, suédois), le Gestionnaire crée une copie avec le commentaire "changez les champs étiquette et description" et l'ouvre dans l'éditeur.
- Bouton «➕  Nouveau fichier de règles…» — assistant avec sélection du type (accent, chiffre, mode du Réalisateur, nouvelle langue source, chiffre algorithmique). Pour les cas simples (accent, chiffre de type "remplacement de lettres"), l'assistant crée un modèle YAML prêt à être édité. Pour les cas nécessitant un programmeur (nouvelle langue source, algorithme de type "mélange des milieux de mots"), l'assistant génère un prompt pour le chatbot IA — vous le collez dans ChatGPT, obtenez un fichier YAML prêt, le sauvegardez dans dictionaries/ et c'est prêt.

Application pratique : Vous voulez ajouter un accent suédois ? Ouvrez le Gestionnaire de Règles, choisissez dictionaries/pl/accents/finski.yaml, cliquez sur "Dupliquer", nommez le fichier suédois, changez le champ étiquette en "Suédois (Alva / Oskar)", le code iso en sv, modifiez quelques règles de remplacement et enregistrez. Retournez à la Page d'accueil, cliquez sur «🔄 Actualiser les accents Réalisateur depuis YAML» et relancez l'application. Le nouvel accent apparaîtra dans le menu Polyglotte (en Mode Réalisateur) et — si vous l'ajoutez au Livre du Monde du personnage («[Marek] - a un accent suédois») — également dans la détection automatique des accents du Réalisateur.

Où chercher plus de documentation sur le dossier dictionaries/ :
- Fichier `docs/dictionaries.pl.txt` (disponible dans le package pour les utilisateurs finaux depuis l'onglet Releases) — description courte et simple de chaque sous-dossier, 6 chiffres prêts, 8 accents prêts et des idées de ce que vous pouvez faire vous-même, sans connaissance de Python.
- Fichier `dictionaries/README.md` (disponible uniquement lors du clonage du dépôt depuis GitHub — les packages de publication filtrent les fichiers .md) — documentation technique détaillée du format YAML avec des exemples, des listes de champs, des règles de pipeline, des regex. Ce document est adressé aux linguistes connaissant les bases de la programmation ainsi qu'aux développeurs.

Conseils importants pour les utilisateurs de lecteurs d'écran (NVDA)

1. Messages de succès et d'erreurs

Lorsque l'application termine une action (par exemple, enregistre un fichier ou rencontre une erreur), une boîte de dialogue apparaît avec un titre tel que "Succès", "Avertissement" ou "Erreur". NVDA annonce immédiatement cette boîte et lit son contenu. Vous n'avez rien à faire — les dialogues sont entièrement accessibles au clavier, et le focus atterrit automatiquement sur le bouton "OK". Il n'y a plus de ruses avec le préfixe "Alerte" — les boîtes de dialogue natives wxPython sont directement prises en charge par le lecteur.

2. Avertissement important : traitement silencieux en arrière-plan

Après avoir cliqué sur des boutons comme "Envoyer à l'IA" ou "Lancer le Traitement", le programme commence immédiatement le traitement en arrière-plan. Une barre de progression (Gauge) apparaît à l'écran, mais NVDA NE lit PAS sa valeur en temps réel — le lecteur d'écran reste silencieux pendant le travail. Ne cliquez pas à nouveau sur le bouton. Attendez qu'une boîte de dialogue avec le résultat ou un message d'erreur apparaisse — NVDA les annoncera automatiquement.

3. Navigation entre les outils

Se déplacer entre les outils (Réalisateur, Polyglotte, Convertisseur, Gestionnaire de Règles) se fait dans une seule fenêtre du programme à l'aide de quatre boutons sur la barre d'outils ou via le menu Outils (Alt, puis N). Raccourcis clavier disponibles : Ctrl+0 (Page d'accueil), Ctrl+1 (Réalisateur), Ctrl+2 (Polyglotte), Ctrl+3 (Convertisseur), Ctrl+4 (Gestionnaire de Règles — nouveauté en 13.0). Après avoir changé d'outil, le focus atterrit automatiquement sur la description du nouveau module — NVDA commence immédiatement à lire la nouvelle vue.

4. Ordre des tabulations et noms des widgets

Chaque élément de l'interface a un nom lisible dans la langue active de l'interface (depuis 13.x, l'interface peut être basculée entre 8 langues, dont le français) — NVDA le lit lorsqu'il est focalisé. L'ordre des tabulations est logique : de la description de l'outil, à travers les champs de configuration, jusqu'aux boutons d'action. Il n'y a pas de surprises ici — la navigation au clavier fonctionne comme dans tout autre programme natif Windows. Tous les menus et boutons sont traduits, et NVDA les lit avec une voix correspondant à la langue de l'interface, sans aucun réglage supplémentaire.

Remarques importantes pour la version 9.0 / Changelog

Nouvelles fonctionnalités et changements dans la version 9

Enregistrement résistant aux pannes de la progression de la traduction (CHANGEMENT — correction d'un bug critique)
Dans la version 8, la reprise d'une traduction interrompue était sujette à un piège silencieux et destructeur : si l'utilisateur suivait les instructions (découpage manuel du fragment traduit), puis reprenait immédiatement la traduction du reste, l'application ouvrait le fichier de sortie en mode de réécriture — effaçant irrévocablement et inconsciemment tout le progrès payé. Dans la version 9, tout le mécanisme a été repensé. Chaque bloc traduit est maintenant immédiatement enregistré dans un fichier temporaire (.jsonl) avec un index attribué. La reprise est entièrement automatique — l'application détecte elle-même le fichier et restaure la progression sans aucune intervention de l'utilisateur. Après une fin réussie, le fichier temporaire est automatiquement supprimé.

Réparateur de Balises en Mode Réalisateur (NOUVEAUTÉ)
Une nouvelle option a été ajoutée au menu du Mode Réalisateur — le Réparateur de Balises. Il injecte uniquement le code de langue ISO à deux lettres fourni par l'utilisateur dans le fichier, sans appliquer de règles phonétiques ni de nettoyage. Un outil de secours au cas où le fichier déjà prêt sortirait avec une balise linguistique incorrecte ou manquante.

Conversion automatique .txt en .html en Mode Traducteur (CHANGEMENT)
Les fichiers texte (.txt et .md) traduits par le Traducteur IA sont maintenant automatiquement enregistrés au format .html avec une balise linguistique intégrée. Grâce à cela, NVDA lit immédiatement le fichier avec la voix appropriée — sans aucune étape supplémentaire de la part de l'utilisateur.

Nomination intelligente des fichiers dans l'Architecte (CHANGEMENT)
L'Architecte d'Audiobooks ne sauvegarde plus le fichier résultant toujours sous le même nom architecture_prête.docx. Maintenant, le nom découle du fichier d'entrée — par exemple, pour anesthesie.txt, le fichier résultant est architecture_anesthesie.docx. Le fichier apparaît dans le même dossier que l'original.

Fonctionnalités conservées sans changement depuis la version 8

Retour au format .txt pour les fichiers de projet (CHANGEMENT)
Les fichiers de projet et les résumés sont maintenant enregistrés au format .txt au lieu de .md (Markdown). L'expérience avec le format .md comme barrière psychologique contre l'édition s'est avérée inefficace — l'IA enfreint souvent la règle anti-closure et il est souvent préférable d'éditer le fichier en cours et ensuite de recharger la mémoire, pour que l'IA, dans la mesure du possible, ne reçoive pas de permission cachée pour enfreindre l'interdiction. Le format .txt est plus intuitif et lisible pour tout le monde.

Règle du Monteur — nouvel avertissement

Dans les instructions (et dans les futures versions de l'interface), un avertissement clair a été ajouté pour expliquer ce qui peut et ne peut pas être modifié dans les fichiers de projet. L'utilisateur a le droit total d'éditer les dialogues et le contenu, mais il ne peut absolument pas modifier les lignes de structure (Acte, Scène, Chapitre, Prologue, Épilogue) — les endommager perturbe la navigation NVDA, la division dans ElevenLabs et la table des matières dans Word.

Prompt de l'Architecte mis à jour (CHANGEMENT)
Le prompt pour le chatbot externe (ChatGPT/Claude) a été repensé. Au lieu de renvoyer du code Markdown brut, l'IA renvoie maintenant une réponse en deux parties distinctes : la Partie 1 est le Livre du Monde enfermé dans un bloc de code Markdown (facile à copier sans les balises), et la Partie 2 est une Recommandation de Mode sous forme de texte ordinaire en dehors du bloc — elle conseille s'il est préférable d'utiliser le Mode Scénario Brut ou le Mode Audiobook Traditionnel. La description des tags de personnages a également été modifiée : au lieu de "sonores", il est maintenant question de l'accent et du ton de la voix dans le tag, par exemple, [Speaker 1: Nom] - zozote et accent français.

Explication de l'état de la directive Anti-Closure (DOCUMENTATION)
Les instructions contiennent maintenant une explication honnête que malgré les interdictions intégrées de l'Anti-Closure, le modèle enfreint encore régulièrement cette règle, en particulier en Mode Audiobook. Au lieu de cacher ce problème, la version 8 le clarifie et renvoie la responsabilité du "fermeture manuelle" au Réalisateur — d'où la Règle du Monteur comme outil de travail officiel et le retour au format texte ordinaire.

Fonctionnalités conservées sans changement depuis la version 7

Prompts Showrunner — Directive Anti-Closure (Réalisation — tous les modes)
Les trois modes de Réalisation conservent les directives showrunner intégrées. Brainstorming fonctionne comme un scénariste de série multi-saisons. Le Mode Scénario Brut et le Mode Audiobook ont l'interdiction de conclure le texte par des résumés, des morales et des fermetures narratives — sauf si l'utilisateur demande explicitement une fin ou un épilogue.

Panneau dédié avec des boutons pour insérer Prologue, Épilogues et coupures de chapitres directement depuis l'interface. Le compteur de chapitres se met à jour automatiquement. Le chargement d'un fichier existant règle le compteur sur le numéro approprié sans comptage manuel.

Attribution de Titres aux Chapitres (Postproduction — Mode Audiobook)
Le module itère sur les chapitres du fichier enregistré et leur attribue un titre court et littéraire en utilisant un modèle IA rapide, en analysant uniquement les débuts de chaque chapitre.

L'option "Russe (par exemple, Milena / Irina / Yuri / Pavel)" est ajoutée à la liste déroulante "Mode Réalisateur / Accents". Contrairement aux autres accents qui ne font que "détériorer" le texte polonais au niveau des lettres latines (par exemple, "sz" → "sh", "w" → "v"), l'accent russe effectue une translittération complète du texte polonais en cyrillique — ainsi, les voix synthétisées russophones (Vocalizer Milena, OneCore Irina / Pavel / Yuri, eSpeak "ru") peuvent "prononcer" les mots. Le mappage a été enrichi avec des voyelles iotisées ("ja" → "я", "je" → "е", "jo" → "ё", "ju" → "ю"), des adoucissements polonais si/ci/ni/zi + voyelle (par exemple, "ciocia" → "цёця"), ainsi que des digrammes spéciaux russes : "ść" / "szcz" → "щ", "sz" → "ш", "cz" → "ч", "rz" → "ж", "ch" → "х".

  Note phonétique : L'accent n'est pas une translittération académique russe (ISO 9, GOST, BGN/PCGN). Le but est uniquement de rendre le texte polonais phonétiquement similaire au russe — pour les besoins de la synthèse vocale, pas pour une translittération sérieuse des noms propres. Pour ce dernier travail, utilisez des outils linguistiques dédiés.

  Code de langue pour le fichier de sortie : "ru" (ISO 639-1). NVDA avec l'option "Changer automatiquement de langue lorsque supporté" activée passera immédiatement à la voix russe.

- Remarque sur "ź" : En russe, il n'y a pas d'équivalent exact du "ź" polonais, donc ce caractère est normalisé en "ж" — tout comme "ż". Certains dialectes du nord de la Russie et le biélorusse prononcent "ź" plus proche de "зь", mais du point de vue du synthétiseur vocal, la différence est négligeable. Si un linguiste préfère "зь", il peut remplacer cette règle dans le fichier `dictionaries/pl/akcenty/rosyjski.yaml` — le moteur charge les YAML dynamiquement, donc cela ne nécessite pas de recompilation de l'application.

- Barre de navigation étendue et menu Outils (CHANGEMENT). La barre a maintenant un quatrième bouton — Gestionnaire de Règles — et le menu "Outils" prend en charge le nouveau raccourci Ctrl+4. Les raccourcis existants (Ctrl+0 Page d'accueil, Ctrl+1 Réalisateur, Ctrl+2 Polyglotte, Ctrl+3 Convertisseur) restent inchangés.

- Bouton "Rafraîchir les accents du Réalisateur depuis YAML" sur la Page d'accueil (NOUVEAUTÉ). Après avoir ajouté un nouvel accent via le Gestionnaire de Règles (ou une édition manuelle du fichier YAML), cliquer sur ce bouton rechargera les wrappers accent_* dans le moteur du Polyglotte et du Réalisateur, afin que le nouvel accent soit visible dans le menu et dans la détection automatique des accents basée sur les tags de personnages dans le Livre du Monde. Le Polyglotte détecte les YAML automatiquement (sans rafraîchissement), mais le Réalisateur nécessite une régénération des wrappers — généralement après le rafraîchissement, il faut encore redémarrer l'application.
