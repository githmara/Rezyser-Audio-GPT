Podręcznik Reżysera Audio AI - Kompletny Przewodnik (Wersja 15.1 – Version de Publication)

Bienvenue dans le Studio d'Enregistrement Hybride ! Cet ensemble d'outils permet l'écriture, la planification, le formatage et la traduction automatiques de scripts pour pièces radiophoniques et livres audio. Il est optimisé pour fonctionner avec des synthétiseurs vocaux professionnels ainsi que des moteurs de lecteurs d'écran locaux (NVDA).

L'ensemble se compose du studio principal (Réalisation), de l'outil de traduction et d'accents (Polyglotte), de l'outil de construction de structure de fichier (Architecte de Livres Audio), du Gestionnaire de Règles (à partir de la version 13.0 — sans Python, vous pouvez ajouter un nouvel accent, un chiffre ou un mode créatif, voir ÉTAPE 7b ci-dessous) et — à partir de la version 15.0 — du module Récits (fiction interactive à la deuxième personne générée par IA, lue par TTS ou lecteur d'écran, décrite dans le manuel séparé recits.fr.txt). Les cinq outils sont disponibles dans une seule fenêtre de programme, commutable par des boutons sur la barre ou par des raccourcis clavier Ctrl+1..Ctrl+5.


KROK 1 : Première exécution (Cross-Platform)

L'application est entièrement portable et prête à fonctionner sur le système Windows. Il suffit d'entrer dans le dossier et de lancer le fichier run.bat (en double-cliquant dessus ou en créant un raccourci sur le bureau). Une fenêtre de terminal éphémère s'ouvrira (elle disparaît automatiquement), et après un moment, la fenêtre principale du programme apparaîtra — Réalisateur Audio GPT. Pas de navigateur, pas de serveur en arrière-plan. Lorsque vous avez terminé votre travail, il suffit de fermer la fenêtre du programme.

Important : Le dossier runtime/ fait partie uniquement des packages prêts pour Windows téléchargés depuis l'onglet Releases sur GitHub. Il contient un environnement Python isolé prêt à l'emploi sans installation. Si vous clonez le dépôt, ce dossier n'existe pas et ne devrait pas exister — vous utilisez alors un environnement virtuel venv décrit dans la section pour les développeurs ci-dessous.

--- Pour les Développeurs (Windows — dépôt Git) ---

1. Clonez le dépôt sur votre disque.
2. Exécutez le fichier setup_dev.bat. Le script créera automatiquement un environnement virtuel Python (venv) et installera toutes les dépendances requises à partir du fichier requirements.txt.
3. Lancez l'application avec la commande python main.py ou via le fichier run_dev.bat — le script détectera automatiquement le dossier venv et lancera le programme.

--- Pour les Développeurs et utilisateurs ordinaires (macOS / Linux) ---

1. Clonez le dépôt sur votre disque.
2. Ouvrez un terminal dans le dossier du projet et accordez aux scripts les permissions d'exécution : chmod +x *.sh
3. Exécutez le script de configuration : ./setup_dev.sh — le script créera l'environnement venv et installera les dépendances.
4. Lancez l'application : python main.py ou ./run.sh

Ce que vous verrez après le lancement : Après le lancement du programme, une fenêtre avec l'écran de démarrage s'ouvre. Vous y trouverez une brève description des outils disponibles ainsi qu'une section "Vérification du Système". Si la clé API n'est pas encore configurée, vous verrez un message rouge indiquant que les modules basés sur l'IA (Mise en scène, Traducteur) ne fonctionneront pas — les fonctions locales gratuites (accents, Architecte) sont cependant actives immédiatement. La configuration de la clé est décrite dans l'étape suivante.

Mises à jour automatiques

L'application vérifie au démarrage si une nouvelle version est disponible sur GitHub — la vérification se fait en arrière-plan et ne bloque pas l'interface.

Si vous avez installé le programme via le fichier d'installation prêt à l'emploi (.exe) : lorsqu'une nouvelle version est détectée, une fenêtre s'affiche pour vous demander si vous souhaitez la télécharger. Après confirmation, une barre de progression s'affiche, et lorsque le téléchargement est terminé, l'application se ferme automatiquement et le nouvel installateur se lance automatiquement — vos projets et votre clé API restent intacts.

Si vous utilisez le dépôt Git (développeurs et utilisateurs macOS/Linux) : au lieu d'une proposition de téléchargement, vous verrez une information sur la nouvelle version avec un lien direct vers la page de publication sur GitHub. Téléchargez l'archive "Source code" ou mettez à jour le dépôt avec la commande git pull.


KROK 2 : Alimentation de l'API (Clé OpenAI)

Pour que l'intelligence artificielle fonctionne, elle a besoin d'accéder aux serveurs d'OpenAI (les créateurs de ChatGPT).

1. Créez un compte sur platform.openai.com et approvisionnez votre compte dans l'onglet Billing.
2. Générez une clé dans l'onglet API Keys (elle commence par sk-proj-). Attention : la clé n'est affichée qu'une seule fois — au moment de sa création. Si vous fermez la fenêtre sans la copier, elle sera perdue à jamais et vous devrez la révoquer (option revoke secret key) et en générer une nouvelle. Copiez-la immédiatement, avant de cliquer sur quoi que ce soit.
3. Sur l'écran d'accueil du programme, cliquez sur le bouton "Générer le fichier golden_key.env et ouvrir l'éditeur de texte". Le système créera automatiquement un fichier de configuration vierge à l'endroit approprié et ouvrira le Bloc-notes avec un modèle prêt à être édité.
4. Dans le fichier ouvert, vous verrez la ligne OPENAI_API_KEY=ICI_COLLER_VOTRE_CLÉ. Supprimez le texte de remplacement et collez votre clé copiée directement après le signe égal (sans espace). Enregistrez le fichier et relancez l'application.

Conseil : Après le redémarrage, l'application vérifiera le fichier et affichera un message vert dans la section "Vérification du Système" — cela signifie que tous les modules AI sont prêts à fonctionner. Sinon, elle vous indiquera clairement ce qui ne va pas et vous permettra d'ouvrir l'éditeur de texte pour corriger rapidement l'erreur.


KROK 3 : Studio Principal de Réalisation

C'est votre centre de commande pour imaginer des histoires et écrire des scénarios. Accédez-y en cliquant sur le bouton "🎬  Réalisateur" dans la barre de boutons ou en sélectionnant Outils → Réalisateur dans le menu (raccourci : Ctrl+1).



IMPORTANT : Format des fichiers de projet — retour au .txt

Dans la version 7, les fichiers de projet étaient enregistrés au format Markdown (.md), par exemple scripts/znieczulica.md. C'était une expérience délibérée — le format .md devait constituer une barrière psychologique pour les personnes non techniques, les décourageant d'ouvrir et de modifier manuellement le fichier dans le Bloc-notes (et donc d'endommager accidentellement les en-têtes de structure).

L'expérience n'a pas fonctionné. L'IA enfreint souvent l'une des interdictions fondamentales (plus à ce sujet dans un instant). Pour cette raison, dans la version 8, nous sommes revenus à de simples fichiers .txt — plus intuitifs et lisibles pour tout le monde. Par exemple, un projet nommé "znieczulica" sera désormais enregistré sous forme de scripts/znieczulica.txt, et son résumé sous forme de scripts/znieczulica_resume.txt. Cela permettra à chacun d'apporter plus facilement des corrections ou des coupures de texte en temps réel.


⚠️ RÈGLE CRITIQUE DU MONTEUR (LISEZ AVANT DE COMMENCER !) ⚠️

Tous vos scripts et livres générés sont enregistrés dans de simples fichiers texte (.txt), que vous pouvez facilement ouvrir dans le Bloc-notes.

En tant que Réalisateur, vous avez le DROIT COMPLET (et même l'obligation) de modifier ce fichier ! Si l'intelligence artificielle s'emballe et, par exemple, résout elle-même le problème des personnages à la fin du fragment généré, ouvrez le fichier, supprimez les dernières lignes et laissez le texte interrompu au moment le plus tendu, avant de vider la mémoire, de recharger le fichier pour recharger la fenêtre contextuelle et de cliquer sur "Envoyer à l'IA" pour continuer.

🔴 CEPENDANT - CE QUE VOUS NE DEVEZ PAS TOUCHER :

Ne modifiez jamais, ne supprimez jamais et ne changez jamais les lignes contenant la structure (par exemple, Acte 1, Scène 2, Chapitre 1, Prologue). Si vous endommagez ces en-têtes :
1. Votre histoire se désintégrera dans les lecteurs d'écran (NVDA).
2. L'architecte de l'audiobook, et donc aussi le Studio Eleven Labs, ne pourra pas diviser correctement votre livre en fragments à lire.
3. Le Convertisseur interne de l'application ne générera pas de table des matières correcte dans le fichier Word ni sur la chronologie dans ElevenLabs.

Éditez les dialogues, coupez l'action, mais laissez la structure intacte !


Comment utiliser la Réalisation ?

- Livre du Monde (barre latérale à gauche) : C'est ici que vous entrez les règles de l'univers. Chaque projet a désormais son propre Livre lié au nom du fichier — si votre fichier d'histoire est par exemple emilia_heist_audiobook.txt, le Livre du Monde sera enregistré sous forme de scripts/emilia_heist_audiobook.md. C'est pourquoi l'ordre est important : entrez d'abord le nom du fichier de projet dans le champ "Nom du fichier de projet", puis vous pouvez enregistrer le Livre. Le bouton "💾 Sauvegarder la Bible de manière permanente" reste grisé tant que vous n'avez pas fourni de nom. Charger un projet existant avec le bouton "Charger l'histoire" chargera automatiquement le fichier .md correspondant — vous n'avez rien à faire manuellement. Remarque : Sans Livre du Monde rempli, l'application bloquera l'envoi de requêtes à l'IA — c'est une mesure de sécurité délibérée qui vous protège contre la génération de texte sans aucune règle.
- Mémoire à Long Terme (barre latérale à gauche) : Le deuxième champ de la barre latérale. Ici, l'IA enregistre automatiquement le résumé de l'intrigue lorsque la mémoire commence à se remplir. Vous pouvez également y inscrire vos propres notes manuellement — le modèle les traitera comme "ce que je sais déjà" avant de lire la scène en cours.
- Mode Brainstorming : Entrez une idée libre, et l'IA vous proposera 3 options de développement de l'intrigue. Pour chaque option, elle générera immédiatement un bloc "--- ÉBAUCHE DE PROMPT ---". Après avoir choisi l'une d'elles, collez ce prompt dans le Mode Script ou Audiobook et ajoutez éventuellement des remarques ou des informations pour le modèle. La mémoire de l'intrigue ne change pas pendant le Brainstorming — vous pouvez expérimenter sans risque !
- Mode Script Brut : Vous collez ici "l'Ébauche de Prompt" générée dans le Brainstorming. L'IA écrira un long fragment avec des balises complètes [Speaker X: Nom - émotion] pour les dialogues et des effets [SFX: ...] pour les sons. Le texte est automatiquement ajouté à votre fichier (par exemple, nouvelle_scene.txt) dans le dossier scripts/.
- Mode Audiobook Traditionnel : Mode pour les écrivains. L'IA génère une prose littéraire pure — zéro balise, zéro phonétique, dialogues classiques intégrés dans la narration. Le texte est ajouté au fichier de la même manière que dans le Mode Script.
- Création automatique de personnages : Le script est programmé pour créer automatiquement de nouvelles balises [Speaker] si l'intrigue nécessite un nouveau personnage. Astuce : Si l'IA crée un personnage intéressant, copiez sa balise et collez-la dans le Livre du Monde pour que le modèle s'en souvienne de façon permanente !

Gestion de projet — trois boutons d'action :
- Charger l'histoire : Charge un fichier de projet existant dans la mémoire. Disponible uniquement lorsque la mémoire est vide et qu'un nom de fichier a été saisi.
- Effacer l'actuel (laisser le Résumé) : Efface uniquement l'histoire actuelle. Le Résumé dans la Mémoire à Long Terme et le Livre du Monde sont conservés — idéal pour continuer un long livre après avoir généré un résumé.
- Fermer le Projet (Réinitialisation Complète) : Efface complètement le projet. Supprime l'histoire, le résumé, le Livre du Monde et réinitialise tous les compteurs. À utiliser lors du changement de projet ou d'une nouvelle histoire.

Note historique — pourquoi les modes sont désormais protégés contre les changements accidentels :
Dans les versions précédentes de l'application, personne ne surveillait la cohérence du mode créatif au sein d'un même projet. Le résultat était une certaine possibilité créative subtile, que l'on pourrait décrire ainsi : vous commencez une histoire en Mode Script, insérez "Acte 1" et "Scène 1" (l'application est ravie de votre cohérence), générez quelques écrans de tension avec des balises [SFX: Porte qui claque] et [Speaker 1: Marek - résigné]... puis — parce que l'inspiration vient de frapper — vous cliquez sur "Insérer coupure Chapitre 1". L'application, sans broncher, ajoute l'en-tête "Chapitre 1" au fichier, juste après "Scène 3". Vous avez maintenant dans le fichier un hybride de pièce radiophonique des années 50 et de roman contemporain. ElevenLabs regarde cette structure, voit l'en-tête de chapitre au milieu de l'acte et décide que c'est probablement une erreur dans la matrice. La table des matières ressemble à l'œuvre d'un artiste d'avant-garde. L'Architecte des Audiobooks, quant à lui, part du principe que vous êtes un adulte et traite simplement cela sans un mot — mais aussi sans aucune garantie de résultat. Depuis la version 12.0, l'interface bloque simplement le changement de mode d'enregistrement lorsque l'histoire est déjà en mémoire. Le Brainstorming est toujours disponible — vous pouvez y comploter sans restrictions.


Prompts de Showrunner — L'IA en tant que scénariste de série (de la version 7, conservé)

C'est le plus grand changement introduit dans la version 7, conservé sans modification. Il n'est pas visible dans l'interface, mais change radicalement la qualité de l'intrigue générée.

Le Showrunner est, dans l'industrie télévisuelle, la personne responsable de l'ensemble de la série — il veille à ce que l'intrigue ne se dirige jamais vers une solution facile, mais qu'elle s'épaississe constamment, multiplie les conflits et maintienne le spectateur en haleine pendant de nombreuses saisons. Dans la version 7, cette philosophie a été directement intégrée dans les instructions système de l'IA.

Directive Anti-Closure — état dans la version 8

Malgré le test de différentes approches, l'interdiction Anti-Closure est souvent enfreinte par le modèle, en particulier en Mode Audiobook Traditionnel. L'IA a une forte tendance à "fermer" l'histoire à chaque occasion — elle insère des phrases résumant l'intrigue, crée de faux happy ends ou clôt les intrigues au milieu du chapitre, comme si chaque fragment était le dernier. Le résultat est que le fragment suivant commence à zéro, sans continuité naturelle.

C'est pourquoi la règle du monteur décrite ci-dessus est si importante : si l'IA enfreint l'interdiction et clôt elle-même la scène, votre tâche en tant que Réalisateur est d'ouvrir le fichier .txt, de supprimer ces dernières phrases et de laisser le texte interrompu au moment tendu avant de le recharger dans l'application.

Chaque mode possède une directive Anti-Closure intégrée :

- Brainstorming : L'IA agit comme un scénariste de série multi-saisons. Chacune des 3 options proposées DOIT multiplier les obstacles, introduire de nouveaux dilemmes, des intrigues ouvertes et des cliffhangers. Interdiction absolue de proposer des options où les personnages se réconcilient de façon permanente, surmontent le principal obstacle sans conséquences majeures ou où l'histoire se dirige vers une fin précipitée. Interdiction d'inventer des lieux magiques bon marché qui brisent l'architecture du monde.
- Mode Script Brut : Interdiction absolue de terminer le texte par des résumés, des morales ou des conclusions. L'IA doit interrompre l'action naturellement à un moment tendu (cliffhanger), en évitant les conclusions, afin que le fragment suivant puisse prendre le relais de la narration en douceur.
- Mode Audiobook Traditionnel : Interdiction absolue de terminer le texte par des résumés pathétiques, de clôturer les intrigues ou de suggérer la fin de l'histoire (par exemple, "Elle était prête pour de nouveaux défis", "Elle comprit qu'il était temps d'aller de l'avant"). Le texte doit s'interrompre au milieu d'une action en cours, d'une tension ou d'une pensée ouverte.

Exception à la règle : Si vous demandez explicitement une conclusion, un final ou un épilogue, l'IA générera une clôture satisfaisante de l'histoire — l'interdiction ne s'applique pas lorsque vous le demandez vous-même.


Gestion des Actes et des Scènes (Mode Script, de la version 7, conservé)

Le Mode Script Brut possède un panneau dédié "✂️ Gestion de la Structure" avec des boutons pour construire la structure de la pièce radiophonique en temps réel.

- Insérer Acte X : Insère l'en-tête de l'acte (par exemple, "Acte 2") ET ajoute automatiquement "Scène 1" en dessous — car chaque nouvel acte commence par la première scène. Le compteur d'actes passe au numéro suivant, et le compteur de scènes se réinitialise à 2 (prêt pour la scène suivante dans cet acte).
- Insérer Scène X : Insère uniquement l'en-tête de la scène (par exemple, "Scène 3") dans l'acte en cours. Le compteur de scènes augmente automatiquement.

Chiffre : Inverseur de Texte

Ce chiffre inverse chaque phrase, mais d'abord il développe certaines abréviations pour éviter des résultats phonétiques absurdes (par exemple ".nim" en polonais).

Pour le français, les abréviations suivantes sont développées :

- "p. ex." → "par exemple"
- "c.-à-d." → "c'est-à-dire"
- "etc." → "et cetera"
- "M." → "Monsieur"
- "Dr" → "Docteur"

Exemple de non-sens : ".xel" (à partir de "p. ex." inversé).

Chargement intelligent de fichier : Lorsque vous chargez un fichier de script existant, l'application le scanne automatiquement et règle les compteurs d'actes et de scènes sur les numéros appropriés. Le compteur de scènes est toujours calculé au sein du dernier acte du fichier.

Gestion Intelligente des Chapitres (Mode Audiobook, de la version 5, conservé)

Le LLM génère un maximum d'environ 5000 caractères par requête — c'est insuffisant pour un chapitre complet. Vous travaillez donc de manière itérative : vous générez des fragments successifs avec le bouton "Envoyer à l'IA" jusqu'à ce que vous estimiez que le chapitre est prêt. Ensuite, vous cliquez sur "Insérer coupure de chapitre" — l'application ajoute un en-tête au fichier et à la mémoire, et le compteur de chapitres passe automatiquement au numéro suivant.

Boutons dans le panneau :

- Insérer coupure (Chapitre X) : Insère un en-tête (par exemple, "Chapitre 3") dans le fichier et la mémoire. Le compteur de chapitres se met à jour automatiquement.
- Insérer Prologue : Fonctionne uniquement au début, lorsque la mémoire est vide. Protection contre l'insertion accidentelle d'un Prologue au milieu de l'histoire.
- Insérer Épilogue : Termine l'histoire. Après avoir inséré l'Épilogue avec du contenu, l'application bloquera la génération de nouveaux fragments — c'est intentionnel, car une fois l'histoire terminée, il n'y a plus rien à ajouter.

Chargement intelligent de fichier : Lorsque vous chargez un fichier existant, l'application le scanne automatiquement et règle le compteur de chapitres sur le bon numéro. Si le fichier a un Prologue et trois chapitres, le compteur affichera "Chapitre 4" — sans comptage manuel.


Accumulateur de l'Intrigue — comment fonctionne la mémoire de l'IA

Seul le texte pur de l'histoire entre dans la mémoire du modèle — ce que l'IA a effectivement écrit. Les instructions, options et plans disparaissent après utilisation et ne polluent pas le contexte. Résultat ? Le modèle reste concentré plus longtemps, se souvient mieux des accents des personnages et s'éloigne moins souvent des règles du Livre du Monde.

L'indicateur "Mémoire du Modèle" à l'écran montre combien d'espace votre histoire occupe déjà :
- Vert (jusqu'à 150 000 caractères) : Le modèle est pleinement concentré, vous avez un tampon de sécurité.
- Jaune (150 000 – 175 000 caractères) : Vous vous approchez de la limite. L'IA peut commencer à raccourcir les discours et ignorer les règles. Commencez à clore lentement l'intrigue.
- Rouge (au-delà de 175 000 caractères) : Surcharge critique !

Mémoire Infinie (de la version 6, conservée)

Lorsque l'alerte rouge s'allume, vous n'avez plus besoin de copier manuellement le résumé. Entrez dans Brainstorming une commande contenant le mot "résumé" — l'IA générera une capsule concise de l'ensemble de l'intrigue jusqu'à présent. Ensuite, cliquez sur le bouton "Enregistrer le Résumé (de façon permanente)" — l'application crée automatiquement un fichier _résumé.txt dans le dossier scripts/ et le protège contre l'écrasement accidentel. Après l'enregistrement, videz la mémoire et vous pouvez continuer à créer dans le fichier actuel. Vous chargerez le résumé dans le champ de Mémoire à Long Terme avant la prochaine session — et vous pouvez continuer l'histoire indéfiniment, sans aucune limite de longueur. Vous devez seulement vous rappeler que si le fichier entier de l'histoire dépasse 175000 caractères, pour pouvoir interrompre le travail en toute sécurité et y revenir plus tard, vous devez générer et enregistrer le Résumé de l'histoire. L'IA y ajoute également quelques derniers paragraphes de l'histoire au moment de l'écriture du résumé.

Résumé automatique : Lorsque la mémoire entre en état d'alerte, Brainstorming passe automatiquement en mode de secours — au lieu de générer immédiatement des options, il crée d'abord un résumé détaillé de toute l'intrigue jusqu'à présent et l'enregistre dans des balises <RÉSUMÉ>. L'application détecte ces balises et transfère automatiquement le résumé dans le champ de Mémoire à Long Terme. Zéro travail manuel !

Chargement intelligent avec fichier de résumé : Lorsque vous chargez un projet qui a déjà un fichier de résumé enregistré (par exemple, znieczulica_résumé.txt), l'application charge automatiquement le résumé dans la Mémoire à Long Terme et laisse la Mémoire Courante vide. Ainsi, vous ne gaspillez pas de jetons à recharger toute l'histoire — le modèle connaît le contexte à partir du résumé et est prêt pour une continuation infinie.


KROK 4 : Postproduction dans Reżyser Audio GPT

Après avoir écrit votre histoire, vous avez à votre disposition un outil de postproduction disponible en bas du panneau de Reżyser (apparaît uniquement en Mode Audiobook).

Attribution de Titres aux Chapitres (Mode Audiobook)

L'IA analysera toute l'histoire et proposera des titres descriptifs et littéraires pour chaque chapitre (ainsi que pour un éventuel Prologue et Épilogue). Le module itère à travers les chapitres du fichier enregistré et leur attribue un titre court, en analysant uniquement le début de chaque chapitre (jusqu'à 6000 caractères). Il retourne uniquement une liste numérotée de titres — sans retranscrire le contenu du livre.

Remarque : Le module nécessite que le fichier soit déjà enregistré sur le disque (généré ou chargé). Si le fichier n'existe pas, l'application affichera un message approprié.


KROK 5 : Polyglotte AI

Application pour la traduction et l'imposition d'accents forts sur les synthétiseurs de lecteurs d'écran. Accédez-y en cliquant sur le bouton "🌍  Polyglotte" dans la barre de boutons ou en sélectionnant Outils → Polyglotte dans le menu (raccourci : Ctrl+2).

Mode 1 : Traducteur Ordinaire (Utilise l'IA - Payant)

Idéal pour écouter des histoires dans une belle langue étrangère correcte.

- Chargez un fichier avec le bouton "Charger le fichier en mémoire" ou utilisez le bouton "Parcourir..." pour sélectionner un fichier dans la fenêtre système.
- Choisissez le mode "Traducteur IA", entrez la langue cible (par exemple, "Finnois").
- Le script traduira le contenu. Si vous chargez un fichier .html, il traduira uniquement le texte visible pour le lecteur et mettra à jour le code de langue dans la balise html.
- Si vous chargez un fichier .txt ou .md ordinaire (par exemple, un script généré par le Réalisateur), le script enregistrera automatiquement le résultat comme un fichier .html avec une balise de langue intégrée — prêt à être lu par NVDA sans aucun travail supplémentaire.
- Prend également en charge les fichiers .docx.

Division intelligente en blocs : Les longs textes sont automatiquement divisés en blocs de 10 000 caractères maximum et traduits séquentiellement avec une barre de progression.

Enregistrement de progression résistant aux pannes (NOUVEAUTÉ dans la version 9) : Chaque bloc traduit est immédiatement enregistré dans un fichier temporaire caché dans le dossier système de l'application. Si la traduction est interrompue en raison de l'épuisement de la limite API, lors du prochain lancement, l'application détectera automatiquement ce fichier, restaurera la progression déjà payée et terminera tranquillement le travail à partir du point d'interruption — sans aucun copier-coller manuel. Après une fin réussie, le fichier temporaire est automatiquement supprimé.

Pourquoi est-ce important ? Dans la version 8, l'approche de reprise de traduction avait un bug critique et silencieux : si vous ne renommiez pas le fichier avec une traduction partielle et coupiez le fragment traduit selon les instructions, puis repreniez immédiatement la traduction du reste — l'application ouvrait le fichier de sortie en mode écrasement. La progression payée était effacée de manière irréversible et inconsciente avant que vous ne puissiez vous en rendre compte. La version 9 élimine complètement ce piège : l'enregistrement est permanent après chaque bloc, peu importe ce que vous faites ensuite.

Mode 2 : Mode Réalisateur / Accents (Gratuit - Fonctionne localement)

Outil pour "détériorer" le texte. Imposant un accent polonais cassé sur les synthétiseurs.

Le menu déroulant intégré du Mode Réalisateur permet de choisir l'accent directement à partir d'une seule liste. Les options disponibles sont :
Anglais (Samantha / Mark — Vocalizer/Apple, Zira / Hazel — OneCore)
Russe (Milena — Vocalizer/Apple, Irina / Pavel / Yuri — OneCore, eSpeak)
Polonais (Ewa — Vocalizer, Paulina — OneCore)
Allemand (Markus / Stefan — Vocalizer/Apple, Hedda / Katja — OneCore)
Espagnol (Jorge / Monica — Vocalizer/Apple, Helena — OneCore)
Islandais (Gudrun — OneCore, eSpeak ; note : Vocalizer ne prend pas en charge cette langue !)
Italien (Alice / Luca — Vocalizer/Apple, Elsa — OneCore)
Finnois (Satu / Mikko — Vocalizer/Apple, Heidi — OneCore)
Et aussi deux options de nettoyage sans accent :
"Aucun (Nettoyage SANS normalisation des nombres)"
"Aucun (Nettoyage AVEC normalisation des nombres)"
L'option avec normalisation des nombres convertit automatiquement les chiffres en leur forme écrite (par exemple, 15 devient "quinze") avant le traitement — ainsi NVDA lit les nombres de manière fluide, et si le texte a un accent imposé, le nombre l'aura aussi, sans aucune exception.
Vous vous demandez probablement si le synthétiseur saura décliner ces nombres normalisés en fonction du contexte ? La réponse est : non. Et c'est une fonctionnalité délibérée. Comme on le sait bien : "la langue polonaise être difficile" — et un étranger écorchant notre grammaire ne fait qu'ajouter à l'authenticité de l'accent cassé !

Réparateur de Balises (NOUVEAUTÉ dans la version 9) : À la fin de la liste, vous trouverez une option supplémentaire — le Réparateur de Balises. Il n'applique aucune règle phonétique ni de nettoyage. Il fait une chose : injecte dans le fichier le code de langue ISO à deux lettres que vous fournissez (par exemple, "fi" pour le finnois, "en" pour l'anglais). Utile lorsque vous avez déjà un fichier prêt — par exemple, précédemment traduit par le Traducteur IA — mais qui est sorti avec une balise de langue incorrecte ou manquante. Au lieu de le traduire à nouveau, vous lancez simplement le Réparateur avec le bon code ISO et en un rien de temps, vous avez un fichier corrigé.

Le script nettoie les didascalies entre parenthèses — il supprime tous les fragments de texte entre parenthèses (par exemple, "(avec des respirations intégrées)", "(en chuchotant)", "(ironiquement)"). ElevenLabs doit lire uniquement les dialogues et la narration, et non les instructions de mise en scène intégrées dans le texte.

Le script nettoie également les balises Markdown — il supprime les hashtags des en-têtes (par exemple, #, ##, ###), les signes égaux utilisés comme soulignements d'en-têtes, ainsi que les virgules orphelines qui pourraient perturber le rythme de lecture par le synthétiseur.

- Bouclier de protection : Le script protège toutes les balises HTML. Il ne détériore que les dialogues et la narration.
- Fonctionne localement et ne coûte rien !

Chiffre : Inverseur de Texte

Cette fonction inverse les phrases, mais d'abord elle développe les abréviations françaises courantes. Par exemple, "p. ex." devient "par exemple", "c.-à-d." devient "c'est-à-dire", etc. Sans cette expansion, les abréviations pointées se renverseraient en un non-sens phonétique (exemple français : ".xe.p").

Chiffre : Typoglycémie

Selon une recherche à l'Université de Cambridge, il n'importe pas dans quel ordre les lettres dans un mot sont, la seule chose importante est que la première et la dernière lettre soient à la bonne place.


Tryb 3 : Chiffreur (NOUVEAUTÉ dans la version 13.0 — jeux de texte, gratuit, local)

Le troisième RadioButton dans Polyglot, à côté du Traducteur IA et du Mode Réalisateur : « Mode Chiffreur (jeux de texte, découpage aléatoire) ». Il active six algorithmes locaux de distorsion de texte — pour des jeux, des énigmes, des casse-têtes linguistiques. Après avoir sélectionné le mode, une liste déroulante d'algorithmes apparaît, et pour l'un d'eux (Chiffre de César), un champ numérique supplémentaire pour le décalage.

Algorithmes disponibles (sélectionnez dans le menu « Choisir l'algorithme de distorsion ») :

- Inverseur de Texte (Lecture à l'envers avec une majuscule) — chaque phrase est inversée caractère par caractère, en conservant le point/exclamation/interrogation à la fin et la majuscule au début. Avant l'inversion, le script développe les abréviations populaires (p. ex., c.-à-d., etc., M., Dr, etc.), pour que le résultat après inversion ait encore du sens — sans cela, « p. ex. » après inversion devient un absurde « .xe ».

  Inspiration : mission du programme « The Traitors. Traîtres ». Quand l'animatrice a montré sans préavis aux participants une chanson populaire polonaise de dessin animé — simplement jouée à l'envers — les réactions allaient dans le style « quelle est cette langue ? », « c'est peut-être de l'arménien », « hongrois ou finnois ». La mission proprement dite consistait en ce qu'une équipe recevait dans la forêt le texte de la chanson écrit à l'envers, devait la chanter sous cette forme inversée, l'autre équipe l'enregistrait, la jouait à l'envers — et en théorie récupérait la chanson originale à deviner. Exactement le même malentendu phonétique amusant est généré par notre Inverseur lorsque vous passez le fichier traité par un synthétiseur TTS.

- Typoglycémie (Milieu des mots mélangé) — effet psycholinguistique classique : « Vous puoevz lirre un txete peu i'moprte l'odrre des ltteers, tnat que la piremère et la derinère ltteer sont à la bnnoe pclae ». Le script mélange aléatoirement le milieu de chaque mot de plus de 4 lettres, la première et la dernière lettre restent intactes. Idéal pour tester « combien je vois vraiment, et combien mon cerveau devine ».

- Téléphone Cassé / Dialecte Serpent — chaque « s », « z » ou digramme « sz » est allongé aléatoirement en un sifflement de 4 à 8 caractères (« sssssss », « zzzzzzz », « sssssssz »). Inspiration : Snecko du jeu « Slay the Spire ». Effet : le texte semble lu par un serpent avec un défaut de prononciation.

- Voyelliseur (Tout résonne en « O ») — chaque voyelle dans le texte est remplacée par « o », en conservant les adoucissements polonais. « Bonjour » → « Bonjoor ». Plus le texte est long, plus l'effet est amusant (et le lecteur d'écran le lit avec pleine conviction).

- Bégaiement Fort / Robot Endommagé — ajoute des bégaiements au début des mots : « co-co-co-computer », « do-do-do-douche ». Pour les mots courts (moins de 3 lettres), l'algorithme les ignore. Si la deuxième lettre du mot est une consonne, il répète les deux premières lettres (effet plus naturel) ; si c'est une voyelle — il ne répète que la première.

- Chiffre de César (décalage de l'alphabet FR) — chiffre de substitution classique : chaque lettre est décalée de N positions dans l'alphabet français (ABCD…ÛÜŸ, 40 caractères avec lettres accentuées). Vous entrez la valeur du décalage dans le champ numérique « Décalage du chiffre de César (0 = aléatoire, plage -39…39) ». Si vous entrez 0 — l'application choisira un décalage aléatoire dans la plage 1-38 et l'affichera dans un message après la fin (pour que vous puissiez ensuite déchiffrer). Les caractères hors alphabet (chiffres, ponctuation, espaces) restent inchangés.

Application pratique : les chiffres enregistrent le résultat dans le même format que le Mode Réalisateur (.html avec balise lang ou .docx avec balises XML), donc NVDA les lira avec la voix de la langue appropriée. En particulier, l'Inverseur et le Voyelliseur sonnent beaucoup plus intéressants dans le synthétiseur que lorsque vous les lisez avec vos yeux — car le cerveau lors de la lecture visuelle essaie automatiquement de « décoder » le texte, tandis que le TTS le lit exactement tel qu'il est écrit.

Les six chiffres sont également décrits dans un langage plus large et accessible dans le fichier docs/dictionaries.pl.txt du package de l'application — avec des conseils sur la façon d'ajouter votre propre chiffre de type « substitution de lettres » sans connaissance en programmation (par exemple, langage argot scolaire, langue de bois).


Détection de la langue

Avant que le script ne "détériore" le texte, il vérifie dans quelle langue il est écrit. S'il détecte que ce n'est pas du polonais, il affichera un avertissement. Les règles phonétiques sont conçues pour le polonais — les appliquer à un texte dans une autre langue donnerait des résultats imprévisibles.


Accents optimisés pour les synthétiseurs locaux (NVDA)

Les accents ont été conçus à 100 % pour les synthétiseurs-lecteurs d'écran locaux, gratuits et payants — Vocalizer et eSpeak dans NVDA. Cela garantit la stabilité et la prévisibilité du résultat sur chaque ordinateur.

Pourquoi pas ElevenLabs ? Les tests sur des documents plus longs ont montré que la distorsion phonétique du texte dans des moteurs comme ElevenLabs n'impose pas l'accent souhaité — le moteur "devine" simplement la langue et en fait plutôt un accent slave occidental/sud. Les synthétiseurs locaux NVDA sont beaucoup plus obéissants à cet égard.


Spécificité des synthétiseurs vocaux locaux (TTS)

Différents moteurs TTS se comportent différemment. Voici les principales différences qui influencent directement le fonctionnement des accents :

eSpeak (Open Source)
Un moteur léger et gratuit avec une vaste base de langues — prend en charge notamment l'islandais. Très strict en matière de codage des caractères, ce qui le rend prévisible. Cependant, il présente des défauts phonétiques : il partage souvent des phonèmes entre les langues, ce qui fait que, par exemple, l'ukrainien sonne avec une teinte russe.


Tiflotecnia Voices pour NVDA (voix Cerrence — anciennement Vocalizer de Nuance)

Tiflotecnia Voices est le successeur direct de Vocalizer de Nuance — un moteur commercial avec des voix de nouvelle génération de la société Cerrence, distribué sous forme de paquet .nvda-addon dans le NVDA Add-on Store. L'ancien Vocalizer (bibliothèques .dll 32 bits de Nuance) a été abandonné avec NVDA 2026.1 ; Cerrence a recompilé les voix en 64 bits et Tiflotecnia les a publiées sous un nouveau nom. La qualité de la prononciation est sensiblement meilleure que dans la génération précédente.

Comment installer : NVDA → Outils → Add-on Store → recherchez « Tiflotecnia Voices for NVDA » → Installer. Après l'installation, un sous-menu dédié « Tiflotecnia Voices » apparaîtra dans le menu NVDA ainsi qu'une catégorie propre dans les paramètres de NVDA. L'interface utilisateur du module complémentaire guide pas à pas à travers l'achat de la licence (ou l'activation d'une période d'essai de 7 jours), le choix et l'installation des premières voix (par exemple, la voix polonaise Ewa pour une lecture fluide des contrôles système, la voix finlandaise Satu pour les accents dans Polyglot). L'aide intégrée du module complémentaire est claire, donc nous ne répétons pas la procédure ici — il suffit de se laisser guider par le module complémentaire.

Conseil pour ceux qui migrent de Vocalizer et Eloquence : une mise à niveau à un prix réduit est disponible. Procédure : après un paiement réussi, écrivez immédiatement un e-mail à l'adresse liée sur l'écran de succès du paiement et demandez la validation de l'ancien code d'activation — Tiflotecnia confirmera le droit à la réduction et ajustera le prix. Sans cet e-mail, le système vous considère comme un nouveau client.

Disponibilité des voix : Tiflotecnia Voices prend en charge la plupart des langues que Vocalizer avait (y compris le polonais, l'anglais, l'allemand, le français, l'espagnol, le finlandais, l'italien, le russe). La liste des voix par langue est visible dans la catégorie des paramètres du module complémentaire avant l'achat de la licence.


Microsoft OneCore
Voix gratuites intégrées dans Windows (Mobile Voices). Un bon compromis entre qualité et disponibilité des langues. Offre une haute qualité et dispose d'un support pour la langue islandaise (Gudrun), finnoise (Heidi) et italienne (Elsa). Remarque : OneCore ne prend PAS en charge nativement le changement automatique de langue basé sur les balises lang (à moins que vous n'utilisiez le lecteur d'écran intégré du système, le narrateur) — voir la section ci-dessous.

Comment télécharger les voix OneCore sur Windows ? Les voix OneCore sont gratuites, mais la plupart des langues ne sont pas installées par défaut. Pour télécharger les langues manquantes, allez dans Paramètres Windows → Heure et langue → Voix → Gérer les voix (ou "Ajouter des voix"). Sélectionnez la langue dans la liste (par exemple, Islandais, Finnois, Italien) et cliquez sur Télécharger. Après le téléchargement, la voix apparaîtra automatiquement dans NVDA — sans aucune configuration supplémentaire.


Apple (iPhone / iPad / Mac) — VoiceOver avec Vocalizer
Sur les appareils Apple, le moteur Vocalizer est intégré nativement dans le système d'exploitation et prend en charge toutes les langues sans achats supplémentaires. Cependant, les versions compactes des voix sont installées par défaut et peuvent sembler un peu mécaniques. Pour obtenir un son bien meilleur et plus naturel, il est conseillé de télécharger les versions étendues ou premium :
- Sur iPhone/iPad : Réglages → Accessibilité → VoiceOver → Voix → choisir la langue (p. ex. Finnois) → toucher le nom de la voix (p. ex. Satu) → vous verrez les options "Étendu" et "Premium". Téléchargez la version choisie — elle prend plus de place sur le disque, mais la différence de qualité est notable.
- Sur Mac : Préférences Système (ou Réglages Système) → Accessibilité → VoiceOver → Ouvrir l'utilitaire VoiceOver → Voix → cliquez sur "Personnaliser" à côté de la voix choisie et téléchargez la version étendue ou premium.


Android — Vocalizer payant pour chaque voix
Sur Android, Vocalizer est disponible en tant qu'application sur le Google Play Store (recherchez "Vocalizer TTS"). Attention : chaque langue et voix est achetée séparément — il n'existe pas de licence unique pour tout. Avant l'achat, vous pouvez tester la voix pendant quelques minutes en mode démo. Après l'achat, la voix est associée à votre compte Google et peut être installée sur n'importe quel appareil utilisant le même compte.


Killer Feature pour les malvoyants : Fichiers avec balises linguistiques

C'est une véritable révolution. Les fichiers traités sont maintenant enregistrés comme suit :

- .html avec un attribut lang (par exemple, lang="fi" pour le finnois) — NVDA lit cette balise et bascule automatiquement sur le synthétiseur vocal approprié. Zéro configuration manuelle !
- .docx en conservant le formatage — chaque segment de texte a une balise linguistique injectée dans le XML du document, donc Word et NVDA savent quelle voix utiliser pour chaque partie.

Les fichiers traités sont toujours enregistrés comme de NOUVEAUX documents (par exemple, accent_Finski.html).


Automatisation du changement de langue dans NVDA — ce que vous devez savoir

Pour que NVDA change effectivement de voix en fonction de la balise lang, le paramètre "Changer automatiquement de langue si pris en charge" doit être activé. Vous le trouverez dans Préférences NVDA → Voix. Par défaut, il est activé lors du premier lancement du lecteur d'écran — mais il est bon de vérifier si quelqu'un ne l'a pas désactivé.

Limitation importante des voix OneCore : Les voix Microsoft OneCore ne prennent pas en charge ce mécanisme avec NVDA de manière native, mais uniquement avec le narrateur intégré de Windows. Il existe un module complémentaire non officiel pour NVDA appelé "One Core Autolang" qui tente de résoudre ce problème — mais son développement a été rapidement interrompu. La raison est simple : chaque année, avec la première version de NVDA de l'année, des changements rompent la compatibilité API (appelés API Breaking Changes). Parfois, il suffit de mettre à jour le champ "last tested version" dans le manifeste du module, mais parfois de véritables modifications du code sont nécessaires — et l'auteur ne parvient pas à suivre les mises à jour. Si vous tenez à l'automatisation du changement de langue, un choix plus sûr est Tiflotecnia Voices (payant, section ci-dessus) ou eSpeak (gratuit, de moindre qualité), qui prennent en charge ce mécanisme de manière native — mais attention : actuellement, dans Tiflotecnia Voices, cela fonctionne avec un bug de priorités (voir "Astuce critique" ci-dessous). Après avoir appliqué le patch, le changement automatique fonctionne parfaitement, comme dans l'ancien Vocalizer.


Krytyczny problème avec Tiflotecnia Voices : détection de langue défectueuse

D'abord, la bonne nouvelle — l'alerte concernant NVDA 2026.1 des versions précédentes du manuel s'est terminée par une fin heureuse : Cerrence a fourni des bibliothèques 64 bits, Tiflotecnia les a publiées dans un paquet .nvda-addon disponible dans l'Add-on Store (section ci-dessus), et Vocalizer, pour ceux qui l'ont conservé jusqu'à la fin, est revenu sous un nouveau nom — avec une meilleure qualité et sans les limitations 32 bits.

Cependant, avec le lancement de Tiflotecnia Voices, un nouveau problème critique est apparu — dans la détection de langue. Dans les paramètres de l'extension, on peut configurer quelle voix doit être utilisée pour certaines lettres (par exemple, latines, cyrilliques) en fonction des voix installées. Le problème réside dans l'ordre des priorités : actuellement, on applique d'abord le remplacement par lettre, puis le retour au code ISO de la langue (en pratique inatteignable pour le MÊME alphabet auquel le remplacement s'est déjà adapté), et enfin la voix choisie. Le résultat apparaît au sein du même alphabet : vous avez un texte en finnois avec la balise correcte `lang="fi"`, Satu installée comme voix finnoise de Tiflotecnia, MAIS dans les paramètres, une voix polonaise est définie pour les lettres latines — Satu NE lira PAS ce texte, malgré la balise ISO correcte. Le remplacement par lettre « voix polonaise pour le latin » l'emporte au premier niveau, l'ISO `fi` n'est jamais vérifié. Pour les paires d'alphabets différents, le mécanisme fonctionne correctement (texte russe + Milena pour le cyrillique + voix polonaise pour le latin — tout le cyrillique est lu par Milena, les éventuels noms propres latins par la voix polonaise ; chaque alphabet reste dans son remplacement). Après la migration de Vocalizer, où le changement de langue basé sur l'ISO fonctionnait parfaitement, les utilisateurs remarqueront cette régression immédiatement — en particulier ceux qui utilisent plusieurs accents européens dans Polyglot (Satu, Alice, Markus) sur le même ensemble de lettres latines.

Diagnostic et correctif : j'ai diagnostiqué le problème au niveau de Python dans le code de l'extension et préparé un correctif modifiant l'ordre des priorités en : ISO → voix choisie → remplacement par lettre. Le correctif conserve le changement utile vers le latin pour les noms latins dans un texte russe, lorsque l'option « détection de langue basée sur les caractères Unicode » est activée dans les paramètres. J'ai envoyé le correctif aux développeurs de Tiflotecnia il y a 5 jours — pour l'instant sans réponse.

Que faire en attendant : si vous tenez à une détection correcte de la langue (cela vaut la peine — c'était l'une des fonctionnalités phares de l'ancien Vocalizer, voir « Fonctionnalité phare pour les aveugles » ci-dessus), ouvrez un problème dans le dépôt de l'application sur GitHub avec l'étiquette `tiflotecnia-patch` et votre adresse email dans le contenu. Un bot automatique fermera immédiatement le problème avec une confirmation de soumission (sans trace dans le fil public), et vous recevrez le correctif par email généralement dans quelques jours. Le correctif lui-même N'EST PAS publié dans le dépôt de l'application ni comme Gist — Tiflotecnia Voices for NVDA est un logiciel commercial, et la licence de l'extension n'autorise pas la redistribution de ses fichiers, même modifiés. Après avoir reçu le correctif, son contenu doit être copié dans `%appdata%\Roaming\nvda\addons\TiflotecniaVoices`, en remplaçant les fichiers. Attention lors de la copie : si Windows n'a pas demandé de remplacement, vous avez probablement copié tout le dossier `TiflotecniaVoices_edits` avec son contenu AU LIEU du contenu lui-même — dans ce cas, entrez dans le sous-dossier créé, coupez tout, collez un niveau plus haut et écrasez. Après avoir appliqué correctement le correctif, redémarrez NVDA — vous profitez de la meilleure qualité des voix Cerrence 64 bits et de la détection correcte de la langue, soit une combinaison introuvable chez un seul fabricant sur le marché. Nous supposons bien sûr que vous avez une licence valide pour Tiflotecnia Voices — nous ne vérifions pas cela, mais vous ne pourrez pas appliquer le correctif sur un dossier étranger sans licence.


KROK 6 : Architecte des Livres Audio

Outil pour préparer une structure de fichier professionnelle pour les lecteurs d'écran et ElevenLabs. Accédez-y en cliquant sur le bouton "📄  Convertisseur" dans la barre de boutons ou en sélectionnant Outils → Convertisseur dans le menu (raccourci : Ctrl+3).

Comment ça fonctionne ?

1. Entrez le chemin du fichier source dans le champ texte ou cliquez sur le bouton "Parcourir..." pour sélectionner un fichier dans la boîte de dialogue système. Le script accepte les fichiers .txt, .docx ainsi que les fichiers .html et .htm.
2. Cliquez sur "Construire l'Architecture pour ElevenLabs".
3. Le script scanne chaque ligne de texte et remplace les mots-clés (Acte, Chapitre, Prologue, Épilogue, Introduction) par des en-têtes "Heading 1" dans le document Word.
4. Les scènes (lignes commençant par le mot "Scène") sont transformées en texte en gras — visible dans le document, mais invisible dans la table des matières d'ElevenLabs.
5. Tout le texte restant (dialogues, descriptions) est laissé inchangé.
6. Vous recevrez un fichier architecture_[nom_original].docx — un document Word professionnel prêt pour un travail ultérieur. Par exemple, si votre fichier d'entrée s'appelait indifférence.txt, le fichier de sortie s'appellera architecture_indifférence.docx et apparaîtra dans le même dossier que l'original.

Nettoyage en passant : Le script supprime automatiquement les balises HTML (si le texte provient d'un navigateur ou d'un fichier .html local, par exemple généré par Poliglot) ainsi que les balises d'en-tête Markdown (par exemple ### ou ####) avant le traitement. Vous n'avez pas besoin de nettoyer le fichier manuellement.

Mode Histoire : regroupement automatique des tours en scènes (à partir de la v15.1)

Si vous chargez dans l'Architecte un fichier scripts/<jeu>.txt généré par le module Histoires Interactives, le convertisseur reconnaîtra les marqueurs de tour (par exemple, « --- Tour 7 ---") dans 9 langues (Tour, Turn, Runde, Turno, Vuoro, Tour, Umferð, Turno, Ход) et insérera un nouvel en-tête de premier niveau toutes les cinq tours sous la forme « Scène N" (le numéro commence à 1, local pour chaque langue — en anglais "Scene N", en allemand "Szene N", etc.). Les autres marqueurs de tour sont supprimés — ils n'apparaissent pas dans la narration du livre audio, car « Tour 7" prononcé par TTS brise l'immersion de l'auditeur. Le résultat est un fichier Word avec une division naturelle en scènes de quelques minutes audio chacune, prêt à être importé dans ElevenLabs. Le mécanisme est auto-détectable — les fichiers audio classiques sans marqueurs de tour (narration classique du Réalisateur) sont traités exactement comme auparavant.

Un avantage puissant pour les utilisateurs de NVDA et ElevenLabs

Le formatage "Heading 1" pour les chapitres n'est pas seulement esthétique. Dans NVDA, vous pouvez naviguer rapidement entre les en-têtes en appuyant sur la touche H (ou 1 pour les en-têtes de premier niveau). Au lieu de faire défiler des centaines de pages, vous passez d'un chapitre à l'autre en une fraction de seconde. Cela change la façon de travailler avec de longs documents. Dans ElevenLabs, vous avez la garantie que le moteur insérera automatiquement des coupures et ne se bloquera pas lors de la réalisation de clips audio.


KROK 7 : Comment écrire le Livre du Monde (Prompt de l'Architecte et Mini-cours Markdown)

L'intelligence artificielle alimentant le Studio Principal comprend le mieux les commandes lorsqu'elles sont formatées en langage de balisage Markdown. Si vous fournissez à l'IA dans le Réalisateur seulement une idée vague (par exemple, "deux sœurs dans l'au-delà"), la machine paniquera par manque de détails et créera une histoire banale et prévisible, ignorant la logique.

Pour éviter cela, utilisez un chatbot externe (par exemple, le ChatGPT ou Claude gratuit) comme votre Architecte personnel. Dans la version 13.0, vous n'avez plus besoin de recopier le prompt à partir des instructions — dans le panneau du Réalisateur, juste en dessous du bouton «💾 Sauvegarder la Bible de manière permanente», vous trouverez le bouton «📖 Prompt de l'Architecte pour l'IA…». Cliquez dessus, et une fenêtre de dialogue s'ouvrira avec le texte du prompt prêt dans un champ «lecture seule» ainsi qu'un bouton «Copier dans le presse-papiers». NVDA annonce tout le contenu dès l'ouverture de la fenêtre — il suffit de cliquer sur «Copier», de coller (Ctrl+V) dans ChatGPT/Claude et de remplacer le segment «[INSÉREZ VOTRE IDÉE ICI]» par votre propre ébauche d'intrigue.

Pourquoi ainsi, et non par copie depuis les instructions ? Le dialogue dans l'interface graphique a un avantage clé en termes d'accessibilité : il est natif et lu sans perturbation par le lecteur d'écran, ne nécessite pas de basculer vers un éditeur de texte (où les accents français et les guillemets peuvent être mal copiés) et fonctionne de manière identique sur chaque système d'exploitation. Le même modèle — un dialogue avec un prompt à copier — est également utilisé dans le Gestionnaire de Règles (voir KROK 7b ci-dessous).

Comment l'IA répond : Vous recevrez une réponse en deux parties. La première est le Livre du Monde enfermé dans un bloc de code Markdown (balises ```markdown … ```). Copiez UNIQUEMENT le contenu du bloc de code (sans les balises ```) et collez-le dans le champ «Livre du Monde» dans le Réalisateur, puis cliquez sur «💾 Sauvegarder la Bible de manière permanente». La deuxième partie est une recommandation sur lequel des modes créatifs (Script ou Audiobook) convient le mieux à votre idée — considérez-la comme une suggestion lors de la sélection du mode dans le RadioBox.

Mini-cours Markdown dans le Livre : un seul hashtag (#) est une section principale (par exemple, «# Personnages»), un double hashtag (##) est une sous-section, les tirets (-) créent des listes, et les doubles astérisques (**texte**) mettent en gras les règles absolues et inviolables (par exemple, «**Le héros NE ment JAMAIS**»). Pour un personnage parlant une langue étrangère, ajoutez une étiquette avec l'accent, par exemple, «[Speaker 1: Marek] - a un accent polonais». Le mot-clé «accent» est NÉCESSAIRE — le moteur de l'application le détecte automatiquement et applique les règles phonétiques correctes aux dialogues du personnage.

Astuce : N'oubliez pas de mettre à jour régulièrement votre Livre du Monde (avec l'expansion de l'intrigue à de nouveaux lieux ou personnages importants). Vous pouvez le faire manuellement ou avec l'aide d'un chatbot externe. Plus le fondement est riche, meilleurs seront les résultats en Réalisation !


KROK 7b : Gestionnaire de Règles (Ctrl+4) — dictionnaires pour les linguistes sans Python

La version 13.0 introduit un quatrième outil dans la barre : le Gestionnaire de Règles. Vous l'ouvrez avec la touche Ctrl+4 ou depuis le menu Outils. C'est un explorateur visuel du dossier dictionaries/, où l'application stocke toutes les règles phonétiques (accents), les chiffres et les modes du Réalisateur dans des fichiers YAML (format lisible par l'homme, plus simple que JSON).

Pourquoi utiliser YAML ? Jusqu'à la version 12.0, tous les accents, modes créatifs et filtres étaient « intégrés » dans le code Python. Ajouter un nouvel accent nécessitait un programmeur. Dans la version 13.0, tout a été déplacé vers des fichiers .yaml dans le dossier dictionaries/ — toute personne capable d'ouvrir le Bloc-notes peut ajuster un accent existant (« remplacer sz par sh par sch ») ou en ajouter un complètement nouveau (suédois, danois, dialecte russe).

Ce que vous trouverez dans le Gestionnaire de Règles :
- Arborescence des fichiers — liste complète de tous les fichiers YAML dans dictionaries/ avec une répartition par langues sources (actuellement complètement implémentées : Polski, Deutsch, English, Español, Suomi, Français, Íslenska, Italiano, Русский) et catégories (accents/, chiffres/, réalisateur/). Navigation avec les flèches comme dans l'Explorateur de fichiers Windows, support complet de NVDA.
- Bouton « 📝  Ouvrir dans l'éditeur de texte » — ouvre le fichier sélectionné dans le Bloc-notes par défaut du système. Vous éditez, enregistrez, cliquez sur « 🔄  Actualiser l'arborescence » et c'est prêt.
- Bouton « 📋  Dupliquer le fichier sélectionné » — le moyen le plus rapide pour un nouvel accent : vous prenez un fichier existant (par exemple finski.yaml), donnez un nouveau nom (par exemple suédois), le Gestionnaire crée une copie avec le commentaire « changez les champs étiquette et description » et l'ouvre dans l'éditeur.
- Bouton « ➕  Nouveau fichier de règles… » — assistant avec choix du type (accent, chiffre, mode Réalisateur, nouvelle langue source, chiffre algorithmique). Pour les cas simples (accent, chiffre de type « remplacement de lettres »), l'assistant crée un modèle YAML prêt à éditer. Pour les cas nécessitant un programmeur (nouvelle langue source, algorithme de type « mélange du milieu des mots »), l'assistant génère une invite pour le chatbot AI — vous collez dans ChatGPT, obtenez un fichier YAML prêt, enregistrez dans dictionaries/ et c'est prêt.

Application pratique : Vous voulez ajouter un accent suédois ? Ouvrez le Gestionnaire de Règles, choisissez dictionaries/pl/accents/finski.yaml, cliquez sur « Dupliquer », nommez le fichier suédois, changez dans celui-ci le champ étiquette en "Suédois (Alva / Oskar)", le code iso en sv, modifiez quelques règles de remplacement et enregistrez. Retournez à la Page d'accueil, cliquez sur « 🔄 Actualiser les accents Réalisateur depuis YAML » et relancez l'application. Le nouvel accent apparaîtra dans le menu Polyglotte (en Mode Réalisateur) et — si vous l'ajoutez au Livre du Monde des personnages (« [Marek] - a un accent suédois ») — également dans la détection automatique des accents du Réalisateur.

Où chercher plus de documentation sur le dossier dictionaries/ :
- Fichier `docs/dictionaries.pl.txt` (disponible dans le package pour les utilisateurs finaux depuis l'onglet Releases) — description courte, en langage simple, de chaque sous-dossier, 6 chiffres prêts, 8 accents prêts et des idées de ce que vous pouvez faire vous-même, sans connaissance de Python.
- Fichier `dictionaries/README.md` (disponible uniquement lors du clonage du dépôt depuis GitHub — les packages de distribution filtrent les fichiers .md) — documentation technique détaillée du format YAML avec des exemples, des listes de champs, des règles de pipeline, des regex. Ce document est destiné aux linguistes connaissant les bases de la programmation ainsi qu'aux développeurs.

Ważne wskazówki dla użytkowników czytników ekranu (NVDA)

1. Komunikaty o sukcesie i błędach

Lorsque l'application termine une action (par exemple, enregistre un fichier ou rencontre une erreur), une boîte de dialogue apparaît avec un titre tel que "Succès", "Avertissement" ou "Erreur". NVDA annoncera immédiatement cette fenêtre et lira son contenu. Vous n'avez rien à faire — les dialogues sont entièrement accessibles au clavier, et le focus se place automatiquement sur le bouton "OK". Il n'y a plus de ruses avec le préfixe "Alerte" — les boîtes de dialogue natives wxPython sont directement prises en charge par le lecteur d'écran.

2. Avertissement important : traitement silencieux en arrière-plan

Après avoir cliqué sur des boutons tels que "Envoyer à l'IA" ou "Lancer le Traitement", le programme commence immédiatement le traitement en arrière-plan. Une barre de progression (Gauge) apparaît à l'écran, mais NVDA NE lit PAS sa valeur en temps réel — le lecteur d'écran reste silencieux pendant le travail. Ne cliquez pas à nouveau sur le bouton. Attendez qu'une boîte de dialogue avec le résultat ou un message d'erreur apparaisse — NVDA l'annoncera automatiquement.

3. Navigation entre les outils

La navigation entre les outils (Réalisateur, Polyglotte, Convertisseur, Gestionnaire de Règles) se fait dans une seule fenêtre de programme à l'aide de quatre boutons sur la barre d'outils ou via le menu Outils (Alt, puis N). Raccourcis clavier disponibles : Ctrl+0 (Page d'accueil), Ctrl+1 (Réalisateur), Ctrl+2 (Polyglotte), Ctrl+3 (Convertisseur), Ctrl+4 (Gestionnaire de Règles — nouveauté en 13.0). Après avoir changé d'outil, le focus se place automatiquement sur la description du nouveau module — NVDA commence immédiatement à lire la nouvelle vue.

4. Ordre de tabulation et noms des widgets

Chaque élément de l'interface a un nom français lisible — NVDA le lira lorsqu'il sera focalisé. L'ordre de tabulation est logique : de la description de l'outil, en passant par les champs de configuration, jusqu'aux boutons d'action. Il n'y a pas de surprises ici — la navigation au clavier fonctionne comme dans n'importe quel autre programme natif Windows. Tous les menus et boutons sont en français et NVDA les lira avec une voix française sans aucun réglage supplémentaire.


Ważne uwagi do wersji 9.0 / Changelog

Nowe funkcje i zmiany w wersji 9

Odporny na awarie zapis postępu tłumaczenia (ZMIANA — naprawa krytycznego buga)
W wersji 8 wznawianie przerwanego tłumaczenia było obarczone cichą, destrukcyjną pułapką: jeśli użytkownik zastosował się do instrukcji (ręczne wycięcie przetłumaczonego fragmentu), a potem od razu wznowił tłumaczenie reszty, aplikacja otwierała plik wyjściowy w trybie nadpisywania — bezpowrotnie i bezwiednie kasując cały opłacony postęp. W wersji 9 cały mechanizm został przeprojektowany. Każdy przetłumaczony blok jest teraz natychmiast zapisywany do pliku tymczasowego (.jsonl) z przypisanym indeksem. Wznowienie jest w pełni automatyczne — aplikacja sama wykrywa plik i odtwarza postęp bez żadnej ingerencji użytkownika. Po udanym zakończeniu plik tymczasowy jest automatycznie usuwany.

Naprawiacz Tagów w Trybie Reżysera (NOWOŚĆ)
Do menu Trybu Reżysera dodano nową opcję — Naprawiacz Tagów. Wstrzykuje do pliku wyłącznie podany przez użytkownika dwuliterowy kod języka ISO, bez stosowania jakichkolwiek reguł fonetycznych ani czyszczenia. Narzędzie ratunkowe na wypadek, gdy gotowy już plik wyszedł z błędnym lub brakującym tagiem językowym.

Automatyczna konwersja .txt na .html w Trybie Tłumacza (ZMIANA)
Pliki tekstowe (.txt oraz .md) tłumaczone przez Tłumacza AI są teraz automatycznie zapisywane w formacie .html z wbudowanym tagiem językowym. Dzięki temu NVDA od razu odczytuje plik właściwym głosem — bez żadnych dodatkowych kroków ze strony użytkownika.

Inteligentne nazewnictwo pliku w Architekcie (ZMIANA)
Architekt Audiobooków nie zapisuje już wynikowego pliku zawsze pod tą samą nazwą architektura_gotowa.docx. Teraz nazwa wynika z pliku wejściowego — np. dla znieczulica.txt wynikowy plik to architektura_znieczulica.docx. Plik pojawia się w tym samym folderze co oryginał.

Funkcje zachowane bez zmian z wersji 8

Powrót do formatu .txt dla plików projektów (ZMIANA)
Pliki projektów i streszczenia zapisują się teraz w formacie .txt zamiast .md (Markdown). Eksperyment z formatem .md jako psychologiczną barierą przed edycją okazał się nieskuteczny — AI często notorycznie łamie zasadę anti-closure i często lepiej edytować plik na bieżąco i potem przeładowywać pamięć, by AI, w miarę możliwości, nie dostawało ukrytego przyzwolenia na łamanie zakazu. Format .txt jest bardziej intuicyjny i czytelny dla każdego.

Zasada Montażysty — nowe ostrzeżenie
W instrukcji (i w przyszłych wersjach interfejsu) dodano wyraźne ostrzeżenie wyjaśniające, co wolno, a czego nie wolno edytować w plikach projektów. Użytkownik ma pełne prawo do edycji dialogów i treści, ale absolutnie nie może modyfikować linii struktury (Akt, Scena, Rozdział, Prolog, Epilog) — ich uszkodzenie psuje nawigację NVDA, podział w ElevenLabs i spis treści w Wordzie.

Zaktualizowany Prompt Architekta (ZMIANA)
Prompt do zewnętrznego chatbota (ChatGPT/Claude) został przeprojektowany. Zamiast zwracać surowy kod Markdown, AI teraz zwraca odpowiedź w dwóch wyraźnie oddzielonych częściach: Część 1 to Księga Świata zamknięta w bloku kodu Markdown (łatwa do skopiowania bez znaczników), a Część 2 to Rekomendacja Trybu jako zwykły tekst poza blokiem — doradza, czy lepiej użyć Trybu Surowego Skryptu, czy Trybu Tradycyjnego Audiobooka. Zmieniono też opis tagów postaci: zamiast "dźwiękowych" mowa teraz o akcencie i tonie głosu w tagu, np. [Speaker 1: Imię] - sepleni i akcent francuski.

Wyjaśnienie stanu dyrektywy Anti-Closure (DOKUMENTACJA)
Instrukcja zawiera teraz szczere wyjaśnienie, że mimo wbudowanych zakazów Anti-Closure model nadal notorycznie łamie tę zasadę, szczególnie w Trybie Audiobooka. Zamiast ukrywać ten problem, wersja 8 stawia sprawę jasno i przekazuje odpowiedzialność za "ręczne domykanie" z powrotem do Reżysera — stąd Zasada Montażysty jako oficjalne narzędzie pracy i powrót do zwykłego formatu tekstowego.

Funkcje zachowane bez zmian z wersji 7

Prompty Showrunnerowe — Dyrektywa Anti-Closure (Reżyseria — wszystkie tryby)
Wszystkie trzy tryby Reżyserii zachowują wbudowane dyrektywy showrunnerowe. Burza Mózgów działa jak scenarzysta serialu wielosezonowego. Tryb Surowego Skryptu i Tryb Audiobooka mają zakaz kończenia tekstu podsumowaniami, morałami i klamrami narracyjnymi — z wyjątkiem sytuacji, gdy użytkownik wprost prosi o finał lub epilog.

Architekt Audiobooków
Narzędzie obsługuje słowa kluczowe Akt, Rozdział, Prolog, Epilog i Czołówka jako nagłówki pierwszego poziomu. Sceny zamieniają się w pogrubiony tekst. Skrypt automatycznie czyści tagi HTML i znaczniki Markdown przed przetworzeniem.

Inteligentne Zarządzanie Rozdziałami (Tryb Audiobooka)
Dedykowany panel z przyciskami do wstawiania Prologu, Epilogów i cięć rozdziałów bezpośrednio z interfejsu. Licznik rozdziałów aktualizuje się automatycznie. Wczytanie istniejącego pliku ustawia licznik na właściwy numer bez ręcznego liczenia.

Nadawanie Tytułów Rozdziałom (Postprodukcja — Tryb Audiobooka)
Moduł iteruje po rozdziałach z zapisanego pliku i nadaje im krótki, literacki tytuł przy użyciu szybkiego modelu AI, analizując tylko początki każdego rozdziału.

Nouvelles fonctionnalités et modifications dans la version 12.0 — Release Candidate

- Révision complète de l'interface utilisateur (CHANGEMENT ARCHITECTURAL). L'application n'est plus un outil web fonctionnant dans un navigateur. Toute l'interface a été réécrite à partir de zéro en tant qu'application de bureau native basée sur le framework wxPython. Il n'y a plus de serveur local, plus de navigateur, plus de fenêtre de terminal fonctionnant en arrière-plan — il y a une seule fenêtre normale du programme. Le point d'entrée est main.py.

- Barre de navigation avec raccourcis clavier (NOUVEAUTÉ). Les outils se changent par trois boutons sur la barre (Réalisateur, Polyglotte, Convertisseur) ou via le menu Outils. Raccourcis clavier disponibles : Ctrl+0 (Page d'accueil avec vérification du système), Ctrl+1 (Réalisateur), Ctrl+2 (Polyglotte), Ctrl+3 (Convertisseur). L'outil actif est visuellement mis en évidence par un bouton en gras.

- Optimisation complète pour les lecteurs d'écran dès le départ (NVDA, VoiceOver). Chaque widget a un nom d'accessibilité clair en polonais. Le focus, après le changement d'outil, se place automatiquement sur la description du module — NVDA commence immédiatement à lire la nouvelle vue. Les dialogues wx.MessageBox sont annoncés nativement par le lecteur d'écran sans aucun truc. L'ordre des tabulations est logique et cohérent dans toute l'interface. Les limitations historiques de Streamlit et du framework React disparaissent.

- Pas de configuration de pare-feu réseau (CHANGEMENT). L'élimination du serveur web local signifie que le pare-feu Windows n'affiche plus de fenêtre demandant l'autorisation d'accéder au réseau lors du premier lancement. L'application se lance simplement.

- Fenêtres de dialogue de sélection de fichiers natives (NOUVEAUTÉ). Les modules Polyglotte et Convertisseur possèdent désormais un bouton "Parcourir..." qui ouvre le dialogue de sélection de fichier du système au lieu de saisir manuellement le chemin.

- Protection du mode créatif (NOUVEAUTÉ). Dans le Réalisateur, il n'est plus possible de changer accidentellement le mode de travail (par exemple, d'Audiobook à Script) lorsque la mémoire est occupée — l'interface bloque le changement vers un autre mode d'enregistrement tant que l'historique ou le résumé n'est pas effacé. Le mode Brainstorming est toujours disponible.

- Bouton de Réinitialisation Dure dans le Réalisateur (NOUVEAUTÉ). Un nouveau bouton "Fermer le Projet (Réinitialisation Dure)" permet de nettoyer tout le projet d'un seul clic : historique, résumé, Livre du Monde et tous les compteurs — sans avoir à réinitialiser manuellement chaque champ séparément.

- Chargement automatique du mode créatif (NOUVEAUTÉ). Lors du chargement d'un projet, l'application restaure automatiquement le dernier mode de travail utilisé (Script ou Audiobook) à partir du fichier de métadonnées géré par l'application. Ainsi, lors de la réouverture du projet, le RadioBox se règle automatiquement — vous n'avez pas besoin de vous souvenir du mode dans lequel vous travailliez.

Nouvelles fonctionnalités et modifications de la version 13.0 — Release Candidate

- Refactorisation en YAML — accents, chiffres et modes du Réalisateur dans des fichiers texte (CHANGEMENT ARCHITECTURAL, le plus grand depuis la migration vers wxPython). Jusqu'à la version 12.0, toutes les règles phonétiques (accents) et les modes créatifs du Réalisateur (Tempête, Script, Livre audio, postproduction des titres) étaient "encodés" dans le code Python en tant que constantes, fonctions et chaînes de prompt rigides, et toute une catégorie de chiffres/jeux de texte n'existait tout simplement pas — ils sont introduits avec la refactorisation 13.0. Dans la version 13.0, tout cela se trouve dans des fichiers .yaml dans le nouveau dossier `dictionaries/` — le moteur (`core_poliglota.py`, `core_rezyser.py`, `przepisy_rezysera.py`) les charge dynamiquement au démarrage. Effet pratique : ajouter un nouvel accent, un nouveau chiffre basé sur des substitutions ou changer le son du prompt système pour un mode du Réalisateur ne nécessite pas de connaître Python — un éditeur de texte suffit. Une brève description pour les utilisateurs finaux se trouve dans `docs/dictionaries.pl.txt` (inclus dans les paquets des Releases) ; la documentation technique complète du format — dans `dictionaries/README.md` (uniquement dans le dépôt Git, car les paquets de version filtrent les fichiers .md).

- Gestionnaire de Règles — quatrième outil dans la barre (NOUVEAUTÉ, Ctrl+4). Explorateur visuel du dossier `dictionaries/` avec un arbre de fichiers YAML (wx.TreeCtrl natif, support complet NVDA) et un ensemble d'actions : « Ouvrir dans un éditeur de texte », « Nouveau fichier de règles... » (assistant avec choix du type : accent, chiffre, mode, nouvelle langue), « Dupliquer le fichier sélectionné », « Supprimer le fichier », « Rafraîchir l'arbre ». Pour les cas dépassant les simples substitutions (nouvelle langue de base, chiffre algorithmique), l'assistant génère un prompt prêt à être copié pour le chatbot AI — explication complète dans la nouvelle ÉTAPE 7b.

- Prompt de l'Architecte directement dans le panneau du Réalisateur (CHANGEMENT A11y). Jusqu'à présent, le prompt pour le chatbot externe pour générer le Livre du Monde n'existait que dans cette instruction — l'utilisateur devait le copier à partir d'un fichier texte (ce qui peut être problématique avec les lecteurs d'écran pour les caractères polonais et les guillemets). Dans la version 13.0, le panneau du Réalisateur dispose d'un nouveau bouton « 📖 Prompt de l'Architecte pour AI... » (juste en dessous de « Enregistrer le Livre de manière permanente »), qui ouvre une fenêtre de dialogue native avec le texte complet du prompt dans un champ READONLY et un bouton séparé « Copier dans le presse-papiers ». Le modèle A11y est identique à celui du dialogue de résultats de l'assistant dans le Gestionnaire de Règles — NVDA lit immédiatement tout le contenu de la fenêtre sans configuration supplémentaire. Description complète dans l'ÉTAPE 7 mise à jour.

- Accent russe dans le Polyglotte (NOUVEAUTÉ — huitième langue européenne dans le menu du Mode Réalisateur). L'option « Russe (p. ex. Milena / Irina / Yuri / Pavel) » est ajoutée à la liste déroulante « Mode Réalisateur / Accents ». Contrairement aux autres accents, qui ne font que « déformer » le texte polonais au niveau des lettres latines (p. ex. « sz » → « sh », « w » → « v »), l'accent russe effectue une translittération complète du texte polonais en cyrillique — permettant ainsi aux voix synthétisées TTS russophones (Vocalizer Milena, OneCore Irina / Pavel / Yuri, eSpeak « ru ») de « prononcer » les mots. Le mappage a été enrichi avec des voyelles iotisées (« ja » → « я », « je » → « е », « jo » → « ё », « ju » → « ю »), des adoucissements polonais si/ci/ni/zi + voyelle (p. ex. « ciocia » → « цёця »), ainsi que des digrammes spéciaux russes : « ść » / « szcz » → « щ », « sz » → « ш », « cz » → « ч », « rz » → « ж », « ch » → « х ».

  Remarque phonétique : L'accent n'est pas une translittération académique russe (ISO 9, GOST, BGN/PCGN). Le but est uniquement de rendre le texte polonais phonétiquement similaire au russe — pour les besoins de la synthèse vocale, pas pour une translittération sérieuse des noms propres. Pour ce dernier travail, utilisez des outils linguistiques dédiés.

  Code langue pour le fichier de sortie : « ru » (ISO 639-1). NVDA avec l'option « Changer automatiquement de langue lorsque pris en charge » activée passera immédiatement à la voix russe.

- Remarque sur « ź » : En russe, il n'y a pas d'équivalent exact du « ź » polonais, donc ce caractère est normalisé en « ж » — tout comme « ż ». Certains dialectes du nord de la Russie et le biélorusse prononcent « ź » plus proche de « зь », mais du point de vue du synthétiseur vocal, la différence est négligeable. Si un linguiste préfère « зь », il peut remplacer cette règle dans le fichier `dictionaries/pl/akcenty/rosyjski.yaml` — le moteur charge les YAML de manière dynamique, donc cela ne nécessite pas de recompilation de l'application.

- Barre de navigation étendue et menu Outils (CHANGEMENT). La barre a maintenant un quatrième bouton — Gestionnaire de Règles — et le menu « Outils » prend en charge le nouveau raccourci Ctrl+4. Les raccourcis existants (Ctrl+0 Accueil, Ctrl+1 Réalisateur, Ctrl+2 Polyglotte, Ctrl+3 Convertisseur) restent inchangés.

- Bouton « Rafraîchir les accents du Réalisateur à partir de YAML » sur la page d'accueil (NOUVEAUTÉ). Après avoir ajouté un nouvel accent via le Gestionnaire de Règles (ou une édition manuelle du fichier YAML), cliquer sur ce bouton rechargera les wrappers accent_* dans le moteur du Polyglotte et du Réalisateur, afin que le nouvel accent soit visible dans le menu et dans la détection automatique des accents basée sur les tags de personnages dans le Livre du Monde. Le Polyglotte détecte les YAML automatiquement (sans rafraîchissement), mais le Réalisateur nécessite une régénération des wrappers — généralement, après le rafraîchissement, il faut encore redémarrer l'application.
