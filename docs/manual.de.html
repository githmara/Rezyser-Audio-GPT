Reżyser Audio GPT — Komplettanleitung (Version 18.20.0 – Release-Version)

Willkommen im Hybriden Aufnahmestudio! Dieses Toolset ermöglicht das automatische Schreiben, Planen, Formatieren und Übersetzen von Hörspiel- und Hörbuchskripten. Es wurde für die Zusammenarbeit mit professionellen Sprachsynthesizern und lokalen Screenreader-Engines (NVDA) optimiert.

Das Set besteht aus dem Hauptstudio (Regie), einem Übersetzungs- und Akzentwerkzeug (Polyglott), einem Werkzeug zum Erstellen der Dateistruktur (Hörbucharchitekt), einem Regelmanager (ab Version 13.0 — ohne Python kannst du einen neuen Akzent, ein Chiffre oder einen kreativen Modus hinzufügen, siehe SCHRITT 7b unten) und — ab Version 15.0 — einem Geschichtenmodul (interaktive, zweite Person AI-generierte Fiktion, gelesen von TTS oder Screenreader, beschrieben in einem separaten Handbuch tales.de.html). Alle fünf Werkzeuge sind in einem Programmfenster verfügbar, das über Schaltflächen in der Leiste oder Tastenkombinationen Ctrl+1..Ctrl+5 umgeschaltet werden kann.

SCHRITT 1: Erste Ausführung (Cross-Platform)

Laden Sie den neuesten Installer von der Registerkarte Releases auf GitHub herunter (Datei Rezyser_Audio_v<numer>_Installer.exe) und starten Sie ihn durch Doppelklick. Der Installer schlägt einen Standardinstallationspfad vor — den Ordner Programme im lokalen Verzeichnis Ihres Kontos — und erfordert keine Administratorrechte. Sie können auch einen eigenen Pfad mit der Schaltfläche „Durchsuchen" wählen — der Installer merkt ihn sich und verwendet ihn bei späteren Updates von selbst, ohne nachzufragen. Nach der Installation starten Sie das Programm über das Desktop-Icon oder das Startmenü. Nach kurzer Zeit erscheint das Hauptfenster des Programms — Audio GPT Regisseur. Ab Version 17.0 ist die Anwendung als nativer ausführbarer Datei im Fenstermodus eingefroren, sodass kein Terminalfenster mehr blinkt und sie schneller startet als zuvor. Kein Browser, kein Hintergrundserver. Wenn Sie die Arbeit beendet haben, schließen Sie einfach das Programmfenster.

Die gesamte Anwendung, einschließlich der Python-Engine, der Projekte und des API-Schlüssels, befindet sich in einem einzigen Ordner unter dem Installationspfad — der gesamte Ordner kann auf einen USB-Stick, in die Cloud oder auf einen anderen Computer verschoben werden (detaillierte Anleitung im Abschnitt „Projekte und API-Schlüssel übertragen" unten).

Wichtig: Der Ordner runtime/ im Installationsordner ist das PyInstaller-Bundle (ab Version 17.0) — er enthält einen isolierten Python-Interpreter und Bibliotheken, die ohne separate Systeminstallation einsatzbereit sind; er dient auch als Container für versteckte Projektdaten. Wenn Sie das Repository klonen (Entwicklungspfad), gibt es diesen Ordner nicht und sollte es auch nicht geben — Sie verwenden dann die virtuelle Umgebung venv, die im Abschnitt für Entwickler unten beschrieben ist.

Für Entwickler (Windows — Git-Repository)

  1. Klonen Sie das Repository auf Ihre Festplatte.
  2. Führen Sie die Datei setup_dev.bat aus. Das Skript erstellt automatisch eine virtuelle Python-Umgebung (venv) und installiert alle erforderlichen Abhängigkeiten aus der Datei requirements.txt.
  3. Starten Sie die Anwendung mit dem Befehl python main.py oder über die Datei run_dev.bat — das Skript erkennt automatisch den venv-Ordner und startet das Programm.

Für Entwickler und normale Benutzer (macOS / Linux)

  1. Klonen Sie das Repository auf Ihre Festplatte.
  2. Öffnen Sie das Terminal im Projektordner und geben Sie den Skripten Ausführungsrechte: chmod +x *.sh
  3. Führen Sie das Konfigurationsskript aus: ./setup_dev.sh — das Skript erstellt die venv-Umgebung und installiert die Abhängigkeiten.
  4. Starten Sie die Anwendung: python main.py oder ./run.sh

Was Sie beim Start sehen: Beim Start des Programms öffnet sich ein Fenster mit dem Startbildschirm. Dort finden Sie eine kurze Beschreibung der verfügbaren Werkzeuge sowie den Abschnitt "Systemprüfung". Wenn der API-Schlüssel noch nicht konfiguriert ist, sehen Sie eine rote Nachricht, die darauf hinweist, dass KI-basierte Module (Regie, Übersetzer) nicht funktionieren — kostenlose lokale Funktionen (Akzente, Architekt) sind jedoch sofort aktiv. Die Konfiguration des Schlüssels wird im nächsten Schritt beschrieben.

Automatische Updates

Die Anwendung überprüft beim Start, ob auf GitHub eine neuere Version verfügbar ist — die Überprüfung erfolgt im Hintergrund und blockiert die Benutzeroberfläche nicht.

Wenn Sie das Programm über die fertige Installationsdatei (.exe) installiert haben: Bei Erkennung einer neueren Version erscheint ein Fenster mit der Frage, ob Sie diese herunterladen möchten. Nach Bestätigung wird ein Fortschrittsbalken angezeigt, und wenn der Download abgeschlossen ist, schließt sich die Anwendung automatisch und der neue Installer startet von selbst. Um den Installationspfad müssen Sie sich dabei nicht kümmern: Der Installer erkennt die frühere Installation und installiert in denselben Ordner wie zuvor — der Assistent zeigt die Seite mit dem Zielordner dann gar nicht erst an (das gilt auch für einen Pfad, den Sie seinerzeit von Hand mit „Durchsuchen" gewählt haben). Das Update überschreibt die Dateien der Anwendungs-Engine und das gesamte Regelpaket (Ordner dictionaries/) — Ihre Projekte (Ordner skrypty/, opowiesci/) und der API-Schlüssel (golden_key.env) bleiben unberührt. WICHTIG: Wenn Sie mit dem Regelmanager Dateien bearbeitet haben, die im Paket vorhanden sind (z.B. Akzentänderungen in dictionaries/pl/akcenty/wloski.yaml), werden diese Änderungen BEI EINEM UPDATE ÜBERSCHRIEBEN — machen Sie vor der Bestätigung des Updates ein Backup des Ordners dictionaries/ gemäß der Anleitung im Abschnitt „Projekte und API-Schlüssel übertragen" unten (es reicht, den Ordner dictionaries/ auf einen USB-Stick zu kopieren) und laden Sie ihn nach dem Update zurück, indem Sie die neueren Dateien überschreiben. Ganz neue Regeln, die Sie von Grund auf erstellt haben und die nicht im Paket enthalten sind (z.B. eine eigene zusätzliche Basissprache oder ein eigener Code), bleiben automatisch unberührt — der Installer entfernt keine Dateien außerhalb des Pakets. Ab Version 15.2.8 zeigt der Dialog, der das Update vorschlägt, diese Warnung direkt im Text an und enthält eine Schaltfläche „Ordner dictionaries öffnen", die mit einem Klick den Explorer an der richtigen Stelle öffnet — drücken Sie ihn vor der Bestätigung des Updates, um bequem ein Backup zu machen, und kehren Sie dann zum Dialog zurück und klicken Sie auf „Herunterladen und installieren".

Nützlich ist der Installationspfad dagegen beim manuellen Kopieren von Dateien (Sicherung, Umzug auf einen anderen Rechner — siehe Abschnitt unten). Wenn Sie ihn nicht mehr wissen, gibt es zwei schnelle Möglichkeiten, ihn wiederherzustellen. Windows 11: Wählen Sie im Kontextmenü der Desktop-Verknüpfung „Dateispeicherort öffnen" (wenn die Option im neuen vereinfachten Kontextmenü nicht sichtbar ist, wählen Sie zuerst „Weitere Optionen anzeigen" oder drücken Sie Shift+F10 zweimal, um sofort das vollständige Menü zu öffnen), gehen Sie eine Ebene höher mit der Rücktaste, markieren Sie den Ordner mit der Anwendung und drücken Sie Ctrl+Shift+C (oder wählen Sie „Als Pfad kopieren" im Kontextmenü) — der vollständige Pfad wird in Anführungszeichen in die Zwischenablage kopiert (beim Einfügen in den Installer denken Sie daran, die Anführungszeichen zu entfernen). Ältere Windows-Versionen (7/8/10): Klicken Sie mit der rechten Maustaste auf die Verknüpfung und wählen Sie „Eigenschaften"; auf der Registerkarte „Verknüpfung" im Feld „Ziel" sehen Sie den vollständigen Pfad zur ausführbaren Datei (.exe in Version 15.2.5+ oder run.bat in älteren Versionen) — kopieren Sie ihn und entfernen Sie den Dateinamen am Ende, es bleibt nur der Installationsordnerpfad.

Hinweis beim Update von älteren Versionen (v15.2.4 oder älter, als die Anwendung über run.bat aus dem Portable-ZIP-Paket gestartet wurde): Die vorhandene Desktop-Verknüpfung kann auf run.bat in der alten Location verweisen, die nach dem Update auf v15.2.5+ nicht mehr existiert — Versionen 15.2.5+ verwenden eine eigenständige .exe-Datei, die vom Installer erstellt wurde. Wenn die Verknüpfung nach dem Update nicht mehr funktioniert, löschen Sie sie manuell und lassen Sie den Installer während der Neuinstallation eine neue erstellen.

Wenn Sie das Git-Repository verwenden (Entwickler und macOS/Linux-Benutzer): Anstelle eines Vorschlags zum Herunterladen sehen Sie eine Information über die neue Version mit einem direkten Link zur Release-Seite auf GitHub. Laden Sie von dort das „Source code"-Archiv herunter oder aktualisieren Sie das Repository mit dem Befehl git pull.

Projekte und API-Schlüssel übertragen (Migration)

Wenn Sie Ihre Projekte, den API-Schlüssel und lokale Einstellungen auf einen anderen Computer übertragen möchten (oder alles nach einer Neuinstallation von Windows wiederherstellen möchten), müssen Sie keine einzelnen Dateien manuell kopieren — der gesamte Anwendungsordner ist autark.

  1. Stellen Sie sicher, dass die Anwendung VOLLSTÄNDIG geschlossen ist. Wenn Sie das Programmsymbol im Systemtray sehen (neben der Uhr, rechts in der Taskleiste), klicken Sie mit der rechten Maustaste darauf und wählen Sie „Schließen". Geöffnete Dateien blockieren das Kopieren.
  2. Finden Sie die Verknüpfung Audio GPT Regisseur auf dem Desktop. Klicken Sie mit der rechten Maustaste darauf (oder mit der Anwendungstaste oder Shift+F10 bei NVDA-Navigation) und wählen Sie die Option „Dateispeicherort öffnen". ACHTUNG bei Windows 11: Im neuen, vereinfachten Kontextmenü kann diese Option versteckt sein — wählen Sie zuerst „Weitere Optionen anzeigen" (oder drücken Sie Shift+F10 zweimal, um sofort das vollständige Menü mit der Option zu öffnen).
  3. Es öffnet sich ein Windows-Explorer-Fenster im Installationsordner des Programms. Drücken Sie die Rücktaste (der einfachste Weg, funktioniert immer) oder klicken Sie auf den Pfeil „Nach oben" in der Symbolleiste, um eine Ebene höher zu gehen — dort sehen Sie den vollständigen Ordner mit der Anwendung. Hinweis: Die Tastenkombination Alt+Pfeil nach oben funktioniert nur, wenn der Fokus auf der Dateiliste liegt — wenn der Explorer mit dem Fokus auf der Adressleiste geöffnet wurde (typisch), macht Alt+Pfeil nach oben nichts, verwenden Sie dann die Rücktaste.
  4. Kopieren Sie diesen gesamten Ordner auf einen USB-Stick, ein Cloud-Laufwerk (OneDrive, Google Drive, Dropbox) oder eine externe Festplatte. Der Ordner enthält alles, was zur Wiederherstellung des Arbeitszustands benötigt wird:
    - Ihre Projekte (Ordner skrypty/ — .txt-Dateien der Erzählungen, .md der Weltbücher sowie die Ergebnisdateien der Postproduktions-Werkzeuge: Speicher, Kapiteltitel, Veröffentlichungskarte; Ordner opowiesci/ — interaktive Spiele).
    - API-Schlüssel (Datei golden_key.env im Hauptordner der Anwendung).
    - Eigene phonetische Regeln, Akzente, Codes, wenn Sie etwas im Regelmanager bearbeitet haben (Ordner dictionaries/<kod>/, z.B. dictionaries/pl/akcenty/wloski.yaml).
    - Anwendungseinstellungen und Auswahl der kreativen Modi (Ordner runtime/skrypty/, .mode-Dateien).
    - Isolierte Python-Umgebung (Ordner runtime/), sodass Sie nichts auf dem neuen Computer installieren müssen.
  5. Auf dem neuen Computer: Laden Sie den neuesten Installer von der Registerkarte Releases auf GitHub herunter und installieren Sie die Anwendung standardmäßig. Starten Sie das Programm einmal, um die leere Struktur der Konfigurationsdateien zu erstellen. Schließen Sie die Anwendung. Kopieren Sie dann den zuvor gespeicherten Ordner an den Installationsort und überschreiben Sie die Dateien — oder wählen Sie selektiv nur die für Sie interessanten Ordner (skrypty/, opowiesci/, golden_key.env) und fügen Sie sie an den entsprechenden Stellen der neuen Installation ein.

Tipp für NVDA-Benutzer: Das Kontextmenü „Dateispeicherort öffnen", das mit der Anwendungstaste aufgerufen wird, ist vollständig zugänglich — NVDA liest jeden Eintrag auf Deutsch. Nachdem der Explorer im Zielordner geöffnet wurde, verwenden Sie die Rücktaste, um eine Ebene höher zu gehen (funktioniert immer, unabhängig davon, ob der Fokus auf der Dateiliste oder der Adressleiste liegt), und dann Ctrl+A, um alles auszuwählen, und Ctrl+C, um zu kopieren.

Hinweis: Die Option „Dateispeicherort öffnen" ist der native Name für die deutsche Version von Windows. Im englischen System lautet sie „Open file location", in anderen Sprachversionen — analog in der lokalen Sprache des Betriebssystems.

SCHRITT 2: API-Versorgung (empfohlener Anthropic / Claude-Schlüssel)

Der empfohlene und standardmäßige KI-Anbieter ist Anthropic (Claude) — alle Prompts der Anwendung sind auf ihn abgestimmt, sodass er die höchste Erzählqualität und die beste Einhaltung der Weltregeln bietet. Bei dieser (empfohlenen) Variante genügt EIN API-Schlüssel in der Datei golden_key.env:

• Anthropic-Schlüssel (Claude) — versorgt die GESAMTE KI-Engine: die Narration des Regisseurs (Hörbuch, Lesebühne, Brainstorming), den Geschichten-Modus, den Polyglott (Übersetzer) sowie die Vergabe von Kapiteltiteln und die Erkennung der Inhaltssprache. Beginnt mit sk-ant-.

Falls Sie von einer älteren Version aktualisieren: Der frühere OpenAI-Schlüssel wird für die Standardvariante nicht mehr benötigt — Sie können seine Zeile in golden_key.env belassen oder löschen, die Anwendung ignoriert sie (es sei denn, Sie konfigurieren bewusst einen anderen Anbieter — siehe SCHRITT 2B weiter unten).

So erhalten Sie einen Anthropic-Schlüssel:
1. Erstellen Sie ein Konto auf console.anthropic.com und laden Sie Guthaben auf (Reiter Billing / Plans).
2. Generieren Sie einen Schlüssel im Bereich API Keys (beginnt mit sk-ant-). Kopieren Sie ihn sofort — er wird mitunter nur einmal angezeigt.

So tragen Sie den Schlüssel in das Programm ein:
3. Klicken Sie auf dem Startbildschirm des Programms auf die Schaltfläche „Generiere die Datei golden_key.env und öffne den Texteditor". Das System erstellt automatisch eine saubere Konfigurationsdatei am richtigen Speicherort und öffnet den Editor mit einer bearbeitungsbereiten Vorlage.
4. In der geöffneten Datei sehen Sie die Zeile: ANTHROPIC_API_KEY=PASTE_YOUR_KEY_HERE. Löschen Sie den Platzhaltertext und fügen Sie Ihren Schlüssel direkt nach dem Gleichheitszeichen ein (ohne Leerzeichen und ohne Anführungszeichen). Speichern Sie die Datei und starten Sie die Anwendung neu.

Hinweis: Nach dem Neustart prüft die Anwendung die Datei und zeigt im Bereich „Systemprüfung" den Status des Schlüssels an. Er muss grün sein, damit alle KI-Module einsatzbereit sind. Fehlt der Schlüssel oder ist er fehlerhaft, weist das Programm klar darauf hin und ermöglicht es, den Texteditor zu öffnen, um den Fehler schnell zu beheben.

SCHRITT 3: Das Haupt-Regie-Studio

Dies ist Ihre Kommandozentrale zum Entwickeln von Geschichten und Schreiben von Drehbüchern. Wechseln Sie dorthin, indem Sie auf die Schaltfläche "🎬 Regisseur" in der Schaltflächenleiste klicken oder im Menü Werkzeuge → Regisseur wählen (Tastenkürzel: Ctrl+1).

Wichtig: Dateiformat der Projektdateien — Rückkehr zu .txt

In Version 7 wurden Projektdateien im Markdown-Format (.md) gespeichert, z. B. skrypty/znieczulica.md. Dies war ein bewusster Versuch — das .md-Format sollte als psychologische Hürde für nicht-technische Personen dienen und sie davon abhalten, die Datei im Texteditor zu öffnen und manuell zu bearbeiten (und dabei versehentlich die Strukturüberschriften zu beschädigen).

Der Versuch hat sich nicht bewährt. Die KI bricht häufig eines der grundlegenden Verbote auf eigenmächtige Weise (mehr dazu gleich). Aus diesem Grund wurde in Version 8 zu einfachen .txt-Dateien zurückgekehrt — intuitiver und für jeden lesbarer. Ein Projekt mit dem Namen „znieczulica" wird nun beispielsweise als skrypty/znieczulica.txt gespeichert, seine Zusammenfassung als skrypty/znieczulica_streszczenie.txt. So kann jeder laufend Regiekorrekturen oder Textkürzungen leichter vornehmen.

⚠️ Kritische Regel des Cutters (lesen Sie dies, bevor Sie beginnen!)

Alle Ihre generierten Skripte und Bücher werden in einfachen Textdateien (.txt) gespeichert, die Sie problemlos im Texteditor öffnen können.

Als Regisseur haben Sie das VOLLE RECHT (ja, sogar die Pflicht), diese Datei zu bearbeiten! Wenn die künstliche Intelligenz zu weit geht und z. B. das Problem der Figuren am Ende des generierten Abschnitts selbst löst, öffnen Sie die Datei, löschen Sie die letzten Zeilen und lassen Sie den Text an der spannendsten Stelle abbrechen, klicken Sie dann auf "Projekt von der Festplatte neu laden", um den Modellspeicher mit der korrigierten Datei zu synchronisieren, und auf "An die KI senden", um fortzufahren.

🔴 Jedoch — was Sie nicht anfassen dürfen

Ändern, löschen oder verändern Sie niemals Zeilen, die die Struktur enthalten (z. B. Akt 1, Szene 2, Kapitel 1, Prolog). Wenn Sie diese Überschriften beschädigen:
1. Zerfällt Ihre Geschichte in Screenreadern (NVDA).
2. Wird der Hörbuch-Architekt und damit auch das ElevenLabs Studio Ihr Buch nicht korrekt in Leseabschnitte aufteilen können.
3. Wird der interne Konverter der Anwendung kein korrektes Inhaltsverzeichnis in der Word-Datei und keine korrekte Zeitachse in ElevenLabs erzeugen.

Bearbeiten Sie Dialoge, kürzen Sie die Handlung, aber lassen Sie die Struktur in Ruhe!

Wie verwendet man das Regie-Studio?

  • Weltbuch (linke Seitenleiste): Hier tragen Sie die Regeln des Universums ein. Jedes Projekt hat nun ein eigenes Weltbuch, das mit dem Dateinamen verknüpft ist — wenn Ihre Geschichtsdatei z. B. emilia_heist_audiobook.txt heißt, wird das Weltbuch als skrypty/emilia_heist_audiobook.md gespeichert. Daher ist die Reihenfolge wichtig: Geben Sie zuerst den Dateinamen des Projekts im Feld „Projektdateiname" ein, und erst dann können Sie das Weltbuch speichern. Die Schaltfläche "💾 Buch dauerhaft speichern" bleibt ausgegraut, solange kein Name angegeben wurde. Beim Laden eines vorhandenen Projekts über die Schaltfläche "Geschichte laden" wird automatisch auch die zugehörige .md-Datei geladen — Sie müssen nichts manuell tun. Hinweis: Ohne ausgefülltes Weltbuch blockiert die Anwendung das Senden von Anfragen an die KI — dies ist eine bewusste Schutzmaßnahme, die Sie davor bewahrt, Text ohne jegliche Regeln zu generieren.
  • Langzeitspeicher (linke Seitenleiste): Das zweite Feld in der Seitenleiste. Hier landet die Handlungszusammenfassung — erzeugt mit dem Werkzeug im Postproduktions-Panel (SCHRITT 4) oder, beim Alarmstand des Speichers, automatisch. Sie können hier auch eigene Notizen manuell eintragen — das Modell behandelt sie als „was ich bereits weiß", bevor es die aktuelle Szene liest. HISTORISCHE LÜCKE (behoben in v15.5): Früher, wenn Sie hier eine sehr kurze Notiz eingetragen und auf „Zusammenfassung speichern" geklickt hatten, bevor in der Erzähldatei etwas Wesentliches stand, lud die Anwendung beim nächsten Öffnen VORRANGIG die Zusammenfassung und ÜBERSPRANG die vollständige Geschichte — das Modell erhielt dann nur das Weltbuch und eine einzeilige Notiz, ohne den Kontext des Tons und der letzten Szenen. Ab v15.5 ist das Laden intelligent: Wenn die gesamte Geschichte in das Kontextfenster passt, wird sie vollständig geladen (und eine überflüssige alte Zusammenfassung gelöscht), sodass das Modell keinen Kontext verliert. Nach manueller Bearbeitung der Erzähldatei im Editor verwenden Sie die neue Schaltfläche „Projekt von der Festplatte neu laden" (ab v15.5), die mit einem Klick den internen Speicher mit der Festplatte synchronisiert; zum bloßen Öffnen der Datei im Editor dient weiterhin „Öffne Erzählungsdatei…".
  • Brainstorming-Modus: Geben Sie eine lose Idee ein, und die KI liefert Ihnen 3 Optionen zur Handlungsentwicklung. Für jede Option generiert sie sofort einen fertigen Block „--- PROMPT-ENTWURF ---". Nachdem Sie eine Option gewählt haben, fügen Sie diesen Prompt in den Skript- oder Hörbuchmodus ein und ergänzen Sie eventuelle Anmerkungen oder Informationen für das Modell. Der Handlungsspeicher ändert sich während des Brainstormings nicht — Sie können experimentieren, ohne Risiko!
  • Rohskript-Modus (ab v16.0 — Lesebühne): Hier fügen Sie den in der Brainstorming-Sitzung generierten „PROMPT-ENTWURF" ein. Die KI schreibt einen langen erzählerisch-dialogischen Abschnitt: Erzählung (Szenerie, Zeit, Handlung) in den Tags [Narrator: ...] sowie Figurenrepliken in den Tags [Name: Emotion]. Keine Soundeffekte — der Kontext wird vom Erzähler durch Worte getragen. Der Text wird automatisch an Ihre Datei (z. B. nowa_scena.txt) im Ordner skrypty/ angehängt. Ein solches fertiges Skript können Sie anschließend in ein mehrstimmiges Hörbuch umwandeln (Brücke zu ElevenLabs Studio — separates Kapitel weiter unten).
  • Traditioneller Hörbuchmodus: Ein Modus für Schriftsteller. Die KI generiert reine literarische Prosa — keine Tags, keine Phonetik, klassische Dialoge in die Erzählung eingebettet. Der Text wird genauso wie im Skriptmodus an die Datei angehängt.
  • Automatische Figurenerstellung: Das Skript ist so programmiert, dass es automatisch neue [Speaker]-Tags erstellt, wenn die Handlung eine neue Figur erfordert. Tipp: Wenn die KI eine tolle Figur erschafft, kopieren Sie deren Tag und fügen Sie ihn in das Weltbuch ein, damit das Modell sie dauerhaft im Gedächtnis behält!

Projektverwaltung — drei Aktionsschaltflächen:
- Geschichte laden: Lädt ein vorhandenes Projekt in den Speicher. Verfügbar, wenn der aktuelle Speicher leer ist. Ab Version 15.2.3 werden zwei Pfade unterstützt: Wenn das Projektnamenfeld leer ist, öffnet sich ein Auswahldialog mit einer Liste aller im Ordner skrypty/ gefundenen Projekte (Zusammenfassungsdateien werden ausgelassen) — NVDA liest die Liste auf natürliche Weise vor, der Nutzer muss den Namen nicht auswendig kennen und abtippen. Wenn das Namensfeld ausgefüllt ist, versucht die Anwendung sofort, das Projekt mit diesem Namen zu laden (Expertenpfad: Enter im Namensfeld oder Klick nach dem Eintippen aus dem Gedächtnis).
- Projekt schließen (Harter Reset): Löscht das Projekt vollständig. Entfernt Geschichte, Zusammenfassung, Weltbuch und setzt alle Zähler zurück. Verwenden Sie dies beim Wechsel des Projekts oder bei einer neuen Geschichte.
- Öffne Erzählungsdatei… (ab v15.2.3): Notfallbearbeitung der Erzähldatei im systemeigenen Texteditor. Erfordert einen eingetragenen Projektnamen. Die Anwendung öffnet skrypty/<nazwa>.txt im Texteditor (Windows), TextEdit (macOS) oder dem Standard-GUI-Editor (Linux). Typische Szenarien: (a) Die KI schließt eine Szene nicht ab und Sie möchten das Ende manuell ergänzen; (b) Sie haben ein Projekt mit Zusammenfassung geladen und möchten die letzten Szenen in das Langzeitspeicher kopieren, damit das Modell den vollständigen Tonkontext hat (oben beschriebene Architekturlücke); (c) Sie möchten eine Textkürzung mitten in einem Kapitel vornehmen, die die Anwendungs-Engine nativ nicht unterstützt.

  • Projekt von der Festplatte neu laden (ab v15.5, umgebaut in v17.6): Lädt das GESAMTE Projekt nach manueller Bearbeitung der Erzähldatei neu von der Festplatte — dies ist ein echter Reload, nicht nur eine Aktualisierung des aktuellen Speichers. Berechnet die Zähler für Kapitel/Akte/Szenen neu, lädt das Weltbuch, den Modus und die Brainstorming-Optionen und synchronisiert den Arbeitsspeicher. Wenn die gesamte Geschichte in das Kontextfenster passt, wird sie vollständig geladen (und eine überflüssige alte Zusammenfassung gelöscht, damit die Engine auf dem vollständigen Text arbeitet). Wenn die Geschichte lang ist und eine gespeicherte Zusammenfassung hat, bleibt diese unberührt, und Sie werden gefragt, ab welcher Überschrift der KI-Arbeitsspeicher starten soll: Im Hörbuchmodus wählen Sie ein Kapitel, im Skriptmodus zuerst einen Akt und dann eine Szene dieses Akts (oder den gesamten Akt) — den Rest repräsentiert die Zusammenfassung. Abbrechen der Auswahl = Notfallschnitt zum letzten Textfragment (deshalb lohnt es sich, die Überschriftenstruktur beizubehalten). Bevor die Felder mit der Version von der Festplatte überschrieben werden, warnt die Anwendung, wenn Sie darin ungespeicherten Inhalt haben. Typisches Szenario: Die KI hat eine Szene falsch abgeschlossen (Anti-Closure verletzt), Sie kürzen das fehlerhafte Ende im Editor und klicken auf Neu laden — kein mühsames Korrigieren an zwei Stellen mehr.

Historische Anmerkung — warum die Modi jetzt vor versehentlicher Änderung geschützt sind:
In früheren Versionen der Anwendung wurde die Konsistenz des kreativen Modus innerhalb eines Projekts nicht überwacht. Das Ergebnis war eine gewisse subtile kreative Möglichkeit, die sich so beschreiben lässt: Sie beginnen eine Geschichte im Skriptmodus, fügen „Akt 1" und „Szene 1" ein (die Anwendung ist begeistert von Ihrer Konsequenz), generieren einige Bildschirme voller Spannung mit Tags wie [SFX: Türknall] und [Speaker 1: Marek - resigniert] ... und dann — weil die Inspiration gerade zuschlägt — klicken Sie auf „Kapitel 1 einfügen". Die Anwendung fügt ohne mit der Wimper zu zucken die Überschrift „Kapitel 1" in die Datei ein, direkt nach „Szene 3". Sie haben nun in der Datei eine Mischung aus einem Radiohörspiel der 1950er Jahre und einem Gesellschaftsroman. ElevenLabs betrachtet diese Struktur, sieht eine Kapitelüberschrift mitten in einem Akt und entscheidet, dass dies wohl ein Fehler in der Matrix ist. Das Inhaltsverzeichnis sieht aus wie das Werk eines Avantgarde-Künstlers. Der Hörbuch-Architekt geht seinerseits davon aus, dass Sie ein erwachsener Mensch sind, und verarbeitet das einfach kommentarlos — aber auch ohne jegliche Ergebnisgarantie. Ab Version 12.0 versuchte die Benutzeroberfläche, die Änderung des Aufzeichnungsmodus zu blockieren — zumindest in der Theorie. Die Praxis erwies sich als kreativer: Das Brainstorming (immer als Planungsmodus aktiv) war eine Hintertür, durch die man mit den Pfeiltasten auf und ab zwischen Skript und Hörbuch wechseln konnte (Hörbuch → Brainstorming → Skript und analog in die andere Richtung). Der erste Klick auf „Akt 1 einfügen" oder „Kapitel 1 einfügen" im neu gewählten Modus überschrieb reibungslos die .mode-Datei und mischte Akte mit Kapiteln in einer einzigen Erzähldatei. Erst ab Version 15.2.3 gibt es echten Schutz: Sobald die Modusentscheidung festgeschrieben ist (erste Struktur oder erster erfolgreicher Produktionsversand), ist die zweite Aufzeichnungsposition im Modusauswahlfeld tatsächlich gesperrt. Das Brainstorming bleibt immer als Planungsmodus aktiv — es liefert Handlungsoptionen — aber man kann durch es nicht mehr seitwärts in einen anderen Aufzeichnungsmodus springen. (Seit Version 18.13 fasst das Brainstorming nichts mehr zusammen; diese Aufgabe hat das Werkzeug für den Langzeitspeicher im Postproduktions-Panel übernommen.)

Showrunner-Prompts — KI als Seriendrehbuchautor (ab Version 7, beibehalten)

Dies ist die größte Änderung, die in Version 7 eingeführt wurde und unverändert erhalten geblieben ist. Sie ist in der Benutzeroberfläche nicht sichtbar, verändert aber die Qualität der generierten Handlung grundlegend.

Ein Showrunner ist in der Fernsehbranche die Person, die für das Gesamtbild einer Serie verantwortlich ist — er sorgt dafür, dass die Handlung nie einer einfachen Lösung zustrebt, sondern sich ständig verdichtet, Konflikte aufschichtet und den Zuschauer über viele Staffeln hinweg in Spannung hält. In Version 7 wurde diese Philosophie direkt in die System-Anweisungen der KI eingebaut.

Die Anti-Closure-Direktive — und was die Anthropic-Engine (Claude) verändert hat

Die Showrunner-Philosophie wird durch die in jeden Modus eingebaute Anti-Closure-Direktive durchgesetzt: ein Verbot, Szenen mit Zusammenfassungen, Moralen und falschen Happy Ends abzuschließen. In der alten Ära (GPT-Modell) war es genau das Gegenteil von heute — die Engine brach dieses Verbot notorisch und „schloss" die Geschichte bei jeder Gelegenheit selbst ab: Sie flocht handlungszusammenfassende Sätze ein, erzeugte falsche Happy Ends oder schloss Handlungsstränge mitten in einem Kapitel ab, als wäre jedes Fragment das letzte. Ab Version 18 arbeitet die gesamte KI-Engine standardmäßig mit Anthropic (Claude) — und ab Version 18.4 können Sie optional einen eigenen Anbieter angeben (SCHRITT 2B) — und Claude hält sich deutlich strenger an die Anti-Closure-Direktive.

Dadurch ist ein anderer, rein technischer Nebeneffekt entstanden: Da das Modell eine Szene konsequent nicht abschließt, kann seine Ausgabe das Längenlimit einer einzelnen Antwort erreichen und mitten in einem Satz abreißen (manchmal sogar mitten in einem Wort). Die Anwendung behandelt das selbstständig — wenn sie erkennt, dass ein Fragment am Limit abgebrochen wurde, schließt sie mit einer kurzen zusätzlichen Anfrage den letzten Satz so ab, dass er in der Sprache Ihrer Geschichte natürlich klingt, und speichert den Text erst dann. Wenn das aus irgendeinem Grund nicht gelingt, sehen Sie eine dezente Warnung, und der Text wird trotzdem in seinem aktuellen Zustand gespeichert — das Speichern wird niemals blockiert, ein abgebrochenes Ende können Sie jederzeit manuell nachbessern.

Die oben beschriebene Cutter-Regel gilt unverändert: Wenn das Modell eine Szene trotz allem zu glatt abschließt, ist es Ihr Recht (ja, Ihre Pflicht) als Regisseur, die .txt-Datei zu öffnen, diese letzten Sätze zu löschen, den Text an einem angespannten Moment abreißen zu lassen und auf „Projekt von der Festplatte neu laden" zu klicken, um den Speicher mit der korrigierten Datei zu synchronisieren.

Jeder Modus verfügt über eine eingebaute Anti-Closure-Direktive:

  • Brainstorming: Die KI agiert wie ein Drehbuchautor einer mehrstaffeligen Serie. Jede der 3 vorgeschlagenen Optionen MUSS Hindernisse aufschichten, neue Dilemmata, offene Handlungsstränge und Cliffhanger einführen. Absolutes Verbot, Optionen vorzuschlagen, bei denen sich die Figuren dauerhaft versöhnen, das Haupthindernis ohne schwerwiegende Konsequenzen überwinden oder die Geschichte auf ein hastiges Ende zusteuert. Verbot, billige, magische Schauplätze zu erfinden, die die Weltarchitektur brechen.
  • Rohskript-Modus: Absolutes Verbot, den Text mit Zusammenfassungen, Moralen oder Klammern zu beenden. Die KI soll die Handlung an einem natürlichen Spannungsmoment abreißen lassen (Cliffhanger) und Schlussfolgerungen vermeiden, damit das nächste Fragment die Erzählung nahtlos übernehmen kann.
  • Traditioneller Hörbuchmodus: Absolutes Verbot, den Text mit pathetischen Zusammenfassungen, dem Abschließen von Handlungssträngen oder dem Andeuten eines Geschichtsendes zu beenden (z. B. „Sie war bereit für neue Herausforderungen", „Sie verstand, dass es Zeit war weiterzugehen"). Der Text soll mitten in einer laufenden Handlung, Spannung oder einem offenen Gedanken abreißen.

Ausnahme von der Regel: Wenn Sie ausdrücklich um ein Ende, ein Finale oder einen Epilog bitten, erzeugt die KI einen befriedigenden Abschluss der Geschichte — das Verbot gilt nicht, wenn Sie selbst darum bitten.

Verwaltung von Akten und Szenen (Skriptmodus, ab Version 7, beibehalten)

Der Rohskript-Modus verfügt über ein dediziertes Panel „✂️ Strukturverwaltung" mit Schaltflächen zum Aufbau der Hörspielstruktur in Echtzeit.

  • Akt X einfügen: Fügt eine Aktüberschrift ein (z. B. „Akt 2") UND schreibt automatisch darunter „Szene 1" — denn jeder neue Akt beginnt mit der ersten Szene. Der Aktzähler springt zur nächsten Nummer, und der Szenenzähler wird auf 2 zurückgesetzt (bereit für die nächste Szene in diesem Akt).
  • Szene X einfügen: Fügt nur eine Szenenüberschrift ein (z. B. „Szene 3") innerhalb des aktuellen Akts. Der Szenenzähler erhöht sich automatisch.

Intelligentes Laden der Datei: Wenn Sie eine vorhandene Skriptdatei laden, scannt die Anwendung sie automatisch und setzt die Akt- und Szenenzähler auf die richtigen Nummern. Der Szenenzähler wird immer innerhalb des letzten Akts in der Datei berechnet.

Prolog und Epilog: Die Schaltflächen „📜 Prolog einfügen" und „🏁 Epilog einfügen" sind für beide Modi gemeinsam und im selben Panel verfügbar.

Der Hörbuch-Architekt wandelt Akte automatisch in die wichtigsten Navigationspunkte (Heading 1) für ElevenLabs und NVDA um — Szenen werden zu fett formatiertem Text, der im Dokument sichtbar ist, aber nicht im Inhaltsverzeichnis erscheint.

Intelligente Kapitelstruktur (Hörbuchmodus, ab Version 5, beibehalten)

Das LLM generiert pro Anfrage maximal etwa 5000 Zeichen — das reicht nicht für ein vollständiges Kapitel. Daher arbeiten Sie iterativ: Sie generieren mit der Schaltfläche „Senden an KI" aufeinanderfolgende Fragmente, bis Sie das jeweilige Kapitel für abgeschlossen halten. Dann klicken Sie auf „Kapitelschnitt einfügen" — die Anwendung schreibt die Überschrift in die Datei und den Speicher, und der Kapitelzähler springt automatisch zur nächsten Nummer.

Schaltflächen im Panel:

  • Schnitt einfügen (Kapitel X): Fügt eine Überschrift (z. B. „Kapitel 3") in die Datei und den Speicher ein. Der Kapitelzähler wird automatisch aktualisiert.
  • Prolog einfügen: Funktioniert nur am Anfang, wenn der Speicher leer ist. Schutz vor versehentlichem Einfügen des Prologs mitten in der Geschichte.
  • Epilog einfügen: Schließt die Geschichte ab. Nachdem der Epilog mit Inhalt eingefügt wurde, blockiert die Anwendung die Generierung neuer Fragmente — das ist beabsichtigt, denn nach dem Ende der Geschichte gibt es nichts mehr hinzuzufügen.

Intelligentes Laden der Datei: Wenn Sie eine vorhandene Datei laden, scannt die Anwendung sie automatisch und setzt den Kapitelzähler auf die richtige Nummer. Hat die Datei einen Prolog und drei Kapitel, zeigt der Zähler „Kapitel 4" — ohne manuelles Zählen.

Handlungsspeicher — wie das KI-Gedächtnis funktioniert

In den Modellspeicher fließt ausschließlich der reine Erzähltext — das, was die KI tatsächlich geschrieben hat. Anweisungen, Optionen und Pläne verschwinden nach der Verwendung und belasten den Kontext nicht. Das Ergebnis: Das Modell behält länger seinen Fokus, erinnert sich besser an Charakterakzente und „flüchtet" seltener von den Regeln des Weltbuchs.

Der Indikator „Modellspeicher" auf dem Bildschirm zeigt an, wie stark das Kontextfenster des Modells gefüllt ist. Ab Version 15.1 werden dabei NICHT mehr nur die Zeichen der Geschichte gezählt — die Anwendung zählt echte TOKEN (nach derselben Methode, die das Modell selbst verwendet) und summiert die GESAMTE an die KI gesendete Last: die aktuelle Geschichte, den Langzeitspeicher (Zusammenfassung) UND das Weltbuch. Daher steigt der Indikator auch dann, wenn Sie das Weltbuch ausbauen oder eine lange Zusammenfassung haben — nicht nur durch die Erzählung selbst. Der Wert wird als prozentualer Füllstand des Fensters angezeigt:
- Grün (bis ca. 70 %): Das Modell ist voll konzentriert, Sie haben einen sicheren Puffer.
- Gelb (ca. 70–90 %): Sie nähern sich der Grenze. Die KI kann beginnen, Aussagen zu kürzen und Regeln zu ignorieren. Das ist der Moment, den Langzeitspeicher selbst zu sichern — und den Handlungsstrang langsam abzuschließen.
- Rot (über ca. 90 %): Kritische Überlastung! Seit Version 18.13 startet die Anwendung auf dieser Stufe nach jedem erfolgreichen Versand selbst das Werkzeug für den Langzeitspeicher aus dem Postproduktions-Panel und sichert die Zusammenfassung — Sie erhalten eine Meldung darüber, und das Panel ist währenddessen gesperrt.

Diagnose des Zusammenfassungsschwellenwerts (wenn die KI früher halluziniert als der Schwellenwert annimmt): Die Schwellenwerte (Warnung ~70 %, Alarm ~90 %) sind empirisch geschätzt. Wenn Sie eine wiederkehrende Tendenz bemerken, dass das Modell von den Regeln „flüchtet" oder zu halluzinieren beginnt, BEVOR der Indikator in den gelben/roten Bereich eintritt — also früher als der Schwellenwert annimmt — öffnen Sie ein Issue im Repository der Anwendung und beschreiben Sie, bei welcher ungefähren Auslastung (Prozentsatz) es tatsächlich zu Problemen kommt, am besten mit einem Beispiel. Wenn sich diese Tendenz breiter bestätigt (bei anderen Nutzern, in verschiedenen Projekten), wird der Schwellenwert für die automatische Zusammenfassung im nächsten Patch gesenkt. Das ist ein bewusst iterativer Mechanismus — es ist besser, ihn anhand realer Daten zu kalibrieren, als im Voraus zu raten.

Unendliches Gedächtnis (ab Version 6, beibehalten)

Wenn der rote Alarm aufleuchtet, müssen Sie die Zusammenfassung nicht mehr manuell kopieren. Seit Version 18.13 erledigt das ein eigenes Werkzeug im Postproduktions-Panel (SCHRITT 4): Ein Klick erzeugt eine prägnante Wissenskapsel über die gesamte bisherige Handlung, speichert sie als Speicherdatei im Ordner skrypty/ (im deutschen Paket <Name>_zusammenfassung.txt) und trägt sie sofort in das Feld des Langzeitspeichers ein. Danach können Sie den Speicher leeren und in derselben Datei weiterschreiben — die Geschichte lässt sich unbegrenzt fortsetzen, ohne jegliche Längenbeschränkung.

Was sich gegenüber früheren Versionen geändert hat: Bis v18.12 bestellte man die Zusammenfassung im Brainstorming, indem man das Wort „Zusammenfassung" oder „Resümee" in die Anweisung schrieb. Dieser Weg hatte einen konstruktionsbedingten Mangel: Der Brainstorming-Prompt verbietet dem Modell alles außer drei Handlungsoptionen, die Bitte um eine bloße Zusammenfassung stellte es also vor zwei widersprüchliche Anweisungen zugleich — und konnte mit einem Fehler statt eines Ergebnisses enden. Deshalb ist das Zusammenfassen jetzt ein eigenständiges Werkzeug mit einer eigenen, widerspruchsfreien Anweisung, und das Brainstorming hat wieder nur eine Aufgabe: die Handlung zu planen.

Wann zusammenfassen (aktualisiert in v15.5): Sie müssen keinen starren Zeichenschwellenwert mehr „vor dem Beenden der Arbeit" im Auge behalten. Am besten fassen Sie nach dem natürlichen Abschluss eines größeren Strukturteils zusammen — nach dem Ende einer Szene, eines Akts oder eines Kapitels. Der Grund: Wenn Sie später das Ende in der Erzähldatei manuell korrigieren und auf „Projekt von der Festplatte neu laden" klicken, fragt die Anwendung, ab welcher Überschrift das frische Fragment wiederhergestellt werden soll — und die Zusammenfassung des früheren Teils bleibt unberührt (kein lästiges Korrigieren an zwei Stellen mehr). Deshalb lohnt es sich umso mehr, die Struktur beizubehalten: Fügen Sie regelmäßig Kapitel-/Akt-/Szenenüberschriften aus dem Strukturpanel ein (von langen Formen ganz ohne Akte/Kapitel wird abgeraten, z. B. ein „modernistisches Drama" als ein einziger Textblock). AUSNAHME: Wenn Sie eine sehr lange Geschichte VÖLLIG ohne Überschriften führen, bleibt das Generieren und Speichern einer Zusammenfassung vor einer Pause notwendig — ohne Marker kann die Anwendung nur das letzte zeichenbasierte Fragment wiederherstellen, und die Engine könnte ohne Kontext „in Panik geraten".

Automatisches Zusammenfassen (in v18.13 neu gebaut): Wenn die Speicheranzeige in den Alarmzustand übergeht (über ca. 90 %), startet die Anwendung nach abgeschlossenem Versand selbst das Werkzeug für den Langzeitspeicher — ohne Rückfrage, denn auf dieser Stufe ist jeder weitere Aufruf bereits gefährdet. Das Ergebnis wandert direkt in die Zusammenfassungsdatei und in das Feld des Langzeitspeichers, und Sie erhalten eine Meldung, dass dies geschehen ist. Null manuelle Arbeit. Die Zusammenfassung können Sie im Feld natürlich korrigieren und mit der Schaltfläche zum Speichern des Speichers erneut sichern.

Die Zusammenfassung ist INKREMENTELL: Das Werkzeug liest nicht jedes Mal das ganze Projekt von vorn. Es erhält den bisherigen Langzeitspeicher sowie den Teil der Erzählung, der nach der letzten Zusammenfassung entstanden ist (die Anwendung merkt sich, bei welcher Überschrift sie aufgehört hat), und führt beides zusammen. Dadurch steigen die Kosten weiterer Zusammenfassungen nicht mit der Länge des Romans, und ältere Ereignisse gehen nicht bei jeder Auffrischung verloren.

Intelligentes Laden und Neuladen von der Festplatte (aktualisiert in v17.6): Sowohl beim Laden eines Projekts als auch nach dem Klicken auf „Projekt von der Festplatte neu laden" (nach manueller Bearbeitung der Erzähldatei im Editor) gleicht die Anwendung in einem einzigen Vorgang den Speicher mit der Festplatte ab — sie berechnet die Strukturzähler neu und lädt das Weltbuch sowie den Modus. Wenn die GESAMTE Geschichte in das Kontextfenster passt, wird sie vollständig geladen, und eine überflüssige alte Zusammenfassung wird gelöscht, damit die Engine auf dem vollständigen Text arbeitet (das schließt eine frühere Lücke, bei der das Modell nur die Zusammenfassung ohne den Kontext der letzten Szenen erhielt). Wenn die Geschichte LANG ist und eine gespeicherte Zusammenfassungsdatei hat, bleibt die Zusammenfassung unberührt, und Sie werden gefragt, ab welcher Strukturüberschrift (Kapitel/Akt/Szene) der KI-Arbeitsspeicher starten soll; den Rest der Handlung repräsentiert die Zusammenfassung. Dadurch verschwenden Sie keine Token für das erneute Laden der gesamten Geschichte, und gleichzeitig entsteht die nächste Zusammenfassung nicht auf Basis veralteter Daten.

SCHRITT 3b: Zwei Ausgaben des Skripts — mehrstimmiges Hörbuch (ElevenLabs) und Version für Screenreader

Das fertige Skript des Lesetheaters (Skript-Modus) hat zwei unabhängige Ausgaben: ein mehrstimmiges ElevenLabs Studio-Projekt (Audio) sowie eine HTML-Version für Screenreader. Das sind zwei Wege, dasselbe Stück zu „hören" — du kannst eine, die andere oder beide verwenden. Beide sind optional und ändern nichts am klassischen Ablauf mit dem Konverter.

Brücke zu ElevenLabs Studio (Audio, optional)

Die Brücke verwandelt das Skript in ein mehrstimmiges Studio-Projekt — Erzähler und jede Figur erhalten eine eigene Stimme. Ohne ElevenLabs-Schlüssel ändert sich nichts: Die Brücke bleibt einfach verborgen.

ElevenLabs-Schlüssel (optional)

Füge deinen ElevenLabs-Schlüssel in die Datei golden_key.env ein, in einer eigenen Zeile: ELEVENLABS_API_KEY=sk_... Hinweis: Der ElevenLabs-Schlüssel beginnt mit sk_ (mit UNTERSTRICH), anders als der Anthropic-Schlüssel (sk-ant-). Wenn du einen eingeschränkten Schlüssel (Restricted Key) verwendest, weise ihm die Berechtigungen (Scopes) projects_write sowie voices_read zu. Der Status des Schlüssels ist auf dem Hauptbildschirm (System Check) sichtbar — ein fehlender Schlüssel ist kein Fehler, die Brücke bleibt einfach verborgen.

Die Brücke erscheint im Regisseur-Panel im Skript-Modus (wenn der Schlüssel korrekt ist). Sie arbeitet mit einem fertigen, auf der Festplatte gespeicherten Stück — generiere oder lade zuerst das Projekt, dann wechsle zur Brücke.

Schritt 1 — Stimmbesetzung

Klicke auf „Sprecherbesetzung…". Die Anwendung liest die Figuren mit Sprechrollen aus deinem Skript aus und fügt immer einen Erzähler-Slot hinzu (der Erzähler ist die Standardstimme — er liest Kapitelüberschriften und die gesamte Narration). Füge für jeden Sprecher eine Voice ID ein. WICHTIG: Jede im Stück verwendete Stimme muss sich zuerst in deinen „My Voices" befinden — Stimmen, die du selbst erstellst (z. B. in „Voice Design"), landen dort automatisch, während Stimmen aus der öffentlichen Bibliothek du im Tab „Explore" durchsuchst und mit der Schaltfläche „Add to My Voices" hinzufügst. So erhältst du eine Voice ID in ElevenLabs (im Browser): Finde die Stimme, spiele die Probe ab, um sicherzugehen, dass es die richtige ist, und kopiere ihre Kennung mit der Schaltfläche „Copy Voice ID"; wenn die Stimme bereits in „My Voices" ist, ist diese Schaltfläche sofort verfügbar — ohne „More actions" aufzuklappen. Stimmauswahl: Um eventuelle Regenerierungen zu minimieren, wähle am einfachsten aus der Kollektion „Best for Eleven v3" (Stimmen, die für das v3-Modell geprüft wurden, auf dem das Projekt erstellt wird); alternativ entwirf eine eigene Stimme in „Voice Design", und für Mutige bleibt das Klonen per IVC (Instant Voice Cloning) oder PVC (Professional Voice Cloning). Du kannst Felder leer lassen und später zurückkehren — die Speicherung ist ein Entwurf.

Schritt 2 — Projekt erstellen

Klicke auf „ElevenLabs-Studio-Projekt erstellen…". Die Anwendung prüft, ob das Skript mindestens ein Kapitel (Prolog/Akt/Kapitel) hat und ob jedem Sprecher sowie dem Erzähler eine Stimme zugewiesen ist, und erstellt dann in deinem Konto ein mehrstimmiges Studio-Projekt, das in Kapitel unterteilt ist. Das bloße Erstellen des Projekts verbraucht KEINE Credits. Die Anwendung stellt sofort die Projektsprache ein (korrekte Aussprache der Kopfzeilen) sowie die Lautstärkenormalisierung nach Hörbuch-Standard — das geschieht über die API, damit du nicht in die Projekteinstellungen im Browser eingreifen musst.

Format-Wächter (Erweiterung der Monteur-Regel): Die Brücke erfordert, dass im Skript JEDE Zeile entweder eine Äußerung mit Sprecher-Markierung ist ([Narrator: …] oder [Name: …]) oder eine Strukturüberschrift (Prolog, Akt, Szene, Kapitel). Gewöhnliche, nicht getaggte Prosa, die „frei" eingetragen wurde — zum Beispiel eine Autorennotiz oder ein Erzählabschnitt ohne Tag — wird keiner Stimme zugeordnet und beim Erstellen stillschweigend übergangen, sodass das fertige Projekt von deiner Datei abweichen könnte. Wenn die Anwendung solche verwaisten Zeilen erkennt, zeigt sie daher deren Liste mit Nummern an und fragt, ob trotzdem gebaut werden soll: Du kannst dann abbrechen und das Skript korrigieren (öffne es mit der Schaltfläche „Öffne Erzählungsdatei…", füge fehlende Sprecher-Markierungen hinzu oder entferne diese Zeilen) oder bewusst trotzdem bauen und deren Auslassung in Kauf nehmen. Das ist eine natürliche Erweiterung der Monteur-Regel: So wie Strukturüberschriften nicht beschädigt werden dürfen, sollte in einem für die Brücke bestimmten Skript jede Zeile einen Sprecher haben oder eine Überschrift sein.

Schritt 3 — Rendering im Browser

Nach dem Erstellen des Projekts zeigt die Anwendung dessen Kennung sowie eine Schaltfläche an, die ElevenLabs Studio öffnet. Finde das Projekt im Browser, rendere die Sprache (das verbraucht erst jetzt Credits — ungefähr 1 Credit pro Zeichen), und exportiere dann die Audiodatei oder veröffentliche das Projekt im Eleven Reader. Rendering und Veröffentlichung erfolgen auf deiner Seite, bewusst — die Anwendung erstellt lediglich das Projekt.

Ausdruck und Akzente (Modell Eleven v3)

Das Projekt wird auf dem Modell Eleven v3 erstellt (über 70 Sprachen). Emotionen werden NICHT durch Großbuchstaben, Auslassungspunkte oder Gedankenstriche ausgedrückt — die Engine ignoriert das. Stattdessen fügt der Regisseur in die Äußerungen englische Audio-Tags v3 ein, zum Beispiel [whispers], [sighs], [angry], [laughs] — diese steuern den Ausdruck und funktionieren unabhängig von der Sprache der Rede. Der AKZENT einer Figur ergibt sich hingegen aus der STIMMPROBE: Wenn jemand z. B. Polnisch mit einem fremden Akzent sprechen soll, wähle oder entwirf in Voice Design eine Stimme, deren Probe diesen Akzent hat. Experimentiere in der Praxis mit dem Stimm-Prompt, bis du z. B. eine polnische Probe mit finnischem Akzent hörst — das Modell v3 behält diesen Akzent in der fertigen Aufnahme bei. Hinweis: Sehr lange Sätze schwächen den Akzent ab, daher wird der Regisseur im Prompt bereits um kurze Sätze gebeten.

Bewusstsein über Modell v3 (Alpha-Phase)

Eleven v3 ist am ausdrucksstärksten, befindet sich aber noch in der Alpha-Phase. Es kann vorkommen, dass eine einzelne Replik als Knistern statt als Sprache gerendert wird — es reicht, sie im Studio neu zu generieren (jeder Block hat einige kostenlose Regenerierungen). In den ElevenLabs-Projekteinstellungen können auch Empfehlungen zur Modellwechsel angezeigt werden (auf Eleven Flash v2.5 oder Multilingual v2) — das ist KEIN Fehler, sondern nur ein Hinweis der Engine. Wenn du diese Meldungen nicht sehen möchtest, öffne einfach nicht die Projekteinstellungen: Die Anwendung hat bereits alles Notwendige über die API eingestellt (Modell, Sprache, Lautstärkenormalisierung).

Warum Lesetheater und keine Soundeffekte? In früheren Versionen produzierte der Skript-Modus rohe Effekte [SFX: ...] ohne Erzähler. Die Brücke zu einer fertigen, mehrstimmigen Aufnahme erfordert jedoch, dass der Kontext (Ort, Zeit, Handlung) vom Erzähler in Worten getragen wird: Soundeffekte in Studio sind für Screenreader nicht zugänglich, und das Modell realisiert ohnehin entweder den Erzähler oder Effekte — niemals stabil beides gleichzeitig. Daher ist der Skript-Modus ein Lesetheater: Erzähler plus Dialog, ohne SFX.

Version für Screenreader (HTML, ohne ElevenLabs)

Im Skript-Modus hast du unabhängig vom ElevenLabs-Schlüssel die Schaltfläche „Version für Screenreader generieren". Sie erstellt eine Datei skrypty/<nazwa>_screen_reader.html — eine separate Ausgabe für Personen, die Screenreader verwenden (z. B. NVDA). So funktioniert es: Äußerungen von Figuren, für die im Weltbuch ein Akzent definiert ist (z. B. der Eintrag „[Joana] finnischer Akzent"), erhalten eine phonetische Schreibweise (absichtlich „fehlerhafte" Orthografie) sowie eine Sprachmarkierung (Attribut lang), sodass der Screenreader sie mit dem richtigen, fremden Akzent vorliest. Audio-Tags v3 (z. B. [whispers]) werden in dieser Version entfernt — der Screenreader soll sie nicht laut vorlesen. Überschriften Prolog/Akt/Szene werden zu HTML-Überschriften, sodass man bequem durch das Dokument navigieren kann.

Das ist die bewusste Ergänzung zur Audio-Brücke: Den Akzent für das v3-Modell trägt die Stimmprobe, und für den Screenreader — die Orthografie plus die Sprachmarkierung. Daher bleibt die Orthografie in der Audio-Version sauber (v3 wählt die Sprache selbst), während die „fehlerhafte" Orthografie ausschließlich in die separate HTML-Datei gelangt, wo sie erwünscht ist.

SCHRITT 4: Postproduktion in der Regie

Nachdem du die Geschichte geschrieben hast, steht dir unten im Regie-Panel ein Bedienfeld mit Postproduktions-Werkzeugen zur Verfügung. Das Panel ist dynamisch: Jedes Werkzeug ist eine eigene YAML-Datei im Ordner rezyser/ (kategoria: postprodukcja), und ihr Feld dla_trybow bestimmt, in welchen Kreativmodi das Werkzeug erscheint. Die Zusammenstellung der Schaltflächen ändert sich also mit dem gewählten Modus — und wenn kein Werkzeug zum aktuellen Modus passt, bleibt das Panel verborgen. Ein eigenes Werkzeug kannst du im Regelmanager erstellen (Vorlagentyp Postproduktion — siehe SCHRITT 7b).

Ein Werkzeug arbeitet in einem von drei Geltungsbereichen (Feld zakres in der YAML-Datei):

  • per_rozdzial — iteriert durch die Kapitel der gespeicherten Datei und verarbeitet jedes einzeln (so funktioniert die Kapitelbenennung weiter unten),
  • calosc — sendet die gesamte Projektdatei in einem einzigen Aufruf an die KI (z. B. einen Bericht oder ein Audit der gesamten Geschichte); besitzt das Projekt ein Weltenbuch, kann das Werkzeug es als zusätzlichen Kontext hinzufügen,
  • rekoncyliacja (ab v18.13) — sendet statt der ganzen Datei das bisherige Langzeitspeicher sowie den Teil der Erzählung, der nach der letzten Zusammenfassung entstanden ist. So arbeitet das unten beschriebene Werkzeug für das Langzeitspeicher; dadurch steigen die Kosten der nachfolgenden Aufrufe nicht mit der Länge des Romans.

Das Ergebnis erscheint immer in einem Dialogfenster (zum Kopieren), und ein Werkzeug mit festgelegtem Ergebnisdatei-Suffix speichert es zusätzlich neben der Erzählung im Ordner skrypty/ (z. B. nazwa_audyt.txt). Bevor eine bestehende Ergebnisdatei überschrieben wird, fragt die Anwendung um Erlaubnis — noch bevor auch nur ein Cent für einen KI-Aufruf ausgegeben wird. Übersteigt das Material für das Werkzeug das Kontextfenster, an dem die Anwendung das Gedächtnis misst (128 Tausend Token), siehst du zunächst eine Warnung mit der Frage, ob das Werkzeug trotzdem gestartet werden soll. Das ist nur eine Warnung: Claude-Modelle haben ein deutlich größeres Fenster als dieser Zähler, aber ein eigener KI-Anbieter mit kleinerem Fenster würde eine solche Anfrage ablehnen — und für den Versuch zahlst du trotzdem.

Kapitelbenennung (Hörbuch-Modus)

Die KI analysiert die gesamte Geschichte und schlägt beschreibende, literarische Titel für jedes Kapitel vor (sowie für einen eventuellen Prolog und Epilog). Das Modul iteriert durch die Kapitel der gespeicherten Datei und vergibt ihnen einen kurzen Titel, indem es nur die Anfänge jedes Kapitels analysiert (bis zu 6000 Zeichen). Es liefert ausschließlich eine nummerierte Liste von Titeln zurück — ohne den Buchinhalt umzuschreiben.

Langzeitspeicher — Projektzusammenfassung (ab v18.13)

Ein Werkzeug, das in beiden Speichermodi (Skript und Hörbuch) verfügbar ist. Es erzeugt eine knappe Faktenaufzeichnung: Handlungsverlauf, Entscheidungen der Figuren und deren Konsequenzen, Charaktere, Schauplätze, offene Handlungsstränge, und am Ende eine einzeilige Notiz zu Stil und Ton der Erzählung. Adressat dieses Textes ist die Erzähl-Engine, nicht der Leser — deshalb ist die Zusammenfassung trocken und sachlich, ohne Ausschmückungen.

Es hat eine Eigenschaft, die keine anderen Werkzeuge besitzen: Sein Ergebnis landet nicht „neben" dem Projekt wie ein Bericht, sondern WIRD zum Langzeitspeicher — es gelangt gleichzeitig in die Speicherdatei im Ordner skrypty/ (deren Namen gibt das Rezept des Werkzeugs vor; im deutschen Paket ist es <Name>_zusammenfassung.txt), in das Feld „Langzeitspeicher" im Panel und in eine interne Markierung, an der die Anwendung erkennt, bis wohin die Zusammenfassung reicht (diese Markierung ermöglicht das inkrementelle Zusammenfassen und lässt die Anwendung dich beim Neuladen des Projekts von der Festplatte nach einem Bezugspunkt fragen). Das Werkzeug startet auch von selbst, wenn der Gedächtnisindikator des Modells in den Alarmzustand übergeht — siehe SCHRITT 3.

Der Name der Speicherdatei ist lokalisiert (ab v18.14). Jedes Sprachpaket gibt im Feld sufiks_pliku_wyniku der Datei rezyser/postprod_streszczenie.yaml sein eigenes, natives Wort an: deutsch _zusammenfassung, englisch _overview, polnisch _streszczenie, finnisch _yhteenveto und so weiter. Du kannst den Wert im Regelmanager auf einen beliebigen eigenen ändern (z. B. _gedaechtnis) — die Anwendung bewältigt den Übergang, denn sie sucht die Speicherdatei über eine KANDIDATENLISTE:

  • sie prüft der Reihe nach die Suffixe der Speicher-Werkzeuge aus dem Paket der INHALTSSPRACHE des Projekts (nicht der Interface-Sprache — die Datei gehört zur Geschichte, nicht zum Menü), dann das neutrale _overview, zuletzt das historische _streszczenie;
  • findet sie GENAU EINE Datei unter einem anderen als dem aktuellen Namen, benennt sie diese samt interner Markierung um — du musst nichts von Hand tun;
  • findet sie MEHRERE (weil du ein eigenes Speicher-Werkzeug „für dich" und eines „für die KI" hast oder Dateien aus Zeiten einer anderen Interface-Sprache), fragt sie dich, welche der Langzeitspeicher sein soll, und lässt die übrigen unangetastet. Das Abbrechen dieser Frage bedeutet eine Sitzung ohne Speicher: das Feld bleibt leer, keine Datei wird geändert oder gelöscht, und bei einer langen Erzählung bittet dich die Anwendung, den Bezugspunkt des Arbeitsspeichers zu wählen.

Veröffentlichungskarte für ElevenReader (ab v18.14)

Das Werkzeug liest den gesamten Projekttext und stellt einen fertigen Satz Metadaten für das Formular zur Hörbuch-Veröffentlichung auf ElevenReader zusammen; das Ergebnis speichert es im Ordner skrypty/ (im deutschen Paket als <Name>_veroffentlichung.txt). Die Karte enthält: Titel und optionalen Untertitel, eine Beschreibung von bis zu 1000 Zeichen (Limit der Plattform), ein oder zwei Genres AUSSCHLIESSLICH aus der kanonischen Liste der 22 Kategorien von ElevenReader, die Zielgruppe, die Kennzeichnung von Inhalten für Erwachsene mit einem Satz Begründung, zwei bis drei als kostenlose Vorschau ausgewählte Auszüge, einen fertigen Prompt für einen Cover-Bildgenerator (vertikal 1200×1800 px, mit Platz für einen lesbaren Titel und Autorennamen) sowie eine Erinnerung an die Felder, die du im Formular auf den Voreinstellungen lässt.

Die Feldnamen in der Karte sind ENGLISCH (Title:, Description, Genres:, Target audience:, Mature content:, Sample chapters:, ISBN:) — das Formular der Plattform existiert nur auf Englisch, du überträgst sie also 1:1. Der Feldinhalt ist in der Sprache deines Projekts, doch auch die WERTE der geschlossenen Felder (Genres, Zielgruppe, das Yes/No bei Inhalten für Erwachsene) bleiben englisch, weil die Plattform sie nur aus ihrer eigenen Liste annimmt.

Was die Karte nicht für dich tut: Sie erfindet weder einen Verlag noch eine ISBN — sie lässt beides als manuell auszufüllende Felder offen (eine ISBN ist eine registrierte Nummer, eine Halluzination wäre hier eine falsche verlegerische Erklärung). Ein Autorenprofil ist auf ElevenReader verpflichtend, weil anonyme Veröffentlichungen nicht erlaubt sind und es mit der Urheberrechtserklärung zusammenhängt — das Werkzeug übernimmt daher den Namen oder das Pseudonym aus dem Weltenbuch, und findet es dort keines, setzt es ein auszufüllendes Feld ein. Die Vorschau-Auszüge wählt es IMMER, denn das Formular verlangt mindestens einen, unabhängig vom später gewählten Auszahlungsmodell.

Nach dem Erzeugen prüft die Anwendung die Karte auf ihrer Seite: ob die Beschreibung im Limit liegt, ob Genres und Zielgruppe aus der Liste der Plattform stammen, ob die erforderlichen Felder ausgefüllt sind und ob im ISBN-Feld Ziffern aufgetaucht sind. Abweichungen zeigt sie als sanfte Hinweise — du bekommst das Ergebnis vollständig und entscheidest selbst, was du korrigierst. Das schützt vor dem Fall, dass das Modell eine nicht existierende Kategorie erfindet und das Formular sie erst am Ende des Assistenten zurückweist.

Hinweis: Postproduktions-Werkzeuge setzen voraus, dass die Projektdatei bereits auf der Festplatte gespeichert ist (generiert oder geladen). Existiert die Datei nicht, zeigt die Anwendung eine entsprechende Meldung an.

SCHRITT 5: Polyglott AI

Anwendung für Übersetzungen und das Erzwingen starker Akzente auf Screenreader-Synthesizern. Gehe zu ihr, indem du auf die Schaltfläche "🌍 Polyglott" in der Symbolleiste klickst oder Werkzeuge → Polyglott aus dem Menü wählst (Tastenkürzel: Ctrl+2).

Modus 1: Normaler Übersetzer (Verwendet AI - Kostenpflichtig)

Ideal zum Anhören von Geschichten in einer schönen, korrekten Fremdsprache.

  • Lade die Datei mit der Schaltfläche "Datei in den Speicher laden" oder durch Klicken auf "Durchsuchen..." zum Auswählen der Datei im Systemfenster.
  • Wähle den Modus "KI-Übersetzer", gib die Zielsprache ein (z.B. "Finnisch").
  • Das Skript übersetzt den Inhalt. Wenn du eine .html-Datei lädst, wird nur der für den Leser sichtbare Text übersetzt und der Sprachcode im HTML-Tag aktualisiert.
  • Wenn du eine normale .txt- oder .md-Datei lädst (z.B. ein vom Regisseur generiertes Skript), speichert das Skript das Ergebnis nach der Übersetzung automatisch als .html-Datei mit eingebettetem Sprach-Tag — bereit für NVDA ohne zusätzliche Arbeit.
  • Unterstützt auch .docx-Dateien.

Intelligente Blockaufteilung: Lange Texte werden automatisch in Blöcke aufgeteilt, die in Modell-Tokens (nicht in Zeichen) gemessen werden, und sequentiell mit Fortschrittsbalken übersetzt. Dadurch passen auch dicht geschriebene Sprachen wie Chinesisch oder Japanisch in das Antwortlimit des Modells, und eine abgeschnittene Antwort wird erkannt und automatisch auf kleineren Fragmenten wiederholt.

Fehlerresistentes Fortschrittsspeichern (NEU in Version 9): Jeder übersetzte Block wird sofort in einer versteckten temporären Datei im Systemordner der Anwendung gespeichert. Wenn die Übersetzung aufgrund eines erschöpften API-Limits unterbrochen wird, erkennt die Anwendung beim nächsten Start diese Datei automatisch, stellt den bereits bezahlten Fortschritt wieder her und setzt die Arbeit ruhig an der Unterbrechungsstelle fort — ohne manuelles Kopieren. Nach erfolgreichem Abschluss wird die temporäre Datei automatisch gelöscht.

Warum ist das wichtig? In Version 8 hatte der Ansatz zur Wiederaufnahme der Übersetzung einen kritischen, stillen Fehler: Wenn man die Datei mit der Teilübersetzung nicht umbenannte und den übersetzten Abschnitt gemäß den Anweisungen ausschneidete und dann sofort die Übersetzung des Rests fortsetzte — öffnete die Anwendung die Ausgabedatei im Überschreibmodus. Der bezahlte Fortschritt wurde unwiderruflich und unbemerkt gelöscht, bevor man es überhaupt bemerkte. Version 9 eliminiert diese Falle vollständig: Das Speichern ist nach jedem Block dauerhaft, unabhängig davon, was man danach tut.

"pt-BR" für brasilianisches Portugiesisch, "zh-Hans" für vereinfachtes Chinesisch).   • Funktioniert lokal und kostet nichts!

Modus 3: Kryptograph (NEU in 13.0 — Textspielereien, kostenlos, lokal)

Der dritte RadioButton im Polyglott, neben dem KI-Übersetzer und dem Regisseur-Modus: „Kryptographenmodus (Textspielereien, zufälliges Stottern)". Er aktiviert sechs lokale Algorithmen zur Textverzerrung — für Spiele, Rätsel, Sprachpuzzles. Nach Auswahl des Modus erscheint eine Dropdown-Liste der Algorithmen, und für einen von ihnen (Caesar-Verschlüsselung) ein zusätzliches Zahlenfeld für die Verschiebung.

Verfügbare Algorithmen (im Menü „Wähle Verzerrungsalgorithmus" markieren):

  • Textumkehrer (Rückwärtslesen mit Großbuchstaben) — jeder Satz wird Zeichen für Zeichen umgekehrt, wobei Punkt/Ausrufezeichen/Fragezeichen am Ende und Großbuchstaben am Anfang beibehalten werden. Vor dem Umkehren erweitert das Skript gängige Abkürzungen (z.B., d.h., usw., bzw., ggf. usw.), damit das Ergebnis nach dem Umkehren noch Sinn ergibt — ohne dies würde „z.B." nach dem Umkehren in das unsinnige „.Bz" verwandelt.

Inspiration: Mission aus dem Programm „The Traitors. Verräter". Als die Moderatorin den Teilnehmern ohne Vorwarnung ein bekanntes polnisches Lied aus einem Märchen zeigte — einfach rückwärts abgespielt — waren die Reaktionen wie „Welche Sprache ist das?", „Das muss Armenisch sein", „Ungarisch oder Finnisch". Die eigentliche Mission bestand darin, dass ein Team im Wald den rückwärts geschriebenen Text des Liedes erhielt, ihn in dieser umgekehrten Form singen sollte, das andere Team es aufnahm, rückwärts abspielte — und theoretisch das Originallied zur Erratung zurückgewann. Genau dasselbe lustige phonetische Missverständnis erzeugt unser Textumkehrer, wenn du die verarbeitete Datei durch einen TTS-Synthesizer laufen lässt.

  • Typoglycämie (Vermischte Wortmitten) — klassischer psycholinguistischer Effekt: „Man knan den Txet in jderer Riehnfolge der Bstuchaben lseen, solgne die erste und ltezte Bstuchabe am rcihtigen Platz sind". Das Skript mischt zufällig die Mitte jedes Wortes, das länger als 4 Zeichen ist, der erste und letzte Buchstabe bleiben unberührt. Hervorragend für den Test „Wie viel sehe ich wirklich, und wie viel errät mein Gehirn".

  • Kaputtes Telefon / Schlangendialekt — jedes „s", „z" oder der Doppelbuchstabe „sch" wird zufällig zu einem Zischen von 4-8 Zeichen verlängert („ssssss", „zzzzzz", „sssssssch"). Inspiration: Snecko aus dem Spiel „Slay the Spire". Effekt: Der Text klingt, als ob ihn eine Schlange mit Sprachfehler gelesen hätte.

  • Vokalisierer (Alles dröhnt auf „O") — jeder Vokal im Text wird durch „o" ersetzt, die Umlaute ä/ö/ü eingeschlossen: „Guten Tag" → „Goton Tog", „Schöne Grüße" → „Schono Großo". Die polnische Erweichungsstufe (dzi/ci/ni/si/zi) ist im deutschen Paket absichtlich leer — solche Schreibweisen gibt es hier nicht, die Regel besteht also nur aus dem Vokaltausch. Je länger der Text, desto lustiger der Effekt (und der Screenreader liest es mit voller Überzeugung).

  • Starkes Stottern / Beschädigter Roboter — fügt Stottern am Anfang von Wörtern hinzu: „C-c-c-computer", „St-st-straße". Bei kurzen Wörtern (weniger als 3 Zeichen) ignoriert der Algorithmus sie. Wenn der zweite Buchstabe des Wortes ein Konsonant ist, werden die ersten beiden Buchstaben wiederholt (natürlicherer Effekt); wenn ein Vokal, wird nur der erste wiederholt.

  • Caesar-Verschlüsselung (Verschiebung des deutschen Alphabets) — klassischer Substitutionscode: Jeder Buchstabe wird um N Positionen im deutschen Alphabet verschoben (ABCD…ÄÖÜ, 29 Zeichen). Den Verschiebungswert gibst du im Zahlenfeld „Caesar-Verschlüsselungsverschiebung (0 = zufällig, Bereich -28…28)" ein. Wenn du 0 eingibst — wählt die Anwendung eine Verschiebung im Bereich 1-28 zufällig aus und zeigt sie nach Abschluss in einer Nachricht an (damit du später entschlüsseln kannst). Zeichen außerhalb des Alphabets (Zahlen, Interpunktion, Leerzeichen) bleiben unverändert.

Praktische Anwendung: Die Verschlüsselungen speichern das Ergebnis im gleichen Format wie der Regisseur-Modus (.html mit Sprach-Tag oder .docx mit XML-Tags), sodass NVDA sie mit der Stimme der entsprechenden Sprache liest. Besonders der Textumkehrer und der Vokalisierer klingen im Synthesizer viel interessanter, als wenn du sie mit den Augen liest — denn das Gehirn versucht beim visuellen Lesen automatisch, den Text zu „entschlüsseln", während TTS ihn genau so liest, wie er geschrieben ist.

Alle sechs Verschlüsselungen sind auch in einer breiteren, zugänglichen Sprache in der Datei docs/dictionaries.pl.html im Anwendungspaket beschrieben — zusammen mit Tipps, wie man ohne Programmierkenntnisse eine eigene Verschlüsselung vom Typ „Buchstabentausch" hinzufügen kann (z.B. Schulsprache, Kauderwelsch).

Verarbeitungssprache, Erzwingung und Qualitätsmodus (NEU in 18.11)

Der Bereich zum Laden der Datei verfügt jetzt über eine Dropdown-Liste für die Verarbeitungssprache. Mit ihr legst du fest, nach welchen Regeln welcher Sprache die Modi Regisseur und Kryptograph arbeiten: Listen der Akzente und Chiffren sowie das Alphabet der Caesar-Chiffre samt Verschiebungsbereich.

  • Die Standardposition „Automatisch erkennen" behält das bisherige Verhalten bei: Die Sprache wird anhand der geladenen Datei bestimmt, und wenn sie sich von der Sprache der Anwendung unterscheidet, erhältst du eine kurze Benachrichtigung, dass die Listen umgeschaltet wurden.
  • Die Auswahl einer bestimmten Sprache aus der Liste ist bindend — die Anwendung ändert sie beim Laden einer Datei nicht eigenständig.

Unter der Liste befindet sich ein Kontrollkästchen, das die gewählte Sprache für das gesamte Dokument erzwingt. Standardmäßig wird jeder Absatz nach der für diesen Absatz erkannten Sprache verarbeitet — das ist normalerweise die beste Wahl, da fremdsprachige Einschübe ihre eigenen, korrekten Regeln erhalten. Aktiviere die Erzwingung, wenn dir eine einheitliche Verarbeitung des gesamten Textes wichtig ist. Ein Beispiel, bei dem dies notwendig ist: umkehrbare mehrschichtige Verschlüsselung. Das Alphabet der Caesar-Chiffre hat in jeder Sprache eine andere Länge, sodass ohne Erzwingung ein sprachlich gemischter Text mit mehreren unterschiedlichen Alphabeten verschlüsselt würde — und die Entschlüsselung würde dann Kenntnis darüber voraussetzen, wo die Sprachgrenzen verliefen. Bei erzwungener Sprache verschlüsselt und entschlüsselt das gesamte Dokument ein und dasselbe Alphabet. Einschränkung: In Sprachen, deren Caesar-Alphabet diakritische Buchstaben enthält, die beim Laden normalisiert werden (Polnisch, Deutsch), ist die Entschlüsselung nicht vollständig verlustfrei — diakritische Buchstaben des Chiffretexts werden beim erneuten Laden in ihre Grundformen umgewandelt, bevor sie die Entschlüsselung erreichen. Volle Umkehrbarkeit bieten Alphabete ohne solche Zeichen (z. B. Englisch).

Der KI-Übersetzer hat hingegen ein Kontrollkästchen für den Qualitätsmodus erhalten. Ist es aktiviert, erhält das Modell ein zusätzliches Budget für die interne Textanalyse vor der Übersetzung (sogenanntes extended thinking) — die Übersetzung dauert länger und kostet mehr Token, aber schwierige Textstellen fallen sorgfältiger aus. Die Option funktioniert ausschließlich mit Anthropic-Claude-Modellen; wenn du einen alternativen Anbieter über einen OpenAI-kompatiblen Endpunkt nutzt, hat das Aktivieren keine Wirkung.

Eine verwandte Kleinigkeit: Zeichen mit Makron, die in der japanischen Romanisierung verwendet werden (z. B. Tōkyō, rāmen, jūdō), werden ab dieser Version wie andere fremde diakritische Zeichen normalisiert — in den meisten Sprachen zum blanken Buchstaben (Tokyo), im finnischen Paket hingegen durch Verdopplung des Vokals (Tookyoo), gemäß der finnischen Schreibkonvention für lange Laute. Dadurch fallen sie nicht mehr als offene Zeichen im Chiffretext aus dem Alphabet der Caesar-Chiffre heraus.

Spracherkennung

Bevor das Skript den Text "verändert", überprüft es, in welcher Sprache er geschrieben ist. Wenn es erkennt, dass es sich nicht um Polnisch handelt, wird eine Warnung angezeigt. Die phonetischen Regeln sind auf die polnische Sprache zugeschnitten — die Anwendung auf fremdsprachige Texte würde unvorhersehbare Ergebnisse liefern.

Akzente optimiert für lokale Sprachsynthesizer (NVDA)

Die Akzente wurden zu 100 % für lokale, kostenlose und kostenpflichtige Sprachsynthesizer-Lesegeräte — Vocalizer und eSpeak in NVDA — entworfen. Dies garantiert Stabilität und Vorhersehbarkeit des Effekts auf jedem Computer.

Warum nicht ElevenLabs? Tests mit längeren Dokumenten haben gezeigt, dass die phonetische Verzerrung des Textes in Engines wie ElevenLabs den beabsichtigten Akzent nicht erzwingt — die Engine "rät" einfach die Sprache und macht daraus eher einen west-/südslawischen Akzent. Lokale NVDA-Synthesizer sind in dieser Hinsicht deutlich gehorsamer.

Spezifika lokaler Sprachsynthesizer (TTS)

Verschiedene TTS-Engines verhalten sich unterschiedlich. Nachfolgend die wichtigsten Unterschiede, die direkten Einfluss auf die Akzente haben:

eSpeak (Open Source)

Leichte, kostenlose Engine mit einer riesigen Sprachdatenbank — unterstützt z.B. Isländisch. Sehr streng bei der Zeichenkodierung, was sie vorhersehbar macht. Hat jedoch phonetische Nachteile: Oft werden Phoneme zwischen Sprachen geteilt, wodurch z.B. Ukrainisch mit einem russischen Akzent klingt.

Der alte Vocalizer (32-Bit-.dll-Bibliotheken von Nuance) wurde mit NVDA 2026.1 eingestellt; Cerrence hat die Stimmen auf 64-Bit umkompiliert und Tiflotecnia hat sie unter neuem Namen veröffentlicht. Die Aussprachequalität ist spürbar besser als in der vorherigen Generation.

Installation: NVDA → Werkzeuge → Add-on Store → suche nach „Tiflotecnia Voices for NVDA" → Installieren. Nach der Installation erscheint im NVDA-Menü ein dediziertes Untermenü „Tiflotecnia Voices" sowie eine eigene Kategorie in den NVDA-Einstellungen. Die integrierte Hilfe des Add-ons ist klar, daher wiederholen wir das Verfahren hier nicht — lassen Sie sich einfach vom Add-on führen.

Hinweis für Umsteiger von Vocalizer und Eloquence: Es ist ein Upgrade zu einem günstigeren Preis verfügbar. Ohne diese E-Mail behandelt das System Sie als neuen Kunden.

Die Liste der Stimmen pro Sprache ist in der Kategorie der Add-on-Einstellungen vor dem Kauf der Lizenz sichtbar.

Kostenlose Stimmen, die in Windows integriert sind (Mobile Voices). Ein guter Kompromiss zwischen Qualität und Verfügbarkeit der Sprachen. Isländisch, Finnisch, Italienisch) und klicken Sie auf Herunterladen. Nach dem Herunterladen erscheint die Stimme automatisch in NVDA — ohne zusätzliche Konfiguration.

Nach dem Kauf ist die Stimme mit deinem Google-Konto verknüpft und kann auf jedem Gerät mit demselben Konto installiert werden.

Killer-Feature für Blinde: Dateien mit Sprach-Tags

Das ist eine echte Revolution. Verarbeitete Dateien werden jetzt gespeichert als:

  • .html mit dem Attribut lang (z.B. lang="fi" für Finnisch) — NVDA liest diesen Tag und wechselt automatisch zur entsprechenden Sprachsynthese. Keine manuelle Konfiguration nötig!
  • .docx mit Formatierungserhaltung — jeder Textabschnitt hat ein Sprach-Tag im XML-Dokument eingebettet, sodass Word und NVDA wissen, mit welcher Stimme jeder Abschnitt gelesen werden soll.

Verarbeitete Dateien werden immer als NEUE Dokumente gespeichert (z.B. akzent_Finski.html).

Automatisches Umschalten der Sprache in NVDA — was Sie wissen müssen

Damit NVDA die Stimme tatsächlich basierend auf dem lang-Tag umschaltet, muss die Einstellung "Sprache automatisch ändern, wenn unterstützt" aktiviert sein. Sie finden diese in den NVDA-Einstellungen → Sprache. Standardmäßig ist sie beim ersten Start des Screenreaders aktiviert — es ist jedoch ratsam zu überprüfen, ob sie nicht deaktiviert wurde.

Wichtiges Einschränkung der OneCore-Stimmen: Microsoft OneCore-Stimmen unterstützen diesen Mechanismus nativ nicht mit NVDA, sondern nur mit dem in Windows integrierten Narrator. Es gibt ein inoffizielles NVDA-Add-on namens „One Core Autolang", das versucht, dies zu beheben — aber seine Entwicklung wurde schnell eingestellt. Der Grund ist banal: Jedes Jahr, mit der ersten NVDA-Version des Jahres, gibt es Änderungen, die die API-Kompatibilität brechen (sogenannte API Breaking Changes). Manchmal reicht es aus, das Feld „last tested version" im Add-on-Manifest zu aktualisieren, aber manchmal sind echte Änderungen im Code erforderlich — und der Autor kommt mit den Updates nicht hinterher. Wenn Ihnen das automatische Umschalten der Sprache wichtig ist, sind Tiflotecnia Voices (kostenpflichtig, siehe Abschnitt oben) oder eSpeak (kostenlos, geringere Qualität) eine sicherere Wahl, da sie diesen Mechanismus nativ unterstützen — aber Achtung: Aktuell funktioniert dies in Tiflotecnia Voices mit einem Prioritätsfehler (siehe „Kritischer Haken" unten). Nach dem Kopieren des Patches funktioniert das automatische Umschalten vorbildlich, wie im alten Vocalizer.

Kritischer Haken bei Tiflotecnia Voices: fehlerhafte Spracherkennung

Zunächst die gute Nachricht — der Alarm bezüglich NVDA 2026.1 aus den vorherigen Versionen des Handbuchs hat ein Happy End gefunden: Cerrence hat 64-Bit-Bibliotheken bereitgestellt, Tiflotecnia hat sie in einem .nvda-addon-Paket veröffentlicht, das im Add-on Store verfügbar ist (siehe Abschnitt oben), und der Vocalizer ist bei denen, die ihn bis zum Ende behalten haben, unter einem neuen Namen zurückgekehrt — mit besserer Qualität und ohne 32-Bit-Einschränkungen.

Mit der Einführung von Tiflotecnia Voices ist jedoch ein neuer kritischer Haken aufgetreten — in der Spracherkennung. In den Einstellungen des Add-ons kann konfiguriert werden, welche Stimme für bestimmte Buchstaben (z.B. lateinische, kyrillische) je nach installierten Stimmen verwendet werden soll. Das Problem liegt in der Prioritätenreihenfolge: Derzeit wird zuerst das Override pro Buchstabe angewendet, dann der Fallback auf den ISO-Sprachcode (in der Praxis unerreichbar für DASSELBE Alphabet, für das bereits ein Override angewendet wurde), und schließlich die gewählte Stimme. Das Ergebnis zeigt sich innerhalb desselben Alphabets: Du hast einen finnischen Text mit dem korrekten Tag lang="fi", Satu als finnische Tiflotecnia-Stimme installiert, ABER in den Einstellungen eine polnische Stimme für lateinische Buchstaben eingestellt — Satu wird diesen Text NICHT lesen, trotz des korrekten ISO-Tags. Das Override pro Buchstabe „polnische Stimme für Latein" gewinnt auf der ersten Ebene, ISO fi wird nie geprüft. Für unterschiedliche Alphabet-Paare funktioniert der Mechanismus korrekt (russischer Text + Milena für Kyrillisch + polnische Stimme für Latein — das gesamte Kyrillisch wird mit Milena gelesen, eventuelle lateinische Eigennamen mit der polnischen Stimme; jedes Alphabet bleibt in seinem Override). Nach der Migration vom Vocalizer, bei dem der Sprachwechsel auf Basis von ISO vorbildlich funktionierte, werden Benutzer diesen Rückschritt sofort bemerken — insbesondere diejenigen, die im Polyglott mehrere europäische Akzente (Satu, Alice, Markus) auf derselben lateinischen Buchstabenmenge verwenden.

Diagnose und Patch: Ich habe das Problem auf Python-Ebene im Add-on-Code diagnostiziert und einen Patch vorbereitet, der die Prioritätenreihenfolge ändert zu: ISO → gewählte Stimme → Buchstaben-Override. Der Patch behält das nützliche Umschalten auf Latein für lateinische Namen im russischen Text bei, wenn in den Einstellungen „Spracherkennung basierend auf Unicode-Zeichen" aktiviert ist. Ich habe den Patch an die Entwickler von Tiflotecnia gesendet — bisher ohne Antwort, sie bleiben also höchstwahrscheinlich bei ihrer eigenen Lösung. Falls das Add-on ein Update erhält, aktualisiere ich den Patch bei Bedarf.

Was man in der Zwischenzeit tun kann: Wenn dir die korrekte Spracherkennung wichtig ist (es lohnt sich — das war eines der Killer-Features des alten Vocalizers, siehe „Killer-Feature für Blinde" oben), öffne ein Issue im Anwendungs-Repository auf GitHub mit dem Label tiflotecnia-patch und deiner E-Mail-Adresse im Inhalt. Es lohnt sich, eine kurze Problembeschreibung in deiner eigenen Sprache hinzuzufügen (2–3 Sätze reichen) — der Bot erkennt die Sprache (unterstützt: Polnisch, Englisch, Deutsch, Spanisch, Finnisch, Französisch, Isländisch, Italienisch, Russisch) und antwortet in derselben; ohne Beschreibung oder in einer anderen Sprache erfolgt die Antwort auf Englisch. Ein automatischer Bot wird das Issue sofort mit einer Bestätigung der Meldung schließen (ohne Spur im öffentlichen Thread), und du erhältst den Patch in der Regel innerhalb weniger Tage privat per E-Mail. Der Patch wird NICHT im Anwendungs-Repository oder als Gist veröffentlicht — Tiflotecnia Voices for NVDA ist kommerzielle Software, und die Lizenz des Add-ons erlaubt keine Weiterverbreitung seiner Dateien, auch nicht in modifizierter Form. Nach Erhalt des Patches musst du dessen Inhalt in %appdata%\Roaming\nvda\addons\TiflotecniaVoices kopieren und die Dateien ersetzen. Vorsicht beim Kopieren: Wenn Windows nicht nach einer Ersetzung gefragt hat, hast du wahrscheinlich den gesamten Ordner TiflotecniaVoices_edits mit seinem Inhalt anstatt nur den Inhalt kopiert — in diesem Fall gehe in den erstellten Unterordner, schneide alles aus, füge es eine Ebene höher ein und überschreibe. Nach erfolgreicher Anwendung des Patches starte NVDA neu — du genießt bessere Cerrence 64-Bit-Stimmenqualität und korrekte Spracherkennung, ein Combo, das kein einzelner Hersteller auf dem Markt bietet. Wir gehen natürlich davon aus, dass du eine gültige Lizenz für Tiflotecnia Voices hast — wir überprüfen das nicht, aber ohne Lizenz kannst du den Patch sowieso nicht auf einen fremden Ordner anwenden.

SCHRITT 6: Audiobook-Architekt

Werkzeug zur Vorbereitung einer professionellen Dateistruktur für Screenreader und ElevenLabs. Öffnen Sie es durch Klicken auf die Schaltfläche "📄 Konverter" in der Schaltflächenleiste oder über Werkzeuge → Konverter im Menü (Tastenkürzel: Ctrl+3).

Wie funktioniert es?

  1. Geben Sie den Pfad zur Quelldatei in das Textfeld ein oder klicken Sie auf „Durchsuchen...", um eine Datei im Systemdialog auszuwählen. Das Skript akzeptiert sowohl .txt als auch .docx sowie .html- und .htm-Dateien.
  2. Klicken Sie auf „Architektur für ElevenLabs erstellen".
  3. Das Skript durchsucht jede Textzeile und wandelt Schlüsselwörter (Akt, Kapitel, Prolog, Epilog, Vorspann) in „Heading 1"-Überschriften im Word-Dokument um.
  4. Szenen (Zeilen, die mit dem Wort „Szene" beginnen) werden in fett formatierten Text umgewandelt — im Dokument sichtbar, aber nicht im ElevenLabs-Inhaltsverzeichnis.
  5. Der gesamte übrige Text (Dialoge, Beschreibungen) wird unverändert übernommen.
  6. Sie erhalten eine Datei architektur_[nazwa_oryginału].docx — ein professionelles Word-Dokument, das für die weitere Bearbeitung bereit ist. Wenn Ihre Eingabedatei beispielsweise znieczulica.txt hieß, trägt die Ausgabedatei den Namen architektur_znieczulica.docx und erscheint im selben Ordner wie das Original.

Bereinigung nebenbei: Das Skript entfernt automatisch HTML-Tags (wenn der Text aus einem Browser oder einer lokalen .html-Datei stammt, z. B. einer vom Polyglotten generierten) sowie Markdown-Überschriftenmarkierungen (z. B. ### oder ####) vor der Verarbeitung. Sie müssen die Datei nicht manuell bereinigen.

Erzählmodus: automatische Gruppierung von Zügen in Szenen (ab v15.1)

Wenn Sie eine vom Modul Interaktiver Geschichten generierte Datei opowiesci/<gra>.txt in den Architekten laden, erkennt der Konverter Zug-Markierungen (z. B. „--- Tura 7 ---" — auch in den übrigen unterstützten Sprachen, falls Sie in einer anderen gespielt haben) und fügt alle fünf Züge eine neue Überschrift erster Ebene „Scena N" ein (die Nummerierung beginnt bei 1, in der Sprache Ihres Spiels). Die übrigen Zug-Markierungen werden entfernt — sie erscheinen nicht in der Audiobook-Narration, da „Tura 7", vom TTS ausgesprochen, die Immersion des Zuhörers bricht. Das Ergebnis ist ein Word-Dokument mit einer natürlichen Einteilung in Szenen von jeweils einigen Minuten Audio, das für den Import in ElevenLabs bereit ist. Der Mechanismus arbeitet automatisch erkennend — gewöhnliche Audiobook-Dateien ohne Zug-Markierungen (klassische Narration aus dem Regisseur) werden genau wie bisher verarbeitet.

Großer Vorteil für NVDA- und ElevenLabs-Nutzer

Die „Heading 1"-Formatierung für Kapitel ist nicht nur Ästhetik. In NVDA können Sie blitzschnell durch Überschriften navigieren, indem Sie die Taste H drücken (oder 1 für Überschriften der ersten Ebene). Anstatt hunderte Seiten zu scrollen, springen Sie in Sekundenbruchteilen von Kapitel zu Kapitel. Das verändert die Arbeitsweise mit langen Dokumenten grundlegend. In ElevenLabs haben Sie die Gewissheit, dass die Engine automatisch Schnitte einfügt und beim Regissieren von Audioclips nicht hängen bleibt.

SCHRITT 7: Wie man das Weltbuch schreibt (Architekten-Prompt und Markdown-Minikurs)

Die künstliche Intelligenz, die das Hauptstudio antreibt, versteht Befehle am besten, wenn sie in der Auszeichnungssprache Markdown formatiert sind. Wenn Sie der KI im Regisseur nur eine lose Idee geben (z. B. „zwei Schwestern im Jenseits"), gerät die Maschine in Panik mangels Details und erstellt eine banale, vorhersehbare Geschichte, die die innere Logik ignoriert.

Um dem entgegenzuwirken, verwenden Sie einen externen Chatbot (z. B. das kostenlose ChatGPT oder Claude) als Ihren persönlichen Architekten. Ab Version 13.0 müssen Sie den Prompt nicht mehr aus der Anleitung abtippen — im Regisseur-Panel, direkt unterhalb der Schaltfläche „💾 Buch dauerhaft speichern", finden Sie die Schaltfläche „📖 Architekten-Prompt für KI…". Klicken Sie darauf, öffnet sich ein Dialogfenster mit dem fertigen Prompt-Text in einem „Nur-Lesen"-Feld sowie einer Schaltfläche „In die Zwischenablage kopieren". NVDA liest den gesamten Inhalt sofort nach dem Öffnen des Fensters vor — klicken Sie einfach auf „Kopieren", fügen Sie den Text (Ctrl+V) in ChatGPT/Claude ein und ersetzen Sie den Abschnitt „[HIER IHRE IDEE EINFÜGEN]" durch Ihren eigenen Handlungsansatz.

Warum so und nicht durch Kopieren aus der Anleitung? Der Dialog in der GUI hat einen entscheidenden Barrierefreiheitsvorteil: Er ist nativ und wird vom Screenreader ohne Störungen vorgelesen, erfordert kein Wechseln in einen Texteditor (wo Sonderzeichen und Anführungszeichen manchmal falsch kopiert werden) und funktioniert identisch auf jedem Betriebssystem. Dasselbe Muster — ein Dialog mit einem zu kopierenden Prompt — wird auch im Regelmanager verwendet (siehe SCHRITT 7b weiter unten).

Wie die KI antwortet: In der Antwort erhalten Sie einen Text in zwei Teilen. Der erste Teil ist das Weltbuch, eingeschlossen in einem Markdown-Codeblock (Markierungen markdown …). Kopieren Sie AUSSCHLIESSLICH den Inhalt des Codeblocks (ohne die Markierungen ``` selbst) und fügen Sie ihn in das Feld „Weltbuch" im Regisseur ein, klicken Sie anschließend auf „💾 Buch dauerhaft speichern". Der zweite Teil ist eine Empfehlung, welcher der kreativen Modi (Skript oder Hörbuch) am besten zu Ihrer Idee passt — betrachten Sie ihn als Hinweis beim Auswählen des Modus im Modusauswahlfeld.

Markdown-Minikurs im Weltbuch: Ein einzelnes Rautezeichen (#) steht für einen Hauptabschnitt (z. B. „# Charaktere"), ein doppeltes Rautezeichen (##) für einen Unterabschnitt, Bindestriche (-) erzeugen Listen, und doppelte Sternchen (Text) fetten absolute, unverletzliche Regeln fett hervor (z. B. „Der Held LÜGT NIE"). Für eine fremdsprachige Figur fügen Sie ein Tag mit Akzentangabe hinzu, z. B. „[Speaker 1: Marek] - hat einen französischen Akzent". Das Schlüsselwort „akcent" ist ZWINGEND ERFORDERLICH — die Engine der Anwendung erkennt es automatisch und wendet die korrekten phonetischen Regeln auf die Dialoge der jeweiligen Figur an.

Hinweis: Denken Sie daran, Ihr Weltbuch von Zeit zu Zeit zu aktualisieren (wenn die Handlung um neue Orte oder wichtige Figuren erweitert wird). Sie können dies manuell oder mithilfe eines externen Chatbots tun. Je reichhaltiger das Fundament, desto bessere Ergebnisse in der Reżyseria!

SCHRITT 7b: Regelmanager (Ctrl+4) — Wörterbücher für Linguisten ohne Python

Version 13.0 führt ein viertes Werkzeug in der Leiste ein: den Regelmanager. Du öffnest ihn mit der Taste Ctrl+4 oder über das Menü Werkzeuge. Es ist ein visueller Explorer des Ordners dictionaries/, in dem die Anwendung alle phonetischen Regeln (Akzente), Chiffren und Modi des Regisseurs in YAML-Dateien (ein für Menschen lesbares Format, einfacher als JSON) speichert.

Warum YAML? Bis Version 12.0 waren alle Akzente, kreativen Modi und Filter im Python-Code „eingebettet“. Das Hinzufügen eines neuen Akzents erforderte einen Programmierer. In Version 13.0 wurde alles in .yaml-Dateien im Ordner dictionaries/ ausgelagert — jeder, der den Notizblock öffnen kann, kann einen bestehenden Akzent anpassen („tausche sz gegen sh gegen sch“) oder einen völlig neuen hinzufügen (schwedisch, dänisch, russischer Dialekt).

Was du im Regelmanager findest:
- Dateibaum — vollständige Liste aller YAML-Dateien in dictionaries/ mit Aufteilung nach Quellsprachen (derzeit vollständig implementiert: Polski, Deutsch, English, Español, Suomi, Français, Íslenska, Italiano, Русский) und fünf Kategorien: akcenty/ (TTS-Phonetik), szyfry/ (Textspielereien), rezyser/ (kreative Modi und Postproduktion), gui/ (UI-Übersetzungen) und opowiesci/ (Modi des Geschichten-Moduls, hinzugefügt in 15.2.4). Navigation mit Pfeiltasten wie im Windows-Dateiexplorer, vollständige NVDA-Unterstützung.
- Schaltfläche „📝 Im Texteditor öffnen“ — öffnet die ausgewählte Datei im standardmäßigen System-Notizblock. Du bearbeitest, speicherst, klickst „🔄 Baum aktualisieren“ und fertig.
- Schaltfläche „📋 Ausgewählte Datei duplizieren“ — der schnellste Weg zu einem neuen Akzent: Du nimmst eine bestehende Datei (z.B. finski.yaml), gibst einen neuen Namen an (z.B. schwedisch), der Manager erstellt eine Kopie mit dem Kommentar „ändere Felder label und description“ und öffnet sie im Editor.
- Schaltfläche „➕ Neue Regeldatei…“ — ein Assistent mit Auswahl des Typs (Akzent, Chiffre, Regisseurmodus, neue Quellsprache, algorithmische Chiffre). Für einfache Fälle (Akzent, Chiffre vom Typ „Buchstabentausch“) erstellt der Assistent eine bearbeitbare YAML-Vorlage. Für Fälle, die einen Programmierer erfordern (neue Quellsprache, Algorithmus vom Typ „Wortmitte mischen“), generiert der Assistent ein Prompt für einen AI-Chatbot — du fügst es in ChatGPT ein, erhältst eine fertige YAML-Datei, speicherst sie in dictionaries/ und fertig.

Praktische Anwendung: Du möchtest einen schwedischen Akzent hinzufügen? Öffne den Regelmanager, wähle dictionaries/pl/akzente/finski.yaml, klicke „Duplikat“, benenne die Datei in schwedisch um, ändere das Feld label in "Schwedisch (Alva / Oskar)", den ISO-Code in sv, ändere einige Tauschregeln und speichere. Kehre zur Startseite zurück und starte die Anwendung neu. Der neue Akzent erscheint im Menü Polyglott (im Regisseurmodus) und — wenn du ihn dem Buch der Welt der Charaktere hinzufügst („[Marek] - hat einen schwedischen Akzent“) — auch in der automatischen Akzenterkennung des Regisseurs.

Wo du weitere Dokumentation zum Ordner dictionaries/ findest:
- Datei docs/dictionaries.pl.html (verfügbar im Paket für Endbenutzer im Reiter Releases) — eine kurze, einfache Beschreibung jedes Unterordners, 6 fertige Chiffren, 8 fertige Akzente sowie Ideen, was man selbst ohne Python-Kenntnisse machen kann.
- Datei dictionaries/README.md (nur beim Klonen des Repositories von GitHub verfügbar — Release-Pakete filtern .md-Dateien) — detaillierte technische Dokumentation des YAML-Formats mit Beispielen, Feldlisten, Pipeline-Regeln, Regex. Dieses Dokument richtet sich an Linguisten mit Grundkenntnissen in Programmierung und an Entwickler.

Wichtige Hinweise für Benutzer von Bildschirmlesegeräten (NVDA)

1. Erfolgs- und Fehlermeldungen

Jede nachfolgende Regel arbeitet auf der Ausgabe der vorherigen. Dies ermöglicht den Aufbau von Pipelines wie „zerlege den Digraphen szcz in shch und ersetze dann ch durch h", birgt jedoch auch die klassische Falle für den Autor eines Sprachpakets.

Die „sequenzielle Schleifen"-Falle. Angenommen, für einen spanischen Akzent, der das polnische „ñ" an die Aussprache von Diego (Loquendo) anpassen soll, fügt der Autor zwei Regeln hinzu:
1. ñ → nj (damit das polnische „ñ" wie ein weiches „nj" klingt)
2. j → x (damit das polnische „j" wie das spanische „j" klingt — phonetisch /x/)

Nach dem Start stellt sich heraus, dass Wörter mit „ñ" als „nx" und nicht als „nj" ausgesprochen werden. Warum? Weil die erste Regel „ñ" in „nj" umwandelt, wird das neue „j" sofort von der zweiten Regel erfasst und in „x" umgewandelt. Ergebnis: Anstatt des beabsichtigten „ñ → nj" erhalten wir „ñ → nx".

Die Regel der Reihenfolge (universell). Wenn eine Regel ein Zeichen einführt, das in einer anderen Regel als Muster verwendet wird, IST DIE REIHENFOLGE WICHTIG. Eine sichere Heuristik: ZUERST das TARGET (das Zeichen, das später als wzor in einer anderen Regel verwendet wird) in etwas Sicheres umwandeln, DANN das SOURCE (das Zeichen, das sich in das TARGET auflösen soll) einführen. Für das spanische Beispiel korrekt: zuerst j → x, dann ñ → nj. Ergebnis: „ñ" ergibt „nj" (das zweite „j" wird nicht mehr erfasst, da die Regel j → x bereits angewendet wurde, als „nj" noch nicht existierte).

Wie man testet. Nach dem Ändern der Reihenfolge der Regeln in der Akzentdatei, lassen Sie einen Satz, der BEIDE Buchstaben enthält, durch den Regisseur-Modus laufen. Für das Beispiel ES: „Niño de paja juega" → das Ergebnis muss sowohl den ñ-Akzent („ñ → nj") als auch den j-Akzent („j → x") haben, also etwas wie „Ninjo de paxa xuega". Wenn Sie „ninxo" statt „ninjo" sehen — die Reihenfolge ist umgekehrt.

Validierung in der Engine (opt-in für Paketautoren). Die Anwendung verfügt über eine eingebaute Heuristik zur Erkennung potenzieller Schleifen, ist jedoch standardmäßig deaktiviert — da viele Pipelines wie eine Schleife aussehen, obwohl sie beabsichtigt sind (klassisches „szcz → shch" + „ch → h"). Um sie zu aktivieren: Setzen Sie die Umgebungsvariable REZYSER_VALIDATE_ZAMIANY=1 und starten Sie die Anwendung von der Konsole aus — aus der Quelle über python main.py, da das eingefrorene .exe im Fenstermodus (ab Version 17.0) kein Konsolenfenster hat. Die Engine gibt für jede Akzentdatei eine aggregierte WARN-Zeile mit den ersten drei potenziellen Schleifen und der Anzahl der verbleibenden aus. Überprüfen Sie die resultierende Phonetik am Testsatz — wenn der Effekt beabsichtigt ist, ignorieren Sie die WARN.

Die Schaltflächen zum Verschieben von Regeln im GUI-Regel-Manager (Drag-and-Drop, „Nach oben / Nach unten") sind eine separate Funktion, die für einen späteren Versionszyklus geplant ist — sie erfordert eine Neugestaltung des Managers (derzeit delegiert er die Bearbeitung der Datei an den externen System-Notizblock und hat keine eigene Regelansicht). Bis zur Implementierung: Bearbeiten Sie die YAML-Datei manuell, verschieben Sie Zeilen im Abschnitt zamiany:, verwenden Sie den Validator mit ENV-Variable und testen Sie an Kontrollsätzen.

SCHRITT 2B (erweitert, optional): Eigener KI-Anbieter kompatibel mit OpenAI

Die meisten Benutzer sollten beim empfohlenen Anthropic (SCHRITT 2) bleiben — er liefert die höchste Qualität. Wenn du jedoch einen eigenen Grund hast (Kosten, Zugang, Datenschutz, eigenes lokales Modell), kannst du ab Version 18.4 JEDEN Endpunkt angeben, der mit der OpenAI-API kompatibel ist — zum Beispiel OpenRouter, Groq, Fireworks, DeepSeek, lokales Ollama oder einen OpenAI-kompatiblen Gemini-Endpunkt. Die gesamte KI-Engine läuft dann über einen einzigen Pfad zu diesem Endpunkt, ohne separate Integration pro Anbieter.

Dies ist eine Option für Fortgeschrittene: Du konfigurierst sie manuell in der Datei golden_key.env, indem du neben (oder anstelle von) dem Anthropic-Schlüssel drei Zeilen sowie den Schlüssel des gewählten Anbieters hinzufügst:

LLM_PROVIDER=openai_compat
LLM_BASE_URL=adresse_des_endpunkts (z. B. https://openrouter.ai/api/v1)
LLM_MODEL=modellname_beim_anbieter (z. B. openai/gpt-4o-mini)
OPENAI_API_KEY=dein_schlüssel_bei_diesem_anbieter

So funktioniert es:
• Wenn LLM_PROVIDER=openai_compat gesetzt ist, nutzt die GESAMTE KI-Engine (Regisseur, Geschichten, Polyglott, Titel, Spracherkennung) den angegebenen Endpunkt, und der Modellname aus den Konfigurationsdateien wird durch LLM_MODEL überschrieben.
• Wenn die Zeile LLM_PROVIDER fehlt (oder den Wert anthropic hat), verhält sich die Anwendung wie in SCHRITT 2 — ausschließlich mit dem Anthropic-Schlüssel. Du musst nichts ändern.

Wichtig (Qualität): Die System-Prompts der Anwendung sind für Claude geschrieben und optimiert. Ein anderes Modell kann eine geringere Qualität liefern — es hält sich möglicherweise schlechter an die Weltregeln, verliert die JSON-Struktur in Modi mit Auswahlmöglichkeiten oder gibt Text in der falschen Sprache zurück. Dies ist ein bewusster Kosten↔Qualität-Kompromiss auf deiner Seite. Wenn dir das beste Ergebnis wichtig ist, bleib bei Anthropic.
