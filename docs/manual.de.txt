Audio AI Regisseur Handbuch - Komplettanleitung (Version 18.5.3 – Release-Version)

Willkommen im Hybriden Aufnahmestudio! Dieses Toolset ermöglicht das automatische Schreiben, Planen, Formatieren und Übersetzen von Hörspiel- und Hörbuchskripten. Es wurde für die Zusammenarbeit mit professionellen Sprachsynthesizern und lokalen Screenreader-Engines (NVDA) optimiert.

Das Set besteht aus dem Hauptstudio (Regie), einem Übersetzungs- und Akzentwerkzeug (Polyglott), einem Werkzeug zum Erstellen der Dateistruktur (Hörbucharchitekt), einem Regelmanager (ab Version 13.0 — ohne Python kannst du einen neuen Akzent, ein Chiffre oder einen kreativen Modus hinzufügen, siehe SCHRITT 7b unten) und — ab Version 15.0 — einem Geschichtenmodul (interaktive, zweite Person AI-generierte Fiktion, gelesen von TTS oder Screenreader, beschrieben in einem separaten Handbuch opowiesci.pl.txt). Alle fünf Werkzeuge sind in einem Programmfenster verfügbar, das über Schaltflächen in der Leiste oder Tastenkombinationen Ctrl+1..Ctrl+5 umgeschaltet werden kann.


SCHRITT 1: Erste Ausführung (Cross-Platform)

Laden Sie den neuesten Installer von der Registerkarte Releases auf GitHub herunter (Datei Rezyser_Audio_v<numer>_Installer.exe) und starten Sie ihn durch Doppelklick. Der Installer schlägt einen Standardinstallationspfad vor — den Ordner Programme im lokalen Verzeichnis Ihres Kontos — und erfordert keine Administratorrechte. Sie können einen eigenen Pfad mit der Schaltfläche „Durchsuchen" wählen; merken Sie sich diesen Pfad (er wird bei Updates nützlich sein — siehe „Automatische Updates" unten). Nach der Installation starten Sie das Programm über das Desktop-Icon oder das Startmenü. Nach kurzer Zeit erscheint das Hauptfenster des Programms — Audio GPT Regisseur. Ab Version 17.0 ist die Anwendung als nativer ausführbarer Datei im Fenstermodus eingefroren, sodass kein Terminalfenster mehr blinkt und sie schneller startet als zuvor. Kein Browser, kein Hintergrundserver. Wenn Sie die Arbeit beendet haben, schließen Sie einfach das Programmfenster.

Die gesamte Anwendung, einschließlich der Python-Engine, der Projekte und des API-Schlüssels, befindet sich in einem einzigen Ordner unter dem Installationspfad — der gesamte Ordner kann auf einen USB-Stick, in die Cloud oder auf einen anderen Computer verschoben werden (detaillierte Anleitung im Abschnitt „Projekte und API-Schlüssel übertragen" unten).

Wichtig: Der Ordner runtime/ im Installationsordner ist das PyInstaller-Bundle (ab Version 17.0) — er enthält einen isolierten Python-Interpreter und Bibliotheken, die ohne separate Systeminstallation einsatzbereit sind; er dient auch als Container für versteckte Projektdaten. Wenn Sie das Repository klonen (Entwicklungspfad), gibt es diesen Ordner nicht und sollte es auch nicht geben — Sie verwenden dann die virtuelle Umgebung venv, die im Abschnitt für Entwickler unten beschrieben ist.

--- Für Entwickler (Windows — Git-Repository) ---

1. Klonen Sie das Repository auf Ihre Festplatte.
2. Führen Sie die Datei setup_dev.bat aus. Das Skript erstellt automatisch eine virtuelle Python-Umgebung (venv) und installiert alle erforderlichen Abhängigkeiten aus der Datei requirements.txt.
3. Starten Sie die Anwendung mit dem Befehl python main.py oder über die Datei run_dev.bat — das Skript erkennt automatisch den venv-Ordner und startet das Programm.

--- Für Entwickler und normale Benutzer (macOS / Linux) ---

1. Klonen Sie das Repository auf Ihre Festplatte.
2. Öffnen Sie das Terminal im Projektordner und geben Sie den Skripten Ausführungsrechte: chmod +x *.sh
3. Führen Sie das Konfigurationsskript aus: ./setup_dev.sh — das Skript erstellt die venv-Umgebung und installiert die Abhängigkeiten.
4. Starten Sie die Anwendung: python main.py oder ./run.sh

Was Sie beim Start sehen: Beim Start des Programms öffnet sich ein Fenster mit dem Startbildschirm. Dort finden Sie eine kurze Beschreibung der verfügbaren Werkzeuge sowie den Abschnitt "Systemprüfung". Wenn der API-Schlüssel noch nicht konfiguriert ist, sehen Sie eine rote Nachricht, die darauf hinweist, dass KI-basierte Module (Regie, Übersetzer) nicht funktionieren — kostenlose lokale Funktionen (Akzente, Architekt) sind jedoch sofort aktiv. Die Konfiguration des Schlüssels wird im nächsten Schritt beschrieben.

Automatische Updates

Die Anwendung überprüft beim Start, ob auf GitHub eine neuere Version verfügbar ist — die Überprüfung erfolgt im Hintergrund und blockiert die Benutzeroberfläche nicht.

Wenn Sie das Programm über die fertige Installationsdatei (.exe) installiert haben: Bei Erkennung einer neueren Version erscheint ein Fenster mit der Frage, ob Sie diese herunterladen möchten. Nach Bestätigung wird ein Fortschrittsbalken angezeigt, und wenn der Download abgeschlossen ist, schließt sich die Anwendung automatisch und der neue Installer startet von selbst. WICHTIG: Stellen Sie im Fenster des neuen Installers sicher, dass der vorgeschlagene Installationspfad DERSELBE ist wie bei der ersten Installation (normalerweise im Feld „Zielordner" sichtbar). Wenn Sie den Standardvorschlag akzeptieren und ursprünglich einen anderen Pfad mit der Schaltfläche „Durchsuchen" gewählt haben, erhalten Sie eine ZWEITE leere Installation ohne Ihre Projekte und den API-Schlüssel — die erste bleibt an der alten Stelle, aber die Verknüpfung auf dem Desktop und im Startmenü wird auf die neue umgestellt. Wenn Sie denselben Pfad wie ursprünglich akzeptieren, überschreibt der Installer die Dateien der Anwendungs-Engine und das gesamte Regelpaket (Ordner dictionaries/) — Ihre Projekte (Ordner skrypty/, opowiesci/) und der API-Schlüssel (golden_key.env) bleiben unberührt. WICHTIG: Wenn Sie mit dem Regelmanager Dateien bearbeitet haben, die im Paket vorhanden sind (z.B. Akzentänderungen in `dictionaries/pl/akcenty/wloski.yaml`), werden diese Änderungen BEI EINEM UPDATE ÜBERSCHRIEBEN — machen Sie vor der Bestätigung des Updates ein Backup des Ordners `dictionaries/` gemäß der Anleitung im Abschnitt „Projekte und API-Schlüssel übertragen" unten (es reicht, den Ordner `dictionaries/` auf einen USB-Stick zu kopieren) und laden Sie ihn nach dem Update zurück, indem Sie die neueren Dateien überschreiben. Ganz neue Regeln, die Sie von Grund auf erstellt haben und die nicht im Paket enthalten sind (z.B. eine eigene zusätzliche Basissprache oder ein eigener Code), bleiben automatisch unberührt — der Installer entfernt keine Dateien außerhalb des Pakets. Ab Version 15.2.8 zeigt der Dialog, der das Update vorschlägt, diese Warnung direkt im Text an und enthält eine Schaltfläche „Ordner dictionaries öffnen", die mit einem Klick den Explorer an der richtigen Stelle öffnet — drücken Sie ihn vor der Bestätigung des Updates, um bequem ein Backup zu machen, und kehren Sie dann zum Dialog zurück und klicken Sie auf „Herunterladen und installieren".

Wenn Sie Ihren Installationspfad nicht mehr wissen, gibt es zwei schnelle Möglichkeiten, ihn wiederherzustellen. Windows 11: Wählen Sie im Kontextmenü der Desktop-Verknüpfung „Dateispeicherort öffnen" (wenn die Option im neuen vereinfachten Kontextmenü nicht sichtbar ist, wählen Sie zuerst „Weitere Optionen anzeigen" oder drücken Sie Shift+F10 zweimal, um sofort das vollständige Menü zu öffnen), gehen Sie eine Ebene höher mit der Rücktaste, markieren Sie den Ordner mit der Anwendung und drücken Sie Strg+Shift+C (oder wählen Sie „Als Pfad kopieren" im Kontextmenü) — der vollständige Pfad wird in Anführungszeichen in die Zwischenablage kopiert (beim Einfügen in den Installer denken Sie daran, die Anführungszeichen zu entfernen). Ältere Windows-Versionen (7/8/10): Klicken Sie mit der rechten Maustaste auf die Verknüpfung und wählen Sie „Eigenschaften"; auf der Registerkarte „Verknüpfung" im Feld „Ziel" sehen Sie den vollständigen Pfad zur ausführbaren Datei (`.exe` in Version 15.2.5+ oder `run.bat` in älteren Versionen) — kopieren Sie ihn und entfernen Sie den Dateinamen am Ende, es bleibt nur der Installationsordnerpfad.

Hinweis beim Update von älteren Versionen (v15.2.4 oder älter, als die Anwendung über `run.bat` aus dem Portable-ZIP-Paket gestartet wurde): Die vorhandene Desktop-Verknüpfung kann auf `run.bat` in der alten Location verweisen, die nach dem Update auf v15.2.5+ nicht mehr existiert — Versionen 15.2.5+ verwenden eine eigenständige `.exe`-Datei, die vom Installer erstellt wurde. Wenn die Verknüpfung nach dem Update nicht mehr funktioniert, löschen Sie sie manuell und lassen Sie den Installer während der Neuinstallation eine neue erstellen.

Wenn Sie das Git-Repository verwenden (Entwickler und macOS/Linux-Benutzer): Anstelle eines Vorschlags zum Herunterladen sehen Sie eine Information über die neue Version mit einem direkten Link zur Release-Seite auf GitHub. Laden Sie von dort das „Source code"-Archiv herunter oder aktualisieren Sie das Repository mit dem Befehl git pull.

Projekte und API-Schlüssel übertragen (Migration)

Wenn Sie Ihre Projekte, den API-Schlüssel und lokale Einstellungen auf einen anderen Computer übertragen möchten (oder alles nach einer Neuinstallation von Windows wiederherstellen möchten), müssen Sie keine einzelnen Dateien manuell kopieren — der gesamte Anwendungsordner ist autark.

1. Stellen Sie sicher, dass die Anwendung VOLLSTÄNDIG geschlossen ist. Wenn Sie das Programmsymbol im Systemtray sehen (neben der Uhr, rechts in der Taskleiste), klicken Sie mit der rechten Maustaste darauf und wählen Sie „Schließen". Geöffnete Dateien blockieren das Kopieren.
2. Finden Sie die Verknüpfung Audio GPT Regisseur auf dem Desktop. Klicken Sie mit der rechten Maustaste darauf (oder mit der Anwendungstaste oder Shift+F10 bei NVDA-Navigation) und wählen Sie die Option „Dateispeicherort öffnen". ACHTUNG bei Windows 11: Im neuen, vereinfachten Kontextmenü kann diese Option versteckt sein — wählen Sie zuerst „Weitere Optionen anzeigen" (oder drücken Sie Shift+F10 zweimal, um sofort das vollständige Menü mit der Option zu öffnen).
3. Es öffnet sich ein Windows-Explorer-Fenster im Installationsordner des Programms. Drücken Sie die Rücktaste (der einfachste Weg, funktioniert immer) oder klicken Sie auf den Pfeil „Nach oben" in der Symbolleiste, um eine Ebene höher zu gehen — dort sehen Sie den vollständigen Ordner mit der Anwendung. Hinweis: Die Tastenkombination Alt+Pfeil nach oben funktioniert nur, wenn der Fokus auf der Dateiliste liegt — wenn der Explorer mit dem Fokus auf der Adressleiste geöffnet wurde (typisch), macht Alt+Pfeil nach oben nichts, verwenden Sie dann die Rücktaste.
4. Kopieren Sie diesen gesamten Ordner auf einen USB-Stick, ein Cloud-Laufwerk (OneDrive, Google Drive, Dropbox) oder eine externe Festplatte. Der Ordner enthält alles, was zur Wiederherstellung des Arbeitszustands benötigt wird:
   - Ihre Projekte (Ordner skrypty/ — .txt-Dateien der Erzählungen, .md der Weltbücher, _streszczenie.txt; Ordner opowiesci/ — interaktive Spiele).
   - API-Schlüssel (Datei golden_key.env im Hauptordner der Anwendung).
   - Eigene phonetische Regeln, Akzente, Codes, wenn Sie etwas im Regelmanager bearbeitet haben (Ordner dictionaries/<kod>/, z.B. dictionaries/pl/akcenty/wloski.yaml).
   - Anwendungseinstellungen und Auswahl der kreativen Modi (Ordner runtime/skrypty/, .mode-Dateien).
   - Isolierte Python-Umgebung (Ordner runtime/), sodass Sie nichts auf dem neuen Computer installieren müssen.
5. Auf dem neuen Computer: Laden Sie den neuesten Installer von der Registerkarte Releases auf GitHub herunter und installieren Sie die Anwendung standardmäßig. Starten Sie das Programm einmal, um die leere Struktur der Konfigurationsdateien zu erstellen. Schließen Sie die Anwendung. Kopieren Sie dann den zuvor gespeicherten Ordner an den Installationsort und überschreiben Sie die Dateien — oder wählen Sie selektiv nur die für Sie interessanten Ordner (skrypty/, opowiesci/, golden_key.env) und fügen Sie sie an den entsprechenden Stellen der neuen Installation ein.

Tipp für NVDA-Benutzer: Das Kontextmenü „Dateispeicherort öffnen", das mit der Anwendungstaste aufgerufen wird, ist vollständig zugänglich — NVDA liest jeden Eintrag auf Deutsch. Nachdem der Explorer im Zielordner geöffnet wurde, verwenden Sie die Rücktaste, um eine Ebene höher zu gehen (funktioniert immer, unabhängig davon, ob der Fokus auf der Dateiliste oder der Adressleiste liegt), und dann Strg+A, um alles auszuwählen, und Strg+C, um zu kopieren.

Hinweis: Die Option „Dateispeicherort öffnen" ist der native Name für die deutsche Version von Windows. Im englischen System lautet sie „Open file location", in anderen Sprachversionen — analog in der lokalen Sprache des Betriebssystems.


SCHRITT 2: API-Versorgung (empfohlener Anthropic / Claude-Schlüssel)

Der empfohlene und standardmäßige KI-Anbieter ist Anthropic (Claude) — alle Prompts der Anwendung sind auf ihn abgestimmt, sodass er die höchste Erzählqualität und die beste Einhaltung der Weltregeln bietet. Bei dieser (empfohlenen) Variante genügt EIN API-Schlüssel in der Datei golden_key.env:

•  Anthropic-Schlüssel (Claude) — versorgt die GESAMTE KI-Engine: die Narration des Regisseurs (Hörbuch, Lesebühne, Brainstorming), den Geschichten-Modus, den Polyglott (Übersetzer) sowie die Vergabe von Kapiteltiteln und die Erkennung der Inhaltssprache. Beginnt mit sk-ant-.

Falls Sie von einer älteren Version aktualisieren: Der frühere OpenAI-Schlüssel wird für die Standardvariante nicht mehr benötigt — Sie können seine Zeile in golden_key.env belassen oder löschen, die Anwendung ignoriert sie (es sei denn, Sie konfigurieren bewusst einen anderen Anbieter — siehe SCHRITT 2B weiter unten).

So erhalten Sie einen Anthropic-Schlüssel:
1. Erstellen Sie ein Konto auf console.anthropic.com und laden Sie Guthaben auf (Reiter Billing / Plans).
2. Generieren Sie einen Schlüssel im Bereich API Keys (beginnt mit sk-ant-). Kopieren Sie ihn sofort — er wird mitunter nur einmal angezeigt.

So tragen Sie den Schlüssel in das Programm ein:
3. Klicken Sie auf dem Startbildschirm des Programms auf die Schaltfläche „Generiere die Datei golden_key.env und öffne den Texteditor". Das System erstellt automatisch eine saubere Konfigurationsdatei am richtigen Speicherort und öffnet den Editor mit einer bearbeitungsbereiten Vorlage.
4. In der geöffneten Datei sehen Sie die Zeile: ANTHROPIC_API_KEY=PASTE_YOUR_KEY_HERE. Löschen Sie den Platzhaltertext und fügen Sie Ihren Schlüssel direkt nach dem Gleichheitszeichen ein (ohne Leerzeichen und ohne Anführungszeichen). Speichern Sie die Datei und starten Sie die Anwendung neu.

Hinweis: Nach dem Neustart prüft die Anwendung die Datei und zeigt im Bereich „Systemprüfung" den Status des Schlüssels an. Er muss grün sein, damit alle KI-Module einsatzbereit sind. Fehlt der Schlüssel oder ist er fehlerhaft, weist das Programm klar darauf hin und ermöglicht es, den Texteditor zu öffnen, um den Fehler schnell zu beheben.

Dies ist Ihr Kontrollzentrum zum Erfinden von Geschichten und Schreiben von Drehbüchern. Gehen Sie dorthin, indem Sie auf die Schaltfläche "🎬  Regisseur" in der Symbolleiste klicken oder im Menü Werkzeuge → Regisseur auswählen (Tastenkombination: Strg+1).



WICHTIG: Projektdateiformat — Rückkehr zu .txt

In Version 7 wurden Projektdaten im Markdown-Format (.md) gespeichert, z.B. skrypty/znieczulica.md. Dies war ein absichtliches Experiment — das .md-Format sollte eine psychologische Barriere für nicht-technische Benutzer darstellen, um sie davon abzuhalten, die Datei im Notizblock zu öffnen und manuell zu bearbeiten (und damit versehentlich die Strukturüberschriften zu beschädigen).

Das Experiment hat sich nicht bewährt. KI bricht häufig eine der grundlegenden Regeln (mehr dazu in Kürze). Aus diesem Grund wurde in Version 8 zu einfachen .txt-Dateien zurückgekehrt — intuitiver und für jeden lesbar. Ein Projekt mit dem Namen "znieczulica" wird jetzt beispielsweise als skrypty/znieczulica.txt gespeichert, und seine Zusammenfassung als skrypty/znieczulica_streszczenie.txt. Dies ermöglicht es jedem, Regieanpassungen oder Textkürzungen leichter vorzunehmen.


⚠️ KRITISCHE REGEL FÜR SCHNITTMEISTER (LESEN SIE, BEVOR SIE BEGINNEN!) ⚠️

Alle Ihre generierten Skripte und Bücher werden in einfachen Textdateien (.txt) gespeichert, die Sie problemlos im Notizblock öffnen können.

Als Regisseur haben Sie das VOLLE RECHT (und sogar die Pflicht), diese Datei zu bearbeiten! Wenn die künstliche Intelligenz sich verrennt und z.B. das Problem der Charaktere am Ende des generierten Abschnitts selbst löst, öffnen Sie die Datei, löschen Sie die letzten Zeilen und lassen Sie den Text an der spannendsten Stelle abbrechen, und klicken Sie dann auf "Projekt von der Festplatte neu laden", um das Modellgedächtnis mit der korrigierten Datei zu synchronisieren, und "An die KI senden", um fortzufahren.

🔴 ABER - WAS SIE NICHT ÄNDERN DÜRFEN:

Verändern, löschen oder ändern Sie niemals Zeilen, die die Struktur betreffen (z.B. Akt 1, Szene 2, Kapitel 1, Prolog). Wenn Sie diese Überschriften beschädigen:
1. Wird Ihre Geschichte in Bildschirmlesegeräten (NVDA) auseinanderfallen.
2. Der Audiobook-Architekt und damit auch das Studio Eleven Labs können Ihr Buch nicht korrekt in Lesefragmente unterteilen.
3. Der interne Konverter der Anwendung wird kein korrektes Inhaltsverzeichnis in der Word-Datei oder auf der Zeitleiste in ElevenLabs generieren.

Bearbeiten Sie Dialoge, kürzen Sie die Handlung, aber lassen Sie die Struktur in Ruhe!


Wie benutzt man die Regie?

- Weltbuch (linke Seitenleiste): Hier geben Sie die Regeln des Universums ein. Jedes Projekt hat jetzt ein eigenes Weltbuch, das mit dem Dateinamen verknüpft ist — wenn Ihre Geschichtsdatei z.B. emilia_heist_audiobook.txt ist, wird das Weltbuch als skrypty/emilia_heist_audiobook.md gespeichert. Daher ist die Reihenfolge wichtig: Geben Sie zuerst den Projektdateinamen im Feld "Projektdateiname" ein, und erst dann können Sie das Weltbuch speichern. Die Schaltfläche "💾 Buch dauerhaft speichern" bleibt ausgegraut, bis Sie einen Namen angeben. Das Laden eines vorhandenen Projekts mit der Schaltfläche "Geschichte laden" lädt automatisch auch die entsprechende .md-Datei — Sie müssen nichts manuell tun. Hinweis: Ohne ausgefülltes Weltbuch blockiert die Anwendung das Senden von Anfragen an die KI — dies ist eine bewusste Sicherheitsmaßnahme, die Sie davor schützt, Text ohne Regeln zu generieren.
- Langzeitgedächtnis (linke Seitenleiste): Das zweite Feld in der Seitenleiste. Hier speichert die KI automatisch eine Zusammenfassung der Handlung, wenn der Speicher voll wird. Sie können hier auch manuell eigene Notizen eingeben — das Modell behandelt sie als "was ich bereits weiß", bevor es die aktuelle Szene liest. HISTORISCHE LÜCKE (behoben in v15.5): Früher, wenn Sie hier eine sehr kurze Notiz eingaben und auf „Zusammenfassung speichern" klickten, bevor in der Erzählungsdatei etwas Bedeutendes war, lud die Anwendung beim nächsten Mal PRIORITÄR die Zusammenfassung und ÜBERSPRANG die vollständige Geschichte — das Modell erhielt dann nur das Weltbuch und eine Ein-Satz-Notiz, ohne Kontext des Tons und der letzten Szenen. Ab v15.5 ist das Laden intelligent: Wenn die gesamte Geschichte in das Kontextfenster passt, wird sie vollständig geladen (und die unnötige alte Zusammenfassung gelöscht), sodass das Modell den Kontext nicht verliert. Nach manueller Bearbeitung der Erzählungsdatei im Editor verwenden Sie die neue Schaltfläche „Projekt von der Festplatte neu laden" (ab v15.5), die mit einem Klick den internen Speicher mit der Festplatte synchronisiert; zum Öffnen der Datei im Editor dient weiterhin „Öffne Erzählungsdatei…".
- Brainstorming-Modus: Geben Sie eine lose Idee ein, und die KI gibt Ihnen 3 Optionen zur Weiterentwicklung der Handlung. Für jede Option wird sofort ein fertiger Block "--- PROMPT-ENTWURF ---" generiert. Nachdem Sie eine ausgewählt haben, fügen Sie diesen Prompt in den Skript- oder Audiobook-Modus ein und geben Sie eventuelle Anmerkungen oder Informationen für das Modell ein. Das Handlungsgedächtnis ändert sich während des Brainstormings nicht — Sie können ohne Risiko experimentieren!
- Rohskript-Modus (ab v16.0 — Lesetheater): Hier fügen Sie den in der Brainstorming-Phase generierten "Prompt-Entwurf" ein. Die KI schreibt einen langen erzählerisch-dialogischen Abschnitt: Erzählung (Szenerie, Zeit, Aktion) in Tags [Erzähler: ...] und Charakterdialoge in Tags [Name: Emotion]. Ohne Soundeffekte — der Kontext wird durch die Worte des Erzählers vermittelt. Der Text wird automatisch Ihrer Datei (z.B. neue_szene.txt) im Ordner skrypty/ hinzugefügt. Ein solches fertiges Skript können Sie später in ein mehrstimmiges Hörbuch umwandeln (Brücke zu ElevenLabs Studio — separates Kapitel weiter unten).
- Traditioneller Audiobook-Modus: Modus für Schriftsteller. Die KI generiert reine literarische Prosa — keine Tags, keine Phonetik, klassische Dialoge in die Erzählung eingebettet. Der Text wird genauso in die Datei eingefügt wie im Skript-Modus.
- Automatische Charaktererstellung: Das Skript ist so programmiert, dass es automatisch neue Tags [Speaker] erstellt, wenn die Handlung einen neuen Charakter erfordert. Tipp: Wenn die KI einen coolen Charakter erstellt, kopieren Sie dessen Tag und fügen Sie ihn in das Weltbuch ein, damit das Modell ihn dauerhaft speichert!

Projektmanagement — drei Aktionsschaltflächen:
- Geschichte laden: Lädt ein bestehendes Projekt in den Speicher. Verfügbar, wenn der aktuelle Speicher leer ist. Ab Version 15.2.3 unterstützt es zwei Pfade: Wenn das Projektname-Feld leer ist, öffnet sich ein Dialog zur Auswahl aus einer Liste aller im Ordner skrypty/ gefundenen Projekte (überspringt Zusammenfassungsdateien) — NVDA liest die Liste natürlich vor, der Benutzer muss sich den Namen nicht merken und eingeben. Wenn das Namensfeld ausgefüllt ist, versucht die Anwendung sofort, das Projekt mit diesem Namen zu laden (Expertenpfad: Enter im Namensfeld oder Klick nach Eingabe aus dem Gedächtnis).
- Projekt schließen (Harter Reset): Löscht das Projekt vollständig. Entfernt Geschichte, Zusammenfassung, Weltbuch und setzt alle Zähler zurück. Verwenden Sie es beim Wechsel des Projekts oder einer neuen Geschichte.
- Öffne Erzählungsdatei… (ab v15.2.3): Notfallbearbeitung der Erzählungsdatei im systemeigenen Texteditor. Erfordert einen eingegebenen Projektnamen. Die Anwendung öffnet skrypty/<nazwa>.txt im Notizblock (Windows), TextEdit (macOS) oder dem Standard-GUI-Editor (Linux). Typische Szenarien: (a) Die KI schließt die Szene nicht ab und Sie möchten das Ende manuell hinzufügen; (b) Sie haben ein Projekt mit Zusammenfassung geladen und möchten die letzten Szenen in das Langzeitgedächtnis kopieren, damit das Modell den vollständigen Tonkontext hat (architektonische Lücke oben beschrieben); (c) Sie möchten einen Textschnitt in der Mitte eines Kapitels machen, den die Anwendungs-Engine nicht nativ unterstützt.
- Projekt von der Festplatte neu laden (ab v15.5, umgebaut in v17.6): Lädt das GESAMTE Projekt nach manueller Bearbeitung der Erzählungsdatei von der Festplatte neu — dies ist ein tatsächliches Reload, nicht nur eine Aktualisierung des aktuellen Speichers. Berechnet die Zähler für Kapitel/Akte/Szenen neu, hebt das Weltbuch, den Modus und die Optionen für das Brainstorming an und synchronisiert den Arbeitsspeicher. Wenn die gesamte Geschichte in das Kontextfenster passt, wird sie vollständig geladen (und die unnötige alte Zusammenfassung gelöscht, damit die Engine mit dem vollständigen Text arbeitet). Wenn die Geschichte lang ist und eine gespeicherte Zusammenfassung hat, bleibt diese unberührt und fragt Sie, ab welcher Überschrift der Arbeitsspeicher der KI starten soll: Im Audiobook-Modus wählen Sie das Kapitel, im Skript-Modus zuerst den Akt und dann die Szene dieses Akts (oder den gesamten Akt) — der Rest wird durch die Zusammenfassung dargestellt. Abbrechen der Auswahl = Notfallschnitt zum letzten Textfragment (daher ist es wichtig, die Struktur der Überschriften beizubehalten). Bevor die Felder mit der Version von der Festplatte überschrieben werden, warnt es, wenn Sie ungespeicherten Inhalt darin haben. Typisches Szenario: Die KI hat die Szene falsch geschlossen (hat das Anti-Closure gebrochen), Sie schneiden das falsche Ende im Editor ab und klicken auf Neu laden — kein Korrigieren an zwei Stellen mehr.

Historische Notiz — warum Modi jetzt vor versehentlicher Änderung geschützt sind:
In früheren Versionen der Anwendung hat niemand die Konsistenz des kreativen Modus innerhalb eines Projekts überwacht. Das Ergebnis war eine subtile kreative Möglichkeit, die man so beschreiben könnte: Sie beginnen die Geschichte im Skript-Modus, fügen "Akt 1" und "Szene 1" ein (die Anwendung ist begeistert von Ihrer Konsequenz), generieren einige Bildschirme Spannung mit Tags [SFX: Türknall] und [Speaker 1: Marek - resigniert]... und dann — weil gerade Inspiration kam — klicken Sie auf "Kapitel 1 einfügen". Die Anwendung fügt den Überschrift "Kapitel 1" ohne mit der Wimper zu zucken direkt nach "Szene 3" in die Datei ein. Sie haben jetzt in der Datei eine Hybridstruktur aus einem 50er-Jahre-Radiohörspiel und einem Gesellschaftsroman. ElevenLabs sieht diese Struktur, erkennt die Kapitelüberschrift mitten im Akt und entscheidet, dass es wahrscheinlich ein Fehler in der Matrix ist. Das Inhaltsverzeichnis sieht aus wie das Werk eines avantgardistischen Künstlers. Der Audiobook-Architekt hingegen geht davon aus, dass Sie ein erwachsener Mensch sind und verarbeitet es einfach ohne ein Wort — aber auch ohne jegliche Garantie für das Ergebnis. Ab Version 12.0 versuchte die Benutzeroberfläche, den Wechsel des Speicherformats zu blockieren — zumindest in der Theorie. Die Praxis erwies sich als kreativer: Brainstorming (immer als Planungsmodus aktiv) war eine Hintertür, durch die man mit den Pfeiltasten nach oben und unten zwischen Skript und Audiobook wechseln konnte (Audiobook → Brainstorming → Skript und umgekehrt). Der erste Klick auf „Akt 1 einfügen" oder „Kapitel 1 einfügen" im neu gewählten Modus überschreibt die .mode-Datei glatt und mischt Akte mit Kapiteln in einer Erzählungsdatei. Erst ab Version 15.2.3 haben wir einen echten Schutz: Nach der Festlegung des Modus (erste Struktur oder erste erfolgreiche Produktionssendung) ist die zweite Speicherposition im RadioBox tatsächlich deaktiviert. Brainstorming bleibt immer als Notfallmechanismus aktiv — es generiert eine Zusammenfassung bei Überfüllung des Kontextfensters und Handlungsoptionen — aber es ist nicht mehr möglich, darüber in einen anderen Speicherformatmodus zu wechseln.


Showrunner-Prompts — KI als Serien-Drehbuchautor (aus Version 7, beibehalten)

Dies ist die größte Änderung, die in Version 7 eingeführt wurde und unverändert beibehalten wurde. Sie ist nicht in der Benutzeroberfläche sichtbar, verändert jedoch radikal die Qualität der generierten Handlung.

Ein Showrunner ist in der Fernsehbranche die Person, die für das Gesamtbild einer Serie verantwortlich ist — er sorgt dafür, dass die Handlung niemals zu einer einfachen Lösung führt, sondern ständig dichter wird, Konflikte aufbaut und den Zuschauer über viele Staffeln hinweg in Spannung hält. In Version 7 wurde diese Philosophie direkt in die systemischen Anweisungen der KI eingebaut.

Anti-Closure-Direktive — Status in Version 8

Trotz der Erprobung verschiedener Ansätze wird das Anti-Closure-Verbot häufig notorisch vom Modell gebrochen, insbesondere im traditionellen Audiobook-Modus. Die KI hat eine starke Tendenz, die Geschichte bei jeder Gelegenheit zu "schließen" — sie fügt zusammenfassende Sätze in die Handlung ein, schafft falsche Happy Ends oder schließt Handlungsstränge mitten im Kapitel, als wäre jeder Abschnitt der letzte. Das Ergebnis ist, dass der nächste Abschnitt von vorne beginnt, ohne natürliche Kontinuität.

Deshalb ist die oben beschriebene Regel des Schnittmeisters so wichtig: Wenn die KI das Verbot bricht und die Szene selbst schließt, ist es Ihre Aufgabe als Regisseur, die .txt-Datei zu öffnen, diese letzten Sätze zu löschen und den Text an einer spannenden Stelle abzubrechen, und dann auf "Projekt von der Festplatte neu laden" zu klicken, um das Gedächtnis mit der korrigierten Datei zu synchronisieren.

Jeder Modus hat eine eingebaute Anti-Closure-Direktive:

- Brainstorming: Die KI agiert wie ein Drehbuchautor einer mehrstaffeligen Serie. Jede der 3 vorgeschlagenen Optionen MUSS Hindernisse aufbauen, neue Dilemmata einführen, offene Handlungsstränge und Cliffhanger enthalten. Es ist absolut verboten, Optionen vorzuschlagen, in denen die Charaktere dauerhaft Frieden schließen, das Hauptproblem ohne erhebliche Konsequenzen überwinden oder die Geschichte zu einem hastigen Ende führt. Es ist verboten, billige, magische Orte zu erfinden, die die Weltarchitektur brechen.
- Rohskript-Modus: Absolutes Verbot, den Text mit Zusammenfassungen, Moral oder Klammern zu beenden. Die KI soll die Handlung natürlich an einem spannenden Punkt (Cliffhanger) abbrechen, ohne eine Schlussfolgerung zu ziehen, damit der nächste Abschnitt die Erzählung nahtlos übernehmen kann.
- Traditioneller Audiobook-Modus: Absolutes Verbot, den Text mit pathetischen Zusammenfassungen, dem Schließen von Handlungssträngen oder dem Andeuten eines Endes der Geschichte zu beenden (z.B. "Sie war bereit für neue Herausforderungen", "Sie verstand, dass es Zeit war, weiterzugehen"). Der Text soll mitten in der laufenden Handlung, Spannung oder einem offenen Gedanken abbrechen.

Ausnahme von der Regel: Wenn Sie ausdrücklich um ein Ende, einen Abschluss oder einen Epilog bitten, wird die KI ein zufriedenstellendes Ende der Geschichte generieren — das Verbot gilt nicht, wenn Sie es selbst anfordern.


Verwaltung von Akten und Szenen (Skript-Modus, aus Version 7, beibehalten)

Der Rohskript-Modus verfügt über ein dediziertes Panel "✂️ Strukturverwaltung" mit Schaltflächen zum Aufbau der Hörspielstruktur in Echtzeit.

- Akt X einfügen: Fügt eine Aktüberschrift ein (z.B. "Akt 2") UND fügt automatisch darunter "Szene 1" hinzu — denn jeder neue Akt beginnt mit der ersten Szene. Der Aktzähler springt auf die nächste Nummer, und der Szenenzähler wird auf 2 zurückgesetzt (bereit für die nächste Szene in diesem Akt).
- Szene X einfügen: Fügt nur die Szenenüberschrift ein (z.B. "Szene 3") innerhalb des aktuellen Akts. Der Szenenzähler erhöht sich automatisch.

Intelligentes Laden der Datei: Wenn Sie eine bestehende Skriptdatei laden, scannt die Anwendung sie automatisch und stellt die Zähler für Akte und Szenen auf die richtigen Nummern ein. Der Szenenzähler wird immer innerhalb des letzten Akts in der Datei berechnet.

Prolog und Epilog: Die Schaltflächen "📜 Prolog einfügen" und "🏁 Epilog einfügen" sind für beide Modi gemeinsam und im gleichen Panel verfügbar.

Der Audiobook-Architekt wandelt Akte automatisch in Hauptnavigationspunkte (Heading 1) für ElevenLabs und NVDA um — Szenen werden als fettgedruckter Text im Dokument sichtbar, aber im Inhaltsverzeichnis unsichtbar.


Intelligente Kapitelverwaltung (Audiobook-Modus, aus Version 5, beibehalten)

Das LLM generiert maximal etwa 5000 Zeichen pro Anfrage — das ist zu wenig für ein vollständiges Kapitel. Daher arbeiten Sie iterativ: Sie generieren weitere Fragmente mit der Schaltfläche "An AI senden", bis Sie der Meinung sind, dass das Kapitel fertig ist. Dann klicken Sie auf "Kapiteltrennung einfügen" — die Anwendung fügt eine Überschrift in die Datei und das Gedächtnis ein, und der Kapitelzähler springt automatisch auf die nächste Nummer.

Schaltflächen im Panel:

- Kapiteltrennung einfügen (Kapitel X): Fügt eine Überschrift (z.B. "Kapitel 3") in die Datei und das Gedächtnis ein. Der Kapitelzähler aktualisiert sich automatisch.
- Prolog einfügen: Funktioniert nur am Anfang, wenn das Gedächtnis leer ist. Schutz vor versehentlichem Einfügen eines Prologs mitten in der Geschichte.
- Epilog einfügen: Schließt die Geschichte ab. Nach dem Einfügen eines Epilogs mit Inhalt blockiert die Anwendung die Generierung neuer Fragmente — das ist beabsichtigt, denn nach dem Abschluss der Geschichte gibt es nichts mehr hinzuzufügen.

Intelligentes Laden der Datei: Wenn Sie eine bestehende Datei laden, scannt die Anwendung sie automatisch und stellt den Kapitelzähler auf die richtige Nummer ein. Wenn die Datei einen Prolog und drei Kapitel hat, zeigt der Zähler "Kapitel 4" an — ohne manuelles Zählen.


Handlungsakku — wie das Gedächtnis der KI funktioniert

Nur der reine Text der Geschichte gelangt in das Gedächtnis des Modells — das, was die KI tatsächlich geschrieben hat. Anweisungen, Optionen und Pläne verschwinden nach Gebrauch und belasten den Kontext nicht. Das Ergebnis? Das Modell bleibt länger fokussiert, erinnert sich besser an die Akzente der Charaktere und weicht seltener von den Regeln des Weltbuchs ab.

Der "Modellspeicher"-Indikator auf dem Bildschirm zeigt an, wie voll das Kontextfenster des Modells ist. Seit Version 15.1 ist dies NICHT mehr das Zählen der reinen Zeichen der Geschichte — die Anwendung zählt reale TOKEN (mit der gleichen Methode, die das Modell verwendet) und summiert die GESAMTE Last, die an die KI gesendet wird: die aktuelle Geschichte, das Langzeitgedächtnis (Zusammenfassung) UND das Weltbuch. Daher wächst der Indikator auch, wenn Sie das Weltbuch erweitern oder eine lange Zusammenfassung haben — nicht nur durch die Erzählung selbst. Der Wert wird als Prozentsatz der Auslastung des Fensters angezeigt:
- Grün (bis ca. 70%): Das Modell ist voll fokussiert, Sie haben einen sicheren Puffer.
- Gelb (ca. 70–90%): Sie nähern sich der Grenze. Die KI könnte beginnen, Aussagen zu kürzen und Regeln zu ignorieren; im Planungsmodus (Brainstorming) beginnt die Engine, eine Zusammenfassung zu erzwingen. Beginnen Sie langsam, den Handlungsstrang zu schließen.
- Rot (über ca. 90%): Kritische Überlastung!

Diagnose der Zusammenfassungsgrenze (wenn die KI früher halluziniert als die Grenze angibt): Die Grenzen (Warnung ~70%, Alarm ~90%) sind empirisch geschätzt. Wenn Sie eine wiederkehrende Tendenz bemerken, dass das Modell „von den Regeln abweicht" oder zu halluzinieren beginnt, BEVOR der Indikator in den gelben/roten Bereich geht — also früher, als die Grenze angibt — öffnen Sie ein Issue im Anwendungsrepository und beschreiben Sie, bei welcher ungefähren Auslastung (Prozentsatz) es tatsächlich beginnt, sich aufzulösen, am besten mit einem Beispiel. Wenn sich diese Tendenz breiter bestätigt (bei anderen Benutzern, in verschiedenen Projekten), wird die automatische Zusammenfassungsgrenze im nächsten Patch gesenkt. Dies ist ein bewusst iterativer Mechanismus — besser, ihn auf realen Daten abzustimmen, als von vornherein zu raten.

Unendliches Gedächtnis (aus Version 6, beibehalten)

Wenn der rote Alarm aufleuchtet, müssen Sie die Zusammenfassung nicht mehr manuell kopieren. Geben Sie im Brainstorming-Modus einen Befehl mit dem Wort "Zusammenfassung" oder "Resümee" ein — die KI generiert eine prägnante Wissenskapsel über die gesamte bisherige Handlung. Klicken Sie dann auf die Schaltfläche "Zusammenfassung speichern (dauerhaft)" — die Anwendung erstellt automatisch eine Datei _zusammenfassung.txt im Ordner skrypty/ und schützt sie vor versehentlichem Überschreiben. Nach dem Speichern leeren Sie das Gedächtnis und können im aktuellen Dokument weiterschreiben. Die Zusammenfassung laden Sie vor der nächsten Sitzung in das Feld Langzeitgedächtnis — und Sie können die Geschichte endlos fortsetzen, ohne Längenbeschränkungen.

Wann zusammenfassen (aktualisiert in v15.5): Sie müssen sich nicht mehr an eine starre Zeichengrenze „vor Arbeitsende" halten. Am besten fassen Sie nach dem natürlichen Abschluss eines größeren strukturellen Teils zusammen — nach dem Ende einer Szene, eines Akts oder eines Kapitels. Grund: Wenn Sie später das Ende manuell im Erzählungsdokument korrigieren und auf „Projekt von der Festplatte neu laden" klicken, fragt die Anwendung, ab welcher Überschrift der frische Abschnitt wiederhergestellt werden soll — und die Zusammenfassung des früheren Teils bleibt unberührt (kein Korrigieren an zwei Stellen mehr). Daher ist es umso wichtiger, die Struktur beizubehalten: Regelmäßig Kapitel/Akt/Szene-Überschriften aus dem Strukturpanel einfügen (lange Formen ohne Akte/Kapitel, z.B. „modernistisches Drama" in einem Zug, werden nicht empfohlen). AUSNAHME: Wenn Sie eine sehr lange Geschichte VÖLLIG ohne Überschriften führen, bleibt das Generieren und Speichern einer Zusammenfassung vor einer Pause notwendig — ohne Marker kann die Anwendung nur das letzte Zeichenfragment wiederherstellen, und der Motor könnte ohne Kontext „in Panik geraten".

Automatische Zusammenfassung: Wenn das Gedächtnis in den Alarmzustand gerät, schaltet das Brainstorming automatisch in den Notfallmodus — anstatt sofort Optionen zu generieren, erstellt es zuerst eine detaillierte Zusammenfassung der gesamten bisherigen Handlung und speichert sie in <ZUSAMMENFASSUNG>-Tags. Die Anwendung erkennt diese Tags und überträgt die Zusammenfassung automatisch in das Feld Langzeitgedächtnis. Keine manuelle Arbeit!

Intelligentes Laden und Neuladen von der Festplatte (aktualisiert in v17.6): Sowohl beim Laden eines Projekts als auch nach dem Klicken auf „Projekt von der Festplatte neu laden" (nach manueller Bearbeitung der Erzählungsdatei im Editor) stimmt die Anwendung das Gedächtnis mit der Festplatte ab — sie berechnet die Strukturzähler neu und hebt das Weltbuch und den Modus an. Wenn die GESAMTE Geschichte in das Kontextfenster passt — lädt sie sie vollständig, und die unnötige alte Zusammenfassung wird gelöscht, damit der Motor mit dem vollständigen Text arbeitet (dies schließt die alte Lücke, in der das Modell nur die Zusammenfassung ohne den Kontext der letzten Szenen erhielt). Wenn die Geschichte LANG ist und eine gespeicherte Zusammenfassungsdatei hat — bleibt die Zusammenfassung unberührt und fragt Sie, ab welcher Strukturüberschrift (Kapitel/Akt/Szene) das Arbeitsgedächtnis der KI starten soll; der Rest der Handlung wird durch die Zusammenfassung dargestellt. So verschwenden Sie keine Tokens für das erneute Laden der gesamten Geschichte, und gleichzeitig wird die nächste Zusammenfassung nicht auf veralteten Daten erstellt.


SCHRITT 3b: Zwei Ausgaben des Skripts — mehrstimmiges Hörbuch (ElevenLabs) und Version für Screenreader

Das fertige Skript des Lesetheaters (Skript-Modus) hat zwei unabhängige Ausgaben: ein mehrstimmiges ElevenLabs Studio-Projekt (Audio) sowie eine HTML-Version für Screenreader. Das sind zwei Wege, dasselbe Stück zu „hören" — du kannst eine, die andere oder beide verwenden. Beide sind optional und ändern nichts am klassischen Ablauf mit dem Konverter.

─────────── Brücke zu ElevenLabs Studio (Audio, optional) ───────────

Die Brücke verwandelt das Skript in ein mehrstimmiges Studio-Projekt — Erzähler und jede Figur erhalten eine eigene Stimme. Ohne ElevenLabs-Schlüssel ändert sich nichts: Die Brücke bleibt einfach verborgen.

ElevenLabs-Schlüssel (optional)

Füge deinen ElevenLabs-Schlüssel in die Datei golden_key.env ein, in einer eigenen Zeile: ELEVENLABS_API_KEY=sk_... Hinweis: Der ElevenLabs-Schlüssel beginnt mit sk_ (mit UNTERSTRICH), anders als der Anthropic-Schlüssel (sk-ant-). Wenn du einen eingeschränkten Schlüssel (Restricted Key) verwendest, weise ihm die Berechtigungen (Scopes) projects_write sowie voices_read zu. Der Status des Schlüssels ist auf dem Hauptbildschirm (System Check) sichtbar — ein fehlender Schlüssel ist kein Fehler, die Brücke bleibt einfach verborgen.

Die Brücke erscheint im Regisseur-Panel im Skript-Modus (wenn der Schlüssel korrekt ist). Sie arbeitet mit einem fertigen, auf der Festplatte gespeicherten Stück — generiere oder lade zuerst das Projekt, dann wechsle zur Brücke.

Schritt 1 — Stimmbesetzung

Klicke auf „Obsada głosowa…". Die Anwendung liest die Figuren mit Sprechrollen aus deinem Skript aus und fügt immer einen Erzähler-Slot hinzu (der Erzähler ist die Standardstimme — er liest Kapitelüberschriften und die gesamte Narration). Füge für jeden Sprecher eine Voice ID ein. WICHTIG: Jede im Stück verwendete Stimme muss sich zuerst in deinen „My Voices" befinden — Stimmen, die du selbst erstellst (z. B. in „Voice Design"), landen dort automatisch, während Stimmen aus der öffentlichen Bibliothek du im Tab „Explore" durchsuchst und mit der Schaltfläche „Add to My Voices" hinzufügst. So erhältst du eine Voice ID in ElevenLabs (im Browser): Finde die Stimme, spiele die Probe ab, um sicherzugehen, dass es die richtige ist, und kopiere ihre Kennung mit der Schaltfläche „Copy Voice ID"; wenn die Stimme bereits in „My Voices" ist, ist diese Schaltfläche sofort verfügbar — ohne „More actions" aufzuklappen. Stimmauswahl: Um eventuelle Regenerierungen zu minimieren, wähle am einfachsten aus der Kollektion „Best for Eleven v3" (Stimmen, die für das v3-Modell geprüft wurden, auf dem das Projekt erstellt wird); alternativ entwirf eine eigene Stimme in „Voice Design", und für Mutige bleibt das Klonen per IVC (Instant Voice Cloning) oder PVC (Professional Voice Cloning). Du kannst Felder leer lassen und später zurückkehren — die Speicherung ist ein Entwurf.

Schritt 2 — Projekt erstellen

Klicke auf „Stwórz projekt ElevenLabs Studio…". Die Anwendung prüft, ob das Skript mindestens ein Kapitel (Prolog/Akt/Kapitel) hat und ob jedem Sprecher sowie dem Erzähler eine Stimme zugewiesen ist, und erstellt dann in deinem Konto ein mehrstimmiges Studio-Projekt, das in Kapitel unterteilt ist. Das bloße Erstellen des Projekts verbraucht KEINE Credits. Die Anwendung stellt sofort die Projektsprache ein (korrekte Aussprache der Kopfzeilen) sowie die Lautstärkenormalisierung nach Hörbuch-Standard — das geschieht über die API, damit du nicht in die Projekteinstellungen im Browser eingreifen musst.

Format-Wächter (Erweiterung der Monteur-Regel): Die Brücke erfordert, dass im Skript JEDE Zeile entweder eine Äußerung mit Sprecher-Markierung ist ([Narrator: …] oder [Name: …]) oder eine Strukturüberschrift (Prolog, Akt, Szene, Kapitel). Gewöhnliche, nicht getaggte Prosa, die „frei" eingetragen wurde — zum Beispiel eine Autorennotiz oder ein Erzählabschnitt ohne Tag — wird keiner Stimme zugeordnet und beim Erstellen stillschweigend übergangen, sodass das fertige Projekt von deiner Datei abweichen könnte. Wenn die Anwendung solche verwaisten Zeilen erkennt, zeigt sie daher deren Liste mit Nummern an und fragt, ob trotzdem gebaut werden soll: Du kannst dann abbrechen und das Skript korrigieren (öffne es mit der Schaltfläche „Otwórz plik narracji…", füge fehlende Sprecher-Markierungen hinzu oder entferne diese Zeilen) oder bewusst trotzdem bauen und deren Auslassung in Kauf nehmen. Das ist eine natürliche Erweiterung der Monteur-Regel: So wie Strukturüberschriften nicht beschädigt werden dürfen, sollte in einem für die Brücke bestimmten Skript jede Zeile einen Sprecher haben oder eine Überschrift sein.

Schritt 3 — Rendering im Browser

Nach dem Erstellen des Projekts zeigt die Anwendung dessen Kennung sowie eine Schaltfläche an, die ElevenLabs Studio öffnet. Finde das Projekt im Browser, rendere die Sprache (das verbraucht erst jetzt Credits — ungefähr 1 Credit pro Zeichen), und exportiere dann die Audiodatei oder veröffentliche das Projekt im Eleven Reader. Rendering und Veröffentlichung erfolgen auf deiner Seite, bewusst — die Anwendung erstellt lediglich das Projekt.

Ausdruck und Akzente (Modell Eleven v3)

Das Projekt wird auf dem Modell Eleven v3 erstellt (über 70 Sprachen). Emotionen werden NICHT durch Großbuchstaben, Auslassungspunkte oder Gedankenstriche ausgedrückt — die Engine ignoriert das. Stattdessen fügt der Regisseur in die Äußerungen englische Audio-Tags v3 ein, zum Beispiel [whispers], [sighs], [angry], [laughs] — diese steuern den Ausdruck und funktionieren unabhängig von der Sprache der Rede. Der AKZENT einer Figur ergibt sich hingegen aus der STIMMPROBE: Wenn jemand z. B. Polnisch mit einem fremden Akzent sprechen soll, wähle oder entwirf in Voice Design eine Stimme, deren Probe diesen Akzent hat. Experimentiere in der Praxis mit dem Stimm-Prompt, bis du z. B. eine polnische Probe mit finnischem Akzent hörst — das Modell v3 behält diesen Akzent in der fertigen Aufnahme bei. Hinweis: Sehr lange Sätze schwächen den Akzent ab, daher wird der Regisseur im Prompt bereits um kurze Sätze gebeten.

Bewusstsein über Modell v3 (Alpha-Phase)

Eleven v3 ist am ausdrucksstärksten, befindet sich aber noch in der Alpha-Phase. Es kann vorkommen, dass eine einzelne Replik als Knistern statt als Sprache gerendert wird — es reicht, sie im Studio neu zu generieren (jeder Block hat einige kostenlose Regenerierungen). In den ElevenLabs-Projekteinstellungen können auch Empfehlungen zur Modellwechsel angezeigt werden (auf Eleven Flash v2.5 oder Multilingual v2) — das ist KEIN Fehler, sondern nur ein Hinweis der Engine. Wenn du diese Meldungen nicht sehen möchtest, öffne einfach nicht die Projekteinstellungen: Die Anwendung hat bereits alles Notwendige über die API eingestellt (Modell, Sprache, Lautstärkenormalisierung).

Warum Lesetheater und keine Soundeffekte? In früheren Versionen produzierte der Skript-Modus rohe Effekte [SFX: ...] ohne Erzähler. Die Brücke zu einer fertigen, mehrstimmigen Aufnahme erfordert jedoch, dass der Kontext (Ort, Zeit, Handlung) vom Erzähler in Worten getragen wird: Soundeffekte in Studio sind für Screenreader nicht zugänglich, und das Modell realisiert ohnehin entweder den Erzähler oder Effekte — niemals stabil beides gleichzeitig. Daher ist der Skript-Modus ein Lesetheater: Erzähler plus Dialog, ohne SFX.

─────────── Version für Screenreader (HTML, ohne ElevenLabs) ───────────

Im Skript-Modus hast du unabhängig vom ElevenLabs-Schlüssel die Schaltfläche „Generuj wersję dla czytników ekranu". Sie erstellt eine Datei skrypty/<nazwa>_screen_reader.html — eine separate Ausgabe für Personen, die Screenreader verwenden (z. B. NVDA). So funktioniert es: Äußerungen von Figuren, für die im Weltenbuch ein Akzent definiert ist (z. B. der Eintrag „[Joana] akcent fiński"), erhalten eine phonetische Schreibweise (absichtlich „fehlerhafte" Orthografie) sowie eine Sprachmarkierung (Attribut lang), sodass der Screenreader sie mit dem richtigen, fremden Akzent vorliest. Audio-Tags v3 (z. B. [whispers]) werden in dieser Version entfernt — der Screenreader soll sie nicht laut vorlesen. Überschriften Prolog/Akt/Szene werden zu HTML-Überschriften, sodass man bequem durch das Dokument navigieren kann.

Das ist die bewusste Ergänzung zur Audio-Brücke: Den Akzent für das v3-Modell trägt die Stimmprobe, und für den Screenreader — die Orthografie plus die Sprachmarkierung. Daher bleibt die Orthografie in der Audio-Version sauber (v3 wählt die Sprache selbst), während die „fehlerhafte" Orthografie ausschließlich in die separate HTML-Datei gelangt, wo sie erwünscht ist.


SCHRITT 4: Postproduktion in der Regie

Nach dem Schreiben der Geschichte steht Ihnen ein Postproduktionswerkzeug zur Verfügung, das unten im Regie-Panel verfügbar ist (erscheint nur im Hörbuchmodus).

Kapitelüberschriften vergeben (Hörbuchmodus)

Die KI analysiert die gesamte Geschichte und schlägt beschreibende, literarische Titel für jedes Kapitel (sowie gegebenenfalls Prolog und Epilog) vor. Das Modul iteriert über die Kapitel der gespeicherten Datei und vergibt kurze Titel, indem es nur die Anfänge jedes Kapitels analysiert (bis zu 6000 Zeichen). Es gibt ausschließlich eine nummerierte Liste von Titeln zurück — ohne den Inhalt des Buches neu zu schreiben.

Hinweis: Das Modul erfordert, dass die Datei bereits auf der Festplatte gespeichert ist (generiert oder geladen). Wenn die Datei nicht existiert, zeigt die Anwendung eine entsprechende Meldung an.


SCHRITT 5: Polyglott AI

Anwendung für Übersetzungen und das Erzwingen starker Akzente auf Screenreader-Synthesizern. Gehe zu ihr, indem du auf die Schaltfläche "🌍  Polyglott" in der Symbolleiste klickst oder Werkzeuge → Polyglott aus dem Menü wählst (Tastenkürzel: Strg+2).

Modus 1: Normaler Übersetzer (Verwendet AI - Kostenpflichtig)

Ideal zum Anhören von Geschichten in einer schönen, korrekten Fremdsprache.

- Lade die Datei mit der Schaltfläche "Datei in den Speicher laden" oder durch Klicken auf "Durchsuchen..." zum Auswählen der Datei im Systemfenster.
- Wähle den Modus "AI-Übersetzer", gib die Zielsprache ein (z.B. "Finnisch").
- Das Skript übersetzt den Inhalt. Wenn du eine .html-Datei lädst, wird nur der für den Leser sichtbare Text übersetzt und der Sprachcode im HTML-Tag aktualisiert.
- Wenn du eine normale .txt- oder .md-Datei lädst (z.B. ein vom Regisseur generiertes Skript), speichert das Skript das Ergebnis nach der Übersetzung automatisch als .html-Datei mit eingebettetem Sprach-Tag — bereit für NVDA ohne zusätzliche Arbeit.
- Unterstützt auch .docx-Dateien.

Intelligente Blockaufteilung: Lange Texte werden automatisch in Blöcke aufgeteilt, die in Modell-Tokens (nicht in Zeichen) gemessen werden, und sequentiell mit Fortschrittsbalken übersetzt. Dadurch passen auch dicht geschriebene Sprachen wie Chinesisch oder Japanisch in das Antwortlimit des Modells, und eine abgeschnittene Antwort wird erkannt und automatisch auf kleineren Fragmenten wiederholt.

Fehlerresistentes Fortschrittsspeichern (NEU in Version 9): Jeder übersetzte Block wird sofort in einer versteckten temporären Datei im Systemordner der Anwendung gespeichert. Wenn die Übersetzung aufgrund eines erschöpften API-Limits unterbrochen wird, erkennt die Anwendung beim nächsten Start diese Datei automatisch, stellt den bereits bezahlten Fortschritt wieder her und setzt die Arbeit ruhig an der Unterbrechungsstelle fort — ohne manuelles Kopieren. Nach erfolgreichem Abschluss wird die temporäre Datei automatisch gelöscht.

Warum ist das wichtig? In Version 8 hatte der Ansatz zur Wiederaufnahme der Übersetzung einen kritischen, stillen Fehler: Wenn man die Datei mit der Teilübersetzung nicht umbenannte und den übersetzten Abschnitt gemäß den Anweisungen ausschneidete und dann sofort die Übersetzung des Rests fortsetzte — öffnete die Anwendung die Ausgabedatei im Überschreibmodus. Der bezahlte Fortschritt wurde unwiderruflich und unbemerkt gelöscht, bevor man es überhaupt bemerkte. Version 9 eliminiert diese Falle vollständig: Das Speichern ist nach jedem Block dauerhaft, unabhängig davon, was man danach tut.

Modus 2: Regisseur-Modus / Akzente (Kostenlos - Funktioniert lokal)

Werkzeug zum "Verfälschen" von Text. Erzwingt gebrochenes Polnisch auf den Synthesizern.

Das integrierte Dropdown-Menü des Regisseur-Modus ermöglicht die direkte Auswahl eines Akzents aus einer Liste. Verfügbare Optionen sind:
Englisch (Samantha / Mark — Vocalizer/Apple, Zira / Hazel — OneCore)
Russisch (Milena — Vocalizer/Apple, Irina / Pavel / Yuri — OneCore, eSpeak)
Französisch (Thomas / Amelie — Vocalizer/Apple, Julie — OneCore)
Polnisch (Ewa — Vocalizer, Paulina — OneCore)
Spanisch (Jorge / Monica — Vocalizer/Apple, Helena — OneCore)
Isländisch (Gudrun — OneCore, eSpeak; Hinweis: Vocalizer unterstützt diese Sprache nicht!)
Italienisch (Alice / Luca — Vocalizer/Apple, Elsa — OneCore)
Finnisch (Satu / Mikko — Vocalizer/Apple, Heidi — OneCore)
Und zwei Optionen zur Bereinigung ohne Akzent:
"Keiner (Bereinigung OHNE Normalisierung von Zahlen)"
"Keiner (Bereinigung MIT Normalisierung von Zahlen)"
Die Option mit Zahlen-Normalisierung wandelt automatisch Ziffern in ihre ausgeschriebene Form um (z.B. wird 15 zu "fünfzehn") vor der Verarbeitung — so liest NVDA Zahlen flüssig, und wenn der Text einen erzwungenen Akzent hat, bekommt die Zahl ihn auch, ohne Ausnahmen.
Ihr fragt euch sicherlich, ob der Synthesizer in der Lage sein wird, solche normalisierten Zahlen je nach Kontext zu deklinieren? Die Antwort lautet: nein. Und das ist ein beabsichtigtes Feature. Wie allgemein bekannt ist: "Polnisch ist eine schwierige Sprache" — und ein Ausländer, der unsere Grammatik bricht, fügt dem gebrochenen Akzent nur Authentizität hinzu!

Tag-Reparierer (NEU in Version 9): Am Ende der Liste findest du eine zusätzliche Option — den Tag-Reparierer. Er wendet keine phonetischen Regeln oder Bereinigungen an. Er macht nur eine Sache: Er injiziert in die Datei den von dir angegebenen ISO-Sprachcode — zweibuchstabig (z.B. "fi" für Finnisch, "en" für Englisch) oder mit Regions- bzw. Schrift-Subtag (z.B. "pt-BR" für brasilianisches Portugiesisch, "zh-Hans" für vereinfachtes Chinesisch). Nützlich, wenn du bereits eine fertige Datei hast — z.B. zuvor vom AI-Übersetzer übersetzt — aber aus irgendeinem Grund mit einem falschen oder fehlenden Sprach-Tag herausgekommen ist. Anstatt sie neu zu übersetzen, startest du einfach den Reparierer mit dem richtigen ISO-Code und hast in Kürze eine korrekte Datei.

Das Skript bereinigt Regieanweisungen in Klammern — es entfernt ganze Textabschnitte, die in runden Klammern stehen (z.B. "(mit eingeflochtenen Atemzügen)", "(flüsternd)", "(ironisch)"). ElevenLabs soll ausschließlich Dialoge und Erzählungen lesen, nicht in den Text eingeflochtene Regieanweisungen.

Das Skript bereinigt auch Markdown-Markierungen — es entfernt Hashtags von Überschriften (z.B. #, ##, ###), Gleichheitszeichen, die als Unterstreichungen von Überschriften verwendet werden, sowie verwaiste Kommata, die den Lesefluss des Synthesizers stören könnten.

- Schutzschild: Das Skript schützt alle HTML-Tags. Es verfälscht nur Dialoge und Erzählungen.
- Funktioniert lokal und kostet nichts!

Chiffre: Textumkehrer

Der Textumkehrer erweitert Abkürzungen, bevor er den Satz umkehrt — ohne Erweiterung würden gepunktete Abkürzungen in phonetischen Unsinn umgekehrt werden (Deutsch Beispiel: ".bZ").

- "z.B." → "zum Beispiel"
- "d.h." → "das heißt"
- "usw." → "und so weiter"
- "bzw." → "beziehungsweise"
- "ggf." → "gegebenenfalls"

Beispiel für Unsinn: ".Bz"

Chiffre: Typoglycemia

Tryb 3: Verschlüsseler (NEU in 13.0 — Textspielereien, kostenlos, lokal)

Der dritte RadioButton im Polyglot, neben dem AI-Übersetzer und dem Regisseur-Modus: „Verschlüsseler-Modus (Textspielereien, zufälliges Stottern)". Er aktiviert sechs lokale Algorithmen zur Textverzerrung — für Spiele, Rätsel, Sprachpuzzles. Nach Auswahl des Modus erscheint eine Dropdown-Liste der Algorithmen, und für einen von ihnen (Caesar-Verschlüsselung) ein zusätzliches Zahlenfeld für die Verschiebung.

Verfügbare Algorithmen (im Menü „Wähle Verzerrungsalgorithmus" markieren):

- Textumkehrer (Rückwärtslesen mit Großbuchstaben) — jeder Satz wird Zeichen für Zeichen umgekehrt, wobei Punkt/Ausrufezeichen/Fragezeichen am Ende und Großbuchstaben am Anfang beibehalten werden. Vor dem Umkehren erweitert das Skript gängige Abkürzungen (z.B., d.h., usw., bzw., ggf. usw.), damit das Ergebnis nach dem Umkehren noch Sinn ergibt — ohne dies würde „z.B." nach dem Umkehren in das unsinnige „.Bz" verwandelt.

  Inspiration: Mission aus dem Programm „The Traitors. Verräter". Als die Moderatorin den Teilnehmern ohne Vorwarnung ein bekanntes polnisches Lied aus einem Märchen zeigte — einfach rückwärts abgespielt — waren die Reaktionen wie „Welche Sprache ist das?", „Das muss Armenisch sein", „Ungarisch oder Finnisch". Die eigentliche Mission bestand darin, dass ein Team im Wald den rückwärts geschriebenen Text des Liedes erhielt, ihn in dieser umgekehrten Form singen sollte, das andere Team es aufnahm, rückwärts abspielte — und theoretisch das Originallied zur Erratung zurückgewann. Genau dasselbe lustige phonetische Missverständnis erzeugt unser Textumkehrer, wenn du die verarbeitete Datei durch einen TTS-Synthesizer laufen lässt.

- Typoglycämie (Vermischte Wortmitten) — klassischer psycholinguistischer Effekt: „Man knan den Txet in jderer Riehnfolge der Bstuchaben lseen, solgne die erste und ltezte Bstuchabe am rcihtigen Platz sind". Das Skript mischt zufällig die Mitte jedes Wortes, das länger als 4 Zeichen ist, der erste und letzte Buchstabe bleiben unberührt. Hervorragend für den Test „Wie viel sehe ich wirklich, und wie viel errät mein Gehirn".

- Kaputtes Telefon / Schlangendialekt — jedes „s", „z" oder der Doppelbuchstabe „sch" wird zufällig zu einem Zischen von 4-8 Zeichen verlängert („ssssss", „zzzzzz", „sssssssch"). Inspiration: Snecko aus dem Spiel „Slay the Spire". Effekt: Der Text klingt, als ob ihn eine Schlange mit Sprachfehler gelesen hätte.

- Vokalisierer (Alles dröhnt auf „O") — jeder Vokal im Text wird durch „o" ersetzt, wobei die deutschen Umlaute erhalten bleiben. „Guten Tag" → „Goton Tog". Je länger der Text, desto lustiger der Effekt (und der Screenreader liest es mit voller Überzeugung).

- Starkes Stottern / Beschädigter Roboter — fügt Stottern am Anfang von Wörtern hinzu: „C-c-c-Computer", „St-st-Straße". Bei kurzen Wörtern (weniger als 3 Zeichen) ignoriert der Algorithmus sie. Wenn der zweite Buchstabe des Wortes ein Konsonant ist, werden die ersten beiden Buchstaben wiederholt (natürlicherer Effekt); wenn ein Vokal, wird nur der erste wiederholt.

- Caesar-Verschlüsselung (Verschiebung des deutschen Alphabets) — klassischer Substitutionscode: Jeder Buchstabe wird um N Positionen im deutschen Alphabet verschoben (ABCD…ÄÖÜ, 29 Zeichen). Den Verschiebungswert gibst du im Zahlenfeld „Caesar-Verschlüsselungsverschiebung (0 = zufällig, Bereich -28…28)" ein. Wenn du 0 eingibst — wählt die Anwendung eine Verschiebung im Bereich 1-27 zufällig aus und zeigt sie nach Abschluss in einer Nachricht an (damit du später entschlüsseln kannst). Zeichen außerhalb des Alphabets (Zahlen, Interpunktion, Leerzeichen) bleiben unverändert.

Praktische Anwendung: Die Verschlüsselungen speichern das Ergebnis im gleichen Format wie der Regisseur-Modus (.html mit Sprach-Tag oder .docx mit XML-Tags), sodass NVDA sie mit der Stimme der entsprechenden Sprache liest. Besonders der Textumkehrer und der Vokalisierer klingen im Synthesizer viel interessanter, als wenn du sie mit den Augen liest — denn das Gehirn versucht beim visuellen Lesen automatisch, den Text zu „entschlüsseln", während TTS ihn genau so liest, wie er geschrieben ist.

Alle sechs Verschlüsselungen sind auch in einer breiteren, zugänglichen Sprache in der Datei docs/dictionaries.pl.txt im Anwendungspaket beschrieben — zusammen mit Tipps, wie man ohne Programmierkenntnisse eine eigene Verschlüsselung vom Typ „Buchstabentausch" hinzufügen kann (z.B. Schulsprache, Kauderwelsch).


Spracherkennung

Bevor das Skript den Text "verändert", überprüft es, in welcher Sprache er geschrieben ist. Wenn es erkennt, dass es sich nicht um Polnisch handelt, wird eine Warnung angezeigt. Die phonetischen Regeln sind auf die polnische Sprache zugeschnitten — die Anwendung auf fremdsprachige Texte würde unvorhersehbare Ergebnisse liefern.


Akzente optimiert für lokale Sprachsynthesizer (NVDA)

Die Akzente wurden zu 100 % für lokale, kostenlose und kostenpflichtige Sprachsynthesizer-Lesegeräte — Vocalizer und eSpeak in NVDA — entworfen. Dies garantiert Stabilität und Vorhersehbarkeit des Effekts auf jedem Computer.

Warum nicht ElevenLabs? Tests mit längeren Dokumenten haben gezeigt, dass die phonetische Verzerrung des Textes in Engines wie ElevenLabs den beabsichtigten Akzent nicht erzwingt — die Engine "rät" einfach die Sprache und macht daraus eher einen west-/südslawischen Akzent. Lokale NVDA-Synthesizer sind in dieser Hinsicht deutlich gehorsamer.


Spezifika lokaler Sprachsynthesizer (TTS)

Verschiedene TTS-Engines verhalten sich unterschiedlich. Nachfolgend die wichtigsten Unterschiede, die direkten Einfluss auf die Akzente haben:

eSpeak (Open Source)
Leichte, kostenlose Engine mit einer riesigen Sprachdatenbank — unterstützt z.B. Isländisch. Sehr streng bei der Zeichenkodierung, was sie vorhersehbar macht. Hat jedoch phonetische Nachteile: Oft werden Phoneme zwischen Sprachen geteilt, wodurch z.B. Ukrainisch mit einem russischen Akzent klingt.


Tiflotecnia Voices für NVDA (Cerrence-Stimmen — ehemals Vocalizer von Nuance)

Tiflotecnia Voices ist der direkte Nachfolger des Vocalizers von Nuance — eine kommerzielle Engine mit Stimmen der neuen Generation von Cerrence, die als .nvda-addon-Paket im NVDA Add-on Store vertrieben wird. Der alte Vocalizer (32-Bit-.dll-Bibliotheken von Nuance) wurde mit NVDA 2026.1 eingestellt; Cerrence hat die Stimmen auf 64-Bit umkompiliert und Tiflotecnia hat sie unter neuem Namen veröffentlicht. Die Aussprachequalität ist spürbar besser als in der vorherigen Generation.

Installation: NVDA → Werkzeuge → Add-on Store → suche nach „Tiflotecnia Voices for NVDA" → Installieren. Nach der Installation erscheint im NVDA-Menü ein dediziertes Untermenü „Tiflotecnia Voices" sowie eine eigene Kategorie in den NVDA-Einstellungen. Die GUI des Add-ons führt Schritt für Schritt durch den Kauf der Lizenz (oder die Aktivierung der 7-tägigen Testphase), die Auswahl und Installation der ersten Stimmen (z.B. die polnische Ewa für flüssiges Lesen von Systemsteuerungen, die finnische Satu für Akzente im Polyglot). Die integrierte Hilfe des Add-ons ist klar, daher wiederholen wir das Verfahren hier nicht — lassen Sie sich einfach vom Add-on führen.

Hinweis für Umsteiger von Vocalizer und Eloquence: Es ist ein Upgrade zu einem günstigeren Preis verfügbar. Verfahren: Nach erfolgreicher Zahlung schreiben Sie sofort eine E-Mail an die auf dem Erfolgsbildschirm der Zahlung verlinkte Adresse und bitten um Validierung des alten Aktivierungscodes — Tiflotecnia bestätigt das Recht auf den Rabatt und regelt den Preis. Ohne diese E-Mail behandelt das System Sie als neuen Kunden.

Verfügbarkeit der Stimmen: Tiflotecnia Voices unterstützt die meisten Sprachen, die der Vocalizer hatte (z.B. Polnisch, Englisch, Deutsch, Französisch, Spanisch, Finnisch, Italienisch, Russisch). Die Liste der Stimmen pro Sprache ist in der Kategorie der Add-on-Einstellungen vor dem Kauf der Lizenz sichtbar.


Microsoft OneCore
Kostenlose Stimmen, die in Windows integriert sind (Mobile Voices). Ein guter Kompromiss zwischen Qualität und Verfügbarkeit der Sprachen. Bietet hohe Qualität und unterstützt die isländische (Gudrun), finnische (Heidi) und italienische (Elsa) Sprache. Hinweis: OneCore unterstützt NICHT nativ das automatische Umschalten der Sprache basierend auf lang-Tags (es sei denn, Sie verwenden den in das System integrierten Bildschirmleser Narrator) — siehe Abschnitt unten.

Wie lädt man OneCore-Stimmen auf Windows herunter? OneCore-Stimmen sind kostenlos, aber die meisten Sprachen sind nicht standardmäßig installiert. Um fehlende Sprachen herunterzuladen, gehen Sie zu Windows-Einstellungen → Zeit und Sprache → Sprache → Stimmen verwalten (oder "Stimmen hinzufügen"). Wählen Sie eine Sprache aus der Liste (z.B. Isländisch, Finnisch, Italienisch) und klicken Sie auf Herunterladen. Nach dem Herunterladen erscheint die Stimme automatisch in NVDA — ohne zusätzliche Konfiguration.


Apple (iPhone / iPad / Mac) — VoiceOver mit Vocalizer
Auf Apple-Geräten ist die Vocalizer-Engine nativ im Betriebssystem integriert und unterstützt alle Sprachen ohne zusätzliche Käufe. Standardmäßig sind jedoch kompakte Versionen der Stimmen installiert, die etwas mechanisch klingen. Um ein deutlich besseres, natürlicheres Klangbild zu erhalten, empfiehlt es sich, die erweiterten oder Premium-Versionen herunterzuladen:
- Auf dem iPhone/iPad: Einstellungen → Bedienungshilfen → VoiceOver → Sprache → Stimme → Sprache auswählen (z.B. Finnisch) → auf den Namen der Stimme tippen (z.B. Satu) → Sie sehen die Optionen "Erweitert" und "Premium". Laden Sie die gewünschte Version herunter — sie benötigt mehr Speicherplatz, aber der Qualitätsunterschied ist deutlich.
- Auf dem Mac: Systemeinstellungen (oder Systemeinstellungen) → Bedienungshilfen → VoiceOver → VoiceOver-Dienstprogramm öffnen → Sprache → Stimme → auf "Anpassen" neben der ausgewählten Stimme klicken und die erweiterte oder Premium-Version herunterladen.


Android — Vocalizer kostenpflichtig pro Stimme
Auf Android ist Vocalizer als App im Google Play Store verfügbar (suche nach "Vocalizer TTS"). Hinweis: Jede Sprache und Stimme wird separat gekauft — es gibt keine All-in-One-Lizenz. Vor dem Kauf kannst du die Stimme für ein paar Minuten im Demo-Modus testen. Nach dem Kauf ist die Stimme mit deinem Google-Konto verknüpft und kann auf jedem Gerät mit demselben Konto installiert werden.


Killer-Feature für Blinde: Dateien mit Sprach-Tags

Das ist eine echte Revolution. Verarbeitete Dateien werden jetzt gespeichert als:

- .html mit dem Attribut lang (z.B. lang="fi" für Finnisch) — NVDA liest diesen Tag und wechselt automatisch zur entsprechenden Sprachsynthese. Keine manuelle Konfiguration nötig!
- .docx mit Formatierungserhaltung — jeder Textabschnitt hat ein Sprach-Tag im XML-Dokument eingebettet, sodass Word und NVDA wissen, mit welcher Stimme jeder Abschnitt gelesen werden soll.

Verarbeitete Dateien werden immer als NEUE Dokumente gespeichert (z.B. akzent_Finski.html).


Automatisches Umschalten der Sprache in NVDA — was Sie wissen müssen

Damit NVDA die Stimme tatsächlich basierend auf dem lang-Tag umschaltet, muss die Einstellung "Sprache automatisch ändern, wenn unterstützt" aktiviert sein. Sie finden diese in den NVDA-Einstellungen → Sprache. Standardmäßig ist sie beim ersten Start des Screenreaders aktiviert — es ist jedoch ratsam zu überprüfen, ob sie nicht deaktiviert wurde.

Wichtiges Einschränkung der OneCore-Stimmen: Microsoft OneCore-Stimmen unterstützen diesen Mechanismus nativ nicht mit NVDA, sondern nur mit dem in Windows integrierten Narrator. Es gibt ein inoffizielles NVDA-Add-on namens „One Core Autolang", das versucht, dies zu beheben — aber seine Entwicklung wurde schnell eingestellt. Der Grund ist banal: Jedes Jahr, mit der ersten NVDA-Version des Jahres, gibt es Änderungen, die die API-Kompatibilität brechen (sogenannte API Breaking Changes). Manchmal reicht es aus, das Feld „last tested version" im Add-on-Manifest zu aktualisieren, aber manchmal sind echte Änderungen im Code erforderlich — und der Autor kommt mit den Updates nicht hinterher. Wenn Ihnen das automatische Umschalten der Sprache wichtig ist, sind Tiflotecnia Voices (kostenpflichtig, siehe Abschnitt oben) oder eSpeak (kostenlos, geringere Qualität) eine sicherere Wahl, da sie diesen Mechanismus nativ unterstützen — aber Achtung: Aktuell funktioniert dies in Tiflotecnia Voices mit einem Prioritätsfehler (siehe „Kritischer Haken" unten). Nach dem Kopieren des Patches funktioniert das automatische Umschalten vorbildlich, wie im alten Vocalizer.


Kritischer Haken bei Tiflotecnia Voices: fehlerhafte Spracherkennung

Zunächst die gute Nachricht — der Alarm bezüglich NVDA 2026.1 aus den vorherigen Versionen des Handbuchs hat ein Happy End gefunden: Cerrence hat 64-Bit-Bibliotheken bereitgestellt, Tiflotecnia hat sie in einem .nvda-addon-Paket veröffentlicht, das im Add-on Store verfügbar ist (siehe Abschnitt oben), und der Vocalizer ist bei denen, die ihn bis zum Ende behalten haben, unter einem neuen Namen zurückgekehrt — mit besserer Qualität und ohne 32-Bit-Einschränkungen.

Mit der Einführung von Tiflotecnia Voices ist jedoch ein neuer kritischer Haken aufgetreten — in der Spracherkennung. In den Einstellungen des Add-ons kann konfiguriert werden, welche Stimme für bestimmte Buchstaben (z.B. lateinische, kyrillische) je nach installierten Stimmen verwendet werden soll. Das Problem liegt in der Prioritätenreihenfolge: Derzeit wird zuerst das Override pro Buchstabe angewendet, dann der Fallback auf den ISO-Sprachcode (in der Praxis unerreichbar für DASSELBE Alphabet, für das bereits ein Override angewendet wurde), und schließlich die gewählte Stimme. Das Ergebnis zeigt sich innerhalb desselben Alphabets: Du hast einen finnischen Text mit dem korrekten Tag `lang="fi"`, Satu als finnische Tiflotecnia-Stimme installiert, ABER in den Einstellungen eine polnische Stimme für lateinische Buchstaben eingestellt — Satu wird diesen Text NICHT lesen, trotz des korrekten ISO-Tags. Das Override pro Buchstabe „polnische Stimme für Latein" gewinnt auf der ersten Ebene, ISO `fi` wird nie geprüft. Für unterschiedliche Alphabet-Paare funktioniert der Mechanismus korrekt (russischer Text + Milena für Kyrillisch + polnische Stimme für Latein — das gesamte Kyrillisch wird mit Milena gelesen, eventuelle lateinische Eigennamen mit der polnischen Stimme; jedes Alphabet bleibt in seinem Override). Nach der Migration vom Vocalizer, bei dem der Sprachwechsel auf Basis von ISO vorbildlich funktionierte, werden Benutzer diesen Rückschritt sofort bemerken — insbesondere diejenigen, die im Polyglot mehrere europäische Akzente (Satu, Alice, Markus) auf derselben lateinischen Buchstabenmenge verwenden.

Diagnose und Patch: Ich habe das Problem auf Python-Ebene im Add-on-Code diagnostiziert und einen Patch vorbereitet, der die Prioritätenreihenfolge ändert zu: ISO → gewählte Stimme → Buchstaben-Override. Der Patch behält das nützliche Umschalten auf Latein für lateinische Namen im russischen Text bei, wenn in den Einstellungen „Spracherkennung basierend auf Unicode-Zeichen" aktiviert ist. Ich habe den Patch an die Entwickler von Tiflotecnia gesendet — bisher ohne Antwort, sie bleiben also höchstwahrscheinlich bei ihrer eigenen Lösung. Falls das Add-on ein Update erhält, aktualisiere ich den Patch bei Bedarf.

Was man in der Zwischenzeit tun kann: Wenn dir die korrekte Spracherkennung wichtig ist (es lohnt sich — das war eines der Killer-Features des alten Vocalizers, siehe „Killer-Feature für Blinde" oben), öffne ein Issue im Anwendungs-Repository auf GitHub mit dem Label `tiflotecnia-patch` und deiner E-Mail-Adresse im Inhalt. Es lohnt sich, eine kurze Problembeschreibung in deiner eigenen Sprache hinzuzufügen (2–3 Sätze reichen) — der Bot erkennt die Sprache (unterstützt: Polnisch, Englisch, Deutsch, Spanisch, Finnisch, Französisch, Isländisch, Italienisch, Russisch) und antwortet in derselben; ohne Beschreibung oder in einer anderen Sprache erfolgt die Antwort auf Englisch. Ein automatischer Bot wird das Issue sofort mit einer Bestätigung der Meldung schließen (ohne Spur im öffentlichen Thread), und du erhältst den Patch in der Regel innerhalb weniger Tage privat per E-Mail. Der Patch wird NICHT im Anwendungs-Repository oder als Gist veröffentlicht — Tiflotecnia Voices for NVDA ist kommerzielle Software, und die Lizenz des Add-ons erlaubt keine Weiterverbreitung seiner Dateien, auch nicht in modifizierter Form. Nach Erhalt des Patches musst du dessen Inhalt in `%appdata%\Roaming\nvda\addons\TiflotecniaVoices` kopieren und die Dateien ersetzen. SCHRITT 6: Hörbuch-Architekt

Ein Werkzeug zur Erstellung einer professionellen Dateistruktur für Screenreader und ElevenLabs. Gehe zu ihm, indem du auf die Schaltfläche "📄  Konverter" in der Symbolleiste klickst oder Werkzeuge → Konverter aus dem Menü wählst (Tastenkombination: Strg+3).

Wie funktioniert es?

1. Gib den Pfad zur Quelldatei in das Textfeld ein oder klicke auf die Schaltfläche "Durchsuchen...", um die Datei im Systemdialog auszuwählen. Das Skript akzeptiert sowohl .txt- als auch .docx-Dateien sowie .html- und .htm-Dateien.
2. Klicke auf "Architektur für ElevenLabs erstellen".
3. Das Skript scannt jede Textzeile und wandelt Schlüsselwörter (Akt, Kapitel, Prolog, Epilog, Vorspann) in "Überschrift 1" im Word-Dokument um.
4. Szenen (Zeilen, die mit dem Wort "Szene" beginnen) werden in fettgedruckten Text umgewandelt — sichtbar im Dokument, aber unsichtbar im Inhaltsverzeichnis von ElevenLabs.
5. Der gesamte übrige Text (Dialoge, Beschreibungen) bleibt unverändert.
6. Du erhältst eine Datei architektura_[originalname].docx — ein professionelles Word-Dokument, bereit für die weitere Bearbeitung. Wenn deine Eingabedatei beispielsweise znieczulica.txt hieß, wird die Ergebnisdatei architektura_znieczulica.docx heißen und im selben Ordner wie das Original erscheinen.

Automatische Bereinigung: Das Skript entfernt automatisch HTML-Tags (wenn der Text aus einem Browser oder einer lokalen .html-Datei stammt, z.B. von Polyglott generiert) sowie Markdown-Überschriften (z.B. ### oder ####) vor der Verarbeitung. Du musst die Datei nicht manuell bereinigen.

Geschichtenmodus: Automatisches Gruppieren von Zügen in Szenen (ab v15.1)

Wenn du eine Datei opowiesci/<gra>.txt, die vom Modul Interaktive Geschichten generiert wurde, in den Architekten lädst, erkennt der Konverter Zugmarkierungen (z.B. „--- Zug 7 ---") in 9 Sprachen (Zug, Turn, Runde, Turno, Vuoro, Tour, Umferð, Turno, Ход) und fügt alle fünf Züge eine neue Überschrift ersten Grades in der Form „Szene N" ein (die Nummer beginnt bei 1, lokal für die jeweilige Sprache — im Englischen „Scene N", im Deutschen „Szene N" usw.). Die übrigen Zugmarkierungen werden entfernt — sie erscheinen nicht in der Erzählung des Hörbuchs, da „Zug 7" vom TTS ausgesprochen die Immersion des Zuhörers bricht. Das Ergebnis ist eine Word-Datei mit einer natürlichen Aufteilung in Szenen von jeweils einigen Minuten Audio, bereit für den Import in ElevenLabs. Der Mechanismus ist autodetektioniert — gewöhnliche Hörbuchdateien ohne Zugmarkierungen (klassische Erzählung aus dem Regisseur) werden genau wie bisher verarbeitet.

Ein großer Vorteil für NVDA- und ElevenLabs-Nutzer

Das Formatieren von "Überschrift 1" für Kapitel ist nicht nur Ästhetik. In NVDA kannst du blitzschnell durch Überschriften navigieren, indem du die Taste H (oder 1 für Überschriften ersten Grades) drückst. Anstatt Hunderte von Seiten zu scrollen, springst du in Bruchteilen von Sekunden von Kapitel zu Kapitel. Das verändert die Arbeitsweise mit langen Dokumenten. In ElevenLabs kannst du sicher sein, dass die Engine automatisch Schnitte einfügt und sich nicht aufhängt, während sie Audioclips dirigiert.


SCHRITT 7: Wie man das Buch der Welt schreibt (Prompt des Architekten und Mini-Markdown-Kurs)

Die künstliche Intelligenz, die das Hauptstudio antreibt, versteht Befehle am besten, wenn sie im Markdown-Markup-Format formatiert sind. Wenn Sie der KI im Regisseur nur eine lose Idee geben (z.B. "zwei Schwestern im Jenseits"), wird die Maschine aufgrund fehlender Details in Panik geraten und eine banale, vorhersehbare Geschichte erstellen, die die Logik ignoriert.

Um dies zu verhindern, verwenden Sie einen externen Chatbot (z.B. den kostenlosen ChatGPT oder Claude) als Ihren persönlichen Architekten. In Version 13.0 müssen Sie den Prompt nicht mehr aus der Anleitung abschreiben — im Regisseur-Panel finden Sie direkt unter dem Button „💾 Buch dauerhaft speichern" den Button „📖 Architekten-Prompt für KI…". Klicken Sie darauf, und ein Dialogfenster öffnet sich mit dem fertigen Prompt-Text im „Nur-Lesen"-Feld sowie einem „In die Zwischenablage kopieren"-Button. NVDA gibt den gesamten Inhalt sofort nach dem Öffnen des Fensters bekannt — einfach auf „Kopieren" klicken, in ChatGPT/Claude einfügen (Strg+V) und den Abschnitt „[HIER IHRE IDEE EINFÜGEN]" durch Ihren eigenen Handlungsansatz ersetzen.

Warum so und nicht durch Kopieren aus der Anleitung? Der Dialog im GUI hat einen entscheidenden Vorteil in Bezug auf die Barrierefreiheit: Er ist nativ und wird ohne Unterbrechungen vom Bildschirmleser gelesen, erfordert keinen Wechsel zum Texteditor (wo polnische „Schwänzchen" und Anführungszeichen oft falsch kopiert werden) und funktioniert identisch auf jedem Betriebssystem. Dasselbe Muster — ein Dialog mit einem kopierbaren Prompt — wird auch im Regelmanager verwendet (siehe SCHRITT 7b unten).

Wie die KI antwortet: Sie erhalten eine Antwort in zwei Teilen. Der erste Teil ist das Buch der Welt, eingeschlossen in einem Markdown-Codeblock (Markierungen ```markdown … ```). Kopieren Sie NUR den Inhalt des Codeblocks (ohne die Markierungen ```) und fügen Sie ihn in das Feld „Buch der Welt" im Regisseur ein, und klicken Sie dann auf „💾 Buch dauerhaft speichern". Der zweite Teil ist eine Empfehlung, welcher der kreativen Modi (Skript oder Hörbuch) am besten zu Ihrer Idee passt — betrachten Sie dies als Hinweis bei der Auswahl des Modus im RadioBox.

Mini-Markdown-Kurs im Buch: Ein einzelnes Hashtag (#) ist der Hauptabschnitt (z.B. „# Charaktere"), ein doppeltes Hashtag (##) ist ein Unterabschnitt, Bindestriche (-) erstellen Listen, und doppelte Sternchen (**Text**) heben absolute, unveränderliche Regeln hervor (z.B. „**Der Held LÜGT NIE**"). Für einen fremdsprachigen Charakter fügen Sie einen Akzent-Tag hinzu, z.B. „[Sprecher 1: Marek] - hat einen französischen Akzent". Das Schlüsselwort „Akzent" ist NOTWENDIG — die Anwendungs-Engine erkennt es automatisch und wendet die richtigen phonetischen Regeln auf die Dialoge des Charakters an.

Tipp: Denken Sie daran, Ihr Buch der Welt regelmäßig zu aktualisieren, wenn Sie die Handlung um neue Orte oder wichtige Charaktere erweitern. Sie können dies manuell oder mit Hilfe eines externen Chatbots tun. Je reicher das Fundament, desto bessere Ergebnisse in der Regie!

SCHRITT 7b: Regelmanager (Ctrl+4) — Wörterbücher für Linguisten ohne Python

Version 13.0 führt ein viertes Werkzeug in der Leiste ein: den Regelmanager. Du öffnest ihn mit der Taste Ctrl+4 oder über das Menü Werkzeuge. Es ist ein visueller Explorer des Ordners dictionaries/, in dem die Anwendung alle phonetischen Regeln (Akzente), Chiffren und Modi des Regisseurs in YAML-Dateien (ein für Menschen lesbares Format, einfacher als JSON) speichert.

Warum YAML? Bis Version 12.0 waren alle Akzente, kreativen Modi und Filter im Python-Code „eingebettet“. Das Hinzufügen eines neuen Akzents erforderte einen Programmierer. In Version 13.0 wurde alles in .yaml-Dateien im Ordner dictionaries/ ausgelagert — jeder, der den Notizblock öffnen kann, kann einen bestehenden Akzent anpassen („tausche sz gegen sh gegen sch“) oder einen völlig neuen hinzufügen (schwedisch, dänisch, russischer Dialekt).

Was du im Regelmanager findest:
- Dateibaum — vollständige Liste aller YAML-Dateien in dictionaries/ mit Aufteilung nach Quellsprachen (derzeit vollständig implementiert: Polski, Deutsch, English, Español, Suomi, Français, Íslenska, Italiano, Русский) und fünf Kategorien: akcenty/ (TTS-Phonetik), szyfry/ (Textspielereien), rezyser/ (kreative Modi und Postproduktion), gui/ (UI-Übersetzungen) und opowiesci/ (Modi des Geschichten-Moduls, hinzugefügt in 15.2.4). Navigation mit Pfeiltasten wie im Windows-Dateiexplorer, vollständige NVDA-Unterstützung.
- Schaltfläche „📝  Im Texteditor öffnen“ — öffnet die ausgewählte Datei im standardmäßigen System-Notizblock. Du bearbeitest, speicherst, klickst „🔄  Baum aktualisieren“ und fertig.
- Schaltfläche „📋  Ausgewählte Datei duplizieren“ — der schnellste Weg zu einem neuen Akzent: Du nimmst eine bestehende Datei (z.B. finski.yaml), gibst einen neuen Namen an (z.B. schwedisch), der Manager erstellt eine Kopie mit dem Kommentar „ändere Felder label und description“ und öffnet sie im Editor.
- Schaltfläche „➕  Neue Regeldatei…“ — ein Assistent mit Auswahl des Typs (Akzent, Chiffre, Regisseurmodus, neue Quellsprache, algorithmische Chiffre). Für einfache Fälle (Akzent, Chiffre vom Typ „Buchstabentausch“) erstellt der Assistent eine bearbeitbare YAML-Vorlage. Für Fälle, die einen Programmierer erfordern (neue Quellsprache, Algorithmus vom Typ „Wortmitte mischen“), generiert der Assistent ein Prompt für einen AI-Chatbot — du fügst es in ChatGPT ein, erhältst eine fertige YAML-Datei, speicherst sie in dictionaries/ und fertig.

Praktische Anwendung: Du möchtest einen schwedischen Akzent hinzufügen? Öffne den Regelmanager, wähle dictionaries/pl/akzente/finski.yaml, klicke „Duplikat“, benenne die Datei in schwedisch um, ändere das Feld label in "Schwedisch (Alva / Oskar)", den ISO-Code in sv, ändere einige Tauschregeln und speichere. Kehre zur Startseite zurück und starte die Anwendung neu. Der neue Akzent erscheint im Menü Polyglot (im Regisseurmodus) und — wenn du ihn dem Buch der Welt der Charaktere hinzufügst („[Marek] - hat einen schwedischen Akzent“) — auch in der automatischen Akzenterkennung des Regisseurs.

Wo du weitere Dokumentation zum Ordner dictionaries/ findest:
- Datei `docs/dictionaries.pl.txt` (verfügbar im Paket für Endbenutzer im Reiter Releases) — eine kurze, einfache Beschreibung jedes Unterordners, 6 fertige Chiffren, 8 fertige Akzente sowie Ideen, was man selbst ohne Python-Kenntnisse machen kann.
- Datei `dictionaries/README.md` (nur beim Klonen des Repositories von GitHub verfügbar — Release-Pakete filtern .md-Dateien) — detaillierte technische Dokumentation des YAML-Formats mit Beispielen, Feldlisten, Pipeline-Regeln, Regex. Dieses Dokument richtet sich an Linguisten mit Grundkenntnissen in Programmierung und an Entwickler.


Wichtige Hinweise für Benutzer von Bildschirmlesegeräten (NVDA)

1. Erfolgs- und Fehlermeldungen

Wenn die Anwendung ihre Aufgabe beendet (z.B. eine Datei speichert oder auf einen Fehler stößt), erscheint ein Dialogfenster mit einem Titel wie "Erfolg", "Warnung" oder "Fehler". NVDA wird dieses Fenster sofort ankündigen und seinen Inhalt vorlesen. Sie müssen nichts tun — die Dialoge sind vollständig über die Tastatur zugänglich, und der Fokus landet automatisch auf der Schaltfläche "OK". Es gibt keine Tricks mehr mit dem Präfix "Alert" — native wxPython-Dialogfenster werden direkt vom Leser unterstützt.

2. Wichtige Warnung: Stille Hintergrundverarbeitung

Nach dem Klicken auf Schaltflächen wie "An die KI senden" oder "Verarbeitung starten" beginnt das Programm sofort mit der Hintergrundverarbeitung. Auf dem Bildschirm erscheint eine Fortschrittsanzeige (Gauge), aber NVDA liest ihren Wert nicht in Echtzeit vor — der Bildschirmleser bleibt während der Arbeit stumm. Klicken Sie nicht erneut auf die Schaltfläche. Warten Sie, bis ein Dialogfenster mit dem Ergebnis oder einer Fehlermeldung erscheint — NVDA wird es automatisch ankündigen.

3. Navigation zwischen den Werkzeugen

Die Navigation zwischen den Werkzeugen (Regisseur, Polyglott, Konverter, Regelmanager) erfolgt in einem einzigen Programmfenster über vier Schaltflächen in der Symbolleiste oder über das Menü Werkzeuge (Alt, dann N). Verfügbare Tastenkombinationen: Strg+0 (Startseite), Strg+1 (Regisseur), Strg+2 (Polyglott), Strg+3 (Konverter), Strg+4 (Regelmanager — neu in 13.0). Nach dem Umschalten des Werkzeugs landet der Fokus automatisch auf der Beschreibung des neuen Moduls — NVDA beginnt sofort, die neue Ansicht zu lesen.

4. Tabulatorreihenfolge und Widget-Namen

Jedes Interface-Element hat einen klaren deutschen Namen — NVDA wird ihn beim Fokussieren vorlesen. Die Tabulatorreihenfolge ist logisch: von der Werkzeugbeschreibung über die Konfigurationsfelder bis zu den Aktionsschaltflächen. Es gibt keine Überraschungen — die Tastaturnavigation funktioniert wie in jedem anderen nativen Windows-Programm. Alle Menüs und Schaltflächen sind auf Deutsch, und NVDA wird sie mit einer deutschen Stimme ohne zusätzliche Einstellungen vorlesen.


Wichtige Hinweise zur Version 9.0 / Changelog

Neue Funktionen und Änderungen in Version 9

Fehlertolerante Speicherung des Übersetzungsfortschritts (ÄNDERUNG — Behebung eines kritischen Fehlers)
In Version 8 war das Fortsetzen einer unterbrochenen Übersetzung mit einer stillen, destruktiven Falle behaftet: Wenn der Benutzer den Anweisungen folgte (manuelles Ausschneiden des übersetzten Abschnitts) und dann sofort die Übersetzung des Rests fortsetzte, öffnete die Anwendung die Ausgabedatei im Überschreibmodus — unwiderruflich und unbemerkt wurde der gesamte bezahlte Fortschritt gelöscht. In Version 9 wurde der gesamte Mechanismus neu gestaltet. Jeder übersetzte Block wird jetzt sofort in einer temporären Datei (.jsonl) mit einem zugewiesenen Index gespeichert. Das Fortsetzen erfolgt vollständig automatisch — die Anwendung erkennt die Datei selbst und stellt den Fortschritt ohne jegliches Eingreifen des Benutzers wieder her. Nach erfolgreichem Abschluss wird die temporäre Datei automatisch gelöscht.

Tag-Reparatur im Regisseur-Modus (NEU)
Dem Menü des Regisseur-Modus wurde eine neue Option hinzugefügt — der Tag-Reparatur. Es injiziert ausschließlich den vom Benutzer angegebenen zweibuchstabigen ISO-Sprachcode in die Datei, ohne jegliche phonetischen Regeln oder Bereinigungen anzuwenden. Ein Rettungswerkzeug für den Fall, dass die fertige Datei mit einem falschen oder fehlenden Sprach-Tag herauskommt.

Automatische Konvertierung von .txt zu .html im Übersetzer-Modus (ÄNDERUNG)
Textdateien (.txt und .md), die vom KI-Übersetzer übersetzt werden, werden jetzt automatisch im .html-Format mit eingebettetem Sprach-Tag gespeichert. Dadurch liest NVDA die Datei sofort mit der richtigen Stimme — ohne zusätzliche Schritte seitens des Benutzers.

Intelligente Dateibenennung im Architekt (ÄNDERUNG)
Der Audiobook-Architekt speichert die Ergebnisdatei nicht mehr immer unter dem gleichen Namen architektura_gotowa.docx. Jetzt ergibt sich der Name aus der Eingabedatei — z.B. für znieczulica.txt ist die Ergebnisdatei architektura_znieczulica.docx. Die Datei erscheint im gleichen Ordner wie das Original.

Funktionen unverändert aus Version 8

Rückkehr zum .txt-Format für Projektdateien (ÄNDERUNG)
Projektdateien und Zusammenfassungen werden jetzt im .txt-Format statt .md (Markdown) gespeichert. Das Experiment mit dem .md-Format als psychologische Barriere gegen Bearbeitung erwies sich als ineffektiv — die KI bricht notorisch die Anti-Closure-Regel, und es ist oft besser, die Datei laufend zu bearbeiten und dann den Speicher neu zu laden, damit die KI, soweit möglich, keine versteckte Erlaubnis zum Brechen des Verbots erhält. Das .txt-Format ist für jeden intuitiver und lesbarer.

Regel des Montageleiters — neue Warnung
In der Anleitung (und in zukünftigen Versionen der Benutzeroberfläche) wurde eine deutliche Warnung hinzugefügt, die erklärt, was in Projektdateien bearbeitet werden darf und was nicht. Der Benutzer hat das volle Recht, Dialoge und Inhalte zu bearbeiten, darf jedoch keinesfalls die Strukturzeilen (Akt, Szene, Kapitel, Prolog, Epilog) modifizieren — deren Beschädigung beeinträchtigt die Navigation in NVDA, die Aufteilung in ElevenLabs und das Inhaltsverzeichnis in Word.

Aktualisierter Prompt des Architekten (ÄNDERUNG)
Der Prompt an den externen Chatbot (ChatGPT/Claude) wurde neu gestaltet. Anstatt rohen Markdown-Code zurückzugeben, gibt die KI jetzt die Antwort in zwei deutlich getrennten Teilen zurück: Teil 1 ist das Buch der Welt, eingeschlossen in einem Markdown-Codeblock (leicht ohne Markierungen zu kopieren), und Teil 2 ist die Modusempfehlung als normaler Text außerhalb des Blocks — es wird beraten, ob besser der Modus des Rohskripts oder der Modus des traditionellen Audiobooks verwendet werden sollte. Auch die Beschreibung der Charakter-Tags wurde geändert: statt "klanglich" wird jetzt von Akzent und Stimmton im Tag gesprochen, z.B. [Speaker 1: Name] - lispelt und französischer Akzent.

Erklärung des Anti-Closure-Direktivzustands (DOKUMENTATION)
Die Anleitung enthält jetzt eine ehrliche Erklärung, dass trotz der eingebauten Anti-Closure-Verbote das Modell diese Regel weiterhin notorisch bricht, insbesondere im Audiobook-Modus. Anstatt dieses Problem zu verbergen, stellt Version 8 die Sache klar und überträgt die Verantwortung für das "manuelle Schließen" zurück an den Regisseur — daher die Regel des Montageleiters als offizielles Arbeitswerkzeug und die Rückkehr zum normalen Textformat.

SCHRITT 7b (Ergänzung): Die Reihenfolge der `zamiany:`-Regeln ist wichtig

Die Dateien in `dictionaries/<kod>/akcenty/*.yaml` enthalten eine Liste von `zamiany:`-Regeln — Paare von `wzor → zamiana`, die die Engine SEQUENZIELL anwendet. Jede nachfolgende Regel arbeitet auf der Ausgabe der vorherigen. Dies ermöglicht den Aufbau von Pipelines wie „zerlege den Digraphen `szcz` in `shch` und ersetze dann `ch` durch `h`", birgt jedoch auch die klassische Falle für den Autor eines Sprachpakets.

Die „sequenzielle Schleifen"-Falle. Angenommen, für einen spanischen Akzent, der das polnische „ñ" an die Aussprache von Diego (Loquendo) anpassen soll, fügt der Autor zwei Regeln hinzu:
1. `ñ → nj` (damit das polnische „ñ" wie ein weiches „nj" klingt)
2. `j → x` (damit das polnische „j" wie das spanische „j" klingt — phonetisch /x/)

Nach dem Start stellt sich heraus, dass Wörter mit „ñ" als „nx" und nicht als „nj" ausgesprochen werden. Warum? Weil die erste Regel „ñ" in „nj" umwandelt, wird das neue „j" sofort von der zweiten Regel erfasst und in „x" umgewandelt. Ergebnis: Anstatt des beabsichtigten „ñ → nj" erhalten wir „ñ → nx".

Die Regel der Reihenfolge (universell). Wenn eine Regel ein Zeichen einführt, das in einer anderen Regel als Muster verwendet wird, IST DIE REIHENFOLGE WICHTIG. Eine sichere Heuristik: ZUERST das TARGET (das Zeichen, das später als `wzor` in einer anderen Regel verwendet wird) in etwas Sicheres umwandeln, DANN das SOURCE (das Zeichen, das sich in das TARGET auflösen soll) einführen. Für das spanische Beispiel korrekt: zuerst `j → x`, dann `ñ → nj`. Ergebnis: „ñ" ergibt „nj" (das zweite „j" wird nicht mehr erfasst, da die Regel `j → x` bereits angewendet wurde, als „nj" noch nicht existierte).

Wie man testet. Nach dem Ändern der Reihenfolge der Regeln in der Akzentdatei, lassen Sie einen Satz, der BEIDE Buchstaben enthält, durch den Regisseur-Modus laufen. Für das Beispiel ES: „Niño de paja juega" → das Ergebnis muss sowohl den ñ-Akzent („ñ → nj") als auch den j-Akzent („j → x") haben, also etwas wie „Ninjo de paxa xuega". Wenn Sie „ninxo" statt „ninjo" sehen — die Reihenfolge ist umgekehrt.

Validierung in der Engine (opt-in für Paketautoren). Die Anwendung verfügt über eine eingebaute Heuristik zur Erkennung potenzieller Schleifen, ist jedoch standardmäßig deaktiviert — da viele Pipelines wie eine Schleife aussehen, obwohl sie beabsichtigt sind (klassisches „szcz → shch" + „ch → h"). Um sie zu aktivieren: Setzen Sie die Umgebungsvariable `REZYSER_VALIDATE_ZAMIANY=1` und starten Sie die Anwendung von der Konsole aus — aus der Quelle über `python main.py`, da das eingefrorene `.exe` im Fenstermodus (ab Version 17.0) kein Konsolenfenster hat. Die Engine gibt für jede Akzentdatei eine aggregierte WARN-Zeile mit den ersten drei potenziellen Schleifen und der Anzahl der verbleibenden aus. Überprüfen Sie die resultierende Phonetik am Testsatz — wenn der Effekt beabsichtigt ist, ignorieren Sie die WARN.

Die Schaltflächen zum Verschieben von Regeln im GUI-Regel-Manager (Drag-and-Drop, „Nach oben / Nach unten") sind eine separate Funktion, die für einen späteren Versionszyklus geplant ist — sie erfordert eine Neugestaltung des Managers (derzeit delegiert er die Bearbeitung der Datei an den externen System-Notizblock und hat keine eigene Regelansicht). Bis zur Implementierung: Bearbeiten Sie die YAML-Datei manuell, verschieben Sie Zeilen im Abschnitt `zamiany:`, verwenden Sie den Validator mit ENV-Variable und testen Sie an Kontrollsätzen.

SCHRITT 2B (erweitert, optional): Eigener KI-Anbieter kompatibel mit OpenAI

Die meisten Benutzer sollten beim empfohlenen Anthropic (SCHRITT 2) bleiben — er liefert die höchste Qualität. Wenn du jedoch einen eigenen Grund hast (Kosten, Zugang, Datenschutz, eigenes lokales Modell), kannst du ab Version 18.4 JEDEN Endpunkt angeben, der mit der OpenAI-API kompatibel ist — zum Beispiel OpenRouter, Groq, Fireworks, DeepSeek, lokales Ollama oder einen OpenAI-kompatiblen Gemini-Endpunkt. Die gesamte KI-Engine läuft dann über einen einzigen Pfad zu diesem Endpunkt, ohne separate Integration pro Anbieter.

Dies ist eine Option für Fortgeschrittene: Du konfigurierst sie manuell in der Datei golden_key.env, indem du neben (oder anstelle von) dem Anthropic-Schlüssel drei Zeilen sowie den Schlüssel des gewählten Anbieters hinzufügst:

LLM_PROVIDER=openai_compat
LLM_BASE_URL=adresse_des_endpunkts (z. B. https://openrouter.ai/api/v1)
LLM_MODEL=modellname_beim_anbieter (z. B. openai/gpt-4o-mini)
OPENAI_API_KEY=dein_schlüssel_bei_diesem_anbieter

So funktioniert es:
•  Wenn LLM_PROVIDER=openai_compat gesetzt ist, nutzt die GESAMTE KI-Engine (Regisseur, Geschichten, Polyglott, Titel, Spracherkennung) den angegebenen Endpunkt, und der Modellname aus den Konfigurationsdateien wird durch LLM_MODEL überschrieben.
•  Wenn die Zeile LLM_PROVIDER fehlt (oder den Wert anthropic hat), verhält sich die Anwendung wie in SCHRITT 2 — ausschließlich mit dem Anthropic-Schlüssel. Du musst nichts ändern.

Wichtig (Qualität): Die System-Prompts der Anwendung sind für Claude geschrieben und optimiert. Ein anderes Modell kann eine geringere Qualität liefern — es hält sich möglicherweise schlechter an die Weltregeln, verliert die JSON-Struktur in Modi mit Auswahlmöglichkeiten oder gibt Text in der falschen Sprache zurück. Dies ist ein bewusster Kosten↔Qualität-Kompromiss auf deiner Seite. Wenn dir das beste Ergebnis wichtig ist, bleib bei Anthropic.
