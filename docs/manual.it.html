Reżyser Audio GPT — Guida completa (Versione 18.20.0 – Versione di Rilascio)

Benvenuto nello Studio di Registrazione Ibrido! Questo set di strumenti consente la scrittura automatica, la pianificazione, la formattazione e la traduzione di script per audiodrammi e audiolibri. È stato ottimizzato per lavorare con sintetizzatori vocali professionali e motori di lettura dello schermo locali (NVDA).

Il set è composto dallo studio principale (Regia), dallo strumento per traduzioni e accenti (Poliglotta), dallo strumento per la costruzione della struttura del file (Architetto Audiolibri), dal Gestore Regole (dalla versione 13.0 — senza Python puoi aggiungere un nuovo accento, cifra o modalità creativa, vedi PASSO 7b sotto) e — dalla versione 15.0 — dal modulo Racconti (finzione interattiva in seconda persona generata da AI, letta da TTS o lettore dello schermo, descritta nel manuale separato tales.it.html). Tutti e cinque gli strumenti sono disponibili in un'unica finestra del programma, commutabile tramite pulsanti sulla barra o scorciatoie da tastiera Ctrl+1..Ctrl+5.

PASSO 1: Primo avvio (Cross-Platform)

Scarica l'ultima versione dell'installer dalla scheda Releases su GitHub (file Rezyser_Audio_v<numer>_Installer.exe) e avvialo con un doppio clic. L'installer proporrà una posizione di installazione predefinita — la cartella Programs nella directory locale del tuo account — e non richiede privilegi di amministratore. Puoi anche scegliere un percorso tuo con il pulsante "Sfoglia": l'installer se lo ricorda e lo riutilizza da solo negli aggiornamenti successivi, senza chiedere. Dopo l'installazione, avvia il programma con l'icona sul desktop o dal Menu Start. Dopo un momento apparirà la finestra principale del programma — Regista Audio GPT. Dalla versione 17.0, l'applicazione è congelata come file eseguibile nativo in modalità finestra, quindi non lampeggia più alcuna finestra del terminale e si avvia più rapidamente di prima. Nessun browser, nessun server in background. Quando hai finito di lavorare, chiudi semplicemente la finestra del programma.

L'intera applicazione, incluso il motore Python, i progetti e la chiave API, vive in una cartella sotto il percorso di installazione — l'intera cartella può essere trasferita su una chiavetta USB, nel cloud o su un altro computer (istruzioni dettagliate nella sezione "Trasferimento progetti e chiave API" sotto).

Importante: La cartella runtime/ all'interno della cartella di installazione è il bundle di PyInstaller (dalla versione 17.0) — contiene un interprete Python isolato e librerie, pronte per l'uso senza installazione separata di sistema; funge anche da contenitore per i metadati nascosti dei progetti. Se cloni il repository (percorso sviluppatore), questa cartella non c'è e non dovrebbe esserci — usi allora l'ambiente virtuale venv descritto nella sezione per sviluppatori sotto.

Per Sviluppatori (Windows — repository Git)

  1. Clona il repository sul tuo disco.
  2. Esegui il file setup_dev.bat. Lo script creerà automaticamente un ambiente virtuale Python (venv) e installerà tutte le dipendenze richieste dal file requirements.txt.
  3. Avvia l'applicazione con il comando python main.py o tramite il file run_dev.bat — lo script rileverà automaticamente la cartella venv e avvierà il programma.

Per Sviluppatori e utenti comuni (macOS / Linux)

  1. Clona il repository sul tuo disco.
  2. Apri il terminale nella cartella del progetto e assegna i permessi di esecuzione agli script: chmod +x *.sh
  3. Esegui lo script di configurazione: ./setup_dev.sh — lo script creerà l'ambiente venv e installerà le dipendenze.
  4. Avvia l'applicazione: python main.py o ./run.sh

Cosa vedrai all'avvio: All'avvio del programma si apre una finestra con la schermata iniziale. Troverai una breve descrizione degli strumenti disponibili e una sezione "Controllo del Sistema". Se la chiave API non è ancora configurata, vedrai un messaggio rosso che informa che i moduli basati su AI (Regia, Traduttore) non funzioneranno — le funzioni locali gratuite (accenti, Architetto) sono però attive immediatamente. La configurazione della chiave è descritta nel passo successivo.

Aggiornamenti automatici

L'applicazione verifica all'avvio se è disponibile una nuova versione su GitHub — la verifica avviene in background e non blocca l'interfaccia.

Se hai installato il programma tramite il file dell'installer (.exe): al rilevamento di una nuova versione apparirà una finestra che chiede se scaricarla. Dopo la conferma, verrà avviata una barra di avanzamento e, al termine del download, l'applicazione si chiuderà automaticamente e il nuovo installer si avvierà automaticamente. Del percorso di installazione non devi preoccuparti: l'installer riconosce l'installazione precedente e installa nella stessa cartella di prima — la procedura guidata non mostra nemmeno la pagina della cartella di destinazione (vale anche per una posizione scelta a mano con il pulsante "Sfoglia"). L'aggiornamento sovrascrive i file del motore dell'applicazione e l'intero pacchetto di regole (cartella dictionaries/) — i tuoi progetti (cartelle skrypty/, opowiesci/) e la chiave API (golden_key.env) rimangono intatti. IMPORTANTE: se hai modificato tramite il Manager delle Regole i file esistenti nel pacchetto (ad es. cambiamenti di accento in dictionaries/pl/akcenty/wloski.yaml), queste modifiche SARANNO SOVRASCRITTE durante l'aggiornamento — prima di confermare l'aggiornamento fai un backup della cartella dictionaries/ secondo la procedura nella sezione "Trasferimento progetti e chiave API" sotto (basta copiare la cartella dictionaries/ su una chiavetta USB), e dopo l'aggiornamento ricaricala sovrascrivendo i file più recenti. Le regole completamente nuove che hai creato da zero e che non sono nel pacchetto (ad es. una lingua di base aggiuntiva o un tuo cifrario) rimangono automaticamente intatte — l'installer non rimuove file al di fuori del pacchetto. Dalla versione 15.2.8 lo stesso dialogo che propone l'aggiornamento visualizza questo avviso direttamente nel contenuto e include un pulsante "Apri cartella dictionaries" che con un clic apre Esplora file nel posto giusto — basta premerlo prima di confermare l'aggiornamento per fare comodamente un backup, e poi tornare al dialogo e cliccare "Scarica e installa".

Il percorso di installazione serve invece per copiare i file a mano (backup, trasferimento su un altro computer — vedi la sezione più sotto). Se non lo ricordi, ci sono due modi rapidi per recuperarlo. Windows 11: nel menu contestuale del collegamento sul desktop seleziona "Apri percorso file" (se l'opzione non è visibile nel nuovo menu contestuale semplificato, seleziona prima "Mostra più opzioni" o premi Shift+F10 due volte per aprire immediatamente il menu completo), vai un livello più in alto con il tasto Backspace, seleziona la cartella con l'applicazione e premi Ctrl+Shift+C (o seleziona "Copia come percorso" dal menu contestuale) — il percorso completo verrà copiato negli appunti tra virgolette (incollando nell'installer ricorda di rimuovere le virgolette stesse). Versioni precedenti di Windows (7/8/10): fai clic con il tasto destro sul collegamento e seleziona "Proprietà"; nella scheda "Collegamento" nel campo "Destinazione" vedrai il percorso completo del file di avvio (.exe nella versione 15.2.5+ o run.bat nelle versioni precedenti) — copialo e rimuovi il nome del file finale, rimarrà solo il percorso della cartella di installazione.

Nota per l'aggiornamento da versioni precedenti (v15.2.4 o precedenti, quando l'applicazione veniva avviata tramite run.bat dal pacchetto Portable ZIP): il collegamento esistente sul desktop potrebbe puntare a run.bat nella vecchia posizione, che dopo l'aggiornamento alla v15.2.5+ non c'è più — le versioni 15.2.5+ usano un file .exe autonomo creato dall'installer. Se dopo l'aggiornamento il collegamento smette di funzionare, eliminalo manualmente e lascia che l'installer ne crei uno nuovo durante la reinstallazione.

Se utilizzi il repository Git (sviluppatori e utenti macOS/Linux): invece della proposta di download vedrai un'informazione sulla nuova versione con un link diretto alla pagina di rilascio su GitHub. Scarica da lì l'archivio "Source code" o aggiorna il repository con il comando git pull.

Trasferimento progetti e chiave API (migrazione)

Se desideri trasferire i tuoi progetti, la chiave API e le impostazioni locali su un altro computer (o ripristinare tutto dopo aver reinstallato Windows), non è necessario copiare manualmente singoli file — l'intera cartella dell'applicazione è autosufficiente.

  1. Assicurati che l'applicazione sia COMPLETAMENTE chiusa. Se vedi l'icona del programma nel vassoio di sistema (accanto all'orologio, sul lato destro della barra delle applicazioni), fai clic con il tasto destro e seleziona "Chiudi". I file aperti bloccano la copia.
  2. Trova il collegamento Regista Audio GPT sul desktop. Fai clic con il tasto destro (o con il tasto Applicazioni o Shift+F10 durante la navigazione NVDA) e seleziona l'opzione "Apri percorso file". ATTENZIONE su Windows 11: nel nuovo menu contestuale semplificato questa opzione potrebbe essere nascosta — seleziona prima "Mostra più opzioni" (o premi Shift+F10 due volte per aprire immediatamente il menu completo con l'opzione).
  3. Si aprirà una finestra di Esplora risorse di Windows nella cartella di installazione del programma. Premi il tasto Backspace (il modo più semplice, funziona sempre) o fai clic sulla freccia "Su" nella barra degli strumenti per andare un livello più in alto — vedrai lì l'intera cartella con l'applicazione. Nota: la scorciatoia Alt+Freccia su funziona solo quando il focus è sulla lista dei file — se Esplora risorse si è aperto con il focus sulla barra degli indirizzi (tipico), Alt+Freccia su non farà nulla, usa allora Backspace.
  4. Copia l'intera cartella su una chiavetta USB, un disco nel cloud (OneDrive, Google Drive, Dropbox) o un disco esterno. La cartella contiene tutto ciò che serve per ripristinare lo stato di lavoro:
    - I tuoi progetti (cartella skrypty/ — file .txt di narrazione, .md del Libro del Mondo e i file di risultato degli strumenti di postproduzione: memoria, titoli, scheda di pubblicazione; cartella opowiesci/ — giochi interattivi).
    - La chiave API (file golden_key.env nella cartella principale dell'applicazione).
    - Le tue regole fonetiche, accenti, cifrari, se hai modificato qualcosa nel Manager delle Regole (cartella dictionaries/<codice_lingua>/, ad es. dictionaries/pl/akcenty/wloski.yaml).
    - Preferenze dell'applicazione e scelta delle modalità creative (cartella runtime/skrypty/, file .mode).
    - Ambiente Python isolato (cartella runtime/), quindi non devi installare nulla sul nuovo computer.
  5. Sul nuovo computer: scarica l'ultima versione dell'installer dalla scheda Releases su GitHub e installa l'applicazione normalmente. Avvia il programma una volta per creare una struttura di file di configurazione vuota. Chiudi l'applicazione. Quindi copia la cartella precedentemente salvata nel percorso di installazione sovrascrivendo i file — oppure scegli selettivamente solo le cartelle che ti interessano (skrypty/, opowiesci/, golden_key.env) e incollale nei posti giusti della nuova installazione.

Suggerimento per gli utenti NVDA: il menu contestuale "Apri percorso file" attivato con il tasto Applicazioni è completamente accessibile — NVDA legge ogni voce in italiano. Dopo aver aperto Esplora risorse nella cartella di destinazione, usa il tasto Backspace per andare un livello più in alto (funziona sempre, indipendentemente dal fatto che il focus sia sulla lista dei file o sulla barra degli indirizzi), quindi Ctrl+A per selezionare tutto e Ctrl+C per copiare.

Suggerimento: l'opzione "Apri percorso file" è il nome nativo per la versione italiana di Windows. Nel sistema inglese si chiama "Open file location", nelle altre versioni linguistiche — analogamente nella lingua locale del sistema operativo.

PASSO 2: Configurazione API (chiave Anthropic / Claude consigliata)

Il fornitore AI consigliato e predefinito è Anthropic (Claude) — tutti i prompt dell'applicazione sono ottimizzati per esso, quindi garantisce la massima qualità narrativa e il miglior rispetto delle regole del mondo. In questa variante (raccomandata) è sufficiente UNA SOLA chiave API nel file golden_key.env:

• Chiave Anthropic (Claude) — alimenta L'INTERO motore AI: la narrazione del Regista (audiolibro, teatro letto, brainstorming), la modalità Racconti, il Poliglotta (traduttore) e l'assegnazione dei titoli ai capitoli e il rilevamento della lingua del contenuto. Inizia con sk-ant-.

Se stai aggiornando da una versione precedente: la vecchia chiave OpenAI non è più necessaria per la variante predefinita — puoi lasciare o rimuovere la sua riga in golden_key.env, l'applicazione la ignora (a meno che tu non stia configurando consapevolmente un altro fornitore — vedi PASSO 2B più avanti).

Come ottenere la chiave Anthropic:
1. Crea un account su console.anthropic.com e ricarica il credito (scheda Billing / Plans).
2. Genera la chiave nella sezione API Keys (inizia con sk-ant-). Copiala subito — a volte viene mostrata una sola volta.

Come inserire la chiave nel programma:
3. Nella schermata iniziale del programma, fai clic sul pulsante "Genera il file golden_key.env e apri l'editor di testo". Il sistema creerà automaticamente un file di configurazione pulito nella posizione corretta e aprirà il Blocco note con un modello pronto per la modifica.
4. Nel file aperto vedrai la riga: ANTHROPIC_API_KEY=PASTE_YOUR_KEY_HERE. Elimina il testo segnaposto e incolla la tua chiave direttamente dopo il segno di uguale (senza spazi e senza virgolette). Salva il file e riavvia l'applicazione.

Suggerimento: Dopo il riavvio, l'applicazione verificherà il file e nella sezione "Controllo del Sistema" mostrerà lo stato della chiave. Deve essere verde affinché tutti i moduli AI siano pronti all'uso. Se la chiave è assente o errata, il programma lo indicherà chiaramente e consentirà di aprire l'editor di testo per correggere rapidamente l'errore.

PASSO 3: Studio di Regia Principale

Questo è il tuo centro di comando per inventare storie e scrivere sceneggiature. Accedivi cliccando il pulsante "🎬 Regista" nella barra dei pulsanti oppure selezionando Strumenti → Regista dal menu (scorciatoia: Ctrl+1).

Importante: Formato dei file di progetto — ritorno al .txt

Nella versione 7 i file di progetto venivano salvati in formato Markdown (.md), ad esempio skrypty/znieczulica.md. Si trattava di un esperimento intenzionale — il formato .md doveva costituire una barriera psicologica per le persone non tecniche, scoraggiandole dall'aprire e modificare manualmente il file in Blocco Note (e quindi dal danneggiare accidentalmente le intestazioni della struttura).

L'esperimento non ha funzionato. L'IA viola spesso in modo prepotente uno dei divieti fondamentali (ne parleremo tra poco). Per questo motivo nella versione 8 si è tornati ai semplici file .txt — più intuitivi e leggibili per tutti. Ad esempio, un progetto chiamato "znieczulica" verrà ora salvato come skrypty/znieczulica.txt, e il suo riassunto come skrypty/znieczulica_streszczenie.txt. Questo permetterà a chiunque di apportare più facilmente correzioni registiche o tagli al testo man mano che si procede.

⚠️ Regola critica del Montatore (leggila prima di iniziare!)

Tutti i tuoi script e libri generati vengono salvati in semplici file di testo (.txt), che puoi aprire facilmente con Blocco Note.

Come Regista hai il PIENO DIRITTO (anzi il dovere) di modificare quel file! Se l'intelligenza artificiale si lascia trascinare e, ad esempio, risolve da sola il problema dei personaggi alla fine del frammento generato, apri il file, elimina le ultime righe e lascia il testo interrotto nel momento di massima tensione, poi clicca "Ricarica progetto dal disco" per sincronizzare la memoria del modello con il file corretto, e "Invia all'AI" per continuare.

🔴 Tuttavia — cosa non devi toccare

Non modificare mai, non eliminare e non alterare le righe contenenti la struttura (ad es. Atto 1, Scena 2, Capitolo 1, Prologo). Se rovini queste intestazioni:
1. La tua storia si frantumerà nei lettori di schermo (NVDA).
2. L'Architetto dell'audiolibro, e di conseguenza anche ElevenLabs Studio, non sarà in grado di suddividere correttamente il tuo libro in frammenti da leggere.
3. Il Convertitore interno dell'applicazione non genererà un indice corretto nel file Word né sulla timeline in ElevenLabs.

Modifica i dialoghi, taglia l'azione, ma lascia la struttura in pace!

Come usare la Regia?

  • Libro del Mondo (barra laterale sinistra): Qui inserisci le regole dell'universo. Ogni progetto ha ora il proprio Libro collegato al nome del file — se il tuo file della storia è ad esempio emilia_heist_audiobook.txt, il Libro del Mondo verrà salvato come skrypty/emilia_heist_audiobook.md. Per questo l'ordine è importante: prima inserisci il nome del file di progetto nel campo "Nome file di progetto", e solo dopo potrai salvare il Libro. Il pulsante "💾 Salva il Libro in modo permanente" rimane disattivato finché non fornisci il nome. Caricare un progetto esistente con il pulsante "Carica storia" caricherà automaticamente anche il file .md corrispondente — non devi fare nulla manualmente. Attenzione: Senza il Libro del Mondo compilato, l'applicazione bloccherà l'invio di richieste all'IA — si tratta di una protezione intenzionale che ti impedisce di generare testo senza alcuna regola.
  • Memoria a Lungo Termine (barra laterale sinistra): Secondo campo nella barra laterale. Qui arriva il riassunto della trama — prodotto dallo strumento nel pannello di postproduzione (PASSO 4) oppure, al livello d'allarme della memoria, in automatico. Puoi anche inserire qui le tue note manualmente — il modello le tratterà come "ciò che già so" prima di leggere la scena corrente. LACUNA STORICA (corretta nella v15.5): in precedenza, se inserivi qui una nota molto breve e cliccavi "Salva Riassunto" prima che nel file della narrazione ci fosse qualcosa di significativo, al successivo caricamento l'applicazione caricava PRIORITARIAMENTE il riassunto e SALTAVA la storia completa — il modello riceveva allora solo il Libro del Mondo e una nota di una riga, senza il contesto del tono e delle ultime scene. Dalla v15.5 il caricamento è intelligente: se l'intera storia rientra nella finestra di contesto, viene caricata per intero (e il vecchio riassunto superfluo viene eliminato), quindi il modello non perde il contesto. Dopo la modifica manuale del file della narrazione nell'editor, usa il nuovo pulsante "Ricarica progetto dal disco" (dalla v15.5), che con un solo clic sincronizza la memoria interna con il disco; per aprire semplicemente il file nell'editor continua a usare "Apri file di narrazione…".
  • Modalità Brainstorming: Inserisci un'idea libera e l'IA ti darà 3 opzioni di sviluppo della trama. Per ciascuna opzione genererà immediatamente un blocco pronto "--- BOZZA DI PROMPT ---". Dopo averne scelta una, incolla quel prompt nella Modalità Script o Audiolibro e aggiungi eventuali osservazioni o informazioni per il modello. La memoria della trama non cambia durante il Brainstorming — puoi sperimentare senza rischi!
  • Modalità Script Grezzo (dalla v16.0 — teatro da leggere): Qui incolli la "BOZZA DI PROMPT" generata nel Brainstorming. L'IA scriverà un lungo frammento narrativo-dialogico: la narrazione (scenografia, tempo, azione) nei tag [Narrator: ...] e le battute dei personaggi nei tag [Nome: emozione]. Senza effetti sonori — il contesto è portato dal narratore con le parole. Il testo viene aggiunto automaticamente al tuo file (ad es. nowa_scena.txt) nella cartella skrypty/. Questo script pronto puoi poi trasformarlo in un audiolibro a più voci (ponte verso ElevenLabs Studio — capitolo separato più avanti).
  • Modalità Audiolibro Tradizionale: Modalità per scrittori. L'IA genera prosa letteraria pura — zero tag, zero fonetica, dialoghi classici intrecciati nella narrazione. Il testo viene aggiunto al file esattamente come nella Modalità Script.
  • Creazione automatica dei personaggi: Lo script è programmato per creare automaticamente nuovi tag [Speaker] se la trama richiede un nuovo personaggio. Suggerimento: Se l'IA crea un personaggio interessante, copia il suo tag e incollalo nel Libro del Mondo affinché il modello lo ricordi in modo permanente!

Gestione del progetto — tre pulsanti di azione:
- Carica storia: Carica un progetto esistente in memoria. Disponibile quando la memoria corrente è vuota. Dalla versione 15.2.3 supporta due percorsi: se il campo del nome del progetto è vuoto, si apre una finestra di dialogo con l'elenco di tutti i progetti trovati nella cartella skrypty/ (esclude i file di riassunto) — NVDA legge l'elenco in modo naturale, l'utente non deve ricordare e riscrivere il nome dalla tastiera. Se il campo del nome è compilato, l'applicazione tenta immediatamente di caricare il progetto con quel nome (percorso esperto: Invio nel campo del nome o clic dopo averlo digitato a memoria).
- Chiudi Progetto (Reset Completo): Cancella completamente il progetto. Elimina la storia, il riassunto, il Libro del Mondo e azzera tutti i contatori. Usalo quando cambi progetto o inizi una nuova storia.
- Apri file di narrazione… (dalla v15.2.3): Modifica di emergenza del file della narrazione nell'editor di testo di sistema. Richiede il nome del progetto inserito. L'applicazione apre skrypty/<nazwa>.txt in Blocco Note (Windows), TextEdit (macOS) o nell'editor GUI predefinito (Linux). Scenari tipici: (a) l'IA non chiude la scena e vuoi aggiungere il finale manualmente; (b) hai caricato un progetto con riassunto e vuoi copiare le ultime scene nella Memoria a Lungo Termine affinché il modello abbia il contesto completo del tono (lacuna architetturale descritta sopra); (c) vuoi effettuare un taglio nel mezzo di un capitolo che il motore dell'applicazione non supporta nativamente.

  • Ricarica progetto dal disco (dalla v15.5, ricostruito nella v17.6): Ricarica L'INTERO progetto dal disco dopo la modifica manuale del file di narrazione — si tratta di un vero reload, non solo di un aggiornamento della memoria corrente. Ricalcola i contatori di Capitoli/Atti/Scene, carica il Libro del Mondo, la modalità e le opzioni del Brainstorming e sincronizza la memoria di lavoro. Se l'intera storia rientra nella finestra di contesto, la carica per intero (ed elimina il vecchio riassunto superfluo affinché il motore lavori sul testo completo). Se la storia è lunga e ha un riassunto salvato, lo conserva intatto e ti chiede da quale intestazione deve partire la memoria di lavoro dell'IA: in modalità Audiolibro scegli il Capitolo, in modalità Script prima l'Atto e poi la Scena di quell'atto (oppure l'intero Atto) — il resto è rappresentato dal riassunto. Annullare la scelta = taglio d'emergenza all'ultimo frammento di testo (per questo vale la pena mantenere la struttura delle intestazioni). Prima di sovrascrivere i campi con la versione dal disco, avvisa se contengono contenuto non salvato. Scenario tipico: l'IA ha chiuso erroneamente la scena (violando l'anti-closure), tu tagli la parte finale sbagliata nell'editor e clicchi Ricarica — fine delle correzioni in due posti diversi.

Nota storica — perché le modalità sono ora protette da cambiamenti accidentali:
Nelle versioni precedenti dell'applicazione nessuno controllava la coerenza della modalità creativa all'interno di un singolo progetto. Il risultato era una certa sottile possibilità creativa, descrivibile così: inizi la storia in Modalità Script, inserisci "Atto 1" e "Scena 1" (l'applicazione è entusiasta della tua coerenza), generi qualche schermata di tensione con i tag [SFX: Scricchiolio della porta] e [Speaker 1: Marek - rassegnato]... e poi — perché proprio in quel momento arriva l'ispirazione — clicchi "Inserisci taglio Capitolo 1". L'applicazione senza battere ciglio aggiunge l'intestazione "Capitolo 1" al file, subito dopo "Scena 3". Hai ora nel file un ibrido tra un radiodramma degli anni '50 e un romanzo di costume. ElevenLabs guarda questa struttura, vede un'intestazione di capitolo nel mezzo di un atto e decide che probabilmente è un errore nella matrice. Il sommario sembra l'opera di un artista d'avanguardia. L'Architetto degli Audiolibri dal canto suo parte dal presupposto che tu sia un adulto e semplicemente elabora il tutto senza dire una parola — ma anche senza alcuna garanzia sul risultato. Dalla versione 12.0 l'interfaccia cercava di bloccare il cambio di modalità di scrittura — almeno in teoria. La pratica si è rivelata più creativa: il Brainstorming (sempre attivo come modalità di pianificazione) era la porta sul retro attraverso cui, con le frecce su e giù, si poteva passare tra Script e Audiolibro (Audiolibro → Brainstorming → Script e analogamente nella direzione opposta). Il primo clic su "Inserisci Atto 1" o "Inserisci Capitolo 1" nella modalità appena selezionata sovrascriveva tranquillamente il file .mode, mescolando atti e capitoli in un unico file di narrazione. Solo dalla versione 15.2.3 abbiamo una vera protezione: dopo che la decisione sulla modalità è stata consolidata (prima struttura o primo invio produttivo riuscito), la seconda voce di scrittura nel campo di selezione della modalità è effettivamente bloccata. Il Brainstorming rimane sempre attivo come modalità di pianificazione — fornisce le opzioni narrative — ma non è più possibile usarlo per saltare lateralmente a un'altra modalità di scrittura. (Dalla versione 18.13 il Brainstorming non riassume più nulla: quel compito è passato allo strumento della Memoria a Lungo Termine nel pannello di postproduzione.)

Prompt da Showrunner — l'IA come sceneggiatore seriale (dalla versione 7, conservato)

Questa è la più grande novità introdotta nella versione 7, conservata invariata. Non è visibile nell'interfaccia, ma cambia radicalmente la qualità della trama generata.

Lo showrunner nel settore televisivo è la persona responsabile dell'intera serie — si assicura che la trama non si avvii mai verso una soluzione facile, ma si infittisca costantemente, accumuli conflitti e tenga lo spettatore in tensione per molte stagioni. Nella versione 7 questa filosofia è stata incorporata direttamente nelle istruzioni di sistema dell'IA.

La Direttiva Anti-Closure — e cosa ha cambiato il motore Anthropic (Claude)

La filosofia dello Showrunner è applicata dalla direttiva Anti-Closure integrata in ogni modalità: il divieto di chiudere le scene con riassunti, morali e falsi lieti fini. Nell'era precedente (modello GPT) accadeva esattamente il contrario di oggi — il motore violava sistematicamente questo divieto e "chiudeva" la storia ad ogni occasione: inseriva frasi riassuntive della trama, creava falsi lieti fini o chiudeva i fili narrativi nel mezzo di un capitolo, come se ogni frammento fosse l'ultimo. Dalla versione 18 l'intero motore IA lavora di default su Anthropic (Claude) — e dalla versione 18.4 puoi facoltativamente indicare il tuo fornitore (PASSO 2B) — e Claude rispetta l'Anti-Closure in modo molto più rigoroso.

Ne è emerso un altro effetto collaterale puramente tecnico: poiché il modello non chiude sistematicamente la scena, la sua risposta può raggiungere il limite di lunghezza della singola risposta e interrompersi a metà frase (e a volte anche a metà parola). L'applicazione gestisce questo autonomamente — quando rileva che il frammento si è interrotto al limite, con una breve query aggiuntiva chiude l'ultima frase in modo che suoni naturale nella lingua della tua storia, e solo allora salva il testo. Se per qualche motivo non riesce a completare questa operazione, vedrai un avviso discreto, ma il testo verrà comunque salvato nella forma attuale — il salvataggio non viene mai bloccato, la parte finale interrotta puoi sempre rifinirla manualmente.

La regola del montatore descritta sopra rimane invariata: se nonostante tutto il modello chiude la scena in modo troppo levigato, è tuo diritto (anzi dovere) come Regista aprire il file .txt, eliminare quelle ultime frasi, lasciare il testo interrotto in un momento di tensione e cliccare "Ricarica progetto dal disco" per sincronizzare la memoria con il file corretto.

Ogni modalità possiede una direttiva Anti-Closure integrata:

  • Brainstorming: L'IA agisce come sceneggiatore di una serie multistagionale. Ognuna delle 3 opzioni proposte DEVE accumulare ostacoli, introdurre nuovi dilemmi, fili narrativi aperti e cliffhanger. Assoluto divieto di proporre opzioni in cui i personaggi si riconciliano definitivamente, superano l'ostacolo principale senza potenti conseguenze o la storia si avvia verso una fine affrettata. Divieto di inventare location economiche e magiche che rompono l'architettura del mondo.
  • Modalità Script Grezzo: Assoluto divieto di concludere il testo con riassunti, morali o chiusure ad anello. L'IA deve interrompere l'azione naturalmente in un momento di tensione (cliffhanger), evitando conclusioni affinché il frammento successivo possa riprendere fluidamente la narrazione.
  • Modalità Audiolibro Tradizionale: Assoluto divieto di concludere il testo con riassunti patetici, chiusura dei fili narrativi o suggerimento della fine della storia (ad es. "Era pronta per le nuove sfide", "Capì che era tempo di andare avanti"). Il testo deve interrompersi nel mezzo di un'azione in corso, di una tensione o di un pensiero aperto.

Eccezione alla regola: Se chiedi esplicitamente un finale, una conclusione o un epilogo, l'IA genererà una chiusura soddisfacente della storia — il divieto non si applica quando sei tu stesso a richiederlo.

Gestione di Atti e Scene (Modalità Script, dalla versione 7, conservato)

La Modalità Script Grezzo dispone di un pannello dedicato "✂️ Gestione della Struttura" con pulsanti per costruire la struttura del radiodramma in tempo reale.

  • Inserisci Atto X: Inserisce l'intestazione dell'atto (ad es. "Atto 2") E aggiunge automaticamente sotto di essa "Scena 1" — perché ogni nuovo atto inizia dalla prima scena. Il contatore degli atti passa al numero successivo e il contatore delle scene si azzera a 2 (pronto per la scena successiva in quell'atto).
  • Inserisci Scena X: Inserisce solo l'intestazione della scena (ad es. "Scena 3") all'interno dell'atto corrente. Il contatore delle scene aumenta automaticamente.

Caricamento intelligente del file: Quando carichi un file di script esistente, l'applicazione lo scansiona automaticamente e imposta i contatori di atti e scene sui numeri corretti. Il contatore delle scene è sempre calcolato all'interno dell'ultimo atto nel file.

Prologo ed Epilogo: I pulsanti "📜 Inserisci Prologo" e "🏁 Inserisci Epilogo" sono comuni a entrambe le modalità e disponibili nello stesso pannello.

L'Architetto degli Audiolibri convertirà automaticamente gli Atti in punti di navigazione principali (Heading 1) per ElevenLabs e NVDA — le Scene diventeranno testo in grassetto visibile nel documento, ma non visibile nel sommario.

Gestione Intelligente dei Capitoli (Modalità Audiolibro, dalla versione 5, conservata)

L'LLM genera al massimo circa 5000 caratteri per singola query — troppo poco per un capitolo completo. Per questo lavori in modo iterativo: generi i frammenti successivi con il pulsante "Invia all'IA", finché non ritieni che il capitolo sia pronto. A quel punto clicchi "Inserisci taglio capitolo" — l'applicazione aggiunge l'intestazione al file e alla memoria, e il contatore dei capitoli passa automaticamente al numero successivo.

Pulsanti nel pannello:

  • Inserisci taglio (Capitolo X): Inserisce l'intestazione (ad es. "Capitolo 3") nel file e nella memoria. Il contatore dei capitoli si aggiorna automaticamente.
  • Inserisci Prologo: Funziona solo all'inizio, quando la memoria è vuota. Protezione contro l'inserimento accidentale del Prologo nel mezzo della storia.
  • Inserisci Epilogo: Chiude la storia. Dopo aver inserito l'Epilogo con contenuto, l'applicazione bloccherà la generazione di nuovi frammenti — è intenzionale, perché dopo la fine della storia non c'è più nulla da aggiungere.

Caricamento intelligente del file: Quando carichi un file esistente, l'applicazione lo scansiona automaticamente e imposta il contatore dei capitoli sul numero corretto. Se il file ha un Prologo e tre capitoli, il contatore mostrerà "Capitolo 4" — senza contare manualmente.

Accumulatore della Trama — come funziona la memoria dell'IA

Nella memoria del modello entra esclusivamente il testo puro della storia — ciò che l'IA ha effettivamente scritto. Le istruzioni, le opzioni e i piani scompaiono dopo l'uso e non inquinano il contesto. Il risultato? Il modello mantiene la concentrazione più a lungo, ricorda meglio le sfumature dei personaggi e "fugge" meno spesso dalle regole del Libro del Mondo.

L'indicatore "Memoria del Modello" sullo schermo mostra quanto è riempita la finestra di contesto del modello. Dalla versione 15.1 NON si tratta più del semplice conteggio dei caratteri della storia — l'applicazione conta i TOKEN reali (con lo stesso metodo usato dal modello) e somma L'INTERO carico inviato all'IA: la storia corrente, la Memoria a Lungo Termine (riassunto) E il Libro del Mondo. Per questo l'indicatore cresce anche quando espandi il Libro del Mondo o hai un riassunto lungo — non solo per via della narrazione stessa. Il valore viene mostrato come percentuale di riempimento della finestra:
- Verde (fino a circa il 70%): Il modello è pienamente concentrato, hai un margine di sicurezza.
- Giallo (circa 70–90%): Ti stai avvicinando al limite. L'IA potrebbe iniziare ad accorciare le risposte e ignorare le regole. È il momento di salvare tu stesso la Memoria a Lungo Termine — e di iniziare a chiudere gradualmente il filo narrativo.
- Rosso (oltre circa il 90%): Sovraccarico critico! Dalla versione 18.13, a questo livello l'applicazione avvia da sola, dopo ogni invio riuscito, lo strumento della Memoria a Lungo Termine dal pannello di postproduzione e salva il riassunto — ne ricevi un avviso e il pannello resta bloccato per il tempo della generazione.

Diagnostica della soglia di riassunto (quando l'IA allucinare prima di quanto previsto dalla soglia): le soglie (avviso ~70%, allarme ~90%) sono stimate empiricamente. Se noti una tendenza ricorrente per cui il modello "fugge" dalle regole o inizia ad allucinare PRIMA che l'indicatore entri nel giallo/rosso — cioè prima di quanto previsto dalla soglia — apri un issue nel repository dell'applicazione e descrivi a quale percentuale di riempimento circa inizia effettivamente a deteriorarsi, preferibilmente con un esempio. Se questa tendenza si conferma più ampiamente (in altri utenti, su progetti diversi), la soglia del riassunto automatico verrà abbassata nella patch successiva. È un meccanismo consapevolmente iterativo — meglio calibrarlo su dati reali che indovinare a priori.

Memoria Infinita (dalla versione 6, conservata)

Quando si accende l'allarme rosso, non devi più copiare manualmente il riassunto. Dalla versione 18.13 se ne occupa uno strumento a sé nel pannello di postproduzione (PASSO 4): un clic genera una pillola sintetica di conoscenza sull'intera trama sviluppata fino a quel momento, la salva come file di memoria nella cartella skrypty/ (nel pacchetto italiano <nome>_riassunto.txt) e la inserisce subito nel campo della Memoria a Lungo Termine. Dopo il salvataggio puoi svuotare la memoria e continuare a scrivere nello stesso file: la storia può proseguire all'infinito, senza alcun limite di lunghezza.

Che cosa è cambiato rispetto alle versioni precedenti: fino alla v18.12 il riassunto si ordinava nel Brainstorming, scrivendo nell'istruzione la parola «riassunto» o «sintesi». Quella strada aveva un difetto insito nella sua costruzione: il prompt del Brainstorming vieta al modello di scrivere qualsiasi cosa oltre alle tre opzioni di trama, quindi la richiesta di un semplice riassunto lo metteva davanti a due istruzioni contraddittorie insieme — e poteva finire con un errore invece che con un risultato. Per questo il riassunto è ora uno strumento autonomo con una propria istruzione, priva di contraddizioni, e il Brainstorming è tornato a un solo compito: pianificare la trama.

Quando riassumere (aggiornato nella v15.5): Non devi più rispettare una soglia rigida di caratteri "prima di terminare il lavoro". È meglio riassumere dopo la chiusura naturale di una parte strutturale più ampia — dopo la fine di una scena, di un atto o di un capitolo. Il motivo: quando in seguito correggi manualmente la parte finale nel file di narrazione e clicchi "Ricarica progetto dal disco", l'applicazione ti chiederà da quale intestazione ripristinare il frammento aggiornato — e il riassunto della parte precedente rimarrà intatto (fine delle correzioni in due posti diversi). Per questo vale ancora di più la pena mantenere la struttura: inserisci regolarmente le intestazioni Capitolo/Atto/Scena dal pannello della struttura (sono sconsigliate le forme lunghe senza alcun atto/capitolo, ad es. un "dramma modernista" in un unico blocco continuo). ECCEZIONE: se stai conducendo una storia molto lunga COMPLETAMENTE senza intestazioni, generare e salvare il Riassunto prima di una pausa rimane necessario — senza marcatori l'applicazione può ripristinare solo l'ultimo frammento contato in caratteri, e il motore senza contesto potrebbe "andare in panico".

Riassunto automatico (ricostruito in v18.13): quando l'indicatore di memoria entra in stato di allarme (oltre circa il 90%), l'applicazione avvia da sola lo strumento della Memoria a Lungo Termine non appena l'invio è concluso — senza chiedere, perché a quel livello ogni chiamata successiva è già a rischio. Il risultato finisce direttamente nel file del riassunto e nel campo della Memoria a Lungo Termine, e tu ricevi un messaggio che te lo comunica. Zero lavoro manuale. Il riassunto puoi naturalmente correggerlo nel campo e salvarlo di nuovo con il pulsante di salvataggio della Memoria.

Il riassunto è INCREMENTALE: lo strumento non rilegge ogni volta l'intero progetto da capo. Riceve la Memoria a Lungo Termine esistente e la parte di narrazione nata dopo l'ultimo riassunto (l'applicazione ricorda a quale intestazione si era fermata) e fonde le due cose. Così il costo dei riassunti successivi non cresce con la lunghezza del romanzo e gli eventi più vecchi non si perdono a ogni aggiornamento.

Caricamento intelligente e ricarica dal disco (aggiornato nella v17.6): Sia durante il caricamento del progetto, sia dopo aver cliccato "Ricarica progetto dal disco" (dopo la modifica manuale del file di narrazione nell'editor), l'applicazione riconcilia la memoria con il disco in un unico passaggio — ricalcola i contatori della struttura e aggiorna il Libro del Mondo e la modalità. Se L'INTERA storia rientra nella finestra di contesto — la carica per intero ed elimina il vecchio riassunto superfluo, affinché il motore lavori sul testo completo (questo chiude una vecchia lacuna in cui il modello riceveva solo il riassunto senza il contesto delle ultime scene). Se la storia è LUNGA e ha un file di riassunto salvato — conserva il riassunto intatto e ti chiede da quale intestazione strutturale (Capitolo/Atto/Scena) deve partire la memoria di lavoro dell'IA; il resto della trama è rappresentato dal riassunto. In questo modo non sprechi token ricaricando l'intera storia, e allo stesso tempo il riassunto successivo non viene generato su dati non aggiornati.

PASSO 3b: Due uscite dello Script — audiolibro multivocale (ElevenLabs) e versione per lettori di schermo

Lo script pronto del teatro di lettura (modalità Script) ha due uscite indipendenti: un progetto multivocale ElevenLabs Studio (audio) e una versione HTML per lettori di schermo. Sono due modi di "ascoltare" lo stesso testo — puoi usarne uno, l'altro o entrambi. Entrambi sono opzionali e non modificano il flusso classico con il convertitore.

Ponte verso ElevenLabs Studio (audio, opzionale)

Il ponte trasforma lo script in un progetto Studio multivocale — il narratore e ogni personaggio ricevono una voce separata. Senza la chiave ElevenLabs non cambia nulla: il ponte rimane semplicemente nascosto.

Chiave ElevenLabs (opzionale)

Incolla la tua chiave ElevenLabs nel file golden_key.env, su una riga separata: ELEVENLABS_API_KEY=sk_... Attenzione: la chiave ElevenLabs inizia con sk_ (con UNDERSCORE), a differenza della chiave Anthropic (sk-ant-). Se utilizzi una chiave con restrizioni (restricted key), assegnale i permessi (scope) projects_write e voices_read. Lo stato della chiave è visibile nella schermata principale (System Check) — l'assenza della chiave non è un errore, il ponte rimane semplicemente nascosto.

Il ponte appare nel pannello del Regista in modalità Script (quando la chiave è corretta). Funziona su uno script pronto salvato su disco — prima genera o carica il progetto, poi accedi al ponte.

Passo 1 — Cast vocale

Clicca su "Cast vocale…". L'applicazione leggerà dallo script i personaggi che hanno battute e aggiungerà sempre uno slot per il Narratore (il narratore è la voce predefinita — legge i titoli dei capitoli e tutta la narrazione). Per ogni parlante incolla il voice ID. IMPORTANTE: ogni voce utilizzata nello script deve prima trovarsi nelle tue "My Voices" — le voci che crei tu stesso (ad es. in "Voice Design") vi finiscono automaticamente, mentre le voci della libreria pubblica le sfogli nella scheda "Explore" e le aggiungi con il pulsante "Add to My Voices". Come ottenere il voice ID in ElevenLabs (nel browser): trova la voce, riproduci un campione per assicurarti che sia quella giusta, e copia il suo identificatore con il pulsante "Copy Voice ID"; quando la voce è già nelle "My Voices", questo pulsante è disponibile immediatamente — senza espandere "More actions". Selezione delle voci: per limitare eventuali rigenerazioni, è più semplice scegliere dalla collezione "Best for Eleven v3" (voci testate per il modello v3 su cui viene creato il progetto); in alternativa progetta la tua voce in "Voice Design", e per i più audaci resta la clonazione IVC (Instant Voice Cloning) o PVC (Professional Voice Cloning). Puoi lasciare i campi vuoti e tornare in seguito — il salvataggio è una bozza.

Passo 2 — Costruisci il progetto

Clicca su "Crea progetto ElevenLabs Studio…". L'applicazione verificherà che lo script abbia almeno un capitolo (Prologo/Atto/Capitolo) e che ogni parlante e il narratore abbiano una voce assegnata, quindi creerà nel tuo account un progetto Studio multivocale suddiviso in capitoli. La sola creazione del progetto NON consuma crediti. L'applicazione imposta immediatamente la lingua del progetto (pronuncia corretta delle righe di intestazione) e la normalizzazione del volume allo standard degli audiolibri — lo fa tramite API, così non devi entrare nelle impostazioni del progetto nel browser.

Guardiano del formato (estensione della Regola del Montatore): il ponte richiede che nello script OGNI riga sia o una battuta con indicazione del parlante ([Narrator: …] o [Nome: …]), oppure un'intestazione di struttura (Prologo, Atto, Scena, Capitolo). La prosa ordinaria non taggata inserita "liberamente" — ad esempio una nota d'autore o un frammento di narrazione senza tag — non viene assegnata ad alcuna voce e viene silenziosamente ignorata durante la costruzione, quindi il progetto finito potrebbe discostarsi dal tuo file. Pertanto, se l'applicazione rileva tali righe orfane, ne mostrerà l'elenco con i numeri e chiederà se procedere comunque: puoi annullare e correggere lo script (aprilo con il pulsante "Apri file di narrazione…", aggiungi i tag mancanti del parlante o elimina quelle righe) oppure costruire consapevolmente lo stesso, accettando che vengano omesse. È un'estensione naturale della Regola del Montatore: così come non si devono rovinare le intestazioni di struttura, in uno script destinato al ponte ogni riga dovrebbe avere il suo parlante oppure essere un'intestazione.

Passo 3 — Render nel browser

Dopo la creazione del progetto, l'applicazione mostrerà il suo identificatore e un pulsante che apre ElevenLabs Studio. Nel browser trova il progetto, esegui il render del parlato (è qui che vengono consumati i crediti — orientativamente 1 credito per carattere), poi esporta il file audio o pubblica il progetto su Eleven Reader. Il render e la pubblicazione avvengono dalla tua parte, consapevolmente — l'applicazione si limita a costruire il progetto.

Espressione e accenti (modello Eleven v3)

Il progetto viene creato con il modello Eleven v3 (oltre 70 lingue). Le emozioni NON si esprimono con lettere maiuscole, puntini di sospensione o trattini — il motore li ignora. Al loro posto il Regista inserisce nelle battute audio-tag v3 in inglese, ad esempio [whispers], [sighs], [angry], [laughs] — sono loro a controllare l'espressione e funzionano indipendentemente dalla lingua del parlato. L'ACCENTO del personaggio deriva invece dal CAMPIONE VOCALE: se vuoi che qualcuno parli ad esempio in polacco con un accento straniero, scegli o progetta in Voice Design una voce il cui campione abbia quell'accento. In pratica sperimenta con il prompt della voce finché non senti ad esempio un campione polacco con accento finlandese — il modello v3 manterrà quell'accento nella registrazione finale. Suggerimento: le frasi molto lunghe indeboliscono l'accento, per questo al Regista viene già chiesto nel prompt di usare frasi brevi.

Consapevolezza del modello v3 (fase alpha)

Eleven v3 è il più espressivo, ma è ancora in fase alpha. Può capitare che una singola replica venga renderizzata come rumore statico invece che come parlato — basta rigenerarla in Studio (ogni blocco ha alcune rigenerazioni gratuite). Nelle impostazioni del progetto ElevenLabs potrebbe anche mostrare raccomandazioni di cambio modello (su Eleven Flash v2.5 o Multilingual v2) — NON è un errore, solo un suggerimento del motore. Se non vuoi vedere questi messaggi, semplicemente non aprire le impostazioni del progetto: l'applicazione ha già impostato tutto il necessario tramite API (modello, lingua, normalizzazione del volume).

Perché teatro di lettura e non effetti sonori? Nelle versioni precedenti la modalità Script produceva effetti grezzi [SFX: ...] senza narratore. Il ponte verso una registrazione multivocale completa richiede però che il contesto (luogo, tempo, azione) sia portato dal narratore con le parole: gli effetti sonori in Studio non sono accessibili ai lettori di schermo, e il modello comunque realizza o il narratore o gli effetti — mai stabilmente entrambi insieme. Per questo la modalità Script è un teatro di lettura: narratore più dialogo, senza SFX.

Versione per lettori di schermo (HTML, senza ElevenLabs)

In modalità Script, indipendentemente dalla chiave ElevenLabs, hai il pulsante "Genera versione per lettori di schermo". Crea il file skrypty/<nazwa>_screen_reader.html — un'uscita separata per le persone che utilizzano lettori di schermo (ad es. NVDA). Funziona così: le battute dei personaggi che nel Libro del Mondo hanno un accento definito (ad es. la voce "[Joana] accento finlandese"), ricevono una trascrizione fonetica (ortografia deliberatamente "alterata") e un indicatore di lingua (attributo lang), grazie al quale il lettore di schermo le legge con l'accento straniero corretto. Gli audio-tag v3 (ad es. [whispers]) vengono rimossi in questa versione — il lettore non deve leggerli ad alta voce. Le intestazioni Prologo/Atto/Scena diventano intestazioni HTML, quindi la navigazione nel documento è comoda.

È un complemento consapevole del ponte audio: l'accento per il modello v3 è portato dal campione vocale, mentre per il lettore di schermo — dall'ortografia più l'indicatore di lingua. Per questo l'ortografia nella versione audio rimane pulita (v3 sceglie da solo la lingua), mentre l'"alterazione" dell'ortografia va esclusivamente nel file HTML separato, dove è desiderata.

PASSO 4: Post-produzione nella Regia

Dopo aver scritto la storia, hai a disposizione un pannello di strumenti di post-produzione nella parte inferiore del pannello Regia. Il pannello è dinamico: ogni strumento è un file YAML separato nella cartella rezyser/ (kategoria: postprodukcja), e il suo campo dla_trybow decide in quali modalità creative lo strumento appare. L'insieme dei pulsanti cambia quindi in base alla modalità selezionata — e quando nessuno strumento corrisponde alla modalità corrente, il pannello resta nascosto. Puoi creare uno strumento personalizzato nel Gestore Regole (modello di tipo postprodukcja — vedi PASSO 7b).

Lo strumento opera in uno dei tre ambiti (campo zakres nello YAML):

  • per_rozdzial — itera sui capitoli del file salvato ed elabora ciascuno separatamente (così funziona l'Assegnazione dei Titoli qui sotto),
  • calosc — invia all'IA l'intero file di progetto in un'unica chiamata (ad esempio un report o un audit dell'intera storia); se il progetto ha un Libro del Mondo, lo strumento può includerlo come contesto aggiuntivo,
  • rekoncyliacja (dalla v18.13) — invece dell'intero file, invia la Memoria a Lungo Termine esistente e la parte di narrazione creata dopo l'ultimo riassunto. Così funziona lo strumento di Memoria a Lungo Termine descritto sotto; grazie a ciò il costo delle chiamate successive non cresce insieme alla lunghezza del romanzo.

Il risultato appare sempre in una finestra di dialogo (da copiare), e uno strumento con il suffisso del file di risultato impostato lo salva inoltre accanto alla narrazione nella cartella skrypty/ (ad es. nazwa_audyt.txt). Prima di sovrascrivere un file di risultato esistente, l'applicazione chiede conferma — ancora prima di spendere un solo centesimo per la chiamata all'IA. Se il materiale per lo strumento supera la finestra di contesto secondo cui l'applicazione misura la memoria (128 mila token), vedrai prima un avviso che chiede se avviare comunque lo strumento. È solo un avviso: i modelli Claude hanno una finestra molto più ampia di questo contatore, ma il tuo provider IA con una finestra più piccola rifiuterà tale richiesta — e per il tentativo pagherai comunque.

L'IA analizzerà l'intera storia e proporrà titoli descrittivi e letterari per ogni capitolo (oltre a un eventuale Prologo ed Epilogo). Memoria a Lungo Termine — riassunto del progetto (dalla v18.13)

Strumento disponibile in entrambe le modalità di salvataggio (Script e Audiolibro). Genera un registro conciso di fatti: svolgimento degli eventi, decisioni dei personaggi e le loro conseguenze, personaggi, luoghi, trame aperte, e alla fine una nota di una frase sullo stile e sul tono della narrazione. Il destinatario di questo testo è il motore narrativo, non il lettore — perciò il riassunto è asciutto e fattuale, senza fronzoli.

Ha una caratteristica che nessun altro strumento possiede: il suo risultato non finisce "accanto" al progetto come un report, ma DIVENTA la Memoria a Lungo Termine — finisce contemporaneamente nel file di memoria nella cartella skrypty/ (il suo nome è dichiarato dalla ricetta dello strumento; nel pacchetto italiano è <nome>_riassunto.txt), nel campo "Memoria a Lungo Termine" del pannello e in un marcatore interno da cui l'applicazione sa fino a dove arriva il riassunto (è questo che permette di riassumere in modo incrementale e che ti chiede un punto di riferimento quando ricarichi il progetto dal disco). Lo strumento si avvia anche automaticamente quando l'indicatore di memoria del modello entra in stato di allarme — vedi PASSO 3.

Il nome del file di memoria è localizzato (dalla v18.14). Ogni pacchetto linguistico dichiara la propria parola nativa nel campo sufiks_pliku_wyniku del file rezyser/postprod_streszczenie.yaml: italiano _riassunto, inglese _overview, tedesco _zusammenfassung, finlandese _yhteenveto e così via. Puoi cambiare il valore nel Gestore Regole con uno tuo qualsiasi (ad es. _memoria) — l'applicazione gestirà la transizione, perché cerca il file di memoria tramite un ELENCO DI CANDIDATI:

  • controlla, uno per uno, i suffissi degli strumenti di memoria del pacchetto della lingua del CONTENUTO del progetto (non della lingua dell'interfaccia — il file appartiene alla storia, non al menu), poi il neutro _overview e infine lo storico _streszczenie;
  • quando trova ESATTAMENTE UN file con un nome diverso da quello attuale, lo rinomina insieme al marcatore interno — non devi fare nulla a mano;
  • quando ne trova PIÙ DI UNO (perché tieni uno strumento di memoria separato «per te» e uno «per l'IA», oppure file dell'epoca di un'altra lingua dell'interfaccia), ti chiede quale debba essere la Memoria a Lungo Termine e non tocca gli altri. Annullare quella domanda significa una sessione senza memoria: il campo resta vuoto, nessun file viene modificato o eliminato e, con una narrazione lunga, l'applicazione ti chiederà di indicare il punto di riferimento della memoria di lavoro.

Scheda di pubblicazione ElevenReader (dalla v18.14)

Lo strumento legge tutto il testo del progetto e compone un insieme di metadati pronto per il modulo di pubblicazione dell'audiolibro su ElevenReader, salvando il risultato nella cartella skrypty/ (nel pacchetto italiano come <nome>_pubblicazione.txt). La scheda contiene: titolo e sottotitolo opzionale, una descrizione fino a 1000 caratteri (limite della piattaforma), uno o due generi presi ESCLUSIVAMENTE dall'elenco canonico delle 22 categorie di ElevenReader, il pubblico di destinazione, l'indicazione dei contenuti per adulti con una frase di motivazione, da due a tre estratti scelti come anteprima gratuita, un prompt pronto per un generatore di immagini di copertina (verticale 1200×1800 px, con spazio per un titolo e un nome dell'autore leggibili) e un promemoria dei campi che nel modulo lasci ai valori predefiniti.

I nomi dei campi nella scheda sono INGLESI (Title:, Description, Genres:, Target audience:, Mature content:, Sample chapters:, ISBN:) — il modulo della piattaforma esiste solo in inglese, quindi li ricopi 1:1. Il contenuto dei campi è nella lingua del tuo progetto, ma anche i VALORI dei campi chiusi (generi, pubblico, il Yes/No dei contenuti per adulti) restano in inglese, perché la piattaforma li accetta solo dal proprio elenco.

Ciò che la scheda non farà al tuo posto: non inventa né l'editore né il numero ISBN — li lascia come campi da compilare a mano (l'ISBN è un numero registrato e un'allucinazione qui sarebbe una falsa dichiarazione editoriale). Il profilo autore è obbligatorio su ElevenReader, perché le pubblicazioni anonime non sono ammesse ed è legato alla dichiarazione sul diritto d'autore — lo strumento ricopierà quindi il nome o lo pseudonimo dal Libro del Mondo e, se non lo trova, inserirà un campo da compilare. Gli estratti per l'anteprima li sceglie SEMPRE, perché il modulo ne richiede almeno uno, indipendentemente dal modello di pagamento che scegli in seguito.

Dopo la generazione l'applicazione controlla la scheda dal proprio lato: se la descrizione rientra nel limite, se generi e pubblico provengono dall'elenco della piattaforma, se i campi obbligatori sono compilati e se nel campo ISBN sono comparse delle cifre. Le discrepanze le mostra come note morbide — il risultato lo ricevi per intero e decidi tu cosa correggere. È una protezione contro il caso in cui il modello inventi una categoria inesistente e il modulo la rifiuti solo alla fine della procedura guidata.

Attenzione: Gli strumenti di post-produzione richiedono che il file di progetto sia già salvato su disco (generato o caricato). Se il file non esiste, l'applicazione visualizzerà un messaggio appropriato.

Modalità 1: Traduttore Normale (Usa AI - A Pagamento)

Ideale per ascoltare storie in una lingua straniera bella e corretta.

  • Carica il file con il pulsante "Carica file in memoria" o utilizzando il pulsante "Sfoglia..." per selezionare il file nella finestra di sistema.
  • Seleziona la modalità "Traduttore AI", inserisci la lingua di destinazione (ad es. "Finlandese").
  • Lo script tradurrà il contenuto. Se carichi un file .html, tradurrà solo il testo visibile al lettore e aggiornerà il codice della lingua nel tag html.
  • Se carichi un normale file .txt o .md (ad es. uno script generato da Regista), lo script salverà automaticamente il risultato come file .html con un tag di lingua incorporato — pronto per essere letto da NVDA senza alcun lavoro aggiuntivo.
  • Supporta anche i file .docx.

Divisione intelligente in blocchi: I testi lunghi vengono automaticamente suddivisi in blocchi misurati in token del modello (non in caratteri) e tradotti sequenzialmente con una barra di avanzamento. In questo modo anche le lingue a scrittura densa, come il cinese o il giapponese, rientrano nel limite di risposta del modello, e una risposta troncata viene rilevata e ritentata automaticamente su frammenti più piccoli.

Salvataggio del progresso resistente ai guasti (NOVITÀ nella versione 9): Ogni blocco tradotto viene immediatamente salvato in un file temporaneo nascosto nella cartella di sistema dell'applicazione. Se la traduzione viene interrotta a causa dell'esaurimento del limite API, al successivo avvio l'applicazione rileverà automaticamente questo file, ripristinerà il progresso già pagato e completerà tranquillamente il lavoro dal punto di interruzione — senza alcuna copia manuale. Al termine con successo, il file temporaneo viene automaticamente eliminato.

Perché è importante? Nella versione 8, l'approccio alla ripresa della traduzione aveva un errore critico e silenzioso: se non si rinominava il file con la traduzione parziale e si tagliava il frammento tradotto secondo le istruzioni, e poi si riprendeva immediatamente la traduzione del resto — l'applicazione apriva il file di output in modalità sovrascrittura. Il progresso pagato veniva cancellato in modo irreversibile e inconsapevole, prima che tu potessi accorgertene. La versione 9 elimina completamente questa trappola: il salvataggio è permanente dopo ogni blocco, indipendentemente da ciò che fai dopo.

Modalità 3: Cifrario (NOVITÀ in 13.0 — giochi di testo, gratuiti, locali)

Il terzo RadioButton in Poliglotta, accanto al Traduttore AI e alla Modalità Regista: "Modalità Cifrario (giochi di testo, distorsione casuale)". Attiva sei algoritmi locali che distorcono il testo — per giochi, enigmi, rompicapi linguistici. Dopo aver selezionato la modalità, appare un menu a tendina con gli algoritmi, e per uno di essi (Cifrario di Cesare) un campo numerico aggiuntivo per lo spostamento.

Algoritmi disponibili (seleziona nel menu "Scegli algoritmo distorsivo"):

  • Invertitore di Testo (Lettura al contrario con lettera maiuscola) — ogni frase viene invertita carattere per carattere, mantenendo il punto/esclamativo/interrogativo alla fine e la lettera maiuscola all'inizio. Prima dell'inversione, lo script espande le abbreviazioni comuni (ad es., ecc., dott., prof., pag. ecc.), in modo che il risultato dopo l'inversione abbia ancora senso — senza questo "ad es." diventa un assurdo ".se da".

Ispirazione: missione dal programma "The Traitors. Traditori". Quando la conduttrice ha mostrato ai partecipanti una popolare canzone polacca di un cartone animato — semplicemente riprodotta al contrario — le reazioni erano del tipo "che lingua è?", "forse armeno", "ungherese o finlandese". La vera missione consisteva nel fatto che una squadra riceveva nel bosco il testo della canzone scritto al contrario, doveva cantarlo in questa forma invertita, l'altra squadra lo registrava, lo riproduceva al contrario — e in teoria recuperava la canzone originale da indovinare. Esattamente lo stesso divertente malinteso fonetico genera il nostro Invertitore, quando fai passare il file elaborato attraverso un sintetizzatore TTS.

  • Tipoglicemia (Centro delle parole mescolato) — classico effetto psicolinguistico: "Non puoi lggeere il toesto in qulasiasi oidrne dlele ltteree, prucché la pmira e l'utlmia ltteera siano al psoto gtisuo". Lo script mescola casualmente il centro di ogni parola più lunga di 4 caratteri, la prima e l'ultima lettera rimangono intatte. Ottimo per il test "quanto vedo davvero e quanto il mio cervello immagina".

  • Telefono Rotto / Dialetto Serpente — ogni "s", "z" o digramma "sz" viene allungato casualmente in un sibilo di lunghezza 4-8 caratteri ("ssssss", "zzzzzz", "ssssssz"). Ispirazione: Snecko dal gioco "Slay the Spire". Effetto: il testo sembra letto da un serpente con un difetto di pronuncia.

  • Vocalizzatore (Tutto rimbomba con "O") — ogni vocale nel testo viene sostituita con "o", comprese quelle accentate. "Buongiorno" → "Boongoorno". Il passaggio delle morbidezze polacche (dzi/ci/ni/si/zi) è volutamente vuoto nel pacchetto italiano: quelle grafie qui non esistono, quindi la regola si riduce al cambio delle vocali. Più lungo è il testo, più divertente è l'effetto (e il lettore di schermo lo legge con piena convinzione).

  • Balbuzie Forte / Robot Danneggiato — aggiunge balbuzie all'inizio delle parole: "c-c-c-computer", "st-st-strada". Per le parole brevi (meno di 3 caratteri) l'algoritmo le ignora. Se la seconda lettera della parola è una consonante, ripete le prime due lettere (effetto più naturale); se è una vocale — ripete solo la prima.

  • Cifrario di Cesare (spostamento dell'alfabeto IT) — classico cifrario sostitutivo: ogni lettera viene spostata di N posizioni nell'alfabeto italiano (ABCDEFGHILMNOPQRSTUVZ, 21 caratteri — senza J, K, W, X, Y). Inserisci il valore dello spostamento nel campo numerico "Spostamento cifrario di Cesare (0 = casuale, intervallo -20…20)". Se inserisci 0 — l'applicazione sceglierà casualmente uno spostamento nell'intervallo 1-20 e lo mostrerà in un messaggio alla fine (così potrai decifrare successivamente). I caratteri al di fuori dell'alfabeto (numeri, punteggiatura, spazi) rimangono invariati.

Applicazione pratica: i cifrari salvano il risultato nello stesso formato della Modalità Regista (.html con tag lang o .docx con tag XML), quindi NVDA li leggerà con la voce della lingua appropriata. In particolare, l'Invertitore e il Vocalizzatore suonano nel sintetizzatore molto più interessanti di quando li leggi con gli occhi — perché il cervello durante la lettura visiva cerca automaticamente di "decodificare" il testo, mentre il TTS lo legge esattamente come è scritto.

Tutti e sei i cifrari sono descritti anche in un linguaggio più ampio e accessibile nel file docs/dictionaries.pl.html nel pacchetto dell'applicazione — insieme a consigli su come aggiungere un proprio cifrario del tipo "sostituzione di lettere" senza conoscenze di programmazione (ad esempio, linguaggio gergale scolastico, linguaggio-trava).

Lingua di elaborazione, forzatura e modalità qualità (NOVITÀ nella 18.11)

La sezione di caricamento file dispone ora di un menu a tendina della lingua di elaborazione. Con questo selettore stabilisci secondo le regole di quale lingua operano le modalità Regista e Cifrante: gli elenchi di accenti e cifrari, nonché l'alfabeto del Cifrario di Cesare insieme all'intervallo di spostamento.

  • La posizione predefinita „Rileva automaticamente" mantiene il comportamento finora in uso: la lingua viene determinata in base al file caricato, e quando differisce dalla lingua dell'applicazione, riceverai una breve notifica che gli elenchi sono stati cambiati.
  • La scelta di una lingua specifica dall'elenco è vincolante — l'applicazione non la modificherà autonomamente durante il caricamento del file.

Sotto l'elenco si trova una casella di selezione che forza la lingua scelta per l'intero documento. Per impostazione predefinita ogni paragrafo viene elaborato secondo la lingua rilevata per quel paragrafo — questa è di norma la scelta migliore, poiché gli inserti in lingua straniera ricevono le proprie, corrette regole. Attiva la forzatura quando ti interessa un'elaborazione uniforme dell'intero testo. Un esempio in cui ciò è necessario: la cifratura multistrato reversibile. L'alfabeto del Cifrario di Cesare ha in ogni lingua una lunghezza diversa, quindi senza la forzatura un testo mistilingue verrà cifrato con diversi alfabeti — e allora la decifrazione richiede di sapere dove passavano i confini tra le lingue. Con la lingua forzata, l'intero documento viene cifrato e decifrato con un unico, medesimo alfabeto. Avvertenza: nelle lingue il cui alfabeto di Cesare contiene lettere diacritiche normalizzate al caricamento (polacco, tedesco), la decifrazione non è del tutto fedele — le lettere diacritiche del crittogramma vengono convertite nelle loro forme base al nuovo caricamento, prima di raggiungere la decifrazione. La reversibilità completa è garantita dagli alfabeti privi di tali caratteri (ad es. l'inglese).

Il Traduttore AI ha invece guadagnato una casella di selezione per la modalità qualità. Una volta selezionata, il modello riceve un budget aggiuntivo per l'analisi interna del testo prima della traduzione (il cosiddetto extended thinking) — la traduzione richiede più tempo e costa più token, ma i passaggi difficili risultano più curati. L'opzione funziona esclusivamente con i modelli Anthropic Claude; se utilizzi un fornitore alternativo tramite un endpoint compatibile con OpenAI, la selezione non ha alcun effetto.

Un dettaglio correlato: i caratteri con macron usati nella romanizzazione giapponese (ad es. Tōkyō, rāmen, jūdō) vengono da questa versione normalizzati come gli altri segni diacritici stranieri — nella maggior parte delle lingue nella lettera semplice (Tokyo), mentre nel pacchetto finlandese tramite raddoppio della vocale (Tookyoo), secondo la convenzione finlandese di trascrizione dei suoni lunghi. Grazie a ciò non escono più dall'alfabeto del Cifrario di Cesare come caratteri in chiaro nel crittogramma.

Rilevamento della lingua

Prima che lo script "rovini" il testo, verifica in quale lingua è scritto. Se rileva che non è polacco, visualizzerà un avviso. Le regole fonetiche sono progettate per il polacco — applicarle a un testo in lingua straniera darebbe risultati imprevedibili.

Killer Feature per non vedenti: File con tag di lingua

Questa è una vera rivoluzione. I file elaborati ora si salvano come:

  • .html con attributo lang (ad esempio, lang="fi" per il finlandese) — NVDA legge questo tag e cambia automaticamente la voce al sintetizzatore linguistico appropriato. Zero configurazione manuale!
  • .docx mantenendo la formattazione — ogni run di testo ha un tag di lingua iniettato nell'XML del documento, quindi Word e NVDA sanno con quale voce leggere ogni frammento.

I file elaborati si salvano sempre come NUOVI documenti (ad esempio, accento_Finski.html).

Automatica commutazione della lingua in NVDA — cosa devi sapere

Affinché NVDA commuti effettivamente la voce in base al tag lang, l'impostazione "Cambia automaticamente la lingua quando supportata" deve essere attivata. La troverai in Preferenze NVDA → Voce. Di default è attivata al primo avvio del lettore — ma vale la pena controllare se qualcuno l'ha disattivata.

Importante limitazione delle voci OneCore: Le voci Microsoft OneCore non supportano nativamente questo meccanismo con NVDA, ma solo con il narratore integrato di Windows. Esiste un componente aggiuntivo non ufficiale per NVDA chiamato "One Core Autolang", che tenta di risolvere questo problema — ma il suo sviluppo è stato rapidamente interrotto. La causa è semplice: ogni anno, con la prima versione di NVDA dell'anno, si verificano cambiamenti che rompono la compatibilità dell'API (i cosiddetti API Breaking Changes). A volte basta aggiornare il campo "last tested version" nel manifesto del componente aggiuntivo, ma a volte sono necessarie vere modifiche nel codice — e l'autore non riesce a tenere il passo con gli aggiornamenti. Se tieni all'automatica commutazione della lingua, una scelta più sicura sono le voci Tiflotecnia (a pagamento, sezione sopra) o eSpeak (gratuito, qualità inferiore), che supportano questo meccanismo nativamente — ma attenzione: attualmente nelle voci Tiflotecnia funziona con un errore di priorità (vedi "Critico inghippo" sotto). Dopo aver applicato la patch, la commutazione automatica funziona perfettamente, come nel vecchio Vocalizer.

Problema critico Tiflotecnia Voices: rilevamento della lingua difettoso

Prima la buona notizia — l'allarme su NVDA 2026.1 delle versioni precedenti del manuale si è concluso con un lieto fine: Cerrence ha fornito librerie a 64 bit, Tiflotecnia le ha rilasciate in un pacchetto .nvda-addon disponibile nel Add-on Store (sezione sopra), e Vocalizer per coloro che lo hanno mantenuto fino alla fine è tornato con un nuovo nome — con una qualità migliore e senza le limitazioni a 32 bit.

Con il lancio di Tiflotecnia Voices è emerso però un nuovo problema critico — nel rilevamento della lingua. Nelle impostazioni dell'add-on è possibile configurare quale voce deve essere utilizzata per determinati caratteri (ad esempio latini, cirillici) a seconda delle voci installate. Il problema sta nella priorità degli ordini: attualmente si applica prima l'override per carattere, poi il fallback al codice ISO della lingua (in pratica irraggiungibile per lo STESSO alfabeto a cui si è già adattato l'override), infine la voce selezionata. Il risultato si manifesta all'interno dello stesso alfabeto: hai un testo in finlandese con il tag corretto lang="fi", installato Satu come voce finlandese di Tiflotecnia, MA nelle impostazioni è impostata una voce polacca per i caratteri latini — Satu NON leggerà questo testo, nonostante il tag ISO corretto. L'override per carattere "voce polacca per il latino" vince al primo livello, l'ISO fi non viene mai verificato. Per le coppie di alfabeti diversi il meccanismo funziona correttamente (testo russo + Milena per il cirillico + voce polacca per il latino — tutto il cirillico va con Milena, eventuali nomi propri latini con la voce polacca; ogni alfabeto sta nel proprio override). Dopo la migrazione da Vocalizer, in cui il cambio di lingua basato su ISO funzionava perfettamente, gli utenti noteranno subito questa regressione — specialmente quelli che in Poliglotta usano diversi accenti europei (Satu, Alice, Markus) sulla stessa gamma di caratteri latini.

Diagnosi e patch: ho diagnosticato il problema a livello di Python nel codice dell'add-on e ho preparato una patch che cambia l'ordine delle priorità in: ISO → voce selezionata → override per carattere. La patch mantiene l'utile passaggio al latino per i nomi latini nel testo russo, quando nelle impostazioni è attivato il "rilevamento della lingua basato sui caratteri Unicode". Ho inviato la patch agli sviluppatori di Tiflotecnia — finora senza risposta, quindi molto probabilmente rimangono alla loro soluzione. Se l'add-on riceve un aggiornamento, aggiornerò la patch se necessario.

Cosa fare nel frattempo: se ti interessa il corretto rilevamento della lingua (vale la pena — era una delle killer features del vecchio Vocalizer, vedi "Killer Feature per i non vedenti" sopra), apri un issue nel repository dell'applicazione su GitHub con l'etichetta tiflotecnia-patch e l'indirizzo email nel contenuto. Vale la pena aggiungere una breve descrizione del problema nella tua lingua (bastano 2–3 frasi) — il bot riconoscerà la lingua (supportate: polacco, inglese, tedesco, spagnolo, finlandese, francese, islandese, italiano, russo) e risponderà nella stessa; senza descrizione o in un'altra lingua, la risposta arriverà in inglese. Un bot automatico chiuderà immediatamente l'issue con la conferma della segnalazione (senza traccia nel thread pubblico), e riceverai la patch privatamente via email di solito entro pochi giorni. La patch NON è pubblicata nel repository dell'applicazione né come Gist — Tiflotecnia Voices for NVDA è un software commerciale e la licenza dell'add-on non consente la ridistribuzione dei suoi file, anche se modificati. Dopo aver ricevuto la patch, il suo contenuto deve essere copiato in %appdata%\Roaming\nvda\addons\TiflotecniaVoices, sostituendo i file. Attenzione durante la copia: se Windows non ha chiesto di sostituire, probabilmente hai copiato l'intera cartella TiflotecniaVoices_edits con il suo contenuto INVECE del solo contenuto — in tal caso entra nella sottocartella creata, taglia tutto, incolla un livello più in alto e sovrascrivi. Dopo aver applicato correttamente la patch, riavvia NVDA — goditi la migliore qualità delle voci Cerrence a 64 bit e il corretto rilevamento della lingua, ovvero una combinazione che nessun singolo produttore sul mercato può offrire. Supponiamo ovviamente che tu abbia una licenza valida per Tiflotecnia Voices — non lo verifichiamo, ma senza licenza non potrai applicare la patch su una cartella altrui.

PASSO 6: Architetto di Audiolibri

Strumento per preparare la struttura professionale del file per i lettori di schermo e ElevenLabs. Accedici cliccando il pulsante "📄 Convertitore" nella barra dei pulsanti oppure selezionando Strumenti → Convertitore dal menu (scorciatoia: Ctrl+3).

Come funziona?

  1. Inserisci il percorso del file sorgente nel campo di testo oppure clicca il pulsante "Sfoglia..." per selezionare il file nella finestra di dialogo di sistema. Lo script accetta sia .txt che .docx, nonché file .html e .htm.
  2. Clicca "Costruisci Architettura per ElevenLabs".
  3. Lo script analizzerà ogni riga del testo e convertirà le parole chiave (Atto, Capitolo, Prologo, Epilogo, Introduzione) in intestazioni "Heading 1" nel documento Word.
  4. Le scene (righe che iniziano con la parola "Scena") diventano testo in grassetto — visibili nel documento, ma non visibili nel sommario di ElevenLabs.
  5. Tutto il testo rimanente (dialoghi, descrizioni) passa invariato.
  6. Riceverai il file architettura_[nazwa_oryginału].docx — un Word professionale pronto per ulteriori elaborazioni. Ad esempio, se il tuo file di input si chiamava znieczulica.txt, il file risultante avrà il nome architettura_znieczulica.docx e apparirà nella stessa cartella dell'originale.

Pulizia contestuale: Lo script rimuove automaticamente i tag HTML (se il testo proviene da un browser o da un file .html locale, ad esempio generato da Poliglotta) e i marcatori di intestazione Markdown (es. ### o ####) prima dell'elaborazione. Non è necessario pulire il file manualmente.

Modalità Racconto: raggruppamento automatico dei turni in scene (dalla v15.1)

Se carichi nell'Architetto un file opowiesci/<gra>.txt generato dal modulo dei Racconti Interattivi, il convertitore riconoscerà i marcatori di turno (es. "--- Tura 7 ---" — anche nelle altre lingue supportate, se hai giocato in un'altra lingua) e ogni cinque turni inserirà una nuova intestazione di primo livello "Scena N" (la numerazione parte da 1, nella lingua del tuo gioco). I restanti marcatori di turno vengono eliminati — non compaiono nella narrazione dell'audiolibro, perché "Tura 7" pronunciata dal TTS rompe l'immersione dell'ascoltatore. Il risultato è un file Word con una suddivisione naturale in scene di qualche minuto audio ciascuna, pronto per l'importazione in ElevenLabs. Il meccanismo è auto-rilevante — i normali file di audiolibri senza marcatori di turno (narrazione classica da Regista) vengono elaborati esattamente come in precedenza.

Potente vantaggio per gli utenti di NVDA e ElevenLabs

La formattazione "Heading 1" per i capitoli non è solo estetica. In NVDA puoi navigare tra le intestazioni in modo fulmineo premendo il tasto H (o 1 per le intestazioni di primo livello). Invece di scorrere centinaia di pagine, salti da un capitolo all'altro in una frazione di secondo. Questo cambia il modo di lavorare con i documenti lunghi. In ElevenLabs hai la certezza che il motore inserirà automaticamente i tagli e non si bloccherà durante la regia delle clip audio.

PASSO 7: Come scrivere il Libro del Mondo (Prompt dell'Architetto e Mini-corso Markdown)

L'intelligenza artificiale che alimenta lo Studio Principale comprende meglio i comandi quando sono formattati nel linguaggio di markup Markdown. Se fornisci all'IA nel Regista solo un'idea vaga (ad es. "due sorelle nell'aldilà"), la macchina andrà nel panico per mancanza di dettagli e creerà una storia banale e prevedibile, ignorando la logica.

Per evitarlo, usa un chatbot esterno (ad es. il gratuito ChatGPT o Claude) come tuo Architetto personale. Nella versione 13.0 non devi più ricopiare il prompt dalle istruzioni — nel pannello del Regista, appena sotto il pulsante "💾 Salva il Libro in modo permanente", troverai il pulsante "📖 Prompt dell'Architetto per AI…". Cliccaci sopra e si aprirà una finestra di dialogo con il testo del prompt già pronto nel campo "sola lettura" e un pulsante "Copia negli appunti". NVDA annuncia l'intero contenuto non appena la finestra si apre — basta cliccare "Copia", incollare (Ctrl+V) in ChatGPT/Claude e sostituire il frammento "[INSERISCI QUI LA TUA IDEA]" con il proprio seme narrativo.

Perché in questo modo e non copiando dalle istruzioni? La finestra di dialogo nella GUI ha un vantaggio fondamentale in termini di accessibilità: è nativa e viene letta senza interferenze dal lettore di schermo, non richiede di passare a un editor di testo (dove le lettere accentate polacche e le virgolette vengono talvolta copiate in modo errato) e funziona in modo identico su qualsiasi sistema operativo. Lo stesso schema — finestra di dialogo con prompt da copiare — viene utilizzato anche nel Manager delle Regole (vedi PASSO 7b di seguito).

Come risponde l'IA: Nella risposta riceverai un testo in due parti. La prima è il Libro del Mondo racchiuso in un blocco di codice Markdown (marcatori markdown …). Copia ESCLUSIVAMENTE il contenuto del blocco di codice (senza i marcatori ``` stessi) e incollalo nel campo "Libro del Mondo" nel Regista, quindi clicca "💾 Salva il Libro in modo permanente". La seconda parte è una raccomandazione su quale delle modalità creative (Sceneggiatura o Audiolibro) si adatti meglio alla tua idea — considerala come un suggerimento quando selezioni la modalità nel campo di scelta della modalità.

Mini-corso Markdown nel Libro: un singolo cancelletto (#) indica la sezione principale (ad es. "# Personaggi"), il doppio cancelletto (##) indica una sottosezione, i trattini (-) creano elenchi, mentre il doppio asterisco (testo) mette in grassetto le regole assolute e inviolabili (ad es. "Il Protagonista NON mente MAI"). Per un personaggio di lingua straniera aggiungi il tag con l'accento, ad es. "[Speaker 1: Marek] - ha accento francese". La parola chiave "accento" è NECESSARIA — il motore dell'applicazione la rileva automaticamente e applica le corrette regole fonetiche ai dialoghi di quel personaggio.

Suggerimento: Ricorda di aggiornare di tanto in tanto il tuo Libro del Mondo (man mano che la trama si arricchisce di nuovi luoghi o personaggi importanti). Puoi farlo manualmente o con l'aiuto di un chatbot esterno. Più ricca è la base, migliori saranno i risultati nella Regia!

PASSO 7b: Gestore Regole (Ctrl+4) — dizionari per linguisti senza Python

La versione 13.0 introduce il quarto strumento nella barra: il Gestore Regole. Lo apri con il tasto Ctrl+4 o dal menu Strumenti. È un esploratore visivo della cartella dictionaries/, dove l'applicazione conserva tutte le regole fonetiche (accenti), cifrari e modalità del Regista in file YAML (formato leggibile dall'uomo, più semplice di JSON).

Perché YAML? Fino alla versione 12.0 tutti gli accenti, le modalità creative e i filtri erano "incorporati" nel codice Python. Aggiungere un nuovo accento richiedeva un programmatore. Nella versione 13.0 tutto è stato spostato nei file .yaml nella cartella dictionaries/ — chiunque sappia aprire il Blocco Note può regolare un accento esistente ("sostituisci sz con sh con sch") o aggiungerne uno completamente nuovo (svedese, danese, dialetto russo).

Cosa troverai nel Gestore Regole:
- Albero dei file — elenco completo di tutti i file YAML in dictionaries/ suddivisi per lingue di base (attualmente completamente implementate: Polski, Deutsch, English, Español, Suomi, Français, Íslenska, Italiano, Русский) e cinque categorie: akcenty/ (fonetica per TTS), szyfry/ (giochi di testo), rezyser/ (modalità creative e post-produzione), gui/ (traduzioni UI) e opowiesci/ (modalità del modulo Racconti, aggiunte nella 15.2.4). Navigazione con le frecce come in Esplora file di Windows, pieno supporto NVDA.
- Pulsante „📝 Apri nell'editor di testo" — apre il file selezionato nel Blocco Note predefinito del sistema. Modifichi, salvi, clicchi „🔄 Aggiorna albero" ed è fatto.
- Pulsante „📋 Duplica file selezionato" — la via più veloce per un nuovo accento: prendi un file esistente (ad es. finski.yaml), dai un nuovo nome (ad es. svedese), il Gestore crea una copia con il commento "cambia i campi etichetta e descrizione" e lo apre nell'editor.
- Pulsante „➕ Nuovo file regole…" — creatore con scelta del tipo (accento, cifrario, modalità Regista, nuova lingua di base, cifrario algoritmico). Per i casi comuni (accento, cifrario tipo "sostituzione lettere") il creatore genera un modello YAML pronto per la modifica. Per i casi che richiedono un programmatore (nuova lingua di base, algoritmo tipo "mescolamento del centro delle parole") il creatore genera un prompt per il chatbot AI — lo incolli in ChatGPT, ottieni un file YAML pronto, lo salvi in dictionaries/ ed è fatto.

Applicazione pratica: Vuoi aggiungere un accento svedese? Apri il Gestore Regole, scegli dictionaries/pl/accenti/finski.yaml, clicca "Duplica", nomina il file svedese, cambia nel campo etichetta in "Svedese (Alva / Oskar)", il codice iso in sv, modifica alcune regole di sostituzione e salva. Torna alla Pagina principale e riavvia l'applicazione. Il nuovo accento apparirà nel menu Poliglotta (in Modalità Regista) e — se lo aggiungi al Libro del Mondo dei personaggi ("[Marek] - ha accento svedese") — anche nel rilevamento automatico degli accenti del Regista.

Dove cercare ulteriore documentazione della cartella dictionaries/:
- File docs/dictionaries.pl.html (disponibile nel pacchetto per gli utenti finali dalla scheda Releases) — breve descrizione in linguaggio semplice di ogni sottocartella, 6 cifrari pronti, 8 accenti pronti e idee su cosa si può fare da soli, senza conoscenza di Python.
- File dictionaries/README.md (disponibile solo clonando il repository da GitHub — i pacchetti di rilascio filtrano i file .md) — documentazione tecnica dettagliata del formato YAML con esempi, elenchi di campi, regole del pipeline, regex. Questo documento è indirizzato a linguisti con conoscenze di base di programmazione e a sviluppatori.

Indicazioni importanti per gli utenti dei lettori di schermo (NVDA)

1. Messaggi di successo ed errore

Quando l'applicazione termina un'operazione (ad es. salva un file o incontra un errore), comparirà una finestra di dialogo con un titolo come "Successo", "Avviso" o "Errore". NVDA annuncerà subito la finestra e ne leggerà il contenuto. Non devi fare nulla — le finestre di dialogo sono pienamente accessibili da tastiera e il focus atterra automaticamente sul pulsante "OK". Non ci sono più trucchi con il prefisso "Alert" — le finestre di dialogo native di wxPython sono gestite direttamente dal lettore di schermo.

2. Avviso importante: elaborazione silenziosa in background

Dopo aver cliccato pulsanti come "Invia all'AI" o "Avvia Elaborazione", il programma avvia immediatamente l'elaborazione in background. Sullo schermo appare una barra di avanzamento (Gauge), ma NVDA NON ne legge il valore in tempo reale — il lettore di schermo resta in silenzio durante il lavoro. Non cliccare di nuovo il pulsante. Attendi finché non compare la finestra di dialogo con il risultato o con il messaggio di errore — NVDA la annuncerà automaticamente.

3. Navigazione tra gli strumenti

Lo spostamento tra gli strumenti (Regista, Poliglotta, Convertitore, Gestore Regole) avviene in un'unica finestra del programma tramite quattro pulsanti sulla barra degli strumenti o tramite il menu Strumenti (Alt, poi N). Scorciatoie da tastiera disponibili: Ctrl+0 (Pagina iniziale), Ctrl+1 (Regista), Ctrl+2 (Poliglotta), Ctrl+3 (Convertitore), Ctrl+4 (Gestore Regole — novità nella 13.0). Dopo aver cambiato strumento il focus atterra automaticamente sulla descrizione del nuovo modulo — NVDA inizia subito a leggere la nuova vista.

4. Ordine di tabulazione e nomi dei widget

Ogni elemento dell'interfaccia ha un nome chiaro in italiano — NVDA lo leggerà al momento del focus. L'ordine di tabulazione è logico: dalla descrizione dello strumento, attraverso i campi di configurazione, fino ai pulsanti d'azione. Non ci sono sorprese — la navigazione da tastiera funziona come in qualsiasi altro programma nativo di Windows. Tutti i menu e i pulsanti sono in italiano e NVDA li leggerà con una voce italiana senza alcuna impostazione aggiuntiva.

I file di testo (.txt e .md) tradotti dal Traduttore AI vengono ora salvati automaticamente in formato .html con un tag di lingua incorporato. In questo modo NVDA legge subito il file con la voce corretta — senza alcun passaggio aggiuntivo da parte dell'utente.

Funzionalità mantenute senza modifiche dalla versione 8

I file di progetto e i riassunti vengono ora salvati in formato .txt invece di .md (Markdown). L'esperimento con il formato .md come barriera psicologica contro la modifica si è rivelato inefficace — l'IA infrange spesso e notoriamente la regola anti-closure, ed è spesso meglio modificare il file al volo e poi ricaricare la memoria affinché l'IA, per quanto possibile, non riceva un permesso nascosto di violare il divieto. Il formato .txt è più intuitivo e leggibile per tutti.

Regola del Montatore — nuovo avviso
Nelle istruzioni (e nelle future versioni dell'interfaccia) è stato aggiunto un avviso chiaro che spiega cosa si può e cosa non si può modificare nei file di progetto. L'utente ha pieno diritto di modificare dialoghi e contenuti, ma non può assolutamente modificare le righe di struttura (Atto, Scena, Capitolo, Prologo, Epilogo) — il loro danneggiamento rovina la navigazione di NVDA, la suddivisione in ElevenLabs e l'indice in Word.

Prompt dell'Architetto aggiornato (MODIFICA)
Il prompt per il chatbot esterno (ChatGPT/Claude) è stato riprogettato. Invece di restituire codice Markdown grezzo, l'IA ora restituisce la risposta in due parti chiaramente separate: la Parte 1 è il Libro del Mondo racchiuso in un blocco di codice Markdown (facile da copiare senza marcatori), e la Parte 2 è la Raccomandazione di Modalità come testo semplice fuori dal blocco — consiglia se sia meglio usare la Modalità Script Grezzo o la Modalità Audiobook Tradizionale. È stata cambiata anche la descrizione dei tag dei personaggi: invece di "sonori", ora si parla di accento e tono di voce nel tag, ad es. [Speaker 1: Nome] - blesa e accento francese.

Invece di nascondere questo problema, la versione 8 mette le cose in chiaro e restituisce la responsabilità della "chiusura manuale" al Regista — da qui la Regola del Montatore come strumento di lavoro ufficiale e il ritorno al normale formato testo.

PASSO 7b (completamento): L'ordine delle regole zamiany: è importante

I file in dictionaries/<kod>/akcenty/*.yaml contengono un elenco di regole zamiany: — coppie wzor → zamiana, che il motore applica SEQUENZIALMENTE. Ogni regola successiva opera sull'output della precedente. Questo permette di costruire pipeline del tipo "scomponi il digramma szcz in shch, e poi sostituisci ch con h", ma apre anche la classica trappola per l'autore del pacchetto linguistico.

La trappola del "ciclo sequenziale". Supponiamo che per l'accento spagnolo, che deve far somigliare la pronuncia polacca di "ñ" a quella di Diego (Loquendo), l'autore aggiunga due regole:
1. ñ → nj (per far suonare la "ñ" polacca come una morbida "nj")
2. j → x (per far suonare la "j" polacca come la "j" spagnola — foneticamente /x/)

Dopo l'esecuzione, si scopre che le parole con "ñ" vengono pronunciate come "nx", non "nj". Perché? Perché quando la prima regola sostituisce "ñ" con "nj", la nuova "j" viene immediatamente catturata dalla seconda regola e sostituita con "x". Risultato: invece del previsto "ñ → nj", otteniamo "ñ → nx".

Regola dell'ordine (universale). Quando una regola introduce un carattere che un'altra regola ha come modello, L'ORDINE CONTA. Un'euristica sicura: PRIMA sostituisci il TARGET (carattere usato successivamente come wzor in un'altra regola) con qualcosa di sicuro, POI introduci il SOURCE (carattere che deve scomporsi nel TARGET). Per l'esempio spagnolo correttamente: prima j → x, poi ñ → nj. Risultato: "ñ" diventa "nj" (la seconda "j" non verrà più catturata, perché la regola j → x è stata applicata prima, quando "nj" non esisteva ancora).

Come testare. Dopo aver cambiato l'ordine delle regole nel file dell'accento, passa una frase contenente ENTRAMBI i caratteri attraverso il Modalità Regista. Per esempio ES: "Niño de paja juega" → il risultato deve avere sia l'accento ñ ("ñ → nj"), sia l'accento j ("j → x"), quindi qualcosa come "Ninjo de paxa xuega". Se vedi "ninxo" invece di "ninjo" — l'ordine è invertito.

Validazione nel motore (opt-in per gli autori dei pacchetti). L'applicazione ha un'euristica incorporata che rileva potenziali cicli, ma è disattivata per impostazione predefinita — perché molte pipeline sembrano cicli, anche se sono intenzionali (il classico "szcz → shch" + "ch → h"). Per attivarla: imposta la variabile d'ambiente REZYSER_VALIDATE_ZAMIANY=1 e avvia l'applicazione dalla console — dalla sorgente tramite python main.py, perché l'eseguibile congelato .exe in modalità finestra (dalla versione 17.0) non ha una finestra console. Il motore stamperà per ogni file di accenti una riga aggregata WARN con i primi tre potenziali cicli e il numero degli altri. Controlla la fonetica risultante sulla frase di test — se l'effetto è quello desiderato, ignora il WARN.

I pulsanti per spostare le regole nel GUI del Gestore Regole (drag-and-drop, "Su / Giù") sono una funzione separata pianificata per un ciclo di versione successivo — richiede una riprogettazione del Gestore (attualmente delega l'editing del file a un Blocco Note esterno di sistema, e non ha una propria vista delle regole). Fino alla sua implementazione: modifica manualmente il file YAML, sposta le righe nella sezione zamiany:, utilizza il validatore tramite ENV-var e testa su frasi di controllo.
