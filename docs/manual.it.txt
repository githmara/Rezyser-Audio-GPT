Manuale del Regista Audio AI - Guida completa (Versione 17.5.0 – Versione di Pubblicazione)

Benvenuto nello Studio di Registrazione Ibrido! Questo set di strumenti consente la scrittura automatica, la pianificazione, la formattazione e la traduzione di script per audiodrammi e audiolibri. È stato ottimizzato per lavorare con sintetizzatori vocali professionali e motori di lettura dello schermo locali (NVDA).

Il set è composto dallo studio principale (Regia), dallo strumento per traduzioni e accenti (Poliglotta), dallo strumento per la costruzione della struttura del file (Architetto Audiolibri), dal Gestore delle Regole (dalla versione 13.0 — senza Python puoi aggiungere un nuovo accento, cifra o modalità creativa, vedi PASSO 7b sotto) e — dalla versione 15.0 — dal modulo Storie (finzione interattiva in seconda persona generata da AI, letta da TTS o lettore dello schermo, descritta nel manuale separato opowiesci.pl.txt). Tutti e cinque gli strumenti sono disponibili in un'unica finestra del programma, commutabile tramite pulsanti sulla barra o scorciatoie da tastiera Ctrl+1..Ctrl+5.


PASSO 1: Primo avvio (Cross-Platform)

Scarica l'ultima versione dell'installer dalla scheda Releases su GitHub (file Rezyser_Audio_v<numer>_Installer.exe) e avvialo con un doppio clic. L'installer proporrà una posizione di installazione predefinita — la cartella Programs nella directory locale del tuo account — e non richiede privilegi di amministratore. Puoi scegliere il tuo percorso con il pulsante "Sfoglia"; in tal caso RICORDALO (sarà utile per gli aggiornamenti — vedi "Aggiornamenti automatici" sotto). Dopo l'installazione, avvia il programma con l'icona sul desktop o dal Menu Start. Dopo un momento apparirà la finestra principale del programma — Regista Audio GPT. Dalla versione 17.0, l'applicazione è congelata come file eseguibile nativo in modalità finestra, quindi non lampeggia più alcuna finestra del terminale e si avvia più rapidamente di prima. Nessun browser, nessun server in background. Quando hai finito di lavorare, chiudi semplicemente la finestra del programma.

L'intera applicazione, incluso il motore Python, i progetti e la chiave API, vive in una cartella sotto il percorso di installazione — l'intera cartella può essere trasferita su una chiavetta USB, nel cloud o su un altro computer (istruzioni dettagliate nella sezione "Trasferimento progetti e chiave API" sotto).


Importante: La cartella runtime/ all'interno della cartella di installazione è il bundle di PyInstaller (dalla versione 17.0) — contiene un interprete Python isolato e librerie, pronte per l'uso senza installazione separata di sistema; funge anche da contenitore per i metadati nascosti dei progetti. Se cloni il repository (percorso sviluppatore), questa cartella non c'è e non dovrebbe esserci — usi allora l'ambiente virtuale venv descritto nella sezione per sviluppatori sotto.

--- Per Sviluppatori (Windows — repository Git) ---

1. Clona il repository sul tuo disco.
2. Esegui il file setup_dev.bat. Lo script creerà automaticamente un ambiente virtuale Python (venv) e installerà tutte le dipendenze richieste dal file requirements.txt.
3. Avvia l'applicazione con il comando python main.py o tramite il file run_dev.bat — lo script rileverà automaticamente la cartella venv e avvierà il programma.

--- Per Sviluppatori e utenti comuni (macOS / Linux) ---

1. Clona il repository sul tuo disco.
2. Apri il terminale nella cartella del progetto e assegna i permessi di esecuzione agli script: chmod +x *.sh
3. Esegui lo script di configurazione: ./setup_dev.sh — lo script creerà l'ambiente venv e installerà le dipendenze.
4. Avvia l'applicazione: python main.py o ./run.sh


Cosa vedrai all'avvio: All'avvio del programma si apre una finestra con la schermata iniziale. Troverai una breve descrizione degli strumenti disponibili e una sezione "Controllo del Sistema". Se la chiave API non è ancora configurata, vedrai un messaggio rosso che informa che i moduli basati su AI (Regia, Traduttore) non funzioneranno — le funzioni locali gratuite (accenti, Architetto) sono però attive immediatamente. La configurazione della chiave è descritta nel passo successivo.


Aggiornamenti automatici

L'applicazione verifica all'avvio se è disponibile una nuova versione su GitHub — la verifica avviene in background e non blocca l'interfaccia.

Se hai installato il programma tramite il file dell'installer (.exe): al rilevamento di una nuova versione apparirà una finestra che chiede se scaricarla. Dopo la conferma, verrà avviata una barra di avanzamento e, al termine del download, l'applicazione si chiuderà automaticamente e il nuovo installer si avvierà automaticamente. IMPORTANTE: nella finestra del nuovo installer assicurati che il percorso di installazione proposto sia LO STESSO della prima installazione (di solito visibile nel campo "Cartella di destinazione"). Se accetti la proposta predefinita e inizialmente hai scelto un'altra posizione con il pulsante "Sfoglia", otterrai UNA SECONDA installazione vuota senza i tuoi progetti e la chiave API — la prima rimane ancora nel vecchio posto, ma il collegamento sul desktop e dal Menu Start verrà sostituito con quello nuovo. Se accetti lo stesso percorso di prima, l'installer sovrascrive i file del motore dell'applicazione e l'intero pacchetto di regole (cartella dictionaries/) — i tuoi progetti (cartelle skrypty/, opowiesci/) e la chiave API (golden_key.env) rimangono intatti. IMPORTANTE: se hai modificato tramite il Manager delle Regole i file esistenti nel pacchetto (ad es. cambiamenti di accento in `dictionaries/pl/akcenty/wloski.yaml`), queste modifiche SARANNO SOVRASCRITTE durante l'aggiornamento — prima di confermare l'aggiornamento fai un backup della cartella `dictionaries/` secondo la procedura nella sezione "Trasferimento progetti e chiave API" sotto (basta copiare la cartella `dictionaries/` su una chiavetta USB), e dopo l'aggiornamento ricaricala sovrascrivendo i file più recenti. Le regole completamente nuove che hai creato da zero e che non sono nel pacchetto (ad es. una lingua di base aggiuntiva o un tuo cifrario) rimangono automaticamente intatte — l'installer non rimuove file al di fuori del pacchetto. Dalla versione 15.2.8 lo stesso dialogo che propone l'aggiornamento visualizza questo avviso direttamente nel contenuto e include un pulsante "Apri cartella dictionaries" che con un clic apre Esplora file nel posto giusto — basta premerlo prima di confermare l'aggiornamento per fare comodamente un backup, e poi tornare al dialogo e cliccare "Scarica e installa".

Se non ricordi il tuo percorso di installazione, ci sono due modi rapidi per recuperarlo. Windows 11: nel menu contestuale del collegamento sul desktop seleziona "Apri percorso file" (se l'opzione non è visibile nel nuovo menu contestuale semplificato, seleziona prima "Mostra più opzioni" o premi Shift+F10 due volte per aprire immediatamente il menu completo), vai un livello più in alto con il tasto Backspace, seleziona la cartella con l'applicazione e premi Ctrl+Shift+C (o seleziona "Copia come percorso" dal menu contestuale) — il percorso completo verrà copiato negli appunti tra virgolette (incollando nell'installer ricorda di rimuovere le virgolette stesse). Versioni precedenti di Windows (7/8/10): fai clic con il tasto destro sul collegamento e seleziona "Proprietà"; nella scheda "Collegamento" nel campo "Destinazione" vedrai il percorso completo del file di avvio (`.exe` nella versione 15.2.5+ o `run.bat` nelle versioni precedenti) — copialo e rimuovi il nome del file finale, rimarrà solo il percorso della cartella di installazione.

Nota per l'aggiornamento da versioni precedenti (v15.2.4 o precedenti, quando l'applicazione veniva avviata tramite `run.bat` dal pacchetto Portable ZIP): il collegamento esistente sul desktop potrebbe puntare a `run.bat` nella vecchia posizione, che dopo l'aggiornamento alla v15.2.5+ non c'è più — le versioni 15.2.5+ usano un file `.exe` autonomo creato dall'installer. Se dopo l'aggiornamento il collegamento smette di funzionare, eliminalo manualmente e lascia che l'installer ne crei uno nuovo durante la reinstallazione.

Se utilizzi il repository Git (sviluppatori e utenti macOS/Linux): invece della proposta di download vedrai un'informazione sulla nuova versione con un link diretto alla pagina di rilascio su GitHub. Scarica da lì l'archivio "Source code" o aggiorna il repository con il comando git pull.

Trasferimento progetti e chiave API (migrazione)

Se desideri trasferire i tuoi progetti, la chiave API e le impostazioni locali su un altro computer (o ripristinare tutto dopo aver reinstallato Windows), non è necessario copiare manualmente singoli file — l'intera cartella dell'applicazione è autosufficiente.

1. Assicurati che l'applicazione sia COMPLETAMENTE chiusa. Se vedi l'icona del programma nel vassoio di sistema (accanto all'orologio, sul lato destro della barra delle applicazioni), fai clic con il tasto destro e seleziona "Chiudi". I file aperti bloccano la copia.
2. Trova il collegamento Regista Audio GPT sul desktop. Fai clic con il tasto destro (o con il tasto Applicazioni o Shift+F10 durante la navigazione NVDA) e seleziona l'opzione "Apri percorso file". ATTENZIONE su Windows 11: nel nuovo menu contestuale semplificato questa opzione potrebbe essere nascosta — seleziona prima "Mostra più opzioni" (o premi Shift+F10 due volte per aprire immediatamente il menu completo con l'opzione).
3. Si aprirà una finestra di Esplora risorse di Windows nella cartella di installazione del programma. Premi il tasto Backspace (il modo più semplice, funziona sempre) o fai clic sulla freccia "Su" nella barra degli strumenti per andare un livello più in alto — vedrai lì l'intera cartella con l'applicazione. Nota: la scorciatoia Alt+Freccia su funziona solo quando il focus è sulla lista dei file — se Esplora risorse si è aperto con il focus sulla barra degli indirizzi (tipico), Alt+Freccia su non farà nulla, usa allora Backspace.
4. Copia l'intera cartella su una chiavetta USB, un disco nel cloud (OneDrive, Google Drive, Dropbox) o un disco esterno. La cartella contiene tutto ciò che serve per ripristinare lo stato di lavoro:
   - I tuoi progetti (cartella skrypty/ — file .txt di narrazione, .md del Libro del Mondo, _streszczenie.txt; cartella opowiesci/ — giochi interattivi).
   - La chiave API (file golden_key.env nella cartella principale dell'applicazione).
   - Le tue regole fonetiche, accenti, cifrari, se hai modificato qualcosa nel Manager delle Regole (cartella dictionaries/<codice_lingua>/, ad es. dictionaries/pl/akcenty/wloski.yaml).
   - Preferenze dell'applicazione e scelta delle modalità creative (cartella runtime/skrypty/, file .mode).
   - Ambiente Python isolato (cartella runtime/), quindi non devi installare nulla sul nuovo computer.
5. Sul nuovo computer: scarica l'ultima versione dell'installer dalla scheda Releases su GitHub e installa l'applicazione normalmente. Avvia il programma una volta per creare una struttura di file di configurazione vuota. Chiudi l'applicazione. Quindi copia la cartella precedentemente salvata nel percorso di installazione sovrascrivendo i file — oppure scegli selettivamente solo le cartelle che ti interessano (skrypty/, opowiesci/, golden_key.env) e incollale nei posti giusti della nuova installazione.

Suggerimento per gli utenti NVDA: il menu contestuale "Apri percorso file" attivato con il tasto Applicazioni è completamente accessibile — NVDA legge ogni voce in italiano. Dopo aver aperto Esplora risorse nella cartella di destinazione, usa il tasto Backspace per andare un livello più in alto (funziona sempre, indipendentemente dal fatto che il focus sia sulla lista dei file o sulla barra degli indirizzi), quindi Ctrl+A per selezionare tutto e Ctrl+C per copiare.

Suggerimento: l'opzione "Apri percorso file" è il nome nativo per la versione italiana di Windows. Nel sistema inglese si chiama "Open file location", nelle altre versioni linguistiche — analogamente nella lingua locale del sistema operativo.


PASSO 2: Alimentazione API (Chiave OpenAI)

Perché l'intelligenza artificiale possa funzionare, ha bisogno di accedere ai server di OpenAI (i creatori di ChatGPT).

1. Crea un account su platform.openai.com e ricarica il credito nella scheda Billing.
2. Genera una chiave nella scheda API Keys (inizia con sk-proj-). Attenzione: la chiave viene mostrata una sola volta — nel momento della creazione. Se chiudi la finestra senza copiarla, va persa irrimediabilmente e dovrai revocarla (opzione revoke secret key) e generarne una nuova. Copiala subito, prima di cliccare qualsiasi cosa.
3. Nella schermata iniziale del programma clicca il pulsante "Genera il file golden_key.env e apri l'editor di testo". Il sistema creerà automaticamente un file di configurazione pulito nel posto giusto e aprirà il Blocco Note con un modello pronto per la modifica.
4. Nel file aperto vedrai la riga OPENAI_API_KEY=TUTAJ_WKLEJ_SWOJ_KLUCZ. Elimina il testo segnaposto e incolla la chiave copiata subito dopo il segno di uguale (senza spazi). Salva il file e riavvia l'applicazione.

Suggerimento: Dopo il riavvio l'applicazione controllerà il file e mostrerà un messaggio verde nella sezione "Controllo del Sistema" — significa che tutti i moduli AI sono pronti all'uso. In caso contrario ti dirà chiaramente cosa non va e ti permetterà di aprire l'editor di testo per correggere rapidamente l'errore.


PASSO 3: Studio Principale del Regista

Questo è il tuo centro di comando per inventare storie e scrivere sceneggiature. Accedici cliccando sul pulsante "🎬  Regista" nella barra dei pulsanti o selezionando Strumenti → Regista dal menu (scorciatoia: Ctrl+1).



IMPORTANTE: Formato dei file di progetto — ritorno al .txt

Nella versione 7, i file di progetto venivano salvati in formato Markdown (.md), ad esempio skrypty/anestesia.md. Era un esperimento deliberato: il formato .md doveva costituire una barriera psicologica per le persone non tecniche, scoraggiandole dall'aprire e modificare manualmente il file in Blocco Note (e quindi dal danneggiare accidentalmente le intestazioni della struttura).

L'esperimento non ha funzionato. L'IA spesso infrange uno dei divieti fondamentali (di più su questo tra poco). Per questo motivo, nella versione 8 si è tornati ai semplici file .txt, più intuitivi e leggibili per tutti. Ad esempio, un progetto chiamato "anestesia" verrà ora salvato come skrypty/anestesia.txt, e il suo riassunto come skrypty/anestesia_riassunto.txt. Questo permetterà a chiunque di apportare facilmente correzioni o tagli al testo in tempo reale.


⚠️ REGOLA CRITICA DEL MONTATORE (LEGGI PRIMA DI INIZIARE!) ⚠️

Tutti i tuoi script e libri generati vengono salvati in semplici file di testo (.txt), che puoi facilmente aprire in Blocco Note.

Come Regista hai il PIENO DIRITTO (anzi, il dovere) di modificare questo file! Se l'intelligenza artificiale si spinge troppo oltre e ad esempio risolve da sola il problema dei protagonisti alla fine di un frammento generato, apri il file, elimina le ultime righe e lascia il testo interrotto nel punto di maggiore tensione, poi clicca "Aggiorna dal disco" per sincronizzare la memoria del modello con il file corretto, e "Invia all'AI" per continuare.

🔴 TUTTAVIA - COSA NON PUOI TOCCARE:

Non modificare mai, eliminare o cambiare le righe che contengono la struttura (ad es. Atto 1, Scena 2, Capitolo 1, Prologo). Se danneggi queste intestazioni:
1. La tua storia si disintegrerà nei lettori di schermo (NVDA).
2. L'architetto dell'audiolibro, e quindi anche lo Studio Eleven Labs, non sarà in grado di dividere correttamente il tuo libro in frammenti da leggere.
3. Il Convertitore interno dell'applicazione non genererà un indice corretto nel file Word né sulla timeline in ElevenLabs.

Modifica i dialoghi, taglia l'azione, ma lascia in pace la struttura!


Come utilizzare la Regia?

- Libro del Mondo (barra laterale a sinistra): Qui inserisci le regole dell'universo. Ogni progetto ha ora il proprio Libro associato al nome del file — se il tuo file di storia è ad esempio emilia_heist_audiobook.txt, il Libro del Mondo verrà salvato come skrypty/emilia_heist_audiobook.md. Pertanto, l'ordine è importante: prima inserisci il nome del file del progetto nel campo "Nome del file del progetto", poi puoi salvare il Libro. Il pulsante "💾 Salva il Libro in modo permanente" rimane disattivato finché non inserisci il nome. Caricare un progetto esistente con il pulsante "Carica storia" caricherà automaticamente anche il file .md corrispondente — non devi fare nulla manualmente. Nota: Senza un Libro del Mondo compilato, l'applicazione bloccherà l'invio di richieste all'IA — è una misura di sicurezza intenzionale che ti protegge dal generare testo senza alcuna regola.
- Memoria a Lungo Termine (barra laterale a sinistra): Il secondo campo nella barra laterale. Qui l'IA salva automaticamente il riassunto della trama quando la memoria inizia a riempirsi. Puoi anche inserire manualmente le tue note — il modello le tratterà come "ciò che già so" prima di leggere la scena corrente. LACUNA STORICA (corretta in v15.5): in passato, se inserivi qui una nota molto breve e cliccavi "Salva Riassunto" prima che nel file di narrazione ci fosse qualcosa di significativo, al caricamento successivo l'applicazione caricava PRIORITARIAMENTE il riassunto e SALTAVA l'intera storia — il modello riceveva allora solo il Libro del Mondo e una nota di una frase, senza il contesto del tono e delle ultime scene. Dalla v15.5 il caricamento è intelligente: se l'intera storia rientra nella finestra di contesto, viene caricata per intero (e il vecchio riassunto superfluo viene cancellato), così il modello non perde il contesto. E dopo aver modificato manualmente il file di narrazione nell'editor, usa il nuovo pulsante "Aggiorna dal disco" (dalla v15.5), che con un solo clic sincronizza la memoria interna con il disco; per la semplice apertura del file nell'editor serve ancora "Apri file di narrazione…".
- Modalità Brainstorming: Inserisci un'idea vaga e l'IA ti darà 3 opzioni per lo sviluppo della trama. Per ciascuna opzione genererà immediatamente un blocco pronto "--- BOZZA PROMPT ---". Dopo aver scelto una di esse, incolla questo prompt nella Modalità Script o Audiobook e aggiungi eventuali commenti o informazioni per il modello. La memoria della trama non cambia durante il Brainstorming — puoi sperimentare senza rischi!
- Modalità Script Grezzo (dalla v16.0 — teatro di lettura): Qui incolli la "Bozza Prompt" generata nel Brainstorming. L'IA scriverà un lungo frammento di narratore e dialogo: la narrazione (ambientazione, tempo, azione) nei tag [Narratore: ...] e le battute dei personaggi nei tag [Nome: emozione]. Nessun effetto sonoro — il contesto lo porta il narratore con le parole. Il testo viene automaticamente aggiunto al tuo file (ad es. nuova_scena.txt) nella cartella skrypty/. Una sceneggiatura così finita puoi poi trasformarla in un audiolibro multivoce (il ponte con ElevenLabs Studio — un capitolo a parte più sotto).
- Modalità Audiobook Tradizionale: Modalità per scrittori. L'IA genera prosa letteraria pura — zero tag, zero fonetica, dialoghi classici intrecciati nella narrazione. Il testo viene aggiunto al file nello stesso modo della Modalità Script.
- Creazione automatica dei personaggi: Lo script è programmato per creare automaticamente nuovi tag [Speaker] se la trama richiede un nuovo personaggio. Suggerimento: Se l'IA crea un personaggio interessante, copia il suo tag e incollalo nel Libro del Mondo affinché il modello lo ricordi permanentemente!

Gestione del progetto — tre pulsanti di azione:
- Carica storia: Carica un progetto esistente nella memoria. Disponibile quando la memoria corrente è vuota. Dalla versione 15.2.3 supporta due percorsi: se il campo del nome del progetto è vuoto, si apre una finestra di dialogo di selezione con l'elenco di tutti i progetti trovati nella cartella skrypty/ (i file di riepilogo vengono filtrati) — NVDA legge l'elenco in modo naturale, il giocatore non deve ricordare e riscrivere il nome dalla tastiera. Se il campo del nome è compilato, l'applicazione tenta direttamente di caricare un progetto con quel nome (percorso esperto: Invio nel campo del nome o clic dopo aver digitato a memoria).
- Cancella corrente (lascia Sommario): Cancella solo la storia corrente. Il Riassunto nella Memoria a Lungo Termine e il Libro del Mondo vengono mantenuti — ideale per continuare un lungo libro dopo aver generato il riassunto.
- Chiudi Progetto (Reset Completo): Cancella completamente il progetto. Elimina la storia, il riassunto, il Libro del Mondo e azzera tutti i contatori. Usalo quando cambi progetto o inizi una nuova storia.
- Apri file di narrazione… (dalla v15.2.3): Modifica di emergenza del file di narrazione nell'editor di testo di sistema. Richiede il nome del progetto nel campo. L'applicazione apre skrypty/<nazwa>.txt in Blocco note (Windows), TextEdit (macOS) o l'editor GUI predefinito (Linux). Scenari tipici: (a) l'IA non chiude una scena e vuoi scrivere il finale manualmente; (b) hai caricato un progetto con un riassunto e vuoi copiare le ultime scene nella Memoria a Lungo Termine in modo che il modello abbia il contesto completo del tono (lacuna architetturale descritta sopra); (c) vuoi fare un taglio testuale nel mezzo di un capitolo che il motore dell'applicazione non supporta nativamente.
- Aggiorna dal disco (dalla v15.5): Sincronizza la memoria interna dell'applicazione con il file di narrazione dopo averlo modificato manualmente — senza un reset completo e senza ricaricare il progetto. Decide da sola: se l'intera storia rientra nella finestra di contesto, la carica per intero (e cancella il vecchio riassunto superfluo, in modo che il motore lavori sul testo completo); se la storia è lunga e ha un riassunto salvato, lo mantiene intatto e ricostruisce solo la coda fresca, contata a partire dall'ultima intestazione di struttura (Atto/Capitolo/Scena) — per questo conviene mantenere la struttura. Non modifica il Libro del Mondo né i contatori. Scenario tipico: l'IA ha chiuso erroneamente una scena (ha infranto l'anti-closure), tu tagli il finale sbagliato nell'editor e clicchi Aggiorna — fine delle correzioni in due posti.

Nota storica — perché le modalità sono ora protette da cambiamenti accidentali:
Nelle versioni precedenti dell'applicazione, nessuno controllava la coerenza della modalità creativa all'interno di un progetto. Il risultato era una certa possibilità creativa sottile, che si potrebbe descrivere così: inizi la storia in Modalità Script, inserisci "Atto 1" e "Scena 1" (l'applicazione è entusiasta della tua coerenza), generi alcune schermate di tensione con tag [SFX: Colpo di porta] e [Speaker 1: Marco - rassegnato]... e poi — perché ti è venuta l'ispirazione — clicchi "Inserisci taglio Capitolo 1". L'applicazione senza battere ciglio aggiunge l'intestazione "Capitolo 1" al file, subito dopo "Scena 3". Ora hai nel file un ibrido tra un radiodramma degli anni '50 e un romanzo di narrativa. ElevenLabs guarda questa struttura, vede l'intestazione del capitolo nel mezzo di un atto e decide che probabilmente è un errore nella matrice. L'indice sembra un'opera di un artista d'avanguardia. L'Architetto degli Audiolibri, d'altra parte, parte dal presupposto che tu sia un adulto e semplicemente lo elabora senza parole — ma anche senza alcuna garanzia di risultato. Dalla versione 12.0 l'interfaccia cercava di bloccare il cambio di modalità di registrazione — almeno in teoria. La pratica si è rivelata più creativa: il Brainstorming (sempre attivo come modalità di pianificazione) era una porta di servizio attraverso la quale, usando le frecce su e giù, si poteva passare tra Script e Audiolibro (Audiolibro → Brainstorming → Script e analogamente in senso inverso). Il primo clic su «Inserisci Atto 1» o «Inserisci Capitolo 1» nella modalità appena selezionata sovrascriveva docilmente il file .mode, mischiando atti e capitoli in un unico file narrativo. Solo dalla versione 15.2.3 abbiamo una protezione vera: una volta fissata la decisione di modalità (primo marcatore di struttura o primo invio di produzione riuscito), la seconda posizione di registrazione nella RadioBox è davvero disabilitata. Il Brainstorming resta sempre attivo come meccanismo d'emergenza — genera il riassunto quando la finestra di contesto si riempie e produce opzioni di trama — ma non puoi più usarlo come salto laterale verso l'altra modalità di registrazione.


Prompt Showrunner — L'IA come sceneggiatore di serie (dalla versione 7, mantenuto)

Questo è il più grande cambiamento introdotto nella versione 7, mantenuto senza modifiche. Non è visibile nell'interfaccia, ma cambia radicalmente la qualità della trama generata.

Il Showrunner è, nel settore televisivo, la persona responsabile dell'intera serie — si assicura che la trama non si diriga mai verso una soluzione facile, ma che continui a intensificarsi, accumulare conflitti e tenere lo spettatore in tensione per molte stagioni. Nella versione 7 questa filosofia è stata incorporata direttamente nelle istruzioni di sistema dell'IA.

Direttiva Anti-Closure — stato nella versione 8

Nonostante i vari approcci testati, il divieto Anti-Closure è spesso infranto dal modello, soprattutto in Modalità Audiobook Tradizionale. L'IA ha una forte tendenza a "chiudere" la storia ad ogni occasione — inserisce frasi riassuntive della trama, crea falsi happy end o chiude i fili narrativi nel mezzo di un capitolo, come se ogni frammento fosse l'ultimo. L'effetto è che il frammento successivo inizia da zero, senza continuità naturale.

Ecco perché è così importante la regola del montatore descritta sopra: se l'IA infrange il divieto e chiude da sola la scena, il tuo compito come Regista è aprire il file .txt, eliminare quelle ultime frasi, lasciare il testo interrotto nel punto di maggiore tensione e poi cliccare "Aggiorna dal disco" per sincronizzare la memoria con il file corretto.

Ogni modalità ha una direttiva Anti-Closure incorporata:

- Brainstorming: L'IA agisce come uno sceneggiatore di una serie multi-stagione. Ognuna delle 3 opzioni proposte DEVE accumulare ostacoli, introdurre nuovi dilemmi, fili narrativi aperti e cliffhanger. Assoluto divieto di proporre opzioni in cui i protagonisti si riconciliano permanentemente, superano l'ostacolo principale senza gravi conseguenze o la storia si dirige verso una fine affrettata. Divieto di inventare luoghi magici economici che infrangono l'architettura del mondo.
- Modalità Script Grezzo: Assoluto divieto di concludere il testo con riassunti, morali o chiusure. L'IA deve interrompere l'azione naturalmente in un momento di tensione (cliffhanger), evitando conclusioni, affinché il frammento successivo possa prendere il controllo della narrazione senza problemi.
- Modalità Audiobook Tradizionale: Assoluto divieto di concludere il testo con riassunti patetici, chiusure di fili narrativi o suggerimenti di fine storia (ad es. "Era pronta per nuove sfide", "Capì che era ora di andare avanti"). Il testo deve interrompersi nel mezzo di un'azione in corso, tensione o pensiero aperto.

Eccezione alla regola: Se chiedi esplicitamente una conclusione, un finale o un epilogo, l'IA genererà una chiusura soddisfacente della storia — il divieto non si applica quando lo richiedi tu stesso.


Gestione di Atti e Scene (Modalità Script, dalla versione 7, mantenuto)

La Modalità Script Grezzo ha un pannello dedicato "✂️ Gestione della Struttura" con pulsanti per costruire la struttura del radiodramma in tempo reale.

- Inserisci Atto X: Inserisce l'intestazione dell'atto (ad es. "Atto 2") E aggiunge automaticamente sotto di essa "Scena 1" — perché ogni nuovo atto inizia con la prima scena. Il contatore degli atti passa al numero successivo e il contatore delle scene si resetta a 2 (pronto per la scena successiva in quell'atto).
- Inserisci Scena X: Inserisce solo l'intestazione della scena (ad es. "Scena 3") all'interno dell'atto corrente. Il contatore delle scene aumenta automaticamente.

Intelligente caricamento del file: Quando carichi un file di script esistente, l'applicazione lo scansiona automaticamente e imposta i contatori degli atti e delle scene sui numeri corretti. Il contatore delle scene è sempre calcolato all'interno dell'ultimo atto nel file.

Prologo ed Epilogo: I pulsanti "📜 Inserisci Prologo" e "🏁 Inserisci Epilogo" sono comuni a entrambe le modalità e disponibili nello stesso pannello.

L'Architetto degli Audiolibri trasformerà automaticamente gli Atti in punti di navigazione principali (Heading 1) per ElevenLabs e NVDA — le Scene diventeranno testo in grassetto visibile nel documento, ma invisibile nell'indice.


Gestione Intelligente dei Capitoli (Modalità Audiobook, dalla versione 5, mantenuto)

LLM genera al massimo circa 5000 caratteri per ogni richiesta — troppo poco per un capitolo completo. Pertanto, lavori in modo iterativo: generi frammenti successivi con il pulsante "Invia all'IA" finché non ritieni che il capitolo sia completo. Poi clicchi "Inserisci taglio capitolo" — l'applicazione aggiunge l'intestazione al file e alla memoria, e il contatore dei capitoli passa automaticamente al numero successivo.

Pulsanti nel pannello:

- Inserisci taglio (Capitolo X): Inserisce l'intestazione (es. "Capitolo 3") nel file e nella memoria. Il contatore dei capitoli si aggiorna automaticamente.
- Inserisci Prologo: Funziona solo all'inizio, quando la memoria è vuota. Protezione contro l'inserimento accidentale del Prologo nel mezzo della storia.
- Inserisci Epilogo: Chiude la storia. Dopo aver inserito l'Epilogo con il contenuto, l'applicazione bloccherà la generazione di nuovi frammenti — è intenzionale, perché dopo la fine della storia non c'è più nulla da aggiungere.

Intelligente caricamento del file: Quando carichi un file esistente, l'applicazione lo scansiona automaticamente e imposta il contatore dei capitoli sul numero corretto. Se il file ha un Prologo e tre capitoli, il contatore mostrerà "Capitolo 4" — senza contare manualmente.


Accumulatore della Trama — come funziona la memoria dell'IA

Nella memoria del modello finisce solo il testo puro della storia — ciò che l'IA ha effettivamente scritto. Le istruzioni, le opzioni e i piani scompaiono dopo l'uso e non ingombrano il contesto. Effetto? Il modello mantiene più a lungo la concentrazione, ricorda meglio gli accenti dei personaggi e raramente "sfugge" alle regole del Libro del Mondo.

L'indicatore "Memoria del Modello" mostra quanto è piena la finestra di contesto del modello. Dalla versione 15.1 NON è più un conteggio dei caratteri della storia — l'applicazione conta TOKEN reali (allo stesso modo del modello) e somma TUTTO il carico inviato all'IA: la storia corrente, la Memoria a Lungo Termine (il riassunto) E il Libro del Mondo. Per questo l'indicatore sale anche quando amplii il Libro del Mondo o hai un riassunto lungo — non solo per la narrazione. Il valore è mostrato come percentuale della finestra:
- Verde (fino a ~70%): Il modello è completamente concentrato, hai un buffer sicuro.
- Giallo (~70–90%): Ti stai avvicinando al limite. L'IA potrebbe iniziare a ridurre le risposte e ignorare le regole; in modalità pianificazione (Brainstorming) il motore inizia a forzare un riassunto. Inizia lentamente a chiudere il filo narrativo.
- Rosso (oltre ~90%): Sovraccarico critico!

Diagnostica della soglia di riassunto (quando l'IA allucina prima di quanto la soglia presuma): le soglie (avviso ~70%, allarme ~90%) sono stimate empiricamente. Se noti una tendenza ripetibile del modello a "deviare" dalle regole o a iniziare ad allucinare PRIMA che l'indicatore diventi giallo/rosso — cioè prima di quanto la soglia presuma — apri una issue nel repository dell'applicazione e descrivi a quale livello di riempimento approssimativo (percentuale) inizia davvero a degradarsi, idealmente con un esempio. Se questa tendenza si conferma più ampiamente (tra più utenti, su progetti diversi), la soglia del riassunto automatico sarà abbassata in una patch futura. È un meccanismo deliberatamente iterativo — meglio regolarlo su dati reali che indovinarlo in anticipo.

Memoria Infinita (dalla versione 6, mantenuto)

Quando si accende l'allarme rosso, non devi più copiare manualmente il riassunto. Inserisci nel Brainstorming un comando contenente la parola "riassunto" o "sommario" — l'IA genererà una sintesi concisa di tutta la trama finora. Poi clicca il pulsante "Salva Riassunto (permanente)" — l'applicazione crea automaticamente un file _riassunto.txt nella cartella skrypty/ e lo protegge da sovrascritture accidentali. Dopo aver salvato, svuota la memoria e puoi continuare a creare nel file corrente. Caricherai il riassunto nel campo della Memoria a Lungo Termine prima della prossima sessione — e puoi continuare la storia all'infinito, senza limiti di lunghezza.

Quando riassumere (aggiornato in v15.5): Non devi più sorvegliare una soglia rigida di caratteri "prima di terminare il lavoro". È meglio riassumere dopo la chiusura naturale di una parte strutturale più ampia — al termine di una scena, di un atto o di un capitolo. Motivo: quando in seguito correggerai manualmente la coda nel file di narrazione e cliccherai "Aggiorna dal disco", l'applicazione ricostruirà con precisione il frammento fresco contato a partire dall'ultima intestazione — mentre il riassunto della parte precedente rimarrà intatto. Per questo conviene ancora di più mantenere la struttura: inserisci regolarmente intestazioni Atto/Capitolo/Scena dal pannello di struttura (sono sconsigliate le forme lunghe senza alcun atto o capitolo, ad es. un "dramma modernista" tutto d'un fiato). ECCEZIONE: se conduci una storia molto lunga COMPLETAMENTE senza intestazioni, generare e salvare il Riassunto prima della pausa resta necessario — senza marcatori l'applicazione può ricostruire solo l'ultimo frammento contato in caratteri.

Riassunto automatico: Quando la memoria entra in stato di allarme, il Brainstorming si commuta automaticamente in modalità di emergenza — invece di generare subito opzioni, crea prima un riassunto dettagliato di tutta la trama finora e lo salva nei tag <RIASSUNTO>. L'applicazione rileva questi tag e trasferisce automaticamente il riassunto nel campo della Memoria a Lungo Termine. Zero lavoro manuale!

Caricamento intelligente e aggiornamento dal disco (aggiornato in v15.5): Sia al caricamento del progetto, sia dopo aver cliccato il nuovo pulsante "Aggiorna dal disco" (dopo aver modificato manualmente il file di narrazione nell'editor), l'applicazione decide da sola come conciliare la memoria con il disco. Se l'INTERA storia rientra nella finestra di contesto — la carica per intero e cancella il vecchio riassunto superfluo, affinché il motore lavori sul testo completo (questo chiude la vecchia lacuna in cui il modello riceveva il solo riassunto senza il contesto delle ultime scene). Se la storia è LUNGA e ha un file di riassunto salvato — mantiene il riassunto intatto e nella Memoria Corrente inserisce solo la coda fresca, contata a partire dall'ultima intestazione di struttura (Atto/Capitolo/Scena). In questo modo non sprechi token per ricaricare l'intera storia, e allo stesso tempo il riassunto successivo non nasce su dati non aggiornati.


PASSO 3b: Due uscite dello Script — audiolibro multivocale (ElevenLabs) e versione per lettori di schermo

Un copione di teatro letto completato (modalità Script) ha due uscite indipendenti: un progetto multivocale di ElevenLabs Studio (audio) e una versione HTML per lettori di schermo. Sono due modi per "ascoltare" la stessa opera — puoi usare l'uno, l'altro o entrambi. Entrambi sono opzionali e non cambiano il flusso classico con il convertitore.

─────────── Ponte a ElevenLabs Studio (audio, opzionale) ───────────

Il ponte trasforma il copione in un progetto Studio multivocale — il narratore e ogni personaggio ricevono una voce separata. Senza la chiave ElevenLabs nulla cambia: il ponte rimane semplicemente nascosto.

Chiave ElevenLabs (opzionale)

Incolla la tua chiave ElevenLabs nel file golden_key.env, su una linea separata: ELEVENLABS_API_KEY=sk_... Nota: la chiave ElevenLabs inizia con sk_ (con SOTTOLINEATURA), a differenza della chiave OpenAI (sk-). Una chiave con restrizioni necessita dei permessi (scope) projects_write e voices_read. Lo stato della chiave è visibile nella schermata principale (System Check) — la mancanza della chiave non è un errore, semplicemente il ponte rimane nascosto.

Il ponte appare nel pannello del Regista in modalità Script (quando la chiave è corretta). Funziona su un'opera pronta salvata sul disco — prima genera o carica il progetto.

Passo 1 — Cast vocale

Clicca su "Cast vocale…". L'applicazione carica i personaggi che hanno battute e aggiunge sempre uno slot per il Narratore (il narratore è la voce predefinita — titoli dei capitoli e tutta la narrazione). Per ogni oratore, incolla l'ID della voce. IMPORTANTE: ogni voce usata nell'opera deve prima trovarsi nelle tue "My Voices" — le voci che crei tu stesso (ad esempio in "Voice Design") finiscono lì automaticamente, mentre le voci della libreria pubblica si esplorano nella scheda "Explore" e si aggiungono con "Add to My Voices". Come ottenere un ID della voce in ElevenLabs (nel browser): trova la voce, ascolta un campione per essere sicuro che sia quella giusta e copia il suo identificatore con "Copy Voice ID"; quando una voce è già nelle "My Voices", quel pulsante è disponibile subito — senza aprire "More actions". Scelta delle voci: per limitare eventuali rigenerazioni, la cosa più facile è scegliere dalla collezione "Best for Eleven v3" (voci verificate per il modello v3 su cui viene creato il progetto); in alternativa progetta la tua voce in "Voice Design", e per i più audaci resta la clonazione IVC (Instant Voice Cloning) o persino PVC (Professional Voice Cloning). Puoi lasciare i campi vuoti e tornare più tardi — il salvataggio è una bozza.

Passo 2 — Costruisci il progetto

Clicca su "Crea progetto ElevenLabs Studio…". L'applicazione verifica che il copione abbia almeno un capitolo (Prologo/Atto/Capitolo) e che ogni voce sia assegnata, quindi crea sul tuo account un progetto Studio multivocale diviso in capitoli. La semplice creazione del progetto NON consuma crediti. L'applicazione imposta anche subito la lingua del progetto (pronuncia corretta delle righe di intestazione) e la normalizzazione del volume allo standard dell'audiolibro — lo fa tramite l'API così non devi aprire le impostazioni del progetto nel browser.

Guardiano del formato (un'estensione della Regola del Montatore): il ponte richiede che nella sceneggiatura OGNI riga sia o una battuta con tag del parlante ([Narratore: …] o [Personaggio: …]) oppure un'intestazione di struttura (Prologo, Atto, Scena, Capitolo). La prosa comune senza tag scritta «alla rinfusa» — per esempio una nota dell'autore o un frammento di narrazione senza tag — non viene assegnata ad alcuna voce e viene saltata in silenzio durante la costruzione, quindi il progetto finito potrebbe divergere dal tuo file. Per questo, se l'applicazione rileva tali righe orfane, ne mostra l'elenco con i numeri di riga e chiede se costruire comunque: puoi allora annullare e correggere la sceneggiatura (aprila con il pulsante «Apri file di narrazione…», aggiungi i tag del parlante mancanti o elimina quelle righe) oppure costruire comunque consapevolmente, accettando che vengano saltate. È un'estensione naturale della Regola del Montatore: così come non devi rompere le intestazioni di struttura, in una sceneggiatura destinata al ponte ogni riga dovrebbe avere il suo parlante o essere un'intestazione.

Passo 3 — Rendering nel browser

L'applicazione mostra l'identificatore del progetto e un pulsante per aprire ElevenLabs Studio. Nel browser, trova il progetto, esegui il rendering della voce (questo consuma crediti — indicativamente 1 credito per carattere), quindi esporta il file audio o pubblica il progetto su Eleven Reader. Il rendering e la pubblicazione avvengono dal tuo lato, consapevolmente — l'applicazione si limita a costruire il progetto.

Espressione e accenti (modello Eleven v3)

Il progetto è creato con il modello Eleven v3 (oltre 70 lingue). L'emozione NON si esprime con maiuscole, puntini di sospensione o trattini — il motore li ignora. Invece, il Regista intreccia nelle battute tag audio v3 in inglese, ad es. [whispers], [sighs], [angry], [laughs] — questi guidano l'espressione e funzionano indipendentemente dalla lingua parlata. L'ACCENTO di un personaggio proviene invece dal CAMPIONE DI VOCE: se vuoi che qualcuno parli, ad esempio, italiano con un accento straniero, scegli o progetta (in Voice Design) una voce il cui campione abbia quell'accento. In pratica, sperimenta con il prompt della voce finché non senti, ad esempio, un campione in italiano con accento finlandese — il modello v3 conserva quell'accento nella registrazione finale. Suggerimento: le frasi molto lunghe indeboliscono l'accento, per questo al Regista viene già chiesto nel prompt di usare frasi brevi.

Consapevolezza del modello v3 (fase alfa)

Eleven v3 è il più espressivo ma ancora in fase alfa. A volte una singola battuta viene resa come un gracchiare invece che come parlato — basta rigenerarla in Studio (ogni blocco ha alcune rigenerazioni gratuite). Le impostazioni del progetto in ElevenLabs possono anche mostrare raccomandazioni per cambiare modello (in Eleven Flash v2.5 o Multilingual v2) — questo NON è un errore, solo un suggerimento del motore. Se non vuoi vedere questi messaggi, semplicemente non aprire le impostazioni del progetto: l'applicazione ha già impostato tutto il necessario tramite l'API (modello, lingua, normalizzazione del volume).

Perché teatro letto e non effetti sonori? Nelle versioni precedenti, la modalità Script produceva effetti grezzi [SFX: ...] senza narratore. Tuttavia, il ponte verso una registrazione multivocale completa richiede che il contesto (luogo, tempo, azione) sia trasmesso dal narratore con le parole: gli effetti sonori in Studio non sono accessibili ai lettori di schermo, e il modello realizza comunque o il narratore o gli effetti — mai entrambi stabilmente. Per questo motivo, la modalità Script è ora teatro letto: narratore più dialogo, senza SFX.

─────────── Versione per lettori di schermo (HTML, senza ElevenLabs) ───────────

In modalità Script, indipendentemente dalla chiave ElevenLabs, hai un pulsante "Genera versione per lettori di schermo". Crea il file skrypty/<nazwa>_screen_reader.html — un'uscita separata per le persone che usano lettori di schermo (ad es. NVDA). Funziona così: le battute dei personaggi che hanno un accento definito nel Libro del Mondo (ad es. una voce "[Joana] accento finlandese") ricevono una grafia fonetica (ortografia deliberatamente "rotta") e un tag di lingua (l'attributo lang), così il lettore di schermo le legge con il corretto accento straniero. I tag audio v3 (ad es. [whispers]) vengono rimossi in questa versione — il lettore non deve leggerli ad alta voce. Le intestazioni Prologo/Atto/Scena diventano intestazioni HTML, così il documento è facile da navigare.

Questo completa deliberatamente il ponte audio: per il modello v3 l'accento proviene dal campione di voce, e per il lettore di schermo dall'ortografia più il tag di lingua. Per questo l'ortografia nella versione audio rimane pulita (v3 sceglie la lingua da sé), e "rompere" l'ortografia va solo nel file HTML separato, dove è desiderabile.


PASSO 4: Postproduzione in Reżyser Audio GPT

Dopo aver scritto la storia, hai a disposizione uno strumento di postproduzione disponibile nella parte inferiore del pannello di Regista (compare solo in Modalità Audiobook).

Assegnazione dei Titoli ai Capitoli (Modalità Audiobook)

L'IA analizzerà l'intera storia e proporrà titoli descrittivi e letterari per ogni capitolo (oltre a un eventuale Prologo ed Epilogo). Il modulo itera sui capitoli del file salvato e assegna loro un breve titolo, analizzando solo l'inizio di ogni capitolo (fino a 6000 caratteri). Restituisce esclusivamente un elenco numerato di titoli — senza riscrivere il contenuto del libro.

Nota: Il modulo richiede che il file sia già salvato sul disco (generato o caricato). Se il file non esiste, l'applicazione visualizzerà un messaggio appropriato.


PASSO 5: Poliglotta AI

Applicazione per traduzioni e imposizione di accenti forti sui sintetizzatori dei lettori di schermo. Accedi cliccando il pulsante "🌍  Poliglotta" sulla barra dei pulsanti o selezionando Strumenti → Poliglotta dal menu (scorciatoia: Ctrl+2).

Modalità 1: Traduttore Normale (Usa AI - A Pagamento)

Ideale per ascoltare storie in una lingua straniera bella e corretta.

- Carica il file con il pulsante "Carica file in memoria" o utilizzando il pulsante "Sfoglia..." per selezionare il file nella finestra di sistema.
- Seleziona la modalità "Traduttore AI", inserisci la lingua di destinazione (ad es. "Finlandese").
- Lo script tradurrà il contenuto. Se carichi un file .html, tradurrà solo il testo visibile al lettore e aggiornerà il codice della lingua nel tag html.
- Se carichi un normale file .txt o .md (ad es. uno script generato da Regista), lo script salverà automaticamente il risultato come file .html con un tag di lingua incorporato — pronto per essere letto da NVDA senza alcun lavoro aggiuntivo.
- Supporta anche i file .docx.

Divisione intelligente in blocchi: I testi lunghi vengono automaticamente suddivisi in blocchi misurati in token del modello (non in caratteri) e tradotti sequenzialmente con una barra di avanzamento. In questo modo anche le lingue a scrittura densa, come il cinese o il giapponese, rientrano nel limite di risposta del modello, e una risposta troncata viene rilevata e ritentata automaticamente su frammenti più piccoli.

Salvataggio del progresso resistente ai guasti (NOVITÀ nella versione 9): Ogni blocco tradotto viene immediatamente salvato in un file temporaneo nascosto nella cartella di sistema dell'applicazione. Se la traduzione viene interrotta a causa dell'esaurimento del limite API, al successivo avvio l'applicazione rileverà automaticamente questo file, ripristinerà il progresso già pagato e completerà tranquillamente il lavoro dal punto di interruzione — senza alcuna copia manuale. Al termine con successo, il file temporaneo viene automaticamente eliminato.

Perché è importante? Nella versione 8, l'approccio alla ripresa della traduzione aveva un errore critico e silenzioso: se non si rinominava il file con la traduzione parziale e si tagliava il frammento tradotto secondo le istruzioni, e poi si riprendeva immediatamente la traduzione del resto — l'applicazione apriva il file di output in modalità sovrascrittura. Il progresso pagato veniva cancellato in modo irreversibile e inconsapevole, prima che tu potessi accorgertene. La versione 9 elimina completamente questa trappola: il salvataggio è permanente dopo ogni blocco, indipendentemente da ciò che fai dopo.

E anche due opzioni di pulizia senza accento:

"Nessuno (Pulizia CON normalizzazione dei numeri)"
L'opzione con normalizzazione dei numeri converte automaticamente i numeri in parole (ad es. 15 diventa "quindici") prima dell'elaborazione — in questo modo NVDA legge i numeri fluentemente, e se il testo ha un accento imposto, anche il numero lo avrà, senza eccezioni.
Vi chiederete se il sintetizzatore sarà in grado di declinare tali numeri normalizzati a seconda del contesto? La risposta è: no. Ed è una caratteristica voluta. Come è noto: "la lingua polacca è difficile" — e uno straniero che storpia la nostra grammatica aggiunge solo autenticità all'accento spezzato!

Correttore di Tag (NOVITÀ nella versione 9): Alla fine dell'elenco troverai un'opzione aggiuntiva — Correttore di Tag. Non applica alcuna regola fonetica o di pulizia. Fa una cosa: inietta nel file il codice ISO della lingua che fornisci — a due lettere (ad es. "fi" per il finlandese, "en" per l'inglese) o con sottotag di regione o scrittura (ad es. "pt-BR" per il portoghese brasiliano, "zh-Hans" per il cinese semplificato). È utile quando hai già un file pronto — ad esempio tradotto in precedenza dal Traduttore AI — ma per qualche motivo è uscito con un tag di lingua errato o mancante. Invece di tradurlo di nuovo, basta eseguire il Correttore con il codice ISO corretto e in poco tempo avrai un file corretto.

Lo script pulisce le didascalie registiche tra parentesi — rimuove interi frammenti di testo racchiusi tra parentesi tonde (ad es. "(con respiri intrecciati)", "(sussurrando)", "(ironicamente)"). ElevenLabs deve leggere solo dialoghi e narrazione, non istruzioni registiche intrecciate nel testo.

Lo script pulisce anche i marcatori Markdown — rimuove gli hashtag dei titoli (ad es. #, ##, ###), i segni di uguale usati come sottolineature dei titoli e le virgole orfane che potrebbero disturbare il ritmo di lettura del sintetizzatore.

- Scudo protettivo: Lo script protegge tutti i tag HTML. Rovina solo dialoghi e narrazione.
- Funziona localmente e non costa nulla!

### Cifrario: Tipoglicemia
Secondo una ricerca all'Università di Cambridge, non importa in quale ordine siano le lettere in una parola, l'unica cosa importante è che la prima e l'ultima lettera siano al posto giusto.


Tryb 3: Cifrario (NOVITÀ in 13.0 — giochi di testo, gratuiti, locali)

Il terzo RadioButton in Poliglotta, accanto al Traduttore AI e alla Modalità Regista: "Modalità Cifrario (giochi di testo, distorsione casuale)". Attiva sei algoritmi locali che distorcono il testo — per giochi, enigmi, rompicapi linguistici. Dopo aver selezionato la modalità, appare un menu a tendina con gli algoritmi, e per uno di essi (Cifrario di Cesare) un campo numerico aggiuntivo per lo spostamento.

Algoritmi disponibili (seleziona nel menu "Scegli algoritmo distorsivo"):

- Invertitore di Testo (Lettura al contrario con lettera maiuscola) — ogni frase viene invertita carattere per carattere, mantenendo il punto/esclamativo/interrogativo alla fine e la lettera maiuscola all'inizio. Prima dell'inversione, lo script espande le abbreviazioni comuni (ad es., ecc., dott., prof., pag. ecc.), in modo che il risultato dopo l'inversione abbia ancora senso — senza questo "ad es." diventa un assurdo ".se da".

  Ispirazione: missione dal programma "The Traitors. Traditori". Quando la conduttrice ha mostrato ai partecipanti una popolare canzone polacca di un cartone animato — semplicemente riprodotta al contrario — le reazioni erano del tipo "che lingua è?", "forse armeno", "ungherese o finlandese". La vera missione consisteva nel fatto che una squadra riceveva nel bosco il testo della canzone scritto al contrario, doveva cantarlo in questa forma invertita, l'altra squadra lo registrava, lo riproduceva al contrario — e in teoria recuperava la canzone originale da indovinare. Esattamente lo stesso divertente malinteso fonetico genera il nostro Invertitore, quando fai passare il file elaborato attraverso un sintetizzatore TTS.

- Tipoglicemia (Centro delle parole mescolato) — classico effetto psicolinguistico: "Non puoi lggeere il toesto in qulasiasi oidrne dlele ltteree, prucché la pmira e l'utlmia ltteera siano al psoto gtisuo". Lo script mescola casualmente il centro di ogni parola più lunga di 4 caratteri, la prima e l'ultima lettera rimangono intatte. Ottimo per il test "quanto vedo davvero e quanto il mio cervello immagina".

- Telefono Rotto / Dialetto Serpente — ogni "s", "z" o digramma "sz" viene allungato casualmente in un sibilo di lunghezza 4-8 caratteri ("ssssss", "zzzzzz", "ssssssz"). Ispirazione: Snecko dal gioco "Slay the Spire". Effetto: il testo sembra letto da un serpente con un difetto di pronuncia.

- Vocalizzatore (Tutto rimbomba con "O") — ogni vocale nel testo viene sostituita con "o", mantenendo le morbidezze polacche. "Buongiorno" → "Boongiorno". Più lungo è il testo, più divertente è l'effetto (e il lettore di schermo lo legge con piena convinzione).

- Balbuzie Forte / Robot Danneggiato — aggiunge balbuzie all'inizio delle parole: "co-co-co-computer", "do-do-doccia". Per le parole brevi (meno di 3 caratteri) l'algoritmo le ignora. Se la seconda lettera della parola è una consonante, ripete le prime due lettere (effetto più naturale); se è una vocale — ripete solo la prima.

- Cifrario di Cesare (spostamento dell'alfabeto IT) — classico cifrario sostitutivo: ogni lettera viene spostata di N posizioni nell'alfabeto italiano (ABCDEFGHILMNOPQRSTUVZ, 21 caratteri — senza J, K, W, X, Y). Inserisci il valore dello spostamento nel campo numerico "Spostamento cifrario di Cesare (0 = casuale, intervallo -20…20)". Se inserisci 0 — l'applicazione sceglierà casualmente uno spostamento nell'intervallo 1-19 e lo mostrerà in un messaggio alla fine (così potrai decifrare successivamente). I caratteri al di fuori dell'alfabeto (numeri, punteggiatura, spazi) rimangono invariati.

Applicazione pratica: i cifrari salvano il risultato nello stesso formato della Modalità Regista (.html con tag lang o .docx con tag XML), quindi NVDA li leggerà con la voce della lingua appropriata. In particolare, l'Invertitore e il Vocalizzatore suonano nel sintetizzatore molto più interessanti di quando li leggi con gli occhi — perché il cervello durante la lettura visiva cerca automaticamente di "decodificare" il testo, mentre il TTS lo legge esattamente come è scritto.

Tutti e sei i cifrari sono descritti anche in un linguaggio più ampio e accessibile nel file docs/dictionaries.pl.txt nel pacchetto dell'applicazione — insieme a consigli su come aggiungere un proprio cifrario del tipo "sostituzione di lettere" senza conoscenze di programmazione (ad esempio, linguaggio gergale scolastico, linguaggio-trava).


Detección della lingua

Killer Feature per non vedenti: File con tag di lingua

Questa è una vera rivoluzione. I file elaborati ora si salvano come:

Automatica commutazione della lingua in NVDA — cosa devi sapere

Affinché NVDA commuti effettivamente la voce in base al tag lang, l'impostazione "Cambia automaticamente la lingua quando supportata" deve essere attivata. La troverai in Preferenze NVDA → Voce. Di default è attivata al primo avvio del lettore — ma vale la pena controllare se qualcuno l'ha disattivata.

Importante limitazione delle voci OneCore: Le voci Microsoft OneCore non supportano nativamente questo meccanismo con NVDA, ma solo con il narratore integrato di Windows. Esiste un componente aggiuntivo non ufficiale per NVDA chiamato "One Core Autolang", che tenta di risolvere questo problema — ma il suo sviluppo è stato rapidamente interrotto. La causa è semplice: ogni anno, con la prima versione di NVDA dell'anno, si verificano cambiamenti che rompono la compatibilità dell'API (i cosiddetti API Breaking Changes). A volte basta aggiornare il campo "last tested version" nel manifesto del componente aggiuntivo, ma a volte sono necessarie vere modifiche nel codice — e l'autore non riesce a tenere il passo con gli aggiornamenti. Se tieni all'automatica commutazione della lingua, una scelta più sicura sono le voci Tiflotecnia (a pagamento, sezione sopra) o eSpeak (gratuito, qualità inferiore), che supportano questo meccanismo nativamente — ma attenzione: attualmente nelle voci Tiflotecnia funziona con un errore di priorità (vedi "Critico inghippo" sotto). Dopo aver applicato la patch, la commutazione automatica funziona perfettamente, come nel vecchio Vocalizer.


Krytyczny problema Tiflotecnia Voices: rilevamento della lingua difettoso

Prima la buona notizia — l'allarme su NVDA 2026.1 delle versioni precedenti del manuale si è concluso con un lieto fine: Cerrence ha fornito librerie a 64 bit, Tiflotecnia le ha rilasciate in un pacchetto .nvda-addon disponibile nel Add-on Store (sezione sopra), e Vocalizer per coloro che lo hanno mantenuto fino alla fine è tornato con un nuovo nome — con una qualità migliore e senza le limitazioni a 32 bit.

Con il lancio di Tiflotecnia Voices è emerso però un nuovo problema critico — nel rilevamento della lingua. Nelle impostazioni dell'add-on è possibile configurare quale voce deve essere utilizzata per determinati caratteri (ad esempio latini, cirillici) a seconda delle voci installate. Il problema sta nella priorità degli ordini: attualmente si applica prima l'override per carattere, poi il fallback al codice ISO della lingua (in pratica irraggiungibile per lo STESSO alfabeto a cui si è già adattato l'override), infine la voce selezionata. Il risultato si manifesta all'interno dello stesso alfabeto: hai un testo in finlandese con il tag corretto `lang="fi"`, installato Satu come voce finlandese di Tiflotecnia, MA nelle impostazioni è impostata una voce polacca per i caratteri latini — Satu NON leggerà questo testo, nonostante il tag ISO corretto. L'override per carattere "voce polacca per il latino" vince al primo livello, l'ISO `fi` non viene mai verificato. Per le coppie di alfabeti diversi il meccanismo funziona correttamente (testo russo + Milena per il cirillico + voce polacca per il latino — tutto il cirillico va con Milena, eventuali nomi propri latini con la voce polacca; ogni alfabeto sta nel proprio override). Dopo la migrazione da Vocalizer, in cui il cambio di lingua basato su ISO funzionava perfettamente, gli utenti noteranno subito questa regressione — specialmente quelli che in Poliglotta usano diversi accenti europei (Satu, Alice, Markus) sulla stessa gamma di caratteri latini.

Diagnosi e patch: ho diagnosticato il problema a livello di Python nel codice dell'add-on e ho preparato una patch che cambia l'ordine delle priorità in: ISO → voce selezionata → override per carattere. La patch mantiene l'utile passaggio al latino per i nomi latini nel testo russo, quando nelle impostazioni è attivato il "rilevamento della lingua basato sui caratteri Unicode". Ho inviato la patch agli sviluppatori di Tiflotecnia — finora senza risposta, quindi molto probabilmente rimangono alla loro soluzione. Se l'add-on riceve un aggiornamento, aggiornerò la patch se necessario.

Cosa fare nel frattempo: se ti interessa il corretto rilevamento della lingua (vale la pena — era una delle killer features del vecchio Vocalizer, vedi "Killer Feature per i non vedenti" sopra), apri un issue nel repository dell'applicazione su GitHub con l'etichetta `tiflotecnia-patch` e l'indirizzo email nel contenuto. Vale la pena aggiungere una breve descrizione del problema nella tua lingua (bastano 2–3 frasi) — il bot riconoscerà la lingua (supportate: polacco, inglese, tedesco, spagnolo, finlandese, francese, islandese, italiano, russo) e risponderà nella stessa; senza descrizione o in un'altra lingua, la risposta arriverà in inglese. Un bot automatico chiuderà immediatamente l'issue con la conferma della segnalazione (senza traccia nel thread pubblico), e riceverai la patch privatamente via email di solito entro pochi giorni. La patch NON è pubblicata nel repository dell'applicazione né come Gist — Tiflotecnia Voices for NVDA è un software commerciale e la licenza dell'add-on non consente la ridistribuzione dei suoi file, anche se modificati. Dopo aver ricevuto la patch, il suo contenuto deve essere copiato in `%appdata%\Roaming\nvda\addons\TiflotecniaVoices`, sostituendo i file. Attenzione durante la copia: se Windows non ha chiesto di sostituire, probabilmente hai copiato l'intera cartella `TiflotecniaVoices_edits` con il suo contenuto INVECE del solo contenuto — in tal caso entra nella sottocartella creata, taglia tutto, incolla un livello più in alto e sovrascrivi. Dopo aver applicato correttamente la patch, riavvia NVDA — goditi la migliore qualità delle voci Cerrence a 64 bit e il corretto rilevamento della lingua, ovvero una combinazione che nessun singolo produttore sul mercato può offrire. Supponiamo ovviamente che tu abbia una licenza valida per Tiflotecnia Voices — non lo verifichiamo, ma senza licenza non potrai applicare la patch su una cartella altrui.


PASSO 6: Architetto degli Audiolibri

Uno strumento per preparare una struttura professionale del file per i lettori di schermo e ElevenLabs. Accedi a esso facendo clic sul pulsante "📄  Convertitore" sulla barra dei pulsanti o selezionando Strumenti → Convertitore dal menu (scorciatoia: Ctrl+3).

Come funziona?

1. Inserisci il percorso del file sorgente nel campo di testo o fai clic sul pulsante "Sfoglia..." per selezionare un file nella finestra di dialogo del sistema. Lo script accetta file .txt, .docx, nonché file .html e .htm.
2. Fai clic su "Costruisci Architettura per ElevenLabs".
3. Lo script scansiona ogni riga di testo e converte le parole chiave (Atto, Capitolo, Prologo, Epilogo, Introduzione) in intestazioni "Heading 1" nel documento Word.
4. Le scene (righe che iniziano con la parola "Scena") vengono trasformate in testo in grassetto — visibile nel documento ma invisibile nell'indice di ElevenLabs.
5. Tutto il testo rimanente (dialoghi, descrizioni) viene trasferito senza modifiche.
6. Riceverai un file architektura_[nome_originale].docx — un documento Word professionale pronto per ulteriori lavori. Ad esempio, se il tuo file di input si chiamava anestesia.txt, il file risultante sarà denominato architektura_anestesia.docx e apparirà nella stessa cartella dell'originale.

Pulizia automatica: Lo script rimuove automaticamente i tag HTML (se il testo proviene da un browser o da un file .html locale, ad esempio generato da Poliglotta) e i marcatori di intestazione Markdown (ad es. ### o ####) prima dell'elaborazione. Non è necessario pulire manualmente il file.

Modalità Storia: raggruppamento automatico dei turni in scene (da v15.1)

Se carichi nell'Architetto un file opowiesci/<gra>.txt generato dal modulo Storie Interattive, il convertitore riconoscerà i marcatori di turno (ad es. „--- Turno 7 ---") in 9 lingue (Turno, Turn, Runde, Turno, Vuoro, Tour, Umferð, Turno, Ход) e ogni cinque turni inserirà una nuova intestazione di primo livello in forma di „Scena N" (il numero parte da 1, locale per la lingua — in inglese „Scene N", in tedesco „Szene N" ecc.). Gli altri marcatori di turno vengono eliminati — non appaiono nella narrazione dell'audiolibro, poiché „Turno 7" pronunciato da TTS interrompe l'immersione dell'ascoltatore. Il risultato è un file Word con una suddivisione naturale in scene di pochi minuti audio ciascuna, pronto per l'importazione in ElevenLabs. Il meccanismo è auto-detectante — i file di audiolibri normali senza marcatori di turno (narrazione classica dal Regista) vengono elaborati esattamente come prima.

Vantaggio potente per gli utenti NVDA e ElevenLabs

Il formato "Heading 1" per i capitoli non è solo estetica. In NVDA puoi navigare rapidamente tra le intestazioni premendo il tasto H (o 1 per le intestazioni di primo livello). Invece di scorrere centinaia di pagine, salti da un capitolo all'altro in una frazione di secondo. Questo cambia il modo di lavorare con documenti lunghi. In ElevenLabs hai la certezza che il motore inserirà automaticamente i tagli e non si bloccherà durante la regia dei clip audio.


PASSO 7: Come scrivere il Libro del Mondo (Prompt dell'Architetto e Mini-corso Markdown)

L'intelligenza artificiale che alimenta lo Studio Principale comprende meglio i comandi quando sono formattati nel linguaggio di markup Markdown. Se fornisci all'AI in Regista solo un'idea vaga (ad es. "due sorelle nell'aldilà"), la macchina andrà in panico per mancanza di dettagli e creerà una storia banale e prevedibile, ignorando la logica.

Per evitare ciò, usa un chatbot esterno (ad es. il gratuito ChatGPT o Claude) come tuo Architetto personale. Nella versione 13.0 non devi più riscrivere il prompt dalle istruzioni — nel pannello di Regista, appena sotto il pulsante "💾 Salva il Libro in modo permanente", troverai il pulsante "📖 Prompt dell'Architetto per AI…". Cliccalo e si aprirà una finestra di dialogo con il testo del prompt pronto nel campo "solo lettura" e un pulsante "Copia negli appunti". NVDA annuncia tutto il contenuto non appena si apre la finestra — basta cliccare "Copia", incollare (Ctrl+V) in ChatGPT/Claude e sostituire il frammento "[INSERISCI QUI LA TUA IDEA]" con il tuo spunto di trama.

Perché così e non copiando dalle istruzioni? Il dialogo nell'interfaccia grafica ha un vantaggio chiave di accessibilità: è nativo e letto senza interruzioni dal lettore di schermo, non richiede di passare a un editor di testo (dove le "lettere accentate" italiane e le virgolette possono essere copiate male) e funziona identicamente su ogni sistema operativo. Lo stesso schema — dialogo con il prompt da copiare — è utilizzato anche nel Manager delle Regole (vedi PASSO 7b sotto).

Come risponde l'AI: In risposta riceverai un testo in due parti. La prima è il Libro del Mondo racchiuso in un blocco di codice Markdown (marcatori ```markdown … ```). Copia SOLO il contenuto del blocco di codice (senza i marcatori ```) e incollalo nel campo "Libro del Mondo" in Regista, quindi clicca "💾 Salva il Libro in modo permanente". La seconda parte è una raccomandazione su quale dei modi creativi (Script o Audiolibro) si adatta meglio alla tua idea — considerala come un suggerimento quando selezioni la modalità nel RadioBox.

Mini-corso Markdown nel Libro: un singolo cancelletto (#) è la sezione principale (ad es. "# Personaggi"), un doppio cancelletto (##) è una sottosezione, i trattini (-) creano elenchi, e le doppie asterischi (**testo**) evidenziano regole assolute e inviolabili (ad es. "**L'eroe NON mente MAI**"). Per un personaggio di lingua straniera aggiungi un tag con l'accento, ad es. "[Speaker 1: Marek] - ha un accento francese". La parola chiave "accento" è NECESSARIA — il motore dell'applicazione la rileva automaticamente e applica le corrette regole fonetiche ai dialoghi del personaggio.

Suggerimento: Ricorda di aggiornare di tanto in tanto il tuo Libro del Mondo (con l'espansione della trama in nuovi luoghi o personaggi importanti). Puoi farlo manualmente o con l'aiuto di un chatbot esterno. Più ricco è il fondamento, migliori saranno i risultati in Regista!

PASSO 7b: Gestore delle Regole (Ctrl+4) — dizionari per linguisti senza Python

La versione 13.0 introduce il quarto strumento nella barra: il Gestore delle Regole. Lo apri con il tasto Ctrl+4 o dal menu Strumenti. È un esploratore visivo della cartella dictionaries/, dove l'applicazione conserva tutte le regole fonetiche (accenti), cifrari e modalità del Regista in file YAML (formato leggibile dall'uomo, più semplice di JSON).

Perché YAML? Fino alla versione 12.0 tutti gli accenti, le modalità creative e i filtri erano "incorporati" nel codice Python. Aggiungere un nuovo accento richiedeva un programmatore. Nella versione 13.0 tutto è stato spostato nei file .yaml nella cartella dictionaries/ — chiunque sappia aprire il Blocco Note può regolare un accento esistente ("sostituisci sz con sh con sch") o aggiungerne uno completamente nuovo (svedese, danese, dialetto russo).

Cosa troverai nel Gestore delle Regole:
- Albero dei file — elenco completo di tutti i file YAML in dictionaries/ suddivisi per lingue di base (attualmente completamente implementate: Polski, Deutsch, English, Español, Suomi, Français, Íslenska, Italiano, Русский) e cinque categorie: akcenty/ (fonetica per TTS), szyfry/ (giochi di testo), rezyser/ (modalità creative e post-produzione), gui/ (traduzioni UI) e opowiesci/ (modalità del modulo Storie, aggiunte nella 15.2.4). Navigazione con le frecce come in Esplora file di Windows, pieno supporto NVDA.
- Pulsante „📝  Apri nell'editor di testo" — apre il file selezionato nel Blocco Note predefinito del sistema. Modifichi, salvi, clicchi „🔄  Aggiorna albero" ed è fatto.
- Pulsante „📋  Duplica file selezionato" — la via più veloce per un nuovo accento: prendi un file esistente (ad es. finski.yaml), dai un nuovo nome (ad es. svedese), il Gestore crea una copia con il commento "cambia i campi etichetta e descrizione" e lo apre nell'editor.
- Pulsante „➕  Nuovo file regole…" — creatore con scelta del tipo (accento, cifrario, modalità Regista, nuova lingua di base, cifrario algoritmico). Per i casi comuni (accento, cifrario tipo "sostituzione lettere") il creatore genera un modello YAML pronto per la modifica. Per i casi che richiedono un programmatore (nuova lingua di base, algoritmo tipo "mescolamento del centro delle parole") il creatore genera un prompt per il chatbot AI — lo incolli in ChatGPT, ottieni un file YAML pronto, lo salvi in dictionaries/ ed è fatto.

Applicazione pratica: Vuoi aggiungere un accento svedese? Apri il Gestore delle Regole, scegli dictionaries/pl/accenti/finski.yaml, clicca "Duplica", nomina il file svedese, cambia nel campo etichetta in "Svedese (Alva / Oskar)", il codice iso in sv, modifica alcune regole di sostituzione e salva. Torna alla Pagina principale e riavvia l'applicazione. Il nuovo accento apparirà nel menu Poliglotta (in Modalità Regista) e — se lo aggiungi al Libro del Mondo dei personaggi ("[Marek] - ha accento svedese") — anche nel rilevamento automatico degli accenti del Regista.

Dove cercare ulteriore documentazione della cartella dictionaries/:
- File `docs/dictionaries.pl.txt` (disponibile nel pacchetto per gli utenti finali dalla scheda Releases) — breve descrizione in linguaggio semplice di ogni sottocartella, 6 cifrari pronti, 8 accenti pronti e idee su cosa si può fare da soli, senza conoscenza di Python.
- File `dictionaries/README.md` (disponibile solo clonando il repository da GitHub — i pacchetti di rilascio filtrano i file .md) — documentazione tecnica dettagliata del formato YAML con esempi, elenchi di campi, regole del pipeline, regex. Questo documento è indirizzato a linguisti con conoscenze di base di programmazione e a sviluppatori.


Indicazioni importanti per gli utenti dei lettori di schermo (NVDA)

1. Messaggi di successo ed errore

Quando l'applicazione termina un'operazione (ad es. salva un file o incontra un errore), comparirà una finestra di dialogo con un titolo come "Successo", "Avviso" o "Errore". NVDA annuncerà subito la finestra e ne leggerà il contenuto. Non devi fare nulla — le finestre di dialogo sono pienamente accessibili da tastiera e il focus atterra automaticamente sul pulsante "OK". Non ci sono più trucchi con il prefisso "Alert" — le finestre di dialogo native di wxPython sono gestite direttamente dal lettore di schermo.

2. Avviso importante: elaborazione silenziosa in background

Dopo aver cliccato pulsanti come "Invia all'AI" o "Avvia Elaborazione", il programma avvia immediatamente l'elaborazione in background. Sullo schermo appare una barra di avanzamento (Gauge), ma NVDA NON ne legge il valore in tempo reale — il lettore di schermo resta in silenzio durante il lavoro. Non cliccare di nuovo il pulsante. Attendi finché non compare la finestra di dialogo con il risultato o con il messaggio di errore — NVDA la annuncerà automaticamente.

3. Navigazione tra gli strumenti

Lo spostamento tra gli strumenti (Regista, Poliglotta, Convertitore, Gestore delle Regole) avviene in un'unica finestra del programma tramite quattro pulsanti sulla barra degli strumenti o tramite il menu Strumenti (Alt, poi N). Scorciatoie da tastiera disponibili: Ctrl+0 (Pagina iniziale), Ctrl+1 (Regista), Ctrl+2 (Poliglotta), Ctrl+3 (Convertitore), Ctrl+4 (Gestore delle Regole — novità nella 13.0). Dopo aver cambiato strumento il focus atterra automaticamente sulla descrizione del nuovo modulo — NVDA inizia subito a leggere la nuova vista.

4. Ordine di tabulazione e nomi dei widget

Ogni elemento dell'interfaccia ha un nome chiaro in italiano — NVDA lo leggerà al momento del focus. L'ordine di tabulazione è logico: dalla descrizione dello strumento, attraverso i campi di configurazione, fino ai pulsanti d'azione. Non ci sono sorprese — la navigazione da tastiera funziona come in qualsiasi altro programma nativo di Windows. Tutti i menu e i pulsanti sono in italiano e NVDA li leggerà con una voce italiana senza alcuna impostazione aggiuntiva.

Nuove funzionalità e modifiche nella versione 9

Salvataggio del progresso di traduzione resistente ai crash (MODIFICA — correzione di un bug critico)
Nella versione 8, la ripresa di una traduzione interrotta nascondeva una trappola silenziosa e distruttiva: se l'utente seguiva le istruzioni (ritagliando manualmente il frammento già tradotto) e poi riprendeva immediatamente la traduzione del resto, l'applicazione apriva il file di output in modalità sovrascrittura — cancellando irrimediabilmente e inconsapevolmente tutto il progresso pagato. Nella versione 9 l'intero meccanismo è stato riprogettato. Ogni blocco tradotto viene ora salvato immediatamente in un file temporaneo (.jsonl) con un indice assegnato. La ripresa è completamente automatica — l'applicazione rileva da sola il file e ripristina il progresso senza alcun intervento dell'utente. Al termine con successo, il file temporaneo viene eliminato automaticamente.

Correttore di Tag nella Modalità Regista (NOVITÀ)
Al menu della Modalità Regista è stata aggiunta una nuova opzione — il Correttore di Tag. Inietta nel file esclusivamente il codice di lingua ISO di due lettere indicato dall'utente, senza applicare alcuna regola fonetica né pulizia. È uno strumento di emergenza nel caso in cui un file già pronto sia uscito con un tag di lingua errato o mancante.

Conversione automatica da .txt a .html nella Modalità Traduttore (MODIFICA)
I file di testo (.txt e .md) tradotti dal Traduttore AI vengono ora salvati automaticamente in formato .html con un tag di lingua incorporato. In questo modo NVDA legge subito il file con la voce corretta — senza alcun passaggio aggiuntivo da parte dell'utente.

Denominazione intelligente del file nell'Architetto (MODIFICA)
L'Architetto degli Audiolibri non salva più il file risultante sempre con lo stesso nome architektura_gotowa.docx. Ora il nome deriva dal file di input — ad esempio, per znieczulica.txt il file risultante è architektura_znieczulica.docx. Il file appare nella stessa cartella dell'originale.

Funzionalità mantenute senza modifiche dalla versione 8

Ritorno al formato .txt per i file di progetto (MODIFICA)
I file di progetto e i riassunti vengono ora salvati in formato .txt invece di .md (Markdown). L'esperimento con il formato .md come barriera psicologica contro la modifica si è rivelato inefficace — l'IA infrange spesso e notoriamente la regola anti-closure, ed è spesso meglio modificare il file al volo e poi ricaricare la memoria affinché l'IA, per quanto possibile, non riceva un permesso nascosto di violare il divieto. Il formato .txt è più intuitivo e leggibile per tutti.

Regola del Montatore — nuovo avviso
Nelle istruzioni (e nelle future versioni dell'interfaccia) è stato aggiunto un avviso chiaro che spiega cosa si può e cosa non si può modificare nei file di progetto. L'utente ha pieno diritto di modificare dialoghi e contenuti, ma non può assolutamente modificare le righe di struttura (Atto, Scena, Capitolo, Prologo, Epilogo) — il loro danneggiamento rovina la navigazione di NVDA, la suddivisione in ElevenLabs e l'indice in Word.

Prompt dell'Architetto aggiornato (MODIFICA)
Il prompt per il chatbot esterno (ChatGPT/Claude) è stato riprogettato. Invece di restituire codice Markdown grezzo, l'IA ora restituisce la risposta in due parti chiaramente separate: la Parte 1 è il Libro del Mondo racchiuso in un blocco di codice Markdown (facile da copiare senza marcatori), e la Parte 2 è la Raccomandazione di Modalità come testo semplice fuori dal blocco — consiglia se sia meglio usare la Modalità Script Grezzo o la Modalità Audiobook Tradizionale. È stata cambiata anche la descrizione dei tag dei personaggi: invece di "sonori", ora si parla di accento e tono di voce nel tag, ad es. [Speaker 1: Nome] - blesa e accento francese.

Spiegazione dello stato della direttiva Anti-Closure (DOCUMENTAZIONE)
Le istruzioni includono ora una spiegazione sincera del fatto che, nonostante i divieti Anti-Closure incorporati, il modello infrange ancora notoriamente questa regola, soprattutto nella Modalità Audiobook. Invece di nascondere questo problema, la versione 8 mette le cose in chiaro e restituisce la responsabilità della "chiusura manuale" al Regista — da qui la Regola del Montatore come strumento di lavoro ufficiale e il ritorno al normale formato testo.

- Accento russo nel Poliglotta (NOVITÀ — ottava lingua europea nel menu Modalità del Regista). Alla lista a discesa "Modalità del Regista / Accenti" si aggiunge l'opzione "Russo (es. Milena / Irina / Yuri / Pavel)". A differenza degli altri accenti, che "distorcono" solo il testo italiano a livello di lettere latine (es. "sz" → "sh", "w" → "v"), l'accento russo esegue una completa traslitterazione del testo italiano in cirillico — in questo modo le voci del sintetizzatore TTS in lingua russa (Vocalizer Milena, OneCore Irina / Pavel / Yuri, eSpeak "ru") hanno su cosa "pronunciare" le parole. È stato arricchito il mapping con le vocali iotate ("ja" → "я", "je" → "е", "jo" → "ё", "ju" → "ю"), le ammorbidimenti italiane si/ci/ni/zi + vocale (es. "ciocia" → "цёця"), così come i digrammi speciali russi: "ść" / "szcz" → "щ", "sz" → "ш", "cz" → "ч", "rz" → "ж", "ch" → "х".

  Nota fonetica: L'accento non è una traslitterazione accademica russa (ISO 9, GOST, BGN/PCGN). L'obiettivo è solo di rendere il testo italiano simile al russo a livello fonetico — per esigenze di sintesi vocale, non per una seria traslitterazione di nomi propri. Per quest'ultimo lavoro, usa strumenti linguistici dedicati.

  Codice lingua per il file di output: "ru" (ISO 639-1). NVDA con l'opzione "Cambia lingua automaticamente quando supportato" si commuta immediatamente alla voce russa.

- Nota su "ź": In russo non esiste un equivalente esatto del "ź" italiano, quindi questo segno viene normalizzato a "ж" — simile a "ż". Alcuni dialetti del nord russo e il bielorusso pronunciano "ź" più vicino a "зь", ma dal punto di vista del sintetizzatore vocale la differenza è trascurabile. Se un linguista ritiene di preferire "зь", può sostituire autonomamente questa singola regola nel file `dictionaries/pl/akcenty/rosyjski.yaml` — il motore carica i YAML dinamicamente, quindi non richiede la ricompilazione dell'applicazione.

PASSO 7b (completamento): L'ordine delle regole `zamiany:` è importante

I file in `dictionaries/<kod>/akcenty/*.yaml` contengono un elenco di regole `zamiany:` — coppie `wzor → zamiana`, che il motore applica SEQUENZIALMENTE. Ogni regola successiva opera sull'output della precedente. Questo permette di costruire pipeline del tipo "scomponi il digramma `szcz` in `shch`, e poi sostituisci `ch` con `h`", ma apre anche la classica trappola per l'autore del pacchetto linguistico.

La trappola del "ciclo sequenziale". Supponiamo che per l'accento spagnolo, che deve far somigliare la pronuncia polacca di "ñ" a quella di Diego (Loquendo), l'autore aggiunga due regole:
1. `ñ → nj` (per far suonare la "ñ" polacca come una morbida "nj")
2. `j → x` (per far suonare la "j" polacca come la "j" spagnola — foneticamente /x/)

Dopo l'esecuzione, si scopre che le parole con "ñ" vengono pronunciate come "nx", non "nj". Perché? Perché quando la prima regola sostituisce "ñ" con "nj", la nuova "j" viene immediatamente catturata dalla seconda regola e sostituita con "x". Risultato: invece del previsto "ñ → nj", otteniamo "ñ → nx".

Regola dell'ordine (universale). Quando una regola introduce un carattere che un'altra regola ha come modello, L'ORDINE CONTA. Un'euristica sicura: PRIMA sostituisci il TARGET (carattere usato successivamente come `wzor` in un'altra regola) con qualcosa di sicuro, POI introduci il SOURCE (carattere che deve scomporsi nel TARGET). Per l'esempio spagnolo correttamente: prima `j → x`, poi `ñ → nj`. Risultato: "ñ" diventa "nj" (la seconda "j" non verrà più catturata, perché la regola `j → x` è stata applicata prima, quando "nj" non esisteva ancora).

Come testare. Dopo aver cambiato l'ordine delle regole nel file dell'accento, passa una frase contenente ENTRAMBI i caratteri attraverso il Modalità Regista. Per esempio ES: "Niño de paja juega" → il risultato deve avere sia l'accento ñ ("ñ → nj"), sia l'accento j ("j → x"), quindi qualcosa come "Ninjo de paxa xuega". Se vedi "ninxo" invece di "ninjo" — l'ordine è invertito.

Validazione nel motore (opt-in per gli autori dei pacchetti). L'applicazione ha un'euristica incorporata che rileva potenziali cicli, ma è disattivata per impostazione predefinita — perché molte pipeline sembrano cicli, anche se sono intenzionali (il classico "szcz → shch" + "ch → h"). Per attivarla: imposta la variabile d'ambiente `REZYSER_VALIDATE_ZAMIANY=1` e avvia l'applicazione dalla console — dalla sorgente tramite `python main.py`, perché l'eseguibile congelato `.exe` in modalità finestra (dalla versione 17.0) non ha una finestra console. Il motore stamperà per ogni file di accenti una riga aggregata WARN con i primi tre potenziali cicli e il numero degli altri. Controlla la fonetica risultante sulla frase di test — se l'effetto è quello desiderato, ignora il WARN.

I pulsanti per spostare le regole nel GUI del Gestore delle Regole (drag-and-drop, "Su / Giù") sono una funzione separata pianificata per un ciclo di versione successivo — richiede una riprogettazione del Gestore (attualmente delega l'editing del file a un Blocco Note esterno di sistema, e non ha una propria vista delle regole). Fino alla sua implementazione: modifica manualmente il file YAML, sposta le righe nella sezione `zamiany:`, utilizza il validatore tramite ENV-var e testa su frasi di controllo.
