Reżyser Audio GPT — Guía Completa (Versión 18.18.0 – Versión de Lanzamiento)

¡Bienvenido al Estudio de Grabación Híbrido! Este conjunto de herramientas permite la escritura, planificación, formateo y traducción automática de guiones para radionovelas y audiolibros. Ha sido optimizado para trabajar con sintetizadores de voz profesionales y motores locales de lectores de pantalla (NVDA).

El conjunto consta del estudio principal (Dirección), la herramienta de traducción y acentos (Políglota), la herramienta para construir la estructura de archivos (Arquitecto de Audiolibros), el Gestor de Reglas (desde la versión 13.0 — sin Python puedes añadir un nuevo acento, cifrado o modo creativo, ver PASO 7b a continuación) y — desde la versión 15.0 — el módulo de Historias (ficción interactiva en segunda persona generada por IA, leída por TTS o lector de pantalla, descrita en un manual separado tales.es.html). Todas las cinco herramientas están disponibles en una sola ventana del programa, conmutables mediante botones en la barra o atajos de teclado Ctrl+1..Ctrl+5.

PASO 1: Primera ejecución (Cross-Platform)

Descarga el instalador más reciente desde la pestaña de Releases en GitHub (archivo Rezyser_Audio_v<número>_Installer.exe) y ejecútalo haciendo doble clic. El instalador propondrá una ubicación de instalación predeterminada — la carpeta Programs en el directorio local de tu cuenta — y no requiere permisos de administrador. También puedes elegir tu propia ruta con el botón "Examinar" — el instalador la recuerda y la usa por su cuenta en las siguientes actualizaciones, sin preguntar. Después de la instalación, inicia el programa con el ícono en el escritorio o desde el Menú de Inicio. Después de un momento, aparecerá la ventana principal del programa — Director de Audio GPT. Desde la versión 17.0, la aplicación está congelada como un archivo ejecutable nativo en modo ventana, por lo que ya no parpadea ninguna ventana de terminal y se inicia más rápido que antes. Sin navegador, sin servidor en segundo plano. Cuando termines de trabajar, simplemente cierra la ventana del programa.

Toda la aplicación, incluido el motor de Python, los proyectos y la clave API, reside en una sola carpeta bajo la ruta de instalación — toda la carpeta se puede mover a un pendrive, a la nube o a otro ordenador (instrucciones detalladas en la sección "Transferencia de proyectos y clave API" más abajo).

Importante: La carpeta runtime/ dentro de la carpeta de instalación es el bundle de PyInstaller (desde la versión 17.0) — contiene un intérprete de Python aislado y bibliotecas, listas para usar sin instalación separada del sistema; también actúa como contenedor de metadatos ocultos de proyectos. Si clonas el repositorio (ruta del desarrollador), esta carpeta no está y no debería estar — entonces usas un entorno virtual venv descrito en la sección para desarrolladores más abajo.

Para Desarrolladores (Windows — repositorio Git)

  1. Clona el repositorio en tu disco.
  2. Ejecuta el archivo setup_dev.bat. El script creará automáticamente un entorno virtual de Python (venv) e instalará todas las dependencias requeridas desde el archivo requirements.txt.
  3. Ejecuta la aplicación con el comando python main.py o a través del archivo run_dev.bat — el script detectará automáticamente la carpeta venv y ejecutará el programa.

Para Desarrolladores y usuarios comunes (macOS / Linux)

  1. Clona el repositorio en tu disco.
  2. Abre una terminal en la carpeta del proyecto y otorga permisos de ejecución a los scripts: chmod +x *.sh
  3. Ejecuta el script de configuración: ./setup_dev.sh — el script creará el entorno venv e instalará las dependencias.
  4. Ejecuta la aplicación: python main.py o ./run.sh

Qué verás al iniciar: Al iniciar el programa, se abre una ventana con la pantalla de inicio. En ella encontrarás una breve descripción de las herramientas disponibles y la sección "System Check". Si la clave API aún no está configurada, verás un mensaje rojo informando que los módulos basados en IA (Dirección, Traductor) no funcionarán — las funciones locales gratuitas (acentos, Arquitecto) están activas de inmediato. La configuración de la clave se describe en el siguiente paso.

Actualizaciones automáticas

La aplicación verifica al inicio si hay una versión más reciente disponible en GitHub — la verificación se realiza en segundo plano y no bloquea la interfaz.

Si instalaste el programa a través del archivo de instalador (.exe): al detectar una nueva versión, aparecerá una ventana preguntando si deseas descargarla. Al confirmar, se iniciará una barra de progreso y, cuando la descarga termine, la aplicación se cerrará automáticamente y el nuevo instalador se ejecutará por sí solo. No tienes que preocuparte por la ruta de instalación: el instalador reconoce la instalación anterior e instala en la misma carpeta que antes — el asistente ni siquiera muestra entonces la página de la carpeta de destino (esto vale también para una ubicación que elegiste a mano con el botón "Examinar"). La actualización sobrescribe los archivos del motor de la aplicación y todo el paquete de reglas (carpeta dictionaries/) — tus proyectos (carpetas skrypty/, opowiesci/) y la clave API (golden_key.env) permanecen intactos. IMPORTANTE: si editaste archivos existentes en el paquete a través del Gestor de Reglas (por ejemplo, cambios de acento en dictionaries/pl/akcenty/wloski.yaml), estas ediciones SERÁN SOBRESCRITAS durante la actualización — antes de confirmar la actualización, haz una copia de seguridad de la carpeta dictionaries/ según el procedimiento de la sección "Transferencia de proyectos y clave API" más abajo (basta con copiar la carpeta dictionaries/ a un pendrive), y después de la actualización, vuelve a cargarla sobrescribiendo los archivos más nuevos. Las reglas completamente nuevas que creaste desde cero y que no están en el paquete (por ejemplo, un nuevo idioma base o un cifrado propio) permanecen intactas automáticamente — el instalador no elimina archivos fuera del paquete. Desde la versión 15.2.8, el mismo diálogo que propone la actualización muestra esta advertencia directamente en el contenido y contiene un botón "Abrir carpeta dictionaries", que con un solo clic abre el Explorador en el lugar correcto — solo necesitas presionarlo antes de confirmar la actualización para hacer una copia de seguridad cómodamente, y luego volver al diálogo y hacer clic en "Descargar e instalar".

La ruta de instalación sí resulta útil para copiar archivos a mano (copia de seguridad, traslado a otro ordenador — véase la sección de más abajo). Si no la recuerdas, hay dos formas rápidas de recuperarla. Windows 11: en el menú contextual del acceso directo en el escritorio, selecciona "Abrir ubicación del archivo" (si la opción no es visible en el nuevo menú contextual simplificado, selecciona primero "Mostrar más opciones" o presiona Shift+F10 dos veces para abrir directamente el menú completo), sube un nivel con la tecla Backspace, selecciona la carpeta con la aplicación y presiona Ctrl+Shift+C (o selecciona "Copiar como ruta" en el menú contextual) — la ruta completa se copiará al portapapeles entre comillas (al pegar en el instalador, recuerda eliminar solo las comillas). Versiones anteriores de Windows (7/8/10): haz clic derecho en el acceso directo y selecciona "Propiedades"; en la pestaña "Acceso directo" en el campo "Destino" verás la ruta completa al archivo de inicio (.exe en la versión 15.2.5+ o run.bat en versiones anteriores) — cópiala y elimina el nombre final del archivo, quedará solo la ruta de la carpeta de instalación.

Nota al actualizar desde versiones anteriores (v15.2.4 o anteriores, cuando la aplicación se ejecutaba a través de run.bat desde el paquete Portable ZIP): el acceso directo existente en el escritorio puede apuntar a run.bat en la ubicación antigua, que después de actualizar a v15.2.5+ ya no existe — las versiones 15.2.5+ usan un archivo .exe independiente creado por el instalador. Si después de la actualización el acceso directo deja de funcionar, elimínalo manualmente y permite que el instalador cree uno nuevo durante la reinstalación.

Si usas el repositorio Git (desarrolladores y usuarios de macOS/Linux): en lugar de la propuesta de descarga, verás información sobre la nueva versión con un enlace directo a la página de lanzamiento en GitHub. Descarga el archivo "Source code" desde allí o actualiza el repositorio con el comando git pull.

Transferencia de proyectos y clave API (migración)

Si deseas transferir tus proyectos, clave API y configuraciones locales a otro ordenador (o restaurar todo después de reinstalar el sistema Windows), no es necesario copiar manualmente archivos individuales — toda la carpeta de la aplicación es autosuficiente.

  1. Asegúrate de que la aplicación esté COMPLETAMENTE cerrada. Si ves el ícono del programa en el área de notificación (junto al reloj, en el lado derecho de la barra de tareas), haz clic derecho y selecciona "Cerrar". Los archivos abiertos bloquean la copia.
  2. Encuentra el acceso directo Director de Audio GPT en el escritorio. Haz clic derecho en él (o con la tecla de Aplicación o Shift+F10 al navegar con NVDA) y selecciona la opción "Abrir ubicación del archivo". ATENCIÓN en Windows 11: en el nuevo menú contextual simplificado, esta opción puede estar oculta — selecciona primero "Mostrar más opciones" (o presiona Shift+F10 dos veces para abrir directamente el menú completo con la opción).
  3. Se abrirá una ventana del Explorador de Windows en la carpeta de instalación del programa. Presiona la tecla Backspace (la forma más sencilla, siempre funciona) o haz clic en la flecha "Arriba" en la barra de herramientas para subir un nivel — allí verás la carpeta completa con la aplicación. Nota: el atajo Alt+Flecha arriba solo funciona cuando el foco está en la lista de archivos — si el Explorador se abrió con el foco en la barra de direcciones (típico), Alt+Flecha arriba no hará nada, usa Backspace en su lugar.
  4. Copia toda esta carpeta a un pendrive, disco en la nube (OneDrive, Google Drive, Dropbox) o disco externo. La carpeta contiene todo lo necesario para restaurar el estado de trabajo:
    - Tus proyectos (carpeta skrypty/ — archivos .txt de narración, .md del Libro del Mundo y los archivos de resultados de las herramientas de postproducción: memoria, títulos, ficha de publicación; carpeta opowiesci/ — juegos interactivos).
    - Clave API (archivo golden_key.env en la carpeta principal de la aplicación).
    - Reglas fonéticas propias, acentos, cifrados, si editaste algo en el Gestor de Reglas (carpeta dictionaries/<código_idioma>/, por ejemplo, dictionaries/pl/akcenty/wloski.yaml).
    - Preferencias de la aplicación y selección de modos creativos (carpeta runtime/skrypty/, archivos .mode).
    - Entorno aislado de Python (carpeta runtime/), por lo que no necesitas instalar nada en el nuevo ordenador.
  5. En el nuevo ordenador: descarga el instalador más reciente desde la pestaña de Releases en GitHub e instala la aplicación de manera estándar. Inicia el programa una vez para que cree una estructura vacía de archivos de configuración. Cierra la aplicación. Luego, copia la carpeta guardada anteriormente en el lugar de instalación sobrescribiendo los archivos — o selecciona solo las carpetas que te interesen (skrypty/, opowiesci/, golden_key.env) y pégalas en los lugares correspondientes de la nueva instalación.

Consejo para usuarios de NVDA: el menú contextual "Abrir ubicación del archivo" invocado con la tecla de Aplicación es completamente accesible — NVDA lee cada posición en polaco. Después de abrir el Explorador en la carpeta de destino, usa la tecla Backspace para subir un nivel (siempre funciona, independientemente de si el foco está en la lista de archivos o en la barra de direcciones), luego Ctrl+A para seleccionar todo y Ctrl+C para copiar.

Consejo: la opción "Abrir ubicación del archivo" es el nombre nativo para la versión polaca de Windows. En el sistema en inglés es "Open file location", en otras versiones de idioma — de manera análoga en el idioma local del sistema operativo.

PASO 2: Configuración de la API (clave Anthropic / Claude recomendada)

El proveedor de IA recomendado y predeterminado es Anthropic (Claude) — todos los prompts de la aplicación están optimizados para él, por lo que ofrece la mayor calidad narrativa y el mejor respeto a las reglas del mundo. En esta variante (recomendada) basta con UNA SOLA clave API en el archivo golden_key.env:

• Clave Anthropic (Claude) — alimenta TODO el motor de IA: la narración del Director (audiolibro, teatro leído, lluvia de ideas), el modo Historias, el Políglota (traductor) y la asignación de títulos a capítulos y la detección del idioma del contenido. Comienza por sk-ant-.

Si estás actualizando desde una versión anterior: la antigua clave OpenAI ya no es necesaria para la variante predeterminada — puedes dejar o eliminar su línea en golden_key.env, la aplicación la ignorará (a menos que estés configurando conscientemente otro proveedor — véase el PASO 2B más abajo).

Cómo obtener la clave Anthropic:
1. Crea una cuenta en console.anthropic.com y añade fondos (pestaña Billing / Plans).
2. Genera la clave en la sección API Keys (comienza por sk-ant-). Cópiala de inmediato — en ocasiones solo se muestra una vez.

Cómo introducir la clave en el programa:
3. En la pantalla de inicio del programa, haz clic en el botón "Generar archivo golden_key.env y abrir editor de texto". El sistema creará automáticamente un archivo de configuración limpio en el lugar correcto y abrirá el Bloc de notas con una plantilla lista para editar.
4. En el archivo abierto verás la línea: ANTHROPIC_API_KEY=PASTE_YOUR_KEY_HERE. Elimina el texto de marcador de posición y pega tu clave directamente después del signo igual (sin espacios ni comillas). Guarda el archivo y reinicia la aplicación.

Consejo: Tras reiniciar, la aplicación comprobará el archivo y en la sección "System Check" mostrará el estado de la clave. Debe aparecer en verde para que todos los módulos de IA estén listos para funcionar. Si la clave falta o es incorrecta, el programa lo indicará claramente y permitirá abrir el editor de texto para corregir el error rápidamente.

PASO 3: El Estudio de Dirección Principal

Este es tu centro de mando para idear historias y escribir guiones. Accede a él haciendo clic en el botón "🎬 Director" de la barra de botones o seleccionando Herramientas → Director en el menú (atajo: Ctrl+1).

Importante: Formato de archivos de proyecto — regreso a .txt

En la versión 7, los archivos de proyecto se guardaban en formato Markdown (.md), por ejemplo skrypty/znieczulica.md. Fue un experimento deliberado: el formato .md debía actuar como barrera psicológica para personas no técnicas, disuadiéndolas de abrir y editar manualmente el archivo en el Bloc de notas (y así dañar accidentalmente los encabezados de estructura).

El experimento no funcionó. La IA infringe con frecuencia y de forma flagrante una de las prohibiciones fundamentales (más sobre esto en un momento). Por esa razón, en la versión 8 se volvió a los simples archivos .txt, más intuitivos y legibles para todos. Por ejemplo, un proyecto llamado "znieczulica" se guardará ahora como skrypty/znieczulica.txt, y su resumen como skrypty/znieczulica_streszczenie.txt. Esto permitirá a cualquiera introducir más fácilmente correcciones de dirección o cortes de texto sobre la marcha.

⚠️ Regla Crítica del Montador (¡lee esto antes de empezar!)

Todos tus guiones y libros generados se guardan en archivos de texto plano (.txt) que puedes abrir fácilmente en el Bloc de notas.

Como Director tienes PLENO DERECHO (y prácticamente la obligación) de editar ese archivo. Si la inteligencia artificial se desboca y, por ejemplo, resuelve por su cuenta el conflicto de los personajes al final del fragmento generado, abre el archivo, elimina las últimas líneas y deja el texto cortado en el momento de mayor tensión; luego haz clic en "Recargar proyecto desde el disco" para sincronizar la memoria del modelo con el archivo corregido, y en "Enviar a la IA" para continuar.

🔴 Sin embargo — lo que no debes tocar

Nunca modifiques, elimines ni alteres las líneas que contienen la estructura (p. ej., Acto 1, Escena 2, Capítulo 1, Prólogo). Si estropeas esos encabezados:
1. Tu historia se desmoronará en los lectores de pantalla (NVDA).
2. El Arquitecto de audiolibros, y por tanto también ElevenLabs Studio, no podrá dividir correctamente tu libro en fragmentos para su lectura.
3. El Convertidor interno de la aplicación no generará un índice correcto en el archivo Word ni en la línea de tiempo de ElevenLabs.

¡Edita los diálogos, corta la acción, pero deja la estructura en paz!

¿Cómo usar la Dirección?

  • Libro del Mundo (barra lateral izquierda): Aquí escribes las reglas del universo. Cada proyecto tiene ahora su propio Libro vinculado al nombre del archivo — si tu archivo de historia es, por ejemplo, emilia_heist_audiobook.txt, el Libro del Mundo se guardará como skrypty/emilia_heist_audiobook.md. Por eso el orden importa: primero escribe el nombre del archivo del proyecto en el campo "Nombre del archivo de proyecto" y solo entonces podrás guardar el Libro. El botón "💾 Guardar Libro permanentemente" permanece en gris hasta que introduzcas el nombre. Cargar un proyecto existente con el botón "Cargar historia" también cargará automáticamente el archivo .md correspondiente — no necesitas hacer nada manualmente. Nota: Sin el Libro del Mundo relleno, la aplicación bloqueará el envío de consultas a la IA — es una protección deliberada que te impide generar texto sin ninguna regla.
  • Memoria a Largo Plazo (barra lateral izquierda): El segundo campo de la barra lateral. Aquí llega el resumen de la trama — generado con la herramienta del panel de postproducción (PASO 4) o, al alcanzarse el nivel de alarma de memoria, de forma automática. También puedes escribir aquí tus propias notas manualmente — el modelo las tratará como "lo que ya sé" antes de leer la escena actual. LAGUNA HISTÓRICA (corregida en v15.5): antes, si escribías aquí una nota muy breve y hacías clic en "Guardar Resumen" antes de que hubiera algo significativo en el archivo de narración, en la siguiente carga la aplicación PRIORIZABA el resumen y OMITÍA la historia completa — el modelo recibía entonces solo el Libro del Mundo y una nota de una frase, sin el contexto del tono ni de las últimas escenas. Desde v15.5 la carga es inteligente: si toda la historia cabe en la ventana de contexto, se carga íntegramente (y el antiguo resumen innecesario se elimina), de modo que el modelo no pierde contexto. Tras editar manualmente el archivo de narración en el editor, usa el nuevo botón "Recargar proyecto desde el disco" (desde v15.5), que con un solo clic sincroniza la memoria interna con el disco; para abrir el archivo en el editor sigue usando "Abrir archivo de narración…".
  • Modo Lluvia de Ideas: Escribe una idea suelta y la IA te dará 3 opciones de desarrollo de la trama. Para cada opción generará de inmediato un bloque listo "--- BORRADOR DE PROMPT ---". Una vez que elijas una, pega ese prompt en el Modo Guion o Audiolibro e introduce los comentarios o información adicional para el modelo. La memoria de la trama no cambia durante la Lluvia de Ideas — ¡puedes experimentar sin riesgo!
  • Modo Guion en Bruto (desde v16.0 — teatro leído): Aquí pegas el "BORRADOR DE PROMPT" generado en la Lluvia de Ideas. La IA escribirá un largo fragmento narrativo-dialogado: narración (escenario, tiempo, acción) en etiquetas [Narrator: ...] y los parlamentos de los personajes en etiquetas [Nombre: emoción]. Sin efectos de sonido — el contexto lo transmite el narrador con palabras. El texto se añade automáticamente a tu archivo (p. ej., nowa_scena.txt) en la carpeta skrypty/. Ese guion terminado puedes convertirlo después en un audiolibro con múltiples voces (puente a ElevenLabs Studio — capítulo aparte más adelante).
  • Modo Audiolibro Tradicional: Modo para escritores. La IA genera prosa literaria pura — sin etiquetas, sin fonética, diálogos clásicos integrados en la narración. El texto se añade al archivo igual que en el Modo Guion.
  • Creación automática de personajes: El guion está programado para crear automáticamente nuevas etiquetas [Speaker] si la trama requiere un nuevo personaje. Consejo: ¡Si la IA crea un personaje interesante, copia su etiqueta y pégala en el Libro del Mundo para que el modelo lo recuerde de forma permanente!

Gestión del proyecto — tres botones de acción:
- Cargar historia: Carga un proyecto existente en la memoria. Disponible cuando la memoria actual está vacía. Desde la versión 15.2.3 admite dos rutas: si el campo del nombre del proyecto está vacío, se abre un diálogo de selección con la lista de todos los proyectos encontrados en la carpeta skrypty/ (omite los archivos de resumen) — NVDA lee la lista de forma natural, el usuario no necesita recordar ni teclear el nombre. Si el campo del nombre está relleno, la aplicación intenta cargar directamente el proyecto con ese nombre (ruta experta: Enter en el campo del nombre o clic tras escribirlo de memoria).
- Cerrar Proyecto (Reinicio Completo): Limpia el proyecto por completo. Elimina la historia, el resumen, el Libro del Mundo y pone a cero todos los contadores. Úsalo al cambiar de proyecto o al comenzar una nueva historia.
- Abrir archivo de narración… (desde v15.2.3): Edición de emergencia del archivo de narración en el editor de texto del sistema. Requiere que el nombre del proyecto esté introducido. La aplicación abre skrypty/<nazwa>.txt en el Bloc de notas (Windows), TextEdit (macOS) o el editor GUI predeterminado (Linux). Escenarios típicos: (a) la IA no cierra la escena y quieres añadir el final manualmente; (b) cargaste el proyecto con el resumen y quieres copiar las últimas escenas a la Memoria a Largo Plazo para que el modelo tenga el contexto completo del tono (laguna arquitectónica descrita anteriormente); (c) quieres hacer un corte de texto en medio de un capítulo que el motor de la aplicación no admite de forma nativa.

  • Recargar proyecto desde el disco (desde v15.5, reconstruido en v17.6): Recarga el proyecto COMPLETO desde el disco tras la edición manual del archivo de narración — es una recarga real, no solo un refresco de la memoria actual. Recalcula los contadores de Capítulos/Actos/Escenas, recupera el Libro del Mundo, el modo y las opciones de Lluvia de Ideas, y sincroniza la memoria de trabajo. Si toda la historia cabe en la ventana de contexto, la carga íntegramente (y elimina el antiguo resumen innecesario para que el motor trabaje con el texto completo). Si la historia es larga y tiene un resumen guardado, lo conserva intacto y te pregunta desde qué encabezado debe arrancar la memoria de trabajo de la IA: en el modo Audiolibro eliges el Capítulo; en el modo Guion, primero el Acto y luego la Escena de ese acto (o el Acto completo) — el resto queda representado por el resumen. Cancelar la selección = corte de emergencia al último fragmento de texto (por eso conviene mantener la estructura de encabezados). Antes de sobrescribir los campos con la versión del disco, avisa si tienes contenido sin guardar en ellos. Escenario típico: la IA cerró incorrectamente la escena (infringió el anti-closure), tú cortas el final erróneo en el editor y haces clic en Recargar — sin más correcciones en dos sitios distintos.

Nota histórica — por qué los modos están ahora protegidos contra cambios accidentales:
En versiones anteriores de la aplicación nadie vigilaba la coherencia del modo creativo dentro de un mismo proyecto. El resultado era una curiosa posibilidad creativa que podría describirse así: empiezas la historia en Modo Guion, insertas "Acto 1" y "Escena 1" (la aplicación encantada con tu coherencia), generas varias pantallas de tensión con etiquetas [SFX: Portazo] y [Speaker 1: Marek - resignado]... y entonces — porque justo te llega la inspiración — haces clic en "Insertar corte Capítulo 1". La aplicación, sin pestañear, añade el encabezado "Capítulo 1" al archivo, justo después de "Escena 3". Tienes ahora en el archivo un híbrido entre una radionovela de los años 50 y una novela costumbrista. ElevenLabs mira esa estructura, ve un encabezado de capítulo en medio de un acto y decide que probablemente es un error en la matrix. El índice parece obra de un artista de vanguardia. El Arquitecto de Audiolibros, por su parte, parte de la base de que eres una persona adulta y simplemente lo procesa sin decir nada — pero también sin ninguna garantía de resultado. Desde la versión 12.0 la interfaz intentaba bloquear el cambio de modo de escritura — al menos en teoría. La práctica resultó ser más creativa: la Lluvia de Ideas (siempre activa como modo de planificación) era la puerta trasera por la que, con las flechas arriba y abajo, se podía pasar entre Guion y Audiolibro (Audiolibro → Lluvia → Guion y análogamente en sentido inverso). El primer clic en "Insertar Acto 1" o "Insertar Capítulo 1" en el modo recién seleccionado sobrescribía sin problemas el archivo .mode, mezclando actos con capítulos en un mismo archivo de narración. Solo desde la versión 15.2.3 existe una protección real: una vez consolidada la decisión de modo (primera estructura o primer envío de producción exitoso), la segunda opción de escritura en el selector de modo queda efectivamente bloqueada. La Lluvia de Ideas permanece siempre activa como modo de planificación — propone opciones argumentales — pero ya no es posible saltar a través de ella a otro modo de escritura. (Desde la versión 18.13 la Lluvia de Ideas ya no resume nada; esa tarea la asumió la herramienta de Memoria a Largo Plazo del panel de postproducción.)

Prompts de Showrunner — la IA como guionista de serie (desde la versión 7, conservado)

Este es el mayor cambio introducido en la versión 7, conservado sin modificaciones. No es visible en la interfaz, pero cambia radicalmente la calidad de la trama generada.

El showrunner es, en la industria televisiva, la persona responsable del conjunto de una serie — se encarga de que la trama nunca avance hacia una resolución fácil, sino que se densifique constantemente, acumule conflictos y mantenga al espectador en tensión durante varias temporadas. En la versión 7 esta filosofía quedó integrada directamente en las instrucciones del sistema de la IA.

La Directiva Anti-Closure — y lo que cambió el motor Anthropic (Claude)

La filosofía del Showrunner se aplica mediante la directiva Anti-Closure integrada en cada modo: prohibición de cerrar escenas con resúmenes, moralejas y falsos finales felices. En la era anterior (modelo GPT) ocurría exactamente lo contrario que hoy — el motor infringía sistemáticamente esta prohibición y "cerraba" la historia en cada oportunidad: intercalaba frases que resumían la trama, creaba falsos finales felices o cerraba tramas en mitad de un capítulo, como si cada fragmento fuera el último. Desde la versión 18 todo el motor de IA trabaja por defecto con Anthropic (Claude) — y desde la versión 18.4 puedes indicar opcionalmente tu propio proveedor (PASO 2B) — y Claude respeta el Anti-Closure de forma mucho más rigurosa.

Esto ha generado un efecto secundario puramente técnico: dado que el modelo no cierra la escena de forma consistente, su respuesta puede alcanzar el límite de longitud de una sola respuesta y cortarse a mitad de frase (o incluso a mitad de palabra). La aplicación lo gestiona sola — cuando detecta que el fragmento se ha cortado por el límite, con una breve consulta adicional cierra la última frase de modo que suene natural en el idioma de tu historia, y solo entonces guarda el texto. Si por algún motivo no se logra ajustar, verás una advertencia discreta y el texto se guardará igualmente en su estado actual — el guardado nunca se bloquea, el final cortado siempre puedes pulirlo manualmente.

La regla del montador descrita anteriormente sigue vigente sin cambios: si aun así el modelo cierra la escena con demasiada suavidad, es tu derecho (y prácticamente tu obligación) como Director abrir el archivo .txt, eliminar esas últimas frases, dejar el texto cortado en el momento de mayor tensión y hacer clic en "Recargar proyecto desde el disco" para sincronizar la memoria con el archivo corregido.

Cada modo tiene integrada la directiva Anti-Closure:

  • Lluvia de Ideas: La IA actúa como guionista de una serie de varias temporadas. Cada una de las 3 opciones propuestas DEBE acumular obstáculos, introducir nuevos dilemas, tramas abiertas y cliffhangers. Prohibición absoluta de proponer opciones en las que los personajes se reconcilian definitivamente, superan el obstáculo principal sin consecuencias importantes o la historia avanza hacia un final apresurado. Prohibición de inventar localizaciones baratas y mágicas que rompan la arquitectura del mundo.
  • Modo Guion en Bruto: Prohibición absoluta de terminar el texto con resúmenes, moralejas o cierres narrativos. La IA debe cortar la acción de forma natural en un momento de tensión (cliffhanger), evitando conclusiones para que el siguiente fragmento pueda retomar la narración fluidamente.
  • Modo Audiolibro Tradicional: Prohibición absoluta de terminar el texto con resúmenes grandilocuentes, cierre de tramas o sugerencia del fin de la historia (p. ej., "Estaba lista para los nuevos retos", "Comprendió que era hora de seguir adelante"). El texto debe cortarse en medio de una acción en curso, una tensión o un pensamiento abierto.

Excepción a la regla: Si solicitas explícitamente un final, un desenlace o un epílogo, la IA generará un cierre satisfactorio de la historia — la prohibición no aplica cuando tú mismo lo pides.

Gestión de Actos y Escenas (Modo Guion, desde la versión 7, conservado)

El Modo Guion en Bruto dispone de un panel dedicado "✂️ Gestión de Estructura" con botones para construir la estructura del guion en tiempo real.

  • Insertar Acto X: Inserta el encabezado de acto (p. ej., "Acto 2") Y automáticamente añade debajo "Escena 1" — porque cada nuevo acto comienza con la primera escena. El contador de actos salta al número siguiente y el contador de escenas se reinicia a 2 (listo para la siguiente escena en ese acto).
  • Insertar Escena X: Inserta solo el encabezado de escena (p. ej., "Escena 3") dentro del acto actual. El contador de escenas aumenta automáticamente.

Carga inteligente de archivo: Al cargar un archivo de guion existente, la aplicación lo escanea automáticamente y establece los contadores de actos y escenas en los números correctos. El contador de escenas se calcula siempre dentro del último acto del archivo.

Prólogo y Epílogo: Los botones "📜 Insertar Prólogo" y "🏁 Insertar Epílogo" son comunes a ambos modos y están disponibles en el mismo panel.

El Arquitecto de Audiolibros convertirá automáticamente los Actos en puntos de navegación principales (Heading 1) para ElevenLabs y NVDA — las Escenas se convertirán en texto en negrita visible en el documento, pero no en el índice.

Gestión Inteligente de Capítulos (Modo Audiolibro, desde la versión 5, conservado)

El LLM genera como máximo unos 5000 caracteres por consulta — insuficiente para un capítulo completo. Por eso trabajas de forma iterativa: generas fragmentos sucesivos con el botón "Enviar a IA" hasta que consideras que el capítulo está listo. Entonces haces clic en "Insertar corte de capítulo" — la aplicación añade el encabezado al archivo y a la memoria, y el contador de capítulos salta automáticamente al número siguiente.

Botones del panel:

  • Insertar corte (Capítulo X): Inserta el encabezado (p. ej., "Capítulo 3") en el archivo y en la memoria. El contador de capítulos se actualiza automáticamente.
  • Insertar Prólogo: Solo funciona al principio, cuando la memoria está vacía. Protección contra la inserción accidental del Prólogo en mitad de la historia.
  • Insertar Epílogo: Cierra la historia. Una vez insertado el Epílogo con contenido, la aplicación bloqueará la generación de nuevos fragmentos — es intencionado, porque tras el final de la historia no hay nada más que añadir.

Carga inteligente de archivo: Al cargar un archivo existente, la aplicación lo escanea automáticamente y establece el contador de capítulos en el número correcto. Si el archivo tiene un Prólogo y tres capítulos, el contador mostrará "Capítulo 4" — sin necesidad de contar manualmente.

Acumulador de Trama — cómo funciona la memoria de la IA

A la memoria del modelo llega únicamente el texto limpio de la historia — lo que la IA ha escrito realmente. Las instrucciones, opciones y planes desaparecen tras su uso y no contaminan el contexto. ¿El resultado? El modelo mantiene la concentración durante más tiempo, recuerda mejor los acentos de los personajes y "se desvía" con menos frecuencia de las reglas del Libro del Mundo.

El indicador "Memoria del Modelo" en pantalla muestra cuánto se ha llenado la ventana de contexto del modelo. Desde la versión 15.1 ya NO se limita a contar los caracteres de la historia — la aplicación cuenta TOKENS reales (con el mismo método que usa el modelo) y suma TODA la carga enviada a la IA: la historia actual, la Memoria a Largo Plazo (resumen) Y el Libro del Mundo. Por eso el indicador también sube cuando amplías el Libro del Mundo o tienes un resumen extenso — no solo por la narración en sí. El valor se muestra como porcentaje de ocupación de la ventana:
- Verde (hasta aprox. 70%): El modelo está plenamente concentrado, tienes un margen de seguridad.
- Amarillo (aprox. 70–90%): Te acercas al límite. La IA puede empezar a acortar respuestas e ignorar las reglas. Es el momento de guardar tú mismo la Memoria a Largo Plazo — y de empezar a cerrar el hilo poco a poco.
- Rojo (por encima de aprox. 90%): ¡Sobrecarga crítica! Desde la versión 18.13, en este nivel la aplicación ejecuta por sí sola, después de cada envío exitoso, la herramienta de Memoria a Largo Plazo del panel de postproducción y guarda el resumen — recibirás un aviso y el panel quedará bloqueado mientras se genera el texto.

Diagnóstico del umbral de resumen (cuando la IA alucina antes de lo que prevé el umbral): los umbrales (aviso ~70%, alarma ~90%) son estimaciones empíricas. Si observas una tendencia repetida a que el modelo "se desvíe" de las reglas o empiece a alucinar ANTES de que el indicador entre en amarillo/rojo — es decir, antes de lo que prevé el umbral — abre un issue en el repositorio de la aplicación y describe a qué porcentaje de ocupación aproximado empieza a fallar, preferiblemente con un ejemplo. Si esta tendencia se confirma de forma más amplia (en otros usuarios, en distintos proyectos), el umbral de resumen automático se reducirá en el siguiente parche. Es un mecanismo deliberadamente iterativo — mejor ajustarlo con datos reales que adivinarlo de antemano.

Memoria Infinita (desde la versión 6, conservada)

Cuando se enciende la alarma roja, ya no tienes que copiar el resumen manualmente. Desde la versión 18.13 se encarga de ello una herramienta aparte del panel de postproducción (PASO 4): un clic genera una cápsula concisa de todo lo ocurrido en la trama hasta ese momento, la guarda como archivo de memoria en la carpeta skrypty/ (en el paquete español <nombre>_resumen.txt) y la coloca de inmediato en el campo de Memoria a Largo Plazo. Después de guardarla puedes limpiar la memoria y seguir creando en el mismo archivo: la historia puede continuar indefinidamente, sin ningún límite de longitud.

Qué ha cambiado respecto a versiones anteriores: hasta la v18.12 el resumen se encargaba en la Lluvia de Ideas escribiendo en la instrucción la palabra "resumen" o "síntesis". Esa vía tenía un defecto de diseño: el prompt de la Lluvia de Ideas prohíbe al modelo escribir nada que no sean tres opciones argumentales, así que pedirle un simple resumen lo colocaba ante dos instrucciones contradictorias a la vez — y podía terminar en error en lugar de en resultado. Por eso resumir es ahora una herramienta independiente con su propia instrucción, sin contradicciones, y la Lluvia de Ideas ha vuelto a una única tarea: planificar la trama.

Cuándo resumir (actualizado en v15.5): Ya no tienes que vigilar un umbral rígido de caracteres "antes de terminar la sesión". Lo mejor es resumir tras el cierre natural de una parte estructural importante — al terminar una escena, un acto o un capítulo. El motivo: cuando más adelante corrijas manualmente el final en el archivo de narración y hagas clic en "Recargar proyecto desde el disco", la aplicación te preguntará desde qué encabezado debe reconstruir el fragmento reciente — y el resumen de la parte anterior quedará intacto (se acabó corregir en dos sitios distintos). Por eso conviene aún más mantener la estructura: inserta regularmente encabezados de Capítulo/Acto/Escena desde el panel de estructura (se desaconsejan las formas largas sin ningún acto ni capítulo, como un "drama modernista" escrito de un tirón). EXCEPCIÓN: si llevas una historia muy larga COMPLETAMENTE sin encabezados, generar y guardar el Resumen antes de una pausa sigue siendo necesario — sin marcadores la aplicación solo puede recuperar el último fragmento contado en caracteres, y el motor sin contexto podría "entrar en pánico".

Resumen automático (reconstruido en v18.13): cuando el indicador de memoria entra en estado de alarma (por encima de aprox. 90%), la aplicación ejecuta por sí sola la herramienta de Memoria a Largo Plazo en cuanto termina el envío — sin preguntar, porque a ese nivel cada llamada siguiente ya está en riesgo. El resultado va directamente al archivo de resumen y al campo de Memoria a Largo Plazo, y tú recibes un aviso de que ha ocurrido. Cero trabajo manual. Por supuesto, puedes corregir el resumen en el campo y volver a guardarlo con el botón de guardado de la Memoria.

El resumen es INCREMENTAL: la herramienta no lee todo el proyecto desde cero cada vez. Recibe la Memoria a Largo Plazo existente y la parte de la narración escrita después del último resumen (la aplicación recuerda en qué encabezado se quedó) y fusiona ambas. Gracias a ello el coste de los resúmenes sucesivos no crece con la longitud de la novela, y los acontecimientos más antiguos no se pierden en cada actualización.

Carga inteligente y recarga desde el disco (actualizado en v17.6): Tanto al cargar el proyecto como tras hacer clic en "Recargar proyecto desde el disco" (después de editar manualmente el archivo de narración en el editor), la aplicación reconcilia la memoria con el disco en un solo proceso — recalcula los contadores de estructura y recupera el Libro del Mundo y el modo. Si TODA la historia cabe en la ventana de contexto — la carga íntegramente y elimina el antiguo resumen innecesario para que el motor trabaje con el texto completo (esto cierra la antigua brecha en la que el modelo recibía solo el resumen sin el contexto de las últimas escenas). Si la historia es LARGA y tiene un archivo de resumen guardado — conserva el resumen intacto y te pregunta desde qué encabezado de estructura (Capítulo/Acto/Escena) debe arrancar la memoria de trabajo de la IA; el resto de la trama queda representado por el resumen. Así no malgastas tokens recargando toda la historia, y al mismo tiempo el siguiente resumen no se genera a partir de datos desactualizados.

PASO 3b: Dos salidas del Guion — audiolibro multipersonaje (ElevenLabs) y versión para lectores de pantalla

El guion terminado del teatro leído (modo Guion) tiene dos salidas independientes: un proyecto multipersonaje de ElevenLabs Studio (audio) y una versión HTML para lectores de pantalla. Son dos formas de "escuchar" la misma obra — puedes usar una, la otra o ambas. Ambas son opcionales y no modifican el flujo clásico con el convertidor.

Puente a ElevenLabs Studio (audio, opcional)

El puente convierte el guion en un proyecto multipersonaje de Studio — el narrador y cada personaje reciben una voz propia. Sin clave de ElevenLabs nada cambia: el puente simplemente permanece oculto.

Clave de ElevenLabs (opcional)

Pega tu clave de ElevenLabs en el archivo golden_key.env, en una línea aparte: ELEVENLABS_API_KEY=sk_... Atención: la clave de ElevenLabs comienza con sk_ (con GUION BAJO), a diferencia de la clave de Anthropic (sk-ant-). Si usas una clave con restricciones (restricted key), otórgale los permisos (scopes) projects_write y voices_read. El estado de la clave se muestra en la pantalla principal (System Check) — la ausencia de clave no es un error, simplemente el puente permanece oculto.

El puente aparece en el panel del Director en modo Guion (cuando la clave es correcta). Funciona con una obra terminada guardada en disco — primero genera o carga el proyecto, luego accede al puente.

Paso 1 — Reparto de voces

Haz clic en «Reparto de voces…». La aplicación leerá del guion los personajes que tienen réplicas y siempre añadirá un slot de Narrador (el narrador es la voz predeterminada — lee los títulos de los capítulos y toda la narración). Para cada locutor, pega el voice ID. IMPORTANTE: cada voz utilizada en la obra debe estar primero en tus «My Voices» — las voces que creas tú mismo (p. ej. en «Voice Design») llegan allí automáticamente, mientras que las voces de la biblioteca pública las exploras en la pestaña «Explore» y las añades con el botón «Add to My Voices». Cómo obtener el voice ID en ElevenLabs (en el navegador): localiza la voz, reproduce la muestra para asegurarte de que es la correcta y copia su identificador con el botón «Copy Voice ID»; cuando la voz ya está en «My Voices», ese botón está disponible de inmediato — sin desplegar «More actions». Selección de voces: para reducir posibles regeneraciones, lo más sencillo es elegir de la colección «Best for Eleven v3» (voces verificadas para el modelo v3 con el que se crea el proyecto); alternativamente, diseña tu propia voz en «Voice Design», y para los más atrevidos queda la clonación IVC (Instant Voice Cloning) o PVC (Professional Voice Cloning). Puedes dejar los campos vacíos y volver más tarde — el guardado es un borrador.

Paso 2 — Construir el proyecto

Haz clic en «Crear proyecto de ElevenLabs Studio…». La aplicación verificará que el guion tenga al menos un capítulo (Prólogo/Acto/Capítulo) y que cada locutor y el narrador tengan una voz asignada, y a continuación creará en tu cuenta un proyecto multipersonaje de Studio dividido en capítulos. La mera creación del proyecto NO consume créditos. La aplicación configura de inmediato el idioma del proyecto (pronunciación correcta de las líneas de encabezado) y la normalización de volumen al estándar de audiolibro — lo hace a través de la API para que no tengas que entrar en los ajustes del proyecto en el navegador.

Guardián de formato (extensión de la Regla del Montador): el puente requiere que en el guion CADA línea sea o bien una réplica con marcador de locutor ([Narrator: …] o [Nombre: …]), o bien un encabezado de estructura (Prólogo, Acto, Escena, Capítulo). La prosa ordinaria sin etiquetar escrita «suelta» — por ejemplo, una nota del autor o un fragmento de narración sin etiqueta — no se asigna a ninguna voz y se omite silenciosamente durante la construcción, por lo que el proyecto terminado podría desincronizarse con tu archivo. Por eso, si la aplicación detecta esas líneas huérfanas, mostrará su lista con números y preguntará si construir de todos modos: puedes entonces cancelar y corregir el guion (ábrelo con el botón «Abrir archivo de narración…», añade los marcadores de locutor que faltan o elimina esas líneas) o construir conscientemente de todos modos, aceptando su omisión. Es una extensión natural de la Regla del Montador: así como no se deben estropear los encabezados de estructura, en un guion destinado al puente cada línea debe tener su locutor o ser un encabezado.

Paso 3 — Render en el navegador

Tras crear el proyecto, la aplicación mostrará su identificador y un botón que abre ElevenLabs Studio. En el navegador, localiza el proyecto, renderiza el audio (esto sí consume créditos — aproximadamente 1 crédito por carácter), y luego exporta el archivo de audio o publica el proyecto en Eleven Reader. El render y la publicación se realizan de tu parte, de forma consciente — la aplicación solo construye el proyecto.

Expresión y acentos (modelo Eleven v3)

El proyecto se crea con el modelo Eleven v3 (más de 70 idiomas). Las emociones NO se expresan con mayúsculas, puntos suspensivos ni guiones — el motor los ignora. En su lugar, el Director inserta en las réplicas etiquetas de audio en inglés propias de v3, como [whispers], [sighs], [angry], [laughs] — estas controlan la expresión y funcionan independientemente del idioma del texto. El ACENTO del personaje proviene en cambio de la MUESTRA DE VOZ: si quieres que alguien hable, por ejemplo, en polaco con acento extranjero, selecciona o diseña en Voice Design una voz cuya muestra tenga ese acento. En la práctica, experimenta con el prompt de la voz hasta escuchar, por ejemplo, una muestra en polaco con acento finlandés — el modelo v3 conservará ese acento en la grabación final. Consejo: las frases muy largas debilitan el acento, por eso el Director ya recibe instrucciones en el prompt de usar frases cortas.

Conciencia del modelo v3 (fase alpha)

Eleven v3 es el más expresivo, pero sigue en fase alpha. Puede ocurrir que una réplica individual se renderice como ruido en lugar de voz — basta con regenerarla en Studio (cada bloque tiene varias regeneraciones gratuitas). En los ajustes del proyecto, ElevenLabs también puede mostrar recomendaciones para cambiar de modelo (a Eleven Flash v2.5 o Multilingual v2) — esto NO es un error, sino una sugerencia del motor. Si no quieres ver esos mensajes, simplemente no abras los ajustes del proyecto: la aplicación ya ha configurado a través de la API todo lo necesario (modelo, idioma, normalización de volumen).

¿Por qué teatro leído y no efectos de sonido? En versiones anteriores, el modo Guion producía efectos crudos [SFX: ...] sin narrador. Sin embargo, el puente hacia una grabación multipersonaje terminada requiere que el contexto (lugar, tiempo, acción) lo transmita el narrador con palabras: los efectos de sonido en Studio no están disponibles para los lectores de pantalla, y el modelo de todos modos realiza o al narrador o los efectos — nunca ambos de forma estable a la vez. Por eso el modo Guion es teatro leído: narrador más diálogo, sin SFX.

Versión para lectores de pantalla (HTML, sin ElevenLabs)

En el modo Guion, independientemente de la clave de ElevenLabs, dispones del botón «Generar versión para lectores de pantalla». Este crea el archivo skrypty/<nazwa>_screen_reader.html — una salida independiente para personas que usan lectores de pantalla (p. ej. NVDA). Funciona así: las réplicas de los personajes que en el Libro del Mundo tienen definido un acento (p. ej. la entrada «[Joana] acento finlandés») reciben una transcripción fonética (ortografía deliberadamente «alterada») y un marcador de idioma (atributo lang), gracias a lo cual el lector de pantalla las lee con el acento extranjero correcto. Las etiquetas de audio v3 (p. ej. [whispers]) se eliminan en esta versión — el lector no debe leerlas en voz alta. Los encabezados Prólogo/Acto/Escena se convierten en encabezados HTML, por lo que la navegación por el documento resulta cómoda.

Es el complemento consciente del puente de audio: el acento para el modelo v3 lo aporta la muestra de voz, y para el lector de pantalla — la ortografía más el marcador de idioma. Por eso la ortografía en la versión de audio permanece limpia (v3 selecciona el idioma por sí mismo), y la «alteración» ortográfica va exclusivamente al archivo HTML separado, donde es deseable.

PASO 4: Postproducción en el Panel de Dirección

Una vez escrita la historia, dispones de un panel de herramientas de postproducción en la parte inferior del panel de Dirección. El panel es dinámico: cada herramienta es un archivo YAML independiente en la carpeta rezyser/ (kategoria: postprodukcja), y su campo dla_trybow decide en qué modos creativos aparece la herramienta. El conjunto de botones cambia, por tanto, según el modo elegido — y cuando ninguna herramienta encaja con el modo actual, el panel permanece oculto. Puedes crear tu propia herramienta en el Gestor de Reglas (plantilla de tipo postprodukcja — ver PASO 7b).

Cada herramienta trabaja en uno de tres ámbitos (campo zakres en el YAML):

  • per_rozdzial — itera por los capítulos del archivo guardado y procesa cada uno por separado (así funciona la asignación de Títulos descrita más abajo),
  • calosc — envía a la IA todo el archivo del proyecto en una sola llamada (por ejemplo, un informe o una auditoría de toda la historia); si el proyecto tiene un Libro del Mundo, la herramienta puede incluirlo como contexto adicional,
  • rekoncyliacja (desde v18.13) — en lugar de enviar todo el archivo, envía la Memoria a Largo Plazo existente junto con la parte de la narración escrita después del último resumen. Así funciona la herramienta de Memoria a Largo Plazo descrita más abajo; gracias a ello, el coste de las llamadas sucesivas no crece junto con la longitud de la novela.

El resultado siempre aparece en una ventana de diálogo (lista para copiar), y una herramienta con el sufijo de archivo de resultado configurado lo guarda además junto a la narración en la carpeta skrypty/ (por ejemplo, nazwa_audyt.txt). Antes de sobrescribir un archivo de resultado ya existente, la aplicación pide confirmación — antes incluso de gastar el más mínimo céntimo en una llamada a la IA. Si el material para la herramienta supera la ventana de contexto con la que la aplicación mide la memoria (128 mil tokens), primero verás una advertencia preguntando si, aun así, deseas ejecutar la herramienta. Es solo una advertencia: los modelos Claude tienen una ventana mucho mayor que este contador, pero tu propio proveedor de IA con una ventana más pequeña rechazará esa solicitud — y aun así pagarás por el intento.

Asignación de Títulos a los Capítulos (Modo Audiolibro)

La IA analizará toda la historia y propondrá títulos descriptivos y literarios para cada capítulo (así como para el eventual Prólogo y Epílogo). El módulo itera por los capítulos del archivo guardado y les asigna un título breve, analizando solo el comienzo de cada capítulo (hasta 6000 caracteres). Devuelve únicamente una lista numerada de títulos — sin reescribir el contenido del libro.

Memoria a Largo Plazo — resumen del proyecto (desde v18.13)

Herramienta disponible en ambos modos de guardado (Guion y Audiolibro). Genera un registro conciso de hechos: el desarrollo de los acontecimientos, las decisiones de los personajes y sus consecuencias, los personajes, los lugares, las tramas abiertas, y al final una nota de una sola frase sobre el estilo y el tono de la narración. El destinatario de este texto es el motor narrativo, no el lector — por eso el resumen es seco y factual, sin adornos.

Tiene una característica que ninguna otra herramienta posee: su resultado no se guarda "al lado" del proyecto como un informe, sino que SE CONVIERTE en la Memoria a Largo Plazo — llega simultáneamente al archivo de memoria en la carpeta skrypty/ (su nombre lo declara la receta de la herramienta; en el paquete español es <nombre>_resumen.txt), al campo "Memoria a Largo Plazo" del panel y a un marcador interno mediante el cual la aplicación sabe hasta dónde llega el resumen (es este marcador el que permite resumir de forma incremental y el que te pregunta por el punto de referencia al recargar el proyecto desde el disco). La herramienta también se ejecuta automáticamente cuando el indicador de memoria del modelo entra en estado de alarma — ver PASO 3.

El nombre del archivo de memoria está localizado (desde v18.14). Cada paquete de idioma declara su propia palabra nativa en el campo sufiks_pliku_wyniku del archivo rezyser/postprod_streszczenie.yaml: español _resumen, inglés _overview, alemán _zusammenfassung, finés _yhteenveto, etc. Puedes cambiar el valor en el Gestor de Reglas por cualquiera propio (por ejemplo _memoria) — la aplicación se encargará de la transición, porque busca el archivo de memoria mediante una LISTA DE CANDIDATOS:

  • comprueba, uno por uno, los sufijos de las herramientas de memoria del paquete del idioma del CONTENIDO del proyecto (no del idioma de la interfaz — el archivo pertenece a la historia, no al menú), después el neutral _overview y, por último, el histórico _streszczenie;
  • cuando encuentra EXACTAMENTE UN archivo con un nombre distinto del actual, lo renombra junto con el marcador interno — no tienes que hacer nada a mano;
  • cuando encuentra VARIOS (porque tienes una herramienta de memoria aparte «para ti» y otra «para la IA», o archivos de la época de otro idioma de la interfaz), te pregunta cuál debe ser la Memoria a Largo Plazo y no toca los demás. Cancelar esa pregunta significa una sesión sin memoria: el campo queda vacío, ningún archivo se modifica ni se elimina y, con una narración larga, la aplicación te pedirá indicar el punto de referencia de la memoria de trabajo.

Ficha de publicación de ElevenReader (desde v18.14)

La herramienta lee todo el texto del proyecto y compone un conjunto de metadatos listo para el formulario de publicación del audiolibro en ElevenReader, guardando el resultado en la carpeta skrypty/ (en el paquete español como <nombre>_publicacion.txt). La ficha contiene: título y subtítulo opcional, una descripción de hasta 1000 caracteres (límite de la plataforma), uno o dos géneros EXCLUSIVAMENTE de la lista canónica de 22 categorías de ElevenReader, el público objetivo, la marca de contenido para adultos con una frase de justificación, de dos a tres fragmentos elegidos como muestra gratuita, un prompt listo para un generador de imágenes de portada (vertical de 1200×1800 px, con espacio para un título y un nombre de autor legibles) y un recordatorio de los campos que dejas por defecto en el formulario.

Los nombres de los campos de la ficha están en INGLÉS (Title:, Description, Genres:, Target audience:, Mature content:, Sample chapters:, ISBN:) — el formulario de la plataforma existe solo en inglés, así que los copias 1:1. El contenido de los campos está en el idioma de tu proyecto, pero también los VALORES de los campos cerrados (géneros, público, el Yes/No del contenido para adultos) se quedan en inglés, porque la plataforma solo los acepta de su propia lista.

Lo que la ficha no hará por ti: no inventa la editorial ni el número ISBN — los deja como campos para rellenar a mano (el ISBN es un número registrado y una alucinación aquí sería una declaración editorial falsa). El perfil de autor es obligatorio en ElevenReader, porque las publicaciones anónimas no están permitidas y va unido a la declaración de derechos de autor — así que la herramienta copiará el nombre o el seudónimo del Libro del Mundo y, si no lo encuentra allí, insertará un campo para rellenar. Los fragmentos de muestra los elige SIEMPRE, porque el formulario exige al menos uno, independientemente del modelo de pago que elijas después.

Tras generarla, la aplicación revisa la ficha por su parte: si la descripción cabe en el límite, si los géneros y el público provienen de la lista de la plataforma, si están rellenados los campos obligatorios y si han aparecido cifras en el campo ISBN. Las discrepancias las muestra como avisos suaves — recibes el resultado completo y decides tú qué corregir. Es una protección frente al caso en que el modelo invente una categoría inexistente y el formulario la rechace solo al final del asistente.

Atención: Las herramientas de postproducción requieren que el archivo del proyecto ya esté guardado en el disco (generado o cargado). Si el archivo no existe, la aplicación mostrará el mensaje correspondiente.

PASO 5: Políglota AI

Aplicación para traducciones y forzar acentos fuertes en sintetizadores de lectores de pantalla. Accede a ella haciendo clic en el botón "🌍 Políglota" en la barra de botones o seleccionando Herramientas → Políglota del menú (atajo: Ctrl+2).

Modo 1: Traductor Normal (Usa AI - De Pago)

Ideal para escuchar historias en un hermoso y correcto idioma extranjero.

  • Carga el archivo con el botón "Cargar archivo en memoria" o usando el botón "Examinar..." para seleccionar un archivo en la ventana del sistema.
  • Selecciona el modo "Traductor IA", ingresa el idioma de destino (por ejemplo, "Finlandés").
  • El script traducirá el contenido. Si cargas un archivo .html, solo traducirá el texto visible para el lector y actualizará el código de idioma en la etiqueta html.
  • Si cargas un archivo .txt o .md normal (por ejemplo, un guion generado por Dirección), el script guardará automáticamente el resultado como un archivo .html con una etiqueta de idioma incorporada, listo para ser leído por NVDA sin ningún trabajo adicional.
  • También admite archivos .docx.

División inteligente en bloques: Los textos largos se dividen automáticamente en bloques medidos en tokens del modelo (no en caracteres) y se traducen secuencialmente con una barra de progreso. Gracias a ello, incluso los idiomas de escritura densa, como el chino o el japonés, caben dentro del límite de respuesta del modelo, y una respuesta cortada se detecta y se reintenta automáticamente en fragmentos más pequeños.

Guardado resistente a fallos (NOVEDAD en la versión 9): Cada bloque traducido se guarda inmediatamente en un archivo temporal oculto en la carpeta del sistema de la aplicación. Si la traducción se interrumpe debido a un límite de API agotado, al reiniciar, la aplicación detectará automáticamente este archivo, restaurará el progreso ya pagado y continuará tranquilamente desde donde se interrumpió, sin necesidad de copiar manualmente. Al finalizar con éxito, el archivo temporal se elimina automáticamente.

¿Por qué es importante? En la versión 8, el enfoque para reanudar la traducción tenía un error crítico y silencioso: si no se renombraba el archivo con la traducción parcial y se cortaba el fragmento traducido según las instrucciones, y luego se reanudaba inmediatamente la traducción del resto, la aplicación abría el archivo de salida en modo de sobrescritura. El progreso pagado se borraba de manera irreversible y sin que te dieras cuenta. La versión 9 elimina completamente esta trampa: el guardado es permanente después de cada bloque, independientemente de lo que hagas después.

El script también limpia los marcadores de Markdown: elimina los hashtags de encabezados (por ejemplo, #, ##, ###), los signos de igualdad usados como subrayados de encabezados y las comas huérfanas que podrían perturbar el ritmo de lectura del sintetizador.

  • Escudo protector: El script protege todas las etiquetas HTML. Solo estropea diálogos y narración.

Modo 3: Cifrador (NUEVO en 13.0 — juegos de texto, gratuito, local)

El tercer RadioButton en Políglota, junto al Traductor IA y el Modo Director: "Modo Cifrador (juegos de texto, interrupciones aleatorias)". Activa seis algoritmos locales que distorsionan el texto — para juegos, acertijos, rompecabezas lingüísticos. Al seleccionar el modo, aparece una lista desplegable de algoritmos, y para uno de ellos (Cifrado César) un campo numérico adicional para el desplazamiento.

Algoritmos disponibles (selecciona en el menú "Elige algoritmo de distorsión"):

  • Inversor de Texto (Lectura al revés con mayúscula) — cada oración se invierte carácter por carácter, manteniendo el punto/exclamación/interrogación al final y la mayúscula al principio. Antes de invertir, el script expande abreviaturas populares (p.ej., ej., etc., es decir, Dr. etc.) para que el resultado tenga sentido al invertirse — sin esto, "p.ej." se convierte en el absurdo ".je.p".

Inspiración: misión del programa "The Traitors. Traidores". Cuando la presentadora mostró sin previo aviso a los participantes una canción popular polaca de un dibujo animado — simplemente reproducida al revés — las reacciones fueron del estilo "¿qué idioma es?", "debe ser armenio", "húngaro o finlandés". La misión consistía en que un equipo recibía en el bosque el texto de la canción escrito al revés, debía cantarlo en esa forma invertida, el otro equipo lo grababa, lo reproducía desde el final — y en teoría recuperaba la canción original para adivinar. Exactamente el mismo divertido malentendido fonético genera nuestro Inversor cuando pasas el archivo procesado por un sintetizador TTS.

  • Tipoglicemia (Centro de palabras mezclado) — clásico efecto psicolingüístico: "No pdueess leer un toexto en cuiaqluer odren de ltreas, si la prmeira y úilmta lretra etsán en su lguar". El script mezcla aleatoriamente el centro de cada palabra de más de 4 letras, la primera y la última letra permanecen intactas. Ideal para probar "cuánto realmente veo y cuánto supone mi cerebro".

  • Teléfono Descompuesto / Dialecto Serpiente — cada "s", "z" o dígrafo "sz" se alarga aleatoriamente en un siseo de 4-8 caracteres ("ssssss", "zzzzzz", "ssssssz"). Inspiración: Snecko del juego "Slay the Spire". Efecto: el texto suena como si lo leyera una serpiente con un defecto de pronunciación.

  • Vocalizador (Todo retumba en "O") — cada vocal en el texto se reemplaza por "o", manteniendo las suavizaciones polacas. "Buenos días" → "Boenos doas". Cuanto más largo el texto, más divertido el efecto (y el lector de pantalla lo lee con total convicción).

  • Tartamudeo Fuerte / Robot Dañado — agrega tartamudeos al comienzo de las palabras: "or-or-or-ordenador", "cr-cr-cristal". Para palabras cortas (menos de 3 letras) el algoritmo las omite. Si la segunda letra de la palabra es una consonante, repite las dos primeras letras (efecto más natural); si es vocal, repite solo la primera.

  • Cifrado César (desplazamiento del alfabeto ES) — clásico cifrado de sustitución: cada letra se desplaza N posiciones en el alfabeto español (ABCDEFGHIJKLMNÑOPQRSTUVWXYZ, 27 caracteres). Introduces el valor de desplazamiento en el campo numérico "Desplazamiento del cifrado César (0 = aleatorio, rango -26…26)". Si introduces 0 — la aplicación elegirá aleatoriamente un desplazamiento en el rango 1-26 y lo mostrará en un mensaje al finalizar (para que luego puedas descifrarlo). Los caracteres fuera del alfabeto (números, puntuación, espacios) permanecen sin cambios.

Aplicación práctica: los cifrados guardan el resultado en el mismo formato que el Modo Director (.html con etiqueta lang o .docx con etiquetas XML), por lo que NVDA los leerá con la voz del idioma correspondiente. Especialmente el Inversor y el Vocalizador suenan en el sintetizador mucho más interesantes que cuando los lees con los ojos — porque el cerebro al leer visualmente automáticamente intenta "descodificar" el texto, y el TTS lo lee exactamente como está escrito.

Los seis cifrados también se describen en un lenguaje más amplio y accesible en el archivo docs/dictionaries.pl.html en el paquete de la aplicación — junto con consejos sobre cómo agregar tu propio cifrado tipo "cambio de letras" sin conocimientos de programación (por ejemplo, jerga escolar, lenguaje de la selva).

Idioma de procesamiento, forzado y modo calidad (NOVEDAD en 18.11)

La sección de carga de archivo tiene ahora una lista desplegable de idioma de procesamiento. Con ella eliges según las reglas de qué idioma funcionan los modos Director y Cifrador: las listas de acentos y cifrados, así como el alfabeto del Cifrado César junto con el rango de desplazamiento.

  • La posición predeterminada „Detectar automáticamente" conserva el comportamiento habitual: el idioma se establece según el archivo cargado, y cuando difiere del idioma de la aplicación, recibirás una breve notificación de que las listas se han cambiado.
  • La selección de un idioma concreto de la lista es vinculante: la aplicación no lo cambiará por sí misma al cargar un archivo.

Debajo de la lista se encuentra una casilla de selección que fuerza el idioma elegido para todo el documento. Por defecto, cada párrafo se procesa según el idioma detectado para ese párrafo — esta suele ser la mejor opción, ya que las inserciones en otros idiomas reciben sus propias reglas correctas. Marca el forzado cuando necesites un procesamiento uniforme de todo el conjunto. Un ejemplo en el que esto es imprescindible: el cifrado reversible multicapa. El alfabeto del Cifrado César tiene una longitud distinta en cada idioma, así que sin forzado un texto lingüísticamente mixto se cifrará con varios alfabetos diferentes — y entonces el descifrado requiere saber dónde estaban los límites entre idiomas. Con el idioma forzado, todo el documento se cifra y descifra con un único alfabeto, el mismo. Advertencia: en los idiomas cuyo alfabeto César contiene letras diacríticas normalizadas al cargar (polaco, alemán), el descifrado no es totalmente fiel — las letras diacríticas del criptograma se convierten a sus formas base al volver a cargarlo, antes de llegar al descifrado. La reversibilidad completa la garantizan los alfabetos sin tales caracteres (p. ej. el inglés).

El traductor de IA, por su parte, ha ganado una casilla de selección de modo calidad. Al marcarla, el modelo recibe un presupuesto adicional para el análisis interno del texto antes de traducir (el llamado extended thinking) — la traducción tarda más y consume más tokens, pero los fragmentos difíciles resultan más cuidados. La opción funciona exclusivamente con los modelos Anthropic Claude; si usas un proveedor alternativo a través de un endpoint compatible con OpenAI, marcarla no tiene ningún efecto.

Un detalle relacionado: los caracteres con macrón usados en la romanización japonesa (p. ej. Tōkyō, rāmen, jūdō) se normalizan desde esta versión igual que el resto de los signos diacríticos extranjeros — en la mayoría de los idiomas a la letra simple (Tokyo), y en el paquete finlandés mediante la duplicación de la vocal (Tookyoo), conforme a la convención finlandesa de notación de sonidos largos. Gracias a ello ya no se salen del alfabeto del Cifrado César como caracteres visibles en el criptograma.

Detección de idioma

Antes de que el script "estropee" el texto, verifica en qué idioma está escrito. Si detecta que no es polaco, mostrará una advertencia. Las reglas fonéticas están diseñadas para el idioma polaco: aplicarlas a un texto en otro idioma daría resultados impredecibles.

Acentos optimizados para sintetizadores locales (NVDA)

Los acentos han sido diseñados al 100% para sintetizadores de lectores de pantalla locales, gratuitos y de pago, como Vocalizer y eSpeak en NVDA. Esto garantiza estabilidad y previsibilidad del efecto en cada computadora.

¿Por qué no ElevenLabs? Las pruebas en documentos más largos demostraron que la distorsión fonética del texto en motores como ElevenLabs no impone el acento deseado: el motor simplemente "adivina" el idioma y tiende a crear un acento eslavo occidental/sur. Los sintetizadores locales de NVDA son mucho más obedientes en este aspecto.

Diferentes motores TTS se comportan de manera distinta. A continuación, se presentan las diferencias clave que tienen un impacto directo en el funcionamiento de los acentos:

eSpeak (Código Abierto)

Un motor ligero y gratuito con una enorme base de idiomas — soporta, entre otros, islandés. Es muy riguroso con la codificación de caracteres, lo que lo hace predecible. Voces gratuitas integradas en Windows (Mobile Voices). Un buen compromiso entre calidad y disponibilidad de idiomas. Killer Feature para personas ciegas: Archivos con etiquetas de idioma

Esto es una verdadera revolución. Los archivos procesados ahora se guardan como:

  • .html con atributo lang (por ejemplo, lang="fi" para finlandés) — NVDA lee esta etiqueta y cambia automáticamente la voz al sintetizador de idioma correspondiente. ¡Cero configuración manual!
  • .docx manteniendo el formato — cada ejecución de texto tiene una etiqueta de idioma inyectada en el XML del documento, por lo que Word y NVDA saben con qué voz leer cada fragmento.

Los archivos procesados siempre se guardan como NUEVOS documentos (por ejemplo, acento_Finlandés.html).

Automatización del cambio de idioma en NVDA — lo que necesitas saber

Para que NVDA realmente cambie la voz según la etiqueta lang, debe estar activada la configuración "Cambiar automáticamente el idioma cuando sea compatible". La encontrarás en Preferencias de NVDA → Voz. Por defecto, está activada en el primer inicio del lector — pero vale la pena verificar si alguien la ha desactivado.

Importante limitación de las voces OneCore: Las voces de Microsoft OneCore no soportan este mecanismo de forma nativa con NVDA, solo con el narrador integrado en Windows. Existe un complemento no oficial para NVDA llamado "One Core Autolang", que intenta solucionar esto — pero su desarrollo fue rápidamente interrumpido. La razón es sencilla: cada año, con la primera versión de NVDA del año, aparecen cambios que rompen la compatibilidad del API (conocidos como API Breaking Changes). A veces basta con actualizar el campo "last tested version" en el manifiesto del complemento, pero a veces se requieren cambios reales en el código — y el autor no puede mantenerse al día con las actualizaciones. Si te importa el cambio automático de idioma, una opción más segura son las voces de Tiflotecnia (de pago, sección anterior) o eSpeak (gratuitas, de menor calidad), que soportan este mecanismo de forma nativa — pero atención: actualmente en Tiflotecnia Voices esto funciona con un error de prioridades (ver "Gancho crítico" abajo). Después de aplicar el parche, el cambio automático funciona perfectamente, como en el antiguo Vocalizer.

Gancho crítico de Tiflotecnia Voices: detección de idioma defectuosa

Primero, la buena noticia: la alarma sobre NVDA 2026.1 de las versiones anteriores del manual terminó con un final feliz: Cerrence proporcionó bibliotecas de 64 bits, Tiflotecnia las lanzó en un paquete .nvda-addon disponible en la Tienda de Complementos (sección anterior), y Vocalizer, para aquellos que lo conservaron hasta el final, regresó bajo un nuevo nombre, con mejor calidad y sin las limitaciones de 32 bits.

Sin embargo, con el lanzamiento de Tiflotecnia Voices surgió un nuevo gancho crítico: en la detección de idioma. En la configuración del complemento, se puede configurar qué voz se debe usar para letras específicas (por ejemplo, latinas, cirílicas) dependiendo de las voces instaladas. El problema radica en el orden de prioridades: actualmente se aplica primero la anulación por letra, luego la opción de retroceso al código ISO del idioma (en la práctica inalcanzable para EL MISMO alfabeto al que ya se ha adaptado la anulación), y finalmente la voz seleccionada. El resultado aparece dentro del mismo alfabeto: tienes texto en finlandés con la etiqueta correcta lang="fi", Satu instalada como la voz finlandesa de Tiflotecnia, PERO en la configuración se ha establecido una voz polaca para las letras latinas: Satu NO leerá este texto, a pesar de la etiqueta ISO correcta. La anulación por letra "voz polaca para latín" gana en el primer nivel, el ISO fi nunca se verifica. Para pares de alfabetos diferentes, el mecanismo funciona correctamente (texto ruso + Milena para cirílico + voz polaca para latín: todo el cirílico se lee con Milena, los nombres propios latinos con la voz polaca; cada alfabeto permanece en su anulación). Después de la migración desde Vocalizer, donde el cambio de idioma basado en ISO funcionaba perfectamente, los usuarios notarán esta regresión de inmediato, especialmente aquellos que en Políglota usan varios acentos europeos (Satu, Alice, Markus) en el mismo conjunto de letras latinas.

Diagnóstico y parche: diagnostiqué el problema a nivel de Python en el código del complemento y preparé un parche que cambia el orden de prioridades a: ISO → voz seleccionada → anulación por letra. El parche conserva el útil cambio al latín para nombres latinos en texto ruso, cuando en la configuración está activada la "detección de idioma basada en caracteres Unicode". Envié el parche a los desarrolladores de Tiflotecnia, pero aún no he recibido respuesta, así que lo más probable es que se mantengan en su propia solución. Si el complemento recibe una actualización, actualizaré el parche si es necesario.

Qué hacer mientras tanto: si te importa la detección correcta del idioma (vale la pena: era una de las características destacadas del antiguo Vocalizer, ver "Característica destacada para ciegos" arriba), abre un problema en el repositorio de la aplicación en GitHub con la etiqueta tiflotecnia-patch y tu dirección de correo electrónico en el contenido. Conviene añadir una breve descripción del problema en tu propio idioma (bastan 2–3 frases) — el bot detectará el idioma (soportados: polaco, inglés, alemán, español, finés, francés, islandés, italiano, ruso) y responderá en el mismo; sin descripción o en otro idioma, la respuesta llegará en inglés. Un bot automático cerrará el problema de inmediato con una confirmación de recepción (sin dejar rastro en el hilo público), y recibirás el parche por correo electrónico generalmente en unos pocos días. El parche NO se publica en el repositorio de la aplicación ni como un Gist: Tiflotecnia Voices para NVDA es software comercial, y la licencia del complemento no permite la redistribución de sus archivos, incluso modificados. Una vez que recibas el parche, su contenido debe copiarse en %appdata%\Roaming\nvda\addons\TiflotecniaVoices, reemplazando los archivos. Precaución al copiar: si Windows no te preguntó sobre la sustitución, probablemente copiaste toda la carpeta TiflotecniaVoices_edits con su contenido EN LUGAR del contenido en sí: en ese caso, entra en la subcarpeta creada, corta todo, pégalo un nivel arriba y sobrescribe. Después de aplicar el parche correctamente, reinicia NVDA: disfruta de la mejor calidad de voces Cerrence de 64 bits y la detección de idioma correcta, una combinación que ningún productor único en el mercado puede ofrecer. Por supuesto, asumimos que tienes una licencia válida de Tiflotecnia Voices: no verificamos esto, pero no podrás aplicar el parche sin una licencia en una carpeta ajena.

PASO 6: Arquitecto de Audiolibros

Herramienta para preparar la estructura profesional de un archivo para lectores de pantalla y ElevenLabs. Accede a ella haciendo clic en el botón "📄 Convertidor" de la barra de botones o seleccionando Herramientas → Convertidor en el menú (atajo: Ctrl+3).

¿Cómo funciona?

  1. Escribe la ruta al archivo fuente en el campo de texto o haz clic en el botón "Examinar..." para seleccionar el archivo en el cuadro de diálogo del sistema. El script acepta tanto .txt como .docx, así como archivos .html y .htm.
  2. Haz clic en "Construir Arquitectura para ElevenLabs".
  3. El script escaneará cada línea del texto y convertirá las palabras clave (Acto, Capítulo, Prólogo, Epílogo, Introducción) en encabezados "Heading 1" en el documento Word.
  4. Las escenas (líneas que comienzan con la palabra "Scena") se convierten en texto en negrita — visibles en el documento, pero no visibles en el índice de ElevenLabs.
  5. Todo el texto restante (diálogos, descripciones) pasa sin cambios.
  6. Recibirás el archivo arquitectura_[nazwa_oryginału].docx — un Word profesional listo para seguir trabajando. Por ejemplo, si tu archivo de entrada se llamaba znieczulica.txt, el archivo resultante tendrá el nombre arquitectura_znieczulica.docx y aparecerá en la misma carpeta que el original.

Limpieza de paso: El script elimina automáticamente las etiquetas HTML (si el texto proviene de un navegador o de un archivo .html local, por ejemplo generado por el Políglota) y los marcadores de encabezados Markdown (p. ej. ### o ####) antes del procesamiento. No necesitas limpiar el archivo manualmente.

Modo Historias: agrupación automática de turnos en escenas (desde v15.1)

Si cargas en el Arquitecto un archivo opowiesci/<gra>.txt generado por el módulo de Historias Interactivas, el convertidor reconocerá los marcadores de turno (p. ej. "--- Tura 7 ---" — también en los demás idiomas compatibles, si jugaste en otro) e insertará un nuevo encabezado de primer nivel "Scena N" cada cinco turnos (la numeración comienza en 1, en el idioma de tu partida). Los demás marcadores de turno son eliminados — no aparecen en la narración del audiolibro, porque "Tura 7" pronunciado por el TTS rompe la inmersión del oyente. El resultado es un archivo Word con una división natural en escenas de varios minutos de audio cada una, listo para importar a ElevenLabs. El mecanismo es de detección automática — los archivos de audiolibro normales sin marcadores de turno (narración clásica del Director) se procesan exactamente igual que antes.

Poderosa ventaja para usuarios de NVDA y ElevenLabs

El formato "Heading 1" para los capítulos no es solo estética. En NVDA puedes navegar por los encabezados de forma instantánea pulsando la tecla H (o 1 para los encabezados de primer nivel). En lugar de desplazarte por cientos de páginas, saltas de capítulo en capítulo en una fracción de segundo. Esto cambia la forma de trabajar con documentos largos. En ElevenLabs tienes la certeza de que el motor insertará los cortes automáticamente y no se bloqueará durante la dirección de los clips de audio.

PASO 7: Cómo escribir el Libro del Mundo (Prompt del Arquitecto y Minicurso de Markdown)

La inteligencia artificial que impulsa el Estudio Principal comprende mejor los comandos cuando están formateados en el lenguaje de marcado Markdown. Si le proporcionas a la IA en el Director solo una idea suelta (p. ej., "dos hermanas en el más allá"), la máquina entrará en pánico por falta de detalles y creará una historia banal y predecible, ignorando la lógica.

Para evitarlo, utiliza un chatbot externo (p. ej., ChatGPT gratuito o Claude) como tu Arquitecto personal. En la versión 13.0 ya no necesitas copiar el prompt de las instrucciones manualmente — en el panel del Director, justo debajo del botón "💾 Guardar Libro permanentemente", encontrarás el botón "📖 Prompt del Arquitecto para IA…". Haz clic en él y se abrirá un cuadro de diálogo con el texto del prompt listo en un campo de "solo lectura" y un botón "Copiar al portapapeles". NVDA anuncia todo el contenido en cuanto se abre la ventana — basta con hacer clic en "Copiar", pegar (Ctrl+V) en ChatGPT/Claude y sustituir el fragmento "[ESCRIBE TU IDEA AQUÍ]" con tu propia semilla argumental.

¿Por qué así y no copiando de las instrucciones? El diálogo en la GUI tiene una ventaja clave de accesibilidad: es nativo y lo lee sin interferencias el lector de pantalla, no requiere cambiar a un editor de texto (donde las letras especiales y las comillas a veces se copian mal) y funciona de forma idéntica en cualquier sistema operativo. El mismo patrón — diálogo con prompt para copiar — también se utiliza en el Gestor de Reglas (véase PASO 7b más abajo).

Cómo responde la IA: En la respuesta recibirás un texto en dos partes. La primera es el Libro del Mundo encerrado en un bloque de código Markdown (marcadores markdown …). Copia ÚNICAMENTE el contenido del bloque de código (sin los propios marcadores ```) y pégalo en el campo "Libro del Mundo" del Director; a continuación, haz clic en "💾 Guardar Libro permanentemente". La segunda parte es una recomendación sobre cuál de los modos creativos (Skrypt o Audiobook) encaja mejor con tu idea — trátala como una sugerencia al seleccionar el modo en el campo de selección de modo.

Minicurso de Markdown en el Libro: un único hashtag (#) es la sección principal (p. ej., "# Postacie"), el doble hashtag (##) es una subsección, los guiones (-) crean listas, y los dobles asteriscos (texto) ponen en negrita las reglas absolutas e inamovibles (p. ej., "Bohater NIGDY nie kłamie"). Para un personaje en otro idioma, añade una etiqueta con el acento, p. ej., "[Speaker 1: Marek] - ma akcent francuski". La palabra clave "akcent" es OBLIGATORIA — el motor de la aplicación la detecta automáticamente y aplica las reglas fonéticas correctas a los diálogos de ese personaje.

Consejo: Recuerda actualizar tu Libro del Mundo de vez en cuando (a medida que la trama se amplíe con nuevos lugares o personajes importantes). Puedes hacerlo manualmente o con la ayuda de un chatbot externo. ¡Cuanto más rico sea el fundamento, mejores serán los resultados en la Reżyseria!

PASO 7b: Gestor de Reglas (Ctrl+4) — diccionarios para lingüistas sin Python

La versión 13.0 introduce la cuarta herramienta en la barra: el Gestor de Reglas. Lo abres con la tecla Ctrl+4 o desde el menú Herramientas. Es un explorador visual de la carpeta dictionaries/, donde la aplicación guarda todas las reglas fonéticas (acentos), cifrados y modos del Director en archivos YAML (formato legible para humanos, más simple que JSON).

¿Por qué YAML? Hasta la versión 12.0, todos los acentos, modos creativos y filtros estaban "embebidos" en el código de Python. Añadir un nuevo acento requería un programador. En la versión 13.0, todo eso se trasladó a archivos .yaml en la carpeta dictionaries/ — cualquiera que pueda abrir el Bloc de notas puede ajustar un acento existente ("cambiar sz por sh por sch") o añadir uno completamente nuevo (sueco, danés, dialecto ruso).

¿Qué encontrarás en el Gestor de Reglas?
- Árbol de archivos — lista completa de todos los archivos YAML en dictionaries/ divididos por idiomas base (actualmente completamente implementados: Polski, Deutsch, English, Español, Suomi, Français, Íslenska, Italiano, Русский) y categorías (akcenty/, szyfry/, rezyser/, opowiesci/, gui/). Navegación con flechas como en el Explorador de archivos de Windows, soporte completo para NVDA.
- Botón "📝 Abrir en editor de texto" — abre el archivo seleccionado en el Bloc de notas predeterminado del sistema. Editas, guardas, haces clic en "🔄 Actualizar árbol" y listo.
- Botón "📋 Duplicar archivo seleccionado" — la forma más rápida de un nuevo acento: tomas un archivo existente (por ejemplo, finski.yaml), le das un nuevo nombre (por ejemplo, sueco), el Gestor crea una copia con el comentario "cambiar campos etiqueta y descripción" y lo abre en el editor.
- Botón "➕ Nuevo archivo de reglas…" — asistente con selección de tipo (acento, cifrado, modo del Director, nuevo idioma base, cifrado algorítmico). Para casos comunes (acento, cifrado tipo "cambio de letras") el asistente crea una plantilla YAML lista para editar. Para casos que requieren un programador (nuevo idioma base, algoritmo tipo "mezcla de medio de palabras") el asistente genera un prompt para el chatbot AI — lo pegas en ChatGPT, obtienes el archivo YAML listo, lo guardas en dictionaries/ y listo.

Aplicación práctica: ¿Quieres añadir un acento sueco? Abre el Gestor de Reglas, selecciona dictionaries/pl/acentos/finski.yaml, haz clic en "Duplicar", nombra el archivo sueco, cambia en él el campo etiqueta a "Sueco (Alva / Oskar)", el código iso a sv, cambia algunas reglas de sustitución y guarda. Regresa a la Página principal y reinicia la aplicación. El nuevo acento aparecerá en el menú Políglota (en el Modo del Director) y — si lo añades al Libro del Mundo de personajes ("[Marek] - tiene acento sueco") — también en la detección automática de acentos del Director.

Dónde buscar más documentación de la carpeta dictionaries/:
- Archivo docs/dictionaries.pl.html (disponible en el paquete para usuarios finales desde la pestaña Releases) — breve descripción en lenguaje simple de cada subcarpeta, 6 cifrados listos, 8 acentos listos y sugerencias sobre lo que se puede hacer por uno mismo, sin conocimientos de Python.
- Archivo dictionaries/README.md (disponible solo al clonar el repositorio desde GitHub — los paquetes de lanzamiento filtran archivos .md) — documentación técnica detallada del formato YAML con ejemplos, listas de campos, reglas de pipeline, regex. Este documento está dirigido a lingüistas con conocimientos básicos de programación y a desarrolladores.

Importante información para usuarios de lectores de pantalla (NVDA)

1. Mensajes de éxito y error

Cuando la aplicación finaliza una acción (por ejemplo, guarda un archivo o encuentra un error), aparecerá un cuadro de diálogo con un título como "Éxito", "Advertencia" o "Error". NVDA anunciará inmediatamente este cuadro de diálogo y leerá su contenido. Después de hacer clic en botones como "Enviar a la IA" o "Iniciar Procesamiento", el programa comienza inmediatamente a procesar en segundo plano. Aparece una barra de progreso en la pantalla (Gauge), pero NVDA NO lee su valor en tiempo real: el lector de pantalla permanece en silencio durante el trabajo. No vuelvas a hacer clic en el botón. Espera a que aparezca un cuadro de diálogo con el resultado o un mensaje de error: NVDA lo anunciará automáticamente.

3. Navegación entre herramientas

Moverse entre herramientas (Director, Políglota, Convertidor, Gestor de Reglas) se realiza en una sola ventana del programa a través de cuatro botones en la barra de herramientas o mediante el menú Herramientas (Alt, luego N). Atajos de teclado disponibles: Ctrl+0 (Página principal), Ctrl+1 (Director), Ctrl+2 (Políglota), Ctrl+3 (Convertidor), Ctrl+4 (Gestor de Reglas — nuevo en 13.0). Después de cambiar de herramienta, el foco automáticamente se posiciona en la descripción del nuevo módulo — NVDA comienza a leer inmediatamente la nueva vista.

4. Orden de tabulación y nombres de los widgets

Cada elemento de la interfaz tiene un nombre claro en español — NVDA lo leerá al enfocarlo. El orden de tabulación es lógico: desde la descripción de la herramienta, pasando por los campos de configuración, hasta los botones de acción. No hay sorpresas aquí — la navegación por teclado funciona igual que en cualquier otro programa nativo de Windows. Todos los menús y botones están en español y NVDA los leerá con voz en español sin configuraciones adicionales.

PASO 7b (complemento): El orden de las reglas zamiany: importa

Los archivos en dictionaries/<kod>/akcenty/*.yaml contienen una lista de reglas zamiany: — pares wzor → zamiana, que el motor aplica SECUENCIALMENTE. Cada regla subsiguiente opera sobre la salida de la anterior. Esto permite construir pipelines del tipo "descomponer el dígrafo szcz en shch, y luego cambiar solo ch por h", pero también abre la clásica trampa para el autor del paquete de idioma.

La trampa del "bucle secuencial". Supongamos que para un acento español que quiere hacer que la "ñ" polaca suene como la pronunciación de Diego (Loquendo), el autor añade dos reglas:
1. ñ → nj (para que la "ñ" polaca suene como una "nj" suave)
2. j → x (para que la "j" polaca suene como la "j" española — fonéticamente /x/)

Al ejecutarlo, resulta que las palabras con "ñ" se pronuncian como "nx", no "nj". ¿Por qué? Porque cuando la primera regla cambia "ñ" por "nj", la nueva "j" es inmediatamente atrapada por la segunda regla y cambiada a "x". Resultado: en lugar de "ñ → nj" como se pretendía, obtenemos "ñ → nx".

Regla del orden (universal). Cuando una regla introduce un carácter que otra regla tiene como patrón, EL ORDEN IMPORTA. Una heurística segura: PRIMERO cambia el TARGET (carácter usado después como wzor en otra regla) a algo seguro, y SOLO DESPUÉS introduce el SOURCE (carácter que debe descomponerse en el TARGET). Para el ejemplo español correctamente: primero j → x, luego ñ → nj. Resultado: "ñ" da "nj" (la segunda "j" ya no será consumida, porque la regla j → x se aplicó antes, cuando "nj" aún no existía).

Cómo probar. Después de cambiar el orden de las reglas en el archivo de acento, pasa una oración que contenga AMBAS letras por el Modo Director. Por ejemplo, ES: "Niño de paja juega" → el resultado debe tener tanto el acento ñ ("ñ → nj") como el acento j ("j → x"), es decir, algo como "Ninjo de paxa xuega". Si ves "ninxo" en lugar de "ninjo" — el orden es incorrecto.

Validación en el motor (opt-in para autores de paquetes). La aplicación tiene una heurística incorporada para detectar bucles potenciales, pero está desactivada por defecto — porque muchas pipelines parecen un bucle, aunque son intencionales (el clásico "szcz → shch" + "ch → h"). Para activarla: establece la variable de entorno REZYSER_VALIDATE_ZAMIANY=1 y ejecuta la aplicación desde la consola — desde la fuente a través de python main.py, porque el .exe congelado en modo ventana (a partir de la versión 17.0) no tiene ventana de consola. El motor imprimirá para cada archivo de acentos una línea agregada WARN con los primeros tres bucles potenciales y el número de los restantes. Verifica la fonética resultante en la oración de prueba — si el efecto es el deseado, ignora el WARN.

Los botones para mover reglas en el GUI del Gestor de Reglas (arrastrar y soltar, "Arriba / Abajo") son una función separada planeada para un ciclo de versión posterior — requiere rediseñar el Gestor (actualmente delega la edición del archivo a un Bloc de Notas externo del sistema y no tiene su propia vista de reglas). Hasta su implementación: edita el archivo YAML manualmente, mueve las líneas en la sección zamiany:, utiliza el validador con la variable ENV y prueba con oraciones de control.

PASO 2B (avanzado, opcional): Proveedor de IA propio compatible con OpenAI

La mayoría de los usuarios debería quedarse con el Anthropic recomendado (PASO 2) — es el que ofrece la mayor calidad. Sin embargo, si tienes una razón propia (coste, acceso, privacidad, modelo local propio), a partir de la versión 18.4 puedes indicar CUALQUIER endpoint compatible con la API de OpenAI — por ejemplo OpenRouter, Groq, Fireworks, DeepSeek, Ollama local o un endpoint de Gemini compatible con OpenAI. Todo el motor de IA sigue entonces un único camino hacia ese endpoint, sin integración separada por proveedor.

Esta es una opción para usuarios avanzados: la configuras manualmente en el archivo golden_key.env, añadiendo junto a (o en lugar de) la clave de Anthropic tres líneas y la clave del proveedor elegido:

LLM_PROVIDER=openai_compat
LLM_BASE_URL=dirección_del_endpoint (p. ej. https://openrouter.ai/api/v1)
LLM_MODEL=nombre_del_modelo_en_el_proveedor (p. ej. openai/gpt-4o-mini)
OPENAI_API_KEY=tu_clave_en_ese_proveedor

Cómo funciona:
• Cuando LLM_PROVIDER=openai_compat, TODO el motor de IA (Director, Historias, Políglota, títulos, detección de idioma) utiliza el endpoint indicado, y LLM_MODEL sobrescribe el nombre del modelo de los archivos de configuración.
• Cuando la línea LLM_PROVIDER no existe (o tiene el valor anthropic), la aplicación funciona como en el PASO 2 — exclusivamente con la clave de Anthropic. No necesitas cambiar nada.

Importante (calidad): los prompts del sistema de la aplicación están escritos y ajustados para Claude. Otro modelo puede ofrecer menor calidad — respetar peor las reglas del mundo, perder la estructura JSON en los modos con elecciones o devolver el texto en un idioma incorrecto. Es un compromiso consciente coste↔calidad de tu parte. Si lo que te importa es el mejor resultado, quédate con Anthropic.
